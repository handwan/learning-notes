    权限与用户¶

    Linux 的权限模型：用户/组、rwx、特殊权限与能力（capabilities）、sudo 提权，以及远程登录的 SSH。

    1. 用户与组¶

    whoami                  # 当前用户
id                      # 当前用户的 uid/gid/所属组
id someuser             # 指定用户的信息
groups                  # 自己所属的组
who / w                 # 谁在线（w 还显示在干什么）
last                    # 最近登录记录
    文件 内容
    /etc/passwd 用户列表：用户名:x:UID:GID:说明:主目录:登录 shell
    /etc/shadow 密码哈希与过期策略（只有 root 能读）
    /etc/group 组列表：组名:x:GID:成员1,成员2 
    getent passwd wang       # 查用户（比直接 cat 更规范）
getent group sudo        # 查组

    用户管理（都要 root/sudo）：

    sudo useradd -m -s /bin/bash alice     # 建用户（-m 建主目录，-s 指定 shell）
sudo passwd alice                       # 设置密码
sudo usermod -aG docker alice           # 加入组（-a 追加！不加 -a 会覆盖原有组）
sudo usermod -L alice                   # 锁定账号
sudo usermod -U alice                   # 解锁账号
sudo userdel -r alice                   # 删除用户（-r 连主目录一起删）
sudo groupadd dev                       # 建组
sudo groupdel dev                       # 删组

    uid 的约定：0 = root；1–999 系统用户（服务用）；1000+ 普通用户。

    2. 权限模型¶

    ls -l f.txt
-rwxr-xr-- 1 wang dev 1024 ... f.txt
└┬┘└┬┘└┬┘
 │  │  └── other（其他人）：r--
 │  └───── group（同组）：r-x
 └──────── owner（属主）：rwx

    rwx 对文件与目录的含义不同：

    权限 对文件 对目录
    r 读内容 列目录（ls）
    w 改内容 增删改目录里的条目
    x 执行 进入目录（cd、访问里面的文件）

    目录只有 r 没有 x：能 ls 看到文件名，但 cat 里面的文件会 Permission denied——这是常见困惑点。

    chmod¶

    chmod 644 f.txt          # rw-r--r--（普通文件）
chmod 755 script.sh      # rwxr-xr-x（可执行/目录）
chmod 600 id_rsa         # rw-------（私钥！）
chmod 700 ~/.ssh         # 只有自己能进

chmod a+x script.sh      # 明确给所有人加执行位
chmod +x script.sh       # 也常用，但会受 umask 影响（不保证三组都加）
chmod u+x script.sh      # 只给属主加
chmod go-w f.txt         # 去掉同组和其他人的写权限
chmod -R u=rwX,go=rX dir/  # 递归：目录可进入，普通文件不误加执行位

    别直接 chmod -R 755 dir/：它会把目录里的普通文件也变成可执行。需要递归修权限时用上面的 X（只有目录或原本可执行的文件才加 x）。

    数字含义：r=4 w=2 x=1，三组分别算——755 = rwx+r-x+r-x，644 = rw-+r--+r--。

    加了执行位后怎么跑（./ 的疑惑都在这）：

    ./script.sh        # 当前目录：必须带 ./（或写别的路径前缀）
script.sh          # ❌ 裸名字去 PATH 里找——当前目录不在 PATH，找不到
scripts/run.sh     # 带斜杠 = 路径，不用加 ./
/opt/run.sh        # 绝对路径；开头的 / 是根目录，和 ./ 不是一回事
bash script.sh     # 兜底：显式指定解释器，没有 x 权限也能跑

    ./ 里的 . 就是"当前目录"；裸名字（ls、python3）则去 $PATH 列出的目录里找（echo $PATH 看列表）。

    chown / chgrp¶

    sudo chown alice f.txt           # 改属主
sudo chown alice:dev f.txt       # 同时改属主和属组
sudo chown -R wang:wang proj/    # 递归（改项目目录常用）
sudo chgrp dev f.txt             # 只改属组

    umask：默认权限¶

    新建权限 = 基准权限按位清零 umask 的位（基准 & ~umask）：文件基准 666，目录基准 777。不是普通减法。

    umask            # 一般是 022
umask 077        # 之后新建的文件 600、目录 700（私有）
umask 002        # 团队共享目录常用（文件 664、目录 775）

    3. 特殊权限¶

    位 显示 作用 典型场景
    setuid rws（属主位） 执行时以文件属主身份运行 passwd 命令（普通用户改密码要写 /etc/shadow）
    setgid rws（属组位） 对文件：以属组身份运行；对目录：新建文件继承该目录的组 团队共享目录
    sticky rwt（other 位） 目录里的文件只有属主能删 /tmp 
    chmod u+s prog           # setuid
chmod g+s shared_dir/    # setgid（目录）
chmod +t /tmp            # sticky

# 数字表示（第四位）：4755 setuid、2775 setgid、1777 sticky
chmod 2775 shared_dir/

    注意：没有执行位时，s/t 显示为大写 S/T（表示"设了但没有执行位"，通常是配置错了）。setuid 有安全风险（提权漏洞），现代系统尽量用 sudo 代替。

    4. 能力（Capabilities）¶

    setuid 是"全给"——进程一提权就是完整的 root。能力把 root 的特权切成小块，只授予需要的那几块：

    getcap /usr/bin/ping              # 看程序带了哪些能力（ping 用它拿原始套接字权限）
sudo getcap -r / 2>/dev/null | head    # 全盘扫"带能力的程序"
sudo setcap cap_net_bind_service=+ep /opt/myapp/server   # 允许绑定 1024 以下端口
sudo setcap -r /opt/myapp/server  # 移除

    为什么好：服务不用 setuid root、也不用 sudo 全家桶，就能单独拿到某一个特权（绑低端口、改系统时间…）——最小权限原则的体现。+ep 里 e=有效、p=许可；细节用到再查。

    5. sudo 与 su¶

    sudo cmd                 # 以 root 执行一条命令（输自己的密码）
sudo -i                  # 进入 root 的交互 shell（登录式）
sudo -s                  # root shell（非登录式，环境变量保留）
sudo -u alice cmd        # 以 alice 身份执行
sudo -l                  # 看我能 sudo 什么
su - alice               # 切换用户（需要对方的密码）

    sudo vs su：

    sudo su
    验证的密码 自己的 目标用户的
    粒度 按命令/按组授权 全有或全无
    审计 有日志（/var/log/auth.log，或 journalctl） 少
    配置 /etc/sudoers（用 visudo 改！） — 
    # /etc/sudoers 里的常见写法（必须用 visudo 编辑，它会检查语法）
alice ALL=(ALL:ALL) ALL                  # alice 可以 sudo 任何命令
%sudo ALL=(ALL:ALL) ALL                  # sudo 组成员
deploy ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart myapp   # 免密+限定命令

    注意：改 sudoers 一律 sudo visudo——直接编辑语法错了会导致"再也 sudo 不了"。

    6. SSH¶

    密钥登录（推荐）¶

    ssh-keygen -t ed25519 -C "wang@laptop"     # 生成密钥对（现代默认；老系统用 -t rsa -b 4096）
# 产出：~/.ssh/id_ed25519（私钥，600）和 ~/.ssh/id_ed25519.pub（公钥，可公开）

ssh-copy-id user@host                       # 把公钥装到对方 ~/.ssh/authorized_keys
ssh user@host                               # 之后免密登录
ssh -p 2222 user@host                       # 指定端口

    权限是硬要求（sshd 会因为权限太松拒绝使用）：

    chmod 700 ~/.ssh
chmod 600 ~/.ssh/id_ed25519 ~/.ssh/authorized_keys
chmod 600 ~/.ssh/config

    家目录本身也不能让 group/other 可写；sshd 的 StrictModes 会检查，权限太松会拒绝密钥登录。

    ssh-agent 与 known_hosts¶

    带口令的私钥每次输入很烦，用 ssh-agent 缓存：

    eval "$(ssh-agent -s)"          # 启动 agent（当前 shell）
ssh-add ~/.ssh/id_ed25519       # 加入缓存
ssh-add -l                      # 看已加载的 key
ssh-add -D                      # 清空

    ssh -A host 可以转发 agent（在远端用你的 key），但只在信任的跳板机上用；远端 root 能借它操作你的其他主机。

    known_hosts 记录主机公钥；主机重装/换 key 后报 REMOTE HOST IDENTIFICATION HAS CHANGED：

    ssh-keygen -F host              # 查记录
ssh-keygen -R host              # 删除旧记录
ssh-keyscan -H host >> ~/.ssh/known_hosts   # 重新采集（先核对指纹）

    ~/.ssh/config：给主机起别名¶

    Host dev
    HostName 192.168.1.10
    User wang
    Port 2222
    IdentityFile ~/.ssh/id_ed25519

    之后 ssh dev 就等于 ssh -p 2222 wang@192.168.1.10。

    经跳板机：

    Host internal
    HostName 10.0.0.5
    User wang
    ProxyJump dev

    临时跳一次也可以：ssh -J dev internal。

    传输文件¶

    scp file.txt user@host:/tmp/              # 传文件
scp -r dir/ user@host:/tmp/               # 传目录
scp user@host:/var/log/app.log .          # 取回来
rsync -avz -e ssh dir/ user@host:/dst/    # 大目录/增量（比 scp 好，见文件与目录）
sftp user@host                            # 交互式传输

    端口转发¶

    # 本地转发：把本地 8080 转到"远端能访问的 3306"（访问远端内网数据库）
ssh -L 8080:127.0.0.1:3306 user@host

# 远程转发：把远端的 9090 转到"本地能访问的 3000"（把本机服务暴露给远端）
ssh -R 9090:127.0.0.1:3000 user@host

# 动态转发：本地开一个 SOCKS5 代理（浏览器走它）
ssh -D 1080 user@host

# 常用参数：-N 不执行命令（只转发）、-f 后台
ssh -NfL 8080:127.0.0.1:3306 user@host

    服务端加固（能改 /etc/ssh/sshd_config 时）¶

    PasswordAuthentication no        # 只允许密钥登录
PermitRootLogin no              # 禁止 root 直登
Port 2222                       # 换端口（减少扫描）
AllowUsers wang deploy          # 只允许这些用户登录（先确认自己也在列表里）
MaxAuthTries 3                  # 单次连接最多认证尝试次数
LoginGraceTime 30               # 登录握手超时（秒）
# 改完：sudo systemctl restart ssh   # RHEL 系服务名通常是 sshd

    改 PasswordAuthentication no 前先确认密钥能登录，并保留一个已登录的会话；否则可能把自己锁在门外。

    7. 其他文件属性¶

    # 扩展属性：防误删/防篡改（需要 root）
sudo chattr +i important.conf    # 不可修改（设置期间 root 也改不了，解除用 chattr -i）
lsattr important.conf            # 查看

# ACL：给"某个用户"单独授权（经典权限做不到）
setfacl -m u:alice:rwx shared/   # 给 alice 单独 rwx
setfacl -d -m u:alice:rwx shared/  # 默认 ACL：之后新建的文件/目录继承
getfacl shared/                  # 查看（会看到 user:alice:rwx 和 default:...）
setfacl -x u:alice shared/       # 移除

    chattr / ACL 都依赖文件系统支持；ext4、XFS 一般没问题，FAT、部分网络盘可能不支持。

    8. 强制访问控制（AppArmor / SELinux）¶

    rwx 是"自主访问控制"——进程以哪个用户跑，就有那个用户的权限。强制访问控制（MAC） 在之上再加一层"这个程序能碰哪些资源"的策略：

    AppArmor SELinux
    默认发行版 Ubuntu / Debian / openSUSE RHEL / CentOS / Fedora
    策略粒度 按程序路径 按类型标签（更细）
    看状态 sudo aa-status getenforce（Enforcing/Permissive/Disabled）
    临时放宽 sudo aa-complain /path/to/prog sudo setenforce 0（测试用）

    常见症状：权限位明明没错，服务就是起不来——先查内核拒绝日志：

    sudo dmesg | grep -i "denied\|apparmor\|selinux"
sudo journalctl -k | grep -i denied

    处理思路：先确认确实是被 MAC 拦的（别一上来就整体关掉）；按日志里的策略名调整规则或给程序打标签（aa-complain / semanage），要关也只针对单个程序。

    9. 常见权限场景对照¶

    场景 权限
    普通文件（配置、源码） 644
    可执行文件 / 脚本 / 目录 755
    私钥 / 含密码的配置 600
    ~/.ssh 目录 700
    团队共享目录（组内可写 + 继承组） 2775（setgid）
    公共可写目录（如 /tmp） 1777（sticky）

    10. 要点回顾¶

    1. uid 0 = root；用户信息在 /etc/passwd，组在 /etc/group，密码哈希在 /etc/shadow
    2. 权限三元组（owner/group/other）+ r=4 w=2 x=1：644 文件、755 目录/可执行、600 私钥
    3. 目录的 x 才是"能进入"；只有 r 能列名但读不了内容
    4. 特殊权限：setuid（以属主运行）、setgid（目录内继承组）、sticky（只有属主能删）
    5. umask 决定新建文件/目录的默认权限（文件 666 & ~umask、目录 777 & ~umask，不是普通减法）
    6. sudo vs su：sudo 用自己密码、按命令授权、有审计；sudoers 改错会很麻烦，用 visudo
    7. SSH 密钥：ssh-keygen -t ed25519 + ssh-copy-id；~/.ssh 700、私钥/authorized_keys 600，家目录也不能 group/other 可写；ssh-agent 缓存口令，known_hosts 记录主机 key，sshd 可加 AllowUsers/MaxAuthTries
    8. 端口转发：-L 本地→远端、-R 反向、-D SOCKS 代理，配 -Nf 后台常驻
    9. 需要单独授权的场景用 ACL（setfacl，默认 ACL 可让新文件继承），需要防改的用 chattr +i（依赖文件系统支持）
    10. 权限位对但被拒 → 可能被 AppArmor/SELinux 拦：sudo dmesg | grep -i denied 查
    11. 能力：把 root 特权切细（getcap/setcap，如绑低端口）——比 setuid 全给更安全
