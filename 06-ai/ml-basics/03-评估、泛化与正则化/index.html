    评估、泛化与正则化¶

    训练损失小，不代表模型好。模型可能在背训练集，也可能在评估时泄漏了测试信息。

    这篇讲四件事：

    • 怎么切数据、怎么做交叉验证
    • 偏差-方差：模型太简单还是太复杂
    • 指标：损失之外，业务到底看什么
    • 数据泄漏与正则化：怎么让评估可信、让泛化更好

    1. 训练误差不是目标¶

    回到第 1 篇学习问题的框架的式子：

    • 经验风险 \(R_{\mathrm{emp}}\)：训练集上的平均损失
    • 真实风险 \(R\)：整个分布上的期望损失

    训练只最小化 R_emp，但我们要的是 R。两者之间的差距就是泛化误差。

    一个极端例子：

    1 个样本、1 个参数，模型可以完全记住它，训练损失 0。
换一个样本，预测可能完全错。

    所以评估的第一原则：用来评估的数据，不能参与训练，也不能参与调参。

    2. 数据切分¶

    最小切法：

    集合 用途
    训练集 学参数
    验证集 选超参数、早停、选模型
    测试集 最后评估一次

    常见错误：

    • 用测试集调参 → 测试集被你“看过”，不再是无偏估计
    • 先标准化/特征选择/补缺失，再切分 → 泄漏
    • 同一用户/设备/文档的样本被随机切到两边 → 分组泄漏
    • 时间序列随机切 → 未来信息泄漏

    特殊切法：

    • 分层采样：分类任务保持类别比例
    • 分组切分：同一组（用户、患者、文档）只出现在一边
    • 时间切分：用过去训练，未来测试

    3. 偏差-方差¶

    平方损失可以分解为：

    \[ \mathbb{E}\bigl[(y-\hat{f}(x))^2\bigr] =\sigma^2+\operatorname{Bias}^2+\operatorname{Variance} \]
    • Bias：模型平均预测偏离真实值 → 模型太简单
    • Variance：模型对训练集变化太敏感 → 模型太复杂
    • 噪声 \(\sigma^2\)：数据本身的噪声，任何模型都消不掉
    现象 训练误差 验证误差 怎么办
    欠拟合（高 bias） 高 高 加容量、加特征、减正则
    过拟合（高 variance） 低 高 加数据、加正则、降容量
    合适 低 低且接近训练 保持

    多项式实验¶

    30 个样本拟合 sin(2πx)，噪声 0.2；22 个训练、8 个验证、400 个测试：

    import numpy as np

rng = np.random.default_rng(5)
n = 30
x = rng.uniform(-1, 1, n)
y = np.sin(2 * np.pi * x) + rng.normal(0, 0.2, n)

idx = rng.permutation(n)
tr, va = idx[:22], idx[22:]
xt = rng.uniform(-1, 1, 400)
yt = np.sin(2 * np.pi * xt) + rng.normal(0, 0.2, 400)

def design(x, deg):
    return np.column_stack([x ** k for k in range(deg + 1)])

def fit(X, y):
    w, *_ = np.linalg.lstsq(X, y, rcond=None)
    return w

def mse(w, X, y):
    return float(np.mean((X @ w - y) ** 2))

print("deg train val test")
for deg in [1, 3, 5, 7, 9, 12, 15]:
    Xtr, Xva, Xte = design(x[tr], deg), design(x[va], deg), design(xt, deg)
    w = fit(Xtr, y[tr])
    print(deg, mse(w, Xtr, y[tr]), mse(w, Xva, y[va]), mse(w, Xte, yt))

    运行结果：

    阶数 训练 MSE 验证 MSE 测试 MSE
    1 0.3838 0.5550 0.4336
    3 0.3656 0.4543 0.4087
    5 0.1228 0.1283 0.1240
    7 0.0338 0.0248 0.0556
    9 0.0316 0.0228 0.0575
    12 0.0110 0.0498 0.2855
    15 0.0080 0.0518 1.7213

    读法：

    • 1–3 阶：训练/验证都高，欠拟合
    • 5–9 阶：训练和验证都低，合适
    • 12–15 阶：训练极低，验证/测试变差，过拟合

    注意：30 个样本、22 个训练样本，15 阶多项式有 16 个系数，容量已经接近样本量；这是为了把现象放大，不代表真实任务的比例。

    4. 交叉验证¶

    单次切分的验证误差会抖：换一个随机种子，最佳阶数可能就变了。

    k 折交叉验证：

    把数据分成 k 份
每次拿 1 份验证，其余 k-1 份训练
重复 k 次，取平均

    5 折的代码：

    # 接着上一段：n, x, y, design, fit, mse 已定义
print("deg cv_mean cv_std")
for deg in [1, 3, 5, 7, 9, 12, 15]:
    scores = []
    r = np.random.default_rng(1)
    for fold in np.array_split(r.permutation(n), 5):
        mask = np.ones(n, bool)
        mask[fold] = False
        w = fit(design(x[mask], deg), y[mask])
        scores.append(mse(w, design(x[fold], deg), y[fold]))
    print(deg, np.mean(scores), np.std(scores))

    运行结果：

    阶数 CV 均值 CV 标准差
    1 0.4644 0.1280
    3 0.4914 0.1768
    5 0.2169 0.1028
    7 0.0648 0.0374
    9 0.0790 0.0362
    12 4.3260 7.9989
    15 17.8836 17.4552
    • CV 选 7 阶；测试 MSE 0.0556
    • 12/15 阶的 CV 均值/标准差都爆炸，说明极不稳定
    • 单次验证选了 9 阶，CV 选 7 阶；两者测试接近，但 CV 用了全部数据，均值/方差更可信

    什么时候不能随机 k 折¶

    • 时间序列：用未来预测过去 → 用时间切分/滚动验证
    • 分组数据：同一用户/患者/文档跨折 → 用 GroupKFold
    • 类别不平衡：用分层 k 折，保持每折比例
    • 超参数选择 + 评估：用嵌套交叉验证，避免选择偏差

    5. 指标¶

    回归¶

    指标 特点
    MSE 惩罚大误差；和损失一致
    MAE 对异常值更稳；和优化目标可能不一致
    \(R^2\) 相对“预测均值”的解释度；可负

    分类¶

    先看混淆矩阵：

    预测正 预测负
    实际正 TP FN
    实际负 FP TN
    • 准确率：\(\dfrac{TP+TN}{N}\)
    • 精确率：\(\dfrac{TP}{TP+FP}\)
    • 召回率：\(\dfrac{TP}{TP+FN}\)
    • F1：精确率和召回率的调和平均
    • ROC-AUC：排序能力；不平衡时结合 PR-AUC 看
    • PR-AUC：正类少时更敏感

    不平衡数据¶

    1000 个样本，正类 5.2%，用一个合成分数演示：

    import numpy as np

rng = np.random.default_rng(7)
n = 1000
y = (rng.random(n) < 0.05).astype(int)
score = rng.normal(0.2 + 0.8 * y, 0.25)

print("positive rate", y.mean())
print("all-negative acc", 1 - y.mean())
print("thr acc prec rec f1")
for thr in [0.2, 0.4, 0.6, 0.8]:
    pred = (score >= thr).astype(int)
    tp = ((pred == 1) & (y == 1)).sum()
    fp = ((pred == 1) & (y == 0)).sum()
    fn = ((pred == 0) & (y == 1)).sum()
    tn = ((pred == 0) & (y == 0)).sum()
    acc = (tp + tn) / n
    prec = tp / (tp + fp) if tp + fp else 0
    rec = tp / (tp + fn) if tp + fn else 0
    f1 = 2 * prec * rec / (prec + rec) if prec + rec else 0
    print(thr, acc, prec, rec, f1)

    运行结果：

    阈值 准确率 精确率 召回率 F1 代价（FP=1, FN=5）
    0.2 0.548 0.103 1.000 0.187 452
    0.4 0.793 0.198 0.981 0.330 211
    0.6 0.940 0.462 0.923 0.615 76
    0.8 0.979 0.804 0.788 0.796 65

    全预测负类的准确率是 94.8%。阈值 0.6 的准确率 94.0%，比“什么都不做”还低，但 F1 有 0.615。

    最后一列按 \(\mathrm{cost}=1\cdot FP+5\cdot FN\) 计算；这张表里 0.8 的代价最低。换一组代价，最优阈值就会变。

    结论：

    • 不平衡时，准确率会骗人
    • 阈值不是固定的 0.5，要按业务代价选
    • 正类少时看 PR-AUC/F1，不要只看 ROC-AUC/准确率

    ROC / PR¶

    分类器输出分数后，扫不同阈值可以得到两条曲线：

    • ROC：横轴 FPR = FP/(FP+TN)，纵轴 TPR = TP/(TP+FN)
    • PR：横轴 recall，纵轴 precision

    ROC-AUC 可以理解为“随机正样本的分数高于随机负样本的概率”。它对类别比例不敏感，但正类很少时，少量 FP 就能让 FPR 变化明显，ROC 可能看着很好。PR-AUC 只看正类，稀有事件优先看它。

    下面用 scikit-learn 算；没装先 pip install scikit-learn：

    from sklearn.metrics import roc_curve, auc, precision_recall_curve, average_precision_score

# 接着上一段：y、score 已定义
fpr, tpr, _ = roc_curve(y, score)
prec, rec, _ = precision_recall_curve(y, score)

print("roc_auc", round(auc(fpr, tpr), 3))
print("pr_auc", round(average_precision_score(y, score), 3))

    输出：

    roc_auc 0.986
pr_auc 0.892

    ROC 到 0.986，PR-AUC 只有 0.892；正类少时，PR 更能反映实际体验。两者都只关心排序，不看概率校准。

    校准与代价阈值¶

    AUC 只看排序，不关心概率是否准。校准看“预测 0.8 的样本里实际正类比例是否接近 0.8”；常用 reliability diagram 和 Brier score：

    \[ \mathrm{Brier}=\frac{1}{n}\sum_{i=1}^{n}(p_i-y_i)^2 \]

    排序和校准是两件事：模型可以把正类排在前面（AUC 高），但概率整体偏高/偏低。需要概率时，用 Platt scaling / isotonic regression 在验证集上校准。

    阈值按业务代价选：

    \[ \mathrm{cost}=C_{FP}\cdot FP+C_{FN}\cdot FN \]

    上面的表取 \(C_{FP}=1,C_{FN}=5\)；换一组代价，最优阈值就会变。

    6. 数据泄漏¶

    泄漏 = 评估时用到了训练时不该知道的信息。

    常见来源：

    来源 例子
    预处理 先对全量数据标准化/补缺失，再切分
    特征选择 用全量标签选特征，再做交叉验证
    目标编码 用全量标签算类别均值
    分组 同一用户/患者跨训练和验证
    时间 用未来数据预测过去
    重复样本 同一记录同时出现在训练和测试

    泄漏实验¶

    100 个样本、2000 个随机特征、随机标签（没有任何真实信号）。代码不长，直接放全：

    import numpy as np

def nearest_centroid(Xtr, ytr, Xte):
    m0 = Xtr[ytr == 0].mean(0)
    m1 = Xtr[ytr == 1].mean(0)
    d0 = ((Xte - m0) ** 2).sum(1)
    d1 = ((Xte - m1) ** 2).sum(1)
    return (d1 < d0).astype(int)

def corr_scores(X, y):
    Xc = X - X.mean(0)
    yc = y - y.mean()
    denom = np.sqrt((Xc ** 2).sum(0) * (yc ** 2).sum()) + 1e-12
    return np.abs(Xc.T @ yc / denom)

rng = np.random.default_rng(8)
n, p, k = 100, 2000, 20
X = rng.normal(size=(n, p))
y = rng.integers(0, 2, n)

def cv_acc(X, y, selector):
    r = np.random.default_rng(9)
    scores = []
    for fold in np.array_split(r.permutation(len(y)), 5):
        mask = np.ones(len(y), bool)
        mask[fold] = False
        s = selector(X[mask], y[mask]) if selector else np.arange(X.shape[1])
        pred = nearest_centroid(X[mask][:, s], y[mask], X[fold][:, s])
        scores.append((pred == y[fold]).mean())
    return np.mean(scores), np.std(scores)

# 错误做法：先在全量标签上选特征，再交叉验证
sel = np.argsort(corr_scores(X, y))[-k:]
print("leakage", cv_acc(X[:, sel], y, None))

# 正确做法：每一折内部重新选特征
print("nested ", cv_acc(X, y, lambda Xtr, ytr: np.argsort(corr_scores(Xtr, ytr))[-k:]))

    运行结果：

    做法 5 折 CV 准确率
    先用全量标签选 20 个特征，再 CV 0.83 ± 0.04
    每折内部选特征（嵌套 CV） 0.54 ± 0.06

    标签是随机的，真实准确率应该接近 0.5。0.83 完全是泄漏：特征选择已经看过验证集的标签。

    正确做法：

    1. 先切分，再预处理
    2. 所有拟合步骤（标准化、补缺失、特征选择、目标编码）只放在训练折里
    3. 用 Pipeline 把预处理和模型绑在一起
    4. 超参数选择用嵌套 CV
    5. 分组/时间数据用对应切分

    7. 正则化与泛化¶

    正则化是降低方差的手段。第 2 篇线性模型讲过 L1/L2，这里只讲它和评估的关系。

    手段 作用
    L2 收缩系数，降低方差
    L1 稀疏化，做特征选择
    早停 在验证误差开始上升时停
    Dropout 训练时随机丢单元，降低共适应
    数据增强 扩大有效数据分布
    标签平滑 抑制过度自信

    调正则化强度：

    对每个 \(\lambda\)：

    1. 在训练折上拟合
    2. 在验证折上算误差
    3. 取平均

    选验证误差最小的 \(\lambda\)，最后在测试集上评估一次。

    正则化不是越强越好：太强会欠拟合，训练/验证都变差。

    8. 学习曲线与诊断¶

    学习曲线和验证曲线不是一回事，先看横轴。

    学习曲线：横轴是训练集大小¶

    形状 判断 下一步
    训练/验证都高，且接近 高 bias 加特征/加容量/减正则
    训练低、验证高，差距大 高 variance 加数据/加正则/降容量
    验证误差随训练集增大还在降 数据不够 加数据
    验证误差已经平 数据够了 调模型/特征

    验证曲线：横轴是模型复杂度或正则强度¶

    形状 判断 下一步
    训练/验证都高，且接近 欠拟合（高 bias） 加容量/减正则
    训练低、验证高 过拟合（高 variance） 降容量/加正则/加数据
    验证误差随复杂度增加还在降 容量不够 加容量/减正则
    验证误差已经上升 过拟合 停在最低点，早停/正则

    加数据主要降方差，不会解决高 bias；加容量主要降 bias，但可能增大方差。

    9. 检查清单¶

    1. 切分了吗？测试集是不是只在最后用了一次？
    2. 预处理、特征选择、目标编码是不是只在训练集上拟合？
    3. 分组/时间数据用对切分了吗？
    4. 指标和业务一致吗？有没有看基线？
    5. 类别不平衡时，是不是只看了准确率？
    6. 超参数是用验证/CV 选的吗？
    7. 报告的是均值，还是单次结果？
    8. 正则化强度调过吗？是不是过强/过弱？

    10. 要点回顾¶

    1. 训练误差不是目标；测试集不能参与训练和调参
    2. 偏差-方差：太简单欠拟合，太复杂过拟合
    3. 交叉验证：k 折、分层、分组、时间切分；报告均值和方差
    4. 指标：回归看 MSE/MAE/\(R^2\)；分类看精确率/召回率/F1/ROC-AUC/PR-AUC；概率还要看校准
    5. 不平衡：准确率会骗人，阈值按业务代价调；稀有正类优先 PR-AUC
    6. 泄漏：预处理、特征选择、目标编码、分组、时间都可能泄漏
    7. 正则化：降低方差，\(\lambda\) 用验证/CV 选，不是越强越好
