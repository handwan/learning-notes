    服务化¶

    模型能跑不等于能提供服务。服务化要处理：

    • API：HTTP/gRPC、OpenAI 兼容、流式
    • 请求生命周期：认证、配额、排队、取消
    • 超时/重试/幂等：别把一次请求变成多次生成
    • 限流/背压：队列不能无限长
    • 可观测性：TTFT/TPOT、错误率、租户、成本
    • 部署：网关、worker、扩缩容、灰度、回滚

    这篇讲 API、流式、超时/重试、限流和可观测性，最后起一个最小 SSE 流式服务。部署/多租户见 Infra 第 5 篇；指标/SLO 见 Infra 第 6 篇。

    1. 服务分层¶

    客户端
→ 网关/边缘（TLS、认证、限流、路由）
→ API 层（HTTP/gRPC、OpenAI 兼容、流式）
→ 队列/调度（准入、优先级、配额）
→ 推理引擎（batching/KV/量化）
→ 可观测性（metrics/logs/traces）
    层 负责 常见问题
    网关 TLS、auth、rate limit、路由 超时、缓冲区、连接复用
    API schema、流式、错误码 版本、兼容、错误格式
    队列 准入、优先级、公平 无界队列、饥饿
    引擎 batching、KV、量化 OOM、TTFT/TPOT
    可观测 指标、日志、trace 基数爆炸、缺 request ID

    2. API 与流式¶

    常见协议：

    • HTTP/REST + JSON：最通用
    • SSE（Server-Sent Events）：服务端单向流式，text/event-stream
    • WebSocket：双向，适合交互式
    • gRPC：protobuf、双向流式、强类型
    • OpenAI 兼容 API：/v1/chat/completions，stream=true 走 SSE

    SSE 格式：

    data: {"token":"Hel"}

data: {"token":"lo"}

data: [DONE]

    要点：

    • 每行 data: ...，事件之间空行
    • 服务端要 flush，别让代理/框架缓冲
    • 客户端断开要停止生成/释放 KV
    • 错误要在流里给结构化错误，不能只断连接
    • [DONE]/finish_reason 要明确

    请求字段（示例）：

    • model、messages、max_tokens
    • temperature/top_p
    • stream
    • tools/response_format
    • user/metadata（注意隐私）

    响应：

    • 文本/增量 token
    • finish_reason
    • usage（prompt/output/cached tokens）
    • request ID

    错误码：

    • 400 参数错误
    • 401/403 认证/权限
    • 404 模型不存在
    • 429 限流
    • 500/503 引擎/过载
    • 错误体要有 code/message/request_id，不要只给 HTML

    3. 请求生命周期¶

    1. 认证/租户识别
    2. 配额/限流
    3. 准入/排队
    4. 调度到模型 worker
    5. prefill/decode/流式返回
    6. 计量/计费/日志
    7. 取消/超时清理

    关键：

    • 每个请求有 request ID，贯穿网关/队列/引擎/日志/trace
    • 超时预算要分阶段：排队、prefill、decode、总时长
    • 客户端断开要取消生成，释放 KV/slot
    • 多租户要按 tenant/model/route 打标签
    • 队列要有上限和拒绝策略

    4. 超时、重试与幂等¶

    超时：

    • connect/read/total 分开
    • 网关、API、引擎各自的超时
    • 流式请求的 idle timeout 和总 timeout
    • 超时要返回明确错误，不要挂死

    重试：

    • 只重试安全/幂等的请求
    • LLM 生成 POST 默认不幂等；用 idempotency key
    • 指数退避 + jitter；设置 retry budget
    • 429 看 Retry-After
    • 避免重试风暴/雪崩

    流式重试：

    • 已经输出的 token 不能“撤回”
    • 重试可能重复生成/重复计费
    • 要么从头开始，要么设计 resume/断点协议
    • 客户端要能处理半截输出 + 错误

    取消：

    • request ID 取消
    • 停止 decode、释放 KV/slot
    • 记录取消原因/阶段

    5. 限流、配额与背压¶

    限流维度：

    • 请求数/QPS
    • token 数（输入/输出）
    • 并发数
    • 租户/模型/路由

    常见算法：

    • token bucket/leaky bucket
    • 滑动窗口
    • 并发信号量
    • 队列 + 优先级

    背压：

    • 队列上限
    • 拒绝/429
    • 降级（小模型/短输出）
    • 负载 shedding

    不要无界队列：延迟会爆炸，最后全部超时。

    配额/计费：

    • prompt + output token
    • cached token
    • 按 tenant/model 计量
    • 配额/预算/告警
    • 失败/取消是否计费要明确

    6. 可观测性¶

    指标：

    • QPS、并发、队列长度、等待时间
    • TTFT、TPOT、p50/p95/p99
    • 错误率/超时率/取消率
    • tokens/s、输入/输出 token
    • GPU 利用率/显存/KV cache
    • 每租户/模型/路由

    日志：

    • request ID、tenant、model、route
    • 输入/输出长度（不要默认记全文）
    • 错误码/阶段/重试/取消
    • PII 脱敏

    Trace：

    • 网关 → 队列 → 引擎 → 流式
    • span：auth、queue、prefill、decode、stream
    • 采样率可调

    注意：

    • label 基数：request_id/user_id 不要进 metrics
    • 日志要能按 request ID 串起来
    • 告警要有 runbook
    • SLO/错误预算见 Infra 第 6 篇

    7. 安全¶

    • 认证：API key/OIDC/mTLS
    • 授权：RBAC、租户隔离
    • 输入：prompt injection、PII、滥用
    • 输出：内容过滤、敏感信息
    • 密钥/权重：加密、访问审计
    • 供应链：镜像签名、SBOM
    • 日志：不要记录密钥/全文/PII

    应用层 guardrails 见 Applications；模型评测/安全见 LLM 第 9 篇。

    8. 部署¶

    • 网关无状态，模型 worker 有状态（权重/KV）
    • readiness 等模型加载完
    • HPA/扩缩容看队列/TTFT/GPU，不只看 CPU
    • canary/blue-green、版本 pin、回滚
    • 多地域：数据驻留、路由、故障切换
    • 模型 registry/配置中心

    部署/多租户细节见 Infra 第 5 篇。

    9. 实验：最小 SSE 流式服务¶

    用 Python 标准库起一个 HTTP 服务：

    • /stream：SSE，先模拟 prefill，再逐 token flush
    • /full：等全部生成完，一次返回
    • 客户端测首字节/首 token 时间和总时间
    代码：最小 SSE 流式服务 
    import http.client
import json
import threading
import time
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer

TOKENS = ["Hel", "lo", " ", "world", "!"]
DELAY = 0.05

class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        if self.path == "/stream":
            self.send_response(200)
            self.send_header("Content-Type", "text/event-stream")
            self.send_header("Cache-Control", "no-cache")
            self.end_headers()
            time.sleep(DELAY)  # 模拟 prefill
            for i, tok in enumerate(TOKENS):
                payload = json.dumps({"i": i, "token": tok}, ensure_ascii=False)
                self.wfile.write(f"data: {payload}\n\n".encode())
                self.wfile.flush()
                time.sleep(DELAY)  # 模拟 decode
            self.wfile.write(b"data: [DONE]\n\n")
            self.wfile.flush()
        elif self.path == "/full":
            time.sleep(DELAY * (len(TOKENS) + 1))
            body = json.dumps({"text": "".join(TOKENS)}).encode()
            self.send_response(200)
            self.send_header("Content-Type", "application/json")
            self.send_header("Content-Length", str(len(body)))
            self.end_headers()
            self.wfile.write(body)
        else:
            self.send_error(404)

    def log_message(self, *args):
        pass

server = ThreadingHTTPServer(("127.0.0.1", 0), Handler)
port = server.server_address[1]
threading.Thread(target=server.serve_forever, daemon=True).start()

def call(path, stream):
    conn = http.client.HTTPConnection("127.0.0.1", port, timeout=5)
    t0 = time.perf_counter()
    conn.request("GET", path)
    resp = conn.getresponse()
    first = None
    n = 0
    if stream:
        while True:
            line = resp.readline()
            if not line:
                break
            if line.startswith(b"data: ") and b"[DONE]" not in line:
                n += 1
                if first is None:
                    first = time.perf_counter() - t0
    else:
        resp.read()
        first = time.perf_counter() - t0
        n = 1
    total = time.perf_counter() - t0
    conn.close()
    return first, total, n

s_first, s_total, s_n = call("/stream", True)
f_first, f_total, f_n = call("/full", False)
print(f"stream first={s_first:.3f}s total={s_total:.3f}s chunks={s_n}")
print(f"full   first={f_first:.3f}s total={f_total:.3f}s chunks={f_n}")
server.shutdown()

    输出（一次运行，数值随机器）：

    stream first=0.052s total=0.303s chunks=5
full   first=0.302s total=0.302s chunks=1

    读法：

    • 流式首 token 0.051s；非流式要等 0.303s 才拿到完整响应
    • 两者总时间相同；流式改善的是 TTFT/感知延迟，不是总计算
    • 真实服务还要加认证、限流、超时、重试、取消、指标
    • 代理/负载均衡可能缓冲 SSE；要确认 flush/超时配置

    10. 常见坑¶

    1. 不流式 用户等完整响应，TTFT 看起来很差。

    2. SSE 没 flush/被代理缓冲 首 token 被卡住；检查网关/框架/压缩。

    3. 超时只设一个总时长 排队/连接/prefill/decode 分不清；要分阶段。

    4. 重试非幂等生成 重复生成/重复计费；用 idempotency key。

    5. 没有退避/jitter 重试风暴，雪崩。

    6. 无界队列 延迟爆炸；要上限/拒绝/背压。

    7. 限流只按 IP 租户/模型/ token 维度没管；要配额。

    8. 没有 request ID 网关/队列/引擎日志串不起来。

    9. 没有 per-tenant 指标 配额/计费/故障定位都难。

    10. 流式重试重复 token 客户端看到重复/半截输出；要定义 resume/restart。

    11. 代理 idle timeout 长生成被断开；调 idle/总超时。

    12. 日志记录全文/密钥 PII/密钥泄漏；脱敏/采样。

    13. 模型版本漂移 没 pin/灰度，行为突变；要版本/回滚。

    11. 要点回顾¶

    1. 服务化分层：网关→API→队列→引擎→可观测
    2. API 支持 HTTP/gRPC/OpenAI 兼容；流式用 SSE/WebSocket
    3. SSE 要 flush、结构化错误、[DONE]、客户端断开取消
    4. 请求生命周期要有 request ID、分阶段超时、取消/清理
    5. 重试只用于幂等请求；生成用 idempotency key + 退避/jitter
    6. 限流按请求/token/并发/租户；队列有上限/背压
    7. 可观测性看 TTFT/TPOT/错误/队列/GPU/成本，按租户/模型
    8. 安全：认证/授权/租户隔离/PII/prompt injection
    9. 部署要 readiness、灰度、版本 pin、回滚；扩缩容看队列/延迟
