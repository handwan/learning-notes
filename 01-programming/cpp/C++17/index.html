    C++17¶

    语言特性¶

    1. 结构化绑定¶

    一次性把 pair / tuple / 结构体 / 数组拆成多个变量：

    std::pair<int, double> p{42, 3.14};
auto [x, y] = p;                    // 拷贝一份：x=42, y=3.14
auto& [rx, ry] = p;                 // 引用：改 rx 就是改 p.first
const auto& [cx, cy] = p;           // 只读、零拷贝（大对象优先这种）

struct Point { int x, y; };
Point pt{1, 2};
auto [px, py] = pt;                 // 结构体也行（成员必须是 public）

int arr[3] = {1, 2, 3};
auto [a, b, c] = arr;               // 数组也行

    什么时候用：

    • 遍历 map：for (auto& [key, value] : m)——比 it->first / it->second 清楚得多
    • 接收多返回值：auto [ok, msg] = try_parse(s);（返回 std::pair/tuple/自定义结构体）

    和 std::tie（C++11）对比：tie 要先把变量声明出来，且只能接收已存在对象；结构化绑定是"就地声明 + 自动推导类型"。

    坑：

    • 变量个数必须和元素个数完全一致（不能多也不能少）
    • auto [x, y] = p; 是拷贝；改 x 不会改 p——要大对象零开销就写 const auto&
    • 不能绑定位域（bit-field）
    • 绑定名是"新变量"，不是原成员的名字（auto [a, b] = p 之后没有 p.first 的别名）

    2. if / switch 带初始化语句¶

    std::map<std::string, int> m{{"a", 1}};

// 变量作用域限制在 if 内，else 里也可见
if (auto it = m.find("a"); it != m.end()) {
    std::cout << it->second << '\n';
} else {
    std::cout << "没找到\n";
}

// 锁 + 条件判断：不用写两行
if (std::lock_guard<std::mutex> lk{mtx}; !queue.empty()) {
    auto task = queue.front();
}

switch (auto n = compute(); n) {
    case 1: break;
    default: break;
}

    好处：作用域收窄，it / lk 不会泄漏到外层，也避免"忘了解锁/名字冲突"。

    3. 折叠表达式¶

    变参模板的展开，四种形式：

    template <typename... Args>
auto sum(Args... args) { return (args + ...); }          // 一元右折叠：a1+(a2+(a3+a4))

template <typename... Args>
auto sum2(Args... args) { return (... + args); }         // 一元左折叠：((a1+a2)+a3)+a4

template <typename... Args>
auto sum3(Args... args) { return (0 + ... + args); }     // 二元左折叠（带初值）

template <typename... Args>
void print_all(Args&&... args) {
    (std::cout << ... << args);                           // 二元右折叠：连着一路 <<
}

template <typename... Args>
bool all_true(Args... args) { return (args && ...); }     // 全为真（非零）才返回 true

    什么时候用：写变参模板时，替代递归展开（旧写法要写"取第一个 + 递归剩下的"两个函数）。

    坑：

    • 空参数包时：&& 折叠是 true、|| 是 false、逗号是 void——都合法；但 +、* 这种没有单位元的运算，空包是编译错误（这时要用带初值的二元折叠：(0 + ... + args)）
    • 能折叠的运算符有限制：?:、[]、. 这类不行

    4. if constexpr（编译期分支）¶

    template <typename T>
auto get_value(T t) {
    if constexpr (std::is_pointer_v<T>) {
        return *t;            // T 是指针时才会实例化这一支
    } else {
        return t;
    }
}

    和普通 if 的区别：if constexpr 条件为 false 的分支不会被实例化——所以可以在里面写"只对该类型合法"的代码（比如对指针解引用、调用某类型专有的成员）。

    典型场景：

    • 按类型分派（替代 enable_if + tag dispatch，可读性好得多）
    • 变参模板的递归展开（if constexpr (sizeof...(args) > 0) 配合拆分首参）

    坑：

    • 在非模板函数里，if constexpr 的 false 分支仍要语法正确（编译器只丢弃实例化，不做语法豁免）
    • 写模板时留意：分支里用到的名字如果是依赖名字，不实例化就不检查——这也是它有用的原因

    5. 内联变量¶

    // config.h
inline int global_count = 0;              // 多个 .cpp 包含这个头 → 不会重定义
inline constexpr double kPi = 3.14159;    // 常量也可以（头文件里定义）

struct Limits {
    static constexpr int kMax = 100;      // C++17 起隐式 inline，不用在 .cpp 里再定义
};

    解决的问题：C++17 之前，头文件里定义变量（或类静态非 const 成员）会被每个包含它的编译单元各定义一份 → 链接期重定义错误。以前只能"头文件声明 + 一个 .cpp 定义"或 static（每个 TU 一份，浪费且不一致）。

    注意：inline 变量是同一个实体（跨 TU 共享地址），static 是各 TU 各一份——选错了会出现"改了一份、别处没变"。

    6. 类模板参数推导（CTAD）¶

    std::pair p{1, 2.0};             // std::pair<int, double>
std::vector v{1, 2, 3};          // std::vector<int>
std::lock_guard lg{mtx};         // 推导出 mutex 类型
std::optional o{42};             // std::optional<int>

// 老写法 / 工厂函数可以退休了：
// std::pair<int, double> p2 = std::make_pair(1, 2.0);
// auto v2 = std::vector<int>{1, 2, 3};

    坑：

    • 混类型会被提升成公共类型（实测 GCC 13 / Clang 18）：std::vector v{1, 2.0} 推导成 std::vector<double>（不是报错、也不是 vector<int>）；{1, 2u} → vector<unsigned>。类型不是自己想要的时候很难一眼看出——混类型时写清类型，或退回工厂函数
    • std::pair p{1, 2.0} 和 vector 不同：pair 的每个元素各推各的（pair<int, double>），不要求同类型
    • 需要"上下文"的地方推导不出来时，还得写显式类型
    • 自定义类想支持 CTAD 要写推导指引（deduction guide），普通使用不必深究

    7. 保证复制省略¶

    std::vector<int> make() {
    return std::vector<int>{1, 2, 3};    // 直接在调用方那儿构造，没有拷贝/移动
}

std::vector<int> v = make();             // 零拷贝、零移动

struct NoCopy {
    NoCopy() = default;
    NoCopy(const NoCopy&) = delete;      // 删掉拷贝也能返回！
};
NoCopy f() { return NoCopy{}; }          // C++17 起合法

    和 C++11/14 的区别：以前"省略构造"是允许（编译器可选），C++17 起对返回纯右值（prvalue）是强制的——这是语言规则，不是优化开关。

    实践：

    • 别写 return std::move(local);——它把局部变量变成右值引用，反而阻止 NRVO（命名返回值优化），是常见的性能反模式
    • 返回值直接用类型名构造（return std::vector<int>{...}），或 return local;（NRVO），两种都会被省略

    8. 嵌套命名空间¶

    namespace A::B::C {          // 等价于 namespace A { namespace B { namespace C {
    int value = 1;
}
}                            // }} 三层

namespace ABC = A::B::C;     // 命名空间别名（老特性）

    用处：库代码分层（company::project::detail）写起来清爽。注意：namespace A::B::C 这种写法只能用于定义，不能像 namespace A = B::C; 那样起别名。

    9. 新增属性标注¶

    [[nodiscard]] int compute();                       // 丢弃返回值（不接收结果）会警告
[[nodiscard("为什么不能丢")]] int must_use();      // C++20 起可带原因

[[maybe_unused]] int debug_flag = 0;               // 暂时没用到的变量，别报警告

switch (x) {
    case 1:
        do_one();
        [[fallthrough]];                            // 明确告诉编译器："穿透是故意的"
    case 2:
        do_two();
        break;
}

[[deprecated("改用 new_api()")]] void old_api();    // 用了就警告

    有用的场景：

    • [[nodiscard]] 用在"返回值必须检查"的函数上（错误码、optional）——对 C++17 的 std::optional 也能标在类型上
    • [[maybe_unused]] 常用于只在 debug 构建里使用的变量/参数
    • [[fallthrough]] 让"故意省略 break"不再被 -Wimplicit-fallthrough 警告

    标准库特性¶

    10. std::optional（可选值）¶

    #include <optional>

std::optional<int> parse_int(const std::string& s) {
    try {
        return std::stoi(s);
    } catch (...) {
        return std::nullopt;               // 明确表示"没有值"
    }
}

if (auto v = parse_int("42")) {
    std::cout << *v << '\n';               // 解引用取值
}
std::cout << parse_int("oops").value_or(-1);   // 无值 → -1

    它表达什么：一个值"可能有、可能没有"——比"返回 -1 表示失败"（哨兵值不通用）、比裸指针（所有权语义不清）都更准确。

    常用 API：has_value() / operator bool、value()、value_or(default)、*o / o->、reset()、emplace(...)、和 std::nullopt 比较。

    坑：

    • std::optional<bool> 有三种状态（true / false / 空）——当成 bool 用会踩"空也算 false"的坑
    • o.value() 在无值时会抛 std::bad_optional_access；不确定就用 value_or 或先判断
    • 大小：optional<T> 比 T 多一个 bool（还可能对齐填充）——大量元素时注意内存

    和异常怎么分工：可预期的失败（输入格式不对）用 optional / 错误码；不可恢复/调用方没法处理的才抛异常。

    11. std::variant（类型安全 union）¶

    #include <variant>

std::variant<int, double, std::string> v;
v = 1;                                    // 存 int
v = std::string("hello");                 // 换成 string（旧的被正确析构）

v.index();                                // 当前是第几个类型（下标）
std::holds_alternative<std::string>(v);   // 是不是某个类型
std::get<std::string>(v);                 // 取出（类型不符抛异常）

// 推荐：visit + 泛型 lambda，让编译器帮你穷举
std::visit([](auto&& x) {
    std::cout << x << '\n';
}, v);

    比 union 强在哪：union 不管构造/析构、也不记录"当前是哪个类型"；variant 自动管理生命周期，并且访问时能检查。

    访问的坑：std::get<T> 访问错误类型会抛 std::bad_variant_access 异常，先判断再取：

    // ❌ 危险：v 当前存的是 int，却按 double 取 → 抛异常
// double d = std::get<double>(v);

// 先判断：
if (std::holds_alternative<int>(v)) {
    int i = std::get<int>(v);
} else if (std::holds_alternative<double>(v)) {
    double d = std::get<double>(v);
}
// 或用 get_if（不抛异常，返回 nullptr）：
if (auto p = std::get_if<int>(&v)) { *p; }

    另一个坑：valueless_by_exception()——某个类型在构造/赋值时抛了异常，variant 可能处于"没有值"的状态（极少见，但检查一下更稳）。

    典型用途：JSON 的值、状态机（每个状态带不同数据）、解析结果。

    12. std::any（任意类型）¶

    #include <any>

std::any a = 1;
a = std::string("hello");
a = 3.14;

std::any_cast<std::string>(a);            // 类型不符 → 抛 std::bad_any_cast
if (auto p = std::any_cast<double>(&a)) { // 指针版：不抛，失败返回 nullptr
    std::cout << *p << '\n';
}
a.type() == typeid(double);               // 查当前类型

    什么时候用：类型信息只在运行时才确定、且没有固定集合的场合——配置系统、插件/脚本边界。

    尽量别用：

    • 类型错误只能在运行时发现（bad_any_cast）
    • 可能发生堆分配（小对象优化不保证）
    • 有固定类型集合时，variant + visit 更安全也更明确

    13. std::string_view（字符串视图，零拷贝）¶

    void log(std::string_view msg);            // 参数用 view：const char* / string / 字面量都能传

std::string s = "hello world";
std::string_view sv = s;                   // 不拷贝
sv.substr(0, 5);                           // 视图切片，O(1)（string::substr 是 O(n)）
sv.size(); sv[0]; sv.starts_with("he");    // C++20 的 starts_with；C++17 用 rfind/compare

    为什么用它做参数：const std::string& 遇到字符串字面量/const char* 会隐式构造临时 string（一次堆分配）；string_view 只存"指针 + 长度"，零拷贝。

    三个坑：

    1. 不拥有数据：源字符串销毁/被改后，view 就是悬垂指针 
      std::string_view bad() {
    std::string local = "temp";
    return local;                 // ❌ 悬垂！local 已经销毁
}
    2. 不保证 \0 结尾：传给 C API（printf、open）之前要 std::string(sv) 转一份，或确认来源
    3. data() 也可能悬垂：不要保存 const char* p = sv.data(); 再去用

    和 std::string 的转换：string → view 隐式；view → string 要显式构造（std::string(sv)，会拷贝）。

    14. std::filesystem（文件系统）¶

    #include <filesystem>
namespace fs = std::filesystem;

fs::path p = "/tmp/data/run1.txt";
p.filename();          // "run1.txt"
p.extension();         // ".txt"
p.parent_path();       // "/tmp/data"
p / "extra" ;          // 用 / 拼路径（跨平台）

fs::exists(p);                     // 是否存在
fs::is_directory(p);               // 是不是目录
fs::create_directories("/tmp/a/b/c");   // 逐级创建（已存在不报错）
fs::file_size(p);                  // 字节数
fs::absolute(p);                   // 绝对路径

// 遍历目录
for (auto& entry : fs::directory_iterator("/tmp")) {
    if (entry.path().extension() == ".txt") { /* ... */ }
}

    坑：

    • 老 GCC 要加 -lstdc++fs：GCC 8 及更早需要；GCC 9+ 不用。链接报一堆 std::filesystem::* 未定义符号时先想这条
    • 两套接口：抛异常版（fs::exists(p)）和无异常版（fs::exists(p, ec)，用 std::error_code）——系统调用失败很常见，工程代码建议用 ec 版
    • 路径拼接用 operator/，别手写字符串加 "/"（Windows 分隔符不同）

    15. 并行算法¶

    #include <algorithm>
#include <execution>
#include <vector>

std::vector<int> v = /* ... */;
std::sort(std::execution::par, v.begin(), v.end());    // 并行排序
std::for_each(std::execution::seq, v.begin(), v.end(), f);   // 串行（和普通版一样）
    策略 含义
    seq 串行
    par 多线程并行
    par_unseq 并行 + 允许乱序/向量化（里面不能加锁、不能分配内存，否则可能死锁）
    unseq 允许向量化（C++20）

    坑（本机实测，Ubuntu + GCC 13）：

    • 没有并行后端时会静默退化成串行：par 照样编译、链接、运行，但实际单线程跑——实测 2000 万随机数的 sort：par 用时 1.16s / CPU 108%，seq 1.15s / CPU 108%（24 核机器上一个核都没多占）。别以为写了 par 就并行了，要么测 CPU 占用，要么确认后端
    • libstdc++ 的并行后端是 TBB：需要 libtbb-dev + 链接 -ltbb（本机没装，也没启用 TBB 后端，所以退化了）
    • 数据竞争要自己保证：算法只负责调度，不会加锁
    • par_unseq 里不能加锁、不能分配内存（可能死锁）
    • 数据量小时并行反而慢（调度开销）；先测再换

    16. std::byte¶

    #include <cstddef>

std::byte b{0xFF};                      // 明确表示"一个字节"
int i = std::to_integer<int>(b);        // 转成整数（要显式）
b << 1;                                 // 位运算有定义
// int bad = b;                         // ❌ 不隐式转成算术类型

    和 char/unsigned char 的区别：char 有"字符"含义、还会隐式参与算术运算；std::byte 只表示原始位，不隐式转换——想表达"这是二进制数据"时语义更清楚。常用在协议/序列化代码里。

    17. std::clamp / std::gcd / std::lcm¶

    #include <algorithm>
#include <numeric>

int v = std::clamp(15, 0, 10);    // 15 夹到 [0, 10] → 10
std::gcd(12, 18);                 // 6（最大公约数）
std::lcm(4, 6);                   // 12（最小公倍数）

// 等价旧写法（要写两层 min/max，容易写反）：
int old = std::max(0, std::min(15, 10));

    坑：std::clamp(v, lo, hi) 要求 lo <= hi，否则是未定义行为（不是夹紧到某个方向）。传参顺序是"值、下界、上界"，别记反。

    18. std::scoped_lock（同时锁多个 mutex）¶

    std::mutex m1, m2;

{
    std::scoped_lock lock{m1, m2};    // 一次锁两个：内部用免死锁算法
    // 临界区
}                                     // 作用域结束自动解锁（RAII）

std::scoped_lock single{m1};          // 锁一个也行（等于 lock_guard）

    解决什么问题：两个线程分别按"先 m1 后 m2"和"先 m2 后 m1"加锁 → 死锁。scoped_lock 一次性加锁所有 mutex，避免这种交叉等待。

    和 lock_guard 的关系：scoped_lock 就是 lock_guard 的变参版；C++17 起新代码直接用 scoped_lock 即可（锁一个也用它）。

    19. std::shared_mutex（读写锁）¶

    #include <shared_mutex>

std::shared_mutex rw;
int data = 0;

// 多个读者可以同时进
{
    std::shared_lock read_lock{rw};    // 共享锁
    int copy = data;
}

// 写者独占
{
    std::unique_lock write_lock{rw};   // 独占锁
    ++data;
}

    什么时候用：读多写少（配置表、缓存）——读者之间不互斥，只有写者独占。

    注意：

    • 名字变化：C++14 是 shared_timed_mutex，C++17 才有不带 timed 的 shared_mutex
    • 不一定比普通 mutex 快：读者计数本身有开销；读操作很短时普通 mutex 可能更快，测了再选
    • 读者/写者饥饿行为由实现决定，不能假设公平

    20. std::apply（tuple 展开调函数）¶

    #include <tuple>

auto add = [](int a, int b) { return a + b; };
std::tuple<int, int> t{1, 2};
int r = std::apply(add, t);            // 等价于 add(1, 2) → 3

// 常用于"参数打包后统一转发"
template <typename F, typename... Args>
auto call_with_tuple(F&& f, const std::tuple<Args...>& args) {
    return std::apply(std::forward<F>(f), args);
}

    配套的还有 std::make_from_tuple<T>(t)：拿 tuple 当构造参数造对象。

    21. insert_or_assign / try_emplace¶

    std::map<std::string, std::string> m;

m.try_emplace("k", "v");        // key 不存在才构造插入；存在则什么都不做
m.insert_or_assign("k2", "v2"); // 存在则覆盖，不存在则插入

// 对比老写法 m["k"] = "v"：
//   operator[] 在 key 不存在时：先默认构造 value，再赋值 → 多一次构造
//   对"构造成本高"的 value 类型，try_emplace 更省

    区别：

    操作 key 已存在时 何时构造 value
    m[k] = v 覆盖 不存在时默认构造再赋值
    insert_or_assign 覆盖 只在需要时构造
    try_emplace 什么都不做 只在插入时构造
    emplace 什么都不做（但不检查 value 是否已构造，可能白构造） 可能先构造再发现重复

    顺带：C++17 还给 map 加了 extract / merge / node_handle（跨容器搬节点，不拷贝）。

    22. to_chars / from_chars（高性能数字转换）¶

    #include <charconv>

// 数字 → 字符串（写到缓冲区，不分配内存）
char buf[32];
auto res = std::to_chars(buf, buf + sizeof(buf), 12345);
if (res.ec == std::errc{}) {
    // 注意：string_view 的第二个参数是"长度"，不是结束指针
    std::string_view sv(buf, static_cast<std::size_t>(res.ptr - buf));   // "12345"
}

// 字符串 → 数字
int x = 0;
auto [p, ec] = std::from_chars(buf, res.ptr, x);
if (ec == std::errc{} && p == res.ptr) { /* 解析成功 */ }

    为什么不用 stoi / stringstream：

    • stoi 会构造 std::string（有分配）+ 受 locale 影响 + 靠异常报错
    • stringstream 更重（分配 + locale + 虚调用）
    • to_chars/from_chars 不分配、不看 locale、不抛异常——高频转换（日志、序列化）里差距明显

    坑：

    • 错误通过 std::errc 返回：std::errc::invalid_argument（格式错）/ std::errc::result_out_of_range（溢出）
    • 浮点支持较晚：GCC 11+ / Clang 14+ 才完整支持浮点的 to_chars/from_chars（老版本只能用整数版）
    • from_chars 不跳过前导空白、不解析 0x 前缀（只认十进制，除非指定 base）——比 stoi 严格
