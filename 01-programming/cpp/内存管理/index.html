    内存管理¶

    C++ 内存管理全貌：内存布局、new/malloc、泄漏检测，以及解决手动管理之痛的智能指针。

    1. 内存布局¶

    程序内存分几个区（高地址 → 低地址）：

    高地址
  栈          ← 局部变量、函数参数（自动管理，出作用域销毁）
  ↓
  （空闲区）
  ↑
  堆          ← new/malloc 分配（手动管理，要 delete/free）
  全局/静态区  ← 全局变量、static 变量（程序运行全程存在）
  常量区       ← 字符串字面量等（只读）
  代码区       ← 程序的机器指令
低地址

    int g = 1;                 // 全局区
static int s = 2;          // 全局区（静态）
const char* p = "hello";   // p 在栈，指向的 "hello" 在常量区

void f() {
    int local = 3;         // 栈
    int* h = new int(4);   // h 在栈，*h 在堆
}

    各区的特点：

    区 谁管理 生命周期 速度
    栈 编译器自动 出作用域销毁 快（移动栈指针）
    堆 手动 new/delete 手动控制 慢（系统调用）
    全局/静态 程序自动 程序全程 —

    栈溢出 vs 堆溢出：

    • 栈溢出：递归太深、函数里开超大局部数组 → 栈空间（默认约 8MB）耗尽
    • 堆溢出：不断 new 且不释放 → 堆空间耗尽

    堆碎片化（很少问）：频繁分配/释放大小不一的对象，堆上留下很多"小块空隙"——总空闲够，但连续空间不足，大对象分配失败。解决：内存池。

    2. new/delete vs malloc/free¶

    // C++ 方式：
int* p = new int(5);     // new：分配 + 调构造函数
delete p;                // delete：调析构函数 + 释放

// C 方式：
int* q = (int*)malloc(sizeof(int));   // malloc：只分配内存
*q = 5;
free(q);                 // free：只释放内存
    区别 new/delete malloc/free
    性质 运算符 函数
    构造函数/析构 ✅ 会调用 ❌ 不调用
    类型安全 ✅ 返回具体类型指针 ❌ 返回 void*，要强转
    失败 抛异常 std::bad_alloc 返回 NULL
    分配大小 编译器算（sizeof 自动） 手动指定字节数

    关键：new = 分配内存 + 调构造函数；malloc 只分配内存。所以 C++ 里必须用 new/delete（类对象要构造/析构）。

    new 失败的处理：new 失败默认抛异常 std::bad_alloc；加 std::nothrow 改为返回 nullptr：

    int* p = new (std::nothrow) int(5);
if (p == nullptr) { /* 分配失败，手动处理 */ }

    // malloc 的坑：类的构造函数没被调用！
std::string* s = (std::string*)malloc(sizeof(std::string));
// s 是未初始化的内存，用它 = 未定义行为！

    delete 的两条规则：

    1. delete 只能配 new（new[] 要配 delete[]，混用是未定义行为 ❌）
    2. 栈对象不用 delete，也不能 delete：局部对象离开作用域自动析构 ✅；对它 delete 是 UB ❌——实测：
    int x = 1;
delete &x;      // 编译期警告：-Wfree-nonheap-object
                // 运行期崩：munmap_chunk(): invalid pointer（进程中止）

    new 的三种形式¶

    int* p1 = new int(5);        // 单个对象，初始化为 5
int* p2 = new int[10];       // 数组（delete[] 释放）
int* p3 = new (buf) int;     // 定位 new（在指定内存上构造，几乎不用）

delete p1;
delete[] p2;                 // ⚠️ 数组必须 delete[]，否则未定义行为

    为什么数组必须 delete[]：delete 不知道指针指向的是"单个对象"还是"数组"，只知道析构一次。用 delete 释放数组 = 只析构第一个元素，剩下的元素和内存布局都乱套 → 未定义行为。

    3. 内存泄漏与检测¶

    常见泄漏场景¶

    // 1. 忘记 delete
void f() {
    int* p = new int(5);
    // 函数返回，p 销毁，但堆内存没人释放 → 泄漏
}

// 2. 异常提前退出
void g() {
    int* p = new int(5);
    throw std::runtime_error("error");   // 异常抛出，delete 没执行 → 泄漏
    delete p;                            // 永远不会执行
}

// 3. 悬垂指针（不是泄漏，但也是内存错误）
int* p = new int(5);
delete p;
*p = 1;              // ❌ p 已悬垂，解引用 = 未定义行为

    解决：全用智能指针（RAII 自动释放），上面 1、2 两个场景都不再泄漏。

    检测工具¶

    工具 用法 检测什么
    Valgrind valgrind --leak-check=full ./程序 内存泄漏、非法访问
    AddressSanitizer 编译加 -fsanitize=address 越界、悬垂、泄漏（更快） 
    # ASan 用法：
g++ -fsanitize=address -g main.cpp -o main
./main    # 有内存错误会直接报告位置

    4. 智能指针¶

    智能指针解决的是手动 new/delete 容易漏 delete 的问题（就是上面第 3 节那些坑）。核心思想是 RAII。

    4.1 RAII（资源获取即初始化）¶

    思想：把资源（内存、文件、锁）的生命周期，绑定到对象的生命周期。

    // 手动管理：容易忘 delete，导致泄漏
int* p = new int(5);
// ... 中间 return 或抛异常就漏了
delete p;

// RAII：对象析构自动释放
{
    std::unique_ptr<int> p = std::make_unique<int>(5);
    // 出作用域自动 delete，即使抛异常也安全
}

    本质：资源在构造函数里获取，在析构函数里释放。对象销毁 = 资源释放，不会漏。

    4.2 unique_ptr（独占所有权）¶

    特点：只能有一个 owner，不可拷贝，只能移动。

    std::unique_ptr<int> p1 = std::make_unique<int>(1);
std::unique_ptr<int> p2 = p1;       // ❌ 编译错误，不能拷贝
std::unique_ptr<int> p3 = std::move(p1);   // 移动，所有权转移，p1 变空

    为什么不可拷贝：拷贝构造和拷贝赋值被 = delete 了，因为"独占"不能有两个 owner。

    底层：就是裸指针的封装，零开销（大小和裸指针一样，8 字节）。

    自定义删除器：

    // 默认 delete，可自定义（比如关闭文件）
std::unique_ptr<FILE, decltype(&fclose)> f(fopen("a.txt", "r"), &fclose);

    4.3 unique_ptr 数组特化¶

    std::unique_ptr<int[]> arr = std::make_unique<int[]>(10);   // 自动 delete[]
arr[0] = 1;      // 只能下标访问，不能 *arr 解引用

    注意：make_unique<T[]> 是 C++14；unique_ptr<T[]> 不能传 make_unique<T>；不支持 * 解引用。

    4.4 reset / release / get 成员函数¶

    std::unique_ptr<int> p = std::make_unique<int>(5);

int* raw1 = p.get();      // 拿到裸指针，不释放所有权（别交给别的智能指针）
int* raw2 = p.release();  // 释放所有权，p 变空，raw2 必须手动 delete
p.reset(new int(6));      // 接管新资源，旧资源先析构
p.reset();                // 释放资源，p 变空
    • .get()：拿裸指针，不释放所有权；禁止把返回值再交给另一个智能指针
    • .release()：释放所有权，返回裸指针，对象不会析构（unique_ptr 独有，常见坑）
    • .reset(p)：接管新资源，旧资源析构

    4.5 shared_ptr（共享所有权）¶

    特点：多个 shared_ptr 可以指向同一个对象，引用计数管理。

    std::shared_ptr<int> s1 = std::make_shared<int>(5);
std::shared_ptr<int> s2 = s1;   // 引用计数 +1，现在 = 2
s1.reset();                     // 计数 -1，= 1
s2.reset();                     // 计数 -1，= 0，自动 delete

    4.6 控制块（Control Block）¶

    shared_ptr 内部有两部分：

    shared_ptr
├── 指针 → 指向对象
└── 控制块指针 → 引用计数 / 弱引用计数 / 删除器
    • 对象和控制块是分开分配的
    • 引用计数在控制块里，是原子操作（保证线程安全）

    4.7 make_shared vs new¶

    // 方式1：new，两次内存分配（对象 + 控制块）
std::shared_ptr<int> s1(new int(5));

// 方式2：make_shared，一次分配（对象和控制块一起）
std::shared_ptr<int> s2 = std::make_shared<int>(5);

    make_shared 更好：一次分配、缓存友好、异常安全。所以优先用 make_shared。

    补充：裸指针构造时，对象和控制块分离——即使对象销毁，只要还有 weak_ptr 存活，控制块仍占内存（要等 weak_ptr 也归零才释放）。make_shared 一次分配，对象和控制块一起销毁，无此问题。

    4.8 weak_ptr 与循环引用¶

    特点：不增加引用计数，观察对象是否还活着。

    std::shared_ptr<int> s = std::make_shared<int>(5);
std::weak_ptr<int> w = s;     // 不增加计数
s.reset();                     // 计数归零，对象销毁
// w.expired() == true，w.lock() 返回空

    循环引用问题：两个对象互相用 shared_ptr 引用，会永远无法释放：

    struct Node {
    std::shared_ptr<Node> next;
};

auto a = std::make_shared<Node>();
auto b = std::make_shared<Node>();
a->next = b;    // b 的计数 = 2（a 和 b 变量各一个）
b->next = a;    // a 的计数 = 2

// 作用域结束，a、b 变量销毁，但计数各 = 1（互相引用）
// → 永远不会到 0，内存泄漏！

    解决：用 weak_ptr 打破循环：

    struct Node {
    std::weak_ptr<Node> next;   // 改成 weak_ptr
};
// 作用域结束，计数归零，正常释放

    记忆：shared_ptr 是"拥有"，weak_ptr 是"借用/观察"。

    weak_ptr 的正确用法（lock）：

    // ❌ 不推荐：expired 和 lock 之间可能有竞态（对象被销毁）
if (!w.expired()) {
    auto s = w.lock();   // 多线程下，此时对象可能已销毁
}

// 推荐：直接 lock，判断是否空
if (auto s = w.lock()) {
    // 用 s，s 保证对象存活
}

    4.9 enable_shared_from_this¶

    问题：在类内部要获取自己的 shared_ptr 时，直接 shared_ptr<T>(this) 会创建新的控制块，导致重复计数、重复 delete。

    struct S : std::enable_shared_from_this<S> {
    std::shared_ptr<S> get() {
        return shared_from_this();   // 正确：返回已有的 shared_ptr
        // return std::shared_ptr<S>(this);  // ❌ 错误：新控制块
    }
};

    原理：enable_shared_from_this 内部存了一个 weak_ptr，shared_from_this() 通过它拿回正确的 shared_ptr。

    ⚠️ 重要前提：只有对象已经被 shared_ptr 管理时，才能调用 shared_from_this()。栈对象或裸 new 对象直接调用会崩溃：

    S s;
s.get();   // ❌ 崩溃！s 没有被 shared_ptr 接管

    4.10 线程安全¶

    • 引用计数：原子操作，线程安全（多个线程同时拷贝 shared_ptr 没问题）
    • 指向的对象：不是线程安全（多线程同时改对象数据要自己加锁）
    // 计数安全： 多线程拷贝 shared_ptr 安全
// 对象安全：❌ 多线程改 *ptr 要加锁

    4.11 常见坑¶

    1. 数组：std::shared_ptr<T[]> 是 C++17 才支持的；C++11/14 想管理数组，只能手写自定义删除器

    2. 不要裸指针和智能指针混用： 

      int* raw = new int(5);
std::shared_ptr<int> s1(raw);      // 第一次，计数=1
std::shared_ptr<int> s2(raw);      // ❌ 第二次，新控制块，会 double delete

    3. 循环引用（上面讲过）

    4. this 不要直接包 shared_ptr（用 enable_shared_from_this）
    5. 不要用 std::auto_ptr：C++17 已移除，拷贝语义有大坑（拷贝时偷偷转移所有权），仅作历史了解

    5. 要点回顾¶

    1. 内存分区：栈/堆/全局区/常量区，各放什么
    2. new vs malloc：new 是运算符（调构造、类型安全、抛异常），malloc 是函数（只分配）
    3. delete vs delete[]：数组必须 delete[]，混用是未定义行为
    4. 内存泄漏：忘 delete、异常提前退出；智能指针解决
    5. 智能指针三件套：unique_ptr（独占）→ shared_ptr（共享）→ weak_ptr（打破循环）
    6. 循环引用：shared_ptr 互指永不释放，weak_ptr 破解
    7. make_shared 优先：一次分配、异常安全
    8. 移动构造要 noexcept：vector 扩容敢用移动
