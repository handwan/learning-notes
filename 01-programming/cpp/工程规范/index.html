    工程规范¶

    写"工程级" C++ 的规范：const 正确性、异常安全、头文件管理、RAII 泛化。

    1. const 正确性¶

    原则：能加 const 就加——const 是"承诺不修改"，帮助编译器优化、帮调用者理解接口。

    class Widget {
public:
    // 成员函数：不修改对象就加 const
    int size() const { return size_; }

    // 参数：只读参数用 const 引用（避免拷贝 + 承诺不改）
    void process(const std::string& name);

    // 返回值：返回内部数据的只读视图
    const std::vector<int>& data() const { return data_; }

private:
    int size_;
    std::vector<int> data_;
};

    工程价值：

    • const 成员函数里不能改成员 → 调用者放心传入 const 对象
    • const& 参数 → 避免拷贝、表明只读
    • const 正确性是一致性工程：一处不加，处处传播（const 对象只能调 const 函数）

    2. 异常安全保证¶

    三种保证（见「异常处理」篇）在工程中的落地：

    强保证（事务性）实现：copy-and-swap¶

    class Container {
public:
    // 赋值：强保证——先拷贝，成功再替换（失败则原对象不变）
    Container& operator=(Container other) {   // 参数按值（拷贝一份）
        swap(*this, other);                    // 交换（不抛异常）
        return *this;
    }
    friend void swap(Container& a, Container& b) noexcept {
        std::swap(a.data_, b.data_);
    }
};

    要点：所有可能失败的操作（拷贝）在临时对象上做，成功后用 noexcept 的 swap 替换。

    工程实践¶

    1. 析构不抛异常（默认 noexcept）
    2. 移动构造/swap 加 noexcept（强保证依赖它）
    3. RAII 管理资源（异常时自动释放）
    4. catch 按引用（catch (const std::exception& e)）

    3. 头文件规范¶

    include-what-you-use（不要多包含）¶

    // ❌ 不需要 include 的场景：只用到自己类的指针/引用
#include "my_type.h"           // 若能前置声明，就别 include

// 前置声明（对象是"自己的类"时可用）
class MyType;                  // 前置声明：不 include 它的头
void process(const MyType& t); // 只用到引用 → 前置声明够

// ⚠️ 但 std 库类型不能前置声明（`class std::vector<int>;` 是错的），要老老实实 include

    规则：

    • 头文件里只包含真正需要的（"include what you use"）
    • 能前置声明就前置声明（尤其是指针/引用参数）

    前置声明优先¶

    // 头文件里只用到指针/引用 → 前置声明即可
class B;                  // 前置声明

class A {
    B* ptr_;              // 指针：前置声明够
    // B b_;              // ❌ 成员对象：需要完整定义（要 include）
};

    好处：减少头文件包含、加快编译、降低耦合。

    包含顺序（Google 规范）¶

    // 1. 对应的头文件（foo.h）
// 2. C 系统头文件
// 3. C++ 标准库头文件
// 4. 其他库头文件
// 5. 本项目头文件
// 好处：暴露隐藏依赖（自己的头文件放第一，缺什么立刻报错）

    头文件循环依赖¶

    // a.h 包含 b.h，b.h 包含 a.h → 循环依赖
// 解决：
// 1. 前置声明（能不用 include 就不用）
// 2. 把公共部分抽到第三个头文件

    4. RAII 泛化应用¶

    RAII 不只管内存——任何"需要配对操作"的资源都适用：

    资源 RAII 封装
    内存 unique_ptr / shared_ptr
    锁 lock_guard / unique_lock
    文件 std::fstream
    Socket 自定义 RAII 类
    数据库连接 连接池 + RAII 句柄 
    // 自定义 Socket 的 RAII：
class Socket {
    int fd_;
public:
    explicit Socket(int fd) : fd_(fd) {}
    ~Socket() { if (fd_ >= 0) close(fd_); }   // 自动关闭
    Socket(const Socket&) = delete;            // 不可拷贝
    Socket(Socket&& o) noexcept : fd_(o.fd_) { o.fd_ = -1; }   // 可移动
};

    核心思想："获取即初始化，析构即释放"——把 open/close、lock/unlock、new/delete 的配对交给构造函数/析构函数，异常安全、不会漏。

    5. 其他工程建议¶

    1. 用 nullptr 不用 NULL/0
    2. 用 auto 简化类型（但不滥用）
    3. override / final 显式标注（防意外重载失败）
    4. enum class 而非裸 enum（类型安全）
    5. {} 初始化（避免窄化、防歧义）
    6. nullptr / const / noexcept 该加就加
    7. 优先智能指针/容器（零法则）

    6. 框架怎么选¶

    工程的一半是"能证明它是对的"：单元测试、sanitizer、微基准。

    框架 特点 适用
    GoogleTest 功能全（夹具/参数化/死亡测试）、CMake 集成成熟 主流选择
    doctest 单头文件、编译快 小项目、嵌入式
    Catch2 语法自然，v3 需要编译 中小项目

    7. GoogleTest 基本用法¶

    #include <gtest/gtest.h>

int add(int a, int b) { return a + b; }

TEST(MathTest, AddWorks) {          // TEST(测试组, 用例名)
    EXPECT_EQ(add(1, 2), 3);        // 失败继续跑
    ASSERT_GT(add(2, 2), 3);        // 失败直接返回本用例
}

    夹具（Fixture）：多个测试共享初始化：

    class VecTest : public ::testing::Test {
protected:
    void SetUp() override { v = {1, 2, 3}; }   // 每个 TEST_F 前执行
    std::vector<int> v;
};

TEST_F(VecTest, SizeIsThree) {                 // 用夹具要用 TEST_F
    EXPECT_EQ(v.size(), 3u);
}

    参数化（一份逻辑跑多组数据）：

    class SquareTest : public ::testing::TestWithParam<std::pair<int, int>> {};

TEST_P(SquareTest, Computes) {
    auto [in, expected] = GetParam();
    EXPECT_EQ(in * in, expected);
}

INSTANTIATE_TEST_SUITE_P(Squares, SquareTest,
    ::testing::Values(std::pair{1, 1}, std::pair{2, 4}, std::pair{3, 9}));

    8. CMake 集成（FetchContent）¶

    cmake_minimum_required(VERSION 3.14)
project(demo CXX)
set(CMAKE_CXX_STANDARD 17)

include(FetchContent)
FetchContent_Declare(googletest
    GIT_REPOSITORY https://github.com/google/googletest.git
    GIT_TAG        v1.15.2)
set(gtest_force_shared_crt ON CACHE BOOL "" FORCE)   # Windows 上避免 CRT 冲突
FetchContent_MakeAvailable(googletest)

enable_testing()
add_executable(tests test_math.cpp)
target_link_libraries(tests PRIVATE GTest::gtest_main)

include(GoogleTest)
gtest_discover_tests(tests)      # 让 ctest 能看到每个 TEST

    cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
ctest --test-dir build --output-on-failure

    已装好 gtest 的环境（系统包 / vcpkg / conan）用 find_package(GTest REQUIRED) + 链接 GTest::gtest_main 即可。

    注意：FetchContent 是从网络拉源码构建（国内网络可能很慢或失败）——离线环境先装好再 find_package，或在公司内网镜像仓库。

    9. sanitizer 进测试¶

    编译期打开 sanitizer，让测试顺便抓越界 / UB / 泄漏：

    option(SANITIZE "Enable ASan+UBSan" OFF)
if(SANITIZE)
    add_compile_options(-fsanitize=address,undefined -fno-omit-frame-pointer -g)
    add_link_options(-fsanitize=address,undefined)
endif()

    cmake -B build-asan -DSANITIZE=ON
cmake --build build-asan -j
ctest --test-dir build-asan --output-on-failure

    CI 里跑两份：普通 build + sanitizer build。

    10. 微基准¶

    和单元测试分开——基准不进 ctest（耗时、受机器负载影响）。

    Google Benchmark：

    #include <benchmark/benchmark.h>
#include <numeric>
#include <vector>

static void BM_Sum(benchmark::State& state) {
    std::vector<int> v(static_cast<size_t>(state.range(0)), 1);
    for (auto _ : state) {                       // 框架自动重复跑
        int s = std::accumulate(v.begin(), v.end(), 0);
        benchmark::DoNotOptimize(s);             // 防止整段被优化掉
    }
    state.SetItemsProcessed(state.iterations() * state.range(0));
}
BENCHMARK(BM_Sum)->Arg(1000)->Arg(100000);
BENCHMARK_MAIN();

    手写最简版（不想引库时）：

    #include <chrono>

auto t0 = std::chrono::steady_clock::now();
// ... 被测代码 ...
auto t1 = std::chrono::steady_clock::now();
// 耗时 = t1 - t0；注意结果要"用掉"，否则可能被优化掉

    规则：

    • 用 -O2/-O3 测（-O0 的数字没有意义）
    • 输入规模、数据分布固定；跑多次看中位数/方差，不看单次
    • 先 perf 找热点，再用微基准验证改动——别反过来
    • 开 -march=native 的结果不能代表部署机器的表现

    11. 测试写什么¶

    • 测行为，不测实现：重构不应该炸测试
    • 边界优先：空 / 0 / 最大值 / 重复 / 异常路径
    • 一个用例一个主题；名字说清"在什么条件下期望什么"
    • 修一个 bug 补一个回归用例
    • 夹具 + 参数化替代复制粘贴

    12. 要点回顾¶

    1. const 正确性：能加就加（成员函数、参数、返回值）
    2. 异常安全落地：copy-and-swap 实现强保证、RAII、移动 noexcept
    3. 头文件：include-what-you-use、前置声明优先、包含顺序、防循环依赖
    4. RAII 泛化：不只内存，锁/文件/socket 都用 RAII
    5. 现代 C++ 习惯：nullptr、auto、override、enum class、大括号初始化
    6. 框架：gtest（主流）/ doctest（单头、小项目）/ Catch2
    7. gtest：TEST / TEST_F（夹具）/ TEST_P（参数化）；EXPECT_* 失败继续、ASSERT_* 失败返回
    8. CMake 集成：FetchContent 拉 gtest → 链接 GTest::gtest_main → gtest_discover_tests 接 ctest；离线环境用 find_package
    9. sanitizer 跑测试：-fsanitize=address,undefined；CI 里普通 + sanitizer 两份
    10. 微基准：Google Benchmark 或手写 chrono；必须 DoNotOptimize 防优化；别用 -O0
    11. 顺序：先 perf 找热点 → 改 → 微基准验证
    12. 测试写行为不写实现；修 bug 补回归用例
