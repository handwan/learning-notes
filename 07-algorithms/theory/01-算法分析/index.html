    算法分析¶

    算法分析回答两个问题：它对不对、它要多少资源。复杂度只是第二问的一部分，不能替代正确性。

    O/Ω/Θ 的定义、常见增长量级、均摊细节见 复杂度与均摊分析；这里讲怎么分析一个算法。

    1. 先证正确，再算代价¶

    一个算法跑得快，但结果是错的，分析没有意义。常见证明方法：

    循环不变式¶

    以数组求和为例：

    s = 0
for i = 0 .. n-1:
    s += a[i]

    循环不变式：每轮开始前，s 等于 a[0..i-1] 的和。

    证明分三步：

    1. 初始化：i=0 时，s=0，空数组和为 0
    2. 保持：假设第 i 轮前成立，加上 a[i] 后，第 i+1 轮前仍成立
    3. 终止：循环结束时 i=n，所以 s 是 a[0..n-1] 的和

    三步缺一不可。只写“显然成立”不算证明。

    递归与归纳¶

    递归算法通常对输入规模做归纳：

    • 基础情况：n=0 或 n=1 时成立
    • 归纳假设：所有小于 n 的输入成立
    • 归纳步骤：证明规模 n 时成立

    归并排序、二分查找、树上的递归都可以这样证。

    贪心：交换论证¶

    要证明贪心选择不劣于最优解：

    1. 取一个最优解
    2. 如果它不含贪心选择，把某一步替换成贪心选择
    3. 证明替换后仍然最优（或不会更差）
    4. 反复替换，得到包含贪心选择的最优解

    区间调度、Huffman、有些最小生成树证明都走这个套路。

    动态规划：最优子结构与无后效性¶

    • 最优子结构：大问题的最优解包含子问题的最优解
    • 无后效性：当前状态确定后，后续只依赖状态，不依赖到达它的路径
    • 覆盖所有选择：转移方程必须枚举最后一步的所有可能

    如果转移漏了一种选择，即使代码能跑，答案也可能是错的。

    反例也是分析¶

    证不出来时，先试小数据：

    • 空输入
    • 一个元素
    • 全部相同
    • 已排序 / 逆序
    • 有重复值
    • 极值 / 溢出边界

    一个合法反例就能推翻算法，比继续“感觉对”有用。

    2. 资源模型¶

    输入规模¶

    先定义 n 是什么：

    • 数组：元素个数
    • 字符串：字符数
    • 图：点数 V、边数 E（两个参数）
    • 矩阵：行数 × 列数
    • 整数：通常按二进制位数，而不是数值大小

    输入规模定义不同，复杂度会完全不同。

    三种常见口径¶

    口径 含义 用途
    最坏情况 所有规模 n 的输入中，代价最大的 给保证
    平均情况 确定性算法按输入分布取期望 分析实际表现
    均摊 任意 n 次操作的总代价 ÷ n 给序列保证

    均摊不是平均：均摊是对操作序列的数学保证，不需要输入分布；平均需要假设分布。细节见复杂度与均摊分析。

    均摊常用三种证法：

    方法 做法
    聚合 算 n 次操作的总代价，再除以 n
    记账 便宜操作存“信用”，贵操作消耗信用
    势能 定义势函数 Φ，摊还代价 = 实际代价 + ΔΦ

    RAM 模型¶

    基础分析通常假设：

    • 基本算术、比较、赋值是 O(1)
    • 随机访问内存是 O(1)
    • 不考虑 cache、分支预测、内存分配

    这个模型适合比较数量级；真实性能还要看常数、缓存、分配。先用它筛掉量级不对的算法，再做实测。

    数主导操作¶

    不要数代码行，数执行次数最多的操作：

    for i in 0..n-1:
    for j in 0..n-1:
        if a[i] + a[j] == target:
            ...

    比较执行 n² 次，所以是 O(n²)，即使函数体只有一行。

    3. 递归式¶

    递归算法写成：

    T(n) = a·T(n/b) + f(n)
    • a：子问题个数
    • n/b：子问题规模
    • f(n)：分解与合并的代价

    代入法¶

    先猜答案，再用归纳证明。

    二分查找：

    T(n) = T(n/2) + O(1)

    猜 T(n) = O(log n)：

    T(n) ≤ c·log(n/2) + d
     = c·log n - c + d
     ≤ c·log n        （取 d ≤ c）

    递归树¶

    把每层代价加起来。

    归并排序：

    T(n) = 2T(n/2) + O(n)

    第 0 层：n
第 1 层：n
...
第 log n 层：n
总代价：n · log n

    主定理¶

    对 T(n) = aT(n/b) + f(n)，令 c = log_b a，比较 f(n) 和 n^c：

    情况 条件 结果
    1 f(n) = O(n^(c-ε))，ε>0 Θ(n^c)
    2 f(n) = Θ(n^c) Θ(n^c log n)
    3 f(n) = Ω(n^(c+ε))，且 a·f(n/b) ≤ k·f(n)，k<1 Θ(f(n))

    例子：

    递归式 结果
    T(n)=2T(n/2)+n Θ(n log n)
    T(n)=T(n/2)+1 Θ(log n)
    T(n)=2T(n/2)+n² Θ(n²)
    T(n)=T(n-1)+n Θ(n²)，不适用主定理
    T(n)=2T(n-1)+1 Θ(2^n)，不适用主定理

    主定理不是万能的：子问题规模不整齐、f(n) 落在间隙里、带根号/对数因子时，还是要画递归树或代入。

    4. 下界¶

    下界回答：在给定计算模型下，这个问题最少要多少代价，而不是某个算法多快。

    比较排序的下界¶

    比较排序只能通过“比较两个元素”获得信息。n 个不同元素有 n! 种排列，决策树至少有 n! 个叶子：

    高度 h 的二叉树最多 2^h 个叶子
2^h ≥ n!
h ≥ log2(n!)
  = Ω(n log n)

    所以任何基于比较的确定性排序，最坏情况都至少 Ω(n log n)。归并排序、堆排序达到这个下界，因而是最优的（数量级意义下）。

    对手论证¶

    对手每次选择比较结果，让算法保留尽可能多的可能性；只要还有多种可能，就不能确定答案。下界证明常用这种思路。

    下界不等于 NP 难¶

    • 下界：在给定计算模型下，某个问题所有算法的最低代价
    • NP 难：所有 NP 问题都能归约到它；若 P≠NP，则通常认为它没有多项式算法

    两者不是一回事。说“排序下界是 Ω(n log n)”是严格结论；说“这个问题 NP 难”并不自动给出一个具体的下界。

    5. 概率分析¶

    随机化算法把随机性放进算法本身，期望是对算法抛硬币取，不是对输入分布取。

    随机快排¶

    每次随机选 pivot：

    • 最坏：O(n²)（极端分割）
    • 期望：O(n log n)
    • 空间：期望递归栈 O(log n)，最坏 O(n)

    期望分析的关键是：任意一对元素被比较的概率，与它们之间的元素个数有关；总期望比较次数是 O(n log n)。

    哈希表¶

    在简单均匀哈希假设下，负载因子 α = n/m：

    • 查找平均 O(1 + α)
    • 负载因子控制在常数，平均就是 O(1)
    • 最坏：所有键冲突，O(n)

    “哈希查找 O(1)”严格说是平均/期望 O(1)，不是最坏保证。对手可以构造冲突。

    期望与高概率¶

    • 期望 O(f(n))：平均意义上
    • 以高概率 O(f(n))：失败概率随 n 增大而快速下降，更强的保证

    有些算法期望很好，但偶尔会非常慢；工程上要看尾部风险。

    6. 空间复杂度¶

    空间复杂度通常指额外空间，不包括输入本身；要明确口径。

    算法 额外空间
    原地快排 期望 O(log n) 栈，最坏 O(n)
    归并排序（数组） O(n)
    堆排序 O(1)
    DFS O(V) 栈/标记
    BFS O(V) 队列
    DP 滚动数组 从 O(n²) 降到 O(n)

    递归不是“免费”的：每层调用都占栈空间。递归深度 n 时，空间至少 O(n)。

    时间与空间经常互换：

    • 空间换时间：DP 表、哈希、索引、缓存
    • 时间换空间：滚动数组、原地算法、重复计算

    7. 分析流程¶

    1. 定义输入规模
    2. 选模型：最坏 / 平均 / 均摊
    3. 数主导操作，写循环或递归式
    4. 解递归式：主定理 / 递归树 / 代入
    5. 检查边界：空输入、重复、极值、溢出
    6. 再谈常数：cache、分配、STL 开销

    8. 常见坑¶

    • 隐藏循环：字符串反复拼接、vector::insert(begin(), ...) 头插、erase 中间元素，都可能把 O(n) 变成 O(n²)
    • STL 不是免费：map 查找 O(log n)，unordered_map 平均 O(1)、最坏 O(n)
    • 递归栈：深度太大不是复杂度问题，是直接栈溢出
    • 哈希最坏情况：平均 O(1) 不等于任何输入都 O(1)
    • 忽略常数：同是 O(n)，数组和链表能差数倍；先筛量级，再看常数
    • 输入规模搞错：图的 O(V+E) 不能写成 O(n) 而不说明 n 是什么
    • 数学溢出：复杂度没问题，结果已经错了；计数、乘法、叉积要注意范围

    9. 要点回顾¶

    1. 先正确，再分析：循环不变式、归纳、交换论证、反例
    2. 三种口径：最坏给保证，平均要分布，均摊给序列保证；均摊可用聚合/记账/势能证明
    3. 递归式：主定理看 f(n) 与 n^(log_b a)；不适用就画树/代入
    4. 比较排序下界：Ω(n log n)，来自 n! 个叶子的决策树
    5. 随机化期望：随机快排期望 O(n log n)，最坏仍是 O(n²)
    6. 哈希平均 O(1)：依赖均匀哈希和负载因子，最坏 O(n)
    7. 空间要算栈：递归深度、BFS 队列、DP 表都要记账
    8. 复杂度不是全部：常数、缓存、分配、溢出都会影响真实表现
