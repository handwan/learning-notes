    字符串¶

    字符串问题的类型比“匹配一个子串”多得多：

    • 查找/匹配：子串、前缀、后缀
    • 统计：频率、异位词、去重
    • 回文：中心扩展、Manacher、DP
    • 字典：Trie、前缀查询
    • 变换：编辑距离、LCS、分割
    • 工程：拼接、切片、编码、不可变性

    先选工具，再写代码。KMP 的教材推导见 串与模式匹配。

    1. 表示与工程细节¶

    字节，不是字符¶

    C++ std::string 是字节序列：

    std::string s = "你好";
s.size();       // UTF-8 下通常是 6，不是 2
s[0];           // 第一个字节，不是第一个汉字
    • ASCII 场景：一个 char 一个字符
    • UTF-8/Unicode：一个字符可能多个字节；按下标切可能切坏编码

    需要按 Unicode 字符处理时，用专门的库；不要直接假设 size() 是字符数。

    char 的符号¶

    char 是否有符号由实现决定。把 s[i] 当下标或传给 tolower 时，先转 unsigned char：

    unsigned char c = static_cast<unsigned char>(s[i]);

    否则负值可能越界/未定义。

    拼接与切片¶

    s += c;             // 均摊 O(1)
s = s + c;          // 可能每次复制整个 s，循环里 O(n²)
s.substr(l, len);   // 返回新字符串，O(len)

    大量切片/查找可以用 std::string_view（C++17），但要保证原字符串活得比 view 久。

    2. 朴素匹配¶

    逐个起点比较：

    for i = 0 .. n-m:
    j = 0
    while j < m and s[i+j] == p[j]: j++
    if j == m: 找到一个匹配
    • 最坏 O(nm)
    • 最好 O(n)
    • 空间 O(1)

    短字符串、一次性匹配够用；长文本/重复模式需要 KMP、哈希或自动机。

    3. KMP¶

    KMP 的核心是 前缀函数 pi[i]：

    p[0..i] 的最长真前缀，同时是它的后缀的长度。

    vector<int> prefix_function(const string& p) {
    int m = p.size();
    vector<int> pi(m, 0);
    for (int i = 1; i < m; ++i) {
        int j = pi[i-1];
        while (j > 0 && p[i] != p[j]) j = pi[j-1];
        if (p[i] == p[j]) ++j;
        pi[i] = j;
    }
    return pi;
}

    匹配：

    int j = 0;
for (int i = 0; i < n; ++i) {
    while (j > 0 && s[i] != p[j]) j = pi[j-1];
    if (s[i] == p[j]) ++j;
    if (j == m) {
        // 匹配位置 i-m+1
        j = pi[j-1];       // 继续找重叠匹配
    }
}
    • 时间 O(n+m)
    • 空间 O(m)
    • 适合单模式、长文本、重叠匹配

    pi 还可以求：

    • 最小循环节：m - pi[m-1]（能整除 m 时）
    • 所有 border
    • 字符串周期

    4. Z 函数¶

    z[i] = s 与 s[i..] 的最长公共前缀长度。

    • 时间 O(n)
    • 适合“每个后缀与原串的 LCP”
    • 也可以做模式匹配：p + '#' + s，找 z[i] == p.size()；分隔符不能出现在 p 或 s 中

    KMP 和 Z 都能线性匹配；KMP 的前缀函数更常用于周期/border，Z 更直观地表达“后缀与原串的 LCP”。

    5. 滚动哈希¶

    把字符串看成一个多项式：

    hash(s) = s[0]·B^(m-1) + s[1]·B^(m-2) + ... + s[m-1]  (mod M)

    前缀哈希：

    h[i+1] = (h[i] * B + s[i]) % M

    子串 [l, r) 的哈希：

    h[r] - h[l] * B^(r-l)   (mod M)

    用途：

    • O(1) 判断子串相等
    • 最长重复子串、回文（正反哈希）
    • Rabin-Karp 匹配

    碰撞¶

    哈希是概率性的：

    • 单模数可能碰撞
    • 双模数/64 位自然溢出降低概率，但不能数学保证
    • 对手可以构造碰撞；安全场景不要用

    需要确定性时，匹配后逐字符验证，或用 KMP/Z。

    实现细节¶

    • 字符值先转 unsigned char
    • B 选大于字符集大小的奇数/质数
    • 模数选大质数
    • 乘法可能溢出，必要时 __int128
    • 子串哈希要处理负数：(x % M + M) % M

    6. Trie¶

    Trie（前缀树）适合“很多字符串的插入/前缀查询”。

    struct Node {
    int child[26];
    bool is_end;
    Node() : is_end(false) { fill(begin(child), end(child), -1); }
};

void insert(const string& s) {
    int u = 0;
    for (char ch : s) {
        int c = ch - 'a';
        if (trie[u].child[c] == -1) {
            trie[u].child[c] = trie.size();
            trie.emplace_back();
        }
        u = trie[u].child[c];
    }
    trie[u].is_end = true;
}

    查询：

    从根走每个字符
走不动：不存在
走完：is_end 表示完整单词存在
    • 插入/查询 O(L)
    • 空间 O(总字符数 × 字母表)；26 个 int 每节点很占内存
    • 字符集大/稀疏时用 unordered_map<char,int> 或压缩
    • 前缀查询、自动补全、词典、IP 路由

    变体：

    • 压缩 Trie / Radix Tree：合并单链
    • AC 自动机：Trie + fail 指针，多模式匹配

    7. 回文¶

    中心扩展¶

    每个中心向两边扩：

    for center in 0..n-1:
    扩展奇数长度（中心是一个字符）
    扩展偶数长度（中心在两个字符之间）
    • 时间 O(n²) 最坏
    • 空间 O(1)
    • 实现简单，短字符串够用

    Manacher¶

    中心扩展要分别处理奇数和偶数中心；Manacher 用分隔符统一：

    s = "abba"
t = "^#a#b#b#a#$"

    p[i] 表示以 t[i] 为中心的回文半径。维护当前最右回文边界 [center, right]：

    for i in 1 .. len(t)-2:
    if i < right:
        p[i] = min(right - i, p[2*center - i])
    while t[i-p[i]-1] == t[i+p[i]+1]:
        p[i]++
    if i + p[i] > right:
        center = i
        right = i + p[i]
    • 时间 O(n)：每个位置最多被扩展一次
    • 空间 O(n)
    • max(p) 就是原串最长回文长度
    • ^ / $ 是哨兵，避免边界判断

    回文 DP¶

    dp[i][j] 表示 s[i..j] 是否回文：

    s[i] == s[j] && (j-i < 2 || dp[i+1][j-1])

    按区间长度遍历。适合分割回文串、回文子串计数。

    8. 频率、异位词、滑动窗口¶

    小写字母固定 26 个时，用数组比哈希表快：

    int cnt[26] = {};
for (char c : s) ++cnt[c - 'a'];

    常见问题：

    • 异位词：排序比较，或频率数组
    • 字母异位词分组：频率编码作为 key
    • 最小覆盖子串：滑动窗口 + 频率差
    • 无重复最长子串：滑动窗口 + 最后出现位置

    Unicode/大小写混合时，先用库做规范化，不要直接 c - 'a'。

    9. 字符串 DP¶

    字符串二维 DP 的常见状态：

    问题 状态 转移
    LCS dp[i][j] 前 i/前 j 相等取对角 +1，否则 max
    编辑距离 dp[i][j] 插入/删除/替换
    回文子序列 dp[i][j] 两端相等/不等
    通配符/正则 dp[i][j] 看 * 分支
    交错字符串 dp[i][j] 从两个串各取一个

    细节见动态规划。

    10. 高级结构（可选）¶

    • 后缀数组：所有后缀排序，支持子串查找、LCP
    • 后缀自动机：子串统计、最长公共子串
    • AC 自动机：多模式匹配
    • Boyer-Moore：长模式、实际很快，但最坏分析复杂

    这些是专项，不建议一开始就写。

    11. 复杂度与选型¶

    问题 工具 复杂度
    单模式匹配 朴素 最坏 O(nm)
    单模式匹配 KMP O(n+m)
    单模式匹配 滚动哈希 平均 O(n+m)，概率
    多模式匹配 AC 自动机 O(总长 + 匹配数)
    前缀查询 Trie O(L)
    子串相等 哈希 O(1)
    最长回文 中心扩展 O(n²)
    最长回文 Manacher O(n)
    编辑距离 DP O(nm)

    12. 常见坑¶

    • 把 std::string::size() 当成 Unicode 字符数
    • 循环里 s = s + c，变成 O(n²)
    • substr 在循环里大量拷贝
    • char 负值直接做数组下标/传给 tolower
    • KMP 匹配成功后忘记 j = pi[j-1]，漏掉重叠匹配
    • KMP 的 pi 定义成“包含自身的 border”，导致边界错
    • 哈希单模数碰撞，或子串哈希没处理负数
    • 用哈希做安全校验
    • Trie 每个节点开 26 个 int，内存爆掉
    • 回文中心扩展忘记偶数长度
    • 字符串 DP 的 i-1/j-1 和 1-based 混用
    • 大小写/Unicode 规范化没做，异位词判断错

    13. 要点回顾¶

    1. 字符串是字节序列：size() 不一定是字符数；char 可能带符号
    2. 朴素匹配最坏 O(nm)；KMP/Z 线性，哈希平均线性但有碰撞
    3. KMP 前缀函数：最长 border；匹配成功后跳 pi[j-1]
    4. Trie：前缀查询 O(L)，空间看字母表和节点数
    5. 滚动哈希：子串 O(1)，但要处理碰撞、溢出、负值
    6. 回文：中心扩展简单，Manacher 线性，DP 适合分割/计数
    7. 频率数组：小写字母场景比哈希表快；Unicode 要先规范化
    8. 字符串 DP：LCS/编辑距离/回文/通配符都是二维状态
