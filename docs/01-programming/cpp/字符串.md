# 字符串

std::string 的底层（SSO）、常用操作、string_view，以及几个真会踩的坑（生命周期、编码、性能）。

> 本文按“常用 + 易错”组织，不是 API 全量；完整接口查 cppreference。

## 1. SSO（短字符串优化）

**问题**：`std::string` 对象本身有多大？如果它总是"指针 + 长度 + 容量"，那每个 string 都要堆分配，短字符串开销大。

**SSO 答案**：短字符串**直接存在 `std::string` 对象内部**（随对象所在存储；局部对象才在栈上），超过阈值才堆分配：

```cpp
// std::string 对象内部（简化）：
// union {
//     char buf[16];          // 短字符串：直接放对象内部
//     char* ptr;             // 长字符串：指向堆
// };
// size_t size, capacity;

std::string s1 = "hi";          // 短：存在对象内部，无堆分配
std::string s2(1000, 'a');      // 长：堆分配

sizeof(std::string);            // 常见是 32（GCC/libstdc++），不管多长都一样
```

**关键**：`sizeof(std::string)` 是固定的（对象本身大小），和字符串多长无关；数据要么在对象内（短），要么在堆上（长）。

**常见问题**："string 有多长时开始堆分配？"——答：超过 SSO 容量（libstdc++ 是 15 个 char）才堆分配。

## 2. 常用操作

```cpp
std::string s = "hello";
s.size();                    // 长度（字节数，不是字符数！）
s += " world";               // 拼接
s.substr(0, 5);              // 子串（返回新 string，拷贝！）
s.find("ll");                // 查找，返回位置或 npos
s.contains("ll");            // C++23，判断包含（C++20 用 find）
s.starts_with("he");         // C++20
s.ends_with(".cpp");         // C++20
s == "hello";                // 比较
s.c_str();                   // 转 C 风格字符串（给 C 接口用）

std::getline(std::cin, s);   // 读整行（保留空格；<iostream>）
s.append("!");               // 尾部追加
s.insert(0, ">> ");          // 指定位置插入
s.erase(0, 3);               // 删除区间
s.replace(0, 2, "xx");       // 替换
s.reserve(100);              // 预分配容量
s.shrink_to_fit();           // 请求释放多余容量
```

**注意**：`s.size()` 返回**字节数**（不关心编码）；如果内容是 UTF-8，常见汉字通常占 3 字节，扩展区/emoji 可能占 4 字节，不是字符个数。

## 3. std::string_view（零拷贝视图）

```cpp
std::string s = "hello world";
std::string_view sv = s;      // 不拷贝，只记录指针+长度

sv.substr(0, 5);              // 视图切片，零拷贝（string 的 substr 是拷贝！）
sv == "hello";                // 直接比较
sv.starts_with("he");         // C++20
sv.ends_with("ld");           // C++20
sv.remove_prefix(1);          // 去掉开头 1 个字符（只改 view）
sv.remove_suffix(1);          // 去掉末尾 1 个字符

// ⚠️ 注意：sv 不拥有数据，源字符串销毁后 sv 悬垂！
```

**对比**：

| | string::substr | string_view::substr |
|--|---------------|--------------------|
| 拷贝 | ✅ 拷贝新字符串 | ❌ 零拷贝 |
| 用途 | 需要独立字符串 | 只读、传递参数 |

C++17 篇有 string_view 的特性索引；这里讲使用和生命周期。

**注意**：`sv.data()` 不保证以 `'\0'` 结尾；不能直接传给 `printf("%s")` 或要求 C 字符串的接口。需要时构造 `std::string(sv)`，或确保 view 覆盖到源串末尾。

## 4. 生命周期：两个真会踩的坑

**① `c_str()` / `data()` 的指针会失效** ❌——之后只要发生**非 const 修改**（`+=`、`append`、`insert`、`erase`、`replace`、`resize`、`reserve`…），指针就不再保证有效；可能重新分配时直接悬垂：

```cpp
std::string s(100, 'a');
const char* p = s.c_str();
s += std::string(1000, 'b');   // 重新分配 → p 悬垂
printf("%c", p[0]);            // UB
```

实测（ASan）：`heap-use-after-free` ❌。**规则**：`c_str()` 的结果只在**下一次修改前**有效；马上用，修改后重新取。

**② `string_view` 不拥有数据**——三种高风险用法：

- 返回**局部 string** 的 view：函数一返回就悬垂
- 存成成员变量 / 跨语句长期持有：只有能保证源串生命周期覆盖 view、且期间不改源串时才安全；否则悬垂
- 指向临时对象（如 `string_view sv = s + "x";`）：语句结束就悬垂

另外，view 存活期间修改源串（`+=`、`reserve`、`clear`、`erase`…）也可能让 view 悬垂或长度失真。

实测（ASan）：同样 `heap-use-after-free` ❌。**安全用法**：只在"源串还活着"的作用域里当只读参数 ✅。

## 5. 编码：`size()` 是字节，不是字符

```cpp
std::string zh = "中文ab";
zh.size();          // 8 —— 2 个中文 × 3 字节 + 2
zh[0];              // 0xE4 —— 只是"中"的第一个字节，不是字符 ❌
zh.substr(0, 1);    // 切出半个"中"（坏掉的 UTF-8 ❌）
```

- ASCII 下"字节 = 字符"，UTF-8 下**必须区分**
- 常见汉字通常 3 字节；扩展区/emoji 可能 4 字节
- 按字符处理要自己解析 UTF-8（看首字节判长度）或用库；C++20 有 `char8_t`/`u8string`（但它仍是**字节序列**）
- 常见翻车：`size()` 当字数、`substr` 按字节截断中文 ❌

## 6. 拷贝与拼接的性能

| 写法 | 复杂度 | 说明 |
|------|:---:|------|
| `s = s + c` | O(n²) | 每轮创建临时串并拷贝 |
| `s += c` | 摊还 O(1) | 容量够时不搬数据 |
| `s.reserve(n)` + `s += c` | 摊还 O(1) | 减少扩容次数 |

- `a + b + c` 会产生临时对象；循环里拼接一律 `+=`/`append`，知道最终长度就 `reserve`
- **函数参数**：传值会整串拷贝；只读参数用 `const std::string&`。如果不需要 `\0` 结尾，`std::string_view` 还能避免字面量/子串的临时 string
- **返回**：直接 `return local;` 通常触发 NRVO；即使没有 NRVO，`std::string` 也会走移动（O(1)）。C++17 强制省略的是**纯右值**，NRVO 不是强制。别写 `return std::move(local);`（会阻止 NRVO，见[右值引用与移动语义](右值引用与移动语义.md)）

**C++23**：`resize_and_overwrite` 可以直接在字符串缓冲区上写，回调返回实际长度，适合格式化/序列化，省掉临时 string。

## 7. 查找：用 `npos`，不要用 `-1`

```cpp
if (s.find(x) >= 0) { }        // ❌ 恒真（无符号），编译器还会警告 -Wtype-limits
if (s.find(x) != std::string::npos) { }   // 正确写法
```

`npos` 是 `size_type(-1)`，通常是 `SIZE_MAX`（64 位下是 18446744073709551615）。另外 `int pos = s.find(x);` 会把 `npos` 截断 ⚠️（开 `-Wconversion` 才会警告）。

## 8. 字符分类函数：必须先转 `unsigned char`

`isalpha` / `isdigit` / `toupper` 的标准要求：参数要么是 `EOF`，要么**能表示成 `unsigned char`** ❌——直接传负的 `char`（中文/非 ASCII 字节）是 UB：

```cpp
char c = (char)0xE9;              // char 是否有符号由实现决定；常见有符号平台得到 -23
isalpha(c);                       // ⚠️ 若 c 是负数则 UB（只允许 EOF 或 unsigned char 范围）
isalpha((unsigned char)c);        // 正确写法
```

而且这些函数是**按字节、按 locale** 的——处理 UTF-8 中文别指望它们。

## 9. 数值转换

```cpp
std::stoi("12abc");        // 12 —— 只解析前缀，不报错 ⚠️
std::stoi("abc");          // 抛 std::invalid_argument
std::stoi("999999999999"); // 抛 std::out_of_range
```

要"不抛异常 + 更快"就用 C++17 的 `from_chars`；它返回的 `ptr` 指向第一个未解析字符（`"12abc"` 的 `'a'`，下标 2）——见 [C++17](C++17.md)。输出方向：`to_string` / `to_chars`。

## 10. 要点回顾

1. **SSO**：短串存在 `std::string` 对象内部（随对象所在存储），libstdc++ 超过 15 个 char 才堆分配
2. **sizeof(string) 固定**：和内容长度无关（libstdc++ 64 位通常 32）
3. **size() 是字节数**：常见汉字通常 3 字节，扩展区/emoji 可能 4 字节
4. **substr 是拷贝**：频繁子串用 string_view（零拷贝）
5. **string_view 不拥有数据**：源串销毁/修改都可能悬垂；别返回局部串 view、别指向临时对象；`data()` 不保证 `\0`
6. **`c_str()` 的指针会失效**：任何非 const 修改后都不再保证有效（ASan 实测 use-after-free）
7. **拼接用 `+=`（可 `reserve`）**：`s = s + c` 是 O(n²)；参数只读用 `const&`/`string_view`
8. **查找用 `npos`**：`find(...) >= 0` 恒真 ❌；`isalpha` 类函数要传 `(unsigned char)` ✅
9. **转换会抛异常**：`stoi` 抛 `invalid_argument`/`out_of_range`；不抛用 `from_chars`
