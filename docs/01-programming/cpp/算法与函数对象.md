# 算法与函数对象

STL 算法是 **100 多个通用函数**，定义在 `<algorithm>`（数值的在 `<numeric>`）。核心思想：操作 **`[begin, end)` 区间**，通过迭代器和容器解耦。

## 1. 核心思想

算法不直接操作容器，而是通过**迭代器**操作区间：

```cpp
std::vector<int> v{3, 1, 2};
std::sort(v.begin(), v.end());   // 对任何容器都能用
```

**好处**：同一个 sort 能用于 vector、deque、array，但**不能用于 list**（list 的迭代器不支持随机访问，要用 `list.sort()`）。

## 2. 查找算法

### find / count

```cpp
auto it = std::find(v.begin(), v.end(), 3);      // 找第一个 3，找不到返回 end
if (it != v.end()) { /* 找到了 */ }

int n = std::count(v.begin(), v.end(), 3);       // 统计 3 出现次数
```

### binary_search / lower_bound / upper_bound（已排序前提）

```cpp
// 前提：区间必须已排序
// 为什么：二分查找靠"比较中间值就能排除一半"，
// 只有有序才能判断目标在左半还是右半，无序无法二分
std::sort(v.begin(), v.end());

bool found = std::binary_search(v.begin(), v.end(), 3);  // 是否存在

auto it1 = std::lower_bound(v.begin(), v.end(), 3);  // 第一个 >= 3 的位置
auto it2 = std::upper_bound(v.begin(), v.end(), 3);  // 第一个 > 3 的位置
```

**lower_bound vs upper_bound 区别**：

- `lower_bound`：第一个**大于等于**目标的位置
- `upper_bound`：第一个**大于**目标的位置
- 两者之间就是所有等于目标的范围

## 3. 排序算法

### sort

```cpp
std::sort(v.begin(), v.end());                       // 升序
std::sort(v.begin(), v.end(), std::greater<>());     // 降序
std::sort(v.begin(), v.end(), [](int a, int b){ return a > b; });  // 自定义比较
```

**sort 的底层**：不是纯快排，是 **introsort**（内省排序）= **快排 + 插入排序 + 堆排序** 的混合：

1.  快排为主（分区）
2.  递归到小区间（小于某阈值，如 16）改用**插入排序**（小数组插排更快，常数小）
3.  检测到快排退化（递归深度超过 2×log n）改用**堆排序**（保证最坏 O(n log n)）

**目的**：兼顾平均性能（快排）+ 最坏保证（堆排）+ 小区间效率（插排），整体 O(n log n)。

```cpp
// 为什么小区间用插入排序？
// 小区间上快排的递归/分区开销大，插入排序常数小、对小数组更快
```

### stable_sort / partial_sort / nth_element

```cpp
std::stable_sort(v.begin(), v.end());                // 稳定排序（相等元素保持原顺序）
std::partial_sort(v.begin(), v.begin()+3, v.end());  // 只排前 3 个（剩下的无序）
std::nth_element(v.begin(), v.begin()+3, v.end());   // 第 4 个元素（下标 3）就位，比它小的在前
```

**底层实现**：

| 算法           | 底层                           | 复杂度     | 稳定性    |
|----------------|--------------------------------|------------|-----------|
| `sort`         | introsort（快排+插排+堆排）    | O(n log n) | ❌ 不稳定 |
| `stable_sort`  | **归并排序**（额外空间换稳定） | O(n log n) | ✅ 稳定   |
| `partial_sort` | **堆**（维护大小为 k 的堆）    | O(n log k) | ❌        |
| `nth_element`  | **快速选择（quickselect）**    | 平均 O(n)  | ❌        |

**用途**：

- `stable_sort`：需要保持相等元素原顺序时
- `partial_sort`：只要前 k 个（如"排行榜 Top 10"）
- `nth_element`：只要第 k 大/小（如"找中位数"），比全排序快 O(n log n) → O(n)

## 4. 修改算法

```cpp
std::copy(src.begin(), src.end(), dst.begin());      // 拷贝
std::transform(v.begin(), v.end(), v.begin(), [](int x){ return x*2; });  // 变换
std::fill(v.begin(), v.end(), 0);                    // 填充
std::replace(v.begin(), v.end(), 1, 9);              // 把 1 换成 9
std::reverse(v.begin(), v.end());                    // 反转
```

### remove 不是真删除（erase-remove 惯用法）

```cpp
std::vector<int> v{1, 2, 3, 2, 5};

std::remove(v.begin(), v.end(), 2);   // ❌ 不是真删除！只是把非 2 元素前移
// 结果 v = {1, 3, 5, ?, ?}，返回指向"新末尾"的迭代器，size 没变

// 正确：配合 erase 真删除
v.erase(std::remove(v.begin(), v.end(), 2), v.end());
// 结果 v = {1, 3, 5}，真正删掉

// C++20 更简洁
std::erase(v, 2);   // 一行搞定
```

**为什么 remove 不真删**：remove 只接受迭代器，不知道容器，无法改 size，只能前移元素。

## 8. 堆算法

```cpp

```

## 9. std::ranges（C++20）

**解决的问题**：传统算法传 `begin()`/`end()`、写法啰嗦、不能组合。ranges 支持**管道式组合**：

```cpp
#include <ranges>

std::vector<int> v{1, 2, 3, 4, 5, 6};

// 传统写法（嵌套、啰嗦）：
std::vector<int> tmp;
std::copy_if(v.begin(), v.end(), std::back_inserter(tmp),
             [](int x){ return x % 2 == 0; });
std::transform(tmp.begin(), tmp.end(), tmp.begin(),
               [](int x){ return x * x; });

// ranges 写法（管道、直观）：
auto result = v
    | std::views::filter([](int x){ return x % 2 == 0; })   // 筛偶数
    | std::views::transform([](int x){ return x * x; });    // 平方
// result 是惰性的：不立刻计算，遍历时才算
```

### 核心特性

**1. 惰性求值（lazy）**：view 不立刻计算，只在**遍历时**才算：

```cpp
auto view = v | std::views::transform([](int x){ return x * x; });
// 此时还没算！遍历 view 时才逐个算
for (int x : view) { ... }   // 这里才真正计算
```

**好处**：无中间容器、省内存、支持无限序列（如 `views::iota`）。

**2. 不修改原容器**：view 是"视图"，只读，不拷贝不改原数据。

**3. 可组合**：`|` 管道串联多个 view。

### 常用 view

```cpp
std::views::filter(pred)     // 筛选
std::views::transform(f)     // 变换
std::views::take(n)          // 取前 n 个
std::views::drop(n)          // 跳过前 n 个
std::views::reverse          // 反转
std::views::iota(a, b)       // 生成序列 a, a+1, ..., b-1
std::views::zip(v1, v2)      // C++23：打包两个范围
```

### ranges 算法

`std::ranges::` 命名空间下的算法，可直接传容器（不用 begin/end）：

```cpp
std::ranges::sort(v);                    // 不用 v.begin(), v.end()
std::ranges::find(v, 3);                 // 直接传容器
auto it = std::ranges::find_if(v, pred);
```

### 优缺点

|         | 说明                                   |
|---------|----------------------------------------|
| ✅ 优点 | 可读性强、可组合、惰性求值、省中间容器 |
| ❌ 缺点 | 编译错误难懂、调试难、编译器支持较新   |

## 10. 函数对象（仿函数）

STL 六大组件里"了解即可"的三个。日常用得少，知道概念和一句话用途就行。

**定义**：重载了 `operator()` 的对象，能像函数一样调用。

```cpp
struct Greater {
    bool operator()(int a, int b) const { return a > b; }
};

std::sort(v.begin(), v.end(), Greater());   // 传入函数对象
```

**为什么了解即可**：C++11 的 **lambda 本质就是函数对象**（编译器把 lambda 生成一个匿名仿函数），所以现在直接写 lambda，很少手写仿函数类：

```cpp
std::sort(v.begin(), v.end(), [](int a, int b){ return a > b; });   // 等价
```

**内置仿函数**：`std::less`、`std::greater`、`std::plus` 等，排序时常用。

### lambda 深入

**捕获列表的细节**：

```cpp
int a = 1, b = 2;
[a](){ return a; };        // 按值捕获 a（拷贝）
[&a](){ return a; };       // 按引用捕获 a
[=](){ return a + b; };    // 全部按值捕获
[&](){ return a + b; };    // 全部按引用捕获
[a, &b](){ /* a 按值，b 按引用 */ };   // 混合

// mutable：按值捕获时默认不能修改，加 mutable 才能改（改的是副本）
int c = 0;
auto f = [c]() mutable { c++; return c; };   // 能改（改副本，不影响原 c）
```

**捕获 this**：

```cpp
struct S {
    int v;
    auto get() { return [this]{ return v; }; }   // 捕获 this 指针（默认）
    // C++17：[*this] 按值捕获整个对象
    auto get2() { return [*this]{ return v; }; }
};
```

**泛型 lambda（C++14）**：

```cpp
auto add = [](auto x, auto y) { return x + y; };   // 参数自动推导
add(1, 2);       // int 版
add(1.5, 2.5);   // double 版
```

**底层**：lambda 被编译器生成一个**匿名函数对象**——捕获的变量变成成员，`()` 变成 `operator()`。所以 lambda 和手写仿函数完全等价。

### std::function（万能可调用对象包装器）

**作用**：把任何可调用的东西（函数指针、lambda、函数对象、成员函数）装进统一类型：

```cpp
#include <functional>

// 1. 普通函数
std::function<int(int, int)> f1 = add;

// 2. lambda（含捕获的也行）
std::function<int(int, int)> f2 = [](int a, int b){ return a + b; };

// 3. 函数对象
std::function<int(int, int)> f3 = Add{};

// 4. 成员函数（配合 bind）
std::function<int(int, int)> f4 = std::bind(&S::add, &s,
                                            std::placeholders::_1,
                                            std::placeholders::_2);
f1(1, 2);   // 都能像函数一样调用
```

### std::function vs 函数指针

|                 | 函数指针         | std::function                 |
|-----------------|------------------|-------------------------------|
| 能装捕获 lambda | ❌（只能无捕获） | ✅                            |
| 能装函数对象    | ❌               | ✅                            |
| 能装成员函数    | ❌（要迂回）     | ✅ 配合 bind                  |
| 类型            | 具体类型         | 统一类型（类型擦除）          |
| 开销            | 无               | 有（虚函数调用 + 可能堆分配） |

### 底层：类型擦除

```cpp
// 简化版原理：内部用虚函数统一接口
class FunctionBase {
public:
    virtual int call(int, int) = 0;
};
template <typename Callable>
class FunctionImpl : public FunctionBase {
    Callable c;
    int call(int a, int b) override { return c(a, b); }
};
// std::function 内部持有 FunctionBase*，调用走虚函数
```

**所以有开销**：虚函数间接调用 + 大对象可能堆分配（小对象有 SBO 优化——类似 string 的 SSO，小可调用对象直接存对象内部栈上，不堆分配）。

**什么时候用**：需要"统一存储不同可调用对象"（回调注册、容器里存函数）。**性能敏感处别用**（用模板，编译期确定，零开销）。

### 实测：模板（可内联） vs std::function（类型擦除）

同一个 `std::sort`，只换比较器的写法（2×10⁶ 个 int，本机实测）：

| 比较器 | 耗时 |
|--------|:---:|
| lambda（模板实例，调用可内联） | **96.5 ms** |
| `std::function`（虚函数 + 间接调用） | 156.4 ms（慢 1.6 倍） |

**结论**：接口边界用 `std::function`（统一类型、好存好传）；热点路径（排序比较器、循环里的回调）用模板/lambda，让它内联。

### 回调（callback）

**一句话**：把自己写的"要做什么"交给别人保管，别人在合适的时机替你调用它。像给闹钟设铃声——你负责定义动作，时钟负责时机。

标准库里到处都是：`std::sort` 不知道你要升序还是降序，你把规则传给它：

```cpp
std::sort(v.begin(), v.end(), [](int a, int b) { return a > b; });  // 降序
```

sort 每比较两个元素就"回调"一次这个 lambda。注意**调用关系是反的**：平时是你调库，这里是库调你（控制反转）。

本项目里也一样：

| 注册 | 库什么时候回调你 |
|------|------------------|
| `svr.Get("/health", …)` | 收到 `GET /health` 时 |
| `svr.Post("/echo", …)` | 收到 `POST /echo` 时 |
| `svr.set_logger(…)` | 每个请求处理完 |

**为什么需要**：库不可能知道你的业务要做什么（返回 ok？查库？打日志？）。它只提供"时机"，把"动作"留给你，两边解耦。

**同步 vs 异步**：

- 同步回调：sort 的比较器——当场调用、调完继续往下跑，同一条线程
- 异步回调：请求到达、定时器到点——未来某个时刻、可能在另一条线程被调用；共享数据要考虑线程安全（见 [并发编程](并发编程.md)）

**演进链**（正好串起前面几节）：

- 函数指针：能传，但带不了状态（C 用 `void* user_data` 硬传，见 [C语言要点](C语言要点.md)）
- lambda / 函数对象：能捕获状态（`[&retries]`）
- `std::function`：能统一存进容器——框架的"回调注册表"就是这么做的

**两个坑**：

- ⚠️ 生命周期：回调里 `[&]` 捕获的对象，被调用时还活着吗？
- ⚠️ 线程：异步回调跑在哪条线程？加锁、别碰已销毁的对象

## 11. 适配器（Adapters）

**定义**：把一种接口"包装"成另一种接口。分三种：

| 适配器       | 例子                            | 说明                                 |
|--------------|---------------------------------|--------------------------------------|
| 容器适配器   | stack/queue/priority_queue      | 包装容器，限制接口（已在容器篇讲过） |
| 迭代器适配器 | reverse_iterator、back_inserter | 反向遍历、插入输出                   |
| 函数适配器   | std::bind、std::not_fn          | 改造函数接口                         |

```cpp
// 函数适配器：bind 固定参数
auto f = std::bind(add, 1, std::placeholders::_1);   // f(x) = add(1, x)
```

**为什么了解即可**：容器适配器（stack/queue）已经按容器讲了；迭代器适配器在迭代器篇提过；函数适配器现在多被 lambda 替代。

## 12. 要点回顾

1.  **`sort` 的底层**：introsort（快排 + 插入排序 + 堆排序），防止退化到 O(n²)
2.  **`lower_bound` vs `upper_bound`**：\>= vs \>，两者之间是等于目标的范围
3.  **`remove` 不是真删除**：只前移元素，配合 `erase` 才是真删（erase-remove 惯用法）
4.  **`binary_search` 前提**：必须已排序
5.  **算法通过迭代器解耦**：所以 list 不能用 sort（要用成员函数 list.sort()）
6.  **算法操作 `[begin, end)` 区间**，通过迭代器和容器解耦
7.  **查找**：find/count 线性，binary_search/lower_bound 二分（需排序）
8.  **排序**：sort（introsort）、stable_sort、partial_sort
9.  **修改**：copy/transform/fill/replace/remove/reverse
10. **记住 erase-remove 惯用法**（remove 不真删）
11. **函数对象**：日常写成 lambda（lambda 本质就是匿名函数对象）
12. **适配器**：`stack`/`queue` 是容器适配器，天天用；`bind`/`mem_fn` 基本被 lambda 取代
13. **分配器**：默认 `std::allocator` 够用
