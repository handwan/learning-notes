# 算法与函数对象

STL 算法是 **100 多个通用函数**，定义在 `<algorithm>`（数值的在 `<numeric>`）。核心思想：操作 **`[begin, end)` 区间**，通过迭代器和容器解耦。

> 本文按“常用 + 易错”组织，不是 API 全量；完整接口查 cppreference。

## 1. 核心思想

算法不直接操作容器，而是通过**迭代器**操作区间：

```cpp
std::vector<int> v{3, 1, 2};
std::sort(v.begin(), v.end());   // 对任何容器都能用
```

**好处**：同一个 sort 能用于 vector、deque、array，但**不能用于 list**（list 的迭代器不支持随机访问，要用 `list.sort()`）。

## 2. 查找算法

### find / count

```cpp
auto it = std::find(v.begin(), v.end(), 3);      // 找第一个 3，找不到返回 end
if (it != v.end()) { /* 找到了 */ }

int n = std::count(v.begin(), v.end(), 3);       // 统计 3 出现次数
```

### binary_search / lower_bound / upper_bound（已排序前提）

```cpp
// 前提：区间必须已排序
// 为什么：二分查找靠"比较中间值就能排除一半"，
// 只有有序才能判断目标在左半还是右半，无序无法二分
std::sort(v.begin(), v.end());

bool found = std::binary_search(v.begin(), v.end(), 3);  // 是否存在

auto it1 = std::lower_bound(v.begin(), v.end(), 3);  // 第一个 >= 3 的位置
auto it2 = std::upper_bound(v.begin(), v.end(), 3);  // 第一个 > 3 的位置
```

**lower_bound vs upper_bound 区别**：

- `lower_bound`：第一个**大于等于**目标的位置
- `upper_bound`：第一个**大于**目标的位置
- 两者之间就是所有等于目标的范围

## 3. 排序算法

### sort

```cpp
std::sort(v.begin(), v.end());                       // 升序
std::sort(v.begin(), v.end(), std::greater<>());     // 降序
std::sort(v.begin(), v.end(), [](int a, int b){ return a > b; });  // 自定义比较
```

**sort 的底层**：不是纯快排，是 **introsort**（内省排序）= **快排 + 插入排序 + 堆排序** 的混合：

1.  快排为主（分区）
2.  递归到小区间（小于某阈值，如 16）改用**插入排序**（小数组插排更快，常数小）
3.  检测到快排退化（递归深度超过 2×log n）改用**堆排序**（保证最坏 O(n log n)）

**目的**：兼顾平均性能（快排）+ 最坏保证（堆排）+ 小区间效率（插排），整体 O(n log n)。

```cpp
// 为什么小区间用插入排序？
// 小区间上快排的递归/分区开销大，插入排序常数小、对小数组更快
```

### 自定义排序（比较器）

`std::sort` 的第三个参数是**比较器**，它回答的问题是：**"a 该排在 b 前面吗？"**——语义就是 `a < b`。

**硬性要求：严格弱序**（不满足 = 未定义行为，可能乱序、可能崩）：

- `cmp(a, a)` 必须为 **false**（所以不能写 `<=`）
- `cmp(a, b)` 和 `cmp(b, a)` 不能同时为 true
- `cmp` 本身可传递：`cmp(a, b) && cmp(b, c)` 则 `cmp(a, c)`
- **等价关系可传递**：若 `a` 与 `b` 等价（`!cmp(a,b) && !cmp(b,a)`），`b` 与 `c` 等价，则 `a` 与 `c` 也等价

为什么这么严：sort 依赖等价类可传递，才能把元素正确分区；前提被破坏后，内部可能读到区间外，行为未定义。

**三种写法**（效果等价，lambda 最常用）：

```cpp
// ① lambda（实战首选）
std::sort(v.begin(), v.end(), [](const Item& a, const Item& b) { return a.age < b.age; });

// ② 函数对象（需要"自带状态"时用，比如"按与某个基准的距离排序"）
struct ByAge {
    bool operator()(const Item& a, const Item& b) const { return a.age < b.age; }
};

// ③ 普通函数
bool ByAge(const Item& a, const Item& b) { return a.age < b.age; }
```

**常用模式**：

```cpp
// 降序
std::sort(v.begin(), v.end(), std::greater<>{});

// 多关键字：age 升序，相同按 name（std::tie 一把梭，需 <tuple>）
std::sort(items.begin(), items.end(), [](const Item& x, const Item& y) {
    return std::tie(x.age, x.name) < std::tie(y.age, y.name);
});

// 升降混搭：一个字段降序、另一个升序，只能老实写 if 链
if (x.score != y.score) return x.score > y.score;   // score 降序
return x.name < y.name;                              // name 升序

// 比较规则不一定是"大小"：179 最大数用"拼接后谁更大"
std::sort(strs.begin(), strs.end(), [](const std::string& a, const std::string& b) {
    return a + b > b + a;
});

// C++20 投影：把"拿哪个字段比"单独抽出来（第二个参数 {} = 默认的 <）
std::ranges::sort(items, {}, &Item::age);               // 按 age 升序
std::ranges::sort(items, std::greater{}, &Item::age);   // 按 age 降序
std::ranges::sort(items, {}, [](const Item& x) {        // 投影返回 pair = 多关键字
    return std::pair(x.age, x.name);
});
```

**两个经典陷阱**（都实测过）：

```cpp
// ❌ 陷阱 1：写成 <=（违反反自反性）
std::sort(v.begin(), v.end(), [](int a, int b) { return a <= b; });
// 开 -D_GLIBCXX_DEBUG 编译运行，直接断言：
// Error: comparison doesn't meet irreflexive requirements, assert(!(a < a)).

// ❌ 陷阱 2：老教材的 return a - b;
std::sort(v.begin(), v.end(), [](int a, int b) { return a - b; });
// 问题一：非零即 true —— 1 - 2 = -1 也是 true，
//         于是 cmp(1,2) 和 cmp(2,1) 同时为真，排序结果乱掉
//         （实测 {3,1,2} 排成 "2 1 3"）
// 问题二：大数相减有符号溢出（UB）——UBSan 报：
//         runtime error: signed integer overflow: 2147483647 - -1 ...
```

**正确写法只有一种形状**：返回 `bool` 的 `a < b`（或它的变形）。

**什么时候不能用 `std::sort`**：list 是双向迭代器，只能用成员函数 `lst.sort(cmp)`（内部是节点重接，且天然稳定）；只要前 k 个或第 k 个，见下一节的 `partial_sort` / `nth_element`。

**刷题常见题**：

| 题 | 比较规则 |
|---|---|
| 56 合并区间 | 按左端点升序 |
| 179 最大数 | 拼接比较 `a + b > b + a` |
| 1029 两地调度 | 按"去 A / 去 B 的费用差"排序 |
| 435 无重叠区间 / 253 会议室 | 按右端点 / 开始时间 |
| 451 按频率排序 | 频率降序 |

### stable_sort / partial_sort / nth_element

```cpp
std::stable_sort(v.begin(), v.end());                // 稳定排序（相等元素保持原顺序）
std::partial_sort(v.begin(), v.begin()+3, v.end());  // 只排前 3 个（剩下的无序）
std::nth_element(v.begin(), v.begin()+3, v.end());   // 第 4 个元素（下标 3）就位；前面的都不大于它，后面的都不小于它
```

**主流实现（标准只规定复杂度和稳定性，不规定具体算法）**：

| 算法           | 底层                           | 复杂度     | 稳定性    |
|----------------|--------------------------------|------------|-----------|
| `sort`         | introsort（快排+插排+堆排）    | O(n log n) | ❌ 不稳定 |
| `stable_sort`  | **归并排序**（额外空间换稳定） | O(n log n) | ✅ 稳定   |
| `partial_sort` | **堆**（维护大小为 k 的堆）    | O(n log k) | ❌        |
| `nth_element`  | **快速选择（quickselect）**    | 平均 O(n)，最坏 O(n²) | ❌        |

**用途**：

- `stable_sort`：需要保持相等元素原顺序时
- `partial_sort`：只要前 k 个（如"排行榜 Top 10"）
- `nth_element`：只要第 k 大/小（如"找中位数"），比全排序快 O(n log n) → O(n)

## 4. 修改算法

```cpp
std::copy(src.begin(), src.end(), dst.begin());      // 拷贝；dst 需先有足够空间
std::transform(v.begin(), v.end(), v.begin(), [](int x){ return x*2; });  // 变换
std::fill(v.begin(), v.end(), 0);                    // 填充
std::replace(v.begin(), v.end(), 1, 9);              // 把 1 换成 9
std::reverse(v.begin(), v.end());                    // 反转
```

**注意**：`std::copy` 和集合算法写到已有位置时，目标必须有足够空间；不确定就用 `back_inserter` / `inserter`，或先 `resize`。

### remove 不是真删除（erase-remove 惯用法）

```cpp
std::vector<int> v{1, 2, 3, 2, 5};

std::remove(v.begin(), v.end(), 2);   // ❌ 不是真删除！只是把非 2 元素前移
// 结果 v = {1, 3, 5, ?, ?}，返回指向"新末尾"的迭代器，size 没变

// 正确：配合 erase 真删除
v.erase(std::remove(v.begin(), v.end(), 2), v.end());
// 结果 v = {1, 3, 5}，真正删掉

// C++20 更简洁
std::erase(v, 2);   // 一行搞定
```

**为什么 remove 不真删**：remove 只接受迭代器，不知道容器，无法改 size，只能前移元素。

## 9. std::ranges（C++20）

**解决的问题**：传统算法传 `begin()`/`end()`、写法啰嗦、不能组合。ranges 支持**管道式组合**（特性清单见 [C++20](C++20.md)）：

```cpp
#include <algorithm>
#include <iterator>
#include <ranges>
#include <vector>

std::vector<int> v{1, 2, 3, 4, 5, 6};

// 传统写法（嵌套、啰嗦）：
std::vector<int> tmp;
std::copy_if(v.begin(), v.end(), std::back_inserter(tmp),
             [](int x){ return x % 2 == 0; });
std::transform(tmp.begin(), tmp.end(), tmp.begin(),
               [](int x){ return x * x; });

// ranges 写法（管道、直观）：
auto result = v
    | std::views::filter([](int x){ return x % 2 == 0; })   // 筛偶数
    | std::views::transform([](int x){ return x * x; });    // 平方
// result 是惰性的：不立刻计算，遍历时才算
```

### 核心特性

**1. 惰性求值（lazy）**：view 不立刻计算，只在**遍历时**才算：

```cpp
auto view = v | std::views::transform([](int x){ return x * x; });
// 此时还没算！遍历 view 时才逐个算
for (int x : view) { ... }   // 这里才真正计算
```

**好处**：无中间容器、省内存、支持无限序列（如 `views::iota`）。

**2. view 不拥有数据，但不等于只读**：构造 view 本身不拷贝整个容器、也不改数据；遍历时是否可写，取决于底层 range 和适配器。`filter` / `reverse` / `take` 产出的通常是引用；`transform` 看 lambda 返回引用还是值；`views::as_const`（C++23）才是显式只读。

**3. 可组合**：`|` 管道串联多个 view。

### 常用 view

```cpp
std::views::filter(pred)     // 筛选
std::views::transform(f)     // 变换
std::views::take(n)          // 取前 n 个
std::views::drop(n)          // 跳过前 n 个
std::views::reverse          // 反转
std::views::iota(a, b)       // 生成序列 a, a+1, ..., b-1
std::views::zip(v1, v2)      // C++23：打包两个范围
```

### ranges 算法

`std::ranges::` 命名空间下的算法，可直接传容器（不用 begin/end）：

```cpp
std::ranges::sort(v);                    // 不用 v.begin(), v.end()
std::ranges::find(v, 3);                 // 直接传容器
auto it = std::ranges::find_if(v, pred);
```

### 优缺点

|         | 说明                                   |
|---------|----------------------------------------|
| **优点** | 可读性强、可组合、惰性求值、省中间容器 |
| **缺点** | 编译错误难懂、调试难、编译器支持较新   |

## 10. 函数对象（仿函数）

STL 六大组件里"了解即可"的三个。日常用得少，知道概念和一句话用途就行；lambda / `std::function` 的语法基础见 [C++11-14](C++11-14.md)。

**定义**：重载了 `operator()` 的对象，能像函数一样调用。

```cpp
struct Greater {
    bool operator()(int a, int b) const { return a > b; }
};

std::sort(v.begin(), v.end(), Greater());   // 传入函数对象
```

**为什么了解即可**：C++11 的 **lambda 本质就是函数对象**（编译器把 lambda 生成一个匿名仿函数），所以现在直接写 lambda，很少手写仿函数类：

```cpp
std::sort(v.begin(), v.end(), [](int a, int b){ return a > b; });   // 等价
```

**内置仿函数**：`std::less`、`std::greater`、`std::plus` 等，排序时常用。

**C++17 调用工具**：

```cpp
std::invoke(&S::f, s, 1);     // 成员函数/函数对象/函数指针统一调用
std::apply([](int a, int b){ return a + b; }, std::tuple{1, 2}); // 展开 tuple
std::ref(x);                  // reference_wrapper：避免拷贝，常用于 bind/function
std::mem_fn(&S::f);           // 把成员函数包成可调用对象
```

`std::invoke` / `std::ref` / `std::mem_fn` 在 `<functional>`，`std::apply` 在 `<tuple>`。

### lambda 深入

**捕获列表的细节**：

```cpp
int a = 1, b = 2;
[a](){ return a; };        // 按值捕获 a（拷贝）
[&a](){ return a; };       // 按引用捕获 a
[=](){ return a + b; };    // 全部按值捕获
[&](){ return a + b; };    // 全部按引用捕获
[a, &b](){ /* a 按值，b 按引用 */ };   // 混合

// mutable：按值捕获时默认不能修改，加 mutable 才能改（改的是副本）
int c = 0;
auto f = [c]() mutable { c++; return c; };   // 能改（改副本，不影响原 c）
```

**捕获 this**：

```cpp
struct S {
    int v;
    auto get() { return [this]{ return v; }; }   // 捕获 this 指针（默认）
    // C++17：[*this] 按值捕获整个对象
    auto get2() { return [*this]{ return v; }; }
};
```

**泛型 lambda（C++14）**：

```cpp
auto add = [](auto x, auto y) { return x + y; };   // 参数自动推导
add(1, 2);       // int 版
add(1.5, 2.5);   // double 版
```

另外：C++14 的 init capture（`[p = std::move(p)]`）、C++17 的 constexpr lambda、C++20 的 pack capture（`[ts...]`）也常用；语法分别见 [C++11-14](C++11-14.md) / [C++17](C++17.md) / [C++20](C++20.md)。

**底层**：lambda 被编译器生成一个**匿名函数对象**——捕获的变量变成成员，`()` 变成 `operator()`。所以 lambda 和手写仿函数完全等价。

### std::function（万能可调用对象包装器）

**作用**：把**可拷贝**的可调用对象（函数指针、lambda、函数对象、成员函数 + bind）装进统一类型：

```cpp
#include <functional>

// 1. 普通函数
std::function<int(int, int)> f1 = add;

// 2. lambda（含捕获的也行）
std::function<int(int, int)> f2 = [](int a, int b){ return a + b; };

// 3. 函数对象
std::function<int(int, int)> f3 = Add{};

// 4. 成员函数（配合 bind）
std::function<int(int, int)> f4 = std::bind(&S::add, &s,
                                            std::placeholders::_1,
                                            std::placeholders::_2);
f1(1, 2);   // 都能像函数一样调用
```

**限制**：`std::function` 要求目标可拷贝；捕获 `unique_ptr` 的 move-only lambda 装不进去，用 C++23 的 `std::move_only_function` 或模板。

### std::function vs 函数指针

|                 | 函数指针         | std::function                 |
|-----------------|------------------|-------------------------------|
| 能装捕获 lambda | ❌（只能无捕获） | ✅                            |
| 能装函数对象    | ❌               | ✅                            |
| 能装成员函数    | ❌（要迂回）     | ✅ 配合 bind                  |
| 类型            | 具体类型         | 统一类型（类型擦除）          |
| 开销            | 无               | 有（虚函数调用 + 可能堆分配） |

### 底层：类型擦除

```cpp
// 简化版原理：内部用虚函数统一接口
class FunctionBase {
public:
    virtual ~FunctionBase() = default;
    virtual int call(int, int) = 0;
};
template <typename Callable>
class FunctionImpl : public FunctionBase {
    Callable c;
    int call(int a, int b) override { return c(a, b); }
};
// std::function 内部持有 FunctionBase*，调用走虚函数
```

**所以有开销**：虚函数间接调用 + 大对象可能堆分配（小对象可能有 SBO 优化——类似 string 的 SSO，可能直接存在 `std::function` 对象内部，随对象所在存储；放不下就堆分配）。

**什么时候用**：需要"统一存储不同可调用对象"（回调注册、容器里存函数）。**性能敏感处别用**（用模板，编译期确定，零开销）。

### 模板（可内联） vs std::function（类型擦除）

- lambda / 模板：比较器类型在编译期确定，调用可内联
- `std::function`：类型擦除，通常走间接调用，可能堆分配
- **结论**：接口边界用 `std::function`（统一类型、好存好传）；热点路径（排序比较器、循环里的回调）用模板/lambda，让它内联。

### 回调（callback）

**一句话**：把自己写的"要做什么"交给别人保管，别人在合适的时机替你调用它。像给闹钟设铃声——你负责定义动作，时钟负责时机。

标准库里到处都是：`std::sort` 不知道你要升序还是降序，你把规则传给它：

```cpp
std::sort(v.begin(), v.end(), [](int a, int b) { return a > b; });  // 降序
```

sort 每比较两个元素就"回调"一次这个 lambda。注意**调用关系是反的**：平时是你调库，这里是库调你（控制反转）。

本项目里也一样：

| 注册 | 库什么时候回调你 |
|------|------------------|
| `svr.Get("/health", …)` | 收到 `GET /health` 时 |
| `svr.Post("/echo", …)` | 收到 `POST /echo` 时 |
| `svr.set_logger(…)` | 每个请求处理完 |

**为什么需要**：库不可能知道你的业务要做什么（返回 ok？查库？打日志？）。它只提供"时机"，把"动作"留给你，两边解耦。

**同步 vs 异步**：

- 同步回调：sort 的比较器——当场调用、调完继续往下跑，同一条线程
- 异步回调：请求到达、定时器到点——未来某个时刻、可能在另一条线程被调用；共享数据要考虑线程安全（见 [并发编程](并发编程.md)）

**演进链**（正好串起前面几节）：

- 函数指针：能传，但带不了状态（C 用 `void* user_data` 硬传，见 [C语言要点](C语言要点.md)）
- lambda / 函数对象：能捕获状态（`[&retries]`）
- `std::function`：能统一存进容器——框架的"回调注册表"就是这么做的

**两个坑**：

- ⚠️ 生命周期：回调里 `[&]` 捕获的对象，被调用时还活着吗？
- ⚠️ 线程：异步回调跑在哪条线程？加锁、别碰已销毁的对象

## 11. 适配器（Adapters）

**定义**：把一种接口"包装"成另一种接口。分三种：

| 适配器       | 例子                            | 说明                                 |
|--------------|---------------------------------|--------------------------------------|
| 容器适配器   | stack/queue/priority_queue      | 包装容器，限制接口（已在容器篇讲过） |
| 迭代器适配器 | reverse_iterator、back_inserter | 反向遍历、插入输出                   |
| 函数适配器   | std::bind、std::not_fn          | 改造函数接口                         |

```cpp
// 函数适配器：bind 固定参数
auto f = std::bind(add, 1, std::placeholders::_1);   // f(x) = add(1, x)
```

**为什么了解即可**：容器适配器（stack/queue）已经按容器讲了；迭代器适配器在迭代器篇提过；函数适配器现在多被 lambda 替代。

## 12. 要点回顾

1. **`sort` 的底层**：introsort（快排 + 插入排序 + 堆排序），防止退化到 O(n²)
2. **`lower_bound` vs `upper_bound`**：`>=` vs `>`，两者之间是等于目标的范围
3. **`binary_search` 前提**：必须已排序
4. **`remove` 不是真删除**：只前移元素，配合 `erase` 才是真删（erase-remove 惯用法）
5. **算法操作 `[begin, end)` 区间**：通过迭代器和容器解耦；list 不能用 `std::sort`，要用成员函数 `list.sort()`
6. **查找**：find/count 线性；binary_search/lower_bound 二分（需排序）
7. **排序**：sort（introsort）、stable_sort、partial_sort、nth_element
8. **修改**：copy/transform/fill/replace/remove/reverse；写已有位置时注意目标空间
9. **函数对象**：日常写成 lambda（lambda 本质就是匿名函数对象）
10. **`std::function`**：类型擦除，只装可拷贝的可调用对象；热点路径用模板/lambda
11. **适配器**：`stack`/`queue` 是容器适配器；`bind`/`mem_fn` 基本被 lambda 取代
12. **自定义比较器**必须满足严格弱序：返回 `a < b` 语义；`<=` 和 `a - b` 都是错误写法（UB）
