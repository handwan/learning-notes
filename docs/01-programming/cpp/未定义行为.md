# 未定义行为

UB（Undefined Behavior）= 标准**不规定结果**的行为。编译器可以做任何事——最坑的是"看起来正常"，换个编译器/优化等级就崩。这是诡异 bug 的根源。

## 1. 什么是 UB

```cpp
// 标准对 UB 不做任何保证：
// 编译器可以：优化掉、崩溃、看起来正常运行、或做任何事
```

**最危险的点**：

- **看起来正常**（当下不报错）→ 上线后换个环境崩
- **性能优化会"失效"**：编译器基于"代码无 UB"的假设优化，有 UB 时代码行为不可预测

## 2. 常见 UB 清单

### 2.1 内存相关

```cpp
int* p = nullptr;
*p;                        // ❌ 解引用空指针

int* q = new int(5);
delete q;
*q;                        // ❌ 悬垂指针（use-after-free）

int arr[3];
arr[5];                    // ❌ 越界访问

int x;
if (x > 0) { }             // ❌ 读取未初始化内存（值不确定）

int* r = new int(5);
delete r;
delete r;                  // ❌ double free
```

### 2.2 严格别名规则（Strict Aliasing）

**规则**：不能通过"不相关类型"的指针访问同一内存（type-punning）：

```cpp
float f = 1.0f;
int* p = reinterpret_cast<int*>(&f);   // ❌ UB：用 int* 访问 float 内存
*p;
```

**为什么是 UB**：编译器优化时**假设**"不同类型的指针不会指向同一块内存"。违反这个假设，优化就出错。

**正确写法**：用 `memcpy` 或 C++20 的 `std::bit_cast`：

```cpp
int i;
std::memcpy(&i, &f, sizeof(f));      // 合法（memcpy 不违反别名规则）
int j = std::bit_cast<int>(f);       // C++20 推荐
```

### 2.3 有符号整数溢出

```cpp
int a = INT_MAX;
a + 1;                     // ❌ UB！有符号溢出

unsigned b = UINT_MAX;
b + 1;                     // 明确定义（回绕到 0）
```

**关键**：**有符号溢出是 UB，无符号溢出是明确定义的**（模 2ⁿ 回绕）。

**为什么危险**：编译器可能假设"有符号数不会溢出"，据此优化循环/条件，结果出错：

```cpp
// 编译器可能假设 i 不会溢出，把循环优化成死循环
for (int i = 0; i <= INT_MAX; i++) { }   // 潜在 UB
```

### 2.4 移位

```cpp
int x = 1 << 31;           // ❌ 左移到符号位（UB）
int y = -1 << 1;           // ❌ 左移负数（UB）
int z = 1 << 32;           // ❌ 移位 >= 类型宽度（UB）
```

### 2.5 序列点与副作用顺序

```cpp
int i = 0;
i = i++ + i++;             // ❌ UB：同一表达式多次改 i，顺序不确定

int a[5] = {0};
int j = 0;
a[j] = j++;                // ❌ UB：读写顺序不确定
```

**规则**：**两个序列点之间**，不能对同一变量既读又写（或多次写）。

**C++17 起收紧**：`a = i++` 这种"先算右边再赋值"现在明确了顺序，但 `i = i++ + i++` 仍是 UB。

### 2.6 其他

```cpp
char* s = "hello";
s[0] = 'H';               // ❌ 修改字符串字面量（常量区只读）

int f() { }               // ❌ 非 void 函数不返回（UB）

void* p = malloc(8);
delete p;                 // ❌ delete 非 new 的指针（要 free）
```

## 3. UB 和性能优化的关系

**编译器优化建立在"程序无 UB"的假设上**：

```cpp
// 代码有 UB（有符号溢出），编译器假设不会溢出：
int f(int x) { return x + 1 > x; }
// 编译器可能直接优化成 return true（假设 x+1 不会溢出）
// 但如果 x = INT_MAX，实际会溢出，结果就错了
```

**所以**：不是"优化让 UB 出问题"，而是"UB 让优化变得不可预测"。写无 UB 的代码，优化才安全。

## 4. 检测工具

```bash
# UBSan：检测未定义行为（溢出、移位、空指针等）
g++ -fsanitize=undefined -g main.cpp -o main

# ASan：检测内存错误（越界、悬垂、泄漏）
g++ -fsanitize=address -g main.cpp -o main

# 编译警告（很多 UB 会警告）
g++ -Wall -Wextra main.cpp

# -fno-strict-aliasing：关闭严格别名优化（临时绕过）
g++ -fno-strict-aliasing main.cpp
```

## 5. 要点回顾

1.  **UB 是什么**：标准不规定，编译器可做任何事，"看起来正常"最坑
2.  **严格别名**：不能用不同类型指针访问同一内存（用 memcpy/bit_cast）
3.  **有符号溢出是 UB，无符号回绕是定义好的**
4.  **序列点**：同一表达式不能多次读写同一变量（`i = i++ + i++`）
5.  **UB 与优化**：优化假设无 UB，有 UB 则优化不可预测
6.  **检测**：UBSan（未定义行为）+ ASan（内存错误）
