# 未定义行为

UB（Undefined Behavior）= 标准**不作任何要求**的行为——不是"结果随机"，而是程序一旦执行到那里，标准不再约束任何事。编译器可以做任何事——最容易误导的是"看起来正常"，换个编译器/优化等级就崩。这是难以排查的错误的根源。

## 1. 什么是 UB

```cpp
// 标准对 UB 不做任何保证：
// 编译器可以：优化掉、崩溃、看起来正常运行、或做任何事
```

**最危险的点**：

- **看起来正常**（当下不报错）→ 上线后换个环境崩
- **性能优化会"失效"**：编译器基于"代码无 UB"的假设优化，有 UB 时代码行为不可预测

## 2. 常见 UB 清单

### 2.1 内存与生命周期

```cpp
int* p = nullptr;
*p;                        // ❌ 解引用空指针

int* w;
*w;                        // ❌ 未初始化（野指针）

int* q = new int(5);
delete q;
*q;                        // ❌ 悬垂指针（use-after-free）

int* r = new int(5);
delete r;
delete r;                  // ❌ double free

int arr[3];
arr[5];                    // ❌ 数组越界

int x;
if (x > 0) { }             // ❌ 读未初始化变量（C++26 起为 erroneous behavior）

int* buf = new int[3];
delete buf;                // ❌ new[] 必须配 delete[]
```

野指针、悬垂指针、空指针的区别见[内存管理](内存管理.md) §3。

**悬垂引用**（和悬垂指针是两回事）：

```cpp
int& Bad() {
  int local = 1;
  return local;            // ❌ 返回后 local 已销毁，使用这个引用是 UB
}
```

内存配对规则：`new` ↔ `delete`、`new[]` ↔ `delete[]`；`malloc`/`free` 不能和 `new`/`delete` 混用。

### 2.2 严格别名

**规则**：不能通过"不相关类型"的指针访问同一内存（type-punning）：

```cpp
float f = 1.0f;
int* p = reinterpret_cast<int*>(&f);   // 转指针本身合法
*p;                                     // ❌ 用 int 左值访问 float 内存
```

**例外**：`char` / `unsigned char` / `std::byte` 读对象字节；**正确做法**是 `memcpy` 或 C++20 的 `std::bit_cast`。

### 2.3 容器与视图

```cpp
std::vector<int> v{1, 2, 3};
auto it = v.begin();
v.erase(v.begin());        // 删除后 it 失效
*it;                       // ❌ 使用失效迭代器

std::vector<int> empty;
empty.front();             // ❌ 空容器上 front()/back()/pop()

std::string_view sv = std::string("hi");  // 临时 string 在分号处销毁
sv[0];                                     // ❌ sv 悬垂
```

**规则**：容器扩容 / 删除元素后，之前的迭代器、引用、指针都可能失效；`string_view` / `span` 不拥有数据，源对象销毁后就悬垂（完整失效规则见[容器与迭代器](容器与迭代器.md)）。

### 2.4 整数与移位

```cpp
int a = INT_MAX;
a + 1;                     // ❌ 有符号溢出（无符号回绕是定义好的）

int b = 1 / 0;             // ❌ 整数除零
int c = INT_MIN / -1;      // ❌ 商无法表示

int d = 1 << 32;           // ❌ 移位位数 >= 类型宽度
int e = 1 << -1;           // ❌ 移位位数为负
int f = -1 << 1;           // C++17 及以前 UB；C++20 起定义为 -2
```

**版本差异**：`1 << 31` 从 C++11 起合法（结果是 `INT_MIN`）；负数左移从 C++20 起按模 2^N 定义；负数右移在 C++20 前是实现定义。

### 2.5 求值顺序

```cpp
int i = 0;
i = i++ + i++;             // ❌ 同一个子表达式里两次修改 i，没有先后顺序

int a[5] = {0};
int j = 0;
a[j] = j++;                // C++17 起定义良好（之前是 UB）：先算 j++，再取 a[1]
```

**规则**：对同一标量对象的两次修改（或一次修改 + 一次读值）如果没有先后顺序，就是 UB。`i = i + 1` 有明确顺序，合法。

**C++17 起**：赋值号右边先于左边求值，`a[i] = i++`、`i = i++ + 2` 从 UB 变成定义良好；但 `i = i++ + i++` 仍然是 UB。

### 2.6 对象与多态

```cpp
struct Base { ~Base() {} };
struct Derived : Base { std::string s; };
Base* b = new Derived();
delete b;                  // ❌ 基类析构不是 virtual（Derived 的析构不会执行）

struct S { void f() {} };
S* s = nullptr;
s->f();                    // ❌ 空指针上调用成员函数（即使 f 不访问成员）

char* str = const_cast<char*>("hello");
str[0] = 'H';              // ❌ 修改 const 对象（字面量通常在只读区）
```

### 2.7 库与算法

```cpp
std::vector<int> v{3, 1, 2};
std::sort(v.begin(), v.end(), [](int a, int b) { return a <= b; });  // ❌ 不满足严格弱序

std::optional<int> opt;
*opt;                      // ❌ 空值解引用（opt.value() 是抛异常，不是 UB）
```

比较器必须满足严格弱序（`<` 语义）；写 `<=` 或 `a - b` 都可能破坏它，`std::sort` 会因此越界/崩溃（见[算法与函数对象](算法与函数对象.md)）。

### 2.8 并发

```cpp
int x = 0;
// 线程 1：x = 1;
// 线程 2：int y = x;    // ❌ 无锁读写同一变量 = 数据竞争 = UB
```

C++ 内存模型规定：**数据竞争就是 UB**，不只是"结果不确定"（见[并发编程](并发编程.md)）。

## 3. UB 和性能优化的关系

**编译器优化建立在"程序无 UB"的假设上**：

```cpp
// 代码有 UB（有符号溢出），编译器假设不会溢出：
int f(int x) { return x + 1 > x; }
// 编译器可能直接优化成 return true（假设 x+1 不会溢出）
// 但如果 x = INT_MAX，实际会溢出，结果就错了
```

**所以**：不是"优化让 UB 出问题"，而是"UB 让优化变得不可预测"。写无 UB 的代码，优化才安全。

## 4. 检测工具

```bash
# UBSan：检测未定义行为（溢出、移位、空指针等）
g++ -fsanitize=undefined -g main.cpp -o main

# ASan：检测内存错误（越界、悬垂、泄漏）
g++ -fsanitize=address -g main.cpp -o main

# TSan：检测数据竞争
g++ -fsanitize=thread -g main.cpp -o main

# 编译警告（很多 UB 会警告）
g++ -Wall -Wextra main.cpp

# -fno-strict-aliasing：关闭严格别名优化（临时绕过）
g++ -fno-strict-aliasing main.cpp
```

## 5. 要点回顾

1.  **UB 是什么**：标准不作任何要求，编译器可做任何事，"看起来正常"最容易误导
2.  **内存**：空指针、悬垂指针/引用、double free、越界、未初始化读、迭代器失效
3.  **整数**：有符号溢出、除零、移位越界是 UB；无符号回绕是定义好的
4.  **求值顺序**：同一子表达式里对同一变量两次修改是 UB；C++17 起 `a[i] = i++` 定义良好
5.  **对象与库**：基类析构要 virtual；比较器要严格弱序；空容器/空 optional 不能直接取值
6.  **并发**：数据竞争 = UB
7.  **检测**：UBSan + ASan + TSan
