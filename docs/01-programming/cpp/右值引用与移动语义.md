# 右值引用与移动语义

C++11 引入的核心特性。解决的问题：**拷贝昂贵对象时，能否"偷"资源而不是复制**。

## 1. 左值 vs 右值

| | 左值（lvalue） | 右值（rvalue） |
|--|--------------|--------------|
| 是什么 | 有名字、可取地址、持久 | 临时对象、无名字、即将销毁 |
| 例子 | 变量、解引用、返回引用 | 字面量、表达式结果、`std::move(x)` |
| 能否取地址 | ✅ `&x` 可以 | ❌ 不可以 |

```cpp
int a = 5;         // a 是左值，5 是右值
int b = a + 1;     // b 是左值，a+1 是右值（临时结果）

std::string s1 = "hello";
std::string s2 = s1 + " world";   // s1 是左值，s1+" world" 是右值（临时）
```

## 2. 右值引用

```cpp
int&& r = 5;              // 右值引用，绑定右值
std::string&& s = std::string("tmp");   // 绑定临时对象

// 左值引用 vs 右值引用：
int& lr = a;              // 左值引用（&），绑定左值
int&& rr = 5;             // 右值引用（&&），绑定右值
```

**意义**：右值引用让函数能区分"传进来的是临时对象（可偷）还是持久对象（不能偷）"。

## 3. 移动构造 / 移动赋值

**问题**：拷贝构造要深拷贝（复制内容），但如果源对象是临时对象（马上要销毁），完全可以"偷"它的资源：

```cpp
class String {
    char* data_;
public:
    // 拷贝构造：深拷贝（复制内容，源对象保留）
    String(const String& other) {
        data_ = new char[strlen(other.data_) + 1];
        strcpy(data_, other.data_);
    }

    // 移动构造：偷资源（把指针抢过来，源对象置空）
    String(String&& other) noexcept {
        data_ = other.data_;     // 直接把指针"抢"过来
        other.data_ = nullptr;   // 源对象置空，防止析构时 double free
    }
};

String s1("hello");
String s2 = s1;                       // 拷贝（s1 还要用）
String s3 = std::move(s1);            // 移动（s1 不要了，资源转给 s3）
String s4 = String("temp");           // 移动（右值自动走移动构造）
```

**本质**：移动 = 浅拷贝 + 源对象置空。偷指针、不复制数据，O(1) 而不是 O(n)。

## 4. std::move

```cpp
std::move(x)   // 把左值"转换"成右值
```

**关键理解**：`std::move` **什么都不移动**！它只是一个**类型转换**（把左值转成右值引用），真正的"移动"发生在移动构造/移动赋值里。

```cpp
// std::move 的实现（简化版）：
template <typename T>
constexpr std::remove_reference_t<T>&& move(T&& t) noexcept {
    return static_cast<std::remove_reference_t<T>&&>(t);   // 就是个 static_cast！
}
// 注意：必须用 remove_reference——否则 T 推导成 T& 时，
// 返回类型 T&& 会折叠回左值引用，就"移不动"了
```

**为什么要用**：当确定某个对象"之后不用了"，用 `std::move` 告诉编译器"可以偷它的资源"。

```cpp
std::vector<std::string> v;
std::string s = "hello";
v.push_back(s);               // 拷贝（s 还要用）
v.push_back(std::move(s));    // 移动（s 之后不用了，资源被偷）
// 之后 s 是"有效但未指定"状态（通常为空），不要再用 s 的值
```

**注意**：`std::move` 后，源对象是"有效但未指定"状态——析构仍安全，但内容不保证。**不要假设它是什么值**。

## 5. 完美转发 std::forward

**问题**：模板函数里转发参数时，怎么保持参数的"左值/右值属性"不丢？

```cpp
template <typename T>
void wrapper(T&& arg) {
    // 直接传 arg：arg 是具名变量，永远是左值！
    // 原来传进来的是右值，这里却变成左值 → 属性丢了
    target(std::forward<T>(arg));   // forward 保持原属性
}

// 用法：
wrapper(5);            // 右值传进来，forward 后仍是右值 → 走移动
int x = 5;
wrapper(x);            // 左值传进来，forward 后仍是左值 → 走拷贝
```

**std::move vs std::forward**：

- `std::move`：无条件转成右值
- `std::forward`：条件性保持原属性（左值还是左值，右值还是右值）

## 6. 万能引用（转发引用）

```cpp
template <typename T>
void f(T&& x);          // T&& 不是右值引用，是"万能引用"！

auto&& y = ...;         // auto&& 也是万能引用
```

**规则**：`T&&` 在**模板推导**或 `auto&&` 时是万能引用——传左值，T 推导成 `T&`，x 是左值引用；传右值，T 推导成 `T`，x 是右值引用。

```cpp
// 非模板的 && 才是真的右值引用：
void g(std::string&& s);   // 真的右值引用（无推导）
```

## 7. 引用折叠

```cpp
// 引用的引用会"折叠"：
T&  &   →  T&
T&  &&  →  T&
T&& &   →  T&
T&& &&  →  T&&      // 只有"右值引用的右值引用"还是右值引用
```

**记忆**：**只要有一个左值引用，折叠结果就是左值引用**。

**为什么有折叠**：C++ 本来**不允许"引用的引用"**（`int& &` 非法），但模板推导、别名组合时可能拼出"引用的引用"，所以标准规定了一套"折叠规则"，把两层引用压成一层。

## 8. RVO / NRVO 拷贝消除

**问题**：函数返回对象时，会拷贝几次？

```cpp
std::string make() {
    return std::string("hello");   // 会拷贝吗？
}
std::string s = make();
```

**答案**：编译器做了**拷贝消除**（copy elision），大多数情况**零拷贝**。

| 术语 | 全称 | 场景 |
|------|------|------|
| **RVO** | Return Value Optimization | 返回**临时对象**（`return std::string(...)`） |
| **NRVO** | Named RVO | 返回**具名局部变量**（`return s;`） |

```cpp
// RVO：返回临时对象，C++17 起是强制保证的（就是"保证复制省略"）
std::string f1() { return std::string("hi"); }

// NRVO：返回具名变量，编译器通常也会优化（但不是标准强制）
std::string f2() {
    std::string s = "hi";
    return s;         // 大多数编译器会 NRVO，不拷贝
}
```

**什么时候失效**（NRVO 是可选优化，这些情况可能失效）：

```cpp
// 1. 有多个返回路径（不同变量）
std::string f(bool flag) {
    std::string a = "A", b = "B";
    return flag ? a : b;     // 可能无法 NRVO
}

// 2. 返回参数/成员（不是局部变量）
std::string g(std::string s) { return s; }   // s 是参数，只能移动不能消除
```

**记忆**：

- C++17 起：返回 prvalue（临时对象）**强制**零拷贝（保证复制省略）
- NRVO：编译器尽力而为，不是标准保证
- 不能消除时：优先移动（有移动构造），再退化拷贝

## 9. 什么时候用移动

1. **返回临时对象**：编译器自动移动（或 NRVO 省略）
2. **要"转移所有权"**：`std::move` + 移动构造（unique_ptr 就是这么实现的）
3. **push_back 大对象且源不再用**：`push_back(std::move(x))`
4. **完美转发**：模板包装函数转发参数

## 10. 进阶：误区与细节

### 10.1 `std::move` 的误用

**坑 1：move 后继续用源对象**

```cpp
std::string s = "hello";
std::string t = std::move(s);
std::cout << s;      // ❌ s 是"有效但未指定"状态，别用它的值
s = "ok";            // 但可以重新赋值
```

**坑 2：对 const 对象 move —— 实际变成拷贝**

```cpp
const std::string s = "hello";
std::string t = std::move(s);   // ⚠️ const 无法移动！实际调拷贝构造
// 因为移动构造参数是 string&&（非 const），const 对象只能绑到 const string&（拷贝）
```

**坑 3：对函数返回的局部变量 move —— 反而妨碍 RVO**

```cpp
std::string f() {
    std::string s = "hello";
    return std::move(s);   // ❌ 画蛇添足！妨碍 NRVO，可能更慢
    // return s;           // 编译器会 NRVO 或自动移动
}
```

### 10.2 移动构造的异常安全

移动构造**必须 noexcept**（前文提过），否则：

```cpp
class String {
    String(String&& other) noexcept { /* 偷指针 */ }   // 加 noexcept
};

// 为什么：vector 扩容要搬移元素。
// 若移动可能抛异常，vector 为了保证"强异常安全"（失败时原容器不变），
// 只能退而用拷贝（拷贝失败可回滚）→ 慢。
// 加 noexcept 后，vector 放心用移动。
```

### 10.3 emplace_back 与 push_back

```cpp
std::vector<std::string> v;

v.push_back("hello");              // ① 用 "hello" 构造临时 string ② 移动进 vector
v.emplace_back("hello");           // ① 直接在 vector 内存上构造 string，无临时对象

// emplace_back 的参数是"构造函数的参数"，直接转发给原地构造
v.emplace_back(5, 'x');            // 构造 "xxxxx"，直接原地
```

**底层**：`emplace_back` 用完美转发把参数传给 `placement new`，在容器内存上**原地构造**，省去"构造临时对象 + 移动"这一步。

```cpp
// 简化原理：
template <typename... Args>
void emplace_back(Args&&... args) {
    new (end_ptr) T(std::forward<Args>(args)...);   // 原地构造
}
```

**所以**：emplace 对"需要显式构造"的场景（如传多个参数）更高效；传现成对象时两者差不多。

**坑：`emplace_back` 的参数是"构造函数参数"** ⚠️——**不能直接传花括号** ❌：

```cpp
std::vector<std::vector<int>> v;
v.push_back({1, 2, 3});                              // ✅ push_back 收 initializer_list
v.emplace_back({1, 2, 3});                           // ❌ 编译错误：花括号推导不出类型
v.emplace_back(std::initializer_list<int>{1, 2, 3}); // ✅ 写全类型才行
```

**怎么选**（同一台机器实测，20 万行 × 100 列）：

| 写法 | 耗时 | 适用 |
|------|:---:|------|
| `push_back(level)` | 25.4 ms | 拷贝——最差 ❌ |
| `push_back(std::move(level))` | 7.8 ms | **手里已有对象** |
| `push_back(vector<int>(COLS, r))` | 22.8 ms | 先造临时再移动（多一次构造 + 析构）❌ |
| `emplace_back(COLS, r)` | 8.4 ms | **没有对象、按参数构造** |
| `resize(n)` + 直接写 `v[i]` | 7.6 ms | 批量、已知数量（最快） |

小类型不用纠结：1000 万次 `push_back(1)` 36 ms vs `emplace_back(1)` 34 ms。一句话：**有对象用 `push_back`（顺手 `move`），没对象用 `emplace_back`**。

### 10.4 move_iterator（移动版迭代器）

普通迭代器解引用是**左值**（拷贝），`move_iterator` 解引用是**右值**（移动）：

```cpp
std::vector<std::string> src{"a", "b"};

// 普通 copy：拷贝
std::vector<std::string> dst1(src.begin(), src.end());

// move_iterator：移动（源被掏空）
std::vector<std::string> dst2(
    std::make_move_iterator(src.begin()),
    std::make_move_iterator(src.end())
);
```

**用途**：批量"搬运"容器元素（如 `std::move(src)` 整体转移时内部就用它）。

## 11. 要点回顾

1. **左值 vs 右值**：可取名取地址 vs 临时即将销毁
2. **移动 = 浅拷贝 + 源置空**，O(1) 偷资源
3. **`std::move` 只是类型转换**，不移动任何东西
4. **move 误用**：move 后别用源、const 对象 move 变拷贝、返回局部变量别 move（妨碍 RVO）
5. **移动构造要加 `noexcept`**（不然 vector 扩容退化用拷贝）
6. **完美转发 `std::forward`**：保持左值/右值属性
7. **万能引用 `T&&`**（模板推导中）：左值右值都能接；**引用折叠**：有左值引用就折叠成左值
8. **emplace_back**：原地构造，省临时对象（比 push_back 高效）
