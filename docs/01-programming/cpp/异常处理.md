# 异常处理

C++ 错误处理机制：`throw` 抛出、`try/catch` 捕获。核心是**栈展开与 RAII**、**异常安全**、**noexcept**；另外要会选错误处理策略。

## 1. 基本语法与栈展开

```cpp
int divide(int a, int b) {
    if (b == 0) throw std::runtime_error("除零");   // 抛出异常
    return a / b;
}

int main() {
    try {
        divide(1, 0);
    } catch (const std::runtime_error& e) {
        std::cout << e.what();     // 捕获：打印 "除零"
    } catch (...) {
        // 最后捕获：记录日志或转成错误码，不要静默忽略
    }
}
```

**机制**：`throw` 后函数立即退出，控制流沿调用栈**往回找** `catch`（栈展开）。找到匹配的 catch 就处理，找不到程序终止（`std::terminate`；是否先展开栈由实现决定）。

**栈展开**：异常抛出后，从 throw 到 catch 之间的所有**局部自动对象**都会被逆序析构。裸指针不会自动 `delete`——这正是要用 RAII 的原因。

## 2. 抛与捕的规则

### 抛：按值

```cpp
throw std::runtime_error("db down");   // 异常对象独立于局部变量
```

- 不要 `throw new MyError()`：谁 `delete`？
- 在 catch 里重新抛出当前异常用 `throw;`（不带操作数）

### 捕：按 const 引用

```cpp
catch (const std::exception& e) { ... }
```

**按值捕获会切片**（实测）：

```cpp
try {
    throw std::runtime_error("db down");
} catch (std::exception e) {          // ❌ 按值：切片
    // e.what() 只剩基类消息，派生类信息丢失
}
```

也不要按指针捕获：所有权和生命周期都不清楚。

### 匹配规则

- 精确类型（忽略 cv 限定）
- **派生类 → 基类**可以匹配
- 允许指针的限定/派生转换
- **不做算术转换、不做用户定义转换**：`throw 1` 不会被 `catch (double)` 接住（会落到 `catch (int)`）

### catch 顺序

最具体的放前面：

```cpp
catch (const MyError& e) { ... }
catch (const std::exception& e) { ... }
catch (...) { /* 记录日志 */ throw; }
```

`catch (...)` 放最后；除非确实能处理所有异常，否则**记录后重新抛出**，不要静默忽略。

## 3. 标准异常体系

| 异常 | 含义 |
|------|------|
| `std::exception` | 所有标准异常的基类；`what()` 是 `noexcept` 虚函数 |
| `std::logic_error` | 程序逻辑错误：`invalid_argument` / `out_of_range` / `length_error` / `domain_error` |
| `std::runtime_error` | 运行时错误：`range_error` / `overflow_error` / `underflow_error`；`system_error` 也继承它 |
| `std::bad_alloc` | `new` 失败 |
| `std::bad_cast` / `std::bad_typeid` | 动态转换 / `typeid` 失败 |
| `std::bad_optional_access` / `std::bad_variant_access` | 空 `optional` / `variant` 取错类型（`value()` / `get` 抛出） |

自定义异常一般继承 `std::runtime_error`：

```cpp
class DbError : public std::runtime_error {
 public:
  using std::runtime_error::runtime_error;   // 继承构造函数
};
```

自定义异常可以重写 `what()`，但不要让它抛异常。

## 4. 异常安全

异常安全分四档：

| 等级 | 保证 | 说明 |
|------|------|------|
| 不抛保证 | 绝不抛异常 | `noexcept` 函数 |
| 强保证 | 失败像没发生一样 | 要么成功，要么状态完全不变 |
| 基本保证 | 不泄漏、对象仍可用 | 状态可能改变 |
| 无保证 | 什么都不保证 | 遗留代码常见，应该避免 |

**强保证的标准写法：copy-and-swap**

```cpp
Widget& operator=(const Widget& other) {
    Widget tmp(other);   // 拷贝可能抛；失败时 *this 一点没动
    swap(tmp);           // swap 必须 noexcept
    return *this;
}
```

RAII 负责"不泄漏"，copy-and-swap 负责"状态可回滚"。

`vector` 扩容的强保证依赖移动构造的 `noexcept`——细节见 [C++11-14](C++11-14.md) 第 17 节。

## 5. noexcept

**含义**：承诺函数不抛异常；违反承诺 → 直接 `std::terminate`。

```cpp
void f() noexcept;                    // 承诺不抛
void g() noexcept(false);             // 可能抛（少见）
```

**noexcept 运算符**：编译期判断表达式是否会抛（`f` / `g` 沿用上面的声明）。

```cpp
static_assert(noexcept(f()));         // true
static_assert(!noexcept(g()));        // true

// 条件 noexcept（模板库常见）
template <typename T>
void swap(T& a, T& b) noexcept(noexcept(a.swap(b)));
```

**C++17 起，noexcept 是函数类型的一部分**：

```cpp
void (*p)() noexcept;   // 与 void (*)() 是不同类型
```

**什么时候标**：

- 不会抛的移动构造 / 移动赋值 → 标 `noexcept`（`vector` 扩容才会放心用移动）
- `swap` → 标
- 析构函数 → 默认就是 `noexcept`，别改
- **可能抛异常的函数不要强行标注**：标了再抛就是 `std::terminate`

## 6. 构造与析构中的异常

### 构造函数抛异常

```cpp
struct Member {
    ~Member() { std::puts("Member::~Member"); }
};

struct Obj {
    Member m;
    Obj() {
        std::puts("Obj::Obj");
        throw std::runtime_error("ctor failed");
    }
    ~Obj() { std::puts("Obj::~Obj"); }
};
```

实测输出：

```
Obj::Obj
Member::~Member      ← 已构造的成员（以及基类）会被析构
（Obj::~Obj 不执行）  ← 对象没构造完成，析构函数不调用
```

**结论**：资源放进成员（RAII），不要放在构造函数体里直接 `new`：

```cpp
class Conn {
 public:
  Conn() {
    raw_ = Open();            // ❌ 后面一抛，raw_ 泄漏
    if (bad) throw ...;
  }
 private:
  RawHandle* raw_;
};
```

### 析构函数不能抛

- 如果正在**栈展开**（处理另一个异常），析构再抛 → 两个异常并存 → `std::terminate`
- 析构里的失败操作（`close`、`flush`）只能忽略或记录日志

## 7. 线程中的异常

**异常不会自动跨线程传播**。线程里没被捕获 → `std::terminate`。

```cpp
// 1) std::async：异常存进 future，get() 时重新抛出
auto fut = std::async(std::launch::async, [] {
    throw std::runtime_error("worker failed");
});
try {
    fut.get();
} catch (const std::exception& e) {
    // ...
}

// 2) exception_ptr：手动搬运到主线程
std::exception_ptr ep;
std::thread t([&] {
    try {
        Work();
    } catch (...) {
        ep = std::current_exception();
    }
});
t.join();
if (ep) {
    try {
        std::rethrow_exception(ep);
    } catch (const std::exception& e) {
        // ...
    }
}
```

`std::future` / `promise` 的异常传递见[并发编程](并发编程.md)。

## 8. 什么时候用 / 性能取舍

### 默认策略

普通应用、服务端、工具链用异常 + RAII 处理真正的异常；可预期、频繁的失败（解析输入、查找未命中、热路径）用错误码 / `std::optional` / `std::expected`；内核、嵌入式、硬实时、部分游戏引擎可以整体禁用异常（`-fno-exceptions`）。

是否禁用是**项目级决策**，不是语言规定。

| 机制 | 适合 |
|------|------|
| 异常 | 构造失败、深调用链、罕见错误、需要跨层传播 |
| 错误码 | 可预期、频繁、性能敏感、C 接口 |
| `std::expected<T, E>`（C++23） | 可预期的失败，且想强制调用方处理 |
| `std::optional<T>` | 只有"有没有值"，没有错误信息 |

### 禁用异常的代价

| 代价 | 说明 |
|------|------|
| 构造函数不能失败 | 只能两段式 `Init()`，或工厂函数返回 `optional` / `expected` |
| 标准库抛异常的路径 | 直接终止（实现相关） |
| 错误传播 | 每层手动检查、传递错误码 |
| 团队约定 | 必须统一 `error_code` / `expected` 体系 |

### 性能：零成本模型

主流实现（GCC/Clang/MSVC）都是"零成本"模型：

- 不抛时：几乎没有运行时开销（靠查表展开，不插分支）
- 抛时：构造异常对象 + 栈展开 + 匹配，**很贵**（微秒级）

所以：

- ❌ 不要用异常做正常控制流（循环退出、查找未命中）
- **冷路径**、真正的异常情况用异常没问题
- 二进制体积会增加（展开表）

**边界**：

- 异常不能穿过 C 栈帧（C 代码没有展开表）——见[编译链接](编译链接.md)的"异常跨库"问题
- `new` 失败默认抛 `std::bad_alloc`；`nothrow` 版返回 `nullptr`——见[内存管理](内存管理.md)

## 9. 常见错误

1. **按值捕获** → 切片，派生信息丢失
2. **`catch (...)` 静默忽略** → 没有日志、没有重新抛出，问题被掩盖
3. **`throw new`** → 没人 `delete`
4. **析构里抛** → 栈展开时 `terminate`
5. **`noexcept` 与实际行为不符** → 直接 `terminate`
6. **构造函数体里直接 `new` 后抛** → 泄漏
7. **catch 顺序反了**（基类在前）→ 派生 catch 永远进不去
8. **线程里漏捕** → `terminate`
9. **异常跨 C / 动态库边界** → 行为不可靠
10. **用异常做流程控制** → 性能和行为都难维护

## 10. 要点回顾

1. **机制**：`throw` → 栈展开（局部对象析构）→ 找 `catch`；找不到 → `terminate`
2. **抛捕**：抛值、捕 `const` 引用；派生→基类匹配、具体在前；`catch (...)` 最后捕获后重新抛出
3. **标准异常**：都继承 `std::exception`；自定义异常一般继承 `std::runtime_error`；`what()` 可重写，但不要让它抛异常
4. **安全与 noexcept**：不抛 / 强 / 基本 / 无保证；RAII 负责不泄漏，copy-and-swap 负责回滚；不会抛才标 `noexcept`，违反 → `terminate`
5. **构造与析构**：构造抛异常时成员/基类会析构、对象析构不调用，资源放成员；析构绝不能抛
6. **线程与策略**：异常不自动跨线程，用 `future` 或 `exception_ptr`；普通应用默认用异常，可预期失败用错误码/`expected`，禁用是项目决策
