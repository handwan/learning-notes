# 基础

C++ 基础常用小知识点合集：引用 vs 指针、this、inline、C++ vs C、auto 推导、函数指针、constexpr、初始化。

## 1. 引用 vs 指针

```cpp
int a = 5;

int& r = a;       // 引用：a 的别名
int* p = &a;      // 指针：存 a 的地址

r = 10;           // 改 r 就是改 a
*p = 10;          // 解引用改 a
```

| 区别 | 引用 | 指针 |
|------|------|------|
| 初始化 | **必须**初始化 | 可以不初始化（危险） |
| 能否为空 | 不能（没有空引用） | 能（nullptr） |
| 能否改绑 | 不能（绑死一个对象） | 能（指向别的） |
| 语法 | `r` 直接用（像别名） | `*p` 解引用 |
| 多级 | 没有引用的引用 | 有多级指针 `int**` |
| sizeof | 引用对象的大小 | 指针本身 8 字节 |

**底层**：引用通常实现为指针（编译器层面），但语义上是"别名"——用的时候不用 `*`，不能为空、不能改绑。

**为什么必须初始化、不能改绑**：引用是"别名"，别名必须绑定一个**已存在的对象**——世界上没有"空的别名"，也没有"今天别名是张三、明天别名是李四"这种事。

**一句话**：引用 = "绑定后不可改的别名"；指针 = "可以指向任意地址的变量"。

### 访问成员：`.` 还是 `->`

看左边是**对象/引用**还是**指针**：

| 左边是 | 用 | 例子 |
|--------|:---:|------|
| 对象、引用 | `.` | `ListNode dummy(0);` → `dummy.next` |
| 指针 | `->` | `ListNode* p = &dummy;` → `p->next` |

`p->x` 就是 `(*p).x` 的简写。写错了编译器会直接点出来（实测）：

- 对象用 `->` → `error: base operand of '->' has non-pointer type`
- 指针用 `.` → `error: request for member ... which is of pointer type ... (maybe you meant to use '->' ?)`

## 2. this 指针

**this 是什么**：成员函数里的**指向当前对象的指针**。

```cpp
class A {
    int x_;
public:
    void set(int x) { x_ = x; }     // 等价于 this->x_ = x
};

// 底层：成员函数其实多一个隐藏参数
// void set(A* this, int x) { this->x_ = x; }
```

**const 成员函数里 this 的类型**：

```cpp
class A {
public:
    void f() const { /* 这里 this 是 const A* */ }
    void g() { /* 这里 this 是 A* */ }
};
// const 成员函数里 this 是 const A*（不能通过 this 修改成员）——这就是 const 成员函数"不修改"的原理
```

**静态成员函数没有 this**（不依赖对象，所以不能访问非静态成员）。

## 3. 内联函数 inline

**作用**：把函数体"展开"到调用处，省掉函数调用的开销（压栈、跳转）。

```cpp
inline int square(int x) { return x * x; }
// 调用 square(5) 可能直接展开成 5*5，不跳转
```

**关键**：**inline 是"建议"不是"命令"**——编译器可能不采纳（函数太大、递归等），也可能自动内联没标 inline 的小函数。

**inline vs 宏**：

| | 内联函数 | 宏 |
|--|---------|-----|
| 类型检查 | ✅ 有 | ❌ 无（纯文本替换） |
| 调试 | ✅ 可调试 | ❌ 难调试 |
| 参数求值 | 一次 | 可能多次（`#define SQUARE(x) x*x` 的坑：`SQUARE(a++)`） |

**现代实践**：inline 主要用于**头文件里定义函数**（避免重复定义），编译器自己会决定要不要真内联。

## 4. C++ 和 C 的区别

经典问题，从这几个维度答：

1. **面向对象**：类、封装、继承、多态（C 只有结构体和函数）
2. **泛型编程**：模板（C 用宏/void* 模拟）
3. **异常处理**：try/catch/throw（C 用返回值 + errno）
4. **智能指针/RAII**：自动资源管理（C 手动 free）
5. **STL**：标准库容器/算法（C 没有）
6. **其他语法**：引用、函数重载、命名空间、bool、constexpr

**更本质的区别**：C++ 是**多范式**（面向对象 + 泛型 + 函数式），强调类型安全和抽象；C 是过程式，贴近硬件。

## 5. auto 推导规则

```cpp
const int& f();

auto a = f();        // a 是 int（auto 丢掉引用和 const！）
auto& b = f();       // b 是 const int&（auto& 保留）
const auto& c = f(); // c 是 const int&
auto&& d = f();      // d 是万能引用
```

**规则**：`auto` 会**丢掉引用和顶层 const**（类似按值传参）；要保留就显式写 `auto&` / `const auto&`。

```cpp
std::vector<bool> v;
auto x = v[0];      // ⚠️ vector<bool> 的坑：x 是代理对象，不是 bool&
auto& y = v[0];     // ❌ 编译错误（v[0] 是临时代理）
```

**decltype 对比**：`decltype(expr)` 保留引用和 const（原封不动），和 auto 不同。

## 6. 函数指针

**声明与使用**：

```cpp
int add(int a, int b) { return a + b; }

int (*fp)(int, int) = add;   // 函数指针声明（绕：(*fp) 是函数）
int (*fp2)(int, int) = &add; // & 可省略

fp(1, 2);      // 调用
(*fp)(1, 2);   // 等价
```

**作为回调**（C 风格，现代多被 std::function/lambda 替代）：

```cpp
void for_each(int* arr, int n, int (*visit)(int)) {
    for (int i = 0; i < n; i++) visit(arr[i]);
}

for_each(arr, 5, square);   // 传函数
```

### 成员函数指针：比普通函数指针多带一个 `this`

非 static 的成员函数有**隐含的第一参数 `this`**，所以它的指针类型和普通函数指针不同：

| | 类型 | `sizeof` |
|---|------|:---:|
| 普通函数指针 | `int (*)(int)` | 8 |
| 成员函数指针 | `int (S::*)(int)` | 16 |

```cpp
int apply(int (*f)(int), int x) { return f(x); }

class S {
public:
    int m(int x) { return x + 1; }         // 普通成员：带 this
    static int s(int x) { return x + 1; }  // static 成员：没有 this
};

apply(&S::s, 1);      // ✅ 能当普通函数用（static 没有 this）
apply(&S::m, 1);      // ❌ cannot convert 'int (S::*)(int)' to 'int (*)(int)'
S obj; obj.m(1);      // ✅ 普通成员必须通过对象调用
```

**实践含义**：函数体里用不到成员时写成 `static` 成员函数——语义清楚（不依赖对象），还能当普通函数用。这是**类型/语义**问题，不涉及运行时开销。

## 7. constexpr vs const

| | const | constexpr |
|--|-------|-----------|
| 含义 | 运行期不可改 | **编译期**求值 |
| 初始化 | 运行期也可 | 必须编译期可确定 |
| 场景 | 一般常量 | 数组大小、模板参数、编译期计算 |

```cpp
const int a = rand();        // 运行期初始化也行
constexpr int b = 10;        // 编译期常量
constexpr int c = rand();    // ❌ 编译错误：rand 不能编译期求值

constexpr int square(int x) { return x * x; }   // constexpr 函数
constexpr int s = square(5);                    // 编译期算好
```

**一句话**：constexpr 是"更强的 const"——保证编译期能算出来。

## 8. 三种初始化方式

```cpp
int a = 5;      // ① 拷贝初始化
int b(5);       // ② 直接初始化
int c{5};       // ③ 列表初始化（C++11 推荐）
```

**③ 大括号的特点**（推荐用它）：

```cpp
int c{5.5};        // ❌ 编译错误：窄化转换被禁止（double → int）
int a = 5.5;       // 编译通过（丢精度，只警告）

// 避免"最令人烦恼的解析"：
T t();             // ❌ 这是函数声明，不是对象！
T t{};             // 明确是构造对象
```

**初始化 vs 赋值**：

```cpp
int a = 5;     // 初始化（创建时给值）
a = 6;         // 赋值（已存在，改值）

// 类对象：
String s1("hello");        // 初始化：直接调构造函数
String s2;
s2 = s1;                   // 赋值：调拷贝赋值运算符（先构造再赋值，两步）
```

**一句话**：初始化是"出生时给值"（调构造函数），赋值是"出生后改值"（调 operator=）。用大括号初始化最安全（禁窄化、防歧义）。

## 9. 输入输出流（IO 流）

### 基本用法

```cpp
#include <iostream>

std::cout << "x = " << x << std::endl;    // 输出（endl = 换行 + 刷新，慢）
std::cout << "x = " << x << '\n';          // 推荐：'\n' 只换行不刷新，更快

int a;
std::cin >> a;                             // 输入

std::cerr << "错误";                        // 错误输出（不缓冲，立即输出）
```

### cin/cout 慢的原因与优化

**问题**：C++ 的 `cin/cout` 默认和 C 的 `scanf/printf` **同步**（保证混用不出错），所以慢。

```cpp
// 算法竞赛/刷题常用优化（放 main 开头）：
std::ios::sync_with_stdio(false);   // 关闭和 stdio 的同步 → 提速
std::cin.tie(nullptr);              // 解除 cin 和 cout 的绑定 → 再提速

// ⚠️ 代价：关了之后不能混用 scanf/printf，否则输出顺序乱
```

### 流状态判断

```cpp
// 读文件/输入失败时检查流状态
std::ifstream f("file.txt");
if (!f.is_open()) { /* 打开失败 */ }
// 或：
if (!f) { /* 流处于失败状态 */ }
```

**流状态位**：good（正常）、eof（到结尾）、fail（逻辑错误，如格式不匹配）、bad（严重错误）。

`sync_with_stdio(false)` + `cin.tie(nullptr)`（为什么要这样写：见上文"cin/cout 慢的原因与优化"）。

## 10. static 的几种用法

C++ 常用小知识点合集：static 用法、const 深度、四种类型转换、空类大小与内存对齐。

### ① 静态局部变量（函数内）

```cpp
void f() {
    static int count = 0;   // 只初始化一次
    count++;                // 函数调用之间保持值
    std::cout << count;
}

f(); f(); f();   // 输出 1 2 3（普通局部变量每次都是 1）
```

**特点**：只初始化一次，生命周期是整个程序，作用域还是函数内。

### ② 静态成员变量（类内）

```cpp
class A {
public:
    static int count;   // 类内声明
};
int A::count = 0;       // ⚠️ 类外必须定义（否则链接错误）

// 所有对象共享同一份
A a1, a2;
a1.count = 1;
std::cout << a2.count;  // 1（共享）
// 也可以不通过对象访问：A::count
```

### ③ 静态成员函数

```cpp
class A {
    static void f();      // 静态成员函数
};

A::f();                   // 不依赖对象，直接类名调用
```

**限制**：不能访问非静态成员（因为没有 this 指针）。

### ④ 静态全局变量/函数（内部链接）

```cpp
static int g = 1;        // 只在本文件可见（其他文件访问不到）
static void helper() { } // 同样只在本文件可见
```

**用途**：限制作用域到本文件，避免多文件符号冲突。

### ⑤ 匿名 namespace（内部链接的现代写法）

```cpp
namespace {                                            // 没有名字
    int expand(const char*, int, int) { return 1; }    // 只在本 .cpp 可见
    struct Helper { };                                 // 类、模板、常量也能装
}
```

和 `static` 一样是**内部链接**，但更通用：`static` 只能修饰变量/函数，匿名 namespace 还能装**类、模板、常量**（C++ 推荐的新写法）。

**为什么需要它**：`.cpp` 里定义的普通自由函数默认是**外部链接**——两个文件写同名函数会在链接期撞车：

```
multiple definition of `expand(char const*, int, int)'    ❌ 链接失败
```

| 需求 | 做法 |
|------|------|
| 只在本文件用（函数/变量） | `static` 或匿名 namespace |
| 只在本文件用（类/模板/常量） | 匿名 namespace ✅ |
| 头文件里定义、多文件共享 | `inline`（类内定义的成员函数天然是 inline） |
| 跨文件共享 | 头文件声明 + 一个 `.cpp` 里定义 ✅（或放进命名空间 ✅） |

## 11. const 深度

### const 指针的三种情况

```cpp
const int* p1;          // 指向常量的指针：不能改 *p1，能改 p1 指向
int* const p2;          // 常量指针：能改 *p2，不能改 p2 指向
const int* const p3;    // 两者都不能改

// 记忆：const 在 * 左边 → 不能改值；在 * 右边 → 不能改指向
```

### 顶层 const vs 底层 const

```cpp
const int a = 5;        // 顶层 const（对象本身是常量）
const int* p = &a;      // 底层 const（指向的对象是常量）
```

### const 成员函数

```cpp
class A {
    int x_;
public:
    int get() const { return x_; }   // const 成员函数：承诺不修改成员
};

const A a;
a.get();     // const 对象只能调 const 成员函数
```

**规则**：

- const 成员函数内不能修改成员变量（除非 mutable）
- **const 对象只能调用 const 成员函数**
- 非 const 对象两者都能调

**为什么 const 对象只能调 const 成员函数**：const 对象承诺"内容不变"，如果允许调非 const 成员函数，这个承诺就被打破。编译器层面：const 对象的 this 是 `const T*`，而 const 成员函数的 this 也是 `const T*`，类型对得上；非 const 成员函数的 this 是 `T*`，`const T*` 传不进 `T*`，所以编译报错。

### const 重载（利用 const 区分重载）

```cpp
class A {
public:
    int& operator[](int i) { return data_[i]; }              // 非 const 版
    const int& operator[](int i) const { return data_[i]; }  // const 版
};
```

### mutable（const 函数里也能改的成员）

```cpp
class A {
    mutable int cache_;   // mutable：const 成员函数也能改它
public:
    int get() const {
        cache_++;         // 即使是 const 函数也能改 mutable 成员
        return 0;
    }
};
```

**用途**：缓存、互斥锁等"逻辑上不影响对象状态"的成员。

## 12. 四种类型转换

| 转换 | 时机 | 用途 | 安全性 |
|------|------|------|--------|
| `static_cast` | 编译期 | 常规转换（int→double、基类→派生类） | 不检查 |
| `dynamic_cast` | 运行期 | 多态向下转型 | 安全（失败返回 nullptr/抛异常） |
| `const_cast` | 编译期 | 去掉 const | 危险 |
| `reinterpret_cast` | 编译期 | 位级重新解释（指针→整数等） | 最危险 |

```cpp
// static_cast：常规类型转换
double d = static_cast<double>(5);       // int → double

// dynamic_cast：多态向下转型（基类指针 → 派生类指针）
Base* p = new Derived();
Derived* d2 = dynamic_cast<Derived*>(p);   // 失败返回 nullptr

// const_cast：去掉 const（尽量别用）
const int a = 5;
int* p = const_cast<int*>(&a);   // ⚠️ 危险：改 const 对象是 UB

// reinterpret_cast：位级重新解释（最危险）
int* p = reinterpret_cast<int*>(0x1234);   // 地址转指针
```

**规则**：优先 `static_cast`；多态向下转型用 `dynamic_cast`；`const_cast` 和 `reinterpret_cast` 能不用就不用。

## 13. 空类大小与内存对齐

### 空类 sizeof = 1

```cpp
class Empty {};
sizeof(Empty);   // → 1（不是 0！）

// 为什么是 1：保证两个对象有不同地址
Empty a, b;
&a != &b;        // 必须成立，所以至少占 1 字节
```

### 有虚函数 = 8（64 位）

```cpp
class Base { virtual void f() {} };
sizeof(Base);    // → 8（一个 vptr 指针，64 位指针是 8 字节）
```

### 内存对齐

```cpp
struct S {
    char c;     // 1 字节
    int i;      // 4 字节
};
sizeof(S);      // → 8（不是 5！）

// 内存布局（对齐到 4 字节边界）：
// | c | 空 | 空 | 空 |   i   |
// 实际占 8 字节，3 字节被"填充"
```

**规则**：成员按自己的大小对齐（int 对齐 4，double 对齐 8），结构体大小 = 最大成员对齐的倍数。

```cpp
struct A { char c; char d; int i; };   // 8（c、d 塞一起，i 对齐）
struct B { char c; int i; char d; };   // 12（i 要对齐，d 单独一字节+填充）
// 成员排列顺序影响大小！小的放前面更紧凑
```

**可以改对齐**（几乎不用）：

```cpp
#pragma pack(1)     // 1 字节对齐（取消填充）
struct S { char c; int i; };
sizeof(S);           // → 5（不打包是 8）
```

### 多继承：几个 vptr？

**每个"多态基类"贡献一个 vptr**（实测）：

```cpp
struct B1 { virtual void f(); };
struct B2 { virtual void g(); };
struct D : B1, B2 {};
sizeof(D);           // → 16：两个多态基类 = 两个 vptr
// 只有一个多态基类时 vtable 会合并 → sizeof = 8
```

### 空基类优化（EBO）

空基类不占空间（实测两个空基类都被优化掉）：

```cpp
struct EmptyA {};
struct EmptyB {};
struct EBO : EmptyA, EmptyB { int x; };
sizeof(EBO);         // → 4（只有 int 的大小）
```

**汇总一条"推导公式"**：类的大小 = 数据成员大小 + 对齐填充 + 每个多态基类一个 vptr（8 字节）− 空基类优化；虚继承再多一个虚基类指针（实测 `struct VB{int a;}; struct D : virtual VB {int b;}` → 16 = 4 + 4 + 8）。不用背题，按这条推每条都出来。

## 14. extern "C"

**问题**：C++ 函数有**名字修饰**（name mangling），编译后函数名会变（如 `f(int)` → `_Z1fi`），而 C 语言没有。所以 C++ 调 C 库时，要告诉编译器"按 C 的方式链接"：

```cpp
// C 头文件里的函数（C 库）
// extern "C" { void c_func(); }

// C++ 里调用：
extern "C" {
    #include "c_library.h"    // 告诉编译器：这些是 C 函数，别做名字修饰
}
```

**为什么需要**：C++ 支持重载（同名函数不同参数），所以编译器用"名字修饰"区分；C 没有重载，函数名不变。链接时名字对不上就报 `undefined reference`。

**常见场景**：调用 C 库（如 SQLite、OpenSSL）、编写供 C 调用的接口。

## 15. 运算符重载

**目的**：让自定义类型支持运算符（`+`、`==`、`<<` 等）：

```cpp
struct Point {
    int x, y;
    Point operator+(const Point& other) const {   // 成员函数版
        return {x + other.x, y + other.y};
    }
    bool operator==(const Point& other) const {
        return x == other.x && y == other.y;
    }
};

Point a{1, 2}, b{3, 4};
auto c = a + b;      // 像内置类型一样用
a == b;              // 自定义比较
```

**流输出（常见）**：

```cpp
std::ostream& operator<<(std::ostream& os, const Point& p) {   // 友元/自由函数版
    os << "(" << p.x << ", " << p.y << ")";
    return os;
}
std::cout << p;      // 打印 (1, 2)
```

**注意事项**：

- 不能重载的：`::`、`.`、`.*`、`?:`、`sizeof`、`typeid`
- 不能发明新运算符（只能重载已有的）
- 运算符重载本质是函数调用（`a + b` = `a.operator+(b)`）

## 16. constexpr 进阶（constexpr / consteval / constinit）

C++11 起有 constexpr，C++20 又加了 consteval、constinit。三者对比：

| 关键字 | 含义 | 版本 |
|--------|------|------|
| `constexpr` | **可能**编译期求值（也可能运行期） | C++11 |
| `consteval` | **必须**编译期求值（编译期函数） | C++20 |
| `constinit` | 变量**必须**编译期初始化（运行期可改） | C++20 |

```cpp
// constexpr：编译期或运行期都行
constexpr int f(int x) { return x * x; }
constexpr int a = f(5);      // 编译期求值
int n = 5;
int b = f(n);                // 运行期调用也合法

// consteval：只能在编译期调用
consteval int g(int x) { return x * x; }
int c = g(5);                // 编译期
// int d = g(n);             // ❌ 编译错误！n 不是编译期常量

// constinit：变量必须编译期初始化
constinit int e = f(5);      // 编译期初始化
// constinit int e2 = n;     // ❌ 编译错误
e = 10;                      // 但运行期可以改值
```

**constexpr 虚函数（C++20）**：虚函数也可以 constexpr：

```cpp
struct Base {
    virtual int f() const = 0;
};
struct D : Base {
    constexpr int f() const override { return 42; }   // C++20
};
constexpr D d;
constexpr int x = d.f();     // 编译期多态
```

**constexpr 容器（C++20）**：vector/string 能在编译期用（编译期构造、修改、释放）：

```cpp
constexpr std::vector<int> v{1, 2, 3};   // C++20 编译期容器
```

**用途**：把计算挪到编译期（零运行开销）、编译期查错（static_assert 配合）。重点在"三者区别"。

## 17. POD / 平凡类型 / 标准布局

三个概念层层递进（涉及"能不能 memcpy"）。

### 平凡类型（Trivial）

**定义**：可以"平凡地"创建/拷贝/销毁——即编译器可以只做内存拷贝，不需要调构造/析构：

```cpp
// 平凡类型：默认构造、拷贝、析构都是编译器默认生成的（没自定义）
struct Trivial {
    int a;
    double b;
    // 没有自定义构造/析构/虚函数
};
```

**判据**：`std::is_trivial<T>::value`。

### 标准布局类型（Standard Layout）

**定义**：内存布局有明确保证（成员顺序、偏移可预测）：

```cpp
struct StandardLayout {
    int a;
    int b;
    // 没有虚函数、所有成员同访问权限、没有基类的非静态成员...
};
```

**判据**：`std::is_standard_layout<T>::value`。

### POD（Plain Old Data）

**定义**：**平凡 + 标准布局** = POD（就是"和 C 结构体一样"的类型）：

```cpp
struct Pod {
    int a;
    double b;
};

std::is_pod_v<Pod>;   // true（C++20 起 is_pod 弃用，拆成 is_trivial + is_standard_layout）
```

### 什么时候能 memcpy / 安全转换

| 操作 | 条件 |
|------|------|
| `memcpy` 拷贝 | 类型是**平凡可拷贝**（trivially copyable）就行 |
| `reinterpret_cast` 往返安全 | **标准布局**类型 |
| 二进制序列化 | 最好是 POD / 平凡类型 |
| 与 C 结构体互操作 | 必须标准布局 |

```cpp
Pod p1{1, 2.0}, p2;
std::memcpy(&p2, &p1, sizeof(Pod));   // POD 可以 memcpy

// ❌ 含虚函数/自定义析构的类不能 memcpy（有 vptr、资源要析构）
```

**一句话**：**POD = 平凡 + 标准布局 = 和 C 结构体等价**，可以安全 memcpy、二进制序列化。含虚函数或自定义构造/析构的类**不是** POD。

## 18. 要点回顾

1. **static 的用法**：静态局部变量、静态成员变量、静态成员函数、内部链接（现代替身：**匿名 namespace**）
2. **const 指针三种**：`const int*`（改不了值）、`int* const`（改不了指向）、`const int* const`
3. **const 对象只能调 const 成员函数**
4. **四种 cast**：static 常规、dynamic 多态向下、const 去 const、reinterpret 位级
5. **空类大小 = 1**（保证不同地址）；有虚函数 +8（vptr）
6. **内存对齐**：成员排列顺序影响结构体大小
7. **constexpr/consteval/constinit 区别**：可能/必须编译期、变量编译期初始化
8. **POD = 平凡 + 标准布局**：和 C 结构体等价，可安全 memcpy
