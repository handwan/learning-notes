# 系统与网络编程

Linux 系统编程核心：文件 IO、进程与线程、信号、进程间通信（IPC）。

## 1. 文件 IO

### 系统调用 vs 库函数

```cpp
// 系统调用（Linux 内核提供）：
int fd = open("file.txt", O_RDONLY);
read(fd, buf, size);
write(fd, buf, size);
close(fd);

// 库函数（C 标准库，带缓冲）：
FILE* fp = fopen("file.txt", "r");
fread(buf, 1, size, fp);
```

**关键区别**：库函数有**用户态缓冲**（减少系统调用次数），系统调用每次都陷入内核。

### 阻塞 / 非阻塞

```cpp
// 阻塞：read 没数据就等着
// 非阻塞：read 没数据立即返回 -1（errno = EAGAIN）
int fd = open("file.txt", O_RDONLY | O_NONBLOCK);   // 非阻塞打开
```

**用途**：非阻塞 IO 是 IO 多路复用/异步 IO 的基础。

### pread / pwrite（带偏移，不改文件位置）

```cpp
pread(fd, buf, size, offset);    // 从 offset 读，不影响 fd 的当前偏移
// 多线程读同一文件时安全（read 会改共享的文件偏移）
```

### mmap（内存映射）

```cpp
void* addr = mmap(NULL, length, PROT_READ, MAP_PRIVATE, fd, offset);
// 把文件映射到内存，像访问内存一样读写文件（省去 read/write 拷贝）
```

**用途**：大文件读写、共享内存、零拷贝。

## 2. 进程 vs 线程

| | 进程 | 线程 |
|--|------|------|
| 资源 | 独立地址空间 | 共享进程地址空间 |
| 开销 | 大（创建/切换） | 小 |
| 通信 | IPC（管道/共享内存等） | 直接读写共享内存 |
| 崩溃影响 | 单进程崩（隔离） | 一线程崩可能全崩 |
| 隔离性 | 强 | 弱 |

```cpp
// 创建进程
pid_t pid = fork();   // 父进程返回子进程 pid，子进程返回 0
if (pid == 0) { /* 子进程 */ }
else { /* 父进程 */ }

// 创建线程
std::thread t(func);
```

## 3. 信号（Signal）

**信号** = 内核发给进程的"异步通知"：

```cpp
#include <csignal>

// 注册信号处理函数
signal(SIGINT, [](int){ /* Ctrl+C 处理 */ });

// 常用信号：
// SIGINT（Ctrl+C）、SIGKILL（强杀，不可捕获）、SIGTERM（优雅终止）、SIGSEGV（段错误）
```

**注意**：信号处理函数里只能调**异步信号安全**的函数（不能 malloc、printf），否则可能死锁。

## 4. 进程间通信（IPC）

| 方式 | 特点 |
|------|------|
| **管道（pipe）** | 单向、父子进程间、字节流（双向要两根） |
| **命名管道（FIFO）** | 无亲缘关系的进程也能用 |
| **共享内存** | 最快（直接读写同一块内存），但要自己同步 |
| **消息队列** | 带格式的消息，内核维护 |
| **信号量** | 同步用（不是传数据） |
| **Socket** | 可跨主机（网络） |

```cpp
// 管道示例：
int fds[2];
pipe(fds);          // fds[0] 读端，fds[1] 写端
write(fds[1], "hello", 5);
read(fds[0], buf, 5);

// 共享内存（最快）：
int shmid = shmget(key, size, IPC_CREAT | 0666);
void* addr = shmat(shmid, NULL, 0);
// 直接读写 addr，多进程共享
```

**选型**：传大量数据用共享内存（最快）；简单通信用管道；跨主机用 socket。

## 5. TCP vs UDP

TCP/UDP、socket、IO 多路复用、零拷贝。后端/服务端 C++ 岗必问。

| | TCP | UDP |
|--|-----|-----|
| 连接 | 面向连接（三次握手） | 无连接 |
| 可靠 | 可靠（重传、有序） | 不可靠（可能丢、乱序） |
| 速度 | 慢（确认、重传） | 快 |
| 场景 | 文件、网页、大多数应用 | 视频、游戏、DNS |

## 6. socket 编程流程

**TCP 服务端**：

```cpp
// 1. 创建 socket
int listenfd = socket(AF_INET, SOCK_STREAM, 0);

// 2. 绑定地址端口
sockaddr_in addr{};
addr.sin_family = AF_INET;
addr.sin_port = htons(8080);           // 端口要用网络字节序
addr.sin_addr.s_addr = INADDR_ANY;
bind(listenfd, (sockaddr*)&addr, sizeof(addr));

// 3. 监听
listen(listenfd, 128);                 // 128 = 全连接队列大小

// 4. 接受连接
int connfd = accept(listenfd, nullptr, nullptr);

// 5. 收发数据
read(connfd, buf, size);
write(connfd, buf, size);

// 6. 关闭
close(connfd);
close(listenfd);
```

**TCP 客户端**：`socket` → `connect` → 收发 → `close`。

**UDP**：`socket` → `sendto`/`recvfrom`（无连接，不用 listen/accept）。

### 字节序转换（别忘了）

**网络字节序 = 大端**，主机可能是小端 → 必须转换：

```cpp
htons(port);    // host to network short（端口）
htonl(addr);    // host to network long（地址）
ntohs(port);    // network to host short
ntohl(addr);    // network to host long
```

## 7. 粘包 / 拆包（TCP 经典问题）

**问题**：TCP 是**字节流**，没有消息边界。发送方的多次 `write` 可能被接收方一次 `read` 读到（粘包），或一次 `write` 被拆成多次 `read`（拆包）。

```
发送：[消息A][消息B]
接收：可能是 [消息A消息B]（粘包）、[消][息A消息B]（拆包）
```

**解决**：应用层定协议划分边界：

1. **固定长度**：每条消息定长
2. **分隔符**：如 `\n` 或 `\0` 结尾
3. **长度前缀**：先发 4 字节长度，再发内容

```cpp
// 长度前缀法：
// 发送：[4字节长度][数据]
// 接收：先读 4 字节得长度 n，再读 n 字节
uint32_t len;
read(fd, &len, 4);
len = ntohl(len);
read(fd, buf, len);
```

## 8. TIME_WAIT / CLOSE_WAIT

**TCP 四次挥手**：主动关闭方最后进入 `TIME_WAIT`，等待 **2MSL**（约 1-4 分钟）。

**TIME_WAIT 多的原因**（主动关闭方）：

- 服务端频繁主动关闭连接（应让客户端先关）
- 短连接太多

**TIME_WAIT 的作用**：保证最后的 ACK 能到达（丢了对方会重发 FIN）、让旧连接的迟到包消散。

**CLOSE_WAIT 多的原因**（被动关闭方）：

- **代码没调 `close()`**！收到对方 FIN，但本端没关闭 → 一直 CLOSE_WAIT（是 bug）

**处理 TIME_WAIT**：
```cpp
// 端口复用（重启服务不用等 TIME_WAIT 结束）
int opt = 1;
setsockopt(fd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));
```

**记忆**：TIME_WAIT 是正常状态（主动关闭方），CLOSE_WAIT 多通常是代码 bug（漏 close）。

## 9. IO 多路复用

**问题**：一个线程怎么同时处理多个连接？

| 机制 | 说明 | 复杂度 |
|------|------|--------|
| **select** | 遍历 fd 集合（有 1024 上限） | O(n) |
| **poll** | 改进 select（无上限，仍是数组） | O(n) |
| **epoll** | 内核事件表 + 回调，只返回就绪的 fd | O(1)（就绪数） |

```cpp
// epoll 三步：
int epfd = epoll_create1(0);
epoll_ctl(epfd, EPOLL_CTL_ADD, fd, &event);   // 注册 fd
epoll_wait(epfd, events, max, timeout);       // 等就绪的 fd

// 边缘触发（ET）：只在状态变化时通知一次（要一次读完）
// 水平触发（LT）：只要还有数据就持续通知（默认，简单）
```

**epoll 为什么快**：

1. 不用像 select 那样每次遍历所有 fd（内核事件表，只返回就绪的）
2. fd 多时性能不下降（select/poll 是 O(n)）

**Reactor 模型**（事件驱动）：

```
IO 就绪事件 → epoll_wait（拿到就绪的 fd）→ 分发 → 事件处理器（处理读写/连接）
```

**用途**：几乎所有高并发服务器（Nginx、Redis、muduo 都是 epoll + Reactor）。

## 10. 零拷贝（Zero-Copy）

**问题**：传统文件发送有多次拷贝（内核/用户态之间）：

```
read(fd, buf, n)：磁盘 → 内核缓冲区 → 用户缓冲区
write(sock, buf, n)：用户缓冲区 → socket 缓冲区 → 网卡
// 4 次拷贝 + 4 次上下文切换
```

**零拷贝**：让数据在内核里直接传递，不经过用户态：

```cpp
sendfile(out_fd, in_fd, offset, count);   // 内核直接传，不经过用户缓冲
splice(fd_in, off_in, fd_out, off_out, len, flags);   // 类似，支持管道
```

**优势**：减少拷贝和上下文切换，大文件传输/静态服务器（Nginx）常用。

## 11. 同步/异步 × 阻塞/非阻塞

| | 阻塞 | 非阻塞 |
|--|------|--------|
| **同步** | read 一直等 | read 立即返回（要轮询） |
| **异步** | — | read 立即返回，数据好了内核通知你 |

- **同步阻塞**：最简单的传统 IO
- **同步非阻塞 + IO多路复用（epoll）**：最常用（Reactor）
- **异步（AIO）**：内核完成后通知（Proactor），Linux 上用得不广

**记忆**：阻塞/非阻塞看"调用是否立即返回"；同步/异步看"数据拷贝由谁完成"。

## 12. 要点回顾

1. **系统调用 vs 库函数**：库函数有用户态缓冲
2. **阻塞/非阻塞**：非阻塞是 IO 多路复用的基础
3. **进程 vs 线程**：地址空间、开销、通信、隔离
4. **信号**：异步通知，处理函数只能调异步安全函数
5. **IPC**：共享内存最快、管道简单、socket 跨主机
6. **mmap**：文件映射、共享内存、零拷贝
7. **TCP vs UDP**：可靠/连接 vs 快/无连接
8. **socket 流程**：socket→bind→listen→accept→read/write
9. **粘包**：TCP 无消息边界，用长度前缀/分隔符解决
10. **TIME_WAIT**（正常，主动关闭方）/ **CLOSE_WAIT**（多=漏 close）
11. **epoll**：只返回就绪 fd，O(1)，高并发核心；LT vs ET
12. **Reactor**：事件驱动模型（epoll_wait + 事件处理）
13. **零拷贝**：sendfile/splice，内核内传递，省拷贝
14. **同步/异步、阻塞/非阻塞**：四象限，epoll 是"同步非阻塞多路复用"
