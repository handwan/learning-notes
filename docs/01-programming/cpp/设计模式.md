# 设计模式

C++ 常用的设计模式 + 惯用法。重点：单例、工厂、策略、观察者、PIMPL。

## 1. 单例（Singleton）

**目的**：全局只有一个实例。

### 线程安全单例（Meyers Singleton）

```cpp
class Singleton {
public:
    static Singleton& instance() {
        static Singleton inst;   // C++11 起：局部 static 初始化线程安全
        return inst;
    }
    Singleton(const Singleton&) = delete;            // 禁拷贝
    Singleton& operator=(const Singleton&) = delete;

private:
    Singleton() = default;   // 私有构造
};
```

**为什么推荐**：C++11 保证局部 static 初始化**线程安全**（编译器加锁），且**惰性初始化**（第一次用时才构造）。

### 对比各种单例写法

| 写法 | 线程安全 | 惰性 | 说明 |
|------|---------|------|------|
| 饿汉（静态成员，程序启动就构造） | ✅ | ❌ | 简单，但启动就构造 |
| 懒汉（用才构造 + 双检锁） | 要小心 | ✅ | 双检锁易写错 |
| **Meyers（局部 static）** | ✅ | ✅ | **推荐**，最简洁安全 |

**双检锁（DCLP）的坑**：

```cpp
// 经典错误写法（有问题的双检锁）：
static Singleton* instance() {
    if (inst == nullptr) {              // 第一次检查
        lock_guard lock(mtx);
        if (inst == nullptr) {          // 第二次检查
            inst = new Singleton();     // ⚠️ 可能先分配地址再构造，别的线程看到半成品
        }
    }
    return inst;
}
// 解决：inst 用 atomic + acquire/release，或直接用 Meyers 单例
```

## 2. 工厂模式（Factory）

**目的**：把"创建对象"的逻辑和"使用对象"解耦。

```cpp
// 简单工厂：根据参数创建不同子类
class Shape {
public:
    virtual void draw() = 0;
    virtual ~Shape() = default;
};

class Circle : public Shape { void draw() override { /* 画圆 */ } };
class Rect : public Shape { void draw() override { /* 画矩形 */ } };

std::unique_ptr<Shape> create_shape(const std::string& type) {
    if (type == "circle") return std::make_unique<Circle>();
    if (type == "rect")   return std::make_unique<Rect>();
    return nullptr;
}
```

**工厂方法（更灵活）**：把创建推迟到子类。

```cpp
class Factory {
public:
    virtual std::unique_ptr<Shape> create() = 0;
};
class CircleFactory : public Factory {
    std::unique_ptr<Shape> create() override { return std::make_unique<Circle>(); }
};
```

**用途**：对象创建复杂、需要根据配置选类型、插件系统。

## 3. 策略模式（Strategy）

**目的**：把"算法/行为"封装成可替换的组件。

```cpp
// 策略接口
class SortStrategy {
public:
    virtual void sort(std::vector<int>&) = 0;
    virtual ~SortStrategy() = default;
};

class QuickSort : public SortStrategy { /* ... */ };
class MergeSort : public SortStrategy { /* ... */ };

// 上下文：持有一个策略，运行时切换
class Sorter {
    std::unique_ptr<SortStrategy> strategy_;
public:
    explicit Sorter(std::unique_ptr<SortStrategy> s) : strategy_(std::move(s)) {}
    void execute(std::vector<int>& v) { strategy_->sort(v); }
    void set_strategy(std::unique_ptr<SortStrategy> s) { strategy_ = std::move(s); }
};
```

**C++ 的"策略"更常用 `std::function` / 模板**（不一定要继承）：

```cpp
// 用 std::function 做策略（更轻量）
using SortFn = std::function<void(std::vector<int>&)>;
class Sorter {
    SortFn sort_;
public:
    explicit Sorter(SortFn f) : sort_(std::move(f)) {}
};
```

## 4. 观察者模式（Observer）

**目的**：对象状态变化时，自动通知所有"观察者"。

```cpp
class Observer {
public:
    virtual void update(int value) = 0;
    virtual ~Observer() = default;
};

class Subject {
    std::vector<Observer*> observers_;
    int state_ = 0;
public:
    void attach(Observer* o) { observers_.push_back(o); }
    void notify() {
        for (auto* o : observers_) o->update(state_);
    }
    void set_state(int v) { state_ = v; notify(); }
};
```

**用途**：事件系统、GUI（按钮点击通知多个监听者）、发布-订阅。
**注意**：观察者生命周期——被观察者持有裸指针，观察者先销毁要 `detach`（或用 `weak_ptr`）。

## 5. 适配器 / 装饰器

**适配器（Adapter）**：把不兼容的接口转成需要的接口。

```cpp
// 把旧接口 wrap 成新接口
class NewInterface { public: virtual void request() = 0; };
class OldClass { public: void old_request() { /* 旧接口 */ } };
class Adapter : public NewInterface {
    OldClass old_;
public:
    void request() override { old_.old_request(); }   // 转发
};
```

**装饰器（Decorator）**：动态给对象加功能（不改变原类）。

```cpp
class Component { public: virtual void run() = 0; };
class Concrete : public Component { void run() override {} };

class Decorator : public Component {
    std::unique_ptr<Component> inner_;
public:
    explicit Decorator(std::unique_ptr<Component> c) : inner_(std::move(c)) {}
    void run() override { inner_->run(); /* 加额外功能 */ }
};
```

## 6. RAII 模式

**目的**：把资源生命周期绑定到对象生命周期（见「内存管理」篇）。

```cpp
// 锁的 RAII（lock_guard）、内存（unique_ptr）、文件（ifstream）都是 RAII
std::lock_guard<std::mutex> lock(m);   // 构造加锁，析构解锁
```

## 7. PIMPL（编译防火墙）

**PIMPL**（Pointer to IMPLementation）：把私有成员藏到"实现类"，头文件只留一个指针。

```cpp
// widget.h（头文件：只暴露接口，不含实现细节）
class Widget {
public:
    Widget();
    ~Widget();                // ⚠️ 必须声明析构（在 .cpp 里定义）
    void do_something();
private:
    struct Impl;              // 前向声明（不暴露内容）
    std::unique_ptr<Impl> pimpl_;   // 只有一个指针
};

// widget.cpp（实现文件：放所有细节）
struct Widget::Impl {
    std::vector<int> data;    // 私有实现
    int cache;
    // 改这里不影响头文件
};
Widget::Widget() : pimpl_(std::make_unique<Impl>()) {}
Widget::~Widget() = default;  // 必须在 .cpp（Impl 完整类型在这里可见）
```

**好处**：

1. **减少编译依赖**：改实现不用重编译所有包含头文件的代码
2. **ABI 稳定**：类大小固定（只是一个指针），加私有成员不破坏 ABI
3. **隐藏实现**：头文件看不到私有成员

**代价**：一次指针间接访问、多了堆分配。

## 8. 状态模式 / 责任链

- **状态模式**：对象行为随内部状态改变（用状态类替代大量 if-else）
- **责任链**：请求沿处理链传递（如日志级别、审批流）

## 9. 设计原则回顾（SOLID）

见「面向对象」篇。核心：**组合优于继承、面向接口编程**。

## 10. 要点回顾

1. **单例**：Meyers 单例（局部 static）最推荐；双检锁的坑
2. **工厂**：解耦创建和使用
3. **策略**：可替换的算法，C++ 常配 `std::function`
4. **观察者**：事件通知，注意生命周期
5. **适配器/装饰器**：接口转换 / 动态加功能
6. **RAII**：C++ 最核心惯用法
7. **PIMPL**：编译防火墙（减依赖 + ABI 稳定）
8. **CRTP**：静态多态（见「模板与泛型」篇）
