# 设计模式

C++ 常用的设计模式 + 惯用法，按创建、行为、结构和 C++ 惯用法组织。

## 1. 单例（Singleton）

**目的**：全局只有一个实例。

### 线程安全单例（Meyers Singleton）

```cpp
class Singleton {
public:
    static Singleton& instance() {
        static Singleton inst;   // C++11 起：局部 static 初始化线程安全
        return inst;
    }
    Singleton(const Singleton&) = delete;            // 禁拷贝
    Singleton& operator=(const Singleton&) = delete;

private:
    Singleton() = default;   // 私有构造
};
```

**为什么推荐**：C++11 保证局部 static 初始化**线程安全**（编译器加锁），且**惰性初始化**（第一次用时才构造）。

### 对比各种单例写法

| 写法 | 线程安全 | 惰性 | 说明 |
|------|---------|------|------|
| 饿汉（静态成员，程序启动就构造） | 初始化完成后 ✅ | ❌ | 简单；注意跨 TU 初始化顺序 |
| 懒汉（用才构造 + 双检锁） | 要小心 | ✅ | 双检锁易写错 |
| **Meyers（局部 static）** | ✅ | ✅ | **推荐**，最简洁安全 |

**双检锁（DCLP）的坑**：

```cpp
// 经典错误写法（有问题的双检锁）：
static Singleton* instance() {
    if (inst == nullptr) {              // 第一次检查：无同步读 inst
        lock_guard lock(mtx);
        if (inst == nullptr) {          // 第二次检查
            inst = new Singleton();     // 普通指针的发布没有 release/acquire
        }
    }
    return inst;                        // 无同步读 inst
}
// 真正的坑是 inst 的读写构成数据竞争，且对象发布没有同步；
// 不是简单的“先分配地址再构造”。
// 解决：inst 用 atomic<Singleton*> + acquire/release，或 std::call_once，或直接用 Meyers 单例。
```

## 2. 工厂模式（Factory）

**目的**：把"创建对象"的逻辑和"使用对象"解耦。

```cpp
#include <memory>
#include <string>

class Shape {
public:
    virtual void draw() = 0;
    virtual ~Shape() = default;
};

class Circle : public Shape {
public:
    void draw() override { /* 画圆 */ }
};
class Rect : public Shape {
public:
    void draw() override { /* 画矩形 */ }
};

std::unique_ptr<Shape> create_shape(const std::string& type) {
    if (type == "circle") return std::make_unique<Circle>();
    if (type == "rect")   return std::make_unique<Rect>();
    return nullptr;
}
```

**工厂方法（更灵活）**：把创建推迟到子类。

```cpp
class Factory {
public:
    virtual std::unique_ptr<Shape> create() = 0;
    virtual ~Factory() = default;
};
class CircleFactory : public Factory {
public:
    std::unique_ptr<Shape> create() override { return std::make_unique<Circle>(); }
};
```

**用途**：对象创建复杂、需要根据配置选类型、插件系统。

## 3. Builder（建造者）

**目的**：分步构造复杂对象，把构造过程和最终表示分开。

```cpp
#include <string>
#include <utility>

struct HttpConfig {
    std::string host;
    int port = 80;
    int timeout_ms = 3000;
};

class HttpConfigBuilder {
public:
    HttpConfigBuilder& host(std::string h) {
        cfg_.host = std::move(h);
        return *this;
    }
    HttpConfigBuilder& port(int p) {
        cfg_.port = p;
        return *this;
    }
    HttpConfigBuilder& timeout(int ms) {
        cfg_.timeout_ms = ms;
        return *this;
    }
    HttpConfig build() const { return cfg_; }

private:
    HttpConfig cfg_;
};

auto cfg = HttpConfigBuilder{}.host("localhost").port(8080).timeout(1000).build();
```

**适用**：参数多、可选参数多、需要校验或分步构造。
**不适用**：简单聚合直接用 `{}` 初始化即可，不必多一层。

## 4. 策略模式（Strategy）

**目的**：把"算法/行为"封装成可替换的组件。

```cpp
#include <memory>
#include <utility>
#include <vector>

class SortStrategy {
public:
    virtual void sort(std::vector<int>&) = 0;
    virtual ~SortStrategy() = default;
};

class QuickSort : public SortStrategy { /* ... */ };
class MergeSort : public SortStrategy { /* ... */ };

class Sorter {
    std::unique_ptr<SortStrategy> strategy_;
public:
    explicit Sorter(std::unique_ptr<SortStrategy> s) : strategy_(std::move(s)) {}
    void execute(std::vector<int>& v) {
        if (strategy_) strategy_->sort(v);
    }
    void set_strategy(std::unique_ptr<SortStrategy> s) { strategy_ = std::move(s); }
};
```

**C++ 的"策略"更常用 `std::function` / 模板**（不一定要继承）：

```cpp
#include <functional>
#include <utility>
#include <vector>

using SortFn = std::function<void(std::vector<int>&)>;

class Sorter {
    SortFn sort_;
public:
    explicit Sorter(SortFn f) : sort_(std::move(f)) {}
    void execute(std::vector<int>& v) { if (sort_) sort_(v); }
};
```

## 5. 观察者模式（Observer）

**目的**：对象状态变化时，自动通知所有"观察者"。

```cpp
#include <algorithm>
#include <vector>

class Observer {
public:
    virtual void update(int value) = 0;
    virtual ~Observer() = default;
};

class Subject {
    std::vector<Observer*> observers_;
    int state_ = 0;
public:
    void attach(Observer* o) { observers_.push_back(o); }
    void detach(Observer* o) {
        observers_.erase(
            std::remove(observers_.begin(), observers_.end(), o),
            observers_.end());
    }
    void notify() {
        for (auto* o : observers_) o->update(state_);
    }
    void set_state(int v) { state_ = v; notify(); }
};
```

**用途**：事件系统、GUI（按钮点击通知多个监听者）、发布-订阅。

**注意**：

- 观察者生命周期：被观察者持有裸指针，观察者先销毁要 `detach`（或用 `weak_ptr`）。
- 不要在 `update()` 里直接 `attach` / `detach`：正在遍历的 `vector` 可能失效；可延迟删除或先复制观察者列表。

## 6. 适配器与装饰器

### 适配器（Adapter）

把不兼容的接口转成需要的接口。

```cpp
class NewInterface {
public:
    virtual void request() = 0;
    virtual ~NewInterface() = default;
};

class OldClass {
public:
    void old_request() { /* 旧接口 */ }
};

class Adapter : public NewInterface {
    OldClass old_;
public:
    void request() override { old_.old_request(); }   // 转发
};
```

### 装饰器（Decorator）

动态给对象加功能（不改变原类）。

```cpp
#include <memory>

class Component {
public:
    virtual void run() = 0;
    virtual ~Component() = default;
};

class Concrete : public Component {
public:
    void run() override {}
};

class Decorator : public Component {
    std::unique_ptr<Component> inner_;
public:
    explicit Decorator(std::unique_ptr<Component> c) : inner_(std::move(c)) {}
    void run() override { inner_->run(); /* 加额外功能 */ }
};
```

## 7. Proxy（代理）

**目的**：控制对真实对象的访问，常见于懒加载、权限、远程调用、引用计数。

```cpp
#include <memory>

class Image {
public:
    virtual void draw() = 0;
    virtual ~Image() = default;
};

class RealImage : public Image {
public:
    void draw() override { /* 真正加载并绘制 */ }
};

class LazyImage : public Image {
    std::unique_ptr<Image> real_;
public:
    void draw() override {
        if (!real_) real_ = std::make_unique<RealImage>();
        real_->draw();
    }
};
```

**和 Decorator 的区别**：

- Proxy 通常自己创建/管理真实对象，控制“能不能访问”
- Decorator 接收已有对象，叠加“额外行为”
- Adapter 改变接口，不改变行为语义

## 8. Command（命令）

**目的**：把一次请求封装成对象，便于排队、记录、撤销。

```cpp
class Command {
public:
    virtual void execute() = 0;
    virtual ~Command() = default;
};

class Light {
public:
    void on() {}
    void off() {}
};

class LightOn : public Command {
    Light& light_;
public:
    explicit LightOn(Light& light) : light_(light) {}
    void execute() override { light_.on(); }
};
```

简单场景也可以直接用 `std::function<void()>`，不必为每个操作建类。命令对象如果进队列，要保证它引用的对象活得足够久。

## 9. 模板方法与 NVI

**模板方法**：基类固定流程，子类实现步骤。

```cpp
class Parser {
public:
    void parse() {          // 固定骨架
        open();
        read();
        close();
    }
    virtual ~Parser() = default;

private:
    virtual void open() = 0;
    virtual void read() = 0;
    virtual void close() = 0;
};
```

**NVI（Non-Virtual Interface）**：public 非虚函数做入口，private 虚函数做实现，也就是上面的写法。`private virtual` 合法，派生类仍可 override。

**和 Strategy 的区别**：

- Template Method：继承 + 固定流程，变化点在子类
- Strategy：组合 + 替换整个算法，变化点在对象

## 10. Visitor（访问者）

**目的**：在不修改元素类的前提下增加操作；靠双重分发选择具体类型和操作。

```cpp
class Circle;
class Rect;

class Visitor {
public:
    virtual void visit(Circle&) = 0;
    virtual void visit(Rect&) = 0;
    virtual ~Visitor() = default;
};

class Shape {
public:
    virtual void accept(Visitor&) = 0;
    virtual ~Shape() = default;
};

class Circle : public Shape {
public:
    void accept(Visitor& v) override;
};

class Rect : public Shape {
public:
    void accept(Visitor& v) override;
};

class DrawVisitor : public Visitor {
public:
    void visit(Circle&) override {}
    void visit(Rect&) override {}
};

void Circle::accept(Visitor& v) { v.visit(*this); }
void Rect::accept(Visitor& v) { v.visit(*this); }
```

**取舍**：

- 增加新操作容易：加一个 Visitor
- 增加新元素类型麻烦：所有 Visitor 都要改

C++17 起，封闭类型集合可以改用 `std::variant` + `std::visit`，省掉双重分发类层次。

## 11. State（状态）

**目的**：对象行为随内部状态改变，用状态类替代大量 `if` / `switch`。

```cpp
#include <memory>
#include <utility>

class Context;

class State {
public:
    virtual void handle(Context&) = 0;
    virtual ~State() = default;
};

class Context {
    std::unique_ptr<State> state_;
public:
    explicit Context(std::unique_ptr<State> s) : state_(std::move(s)) {}
    void set_state(std::unique_ptr<State> s) { state_ = std::move(s); }
    void request() { if (state_) state_->handle(*this); }
};

class Idle : public State {
public:
    void handle(Context& c) override;
};

class Running : public State {
public:
    void handle(Context& c) override;
};

void Idle::handle(Context& c) {
    c.set_state(std::make_unique<Running>());
}
void Running::handle(Context& c) {
    c.set_state(std::make_unique<Idle>());
}
```

**和 Strategy 的区别**：State 的切换通常由状态自己推动；Strategy 通常由外部选择或注入。

## 12. RAII 模式

**目的**：把资源生命周期绑定到对象生命周期（见[内存管理](内存管理.md)）。

```cpp
// 锁的 RAII（lock_guard）、内存（unique_ptr）、文件（ifstream）都是 RAII
std::lock_guard<std::mutex> lock(m);   // 构造加锁，析构解锁
```

## 13. PIMPL

PIMPL（Pointer to IMPLementation）：把私有成员藏到"实现类"，头文件只留一个指针。

```cpp
// widget.h（头文件：只暴露接口，不含实现细节）
#include <memory>

class Widget {
public:
    Widget();
    ~Widget();                // ⚠️ 必须声明析构（在 .cpp 里定义）
    Widget(Widget&&) noexcept;
    Widget& operator=(Widget&&) noexcept;
    void do_something();
private:
    struct Impl;              // 前向声明（不暴露内容）
    std::unique_ptr<Impl> pimpl_;   // 只有一个指针
};

// widget.cpp（实现文件：放所有细节）
#include <vector>

struct Widget::Impl {
    std::vector<int> data;    // 私有实现
    int cache = 0;
    // 改这里不影响头文件
};
Widget::Widget() : pimpl_(std::make_unique<Impl>()) {}
Widget::~Widget() = default;  // 必须在 .cpp（Impl 完整类型在这里可见）
Widget::Widget(Widget&&) noexcept = default;
Widget& Widget::operator=(Widget&&) noexcept = default;
```

**好处**：

1. **减少编译依赖**：改实现不用重编译所有包含头文件的代码
2. **ABI 稳定**：类大小固定（只是一个指针），加私有成员不破坏 ABI
3. **隐藏实现**：头文件看不到私有成员

**代价**：一次指针间接访问、多了堆分配。

## 14. 设计原则与选型

见[面向对象](面向对象.md)篇。核心：**组合优于继承、面向接口编程**。

| 问题 | 模式 |
|---|---|
| 复杂对象构造、可选参数多 | Builder |
| 创建逻辑和类型选择解耦 | Factory |
| 算法/行为可替换 | Strategy |
| 状态变化通知多个对象 | Observer |
| 接口不兼容 | Adapter |
| 动态叠加功能 | Decorator |
| 控制真实对象访问 | Proxy |
| 操作要排队、记录、撤销 | Command |
| 固定流程、步骤可变 | Template Method / NVI |
| 给封闭类型集合加操作 | Visitor / `std::variant` + `std::visit` |
| 行为随内部状态变化 | State |

**不要为了模式而模式**：

- 简单聚合初始化不需要 Builder
- 只有一个实现、也不会运行时替换，不需要 Strategy 继承体系
- Singleton 容易变成全局状态，优先考虑依赖注入
- 观察者注意生命周期，命令对象注意引用对象的生命周期

C++ 惯用法继续看[模板与泛型](模板与泛型.md)的 CRTP，以及[算法与函数对象](算法与函数对象.md)的类型擦除。

## 15. 要点回顾

1. **单例**：Meyers 单例（局部 static）最推荐；双检锁的坑
2. **工厂**：解耦创建和使用
3. **Builder**：分步构造复杂对象；简单聚合不要用
4. **策略**：可替换的算法，C++ 常配 `std::function`
5. **观察者**：事件通知，注意生命周期、`detach` 和回调中修改列表
6. **适配器/装饰器**：接口转换 / 动态加功能
7. **Proxy**：控制对真实对象的访问；和 Decorator 的意图不同
8. **Command**：把请求封装成对象，支持排队/记录/撤销
9. **Template Method / NVI**：基类固定流程，子类实现步骤
10. **Visitor**：双重分发；也可以用 `std::variant` + `std::visit`
11. **State**：行为随内部状态变化，转换由状态推动
12. **RAII**：C++ 最核心惯用法
13. **PIMPL**：编译防火墙（减依赖 + ABI 稳定；需要移动就显式实现）
14. **多态基类**：有虚函数就要有虚析构，尤其是 `unique_ptr<Base>` 持有派生对象时
