# 容器与迭代器

STL 容器分四大类，核心是记住每个容器的**底层数据结构**和**复杂度**。

> 本文按“常用 + 易错”组织，不是 API 全量；完整接口查 cppreference。

## 1. 分类总览

| 分类 | 容器 | 底层 | 特点 |
|------|------|------|------|
| 序列容器 | vector / deque / list / forward_list / array / string | 线性结构 | 有顺序 |
| 关联容器 | set / multiset / map / multimap | 有序结构（主流用红黑树） | 有序，O(log n) |
| 无序关联容器 | unordered_set / unordered_map 等 | 哈希表 | 无序，平均 O(1) |
| 容器适配器 | stack / queue / priority_queue | 包装其他容器 | 受限接口 |

（`array` = 定长数组，`forward_list` = 单向链表，使用频率低于 vector；`string` 是字符序列，另有专篇。）

`std::array` 是定长连续数组，支持 `fill` / `data` / `size`，不能增删；需要动态数组用 `std::vector`。

## 2. vector

### vector 底层与复杂度

```cpp
// 底层：动态数组（连续内存）
// 随机访问 O(1)，缓存友好
// 尾部插入/删除 均摊 O(1)
// 头部/中间插入/删除 O(n)（要搬移元素）
```

### 扩容机制

当 `size == capacity` 时扩容：

1. 申请更大的新内存（一般是 **1.5 倍（MSVC）或 2 倍（GCC）**，标准不规定）
2. 把旧元素**拷贝/移动**到新内存
3. 释放旧内存

```cpp
std::vector<int> v;
v.push_back(1);   // libstdc++：capacity 从 0 开始，逐步 1→2→4→8→16...
```

**为什么尾部插入均摊 O(1)**：不是每次扩容，偶尔扩容一次，摊到每次插入上，平均还是 O(1)。

### size / capacity / reserve / resize

```cpp
std::vector<int> v;
v.size();       // 实际元素个数
v.capacity();   // 当前分配的容量（>= size）

v.reserve(100);  // 只扩 capacity，不改 size（提前预留，避免反复扩容）
v.resize(10);    // 改 size（多了补 0，少了删元素），必要时也扩 capacity
```

### 常用 API

```cpp
v.push_back(x);       // 尾部插入（拷贝/移动）
v.emplace_back(...);  // 尾部原地构造；省掉临时对象/移动，视参数而定（int 等无差别）
v.pop_back();         // 尾部删除
v.front(); v.back();  // 首/尾元素
v[i]; v.at(i);        // 下标访问；at 会做越界检查
v.insert(pos, x);     // 指定位置插入 O(n)
v.erase(pos);         // 指定位置删除 O(n)
v.insert(v.end(), other.begin(), other.end()); // 范围插入
v.erase(v.begin(), v.begin() + 2);             // 范围删除
v.emplace(v.begin(), ...);                     // 指定位置原地构造
v.data();             // 连续存储首地址（vector<bool> 没有）
v.shrink_to_fit();    // 请求释放多余 capacity
```

C++20 的 `std::erase` / `std::erase_if` 见 [C++20](C++20.md)，不用再手写 erase-remove。

### vector<bool>（特例）

`std::vector<bool>` 是位压缩特化，不是普通 `vector<bool>`：

- `operator[]` 返回代理对象，不是 `bool&`
- 没有可用的 `data()`，不能 `&v[0]`
- 不满足连续迭代器；前面“连续内存/引用”的规则不要直接套

需要真正的连续 `bool` 存储时，用 `std::vector<char>` / `std::vector<std::uint8_t>`（或定长 `std::bitset`）。

### 迭代器失效

```cpp
std::vector<int> v{1, 2, 3};
auto it = v.begin();
v.push_back(4);   // 若触发扩容，it 指向已释放的旧内存，悬空！
// *it;           // 未定义行为
```

**规则**：扩容导致所有迭代器、引用、指针失效；插入/删除导致**插入点/删除点及之后**的迭代器、引用、指针失效。`push_back` 即使不扩容也会让 `end()` 失效；`reserve`/`resize` 若发生重新分配则全部失效。

### 要点回顾

- 扩容机制（1.5/2 倍、搬移、均摊 O(1)）
- `reserve` vs `resize`
- `emplace_back` vs `push_back`（原地构造 vs 先构造临时对象/移动；视参数）
- 迭代器失效
- 为什么中间插入慢（要搬移元素）

## 3. list（双向链表）

### list 底层与复杂度

```cpp
// 底层：双向链表（节点分散，指针连接）
// 已有迭代器时，插入/删除 O(1)（只改指针）；找位置 O(n)
// 不支持随机访问（不能 v[i]，要遍历 O(n)）
// 内存不连续，缓存不友好
```

### list vs vector

| | vector | list |
|--|--------|------|
| 底层 | 动态数组（连续） | 双向链表（分散） |
| 随机访问 | O(1) | ❌ 不支持 |
| 插入/删除 | 尾 O(1)，中间 O(n) | 已有迭代器时任意位置 O(1) |
| 缓存友好 | ✅ 好 | ❌ 差 |
| 迭代器失效 | 扩容全失效 | 删除只失效被删的 |

**什么时候用**：已经持有迭代器、且频繁在中间插入/删除时用 list；如果要先查找位置，`list` 的查找是 O(n)，`vector` 往往反而更快（缓存友好）。其余默认 vector。

**list 特有操作**：

```cpp
lst.splice(pos, other);   // O(1) 把 other 的节点接到 pos 前（同 allocator）
lst.remove(2);            // 删除所有 2
lst.remove_if(pred);
lst.unique();             // 删除相邻重复
lst.merge(other);         // 合并两个有序 list
lst.sort();               // 成员排序（稳定）
lst.reverse();
```

**注意**：`splice` 是 list 相对 vector 的核心优势；`unique` 只去相邻重复，先排序才能全去重。

`forward_list` 是单向链表，只有 `insert_after` / `erase_after`，没有 `size()`；用 `before_begin()` 当前哨。

## 4. deque（双端队列）

### deque 底层与复杂度

```cpp
// 底层：分段连续数组（多段连续内存，用指针串起来）
// 头尾插入/删除 O(1)
// 随机访问 O(1)（比 vector 略慢）
// 中间插入 O(n)
```

**中控器（deque 的底层结构）**：

- 一个指针数组（中控器），每项指向一段固定大小的连续缓冲区
- 元素分布在这些缓冲区里；头尾操作只需在首/尾缓冲区处理
- 缓冲区用完就增加一段；中控器扩容时搬的是指针，不搬元素

**注意**：头尾插入虽然不搬元素，但会让所有迭代器（含 `end()`）失效；引用和指针仍然有效。

**为什么两端插入 O(1)**：只需在头/尾缓冲区追加，缓冲区满了就加一段（中控器扩容），**不搬移已有元素**（不同于 vector 的扩容搬移）。

**为什么随机访问略慢于 vector**：要经过"中控器 → 缓冲区"两次间接寻址，不是直接算地址。

**vs vector**：deque 支持头部插入 O(1)（vector 头部插入 O(n)），但内存不如 vector 连续（缓存略差）。

**用途**：stack 和 queue 的默认底层就是 deque。

## 5. map vs unordered_map

### map（红黑树）

```cpp
// 底层：主流实现用红黑树（标准只要求有序和 O(log n) 操作）
// 查找/插入/删除 O(log n)
// 自动按键排序（有序遍历）
// 内存：树节点，有额外开销
```

**红黑树的平衡规则**：

1. 每个节点是红或黑
2. 根节点是黑
3. 红节点的子节点必须是黑（不能红红相连）
4. 从任一节点到其所有叶子的路径，黑节点数相同
5. 新插入节点是红

**目的**：通过旋转 + 变色，保证树"大致平衡"（最长路径 ≤ 2×最短路径），从而查找 O(log n)。比 AVL 树（严格平衡）**插入删除更少旋转**，综合性能更好，所以主流 STL 实现用红黑树。

**`[]` 的暗坑：只读访问也会插入** ⚠️

```cpp
std::map<std::string, int> m; m["x"] = 1;      // size = 1
int v = m["y"];                                // ⚠️ 顺手插入了 ("y", 0) → size = 2
if (m.find("y") != m.end()) { }               // C++17；只读判断
if (m.contains("y")) { }                      // C++20
```

**要取值就选 `find`**：查到之后还要用值时，`find` 一次查找就能拿到 `it->second`；`contains` 只适合"只判存在"——之后再用 `[]` 取值就是两次查找了。

**只读且不允许不存在 → `at`**：`m.at(k)` 不存在会抛 `std::out_of_range`——和 `[]` 的"静默插入"正好相反：一个安静地改坏数据，一个响亮地报错。

**四种插入的覆盖行为**（key 已存在时）：

| 写法 | 已存在时的行为 |
|------|---------------|
| `m[k] = v` | **覆盖** |
| `m.insert({k, v})` | 不覆盖 |
| `m.emplace(k, v)` | 不覆盖（但 `pair` 已经构造了，白费 ⚠️） |
| `m.try_emplace(k, args...)`（C++17） | 不覆盖，且**不构造**——value 构造成本高时更省 |

**节点转移（C++17）**：`extract` / `merge` 不重新分配节点：

```cpp
auto node = m.extract("k");       // 取出节点
other.insert(std::move(node));    // 插入另一个 map
other.merge(m);                   // 把 m 中不冲突的节点并进来（不覆盖已有 key）
```

`unordered_map` 同样支持；适合把节点在容器间搬来搬去，避免重新构造。

### unordered_map（哈希表）

```cpp
// 底层：哈希表（标准不规定冲突处理策略）
// 查找/插入/删除 平均 O(1)，最坏 O(n)（哈希冲突）
// 无序
// 内存：桶 + 节点，有额外开销
```

**哈希冲突处理**：主流实现用**开链法**（拉链法）；标准只要求平均 O(1)、最坏 O(n)，不规定具体冲突策略：

- 桶数组的每个槽位存一个链表头
- 哈希到同一桶的元素串在该链表上
- 查找时先定位桶，再遍历链表

**负载因子（load factor）与 rehash**：

```cpp
负载因子 = 元素个数 / 桶个数
// 默认阈值：负载因子超过 1.0（libstdc++）触发 rehash

// rehash 过程：
// 1. 分配更多的桶（通常翻倍）
// 2. 所有元素重新计算哈希，重新分配到新桶
// 3. 释放旧桶
// 代价大（O(n)），所以最好预留容量：m.reserve(n)
```

**为什么 unordered_map "不稳定"**：

1. rehash 时**所有迭代器失效**
2. 最坏情况（哈希退化，全冲突）O(n)（可用红黑树防御的 Java HashMap 对比）
3. 遍历顺序不确定（依赖哈希）

**自定义类型作 key**：要"能相等比较"+"能哈希"（且**相等必须同哈希**）——两条路：特化 `std::hash<T>`，或传一个哈希仿函数（如下）。

```cpp
struct Point {
    int x = 0;
    int y = 0;
    bool operator==(const Point&) const = default;   // C++20；或手写
};

struct PointHash {
    size_t operator()(const Point& p) const {
        size_t h1 = std::hash<int>{}(p.x);
        size_t h2 = std::hash<int>{}(p.y);
        return h1 ^ (h2 + 0x9e3779b9 + (h1 << 6) + (h1 >> 2));  // 经典混合
    }
};

std::unordered_map<Point, int, PointHash> mp;   // 第三个模板参数：哈希仿函数
```

⚠️ 组合哈希别用 `h1 ^ h2` 这种对称写法——`(1,2)` 和 `(2,1)` 会撞到同一个桶。

### 与 map 对比

| | map | unordered_map |
|--|-----|---------------|
| 底层 | 红黑树 | 哈希表 |
| 查找 | O(log n) | 平均 O(1) |
| 是否有序 | ✅ 有序 | ❌ 无序 |
| 稳定性 | 稳定（最坏 O(log n)） | 最坏 O(n) |
| 场景 | 需要有序遍历 | 只查不排序 |

**什么时候用哪个**：

- 需要**按键有序遍历** → map
- 只需要**快速查找** → unordered_map（更快）
- ⚠️ 但**小规模（几十个元素）**时别迷信"O(1)"：`map` 常数小、缓存友好，常和 unordered 打平甚至更快——"哈希更快"主要在大 n 时才兑现

## 6. set / unordered_set

```cpp
std::set<int> s;              // 有序集合，元素唯一
std::unordered_set<int> us;   // 无序集合，元素唯一
s.insert(1);
s.count(2);   // 判断是否存在（1 或 0）
s.contains(2); // C++20
```

**用途**：去重、判断元素是否存在。

## 7. 容器适配器

| 容器 | 底层 | 说明 |
|------|------|------|
| `stack` | deque（默认） | 栈，后进先出，只有 top/push/pop |
| `queue` | deque（默认） | 队列，先进先出，只有 front/back/push/pop |
| `priority_queue` | vector + 堆 | 优先队列，自动取最大/最小 |

```cpp
std::stack<int> s;
s.push(1); s.top(); s.pop();

std::queue<int> q;
q.push(1); q.front(); q.pop();

std::priority_queue<int> pq;      // 大顶堆，top 是最大
std::priority_queue<int, std::vector<int>, std::greater<int>> min_pq;  // 小顶堆
```

**关键**：它们是"适配器"，包装了底层容器，只暴露有限接口（比如 stack、queue 都不能遍历）。

**`stack` 的方法（全部）**：

| 方法 | 作用 |
|------|------|
| `push(v)` / `emplace(args...)` | 压入 / 原地构造压入 |
| `top()` | 看栈顶（返回引用，可改） |
| `pop()` | 弹出——**没有返回值** |
| `empty()` / `size()` | 判空 / 元素个数 |
| `swap(other)` | 交换 |

**`stack` 的四个坑**：

1. `pop()` 不返回值——取值要先 `top()` 再 `pop()`（`int v = s.pop();` 编译不过）
2. **空栈上 `top()`/`pop()` 是未定义行为**（不抛异常）——先 `empty()` 检查
3. **没有 `clear()`**：`s = {};`，或 `while (!s.empty()) s.pop();`
4. 不能遍历——想看内容只能一个个弹（会清空）

**底层可换**：`std::stack<int, std::vector<int>>` 用 vector 当底层（默认 deque）；刷题里也常直接用 `vector` 手写栈（可遍历 + 连续内存更快）：

```cpp
std::vector<int> st;
st.push_back(x);   // 压
st.back();         // 顶
st.pop_back();     // 弹
```

**`queue` 的方法（全部）**：

| 方法 | 作用 |
|------|------|
| `push(v)` / `emplace(args...)` | 尾部入队 / 原地构造入队 |
| `front()` | 看队头（返回引用，可改） |
| `back()` | 看队尾（返回引用，可改） |
| `pop()` | 弹出队头——**没有返回值** |
| `empty()` / `size()` | 判空 / 元素个数 |
| `swap(other)` | 交换 |

**`queue` 的四个坑**：

1. `pop()` 不返回值——取值要先 `front()` 再 `pop()`（`int v = q.pop();` 编译不过）
2. **空队列上 `front()`/`back()`/`pop()` 是未定义行为**（不抛异常）——先 `empty()` 检查
3. **没有 `clear()`**：`q = {};`，或 `std::queue<int>().swap(q);`
4. 不能遍历——没有迭代器，也没有 `begin()/end()`

**底层不能是 `vector`**：queue 要求底层提供 `pop_front()`，vector 没有——`std::queue<int, std::vector<int>>` 能声明，但一调 `pop()` 就编译报错；默认 deque，也可以换 `std::list`。

**用途**：BFS 层序遍历、拓扑排序（Kahn 算法）、任务排队；`std::queue` 本身不加锁，多线程生产者—消费者要自己配互斥量和条件变量（见[并发编程](并发编程.md)的 `BlockingQueue`）。

## 8. 迭代器失效完整规则

**注意**：迭代器、**引用**、**指针**的失效规则不完全一样（容易踩坑）。

| 容器 | 操作 | 迭代器 | 引用/指针 |
|------|------|--------|----------|
| **vector** | 扩容 / reserve / shrink_to_fit（重分配） | 全失效 | 全失效 |
| | 插入 / push_back（未重分配） | 插入点及之后；`end()` 失效 | 插入点及之后 |
| | 删除 / pop_back | 删除点及之后；`end()` 失效 | 删除点及之后 |
| **deque** | 两端插入（push_front/push_back） | **全失效（含 end）** | 不影响 |
| | 两端删除（pop_front/pop_back） | 被删元素 + `end()` 失效 | 只失效被删元素 |
| | 中间插入/删除 | **全失效** | 全失效 |
| **list** | 插入 | 不影响 | 不影响 |
| | 删除 | 只被删的失效 | 只被删的失效 |
| **map/set** | 插入 | 不影响 | 不影响 |
| | 删除 | 只被删的失效 | 只被删的失效 |
| **unordered_map** | 插入（触发 rehash） | **全失效** | 不影响（引用稳定） |
| | 插入（未 rehash） | 不影响 | 不影响 |
| | 删除 | 只被删的失效 | 只被删的失效 |

`resize` 变大按插入、变小按删除处理；如果重新分配，按扩容规则。

**关键区别**：

- `vector` 扩容：迭代器、引用、指针**全失效**
- `deque` 两端插入：**迭代器全失效，但引用/指针不失效**（元素没搬）
- `unordered_map` rehash：**迭代器全失效，但引用/指针不失效**（节点没动，只是桶重排）← 这是容易忽略的细节

**安全做法**：遍历中要插入/删除，用 `it = container.erase(it)`（erase 返回下一个有效迭代器），别用失效的。

## 9. 容器的异常安全保证

| 操作 | 保证等级 |
|------|---------|
| vector 的 push_back | 强保证（元素可拷贝，或移动构造 noexcept；否则可能只剩基本/未指定） |
| vector 扩容 | 同上；move-only 且移动可能抛时不要假设强保证 |
| vector 的 insert（中间） | 基本保证；标准不保证强异常安全（具体看元素类型和实现） |
| list/map 的插入删除 | 强保证（只动节点） |

**强保证依赖移动构造 noexcept**（呼应右值引用）：

```cpp
// vector 扩容要搬移元素：
// 移动构造 noexcept → 可以安全搬移，失败也能回滚（强保证）
// 移动构造可能抛 → 有拷贝就拷贝回滚；move-only 且移动可能抛 → 不保证强异常安全
```

所以"移动构造加 noexcept"不只是性能，还关系到**异常安全**。

## 10. 迭代器是什么

迭代器是**容器和算法之间的桥梁**：算法通过迭代器操作容器，不用关心容器具体是什么。

迭代器 = 一个"像指针"的对象，指向容器中的元素，支持 `*` 解引用和 `++` 前进：

```cpp
std::vector<int> v{1, 2, 3};
auto it = v.begin();   // 指向第一个元素
*it;                   // 解引用，得到 1
++it;                  // 前进到下一个
it != v.end();         // 判断是否到末尾
```

## 11. 五种迭代器（按能力从弱到强）

| 迭代器 | 能力 | 例子 |
|--------|------|------|
| 输入迭代器 | 只读、单遍、单向 | 读文件流 |
| 输出迭代器 | 只写、单遍、单向 | 写文件流 |
| 前向迭代器 | 读写、多遍、单向 | forward_list |
| 双向迭代器 | 读写、多遍、双向（`++` 和 `--`） | list、map |
| **随机访问迭代器** | 读写、多遍、任意跳转（`it+n`） | vector、deque、array |

C++20 还细分出**连续迭代器**（`contiguous_iterator`）：在随机访问之上要求元素在内存中连续。`vector` / `array` / `string` 是连续迭代器；`deque` 是随机访问，但**不连续**。

**关键**：能力越强的迭代器，能用越多的算法。比如 `sort` 需要**随机访问迭代器**，所以 list 不能用 `std::sort`（list 是双向迭代器，要用 `list.sort()`）。

### 迭代器工具（常用）

| 工具 | 作用 |
|------|------|
| `std::distance` | 两个迭代器的距离；随机访问 O(1)，其他 O(n) |
| `std::advance` / `std::next` / `std::prev` | 前进/后移；`advance` 修改原迭代器，`next`/`prev` 返回新迭代器 |
| `std::begin` / `std::end` | 泛型取界（数组、容器都行） |
| `std::size` / `std::data` / `std::empty` | C++17，数组和容器统一接口 |
| `std::ssize` | C++20，有符号 size |
| `std::inserter` / `std::front_inserter` / `std::back_inserter` | 插入迭代器 |
| `std::iterator_traits<It>` | 取 `value_type` / `difference_type` 等（写泛型代码时用） |

## 12. begin / end 系列

```cpp
v.begin();   // 指向第一个元素
v.end();     // 指向最后一个元素的"下一个"（不是最后一个！）

v.rbegin();  // 反向：指向最后一个
v.rend();    // 反向：指向第一个的前一个

v.cbegin();  // const 版本
```

**关键**：`[begin, end)` 是**左闭右开**区间，`end()` 不指向任何有效元素，只作"哨兵"。

## 13. 迭代器失效（速查）

完整规则和引用/指针差异见 §8。只记三条：

- **vector**：扩容全失效；插入/删除点及之后失效；`push_back` 也失效 `end()`
- **deque**：两端插入迭代器全失效，但引用/指针稳定
- **list / map**：只失效被删元素

```cpp
std::vector<int> v{1, 2, 3};
auto it = v.begin();
v.push_back(4);   // 若扩容，it 失效；即使不扩容，end() 也失效
```

## 14. 迭代器适配器（reverse_iterator / insert_iterator）

```cpp
// 反向迭代器
std::vector<int> v{1, 2, 3};
for (auto it = v.rbegin(); it != v.rend(); ++it) { /* 3, 2, 1 */ }

// 插入迭代器：把输出插入到容器
std::vector<int> dst;
std::copy(v.begin(), v.end(), std::back_inserter(dst));   // 自动 push_back
```

## 15. 分配器（Allocator）

**定义**：管理内存分配/释放的对象，容器默认用 `std::allocator`。

```cpp
std::vector<int, MyAllocator<int>> v;   // 指定自定义分配器（几乎不用）
```

**为什么了解即可**：默认 `std::allocator`（就是 new/delete）自动生效，日常**完全不用管**。只有写内存池、嵌入式、性能极致优化时才自定义。

**allocator 的 rebind**（写自定义容器才碰到）：

```cpp
// rebind：把分配"T 类型内存"的分配器，换成分配"另一个类型 U 内存"的分配器
template <typename T>
struct MyAllocator {
    template <typename U>
    MyAllocator(const MyAllocator<U>&) { /* ... */ }     // rebind 需要的转换构造
    template <typename U>
    struct rebind { using other = MyAllocator<U>; };     // rebind 定义
};

// 为什么需要：std::list<T> 分配的是"节点"（内含 T），
// 所以要把 allocator<T> 重绑定成 allocator<节点类型>
```

实际极少用到，知道"rebind = 把分配器重绑定到另一类型"即可。

### std::pmr 多态分配器（C++17，实用）

**问题**：传统 allocator 是**模板参数**（`vector<int, MyAlloc<int>>`），类型不同就换不了，运行时无法切换。

**pmr**（Polymorphic Memory Resource）解决这个：**运行时**指定内存资源：

```cpp
#include <memory_resource>

// 用栈上的缓冲区做内存池（避免堆分配）
std::array<std::byte, 1024> buf;
std::pmr::monotonic_buffer_resource pool{buf.data(), buf.size()};

// 容器用 pmr 版本，绑定到这个 pool
std::pmr::vector<int> v{&pool};
v.push_back(1);   // 小分配从 buf 切；池用完后会走上游分配（默认堆）

// 常用 memory_resource：
// monotonic_buffer_resource：只增不减的分配器（适合"构建后只读"）
// unsynchronized_pool_resource：非线程安全内存池（快）
// synchronized_pool_resource：线程安全内存池
```

**用途**：频繁小对象分配优化（游戏、解析器）、减少堆分配、控制生命周期。

### 内存池设计思路（工程优化）

**问题**：频繁 `new/delete` 小对象 → 慢（系统调用）+ 碎片。

**内存池做法**：一次性申请一大块，自己管理小块分配：

```cpp
// 简化思路：
// 1. 启动时申请一大块内存
// 2. 分配时从池里切一块（无系统调用）
// 3. 释放时还回池里（不还给系统）
// 4. 池销毁时整体释放

// 定长对象池（free list，空闲链表）：
class ObjectPool {
    // 空闲节点串成链表，分配时取头，释放时插回头
};
```

**收益**：分配 O(1)（无系统调用）、减少碎片、提升 cache 命中。

### scoped_allocator

嵌套容器的分配器传播：`vector<vector<int>>` 时，外层容器的分配器如何传给内层。嵌套场景才用到，很少用。

## 16. 要点回顾

1. **底层结构决定复杂度**：vector=数组、list=链表、map=红黑树（主流实现）、unordered_map=哈希
2. **默认用 vector**（连续内存、缓存友好）
3. **需要有序 → map，只查找 → unordered_map**
4. **已有迭代器且频繁中间插入/删除才用 list**；否则 vector 往往更快
5. 迭代器失效：vector 扩容全失效；deque 两端插入全失效但引用稳定；list/map 只失效被删的
6. **迭代器 = 算法和容器的桥梁**，像指针
7. **迭代器五种能力**；C++20 还有连续迭代器（vector/array/string）
8. **`[begin, end)` 左闭右开**，end 是哨兵
9. 反向迭代器 `rbegin/rend`、插入迭代器 `back_inserter`
10. **`vector<bool>` 是特例**：位压缩 + 代理引用，没有可用的 `data()`，不要套普通 vector 的连续/引用规则
