# C++20

## 语言特性

### 1. Concepts（概念）

**解决的问题**：C++11 的模板报错是"天书"（SFINAE 失败信息几十行），而且约束只写在文档里、编译器不检查。

```cpp
#include <concepts>

template <typename T>
concept Numeric = std::integral<T> || std::floating_point<T>;

template <Numeric T>
T add(T a, T b) { return a + b; }

add(1, 2);          //
// add("a", "b");   // ❌ 报错第一行就写：constraints not satisfied，并指出 Numeric<T>

// 写法二：requires 子句
template <typename T>
    requires std::integral<T>
T gcd(T a, T b);

// 写法三：requires 表达式（直接描述"需要什么操作"）
template <typename T>
    requires requires(T a, T b) { a + b; }
auto add2(T a, T b) { return a + b; }

// 写法四：缩写函数模板（最简）
void print(std::integral auto x) { std::cout << x << '\n'; }
```

**常用标准 concept**：

| concept | 要求 |
|---------|------|
| `std::integral` / `std::floating_point` | 整数 / 浮点 |
| `std::same_as<T, U>` | 类型完全相同 |
| `std::convertible_to<From, To>` | 可隐式转换 |
| `std::invocable<F, Args...>` | 能用这些参数调用 |
| `std::derived_from<D, B>` | 继承关系 |
| `std::movable` / `std::copyable` | 可移动 / 可拷贝 |
| `std::ranges::range<T>` | 是个范围（能 range-for） |

**什么时候用**：写模板库/工具函数时给参数加约束——报错更清楚（约束满足与否在签名里），重载选择也更明确（concept 更强的版本优先）。

**注意**：concept 只做**编译期约束检查**，不产生运行时代码；也不会帮你"排除"不该选的类型——不满足就编译失败。

### 2. 三路比较运算符 <=>（spaceship）

```cpp
#include <compare>

struct Version {
    int major, minor;
    auto operator<=>(const Version&) const = default;   // 一行生成全部比较
};

Version a{1, 2}, b{1, 3};
a < b;   a == b;    a >= b;    // 全部可用
```

**一行 `= default` 生成什么**：按成员依次做 `<=>`（再自动合成 `<`、`>`、`<=`、`>=`）和 `==`。省掉 6 个比较运算符的手写。

**三种返回类型**：

| 类型 | 含义 | 例子 |
|------|------|------|
| `std::strong_ordering` | 全序，相等即**可互换** | 整数、字符串 |
| `std::weak_ordering` | 相等但对象**不可互换**（等价但不相同） | 大小写不敏感的字符串 |
| `std::partial_ordering` | 可能**不可比** | 浮点（NaN 和任何值都不可比） |

**坑**：

- 类里有**浮点成员** → 推导出 `partial_ordering`，用 `<` 比较时 NaN 会让所有比较都是 false
- 想**自定义"相等"的含义**（比如按 id 判等但按名字排序）就要手写 `operator==` / `<=>`，别 `= default`
- `= default` 的 `<=>` 要求所有成员都支持 `<=>`；不支持的成员要自己写

### 3. 指定初始化器

```cpp
struct Config {
    int retries = 3;
    bool verbose = false;
    std::string name;
};

Config c{.retries = 5, .name = "run1"};    // 只写想改的，其余用默认值
Config d{.name = "x"};                     // 跳过前面的成员也行（有默认值）
```

**规则（和 C 不同，容易踩）**：

- 必须**按声明顺序**写：`.name` 不能写在 `.retries` 前面
- 只能用于**聚合类型**（没有用户提供的构造函数）
- 不能把指定和位置初始化**混用**：`{1, .name = "x"}` ❌
- 不能嵌套指定（`.inner.x = 1` ❌）

**什么时候用**：结构体字段多、又有默认值时，比"按位置传一堆 bool"可读得多。

### 4. 范围 for 带初始化语句

```cpp
// 循环期间持锁（range-for 本身没有"自增表达式"，init 常用来放守卫/引用）
for (std::lock_guard<std::mutex> lk{mtx}; auto& task : queue) {
    task.run();
}

// 先把容器引用取出来（避免 get() 被反复调用）
for (auto& container = get_container(); auto& x : container) {
    x.process();
}
```

和 `if`/`switch` 的初始化语句一样：把循环用到的辅助变量作用域收进循环。

### 5. lambda 增强

```cpp
// ① 模板 lambda：显式类型参数（C++14 的 auto 参数不够用时）
auto print_size = []<typename T>(const std::vector<T>& v) {
    std::cout << v.size() << '\n';
};

// ② 捕获参数包（变参场景）
template <typename... Args>
void log_all(Args&&... args) {
    auto f = [args...] { ((std::cout << args << ' '), ...); };   // 按值捕获整包
    f();
}

// ③ 按值捕获 *this（副本），而不是捕获 this 指针
struct Worker {
    int id = 0;
    auto make_task() {
        return [*this] { return id; };      // 副本：对象销毁后任务仍安全
    }
};
```

**其他变化**：

- **无捕获的 lambda 可以默认构造和赋值**（C++20 起）——可以放进容器、作为"默认函数"用
- lambda 可以用在**未求值上下文**（`decltype` / `sizeof` 里）
- `[=]` **隐式捕获 this 被弃用**（C++20 起）——写 `[=, this]` 或 `[*this]` 明确意图（多线程/异步里捕获 `this` 最容易悬垂）

### 6. consteval / constinit（以及 constexpr 的动态分配）

三个关键字各管一段，容易混：

```cpp
constexpr int f() { return 42; }     // 能编译期也能运行期求值（"可以"）
consteval int g() { return 42; }     // 立即函数：必须编译期求值（"必须"）
constinit int x = f();               // 要求 x 是"常量初始化"，但 x 之后可改
```

**consteval（立即函数）**：调用它必须产生编译期常量——用在"这个函数只能在编译期调用"的场合（比如生成查表、编译期校验）。

**constinit 解决什么**：**静态初始化顺序问题**——不同编译单元的全局对象初始化顺序不确定，用 `constinit` 强制"必须在编译期算好"，避免"用一个还没初始化的全局对象"。

```cpp
constinit int table[4] = {f(), f(), f(), f()};   // 编译期就算好，运行时零初始化
```

**C++20 起 constexpr 里能用动态分配**（`new` / `std::vector` / `std::string`），只要内存在常量求值结束前释放：

```cpp
constexpr int sum_upto(int n) {
    std::vector<int> v;                 // constexpr 里能建 vector（GCC 12+）
    for (int i = 1; i <= n; ++i) v.push_back(i);
    return std::accumulate(v.begin(), v.end(), 0);
}
static_assert(sum_upto(4) == 10);       // 编译期算出来
```

**坑**：分配的内存**不能"逃逸"**出常量求值——`constexpr auto v = make_vec();` 这种"把编译期 vector 存起来"是不允许的（编译错误）；只能用它算出一个标量/固定大小的结果。

### 7. Coroutines（协程）

```cpp
#include <coroutine>
// 三个关键字：co_await（挂起等待）、co_yield（产出值）、co_return（返回）
```

**本质**：协程 = 可挂起/恢复的函数。`co_yield` 处函数"暂停"，把值交出去，下次调用从暂停处继续。写生成器、异步 IO 时很有用（但实现细节多，业务中常用库封装好的）。

**协程进阶**：

**有栈协程 vs 无栈协程**：

| | 有栈协程 | 无栈协程（C++20） |
|--|---------|------------------|
| 栈 | 每个协程独立栈 | 共享线程栈（状态存堆上） |
| 切换开销 | 大（切栈） | 小（只存局部状态） |
| 内存 | 每协程一个栈 | 按需分配 |
| 例子 | Go goroutine、libco | C++20 协程 |

**为什么 C++ 协程"看起来难用"**：标准只定义了**机制**（编译器把协程函数变成状态机 + 调 `promise_type` 的钩子），**没有**给你现成的 Generator/Task 类型——要自己写 `promise_type`（约 30 行样板），或者用库（cppcoro、asio、C++23 的 `std::generator`）。

**一个能跑的极简生成器**：

```cpp
#include <coroutine>
#include <iostream>

template <typename T>
struct Generator {
    struct promise_type {
        T current;
        Generator get_return_object() {
            return Generator{std::coroutine_handle<promise_type>::from_promise(*this)};
        }
        std::suspend_always initial_suspend() { return {}; }
        std::suspend_always final_suspend() noexcept { return {}; }
        std::suspend_always yield_value(T v) { current = v; return {}; }
        void return_void() {}
        void unhandled_exception() { std::terminate(); }
    };

    std::coroutine_handle<promise_type> handle;
    explicit Generator(std::coroutine_handle<promise_type> h) : handle(h) {}
    ~Generator() { if (handle) handle.destroy(); }
    Generator(const Generator&) = delete;

    bool next() { handle.resume(); return !handle.done(); }
    T value() const { return handle.promise().current; }
};

Generator<int> range(int n) {
    for (int i = 0; i < n; ++i) co_yield i;      // 挂在这里，下次从这继续
}

int main() {
    auto g = range(3);
    while (g.next()) std::cout << g.value() << ' ';   // 0 1 2
}
```

**结论**：协程不是"更快的线程"，而是"**用户态的轻量任务**"，适合 IO 密集高并发（一个线程跑很多协程）。C++20 提供机制，实际用需配合调度器/库（如 asio）。

### 8. Modules（模块）

**解决的问题**：`#include` 是文本替换——同一个头被反复解析、宏会互相污染、编译慢。模块把接口**编译成二进制**，`import` 时直接读：

```cpp
// math.cppm —— 模块接口
export module math;                                // 声明模块名

export int add(int a, int b) { return a + b; }     // export 才对导入方可见
int helper() { return 1; }                         // 没 export：模块私有
```

```cpp
// main.cpp
import math;          // 不再需要 #include；add 直接可用
```

| | 头文件 | 模块 |
|--|--------|------|
| 处理方式 | 文本包含，每个编译单元重新解析 | 预编译的二进制接口 |
| 宏污染 | 会外泄 | 模块内的宏不外泄 |
| 顺序依赖 | 有（包含顺序会影响结果） | 无 |
| 编译速度 | 重复解析，慢 | 一次编译，多次 import |

**现状**：C++20 进了标准，`import std;` 是 C++23 写法。编译器方面 MSVC 最完整，GCC 用 `-fmodules-ts` 可编（需 `-x c++` 指定语言）；**构建系统**（CMake 3.28+ 的 `CXX_MODULES` 文件集）和**生态**（绝大多数库仍是头文件）还在过渡——新项目可以试，老项目迁移成本主要在依赖。

## 标准库特性

### 9. std::span（视图，零拷贝）

```cpp
#include <span>

void process(std::span<const int> data) {      // 参数用 span：什么连续容器都能传
    for (int x : data) { /* ... */ }
    data.size();
    data.size_bytes();                         // 字节数（= size * sizeof(T)）
}

std::vector<int> v{1, 2, 3};
std::array<int, 3> a{1, 2, 3};
int c[3] = {1, 2, 3};
process(v);        //
process(a);        //
process(c);        //

std::span<int> s = v;          // 可写（元素类型不带 const）
s.first(2);                    // 前两个
s.last(1);                     // 最后一个
s.subspan(1, 2);               // 从 1 开始取 2 个（子视图）
```

**它替代什么**：老代码的 `(const int* ptr, size_t len)` 或 `(begin, end)` 两个参数——一个 `span` 搞定，且自带 `size()`。

**静态长度版**：`std::span<int, 3>`（编译期已知长度，更严格）。

**坑**：

- **不拥有数据**——和 `string_view` 一样是"指针 + 长度"，源容器销毁/扩容后就是悬垂：
  ```cpp
  std::span<const int> bad() {
      std::vector<int> v{1, 2, 3};
      return v;              // ❌ 悬垂
  }
  ```
- `vector` 扩容后旧的 span 也可能失效（指向老内存）
- `span<string_view>`、`span<char>` 这些要留神元素语义（char 是字节还是字符）

### 10. std::format（格式化输出）

```cpp
#include <format>

std::string s = std::format("{}-{:.2f}", "lr", 3.14159); // "lr-3.14"（注意 0.015 会格式化成 0.01：二进制表示略小）
std::format("{:>8}|", 42);        // "      42|"（右对齐 8）
std::format("{:08}", 42);         // "00000042"
std::format("{:#x}", 255);        // "0xff"
std::format("{1} {0}", "a", "b"); // "b a"（按位置取参）
```

**和 printf / iostream 比**：

| | printf | iostream | std::format |
|--|--------|----------|-------------|
| 类型安全 | ❌（格式串和参数不匹配是 UB） | ✅ | ✅（编译期检查） |
| 可读性 | 格式串和参数分离 | 链式 `<<` 冗长 | 一个格式串 |
| 扩展 | 不能自定义 | 要重载 `<<` | 特化 `std::formatter<T>` |

**其他接口**：`std::format_to(输出迭代器, ...)`（不产生中间 string）、`std::formatted_size(...)`（先算长度）、`std::vformat`（运行期格式串）。

**坑**：

- 编译器/标准库支持较晚：GCC 13+ 才有 `<format>`（本机可用）；MSVC 需要较新版本并开 `/std:c++20`
- 格式串里的 `{}` 数量和参数个数不匹配是**编译错误**（这是优点）
- `std::format` **不支持命名参数**（那是 fmt 库的 `fmt::arg` 扩展）——要按位置或顺序写

### 11. std::ranges（范围库）

```cpp
#include <ranges>
namespace rv = std::views;                 // C++20 起 std::views 是标准别名

std::vector<int> v{1, 2, 3, 4, 5, 6};

// 算法直接吃容器（不用 begin/end）
std::ranges::sort(v);
std::ranges::find(v, 3);

// views 管道：惰性、可组合
auto result = v | rv::filter([](int x) { return x % 2 == 0; })
                | rv::transform([](int x) { return x * x; })
                | rv::take(2);
for (int x : result) std::cout << x << ' ';      // 4 16

// 常用 views
rv::iota(1, 5);            // 1 2 3 4
rv::reverse(v);
rv::drop(v, 2);            // 跳过前 2 个
rv::join(nested);          // 把"范围的范围"拍平
```

**关键点**：

- **惰性**：`filter | transform` 不产生中间容器，遍历到哪个元素才算哪个
- **可组合**：`|` 拼流水线，比嵌套算法调用好读
- 元素类型复杂时用 `auto` 接（`std::ranges::range_value_t` 这类别名帮忙取类型）

**坑**：

- **view 不拥有数据**：`auto f() { std::vector<int> v; return v | rv::take(1); }` ❌ 悬垂
- 某些 view 里**缓存了迭代器**（如 `filter`）；对容器做插入/删除后继续用同一个 view 可能失效
- C++20 的 ranges 算法和迭代器版**并存**：`std::sort(v.begin(), v.end())` 和 `std::ranges::sort(v)` 都在，后者带概念约束、报错更好

### 12. std::jthread（自动 join 的线程）

```cpp
#include <thread>

std::jthread t{[](std::stop_token st) {          // 参数能接 stop_token
    int i = 0;
    while (!st.stop_requested()) {               // 协作式检查停止请求
        work(i++);
    }
}};

t.request_stop();        // 请求停止（线程自己决定何时退出）
// t 析构时：自动 request_stop + join —— 不会像 std::thread 那样 terminate
```

**和 `std::thread` 对比**：

| | `std::thread` | `std::jthread` |
|--|---------------|----------------|
| 析构时 | 没 join/detach → **std::terminate** | 自动 request_stop + join |
| 停止机制 | 无（自己用 atomic/flag） | `stop_token` 标准化 |
| 条件变量集成 | 无 | `condition_variable_any::wait` 直接接 stop_token |

**坑**：停止是**协作式**的——`request_stop()` 只是发信号，线程要自己检查 `stop_requested()`（或用支持 stop_token 的等待函数），否则照跑不误。

### 13. std::contains（容器判断成员）

```cpp
std::map<std::string, int> m{{"a", 1}};
if (m.contains("a")) { }              // 替代 m.find("a") != m.end()
if (std::set<int>{1, 2}.contains(2)) { }
if (std::string("hello").contains("ell")) { }
```

**注意**：对 map/set 是 O(log n) / O(1)；`std::vector` **没有** `contains`（线性查找语义不明显，用 `std::find`）。

### 14. std::erase / std::erase_if（统一删除）

```cpp
std::vector<int> v{1, 2, 2, 3, 4};
std::erase(v, 2);                                    // 顺序容器：删掉所有等于 2 的 → {1, 3, 4}
std::erase_if(v, [](int x) { return x % 2 == 0; });  // 按条件删

std::map<std::string, int> m{{"a", 1}, {"b", 2}};
std::erase_if(m, [](auto& kv) { return kv.second > 1; });   // 关联容器：只有 erase_if
m.erase("a");                                        // 按 key 删 → 用成员函数
```

**替代了什么**：vector 的 erase-remove 惯用法（`v.erase(std::remove_if(...), v.end())`）——现在一行。

**注意（实测 GCC 13）**：

- `std::erase(container, value)` **只有顺序容器**（vector / deque / list / string）有
- 关联容器（map / set / unordered_*）只有 `std::erase_if`；**`std::erase(map, key)` 用不了**（C++20 / C++23 模式都不行），按 key 删还是 `m.erase(key)`

### 15. std::bit_cast（安全的位级转换）

```cpp
#include <bit>

float f = 3.14f;
std::uint32_t bits = std::bit_cast<std::uint32_t>(f);   // 按位重解释

static_assert(sizeof(float) == sizeof(std::uint32_t));  // 要求同大小
```

**为什么不用别的**：

- `reinterpret_cast` 读另一种类型 → **违反严格别名规则（UB）**
- `memcpy(&dst, &src, sizeof(src))` → 正确但啰嗦，且 constexpr 里不能用
- `std::bit_cast` → 类型安全、要求"同大小 + 可平凡复制"、**constexpr 可用**

**用途**：浮点位级比较（区分 +0.0 / -0.0、看 NaN 载荷）、哈希、序列化。

### 16. 并发同步原语

C++20 补齐了几个基础件（以前只能自己封装条件变量）：

```cpp
#include <latch>
#include <barrier>
#include <semaphore>

// latch：一次性倒计数（等 N 个事件都到齐）
std::latch done{3};
auto worker = [&done] { do_work(); done.count_down(); };
std::thread t1{worker}, t2{worker}, t3{worker};
done.wait();                       // 主线程等三个都完成

// barrier：可复用的屏障（每个阶段都同步）
std::barrier sync{4};
auto phase_worker = [&sync] {
    for (int phase = 0; phase < 10; ++phase) {
        do_phase(phase);
        sync.arrive_and_wait();     // 每轮等所有人
    }
};

// counting_semaphore：经典信号量（限制并发数）
std::counting_semaphore<4> slots{4};
slots.acquire();                   // 拿一个许可（没有就阻塞）
// ...
slots.release();

// atomic 的等待/通知（C++20）：替代"轮询 + sleep"
std::atomic<int> flag{0};
// 线程 A：flag.store(1); flag.notify_one();
// 线程 B：flag.wait(0);        // 等到值不再是 0 才醒
```

**怎么选**：

| 需求 | 用什么 |
|------|--------|
| 等一组任务全部就绪（一次） | `latch` |
| 多阶段循环同步（每轮对齐） | `barrier` |
| 限流 / 资源池 | `counting_semaphore` |
| 轻量事件通知 | `atomic` 的 `wait`/`notify_*` |

### 17. std::numbers（数学常量）

```cpp
#include <numbers>

std::numbers::pi;          // double
std::numbers::pi_v<float>; // float 精度
std::numbers::e;
std::numbers::sqrt2;
std::numbers::ln2;
```

替代自己写 `#define PI 3.14159...`（精度/类型不一致的问题）。

### 18. char8_t

```cpp
char8_t c = u8'a';             // UTF-8 码元（独立的类型，不再是 char）
const char8_t* s = u8"你好";    // u8 字面量的类型变了
std::u8string us = u8"你好";
```

**注意**：C++20 起 `u8"..."` 的类型从 `const char[]` 变成 `const char8_t[]`——**可能破坏旧代码**（传 `const char*` 的地方不行了，要转换/重写）。

## 小工具

### 19. 常用小特性

```cpp
// string / string_view 的前后缀判断（不用再 compare(0, n, ...)）
std::string s = "hello.cpp";
s.starts_with("hello");        // true
s.ends_with(".cpp");           // true

// 源码位置（日志/断言里记录"哪个文件哪一行"）
#include <source_location>
void log(std::string_view msg,
         const std::source_location& loc = std::source_location::current()) {
    std::cout << loc.file_name() << ':' << loc.line() << " " << msg << '\n';
}

// <bit>：位运算工具
std::popcount(0b1011u);        // 3（1 的个数）
std::countl_zero(0b1u);        // 前导零个数
std::bit_width(5u);            // 3（表示 5 需要几位）
std::has_single_bit(8u);       // true（是不是 2 的幂）

// 有符号长度（和 int 比较不会有符号警告）
std::ssize(v);                 // 等价 (long)v.size()

// 数组 → std::array
auto a = std::to_array({1, 2, 3});

// 分支提示（给编译器的优化提示，别乱用）
if (x > 0) [[likely]] { /* 热路径 */ }
else [[unlikely]] { /* 冷路径 */ }

// 成员的空基类优化（把空类型成员压成 0 字节）
struct Empty {};
struct S {
    [[no_unique_address]] Empty e;   // sizeof(S) 可能还是 1，取决于实现
    int x;
};

// 告诉编译器"这块内存按 N 字节对齐"（帮助自动向量化）
float* p = std::assume_aligned<32>(raw);

// 中点 / 线性插值（比 (a+b)/2 更稳：不会溢出）
#include <numeric>             // std::midpoint
#include <cmath>               // std::lerp
std::midpoint(3, 7);           // 5
std::lerp(0.0, 10.0, 0.25);    // 2.5

// 字节序
if constexpr (std::endian::native == std::endian::little) { /* 小端 */ }
```
