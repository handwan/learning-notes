# 面向对象

C++ 面向对象三大特性：**封装、继承、多态**。多态（虚函数）是核心。

## 1. 封装（Encapsulation）

**目的**：隐藏内部实现，只暴露接口。

```cpp
class Person {
private:        // 只有类内部能访问
    int age_;

public:         // 外部都能访问
    void set_age(int a) { age_ = a; }   // 通过接口访问，可加校验
    int get_age() const { return age_; }
};

// struct 默认 public，class 默认 private（默认继承方式也同理：struct 默认公有继承、class 默认私有继承）
```

**作用**：控制谁能改数据（校验、不变性）、隐藏实现细节（改内部不影响使用者）。

### 访问级别速查

| 级别 | 谁可以访问 |
|------|-----------|
| `public` | 任何人 |
| `protected` | 类内部 + **派生类** + 友元 ✅（外部不行 ❌） |
| `private` | 类内部 + 友元 ✅（派生类也不行 ❌） |

`protected` 的意义：给子类留"可改可调"的接口，对**外部**依旧隐藏 ✅——它是"继承专用"的中间级别 ✅（实测：子类能读 `prot_` ✅；外部 `b.prot_` 报 `is protected within this context` ❌）。

**默认与写法**：`class` 默认 `private`、`struct` 默认 `public`（继承方式同理）；`private` 可以省略不写，但**建议显式写**——读代码的人不用回忆默认规则。

### 友元（friend）

**作用**：把"访问 private 的权限"单独开给某个函数/类；它**不是成员**。

```cpp
class Matrix {
    friend std::ostream& operator<<(std::ostream& os, const Matrix& m);   // 声明友元
private:
    int data_[2] = {7, 9};
};
std::ostream& operator<<(std::ostream& os, const Matrix& m) {
    return os << "{" << m.data_[0] << "," << m.data_[1] << "}";           // 友元能访问 private
}
```

三条性质（都实测过）：

- **单向**：A 是 B 的友元 ≠ B 是 A 的友元 ❌
- **不继承**：父类的友元**不能**访问子类的 private（实测报错：`'int D::d_' is private within this context`）
- **不可传递**：A 友元于 B、B 友元于 C ≠ A 能访问 C ❌

**什么时候用**：重载 `operator<<` / `operator>>`（见[基础](基础.md)）、`swap`（见[工程规范](工程规范.md)）、两个类必须访问彼此内部的场景。**别滥用**——友元是给封装开的口子，能用公共接口就别开口子。

## 2. 继承（Inheritance）

**目的**：复用代码，建立"is-a"关系。

```cpp
class Animal {
public:
    void eat() { /* ... */ }
};

class Dog : public Animal {   // Dog 是 Animal（is-a）
public:
    void bark() { /* ... */ }
};

Dog d;
d.eat();    // 继承来的
d.bark();   // 自己的
```

### 构造/析构顺序

```cpp
// 构造：先基类，后派生类
// 析构：先派生类，后基类（和构造相反）
```

**为什么这个顺序**：派生类**依赖**基类——派生类的构造/析构函数里要用基类的成员（继承来的变量、基类方法），所以基类必须先构造好、最后析构。

```cpp
class Base {
public:
    Base()  { std::cout << "Base 构造\n"; }
    ~Base() { std::cout << "Base 析构\n"; }
};

class Derived : public Base {
public:
    Derived()  { std::cout << "Derived 构造\n"; }
    ~Derived() { std::cout << "Derived 析构\n"; }
};

Derived d;
// 输出：Base 构造 → Derived 构造 → Derived 析构 → Base 析构
```

**记忆**：像穿衣服——先穿内衣（基类）再穿外套（派生类），脱的时候反过来（先外套后内衣）。

**完整顺序**（实测）：**虚基类 → 基类（按继承列表顺序）→ 成员（按声明顺序）→ 自己的构造体**；析构严格逆序。

两个容易忽略的细节：

**① 成员按"声明顺序"初始化，与初始化列表的书写顺序无关**：

```cpp
struct S {
    M1 m1;              // 先声明 → 先初始化
    M2 m2;
    S() : m2(), m1() {} // 故意写反：实际仍是 m1 → m2（编译器给 -Wreorder 警告）
};
```

实测输出 `M1 → M2`。顺序写反还让成员**互相依赖**（用一个尚未初始化的成员去初始化另一个）就是 bug——打开 `-Wall` 让 `-Wreorder` 提醒。

**② 虚基类最先构造，且由"最派生类"负责初始化**：

```cpp
struct V        { V()  { /* ... */ } };
struct A : virtual V { A() { /* ... */ } };
struct B : virtual V { B() { /* ... */ } };
struct D : A, B      { D() : V(), A(), B() {} };   // 虚基类由 D 初始化（A/B 的初始化被忽略）
```

实测构造顺序：`虚基类 V → A → B → D`——这样"共享的那一份 V"只初始化一次，不会被子类重复构造。

### 三种继承方式

| 继承方式 | 基类 public 成员变 | 基类 protected 成员变 |
|---------|------------------|---------------------|
| `public` 继承 | public | protected |
| `protected` 继承 | protected | protected |
| `private` 继承 | private | private |

**日常 99% 用 `public` 继承**，其他两种几乎不用。

### 菱形继承与虚继承

多继承时，两个基类继承自同一祖先，会出现"菱形"结构：

```cpp
class A { public: int a; };

class B : public A { /* ... */ };
class C : public A { /* ... */ };

class D : public B, public C { /* ... */ };
// 问题：D 里有两份 A 的成员（B 的 A 和 C 的 A），
// d.a 有歧义（到底用哪份？），内存也浪费
```

**解决：虚继承**（让 B、C 虚继承 A，共享同一份 A）：

```cpp
class B : virtual public A { /* ... */ };
class C : virtual public A { /* ... */ };
class D : public B, public C { /* ... */ };
// 现在 D 里只有一份 A
```

**代价**：虚继承有额外开销（虚基类指针），所以**能不用多继承就不用**。知道概念即可。

### 名字隐藏（Name Hiding）

派生类定义同名函数，会**隐藏基类的所有同名重载**：

```cpp
class Base {
public:
    void f() { /* ... */ }
    void f(int) { /* ... */ }     // 两个重载
};

class Derived : public Base {
public:
    void f() { /* ... */ }        // 隐藏了基类的所有 f
};

Derived d;
d.f();        // 调 Derived 的
d.f(1);       // ❌ 编译错误！基类的 f(int) 被隐藏了
```

**解决**：用 `using Base::f;` 把基类的重载"拉"回来：

```cpp
class Derived : public Base {
public:
    using Base::f;                // 基类重载重新可见
    void f() { /* ... */ }
};
```

## 3. 多态（Polymorphism）

**多态 = 同一接口，不同行为**。分两种：

- **静态多态**（编译期）：函数重载、模板
- **动态多态**（运行期）：虚函数

### 虚函数与动态多态

```cpp
class Animal {
public:
    virtual void speak() { std::cout << "...\n"; }   // 虚函数
};

class Dog : public Animal {
public:
    void speak() override { std::cout << "汪\n"; }   // 重写
};

class Cat : public Animal {
public:
    void speak() override { std::cout << "喵\n"; }
};

Animal* a = new Dog();
a->speak();   // 输出"汪"——按实际类型调用，这就是多态！
```

**关键**：基类指针/引用指向派生类对象时，虚函数按**实际对象类型**调用（不是指针类型）。

### 虚函数表（vtable）——底层原理

```cpp
// 有虚函数的类，编译器为它生成一张虚函数表（vtable）
// 对象里多存一个指针 vptr，指向虚函数表

// Dog 对象布局（简化）：
//   vptr ──→ Dog 的 vtable：[&Dog::speak]
//   成员变量...

// 调用 a->speak() 时：
// 1. 通过 a 的 vptr 找到 vtable
// 2. 查 speak 在 vtable 里的位置
// 3. 调用实际指向的函数
```

**所以虚函数有开销**：多一次间接寻址（vptr → vtable → 函数）。

### 纯虚函数与抽象类

```cpp
class Shape {
public:
    virtual double area() = 0;   // 纯虚函数（= 0），没有实现
};

// Shape 是抽象类，不能实例化
// Shape s;   // ❌ 编译错误

class Circle : public Shape {
    double area() override { return 3.14 * r * r; }
};
// 派生类必须实现所有纯虚函数，否则也是抽象类
```

**用途**：定义接口（像 Java 的 interface），强制派生类实现。

### 虚析构函数

```cpp
class Base {
public:
    virtual ~Base() { /* ... */ }   // ⚠️ 基类析构必须是 virtual
};

class Derived : public Base {
    std::string data_;              // 派生类有自己的资源
};

Base* p = new Derived();
delete p;   // 如果 ~Base 不是虚的，Derived 的析构不会被调，泄漏！
```

**规则**：**只要一个类会被继承，析构函数就要写 `virtual`**。否则基类指针 delete 派生类对象时，派生类的析构不会被调用（内存泄漏）。

### 构造/析构里调用虚函数

```cpp
class Base {
public:
    Base() { init(); }              // ❌ 构造里调虚函数
    virtual void init() { /* Base 版 */ }
};

class Derived : public Base {
    void init() override { /* Derived 版 */ }
};

// 构造 Derived 时，先执行 Base 构造函数，
// 此时 Derived 还没构造完，init() 调的是 Base 版（不是 Derived 版）
```

**规则**：构造/析构函数里调虚函数，调的是**当前类**的版本，不是派生类版本（因为派生类还没构造/已析构）。

### 对象切片（Object Slicing）

派生类对象**按值**传给基类参数时，派生类部分被"切掉"：

```cpp
class Base { /* ... */ };
class Derived : public Base { int extra; };

void f(Base b) { /* 按值传递 */ }

Derived d;
f(d);        // ❌ d 被切片！只拷 Base 部分，extra 丢了

// 多态必须用指针或引用：
void g(Base& b) { /* 引用，不切片 */ }
g(d);        //
```

**规则**：多态传参用**指针或引用**，按值传递会切片。

### 虚函数带默认参数

```cpp
class Base {
public:
    virtual void f(int n = 10) { /* ... */ }
};

class Derived : public Base {
    void f(int n = 20) override { /* ... */ }   // ⚠️ 默认参数各自不同
};

Derived d;
Base* p = &d;
p->f();   // 用哪个默认值？→ 10（Base 的）！
```

**原因**：虚函数是**动态绑定**（运行期确定函数），但默认参数是**静态绑定**（编译期确定）。`p` 是 Base*，默认值就取 Base 的 10。

**规则**：**虚函数不要用默认参数**（容易踩坑），或保持基类派生类默认值一致。

### dynamic_cast 与 RTTI

运行期类型转换，用于**向下转型**（基类指针 → 派生类指针）：

```cpp
Base* p = new Derived();

// 指针版：失败返回 nullptr
if (auto* d = dynamic_cast<Derived*>(p)) {
    // p 真的是 Derived，安全使用 d
}

// 引用版：失败抛 std::bad_cast
Derived& d = dynamic_cast<Derived&>(*p);
```

**前提**：基类必须有虚函数（多态类型）才能用 dynamic_cast。

**对比**：

| 转换 | 时机 | 安全 |
|------|------|------|
| `static_cast` | 编译期 | 不安全（不检查） |
| `dynamic_cast` | 运行期（RTTI） | 安全（失败返回 nullptr/抛异常） |

**为什么少用**：dynamic_cast 有运行期开销，且设计良好的代码一般不需要（应该靠虚函数，而不是判断实际类型）。

## 4. 拷贝控制：浅拷贝 vs 深拷贝

### 浅拷贝 vs 深拷贝

**浅拷贝**（默认拷贝构造）：只拷贝**指针本身**，两个对象指向同一块内存：

```cpp
class String {
    char* data_;
public:
    String(const char* s) { data_ = new char[strlen(s)+1]; strcpy(data_, s); }
    // 没自定义拷贝构造 → 用默认的浅拷贝
};

String s1("hello");
String s2 = s1;      // 浅拷贝！s1.data_ 和 s2.data_ 指向同一块内存

// 问题1：s1 析构 delete 了内存，s2.data_ 变悬垂指针
// 问题2：s2 析构又 delete 一次 → double free！
```

**深拷贝**：拷贝**指针指向的内容**，各自有独立的内存：

```cpp
class String {
    char* data_;
public:
    // 自定义拷贝构造 = 深拷贝
    String(const String& other) {
        data_ = new char[strlen(other.data_) + 1];
        strcpy(data_, other.data_);
    }
};
```

**一句话**：浅拷贝拷指针，深拷贝拷内容。**类里有指针成员，必须自定义拷贝构造做深拷贝**。

### 三/五/零法则（Rule of Three / Five / Zero）

**三法则**（C++98）：自定义了下面三个之一，通常三个都要自定义：

1. 析构函数
2. 拷贝构造函数
3. 拷贝赋值运算符

**五法则**（C++11 加上移动）：

1. 析构函数
2. 拷贝构造
3. 拷贝赋值
4. 移动构造
5. 移动赋值

**零法则**（现代推荐）：**能不自定义就不自定义**——让编译器自动生成，或用智能指针/容器管理资源，默认的拷贝/移动就是对的：

```cpp
class Good {
    std::string name_;              // 用 std::string 管理，不碰裸指针
    std::vector<int> data_;         // 用容器管理
    // 什么都不写 → 零法则，默认拷贝/移动自动正确
};
```

**记忆**：裸指针时代要三/五法则，现代 C++ 用智能指针/容器 → 零法则。

## 5. SOLID 设计原则

面向对象的设计思想，五个原则的首字母：

| 原则 | 含义 | 一句话 |
|------|------|--------|
| **S** 单一职责 | 一个类只干一件事 | 改一个原因 |
| **O** 开闭原则 | 对扩展开放，对修改关闭 | 加功能不改老代码 |
| **L** 里氏替换 | 子类能替换父类使用 | 子类不破坏父类契约 |
| **I** 接口隔离 | 接口要小而专 | 别塞一堆用不上的方法 |
| **D** 依赖倒置 | 依赖抽象，不依赖具体 | 面向接口编程 |

```cpp
// 开闭原则的例子：
// ❌ 违反：每加一种形状就要改这个函数
double area(Shape* s) {
    if (typeid(*s) == typeid(Circle)) { /* 圆 */ }
    else if (typeid(*s) == typeid(Rect)) { /* 矩形 */ }
    // 加三角形 → 改这里
}

// 符合：加新形状 = 加新类，不改旧代码
class Shape {
public:
    virtual double area() = 0;   // 抽象接口
};
class Circle : public Shape { double area() override { /* ... */ } };
class Rect : public Shape { double area() override { /* ... */ } };
// 加 Triangle → 新建类即可，不碰已有代码
```

**要点**：SOLID 里重点是开闭原则、依赖倒置。

### 里氏替换与对象切片的关联

**里氏替换**：子类必须能替换父类而不破坏程序。**对象切片是违反里氏替换的典型表现**：

```cpp
class Bird { public: virtual void fly() { /* 默认飞 */ } };
class Penguin : public Bird { void fly() override { /* 企鹅不能飞 */ } };

void let_fly(Bird b) { b.fly(); }   // ❌ 按值传参 → 切片！
// Penguin 被切成 Bird，调用的是 Bird::fly（多态失效）→ 违反里氏替换

void let_fly2(Bird& b) { b.fly(); }  // 引用，多态正确
```

**关键**：里氏替换要求"多态正确"，而**对象切片破坏多态**——所以"多态必须用指针/引用"，这也是里氏替换的工程要求。

### 违反 SOLID 的后果

| 违反 | 后果 |
|------|------|
| 单一职责 | 类臃肿，改一处影响多处 |
| 开闭原则 | 每加功能都改老代码，易引入 bug |
| 里氏替换 | 子类行为异常，多态出错 |
| 接口隔离 | 实现类被迫实现用不到的方法 |
| 依赖倒置 | 高层依赖低层细节，难测试、难替换 |

## 6. 面向对象设计陷阱

### 继承滥用（组合优于继承）

```cpp
// ❌ 继承滥用：只为了复用代码而继承
class Stack : public std::vector<int> { /* ... */ };
// 问题：Stack 继承了 vector 所有接口（可以 insert/erase 破坏栈语义）

// 组合：包含一个 vector，只暴露栈接口
class Stack {
    std::vector<int> data_;
public:
    void push(int x) { data_.push_back(x); }
    void pop() { data_.pop_back(); }
    int top() { return data_.back(); }
};
```

**原则**：**"is-a" 用继承，"has-a" 用组合**。继承是强耦合，组合更灵活。

### 纯虚函数的契约意义

纯虚函数不只是"没实现"，更是**接口契约**——派生类必须遵守的约定（前置条件、后置条件、不变量）。基类的文档应说明契约，派生类不能"违约"（否则违反里氏替换）。

### 虚析构的完整影响

```cpp
// 基类有虚函数 → 析构必须 virtual（否则 delete 基类指针漏析构）
// 但代价：加虚析构 = 加 vtable，所有派生类也都有 vptr（内存开销）
// 权衡：会被继承的类，析构加 virtual；不打算继承的类，别加（省开销）
```

### 多继承的正确使用

多继承复杂（菱形、二义性），正确用法：**继承一个"实现类" + 多个"接口类"**（Java 风格）：

```cpp
class Concrete : public Base, public IInterface1, public IInterface2 { /* ... */ };
// 只允许一个"有实现"的基类，其余都是纯接口（纯虚）
```

## 7. 转换构造与 explicit

**单参数构造函数 = 一个隐式转换**：`int` 能悄悄变成 `Meter`。

```cpp
struct Meter {
    int v;
    Meter(int x) : v(x) {}      // 没有 explicit
};
void print(Meter);
print(42);          // 合法：int 隐式转成 Meter
Meter m = 42;       // 合法
```

加 `explicit` 后只能显式构造：

```cpp
struct Meter2 {
    int v;
    explicit Meter2(int x) : v(x) {}
};
print2(42);             // ❌ error: could not convert '42' from 'int' to 'Meter2'
print2(Meter2{42});     // 必须这么写
```

**为什么要 explicit**：隐式转换带来意外——函数重载被"转换后的类型"悄悄选中、`Foo f = 0` 把 0 当数据。**单参构造默认加 explicit**，除非你就是要它隐式（如 `std::string s = "abc";` 这种刻意设计）。

**转换运算符同理**（实测对比）：

```cpp
struct GuardBad { bool ok; operator bool() const { return ok; } };            // 危险
struct GuardGood { bool ok; explicit operator bool() const { return ok; } };

GuardBad gb{true};
int x = gb;            // 竟然合法（bool 悄悄转 int）—— 实测能编过
GuardGood gg{true};
if (gg) { }            // 可以：if/while/! 等上下文转换不受 explicit 影响
int y = gg;            // ❌ error: cannot convert 'GuardGood' to 'int'
```

（C++20 还支持条件 explicit：`explicit(常量表达式) operator bool()`——`std::span` 用它。了解即可。）

## 8. 静态成员（static 成员）

**属于类、不属于对象**——所有对象共享同一份。

**静态成员变量**：类内声明，**类外定义**（少了就是链接错误）：

```cpp
struct Counter {
    static int created;      // 声明
    Counter() { ++created; }
};
int Counter::created = 0;    // 定义 + 初始化，必须有

Counter a, b;                // 实测：Counter::created == a.created == b.created == 2
sizeof(Counter)              // == 1：静态成员不占对象内存
```

**C++17 起**可以类内直接定义（`inline static`），省掉类外那行：

```cpp
struct WithInline {
    inline static int n = 0;
    static int get() { return n; }
};
WithInline::n = 7;           // 实测：WithInline::get() == 7
```

**静态成员函数**：没有 `this` → 不能访问非静态成员，也不能是 `const`。

**用途**：计数器、单例、类级常量（`static constexpr double kPi = 3.14;`）。

**易错**：

- ⚠️ 只有类内声明、忘了类外定义 → **链接错误**（`undefined reference to Counter::created`），不是编译错误，报错位置看着很迷惑
- ⚠️ 静态成员函数里写 `this` 或直接写成员名 → 编译错误

## 9. 运算符重载

给自定义类型定义运算符行为（`+`、`==`、`<`、`<<`、`[]`……）。

**三条硬规则**：

- 至少一个操作数是自定义类型（不能重载 `int + int`）
- 不能发明新运算符、不能改优先级/结合性
- 不能重载：`::`、`.`、`.*`、`?:`、`sizeof`

**成员还是非成员**：

| 运算符 | 写法 | 理由 |
|---|---|---|
| `=` `[]` `()` `->` | **必须成员** | 语言规定 |
| `+` `-` `*` `==` `<` | 都行；想支持"左边也隐式转换"就用非成员 | `1 + v` 这种成员版不支持 |
| `<<` `>>`（流） | **非成员** | 左边是 `ostream`，不是你的类 |

**返回什么**：算术返回**值**（返回引用会悬垂——返回的是函数内临时对象）；`operator<<` 返回 `ostream&`（支持链式）；比较返回 `bool`。

**C++20 大礼包**：`==` 和 `<=>` 可以 `= default`，让编译器生成全套比较：

```cpp
struct Vec2 {
    double x, y;
    Vec2 operator+(const Vec2& o) const { return {x + o.x, y + o.y}; }
    bool operator==(const Vec2&) const = default;               // 生成 ==
};
std::ostream& operator<<(std::ostream& os, const Vec2& v) {     // 非成员
    return os << "(" << v.x << ", " << v.y << ")";
}
// 实测：a + b = (4, 6)   a == a: 1   a == b: 0

struct Ver {
    int major, minor;
    auto operator<=>(const Ver&) const = default;   // 一次生成 < > <= >=
};
// 实测：Ver{1,2} < Ver{1,3} 为 1
```

**易错**：

- ⚠️ `operator+` 返回引用 → 悬垂引用（引用的对象出函数就没了）
- ⚠️ 重载 `&&` / `||` 会**失去短路求值**——别重载
- ⚠️ `operator&`（取地址）重载会坑所有人——别重载
- `operator<<` 要访问 private 成员：用公有 getter，或声明 `friend`

## 10. 要点回顾

1. **三大特性**：封装、继承、多态，各一句话说清
2. **虚函数表（vtable）原理**：对象存 vptr → vtable → 实际函数
3. **虚析构函数**：基类析构必须 virtual，否则 delete 基类指针漏析构
4. **纯虚函数**：`= 0`，抽象类不能实例化
5. **构造/析构里调虚函数**：调的是当前类版本
6. **浅拷贝 vs 深拷贝**：浅拷指针、深拷内容，指针成员必须深拷贝
7. **三/五/零法则**：现代 C++ 用智能指针实现零法则
8. **对象切片**：多态传值会切片，要用指针/引用（也是里氏替换的要求）
9. **菱形继承**：多继承的两份祖先问题，虚继承解决
10. **SOLID**：尤其开闭原则（加功能不改老代码）、依赖倒置（面向接口）
11. **组合优于继承**：is-a 用继承，has-a 用组合
12. **override vs 重载**：override 是重写（虚函数），重载是参数不同的同名函数
13. **访问级别与友元**：`protected` 只对派生类开放；友元单向、不继承、不可传递，是"给封装开的口子"，能不用就不用
14. **explicit**：单参构造默认加，防隐式转换；`operator bool` 也要 explicit（否则能悄悄转成 int）；if/while 里的上下文转换不受影响
15. **静态成员**：类内声明 + 类外定义（C++17 可用 `inline static`）；共享一份、不占对象内存、静态函数没有 `this`
16. **运算符重载**：不能发明运算符；`=`/`[]`/`()`/`->` 必须成员，流运算符必须非成员；算术返回值不返引用；`==`/`<=>` 可以 `= default`
