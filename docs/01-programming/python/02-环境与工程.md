# 环境与工程

从"能跑"到"能维护"：环境隔离、依赖管理、项目结构、类型检查、测试——语言语法见[基础语法](01-基础语法.md)。

## 1. 虚拟环境

**问题**：系统 Python 是所有系统工具共用的，直接 `pip install` 装进去，可能**弄坏系统的包**（现代发行版会直接报错 `externally-managed-environment`）。

**解决**：每个项目一个独立环境。

```bash
# 标准做法：venv（Python 自带）
python3 -m venv .venv
source .venv/bin/activate      # Linux/macOS；Windows 用 .venv\Scripts\activate
pip install numpy
deactivate                     # 退出

# 也可以不激活，直接用绝对路径
./.venv/bin/python main.py
```

**三种环境工具怎么选**：

| 工具 | 特点 | 什么时候用 |
|------|------|-----------|
| **venv** | 自带、标准 | 普通项目 |
| **conda** | 能装**非 Python 依赖**（CUDA 库、MKL 等） | 科学计算/深度学习环境 |
| **uv** | Rust 写的，极快，兼容 pip/venv | 新项目/CI |

## 2. 依赖管理

```bash
pip install numpy pandas            # 安装
pip freeze > requirements.txt       # 导出当前环境的精确版本
pip install -r requirements.txt     # 按文件还原
```

**国内镜像**（下载慢时）：

```bash
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

**现代标准：`pyproject.toml`**（替代老的 `setup.py`）：

```toml
[project]
name = "myapp"
version = "0.1.0"
requires-python = ">=3.10"
dependencies = [
    "numpy>=1.26",
    "requests",
]

[project.optional-dependencies]
dev = ["pytest", "mypy", "ruff"]

[build-system]
requires = ["setuptools>=61"]
build-backend = "setuptools.build_meta"
```

| 文件 | 定位 |
|------|------|
| `requirements.txt` | **精确锁定**（`pip freeze` 的产物），适合部署还原 |
| `pyproject.toml` | 项目**声明**（依赖范围、工具配置），现代项目的入口 |
| `setup.py` | 老式构建脚本，新项目不用写 |

**本地安装与打包**：

```bash
pip install -e .          # editable 安装：改代码即时生效，不用重装
python -m build           # 打包：dist/ 下生成 wheel 和 sdist（先 pip install build）
```

`src/` 布局的项目，不装就没法在项目外 `import` 自己的包——开发时用 `-e`。

## 3. uv（venv + pip 的现代替代）

把 **venv + pip + pip-tools + pipx + pyenv** 合成一台工具（快一个数量级）；兼容 pip 老习惯，也有更省事的项目模式。

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh    # 安装
```

**模式一：兼容老习惯**（命令基本只是加 `uv` 前缀）：

```bash
uv venv ~/.venvs/foo                 # ≈ python -m venv
source ~/.venvs/foo/bin/activate     # 激活后 uv 自动认这个环境
uv pip install torch                 # ≈ pip install（参数同款，含 --index-url）
uv pip install -r requirements.txt
uv pip install --python ~/.venvs/foo/bin/python torch   # 不激活也行
```

**模式二：项目模式**（新项目推荐）：

```bash
uv init myproj && cd myproj
uv add requests torch                # 写进 pyproject.toml，生成 uv.lock
uv run python demo.py                # 不用手动激活（自动用项目 .venv）
uv sync                              # 按 uv.lock 还原环境
```

- `uv.lock`：精确锁（版本 + 来源 + 哈希），**进 git**——比 `pip freeze` 强；CI/部署用 `uv sync --frozen` 按锁装
- `uv python install 3.12` 装/管 Python 本身（替代 pyenv）；`uvx ruff check .` 不安装直接跑（替代 pipx）
- `uv run --with requests script.py`：临时带依赖跑单个脚本，不建项目也不装环境

**镜像 / CUDA 源**（同 pip 思路）：

```bash
uv pip install numpy --index-url https://pypi.tuna.tsinghua.edu.cn/simple
uv pip install torch --index-url https://download.pytorch.org/whl/cu130
```

**注意**：uv **不读** `pip.conf` / `PIP_INDEX_URL`（pip 的镜像配置对它无效）——镜像要单独配：`--index-url`、`UV_INDEX_URL`，或写进 `uv.toml`。

**存量不用迁移**：已有的 venv（如 `~/.venvs/vllm`）继续用——uv 一样能往里装包；新环境从 uv 起。

## 4. 项目结构

```text
myproject/
├── pyproject.toml
├── README.md
├── src/
│   └── myapp/
│       ├── __init__.py       # 有它才是"包"
│       ├── main.py
│       └── utils.py
└── tests/
    └── test_utils.py
```

**关键概念**：

- **模块** = 一个 `.py` 文件；**包** = 带 `__init__.py` 的目录
- **入口文件**加：

```python
def main():
    ...

if __name__ == "__main__":     # 只有直接运行时才执行（被 import 时不执行）
    main()
```

- **导入**：

```python
import numpy as np                  # 绝对导入
from pathlib import Path            # 从模块里拿具体对象
from .utils import helper           # 相对导入（只在包内部用）
```

**坑**：**别把文件命名成标准库的名字**（`random.py`、`types.py`、`json.py`）——会把自己导入进去，出诡异错误。

## 5. 类型注解 + mypy

动态类型没编译期检查，注解 + `mypy` 就是补这条腿（**运行时不影响**，只是给工具看）：

```python
def add(a: int, b: int) -> int:
    return a + b

names: list[str] = []
scores: dict[str, float] = {}
maybe: int | None = None          # 3.10+ 写法，等价 Optional[int]

def find(items: list[str], key: str) -> str | None:
    ...
```

更复杂的类型：

```python
from typing import Callable, TypedDict

class User(TypedDict):              # 字典的"结构体"（解析 JSON、**kwargs 场景）
    name: str
    age: int

Handler = Callable[[int], str]      # 函数类型
```

mypy 配置（`pyproject.toml`）：

```toml
[tool.mypy]
strict = true                       # 新项目建议开
```

```bash
pip install mypy
mypy src/          # 静态检查类型
```

**收益**：IDE 补全/跳转准、重构敢动、提前发现 `None` 相关的错。

## 6. 测试与代码质量

**pytest**（测试）：

```python
# tests/test_math.py
from myapp.math import add

def test_add():
    assert add(1, 2) == 3

def test_add_negative():
    assert add(-1, 1) == 0
```

```bash
pip install pytest
pytest                 # 自动找 test_*.py 里的 test_* 函数
```

**fixture 与参数化**：

```python
import pytest

@pytest.fixture
def sample_cfg(tmp_path):          # 每个用到它的测试都拿到新副本
    p = tmp_path / "cfg.json"      # tmp_path 是内置 fixture，测试后自动清理
    p.write_text("{}")
    return p

@pytest.mark.parametrize("n,expected", [(1, 1), (2, 4), (3, 9)])
def test_square(n, expected):
    assert n * n == expected
```

**ruff**（检查 + 格式化，替代 flake8/isort/black，极快）：

```bash
ruff check . --fix     # 检查并自动修
ruff format .          # 格式化
```

## 7. 调试与性能定位

**调试**：代码里插一个 `breakpoint()`（3.7+）就进入调试器：

```python
def buggy(data):
    breakpoint()       # 停在这里
    return process(data)
```

| pdb 命令 | 作用 |
|---------|------|
| `n` | 下一行（不进入函数） |
| `s` | 进入函数 |
| `c` | 继续到下一个断点 |
| `p expr` | 打印表达式 |
| `l` | 看当前代码 |
| `bt` | 调用栈 |
| `q` | 退出 |

**日志**（比 `print` 强在能分级、能关）：

```python
import logging

logging.basicConfig(level=logging.INFO, format="%(asctime)s %(levelname)s %(message)s")
logger = logging.getLogger(__name__)
logger.info("start")
```

**找性能瓶颈**：和 C++ 一样，先测再优化。

```bash
python -m cProfile -s cumtime script.py    # 各函数累计耗时
pip install py-spy
py-spy top -- python script.py             # 像 top 一样看运行中的 Python
```

## 8. 要点回顾

1. **每个项目一个虚拟环境**（venv 够用；科学计算用 conda；**新项目用 uv**——venv + pip 一体，快一个数量级）
2. **依赖**：`requirements.txt` 锁精确版本，`pyproject.toml` 是项目声明（`setup.py` 过时）
3. **模块/包**：`.py` 文件 + `__init__.py` 目录；入口用 `if __name__ == "__main__"`
4. **别用标准库名当文件名**
5. **类型注解 + mypy** 补动态类型的短板（注解不改变运行时）
6. **pytest 测、ruff 管风格、cProfile / py-spy 找瓶颈**
7. `breakpoint()` 进调试器；日志用 `logging` 而不是 `print`
