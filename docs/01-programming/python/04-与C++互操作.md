# 与 C++ 互操作

**Python 写胶水（灵活）+ C++ 干重活（快）**——这是 AI 部署里的标准结构。这篇讲怎么把 C++ 包成 Python 能调的模块。

## 1. 为什么要互操作

- Python 调不动的地方：大量小循环、对延迟敏感的推理内核、已有的 C++ 库
- 但生产不会用 Python 重写一切：**实验用 Python，内核用 C++**

**典型分层**：

```text
Python 层：配置、调度、数据处理（pandas 等）
    ↓ 调用
C++ 层：计算内核、推理引擎、高性能算子
```

## 2. 四种方式对比

| 方式 | 写法 | 优点 | 缺点 |
|------|------|------|------|
| **ctypes** | Python 里写声明 | 零依赖、不重编译 | 只认 **C ABI**；数组/异常/复杂类型难搞 |
| **pybind11** | C++ 侧写绑定 | 现代、自动类型转换、支持 STL/NumPy | 要编译，引入头文件依赖 |
| **Cython** | `.pyx` 方言 | 接近 Python、可渐进加速 | 多一套语法 |
| 手写 C 扩展 | CPython C API | 最可控 | 引用计数易错、繁琐 |

**推荐**：C++ 项目用 **pybind11**（PyTorch 自己的 C++ 扩展也用它）。

## 3. pybind11 最小例子

**C++ 侧**（`example.cpp`）：

```cpp
#include <pybind11/pybind11.h>
#include <pybind11/stl.h>        // std::vector 自动转 list

namespace py = pybind11;

int add(int a, int b) {
    return a + b;
}

PYBIND11_MODULE(example, m) {         // 模块名必须和编译产物同名
    m.doc() = "pybind11 demo";
    m.def("add", &add, "add two ints");
}
```

**编译**（官方一行命令）：

```bash
pip install pybind11
c++ -O3 -Wall -shared -std=c++11 -fPIC \
    $(python3 -m pybind11 --includes) \
    example.cpp -o example$(python3-config --extension-suffix)
```

**环境要求**：编译需要 Python 开发头文件（Ubuntu 上 `sudo apt install python3-dev`）；`python3-config` 来自系统 Python，venv 里没有，用系统那份即可。

**标准可改**：`-std=c++11` 只是最低要求——`c++17` / `c++20` / `c++23` 都能编（pybind11 自身检测到 C++20 为止，更高标准照常工作）；**和主项目用同一个标准**（CMake 里跟随 `CMAKE_CXX_STANDARD` 即可）。

**Python 侧**：

```python
import example
print(example.add(1, 2))     # 3
```

**CMake 方式**（工程里更常见）：

```cmake
find_package(pybind11 REQUIRED)
pybind11_add_module(example example.cpp)
```

## 4. 绑 C++ 类（py::class_）

函数之外，最常用的是把类暴露给 Python：

```cpp
class Counter {
public:
    explicit Counter(int start) : n_(start) {}
    void add(int d) { n_ += d; }
    int value() const { return n_; }

private:
    int n_;
};

PYBIND11_MODULE(example, m) {
    py::class_<Counter>(m, "Counter")
        .def(py::init<int>(), py::arg("start") = 0)      // 构造器 + 默认参数
        .def("add", &Counter::add, py::arg("d") = 1)     // 成员函数
        .def("value", &Counter::value)
        .def_property_readonly("n", &Counter::value)     // 只读属性（可写用 def_property）
        .def("__repr__", [](const Counter& c) {          // 魔术方法也能绑
            return "<Counter " + std::to_string(c.value()) + ">";
        });
}
```

```python
c = example.Counter(10)
c.add(5)
print(c.value(), c.n, repr(c))    # 15 15 <Counter 15>
print(example.Counter().value())  # 0（默认参数生效）
```

**常用搭配**：

| 需求 | 写法 |
|------|------|
| 默认参数 | `py::arg("x") = 1` |
| 只读 / 可读写属性 | `def_property_readonly` / `def_property` |
| 返回引用（对象必须活着） | `py::return_value_policy::reference` 或 `py::keep_alive<1, 2>()` |
| 用 `shared_ptr` 管理 | `py::class_<T, std::shared_ptr<T>>(m, "T")` |
| 继承关系 | `py::class_<Derived, Base>(m, "Derived")` |

**关键坑：生命周期**。C++ 对象被 Python 持有后，谁负责销毁、返回的引用会不会悬垂——由返回策略决定；拿不准就用值语义（返回值拷贝）或智能指针。

## 5. 传 NumPy 数组（零拷贝）

`py::array_t<double>` 拿到的**指针直接指向原数组**——不复制：

```cpp
#include <pybind11/numpy.h>

double mean(py::array_t<double> arr) {
    auto buf = arr.request();              // 拿到缓冲区信息
    auto* ptr = static_cast<double*>(buf.ptr);
    double sum = 0.0;
    for (py::ssize_t i = 0; i < buf.size; ++i) {   // 用 py::ssize_t，避免 size_t 比 ssize_t 的类型警告
        sum += ptr[i];
    }
    return buf.size ? sum / buf.size : 0.0;
}
```

```python
import numpy as np
example.mean(np.array([1.0, 2.0, 3.0]))    # 2.0
```

（别忘了在 `PYBIND11_MODULE` 里加 `m.def("mean", &mean);`。）

**注意**：上面假设一维且连续。工程里要检查 `buf.ndim` / `buf.strides`；或 `arr.checked<1>()`（每次访问都查维度 + 越界）/ `arr.unchecked<1>()`（创建时校验一次维度，之后不查越界，更快）。

**返回数组**：

```cpp
py::array_t<double> ramp(size_t n) {
    py::array_t<double> out(n);            // 分配新数组
    auto r = out.mutable_unchecked<1>();
    for (size_t i = 0; i < n; ++i) {
        r(i) = static_cast<double>(i);
    }
    return out;
}
```

## 6. 释放 GIL

Python 调 C++ 时，**GIL 默认一直拿着**——别的线程全被堵住。

长计算的函数要主动释放：

```cpp
long long heavy(int n) {
    py::gil_scoped_release release;        // 这之后不碰 Python 对象
    long long s = 0;
    for (int i = 0; i < n; ++i) {
        s += i;
    }
    return s;                              // 作用域结束自动重新拿 GIL
}
```

**规则**：释放期间**不能碰任何 Python 对象**（不能调 Python、不能用 list/dict）；纯 C++ 计算和 NumPy 裸指针是安全的。

**收益**：多线程可以真正并行跑 C++ 计算（而不是排队等 GIL）。

**异常也会跨语言传递**：C++ 抛出的异常，pybind11 默认转成 Python 的 `RuntimeError`（消息带 `what()`）；要映射成具体类型：

```cpp
py::register_exception<MyError>(m, "MyError");   // C++ 的 MyError → Python 的 example.MyError
```

## 7. 什么时候值得

**先 profile，再决定**（`cProfile` / `py-spy`，见[环境与工程](02-环境与工程.md)）：

| 情况 | 判断 |
|------|------|
| 瓶颈是大量 Python 小循环 | ✅ 值得搬 C++ |
| 瓶颈已经是向量化的 NumPy | ❌ 不值得（NumPy 本身就是 C） |
| 已有成熟的 C++ 库想复用 | ✅ 包出来 |
| 只是"感觉 Python 慢" | ❌ 先测，别猜 |

**另外**：跨界调用本身有开销（参数转换）——**别在 Python 循环里调 C++ 小函数**，要**批量传数组**，一次调用干完。

## 8. 要点回顾

1. **结构**：Python 胶水 + C++ 内核，是部署的标准分层
2. **选型**：C++ 用 **pybind11**；纯 C 接口用 ctypes；渐进加速用 Cython
3. **pybind11 三件套**：`PYBIND11_MODULE` 定义模块、`m.def` 导出函数、编译成 `.so`（后缀由 `python3-config --extension-suffix` 给出）
4. **NumPy 数组零拷贝**：`py::array_t<T>` + `request()` / `unchecked<>()`；注意检查维度和连续性
5. **释放 GIL**：`py::gil_scoped_release`，期间不碰 Python 对象 → 多线程真并行
6. **绑类用 `py::class_`**：构造器 `py::init`、属性 `def_property(_readonly)`、`__repr__` 也能绑；返回引用时注意生命周期（`keep_alive` / `return_value_policy`）
7. **批量传参**，别在循环里跨界调用
8. **先 profile 再动手**——NumPy 已覆盖的场景不用搬 C++
