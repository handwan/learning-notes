# 所有权与借用

C++ 里靠人小心避免的悬垂指针、double free、数据竞争，Rust 用**编译期检查**拦掉——代价是要过借用检查器（borrow checker）这一关。这篇讲它到底在检查什么。

## 1. 和 C++ 的定位差别

|                 | C++                          | Rust                                                                                |
|-----------------|------------------------------|-------------------------------------------------------------------------------------|
| 内存管理        | 手动 / RAII                  | 所有权 + 作用域自动释放（同样是 RAII，但**编译器强制**）                            |
| 悬垂 / 重复释放 | UB（运行时才可能炸）         | **编译错误**                                                                        |
| 数据竞争        | UB                           | safe 代码里**编译错误**                                                             |
| 空指针          | `nullptr` 满天飞             | 没有 null（用 `Option`，见[类型系统](03-类型系统.md)） |
| 移动后使用      | 合法但危险（"有效但未指定"） | **编译错误**                                                                        |

一句话：**Rust 把"要小心"变成了"编译器不让你不小心"**。

## 2. 所有权三条规则

```rust
① 每个值有且只有一个所有者（owner）
② 同一时刻只能有一个所有者
③ 所有者离开作用域，值被 drop（自动释放）
```

```rust
fn main() {
    let s = String::from("hello");   // s 拥有这个 String
    println!("{}", s);               // 借用 s 来打印
}                                    // 作用域结束 → drop(s)
```

第 ③ 条就是 RAII——和 C++ 的作用域释放一样。

## 3. 移动（move）：赋值默认就是移动

```rust
let a = String::from("hi");
let b = a;              // 所有权从 a 移到 b
// println!("{}", a);   // ❌ 编译错误：borrow of moved value: `a`
println!("{}", b);      //
```

**和 C++ `std::move` 的关键差别**：

- C++：`b = std::move(a)` 之后 `a` 是"有效但未指定"状态，**用它不报错**（危险）
- Rust：`a` 直接**不可用**（编译期报错）

### Copy 类型：赋值 = 拷贝，原变量还能用

```rust
let x = 5;
let y = x;                 // i32 是 Copy：直接拷贝
println!("{} {}", x, y);   // 都还能用
```

| 类别                      | 类型                                                                     |
|---------------------------|--------------------------------------------------------------------------|
| **Copy**（赋值即拷贝）    | 所有整数/浮点、`bool`、`char`、只含 Copy 字段的元组和数组、共享引用 `&T` |
| **非 Copy**（赋值即移动） | `String`、`Vec<T>`、`Box<T>` 等**拥有堆内存**的类型                      |

需要"用完还想留一份"的非 Copy 类型，显式 `clone()`（对应 C++ 的拷贝构造）。

## 4. 借用（borrow）与别名规则

**借用 = 引用**：不拿走所有权，只是"看看"。

```rust
fn len(s: &str) -> usize {
    s.len()
}

fn main() {
    let s = String::from("hello");
    let n = len(&s);           // 借出去（&String 自动转 &str）
    println!("{} {}", s, n);   // s 还在
}
```

**要改就借可变的**：

```rust
fn add_world(s: &mut String) {
    s.push_str(" world");
}

fn main() {
    let mut s = String::from("hello");
    add_world(&mut s);
    println!("{}", s);         // hello world
}
```

### 核心规则：要么多个读，要么一个写

```rust
&T    （不可变借用）：可以同时存在多个
&mut T（可变借用）：同一时刻只能有一个，且不能和 &T 共存
```

这条规则正是 C++ 里"别名导致的 UB/数据竞争"的判定条件——Rust 让编译器在编译期执行它：

```rust
let mut v = vec![1, 2, 3];

let first = &v[0];       // 不可变借用
v.push(4);               // ❌ 编译错误：v 正被不可变借用，push 需要 &mut
println!("{}", first);
```

**解法**：先把要用的值取出来（Copy），再改：

```rust
let mut v = vec![1, 2, 3];
let first = v[0];        // i32 是 Copy：拷一份出来
v.push(4);               // 没有活着的借用了
println!("{}", first);
```

**理解**：借用检查器不是"不让你写"，而是逼你想清楚"这个引用还在不在用"。

### NLL：借用用到哪，就到哪结束

借用检查器按"**最后一次使用**"结束借用（非词法生命周期，NLL）——不用等到作用域结束：

```rust
let mut v = vec![1, 2, 3];
let first = &v[0];
println!("{}", first);   // 借用在这里用完
v.push(4);               // 之后就不冲突了
```

## 5. 生命周期标注

**大多数时候不用写**——编译器自己推。只有"返回值引用谁"说不清时，才需要标：

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

读法：**返回的引用不会活得比 x、y 更久**（取两者中短的那个）。

**省略规则（elision）**：

- 只有一个输入引用时，输出的生命周期直接取它
- 有多个输入引用、又没有 `self` 时，输出引用必须手写生命周期
- 方法带 `&self` / `&mut self` 时，输出引用默认绑定到 `self`

```rust
fn first_word(s: &str) -> &str {
    // 等价于 fn first_word<'a>(s: &'a str) -> &'a str
    match s.find(' ') {
        Some(i) => &s[..i],
        None => s,
    }
}
```

**结构体里存引用必须标**：

```rust
struct Holder<'a> {
    text: &'a str,
}
```

**`'static`**：活得和程序一样久。字符串字面量就是 `&'static str`：

```rust
let s: &'static str = "hello";
```

## 6. 常见报错与解法

| 想干的事                         | 编译错误                                                                                          | 解法                                        |
|----------------------------------|---------------------------------------------------------------------------------------------------|---------------------------------------------|
| 返回局部变量的引用               | `missing lifetime specifier`（无参数时）/ `cannot return reference to local variable`（有参数时） | 返回**所有权**（`String` 而不是 `&String`） |
| 结构体存自己字段的引用（自引用） | 生命周期说不清                                                                                    | 用索引 / `Rc`（一般绕开）                   |
| 持有 `&v[i]` 时 `v.push`         | `cannot borrow v as mutable`                                                                      | 先取值（Copy）或先算好 `len`，再改          |
| 写双向链表 / 图                  | 借用规则过不去                                                                                    | `Rc<RefCell>`、索引下标、专门的库           |

**先别硬写链表**：教科书数据结构（链表、图）恰好是借用检查器最不友好的地方——不是 Rust 不适合你，是**数据结构和所有权模型要匹配**。

## 7. String vs &str

|            | `String`           | `&str`                    |
|------------|--------------------|---------------------------|
| 拥有内存   | ✅（堆上，可增长） | ❌（借来看）              |
| C++ 类比   | `std::string`      | `std::string_view`        |
| 什么时候用 | 需要拥有或修改     | **函数参数优先用 `&str`** |

```rust
fn greet(name: &str) -> String {
    format!("hello, {}", name)
}

fn main() {
    let a = String::from("Tom");
    println!("{}", greet(&a));       // String → &str
    println!("{}", greet("Jerry"));  // 字面量本来就是 &str
}
```

## 8. 要点回顾

1.  **所有权**：一个值一个所有者，作用域结束自动 drop（编译器强制的 RAII）
2.  **赋值默认是移动**：移动后原变量不可用（C++ 是"有效但未指定"，Rust 直接编译错）
3.  **Copy 类型**（整数/浮点/bool/char/引用/纯 Copy 组合）赋值是拷贝
4.  **借用规则**：多个 `&T` 或一个 `&mut T`，不能共存——编译期消灭别名 UB 和数据竞争
5.  **NLL**：借用"最后一次使用"后即结束
6.  **生命周期标注**只在"返回的引用来自哪个参数"说不清时才需要；单个输入引用可省略
7.  **`String` 拥有、`&str` 借用**（≈ `std::string` vs `string_view`）
8.  报错是**让你把所有权想清楚**，不是刁难；链表/图要换建模方式
