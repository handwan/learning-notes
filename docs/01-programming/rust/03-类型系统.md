# 类型系统

Rust 类型系统的三件套：**enum 表达状态**、**Option/Result 干掉 null 和异常**、**trait 替代继承**。

## 1. 表达式语言

Rust 的 `if`、`match`、块都是表达式，最后一行不带分号就是值；语法细节见[基础语法](01-基础语法.md)。从类型角度看，每个表达式都有类型，`if` 的两个分支、`match` 的所有分支都必须得到兼容的类型。

函数返回值同理——最后一个表达式就是返回值，`return` 只用于提前返回。

## 2. enum：每个变体可以带数据

C++ 的 `enum` 只是"给整数起名"；Rust 的 `enum` 是**代数数据类型**：

```rust
enum Shape {
    Circle(f64),              // 带一个 f64
    Rect { w: f64, h: f64 },  // 带命名字段
    Empty,                    // 不带数据
}
```

≈ C++17 的 `std::variant` + 手动 tag——但 Rust 是语言原生支持。

### match：穷尽性检查

```rust
fn area(s: &Shape) -> f64 {
    match s {
        Shape::Circle(r) => 3.14159 * r * r,
        Shape::Rect { w, h } => w * h,
        Shape::Empty => 0.0,
    }
}
```

**少一个分支就编译不过**——这是 enum 的杀手锏：新增状态时，所有需要处理它的地方都会在编译期暴露。

**match 的常用形式**：

```rust
match n {
    0 => "zero",
    1 | 2 => "small",          // 多个值
    x if x < 10 => "middle",   // 匹配守卫
    10..=99 => "big",          // 范围
    _ => "huge",               // 兜底
}
```

**解构**：match 的同时把里面的值取出来（`Shape::Circle(r)` 里的 `r` 就是绑定）。

### if let / while let / let else

只关心一个分支时不用写全：

```rust
if let Some(x) = maybe {
    println!("{}", x);
}

while let Some(x) = stack.pop() {
    println!("{}", x);
}

let Some(x) = maybe else {
    return;                 // 不匹配就走这里（提前退出）
};
println!("{}", x);
```

## 3. Option：没有 null

```rust
enum Option<T> {
    Some(T),
    None,
}
```

"可能没有"必须写进类型，编译器强制你处理：

```rust
fn find(v: &[i32], target: i32) -> Option<usize> {
    for (i, &x) in v.iter().enumerate() {
        if x == target {
            return Some(i);
        }
    }
    None
}

fn main() {
    let v = [10, 20, 30];

    match find(&v, 20) {
        Some(i) => println!("下标 {}", i),
        None => println!("没有"),
    }

    if let Some(i) = find(&v, 30) {
        println!("{}", i);
    }
}
```

这就是"十亿美元错误"（null）的正解：**忘了处理 None 就编译不过**。

## 4. Result 与 ?：错误处理

Rust **没有异常**（`panic!` 只用于 bug 级终止，不是常规错误处理）。可恢复错误用 `Result`：

```rust
enum Result<T, E> {
    Ok(T),
    Err(E),
}
```

`?` 运算符：成功就取值，失败就**提前返回错误**（顺带做类型转换）：

```rust
use std::fs;

fn read_number(path: &str) -> Result<i32, Box<dyn std::error::Error>> {
    let text = fs::read_to_string(path)?;   // 失败：io::Error → 提前 return
    let n: i32 = text.trim().parse()?;      // 失败：ParseIntError → 提前 return
    Ok(n)                                   // 成功：返回 Ok(值)
}

fn main() {
    match read_number("num.txt") {
        Ok(n) => println!("读到 {}", n),
        Err(e) => eprintln!("出错: {}", e),
    }
}
```

`?` 也能用在 `Option` 上：遇到 `None` 就提前返回 `None`。

```rust
fn first(v: &[i32]) -> Option<i32> {
    let x = v.first()?;     // None → 整个函数返回 None
    Some(*x)
}
```

**和 C++ 异常对比**：

|              | C++ 异常             | Rust `Result`                        |
|--------------|----------------------|--------------------------------------|
| 是否强制处理 | 否（可以不管）       | **是**（返回类型里写明，`must_use`） |
| 错误类型     | 任意类型，运行时展开 | 值，编译期可见                       |
| 正常路径开销 | 近零                 | 就是返回一个值                       |

**`unwrap()` / `expect()`**：错了就 panic——写原型/测试可以，**生产代码别随手 unwrap**（用 `?`、`match` 或 `unwrap_or` 系列）。

### 自定义错误类型

`Box<dyn Error>` 适合小工具；项目里通常自定义错误，让调用方能**按类型处理**：

```rust
use std::fmt;

#[derive(Debug)]
enum LoadError {
    Io(std::io::Error),
    BadFormat(String),
}

impl fmt::Display for LoadError {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            LoadError::Io(e) => write!(f, "IO 错误: {e}"),
            LoadError::BadFormat(msg) => write!(f, "格式错误: {msg}"),
        }
    }
}

impl std::error::Error for LoadError {}

impl From<std::io::Error> for LoadError {      // 让 ? 自动转换
    fn from(e: std::io::Error) -> Self {
        LoadError::Io(e)
    }
}
```

手写这些很啰嗦，生态里两个 crate 分工明确：

| crate           | 用在哪            | 做什么                                    |
|-----------------|-------------------|-------------------------------------------|
| **`thiserror`** | **库**            | derive 自动生成 `Display` 和 `From`       |
| **`anyhow`**    | **应用 / 二进制** | 一个 `anyhow::Error` 装所有错误，带上下文 |

```rust
// 库：thiserror —— 保留错误类型
use thiserror::Error;

#[derive(Error, Debug)]
pub enum LoadError {
    #[error("IO 错误: {0}")]
    Io(#[from] std::io::Error),
    #[error("格式错误: {0}")]
    BadFormat(String),
}
```

```rust
// 应用：anyhow —— 不关心类型，只要消息和错误链
use anyhow::{Context, Result};

fn run(path: &str) -> Result<()> {
    let text = std::fs::read_to_string(path).context("读配置失败")?;
    println!("{text}");
    Ok(())
}
```

**选择**：库用 `thiserror`（错误类型是 API 的一部分）；应用用 `anyhow`（方便、能加链式上下文）。

## 5. trait：接口与约束

```rust
trait Animal {
    fn name(&self) -> &str;          // 必须实现
    fn speak(&self) -> String {      // 默认实现（可覆写）
        format!("{} makes a sound", self.name())
    }
}

struct Dog;

impl Animal for Dog {
    fn name(&self) -> &str { "dog" }
}

fn main() {
    let d = Dog;
    println!("{}", d.speak());   // dog makes a sound
}
```

### 静态分发 vs 动态分发

```rust
// 静态分发：单态化（monomorphization），每个具体类型生成一份代码
fn print_static<T: Animal>(a: &T) { println!("{}", a.speak()); }
fn print_impl(a: &impl Animal) { println!("{}", a.speak()); }   // 等价写法

// 动态分发：虚表（≈ C++ 虚函数）
fn print_dyn(a: &dyn Animal) { println!("{}", a.speak()); }
```

|          | `<T: Trait>` / `impl Trait` | `dyn Trait`              |
|----------|-----------------------------|--------------------------|
| 分发时机 | 编译期（单态化）            | 运行时（vtable）         |
| 能否内联 | ✅                          | ❌ 一般不行              |
| 代码大小 | 膨胀（每类型一份）          | 一份                     |
| 异质集合 | ❌                          | ✅ `Vec<Box<dyn Trait>>` |

**C++ 对照**：模板 ≈ 单态化泛型；虚函数 ≈ `dyn Trait`。Rust **默认选静态分发**（更快），要"一个容器装不同类型"时才用 `dyn`。

### 常用标准 trait

| trait                      | 作用                  | C++ 对应           |
|----------------------------|-----------------------|--------------------|
| `Clone` / `Copy`           | 显式复制 / 按位复制   | 拷贝构造           |
| `Debug` / `Display`        | `{:?}` / `{}` 格式化  | `operator<<`       |
| `PartialEq` / `Eq` / `Ord` | 相等 / 全序（可排序） | `operator==` / `<` |
| `Hash`                     | 可作哈希键            | `std::hash`        |
| `Default`                  | `T::default()`        | 默认构造           |
| `Drop`                     | 析构                  | 析构函数           |
| `From` / `Into`            | 类型转换              | 转换构造           |
| `Iterator`                 | `for` 的底层协议      | 迭代器             |

**`#[derive(...)]` 自动生成实现**：

```rust
#[derive(Debug, Clone, PartialEq)]
struct Point { x: f64, y: f64 }
```

**运算符重载 = 实现 trait**：

```rust
use std::ops::Add;

#[derive(Debug, Clone, Copy)]
struct Point { x: f64, y: f64 }

impl Add for Point {
    type Output = Point;
    fn add(self, other: Point) -> Point {
        Point { x: self.x + other.x, y: self.y + other.y }
    }
}

fn main() {
    let p = Point { x: 1.0, y: 2.0 } + Point { x: 3.0, y: 4.0 };
    println!("{:?}", p);      // Point { x: 4.0, y: 6.0 }
}
```

**孤儿规则**：trait 和类型**至少有一个**是本 crate 的——防止不同库给同一类型实现同一 trait 造成冲突。

## 6. 泛型 + trait bound

```rust
fn largest<T: PartialOrd + Copy>(list: &[T]) -> T {
    let mut max = list[0];
    for &x in &list[1..] {
        if x > max {
            max = x;
        }
    }
    max
}
```

这个写法假定切片非空；空切片会 panic，实际代码要先处理空输入。

**bound 就是"类型必须满足的接口"**（≈ C++20 concepts）。约束多了可以换行：

```rust
fn largest<T>(list: &[T]) -> T
where
    T: PartialOrd + Copy,
{
    ...
}
```

## 7. 要点回顾

1.  **if / match / 块都是表达式**，最后一行不加分号就是值
2.  **enum 变体可带数据 + match 穷尽检查**——加新状态时，编译器帮你找全所有分支
3.  **`Option<T>` 取代 null**；**`Result<T, E>` + `?` 取代异常**（错误必须被处理）
4.  **trait = 接口**：默认方法、泛型约束、运算符重载都靠它；孤儿规则约束实现位置
5.  **静态分发（`<T: Trait>`，单态化、可内联）优先**；异质集合/动态场景才 `dyn Trait`
6.  `#[derive]` 自动生成常用实现；`unwrap` 只适合原型和测试
7.  `panic!` 是 bug 级终止，**可恢复错误一律 `Result`**
