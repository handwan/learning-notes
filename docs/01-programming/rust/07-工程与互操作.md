# 工程与互操作

cargo 是"构建系统 + 包管理 + 测试 + lint"一体；FFI 部分对应 C++ 笔记里的 pybind11 位置——**Rust 和 C/C++ 怎么互调**。

## 1. cargo：一个工具全包

```bash
cargo new myapp          # 新建项目（edition 2024）
cargo run                # 编译 + 运行
cargo run --release      # 优化编译（≈ -O2/-O3）
cargo build              # 只编译（产物在 target/）
cargo test               # 跑测试
cargo fmt                # 格式化
cargo clippy             # lint（比编译器更严）
cargo add serde          # 添加依赖（自动写进 Cargo.toml）
cargo doc --open         # 生成并打开文档
```

**Cargo.toml**：

```toml
[package]
name = "myapp"
version = "0.1.0"
edition = "2024"

[dependencies]
serde = { version = "1", features = ["derive"] }

[dev-dependencies]
criterion = "0.5"        # 只在测试/基准里用

[profile.release]
lto = true
opt-level = 3
```

| 概念 | Rust | C++ 世界对应 |
|------|------|-------------|
| 构建 + 依赖一体 | **cargo** | CMake + vcpkg/conan |
| 官方包仓库 | crates.io | 无官方（vcpkg/conan） |
| 测试内置 | `#[test]` | 外挂 gtest/Catch2 |
| 官方格式化 / lint | `cargo fmt` / `clippy` | clang-format / clang-tidy |
| 锁定版本 | `Cargo.lock` | lock 文件（vcpkg 等） |

**测试**：

```rust
fn add(a: i32, b: i32) -> i32 { a + b }

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_add() {
        assert_eq!(add(1, 2), 3);
    }
}
```

```rust
// tests/integration.rs —— 集成测试：像外部用户一样调用 crate
use mylib::add;

#[test]
fn works_from_outside() {
    assert_eq!(add(2, 3), 5);
}
```

```rust
/// 加法。
///
/// ```
/// assert_eq!(mylib::add(1, 1), 2);
/// ```
pub fn add(a: i32, b: i32) -> i32 { a + b }
```

`cargo test` 会一起跑单元测试、`tests/` 集成测试，以及文档注释里的示例代码。

## 2. 模块系统

```text
src/
├── main.rs        # 二进制入口
├── lib.rs         # 库入口
├── utils.rs       # 模块
└── net/
    └── mod.rs     # 子模块
```

```rust
mod utils;                   // 声明模块（对应 utils.rs）
use crate::utils::helper;    // 引用：crate:: 表示本 crate 根

pub fn api() {}              // pub：对外可见
pub(crate) fn internal() {}  // 只在本 crate 内可见
```

**默认私有**（模块级）——不写 `pub` 外面看不到，和 C++ 的 `class` 默认私有思路类似。

## 3. features：条件编译 + 可选依赖

```toml
[features]
default = ["std"]
std = []
gpu = ["dep:cudarc"]     # 开 gpu 才拉这个依赖
```

```rust
#[cfg(feature = "gpu")]
fn init_gpu() { /* 只有开了 gpu 才会被编译 */ }
```

**用途**：一个库支持多种后端（CPU/GPU、不同协议）——不选的功能**根本不参与编译**（没依赖、没体积、没维护成本）。

## 4. 宏：声明式与过程宏

宏在编译期展开，用来消除重复语法。先试函数、泛型、trait；这些能表达就不要上宏。

### `macro_rules!`

```rust
macro_rules! unless {
    ($cond:expr, $body:block) => {
        if !$cond { $body }
    };
}

fn main() {
    let debug = false;
    unless!(debug, {
        println!("release");
    });
}
```

- `$cond:expr` 匹配表达式，`$body:block` 匹配代码块
- 宏按 token 展开，不按文本替换；有卫生性，宏里定义的局部变量不会污染调用处
- 重复片段用 `$(...),*` 和 `$($x),*` 展开
- 导出的宏用 `#[macro_export]`；在宏内部引用本 crate 的路径用 `$crate::`

### 过程宏

过程宏是编译期运行的 Rust 函数，放在单独的 `proc-macro` crate：

```toml
[lib]
proc-macro = true

[dependencies]
syn = "2"
quote = "1"
```

三种形式：

- `#[derive(...)]`：为结构体/枚举生成 impl，最常见
- 属性宏：替换或补充被标注的项
- 函数式宏：`my_macro!(...)`，直接生成代码

`syn` 负责解析 token，`quote` 负责生成代码。过程宏调试成本高，逻辑尽量放进普通函数/库，宏只做代码生成。

C++ 对照：`#define` 是文本替换；Rust 宏基于 token tree，带卫生性。模板负责类型级泛型，过程宏负责语法级代码生成。

## 5. unsafe：到底放开什么

`unsafe` **不是关掉所有检查**——类型检查、借用检查照常。它只允许五件事：

1. 解引用**裸指针**（`*const T` / `*mut T`）
2. 调用 `unsafe` 函数
3. 访问 / 修改**可变静态变量**
4. 实现 `unsafe trait`（如手写 `Send` / `Sync`）
5. 访问 `union` 的字段

```rust
let x = 5;
let p = &x as *const i32;
let y = unsafe { *p };      // 解引用裸指针要放在 unsafe 块里
println!("{}", y);
```

**原则：unsafe 要小、要封装**——外面包一层 safe 接口，把"为什么这里安全"写清楚：

```rust
// SAFETY: p 指向有效的栈变量 x，且 x 在整个作用域内没有被移动
let y = unsafe { *p };
```

标准库里的 `Vec`、`Mutex` 内部全是 unsafe，但对使用者是 safe——**unsafe 是给实现者的工具，不是给使用者的借口**。

## 6. FFI：和 C / C++ 互调

### Rust 调 C

```rust
unsafe extern "C" {                 // Edition 2024 必须带 unsafe（旧版可写 extern）
    fn abs(input: i32) -> i32;
}

fn main() {
    let x = unsafe { abs(-5) };
    println!("{}", x);
}
```

### 导出给 C 调

```rust
#[unsafe(no_mangle)]                // Edition 2024 必须这么写（旧版 #[no_mangle]）
pub extern "C" fn add(a: i32, b: i32) -> i32 {
    a + b
}
```

**注意**：跨 FFI 边界传的东西要**简单**（整数、指针、`#[repr(C)]` 结构体），Rust 的 `String`/`Vec` 不能直接给 C。

### 和 C++ 互操作

| 需求 | 工具 |
|------|------|
| 从 C 头文件生成 Rust 绑定 | `bindgen` |
| Rust ↔ C++ **双向**、类型安全 | **`cxx`** |
| 自动包装现成 C++ 库 | `autocxx` |

`cxx` 的定位和 C++ 侧的 pybind11 类似：两边各写一段声明，它生成胶水代码——不用先退化到 C ABI。

**实践建议**：新项目优先**只暴露 C ABI**（最稳）；C++ 复杂类型必须互通时上 `cxx`。

## 7. 要点回顾

1. **cargo 全包**：构建、依赖、测试、格式化、lint、文档（`Cargo.toml` 声明 + `Cargo.lock` 锁定）
2. **模块默认私有**，`pub` / `pub(crate)` 控制可见性
3. **features** = 条件编译 + 可选依赖，多后端库的标配
4. **宏**：`macro_rules!` 按 token 匹配、有卫生性；过程宏放在 `proc-macro` crate，常用 `syn` + `quote`
5. **`unsafe` 只放开五件事**（裸指针解引用、调 unsafe 函数、可变静态、unsafe trait、union）——借用/类型检查照旧
6. **FFI**：Rust 调 C 用 `unsafe extern "C"`；导出用 `#[unsafe(no_mangle)] pub extern "C"`；C++ 双向用 **`cxx`**，C 绑定生成用 `bindgen`
7. **unsafe 要小而封装**，用 `// SAFETY:` 注释交代不变量
