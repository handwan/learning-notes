# 迭代器与闭包

Rust 的日常写法就是**闭包 + 迭代器链**。C++ 里对应 lambda + `<algorithm>`，但 Rust 的迭代器是语言/标准库的一等公民。

## 1. 闭包

### 语法与捕获

```rust
let add = |a, b| a + b;          // 参数不用标类型（一般能推）
assert_eq!(add(1, 2), 3);

let n = 10;
let plus_n = |x| x + n;          // 捕获外部变量 n（默认按引用捕获）
assert_eq!(plus_n(5), 15);
```

C++ 对照：`[n](int x) { return x + n; }`——Rust 不用写捕获列表，**捕获谁编译器自己推**。

### 三种能力：Fn / FnMut / FnOnce

闭包"能怎么调"由它**怎么用捕获的变量**决定：

| trait    | 调用能力                       | 典型捕获方式             |
|----------|--------------------------------|--------------------------|
| `Fn`     | 可多次调用，不消耗捕获         | 共享借用或 Copy 值       |
| `FnMut`  | 可多次调用，可修改捕获         | 可变借用                 |
| `FnOnce` | 至少可调用一次，可能消耗捕获   | 所有权 / 移动            |

```rust
let s = String::from("hi");

let read_it = || println!("{s}");            // Fn：只读

let mut count = 0;
let mut inc = || count += 1;                 // FnMut：改外部变量
inc();
inc();
assert_eq!(count, 2);

let consume = move || drop(s);               // FnOnce：s 被移进闭包
consume();
// consume();                                // ❌ 只能用一次
```

**读报错的方式**：编译器说"closure is `FnMut` but `Fn` is required"之类，就是在告诉你它捕获了什么。

### move 闭包（跨线程必须）

`move` 强制**按值捕获**（Copy 类型就是拷贝）：

```rust
use std::thread;

let v = vec![1, 2, 3];
let h = thread::spawn(move || v.iter().sum::<i32>());   // 所有权移进线程
assert_eq!(h.join().unwrap(), 6);
```

**为什么线程必须 `move`**：新线程可能比当前作用域活得久，借用会悬垂——拷进去（或移动）才安全。

### 闭包作为一个类型

每个闭包有**独一无二的匿名类型**，所以：

```rust
fn apply<F: Fn(i32) -> i32>(f: F, x: i32) -> i32 { f(x) }        // 泛型（静态分发）
fn apply_dyn(f: &dyn Fn(i32) -> i32, x: i32) -> i32 { f(x) }     // trait 对象

fn make_adder(n: i32) -> impl Fn(i32) -> i32 {                   // 返回闭包
    move |x| x + n
}
```

C++ 对照：C++ 只能用模板或 `std::function`（有开销）；Rust 的泛型闭包是**单态化**的，没有虚调用。

## 2. 迭代器的三种拿法

**同一个容器，三种迭代方式拿到的元素类型不同**：

```rust
let mut v = vec![10, 20, 30];

for x in v.iter() {          // &T      —— 只读借用
    print!("{x} ");
}

for x in v.iter_mut() {      // &mut T  —— 可修改
    *x += 1;
}

for x in v.into_iter() {     // T       —— 消费掉容器（所有权）
    print!("{x} ");
}
```

和 `for` 语法糖的对应关系：

| 写法              | 等价于          | 元素     |
|-------------------|-----------------|----------|
| `for x in &v`     | `v.iter()`      | `&T`     |
| `for x in &mut v` | `v.iter_mut()`  | `&mut T` |
| `for x in v`      | `v.into_iter()` | `T`      |

**选哪个**：只读用 `iter()`；要改元素用 `iter_mut()`；不再用容器、要拿走元素（比如 String）用 `into_iter()`。

## 3. 适配器链

### 常用适配器

```rust
let nums = vec![1, 2, 3, 4, 5, 6];

let squares_of_evens: Vec<i32> = nums.iter()
    .filter(|&&x| x % 2 == 0)      // 留偶数
    .map(|&x| x * x)               // 平方
    .collect();
assert_eq!(squares_of_evens, vec![4, 16, 36]);
```

| 适配器              | 作用                                              |
|---------------------|---------------------------------------------------|
| `map`               | 每个元素变换（可改类型）                          |
| `filter`            | 保留满足条件的                                    |
| `filter_map`        | 变换 + 过滤一步到位（返回 `Option`，`None` 丢掉） |
| `flat_map`          | 每个元素展开成多个（再拼平）                      |
| `enumerate`         | 附加下标：`(usize, T)`                            |
| `zip`               | 两个迭代器配对                                    |
| `take` / `skip`     | 取前 n 个 / 跳过前 n 个                           |
| `copied` / `cloned` | `&T` → `T`（Copy）/ 克隆                          |

还有 `chain`/`take_while`/`rev`/`peekable` 等，按需查 std 文档。

```rust
// flat_map：拆开再拼平
let text = ["hello world", "foo bar"];
let chars: Vec<char> = text.iter().flat_map(|s| s.chars()).collect();
assert_eq!(chars.len(), 18);

// zip：配对
let a = vec![1, 2, 3];
let b = vec![10, 20, 30];
let sums: Vec<i32> = a.iter().zip(b.iter()).map(|(x, y)| x + y).collect();
assert_eq!(sums, vec![11, 22, 33]);

// enumerate：要下标又不想手写计数器
let names = ["a", "b", "c"];
let indexed: Vec<String> = names.iter().enumerate()
    .map(|(i, name)| format!("{i}:{name}"))
    .collect();
assert_eq!(indexed, vec!["0:a", "1:b", "2:c"]);
```

### 惰性：不消费就不执行

**适配器只是"记了个流水线"，直到终结器（`collect`/`for`/`sum`/`count`/`fold`）才真正跑**：

```rust
let v = vec![1, 2, 3];

let lazy = v.iter().map(|x| {
    println!("计算 {x}");       // 现在不会打印
    x * 2
});

let out: Vec<i32> = lazy.collect();   // 到这里才打印三行
```

好处：**不产生中间数组**——`filter().map().collect()` 一趟扫完，不像 Python 的推导式要建中间列表（对比见 [Python 基础语法](../python/01-基础语法.md)）。

### 终结器（消费迭代器）

```rust
let nums = vec![1, 2, 3, 4, 5];

nums.iter().sum::<i32>();                    // 15
nums.iter().count();                         // 5
nums.iter().max();                           // Some(&5)
nums.iter().any(|&x| x > 4);                 // true
nums.iter().all(|&x| x > 0);                 // true
nums.iter().find(|&&x| x > 2);               // Some(&3)
nums.iter().position(|&x| x == 3);           // Some(2)
(1..=5).fold(0, |acc, x| acc + x);           // 15
```

**`for` 循环能用的一切，迭代器都能表达**——需要"状态 + 提前退出"时用循环更清楚。

## 4. collect：收进容器或 Result

```rust
use std::collections::HashMap;

let v: Vec<i32> = (1..=5).map(|x| x * x).collect();
let set: std::collections::HashSet<i32> = v.iter().copied().collect();

// collect 成 HashMap：二元组序列
let pairs = vec![("a", 1), ("b", 2)];
let map: HashMap<&str, i32> = pairs.into_iter().collect();
assert_eq!(map["a"], 1);
```

**`collect` 到 `Result`**：一串可能失败的转换，一次收集；错一个就整体失败：

```rust
fn parse_all(items: &[&str]) -> Result<Vec<i32>, std::num::ParseIntError> {
    items.iter().map(|s| s.trim().parse::<i32>()).collect()
}

assert_eq!(parse_all(&["1", "2"]).unwrap(), vec![1, 2]);
assert!(parse_all(&["1", "oops"]).is_err());
```

**注意**：`?` 只有在闭包本身返回 `Result` 时才能用；如果闭包返回的是普通值，就不能直接写 `?`。这时可以像上面一样用 `collect`，或把逻辑抽成返回 `Result` 的函数再用 `map`。例如闭包显式返回 `Result` 时是合法的：

```rust
let parsed: Result<Vec<i32>, _> = items
    .iter()
    .map(|s| -> Result<i32, _> {
        let n = s.parse::<i32>()?;
        Ok(n)
    })
    .collect();
```

## 5. 自定义迭代器

实现 `next` 一个方法，**自动获得全部适配器**：

```rust
struct Fib {
    a: u64,
    b: u64,
}

impl Iterator for Fib {
    type Item = u64;

    fn next(&mut self) -> Option<u64> {
        let out = self.a;
        self.a = self.b;
        self.b = out + self.b;
        Some(out)          // 永不结束；配合 take 用
    }
}

let first: Vec<u64> = Fib { a: 0, b: 1 }.take(5).collect();
assert_eq!(first, vec![0, 1, 1, 2, 3]);
```

要点：

- `type Item` 是**关联类型**（迭代器产出什么）
- `next` 返回 `Option`：`None` 表示结束
- 无限迭代器完全合法（靠 `take`/`find` 截断）

## 6. 性能

**迭代器链通常编译成和手写循环一样的机器码**：泛型单态化 + 内联 → 没有虚调用、没有中间容器（实测同机同题：迭代器写法甚至更快，因为更容易被优化器向量化）。

```rust
// 这两种写法性能基本相同
let sum1: u64 = (1..=1_000_000).filter(|x| x % 3 == 0).sum();

let mut sum2 = 0u64;
for x in 1..=1_000_000 {
    if x % 3 == 0 {
        sum2 += x;
    }
}
assert_eq!(sum1, sum2);
```

**例外**：`Box<dyn Iterator>`（动态分发，不能内联）、链太长导致内联失败——真在意就测（`cargo bench` / criterion），别猜。

## 7. 和 C++ 对照

|            | C++                          | Rust                         |
|------------|------------------------------|------------------------------|
| 匿名函数   | `[](int x){...}`             | `|x| ...`                    |
| 捕获       | 显式写 `[&]` / `[=]` / `[x]` | 编译器推断；跨线程加 `move`  |
| 捕获可变性 | `mutable` 关键字             | `FnMut`（自动推）            |
| 链表式处理 | ranges（C++20）              | 迭代器链（更早、更普遍）     |
| 惰性       | `std::views::filter`         | 默认惰性                     |
| 动态函数   | `std::function`（有开销）    | `dyn Fn`（显式选，才有开销） |

## 8. 要点回顾

1.  **闭包捕获由编译器推**；能力分 `Fn`（只读）/ `FnMut`（改）/ `FnOnce`（消耗）
2.  **跨线程闭包必须 `move`**
3.  **迭代器三种拿法**：`iter()`→`&T`、`iter_mut()`→`&mut T`、`into_iter()`→`T`
4.  **适配器惰性**，`collect`/`for`/`sum` 等终结器才触发；不产生中间容器
5.  **`collect` 能收进 `Vec`/`HashMap`，也能收进 `Result`**——一串可能失败的转换一次搞定
6.  **实现 `next` 就白得所有适配器**；无限迭代器 + `take` 是常见组合
7.  **迭代器链和手写循环性能基本一样**（单态化 + 内联）；有疑问就 benchmark
8.  `?` 不能用在迭代器闭包里——用 `collect` 或抽成函数
