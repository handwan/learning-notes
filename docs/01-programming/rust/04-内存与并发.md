# 内存与并发

Rust 没有 GC，也不用手动 `free`：**所有权 + 智能指针**。并发更进一步——**数据竞争在 safe 代码里是编译错误**。

## 1. 智能指针

| 用途 | C++ | Rust |
|------|-----|------|
| 独占、堆分配 | `std::unique_ptr<T>` | `Box<T>` |
| 共享所有权（单线程） | `std::shared_ptr<T>` | `Rc<T>` |
| 共享所有权（多线程） | `shared_ptr` + 原子操作 | `Arc<T>` |
| 内部可变 | `mutable` / `const_cast` | `RefCell<T>` |
| 互斥锁 + 数据 | `std::mutex` + 数据分开写 | `Mutex<T>`（锁**含**数据） |

### Box：独占的堆对象

```rust
let b = Box::new(5);       // 堆上分配，b 是唯一所有者
println!("{}", b);         // 自动解引用

// 递归类型必须用 Box（否则类型大小无限）
enum List {
    Cons(i32, Box<List>),
    Nil,
}
```

### Rc / Arc：共享所有权

```rust
use std::rc::Rc;

let a = Rc::new(String::from("shared"));
let b = Rc::clone(&a);              // 只加引用计数，不复制字符串
println!("{} {}", a, b);
println!("count = {}", Rc::strong_count(&a));   // 2
```

**注意**：`Rc`/`Arc` 只提供**共享读**（里面不可变）。要修改就套 `RefCell`（单线程）或 `Mutex`（多线程）。

### RefCell：单线程的"内部可变"

```rust
use std::cell::RefCell;

let c = RefCell::new(5);
*c.borrow_mut() += 1;          // 运行时检查借用
println!("{}", c.borrow());    // 6
```

借用规则没变，只是**从编译期挪到运行时**——违规会 **panic**（不是编译错误）。

**经典组合：`Rc<RefCell<T>>` = 多个所有者 + 可修改**

```rust
use std::cell::RefCell;
use std::rc::Rc;

let shared = Rc::new(RefCell::new(vec![1, 2, 3]));
let copy = Rc::clone(&shared);
copy.borrow_mut().push(4);
println!("{:?}", shared.borrow());   // [1, 2, 3, 4]
```

### Cell 与 OnceLock：更轻的内部可变

`RefCell` 要在运行时检查借用；只读写一个 Copy 小值时，`Cell` 更轻。全局配置的一次性初始化用 `OnceLock`。

```rust
use std::cell::Cell;

let hits = Cell::new(0);
hits.set(hits.get() + 1);
assert_eq!(hits.get(), 1);
```

`Cell<T>` 通过 `get` / `set` 整体读写，不返回借用；`T: Copy` 时最方便。

```rust
use std::sync::OnceLock;

static CONFIG: OnceLock<String> = OnceLock::new();

let config = CONFIG.get_or_init(|| "dev".to_string());
assert_eq!(config.as_str(), "dev");
```

- `OnceLock` 是线程安全的；单线程一次性初始化可用 `std::cell::OnceCell`
- C++ 对应 `std::call_once` + `std::once_flag`

### Weak：不拥有所有权的引用

`Rc` / `Arc` 互相强引用会形成环，引用计数永远不归零。父指针改成 `Weak` 可以打破循环。

```rust
use std::rc::{Rc, Weak};

let strong = Rc::new(5);
let weak: Weak<i32> = Rc::downgrade(&strong);

assert_eq!(weak.upgrade().as_deref(), Some(&5));
drop(strong);
assert!(weak.upgrade().is_none());
```

`Weak::upgrade()` 返回 `Option<Rc<T>>`：对象还在就临时升级成强引用，不在就返回 `None`。`Weak` 自己不会延长对象寿命。C++ 对应 `std::weak_ptr`。

### 原子类型：共享计数与标志

`Mutex` 用来保护一组必须一起变化的数据；只有一个整数或布尔标志时，`Atomic*` 更直接。

```rust
use std::sync::Arc;
use std::sync::atomic::{AtomicUsize, Ordering};
use std::thread;

let counter = Arc::new(AtomicUsize::new(0));
let mut handles = Vec::new();

for _ in 0..4 {
    let c = Arc::clone(&counter);
    handles.push(thread::spawn(move || {
        for _ in 0..1000 {
            c.fetch_add(1, Ordering::Relaxed);
        }
    }));
}

for h in handles {
    h.join().unwrap();
}
assert_eq!(counter.load(Ordering::Relaxed), 4000);
```

常见方法：

- `load` / `store`：读 / 写
- `fetch_add` / `fetch_sub`：原子加减，返回旧值
- `compare_exchange`：比较并交换，用来实现锁、状态机等
- `swap`：写入新值并返回旧值

内存序按用途选，不要见到原子就全写 `Relaxed`：

- `Relaxed`：只保证这个原子操作本身不可分割；适合独立计数器
- `Release` 写 + `Acquire` 读：把之前写好的普通数据发布给另一个线程
- `SeqCst`：最强的全局顺序；不确定时先用它
- 原子只保证单个操作的原子性，**不保证多条语句组成的不变量**

C++ 对应 `std::atomic<T>` 和 `std::memory_order_*`。

## 2. 线程与 Send / Sync

```rust
use std::thread;

fn main() {
    let v = vec![1, 2, 3];
    let h = thread::spawn(move || {      // move：把 v 的所有权移进新线程
        println!("{:?}", v);
    });
    h.join().unwrap();                   // 等线程结束（返回 Result）
}
```

**`Send` / `Sync` 是"能不能跨线程"的标记 trait**：

| trait | 含义 |
|-------|------|
| `Send` | 值可以**移动**到另一个线程 |
| `Sync` | 值的**引用**可以安全共享给多个线程 |

- 多数类型自动是 `Send + Sync`
- `Rc<T>` **不是**（引用计数非原子）→ 跨线程改用 `Arc`
- `RefCell<T>` **不是** `Sync` → 跨线程改用 `Mutex`

**对比 C++**：把 `shared_ptr` 传进线程、在线程里共享引用，都是合法代码，出事算 UB；Rust 直接用 trait 把它们**挡在编译期**。

### thread::scope：借用跨线程，不用 Arc

`thread::spawn` 要求闭包 `'static`（不能借用局部变量），所以共享数据通常要 `Arc`。**如果确定线程在作用域内结束**，`thread::scope` 可以直接借用：

```rust
use std::thread;

let v = vec![1, 2, 3];

thread::scope(|s| {
    s.spawn(|| {                       // 直接借用 v，不用 Arc
        println!("{:?}", v);
    });
    s.spawn(|| {
        let total: i32 = v.iter().sum();
        println!("{total}");
    });
});                                     // 作用域结束：所有线程已 join
```

省掉 `Arc` 的堆分配和引用计数开销；作用域外线程一定已经结束，借用安全由编译器证明。

## 3. Arc + Mutex：共享可变状态

```rust
use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    let counter = Arc::new(Mutex::new(0));
    let mut handles = Vec::new();

    for _ in 0..10 {
        let c = Arc::clone(&counter);
        handles.push(thread::spawn(move || {
            let mut n = c.lock().unwrap();   // 拿锁；MutexGuard 析构时自动解锁
            *n += 1;
        }));
    }

    for h in handles {
        h.join().unwrap();
    }
    println!("count = {}", *counter.lock().unwrap());   // 10
}
```

**两个设计上的差别（都少一个坑）**：

1. **`Mutex<T>` 把数据装在锁里**——不拿锁就碰不到数据（C++ 是 mutex 和数据两个变量，容易忘锁）
2. **`MutexGuard` 是 RAII**——提前 return / panic 都会自动解锁（C++ 得用 `lock_guard`，裸 mutex 会忘）

**仍要注意**：

- 持锁线程 panic → 锁"中毒"，之后 `lock()` 返回 `Err`（示例用 `unwrap` 简化）
- **死锁没有编译期保护**：同一线程重复 `lock` 会死锁（或 panic），AB-BA 锁序依然要靠设计避免

## 4. 消息传递：channel

"不要用共享内存来通信，用通信来共享内存"：

```rust
use std::sync::mpsc;
use std::thread;

fn main() {
    let (tx, rx) = mpsc::channel();

    thread::spawn(move || {
        tx.send("hello from thread").unwrap();
    });

    println!("收到: {}", rx.recv().unwrap());
}
```

**特点**：sender 可克隆出多个（多生产者），recv 阻塞等待；所有权随消息**移动**过去，天然没有共享。

## 5. 数据并行：rayon

```rust
use rayon::prelude::*;

let sum: i64 = (1..=1_000_000).into_par_iter().sum();
```

`iter()` 换成 `par_iter()` 就自动并行——适合数据处理/预处理这类天然可分的任务（AI infra 里常见）。

## 6. 和 C++ 的并发对比

内存安全的对比见[所有权与借用](02-所有权与借用.md)；这里只列并发相关的差异。

| 问题 | C++ | Rust（safe 代码） |
|------|-----|------------------|
| 忘记解锁 | 可能（提前 return / 异常） | RAII（`MutexGuard`） |
| 忘记加锁 | 容易 | 拿不到数据（锁含数据） |
| 共享可变状态 | 手动保证 | 必须显式写 `Rc<RefCell>` / `Arc<Mutex>` |
| 死锁 | 有 | **也有**（编译期管不了逻辑死锁） |

**Rust 保证的边界**：safe 代码内**内存和并发安全**；`unsafe` 里责任回到程序员（见[工程与互操作](07-工程与互操作.md)）。**死锁、逻辑错误、性能问题一个都不会少**。

## 7. 要点回顾

1. **`Box` ≈ unique_ptr**（递归类型必须 Box）；**`Rc`/`Arc` ≈ shared_ptr**（单线程/多线程）
2. **`Rc`/`Arc` 只给共享读**；要改就套 `RefCell`（单线程，违规 panic）或 `Mutex`（多线程）
3. **`Send`/`Sync`** 把"跨线程是否安全"变成编译期检查；`Rc`/`RefCell` 不过关
4. **`Mutex<T>` 锁含数据 + RAII 解锁**，比 C++ 少"忘锁/忘解锁"两个坑，但**不防死锁**
5. **channel**（mpsc）：消息带着所有权移动，天然无共享
6. **rayon 的 `par_iter()`** 一行切数据并行
7. Rust 只保证内存/并发安全，**不保证不死锁、不出逻辑 bug**
