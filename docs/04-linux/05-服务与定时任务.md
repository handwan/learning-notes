# 服务与定时任务

用 systemd 管服务（开机自启、崩溃重启、日志）、用 timer 和 crontab 做定时任务，以及日志轮转和启动排查。

## 1. systemctl 常用操作

```bash
systemctl status nginx            # 状态（是否运行、最近日志）
systemctl start nginx
systemctl stop nginx
systemctl restart nginx
systemctl reload nginx            # 重载配置（不中断服务；服务要支持）
systemctl enable nginx            # 开机自启（创建符号链接）
systemctl disable nginx
systemctl enable --now nginx      # 自启 + 立即启动（常用组合）
systemctl is-active nginx         # 只看是否在跑（脚本里用）
systemctl is-enabled nginx
systemctl mask nginx              # 禁止启动（连依赖拉起也不行；unmask 解除）

systemctl list-units --type=service --state=running   # 正在跑的服务
systemctl list-unit-files --state=enabled             # 已设自启的
systemctl daemon-reload           # 改了 unit 文件后必须执行！
systemctl cat nginx               # 看某个服务的 unit 内容（含 override）
systemctl show nginx -p MainPID   # 看某个属性（脚本友好）
```

**`start` 和 `enable` 是两件事**：`start` 只管现在跑；`enable` 只设开机自启。所以加固/部署脚本里常见 `systemctl enable --now xxx`。

**用户级服务**：`systemctl --user ...`，unit 放 `~/.config/systemd/user/`。要让服务在用户未登录时也启动，需要 `loginctl enable-linger <user>`。

## 2. 写一个自己的服务

**unit 文件位置**：

| 目录 | 用途 |
|------|------|
| `/etc/systemd/system/` | 自己写的/管理员改的（优先） |
| `/lib/systemd/system/`（或 `/usr/lib/...`） | 软件包安装的（别直接改，用 override） |

改软件包自带的 unit 别直接编辑源文件——用 `sudo systemctl edit nginx` 生成 **override**（`/etc/systemd/system/nginx.service.d/override.conf`），只写要覆盖的字段；`systemctl cat` 能看到合并后的结果。

```ini
# /etc/systemd/system/myapp.service
[Unit]
Description=My inference server
After=network-online.target              # 等网络真正就绪
Wants=network-online.target

[Service]
Type=simple                             # 默认：ExecStart 是主进程、前台运行
ExecStartPre=/usr/bin/test -x /opt/myapp/bin/server   # 启动前检查可执行文件
ExecStart=/opt/myapp/bin/server --port 8080
ExecStartPost=/usr/bin/curl -fsS http://127.0.0.1:8080/health  # 可选：就绪检查
ExecStop=/bin/kill -TERM $MAINPID        # 可选：自定义停止；systemd 默认也会发 TERM
TimeoutStopSec=20                        # 停止超时后升级为 KILL
WorkingDirectory=/opt/myapp             # 工作目录
User=appuser                            # 用哪个用户跑（别用 root）
Group=appuser
Environment="LOG_LEVEL=info"            # 环境变量（多个写多行）
EnvironmentFile=-/etc/myapp.env         # 从文件读环境变量（- 表示文件不存在也不报错）
Restart=on-failure                      # 崩溃自动拉起
RestartSec=3
LimitNOFILE=65535                       # 文件描述符上限（高并发服务要调）
NoNewPrivileges=true                    # 禁止再提权
PrivateTmp=true                         # 独立 /tmp
ProtectSystem=full                      # /usr、/boot、/etc 只读
ProtectHome=true                        # 隐藏 /home、/root
RuntimeDirectory=myapp                  # /run/myapp，退出自动清理
StateDirectory=myapp                    # /var/lib/myapp，持久化数据
# 需要写其他目录时再显式放开：ReadWritePaths=/var/lib/myapp

[Install]
WantedBy=multi-user.target              # enable 时挂到这个 target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now myapp
systemctl status myapp
journalctl -u myapp -f                  # 跟踪它的日志
```

`ExecStartPost` 失败会让 unit 启动失败；健康检查要留重试（`curl --retry`）或干脆去掉。

**`Type` 的选择**：

| Type | 含义 | 例子 |
|------|------|------|
| `simple` | 默认，ExecStart 就是主进程（前台） | 自己写的服务 |
| `forking` | 程序自己 daemon 化、父进程退出 | 老式服务 |
| `oneshot` | 跑完就退出的任务（配 `RemainAfterExit=yes`） | 初始化脚本 |
| `notify` | 程序主动通知 systemd"我好了" | 部分现代服务 |

**`Restart` 选项**：`no`（默认）、`on-failure`（非零退出/信号杀）、`always`、`on-abnormal`。

## 3. journalctl 看日志

systemd 会把服务日志收进 journal（结构化、带时间戳和优先级）：

```bash
journalctl -u myapp                # 某个服务的日志
journalctl -u myapp -f             # 实时跟踪（等价 tail -f）
journalctl -u myapp -n 100         # 最近 100 行
journalctl -u myapp --since "10 min ago"
journalctl -u myapp --since today
journalctl -u myapp -p err         # 只看 error 级别及以上
journalctl -u myapp -xe            # 末尾 + 解释性提示
journalctl --user-unit myapp        # 用户级 service（systemctl --user）
journalctl -b                     # 本次启动的日志（-b -1 是上次启动，排开机故障用）
journalctl --no-pager | grep xxx   # 不分页（脚本里用）
```

**journal 占磁盘**：

```bash
journalctl --disk-usage            # 看占用
sudo journalctl --vacuum-time=1w   # 只留最近一周
sudo journalctl --vacuum-size=500M # 限制总大小
```

## 4. 定时任务：systemd timer（推荐）与 cron

### systemd timer

```ini
# /etc/systemd/system/backup.service（要执行什么）
[Unit]
Description=Daily backup
[Service]
Type=oneshot
ExecStart=/opt/scripts/backup.sh
```

```ini
# /etc/systemd/system/backup.timer（什么时候执行）
[Unit]
Description=Run backup daily
[Timer]
OnCalendar=daily                  # 每天 00:00；也可写 *-*-* 03:30:00
Persistent=true                   # 错过的时间（关机）开机后补跑
AccuracySec=1min                  # 允许延迟窗口（省电/合并唤醒）
RandomizedDelaySec=30s            # 加随机抖动，避免整点一起跑
[Install]
WantedBy=timers.target
```

```bash
sudo systemctl enable --now backup.timer
systemctl list-timers               # 看所有 timer 和下次触发时间
journalctl -u backup                # 日志用 journalctl 查
```

**Timer 比 cron 好在**：日志进 journal、支持"错过后补跑"、依赖关系（After）、资源限制、`systemctl status` 可查。

### crontab

```bash
crontab -l            # 列出当前用户的定时任务
crontab -e            # 编辑（用 $EDITOR）
crontab -r            # 全部删除（危险，没有确认）
```

```cron
# 分 时 日 月 周   命令
* * * * *         echo hi >> /tmp/cron.log     # 每分钟
0 3 * * *         /opt/scripts/backup.sh       # 每天 03:00
*/10 * * * *      /opt/scripts/check.sh        # 每 10 分钟
0 9 * * 1-5       /opt/scripts/report.sh       # 工作日 09:00
@reboot           /opt/scripts/start_thing.sh  # 开机时执行一次
@daily            /opt/scripts/cleanup.sh      # 等价 0 0 * * *
```

crontab 顶部常用设置：

```cron
MAILTO=""                         # 不发送任务输出邮件
SHELL=/bin/bash
PATH=/usr/local/bin:/usr/bin:/bin
```

**一次性任务用 `at`**（cron 只管周期任务）：

```bash
sudo apt install at
echo "/opt/scripts/backup.sh" | at 03:00     # 今天 03:00 执行一次
atq                                          # 看队列；atrm <编号> 删除
```

**cron 的坑**：

- **环境变量几乎是空的**（PATH 通常是 `/usr/bin:/bin`）——命令一律写**绝对路径**，或在 crontab 顶部自己设 `PATH=...`
- **输出默认当邮件发**（本机没邮件系统就丢了）；要留证据就重定向：`... >> /var/log/mytask.log 2>&1`
- 任务日志：`journalctl -u cron`（RHEL 系是 `crond`）；或 `/var/log/syslog`（RHEL 系 `/var/log/cron`）里搜 CRON
- `crontab -r` 一键清空**不会确认**——别手滑
- 命令里的 `%` 要转义成 `\%`（cron 把未转义的 `%` 当"标准输入分隔符"——`date +%F` 这类格式化命令常踩）
- 需要 sudo 的任务：写进 root 的 crontab（`sudo crontab -e`）

## 5. 时区与时间同步

```bash
timedatectl                          # 当前时间/时区/NTP 状态
timedatectl list-timezones | grep Shanghai
sudo timedatectl set-timezone Asia/Shanghai
sudo timedatectl set-ntp true        # 打开网络时间同步
date                                 # 查看时间；date -d @1700000000 转时间戳
```

**服务里时间不对**（日志时间戳偏移）先查这里：`timedatectl` 看时区 + NTP 是否同步。

## 6. 日志轮转（logrotate）

日志文件会越写越大，`logrotate` 按规则切割/压缩/删除：

```bash
ls /etc/logrotate.d/                 # 各软件的轮转配置
```

```
# /etc/logrotate.d/myapp
/var/log/myapp/*.log {
    daily                # 每天轮转（或 weekly/monthly/size 100M）
    rotate 7             # 保留 7 份
    compress             # 旧的压缩（delaycompress 表示"上一份先不压"）
    missingok            # 文件不存在不报错
    notifempty           # 空文件不轮转
    create 0640 appuser appuser   # 新文件权限/属主
    su appuser appuser            # 以该用户身份轮转（日志目录属该用户时）
    dateext                      # 用日期后缀，便于按天查找
    postrotate
        systemctl reload myapp      # 切完后通知程序重开日志文件
    endscript
}
```

```bash
sudo logrotate -d /etc/logrotate.d/myapp   # 预演：只打印会做什么（-d = debug）
sudo logrotate -f /etc/logrotate.d/myapp   # 强制执行一次（忽略时间条件）
```

**为什么需要 postrotate**：程序还开着旧文件句柄（往被改名/删除的文件里写）——要让它重开日志文件（reload/发信号）。

程序**不支持** reload/信号（不会重开句柄）时，改用 `copytruncate`：先复制再截断原文件——不用改程序，代价是复制瞬间可能丢一条日志。

## 7. 启动、关机与救援（了解）

```bash
systemctl get-default                # 默认启动目标
systemctl isolate rescue.target      # 切到救援模式（单用户，排障用）
systemctl reboot
systemctl poweroff

journalctl -b -1                     # 上次启动的日志（开机失败时看这个）
systemctl list-units --failed        # 启动失败的服务
systemctl --failed                   # 同上（简写）

systemd-analyze                      # 启动耗时
systemd-analyze blame | head         # 哪个服务最慢
```

**忘了 root 密码（物理/控制台可及）**：GRUB 菜单按 `e` 编辑内核行，末尾加 `rd.break` 或 `init=/bin/bash` 进入紧急 shell，重新设置密码（`mount -o remount,rw /sysroot` 之类），改完重启。`rd.break` 主要适用于 dracut（RHEL/Fedora）；Ubuntu 的 initramfs 常用 `init=/bin/bash`。这是"能接触机器"才做得到的操作，远程机器别试。

## 8. 要点回顾

1. **start 管现在，enable 管开机，mask 禁止启动**；改 unit 后必须 `daemon-reload`
2. unit 三块：`[Unit]`（描述/依赖）、`[Service]`（怎么跑）、`[Install]`（enable 挂到哪）；启动/停止流程用 `ExecStartPre`/`ExecStartPost`/`ExecStop`/`TimeoutStopSec`，运行时目录用 `RuntimeDirectory`/`StateDirectory`
3. **别用 root 跑服务**（`User=`），配上 `Restart=on-failure`、`LimitNOFILE` 和 `NoNewPrivileges`/`PrivateTmp`/`ProtectSystem`
4. **日志统一用 `journalctl -u 服务`**（`-f` 跟踪、`--since` 限时、`-p err` 过滤、`--vacuum-*` 清理；用户服务用 `--user-unit`）
5. **定时任务优先 systemd timer**（日志/补跑/依赖），cron 适合简单场景；timer 可用 `AccuracySec`/`RandomizedDelaySec`
6. **cron 的 PATH 几乎为空 + 输出当邮件**——绝对路径 + 重定向是标配；`MAILTO=""` 可关闭邮件；`crontab -r` 无确认
7. **时区/NTP** 不对会让所有日志时间错乱：`timedatectl`
8. **logrotate** 用 `-d` 预演；切割后要 `postrotate` 通知程序重开日志；非 root 日志目录用 `su` 指定身份
