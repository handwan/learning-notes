# 磁盘与文件系统

看磁盘、挂载、空间与 inode 的排查、swap、磁盘 IO 与 SMART 健康。

## 1. 看磁盘与分区

```bash
lsblk                      # 块设备树（盘 → 分区 → 挂载点）
lsblk -f                   # 附加文件系统类型/UUID/可用空间
sudo fdisk -l              # 分区表详情（需要 root）
blkid                      # 各设备的 UUID 与文件系统类型
findmnt                    # 挂载树（比 mount 好读）
mount | grep -v tmpfs      # 传统看法
```

**设备命名**：

| 名字 | 含义 |
|------|------|
| `/dev/sda`、`/dev/sdb` | SATA/USB/虚拟磁盘（sda1 是第一个分区） |
| `/dev/nvme0n1`、`nvme0n1p1` | NVMe 盘与分区（注意 p） |
| `/dev/vda` | 虚拟机磁盘（virtio） |
| `/dev/mapper/...` | LVM 逻辑卷 / 加密卷 |

## 2. 挂载

```bash
sudo mount /dev/sdb1 /mnt/data         # 挂载分区
sudo mount -o ro /dev/sdb1 /mnt/data   # 只读挂载
sudo umount /mnt/data                  # 卸载（或 umount /dev/sdb1）
umount -l /mnt/data                    # 懒卸载（有进程占用时，不推荐常用）

sudo mount -o loop disk.img /mnt/img   # 挂载镜像文件（loop 设备）
# 注意：镜像里文件系统的根目录可能属于 root，写不进去时用 sudo 或先 chown
sudo mount --bind /src /dst             # 目录绑定挂载
sudo mount -o remount,rw /mnt/data      # 重新挂载为读写（救援/resize 后用）
findmnt /mnt/data                       # 确认挂载参数
```

**卸载报 `target is busy`**——谁占着它：

```bash
lsof +f -- /mnt/data        # 打开该挂载点里文件的进程
fuser -vm /mnt/data         # 另一条路（连用户和权限一起看）
```

**永久挂载：`/etc/fstab`**（6 列）：

```
# 设备              挂载点    类型   选项                 dump pass
UUID=abcd-1234      /         ext4   defaults              0    1
UUID=efgh-5678      /data     ext4   defaults,nofail       0    2
tmpfs               /tmp      tmpfs  defaults,size=2G      0    0
```

```bash
blkid                             # 先拿 UUID（比 /dev/sdX 稳，插拔顺序会变）
sudo mount -a                     # 测试 fstab 有没有写错（不改 fstab 就安全）
```

**要点**：

- **用 `UUID=` 而不是 `/dev/sdX`**：设备名会变（插新盘后 sda/sdb 可能互换）
- **可移动盘加 `nofail`**：设备不在时也不阻塞启动（否则可能进不了系统）
- **改完 fstab 先 `mount -a` 验证**，再重启
- SSD 可考虑 `noatime`；一般不要长期用 `discard`，用 `fstrim.timer` 周期 TRIM
- 网络盘加 `_netdev`；按需挂载可用 `x-systemd.automount`

## 3. 文件系统类型

| 类型 | 特点 |
|------|------|
| **ext4** | 最通用、稳定（默认） |
| xfs | 大文件/大并发好（RHEL 系默认） |
| btrfs | 快照/校验/压缩（openSUSE、部分桌面发行版） |
| tmpfs | 内存文件系统（`/dev/shm`、`/run`；有些发行版 `/tmp` 也是） |

```bash
sudo mkfs.ext4 /dev/sdb1     # 格式化【危险：清空数据】，新盘才用
sudo mkfs.ext4 -L data /dev/sdb1     # 顺便打标签
sudo fsck /dev/sdb1          # 文件系统检查/修复（必须先卸载；根分区要在救援模式下做）
```

## 4. 空间与 inode

```bash
df -h                    # 各文件系统空间
df -hT                   # 顺带显示文件系统类型
df -i                    # inode 使用量（很多人不知道要看这个）
du -sh dir/              # 目录占用
du -h --max-depth=1 . | sort -rh | head   # 逐层找大头
du -x -h --max-depth=1 / | sort -rh | head # 不跨文件系统
```

**两种"磁盘满"**：

| 情况 | 症状 | 查法 |
|------|------|------|
| **空间满** | `df -h` 接近 100% | `du` 逐层找大文件/目录 |
| **inode 满** | `df -h` 还有空间，但创建文件报 `No space left on device` | `df -i` 看 IUse% |

**inode 满**通常是小文件太多（缓存、session、邮件队列）——找哪个目录文件数量爆炸：

```bash
sudo find / -xdev -type f | wc -l                 # 全盘文件数
sudo find /var -xdev -type f -printf '%h\n' 2>/dev/null | sort | uniq -c | sort -rn | head   # 哪个目录文件最多
for d in /var/*; do echo "$(find "$d" -xdev -type f 2>/dev/null | wc -l) $d"; done | sort -rn | head
```

**`df` 和 `du` 对不上**：被删除但进程还开着的文件占着空间（`lsof | grep deleted`，见进程篇）。

## 5. swap

```bash
swapon --show             # 当前 swap
free -h                   # 内存 + swap 使用

# 加一个 2G 的 swap 文件（没有独立分区时）
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
# 永久生效：写进 /etc/fstab → /swapfile none swap sw 0 0

sysctl vm.swappiness      # 倾向用 swap 的程度（默认 60；服务器常调到 10）
```

**注意**：swap 不是"内存不够的补丁"——频繁换页（si/so 高）说明内存真的不够，先查谁在吃内存。

## 6. 磁盘 IO 观测

```bash
iostat -x 1 5             # 每秒一次共 5 次（需要 sysstat 包）
# 关键列：%util（接近 100% = 磁盘饱和）、await（平均等待 ms，含排队）

iotop -oPa                # 谁在读写（需要 root，iotop 包）
dd if=/dev/zero of=/tmp/test.bin bs=1M count=1024 oflag=direct   # 简单测写入速度
dd if=/tmp/test.bin of=/dev/null bs=1M iflag=direct              # 测读取
```

**排查思路**：进程状态大量 `D`（不可中断睡眠）→ 看 `iostat -x` 的 `%util`/`await` → 用 `iotop` 或 `/proc/<pid>/io` 找是哪个进程。

## 7. 空间清理实践

```bash
# 1) 找出最大的文件和目录
du -ah / 2>/dev/null | sort -rh | head -30
find / -xdev -type f -size +1G -printf '%s %p\n' 2>/dev/null | sort -rn | head

# 2) 常见占空间大户
du -sh /var/log /var/cache/apt /var/lib/docker /tmp 2>/dev/null
sudo journalctl --vacuum-size=500M     # systemd 日志（见服务篇）
sudo apt clean                         # apt 缓存

# 3) 被删除但仍被占用的文件
lsof | grep deleted                    # 找到进程后重启它，空间才会释放
```

**`/dev/shm` 与 `/run` 是内存文件系统**（tmpfs，大小受内存限制，大文件别放）；**`/tmp` 看发行版**（Ubuntu 默认在磁盘上，有些发行版用 tmpfs）。容器里的 `/dev/shm` 默认只有 64M（AI 部署常踩，见系统观测与调优篇）。

## 8. 磁盘健康（SMART）

```bash
sudo apt install smartmontools
sudo smartctl -H /dev/nvme0n1     # 健康自评：PASSED / FAILED
sudo smartctl -a /dev/nvme0n1     # 全量：温度、通电时长、磨损、重分配扇区
```

主要看：`Reallocated_Sector_Ct`（重分配扇区，涨了要警惕）和温度；NVMe 盘直接看 `Percentage Used`（寿命耗用百分比）。要定时盯着就开 `smartd` 服务。

SSD 还要管 TRIM：

```bash
sudo fstrim -av                  # 手动 TRIM 所有支持的文件系统
systemctl status fstrim.timer    # 周期 TRIM（发行版通常已启用）
```

## 9. LVM 与 RAID（了解）

- **LVM**：物理卷（PV）→ 卷组（VG）→ 逻辑卷（LV）——能在不关机的情况下扩缩容、快照，服务器常用
  ```bash
  pvs                      # 物理卷
  vgs                      # 卷组
  lvs                      # 逻辑卷
  sudo lvextend -r -L +10G /dev/vg0/lv_data   # 扩容并同步文件系统
  # 不用 -r 时手动扩文件系统：resize2fs（ext4）或 xfs_growfs（XFS）
  ```
- **RAID**：多盘组合（0 条带性能 / 1 镜像 / 5 校验 / 10），软件 RAID 用 `mdadm`，硬件 RAID 在 BIOS/阵列卡做

  ```bash
  cat /proc/mdstat                 # 软件 RAID 状态
  sudo mdadm --detail /dev/md0     # 阵列详情
  ```
- 单机开发用不上，知道"服务器上磁盘可以做池化/冗余"即可

## 10. 要点回顾

1. **看盘**：`lsblk -f`（树 + 文件系统）、`findmnt`（挂载树）、`blkid`（UUID）
2. **永久挂载写 `/etc/fstab`**：用 `UUID=` + 可移动设备加 `nofail`；改完先 `mount -a` 验证
3. **两种磁盘满**：空间满看 `df -h`、**inode 满看 `df -i`**（小文件太多）；`df` 与 `du` 不符查 `lsof | grep deleted`
4. **swap**：`swapon --show` 看，swap 文件加进 fstab；`si/so` 高说明内存不足
5. **IO 排查**：`D` 状态多 → `iostat -x`（%util/await）→ `iotop` 定位进程
6. **清理**：`du` 排序找大头、journal/apt 缓存、被删除占用的文件
7. **`/dev/shm`、`/run` 是内存**（tmpfs），大小受限；`/tmp` 看发行版
8. **LVM/RAID** 是服务器玩法：LVM 弹性扩容、RAID 冗余/性能
9. **SMART**：`smartctl -H` 看健康、`-a` 看磨损；NVMe 看 `Percentage Used`
