# 网络配置与排查

看网络配置、测连通性、查端口、抓包、防火墙，以及一套自下而上的排查套路。

## 1. 看本机网络

```bash
ip -br addr                # 简洁列出网卡与 IP（-br = brief，日常首选）
ip addr                    # 详情（替代老命令 ifconfig）
ip link                    # 网卡物理状态（UP/DOWN）
ip route                   # 路由表（看默认网关）
ip route get 8.8.8.8       # 去某个地址会走哪块网卡/网关
ip -s link                 # 网卡收发包、错误、丢包统计
ip neigh                   # ARP / IPv6 邻居表（同网段解析）
ethtool eth0               # 网卡速率、双工、Link detected（需 ethtool）
hostname -I                # 本机所有 IP
hostnamectl                # 主机名与系统信息
```

**解析相关**：

```bash
cat /etc/hosts             # 本地静态解析（优先于 DNS）
cat /etc/resolv.conf       # DNS 服务器（Ubuntu 桌面/服务器由 systemd-resolved 管理）
resolvectl status          # 看真实 DNS 配置（systemd 环境）
resolvectl query example.com   # 用当前 DNS 解析一次
getent hosts example.com       # 走 NSS 的解析结果（含 /etc/hosts）
```

改 DNS 的现代做法：`resolvectl dns <网卡> 8.8.8.8`；桌面环境也可以改 netplan 配置。直接改 `/etc/resolv.conf` 可能被覆盖。

### 临时改地址/路由

```bash
sudo ip addr add 192.168.1.10/24 dev eth0       # 临时加 IP
sudo ip route add default via 192.168.1.1       # 临时默认网关
sudo ip route del default                       # 删除默认路由
```

这些命令重启就没了，适合排障；持久化用 NetworkManager 或 netplan：

```bash
nmcli device status
nmcli connection show
sudo nmcli connection up "Wired connection 1"
sudo netplan try        # 先试跑，确认能回滚
sudo netplan apply
```

## 2. 连通性测试

```bash
ping -c 4 8.8.8.8          # 通不通（ICMP；有的环境禁 ping，不通≠网络坏）
ping -c 4 example.com      # 顺便测 DNS（域名能解析才通）
ping -6 -c 4 ::1           # IPv6

traceroute example.com     # 路径（每跳延迟）；mtr 更好（持续统计）
mtr -rw -c 10 example.com  # 报告模式跑 10 轮

curl -I https://example.com            # 只看响应头
curl -v https://example.com            # 看握手细节（排 TLS/代理）
curl -s -o /dev/null -w '%{http_code} %{time_total}s\n' https://example.com   # 只看状态码和耗时
curl --connect-timeout 3 --max-time 10 https://example.com   # 限制连接/总耗时
curl -L https://example.com            # 跟随重定向
curl -x http://proxy:8080 https://example.com   # 走代理
curl --resolve example.com:443:1.2.3.4 https://example.com   # 绕过 DNS 指定 IP（测 DNS 问题）
wget -c https://example.com/big.iso    # 断点续传下载

nc -zv host 8080           # 测端口通不通（-z 只探测，-v 显示结果）
```

**DNS 细查：dig**：

```bash
dig example.com              # 完整结果（主要看 ANSWER 段）
dig +short example.com       # 只要解析结果
dig @8.8.8.8 example.com     # 换一个 DNS 服务器查（对比"是不是本机 DNS 的问题"）
dig -t MX example.com        # 指定记录类型（MX / NS / CNAME / TXT…）
dig +trace example.com       # 从根开始逐级解析（定位是哪个环节不对）
```

**TLS 证书检查**：

```bash
openssl s_client -connect example.com:443 -servername example.com
openssl s_client -connect example.com:443 -servername example.com -showcerts
```

看证书链、有效期、SNI 是否匹配；`curl -v` 也能看到 TLS 握手和证书错误。

**ping 的替身**：环境禁 ICMP 时，用 `nc -zv host port` 或 `curl -v telnet://host:port` 测 TCP 连通。

## 3. 端口与连接

```bash
ss -ltnp                   # 监听的 TCP 端口 + 进程（排查"谁占了 8080"）
ss -ltunp                  # 加上 UDP
ss -tnp                    # 已建立的连接（谁连着我）
ss -s                      # 连接数统计（TIME_WAIT 数量等）
ss -H -tan state time-wait | wc -l # 数 TIME_WAIT（-H 去掉表头）
ss -tnp dst 10.0.0.5:443   # 到某个目标的所有连接
lsof -i :8080              # 等价视角（见进程篇）
```

## 4. 抓包：tcpdump

```bash
sudo tcpdump -i any -nn port 8080              # 监听所有网卡、不解析域名/端口名
sudo tcpdump -i eth0 -nn host 10.0.0.5         # 某主机的流量
sudo tcpdump -nn -c 100 'tcp and port 443'     # 抓 100 个包
sudo tcpdump -nn -A port 80                     # -A 用 ASCII 看内容（HTTP 明文）
sudo tcpdump -i any -nn -w cap.pcap port 8080  # 存到文件，之后用 Wireshark 看
sudo tcpdump -nn -r cap.pcap                    # 读回来
```

**过滤表达式**：`host x`、`src/dst x`、`port n`、`tcp/udp/icmp`、`and/or/not`（例：`src 10.0.0.5 and port 80`）。

抓包常用套路：先 `-nn` 看有没有包到；再看端口方向；还不行就 `-A` 看内容是否符合预期。

## 5. 防火墙

```bash
sudo ufw status verbose        # 看状态与规则（Ubuntu 默认工具）
sudo ufw default deny incoming # 默认拒绝入站
sudo ufw allow 22/tcp          # 放行 SSH（先做！否则可能连不上）
sudo ufw allow from 10.0.0.0/24 to any port 8080
sudo ufw enable                # 启用（会警告可能断开 ssh）
sudo ufw status numbered       # 规则带编号，按编号删除更稳
sudo ufw delete allow 22/tcp
```

**iptables/nftables** 是底层（链、表、规则），`ufw`/`firewalld` 是它的前端。Ubuntu 日常用 ufw 就够；RHEL 系看 `firewall-cmd --list-all`。只有在做网关/NAT/复杂规则时才需要直接写 iptables/nft。

## 6. 代理（环境变量）

```bash
export http_proxy=http://127.0.0.1:7890
export https_proxy=http://127.0.0.1:7890
export no_proxy=localhost,127.0.0.1,.internal.example.com    # 这些不走代理
```

**注意**：

- 变量名**大小写都认**（`HTTP_PROXY` 也被 curl/wget 认）——但 `HTTP_PROXY` 在某些 CGI 环境有安全问题，推荐小写
- `no_proxy` 别忘——不然本机/内网服务也会被绕去代理（排查"本地接口连不上"时先看这个）
- 只对当前 shell 生效；要持久化写进 `~/.bashrc`（或系统的 profile）
- 给 apt 单独配代理：`/etc/apt/apt.conf.d/proxy.conf`；给 git：`git config --global http.proxy ...`

## 7. 排查套路（自下而上）

```
1. ip link               网卡 UP 吗？
2. ip addr               有 IP 吗？（169.254.x.x = DHCP 失败）
3. ip route              有默认网关吗？
4. ping <网关>            局域网通吗？
5. ping 8.8.8.8          出网通吗？（不通：路由/网关/防火墙）
6. dig example.com       能解析吗？（不通：DNS 配置）
7. curl/nc host port     应用端口通吗？（不通：服务没起/防火墙）
```

| 症状 | 常见原因 |
|------|---------|
| `Temporary failure in name resolution` | DNS 问题（resolv.conf/resolvectl） |
| `Connection refused` | 服务没启动、只监听 127.0.0.1，或防火墙用 REJECT 返回 RST；DROP 通常表现为 timeout |
| `Connection timed out` | 防火墙/网络不通/端口没开 |
| ping 通但域名不通 | DNS 有问题（不是网络） |
| 本地能通、外部不通 | 服务监听地址（`0.0.0.0` vs `127.0.0.1`）或防火墙 |

```bash
# 查服务监听在哪个地址（0.0.0.0 = 所有网卡；127.0.0.1 = 只有本机能连）
ss -ltnp | grep 8080
```

## 8. 要点回顾

1. **看配置**：`ip -br addr`、`ip route`、`ip -s link`、`ip neigh`、`ethtool`；临时改地址/路由用 `ip addr add`/`ip route add`，持久化用 `nmcli`/netplan；DNS 看 `resolvectl status`（别直接改 resolv.conf）
2. **测连通**：`ping`（ICMP 可能被禁）→ `nc -zv`/`curl` 测 TCP；`curl -w` 看耗时、`--connect-timeout` 限时、`--resolve` 绕 DNS；DNS 细查用 `dig`（`+short`/`@`/`+trace`），TLS 用 `openssl s_client`
3. **查端口**：`ss -ltnp`（监听 + 进程）、`ss -tnp`（已建立）、`ss -s`（连接数）、`ss -tan state time-wait`
4. **抓包**：`tcpdump -i any -nn port N`，`-A` 看内容，`-w` 存文件给 Wireshark
5. **防火墙**：Ubuntu 用 ufw，RHEL 用 `firewall-cmd`（放行 SSH 先于 enable）；iptables/nft 是底层，按需再深入
6. **代理**：`http_proxy`/`https_proxy`/`no_proxy`（别忘 no_proxy）；大小写都认
7. **排查顺序**：网卡 → IP → 网关 → 出网 → DNS → 端口，逐层排
8. **`Connection refused`** 常见于服务没起/只监听本地，也可能是防火墙 REJECT；防火墙 DROP 通常给 timeout
