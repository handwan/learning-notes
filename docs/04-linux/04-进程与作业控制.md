# 进程与作业控制

看进程、管进程（信号、会话与守护进程）、前后台、优先级与调度，以及"谁占了端口/文件"的排查。

## 1. 查看进程

```bash
ps aux                    # BSD 风格：所有进程 + 资源占用（日常最常用）
ps -ef                    # UNIX 风格：所有进程 + PPID（看父子关系）
ps -ef --forest           # 树状显示（谁 fork 了谁）
ps -eo pid,ppid,pcpu,pmem,etime,cmd --sort=-pcpu | head    # 自定义列 + 按 CPU 排序
pstree -p                 # 进程树（带 PID）

pgrep -a nginx            # 按名字找 PID（-a 显示完整命令行）
pgrep -f "python.*train"  # 按完整命令行匹配
pgrep -P 1234             # 找某个进程的子进程
pidof nginx               # 按程序名找 PID
```

**`ps aux` 各列**：

| 列 | 含义 |
|----|------|
| `USER` | 属主 |
| `PID` / `PPID` | 进程号 / 父进程号 |
| `%CPU` / `%MEM` | CPU / 内存占用 |
| `VSZ` / `RSS` | 虚拟内存 / 常驻物理内存 |
| `STAT` | 状态（见下） |
| `START` / `TIME` | 启动时间 / 累计 CPU 时间 |
| `COMMAND` | 命令（`[]` 是内核线程） |

**进程状态（STAT）**：

| 状态 | 含义 |
|------|------|
| `R` | 运行/可运行 |
| `S` | 可中断睡眠（等待事件，正常） |
| `D` | **不可中断睡眠**（多在等 IO；杀不掉，先查磁盘/网络） |
| `T` | 被停止（Ctrl+Z 或 SIGSTOP） |
| `Z` | **僵尸**（已结束，等父进程回收） |
| `s` / `l` / `+` | 会话首进程 / 多线程 / 前台进程组（附加标记） |

### top / htop

```bash
top                       # 实时（q 退出）
top -u wang               # 只看某用户
top -p 1234               # 只看某进程
```

**top 里的常用键**：`M` 按内存排序、`P` 按 CPU 排序、`k` 杀进程、`1` 展开每个核、`c` 显示完整命令行、`H` 显示线程。

**看线程**：

```bash
ps -L -p 1234              # 列出该进程的线程（LWP）
top -H -p 1234             # top 按线程显示
ls /proc/1234/task         # 每个线程一个目录
```

**头部信息**：`load average: 1.2, 0.8, 0.5` 是 1/5/15 分钟的平均负载——**相对于核数看**（24 核机器 load 20 不算高；4 核 load 8 就该查了）。`%Cpu(s)` 里 `wa`（IO wait）高说明瓶颈在磁盘。

## 2. PID 与 /proc

```bash
echo $$                   # 当前 shell 的 PID
ps -o ppid= -p $$         # 自己的父进程
cat /proc/1/comm          # PID 1 是啥（systemd）
```

**`/proc/<pid>/` 是进程的"透视窗口"**（虚拟文件，不占磁盘）：

```bash
cat /proc/<pid>/cmdline          # 启动命令（\0 分隔）
tr '\0' ' ' < /proc/<pid>/cmdline   # 转成一行看
cat /proc/<pid>/status           # 状态、内存、uid 等（人可读）
ls -l /proc/<pid>/cwd            # 工作目录（链接到实际路径）
ls -l /proc/<pid>/exe            # 可执行文件路径
ls -l /proc/<pid>/fd/            # 打开的文件描述符（排查"文件被谁占着"）
cat /proc/<pid>/environ          # 环境变量（\0 分隔）
tr '\0' '\n' < /proc/<pid>/environ # 一行一个变量
```

## 3. 信号

**常用信号**：

| 信号 | 编号 | 默认行为 | 说明 |
|------|:---:|---------|------|
| `SIGHUP` | 1 | 终止 | 终端断开；很多服务用它表示"重载配置" |
| `SIGINT` | 2 | 终止 | **Ctrl+C** |
| `SIGQUIT` | 3 | 终止+core | Ctrl+\\ |
| `SIGKILL` | 9 | 终止 | **强杀，不可捕获/忽略** |
| `SIGTERM` | 15 | 终止 | `kill` 的默认信号；可被程序捕获做清理 |
| `SIGSTOP`/`SIGCONT` | 19/18 | 停止/继续 | `SIGSTOP` 不可捕获 |
| `SIGUSR1`/`SIGUSR2` | 10/12 | 终止 | 用户自定义（程序自己解释） |
| `SIGCHLD` | 17 | 忽略 | 子进程状态变化（给父进程） |

```bash
kill <pid>                # 默认发 SIGTERM（15）——先礼
kill -9 <pid>             # SIGKILL——后兵（程序来不及清理，最后手段）
kill -HUP <pid>           # 让服务重载配置（nginx 等支持）
kill -l                   # 列出所有信号

pkill nginx               # 按名字杀（支持 -f 匹配完整命令行）
killall nginx             # 按程序名杀所有同名进程
pkill -u wang sleep       # 限定用户
kill -0 <pid>             # 不发信号，只探测进程在不在（脚本里用）
```

**要点**：

- `kill -0` 返回 0 只说明进程存在且有权限；返回 `EPERM` 表示进程存在但没权限，脚本不能只判断 0/1
- **先 `kill`（TERM）再 `kill -9`**：TERM 给程序清理机会（存盘、断连接）；9 是"直接拔电"
- **9 和 19 不能被程序捕获或忽略**；TERM 可以（程序会先清理再退出）
- **僵尸进程**：子进程结束了但父进程没 `wait` 它——`ps` 里是 `Z`。**杀僵尸没用**（已经死了），要处理父进程：要么让父进程回收，要么杀掉父进程（由 init 接管并收尸）
- 忘了 PID 时：`pgrep -a 名字`

**坑：`pkill -f` 匹配"完整命令行"，会命中调用它的 shell**。`-f` 是拿正则匹配 `/proc/<pid>/cmdline`，所以命令行里含这个串的进程全都中，包括：

- `bash -c 'pkill -f myapp'` 里的那个 bash（它的 cmdline 就是命令文本）
- `timeout` / `xargs` 之类的包装进程
- 脚本自己（`bash deploy-myapp.sh` 的 cmdline 里含 `myapp`）

交互式手敲通常没事（shell 的 cmdline 只是 `bash`），所以这个坑**专在脚本/CI 里发作**。

**防法**：

```bash
pkill -x name              # 只匹配进程名（comm），不碰命令行
pkill -f '[m]yapp'         # 括号技巧：正则匹配目标，但调用者的字面量 "[m]yapp" 匹配不上自己
pgrep -a -f myapp          # 先看会命中谁（注意结果里会包含你自己）
```

更稳的姿势：服务交给 `systemctl stop`；自己的程序用 PID 文件——启动时写 `/run/myapp.pid`，停止/探活都读它（`kill "$(cat /run/myapp.pid)"`）；防"双开"再配一道 `flock -n /run/myapp.lock`（拿不到锁就退出）。

## 4. 会话、进程组与守护进程

**为什么关掉终端进程会死**：内核把同一终端上的一批进程编成**进程组**，终端关闭时向前台进程组发 `SIGHUP`（默认终止）——`nohup`/`setsid` 就是躲它（见下节）。

**孤儿进程**：父进程先退出、子进程还活着——内核把它**过继**给最近的"长辈"（一般是 PID 1），将来由收养者 `wait` 收尸。所以孤儿**无害**：对比之下，僵尸 = 死了没人收，孤儿 = 活着但换了个爹。

**守护进程（daemon）**：脱离终端、后台长驻的进程。经典套路是"主动孤儿化"：

```
fork → 父进程退出（子进程归 init 收养）
     → setsid()（开新会话、脱离控制终端）
     → 重定向 stdin / stdout / stderr
     → 跑主逻辑
```

现在更推荐直接交给 systemd 管（`Type=simple`，见服务篇），手写 daemon 化的场景已经很少。

## 5. 前后台与作业控制

```bash
long_cmd &                # 丢到后台运行（打印 [1] PID）
echo $!                   # 最近一个后台进程的 PID
jobs                      # 看当前 shell 的后台作业
wait                      # 等所有后台作业结束
wait $!                   # 只等最近一个
wait %1                   # 等 1 号作业
fg %1                     # 把 1 号作业调回前台
bg %1                     # 让暂停的作业在后台继续
Ctrl+Z                    # 把当前前台任务挂起（暂停，放进后台）
Ctrl+C                    # 发 SIGINT 终止前台任务
```

**让任务在退出终端后继续跑**：

```bash
nohup long_cmd &                    # 忽略 SIGHUP，登出不断
nohup long_cmd > out.log 2>&1 &     # 顺带把输出重定向（默认写 nohup.out）
disown %1                           # 从作业表移除（不再受终端 HUP 影响）
setsid long_cmd                     # 新会话运行（完全脱离终端）
timeout 30s long_cmd                # 30 秒后发 TERM
timeout -s KILL 10s long_cmd        # 直接 KILL（最后手段）
```

**常驻任务的三种方式**：

| 方式 | 适合 |
|------|------|
| `nohup ... &` | 临时跑一次的长任务 |
| `tmux` / `screen` | 需要回头看的交互任务（推荐，见 Shell 与脚本） |
| **systemd 服务** | 正经的常驻服务（开机自启、崩溃重启、日志入 journal——见服务与定时任务） |

## 6. 优先级与调度类

```bash
nice -n 10 make -j8              # 以较低优先级启动（默认 +10）
sudo nice -n -5 cmd              # 提高优先级（负值要 root；sudo 要放在 nice 前）
renice -n 15 -p 1234             # 改运行中进程的优先级
renice -n 5 -u wang              # 改某用户所有进程
```

**范围 -20（最高）~ 19（最低）**，默认 0。普通用户只能**降低**优先级（调大 nice 值）；编译、备份这类任务用 `nice -n 10` 免得抢交互响应。

**坑**：普通用户执行 `nice -n -5 cmd` 只会打印 `cannot set niceness: Permission denied`，**然后按原优先级照跑，退出码还是 0**——不看输出会以为生效了。确认方式：`ps -o nice= -p <pid>`。

**IO 优先级（ionice）**：

```bash
ionice -c2 -n7 ./backup.sh     # best-effort（-c2），0（高）~7（低）；备份/下载给 7
ionice -c3 ./reindex.sh        # idle：只有没人用 IO 时才跑
ionice -p <pid>                # 查某进程当前设置
```

**实时调度（chrt，了解）**：

```bash
chrt -p <pid>                  # 看进程的调度类与优先级
chrt -f 50 ./control_loop      # SCHED_FIFO（实时类，先来先服务）
chrt -r 10 ./app               # SCHED_RR（实时类，轮转）
```

默认所有进程都是 CFS（`SCHED_OTHER`）。实时类高过一切普通进程，配不好会把系统饿死——只给硬实时场景用，实验时加 `timeout` 兜底。设置实时调度通常需要 root 或 `CAP_SYS_NICE`。

## 7. 排查：谁占了端口 / 文件

```bash
ss -ltnp                  # 监听中的 TCP 端口 + 对应进程（需权限看进程名）
ss -ltnp | grep :8080     # 谁占了 8080
ss -tnp                   # 已建立的 TCP 连接
ss -s                     # 连接数统计（TIME_WAIT 等）
lsof -i :8080             # 同上（另一条路）
lsof -p 1234              # 某进程打开的所有文件
lsof +D /path/to/dir      # 谁在用这个目录（递归，慢）
lsof | grep deleted       # 被删除但还被占用的文件（df 与 du 对不上的原因）
fuser -v 8080/tcp         # 占端口的进程
```

`fuser -k 8080/tcp` 会直接杀进程；先 `-v` 看清是谁。

```bash
# 按资源占用排行的通用写法
ps -eo pid,user,pcpu,pmem,cmd --sort=-pcpu | head -10
ps -eo pid,user,pcpu,pmem,cmd --sort=-pmem | head -10
```

## 8. 要点回顾

1. **`ps aux` 看全局，`ps -ef --forest` 看父子，`ps -L`/`top -H` 看线程**，`top` 实时；load average 要对着核数读
2. **STAT 里 `D` 杀不掉**（等 IO）、`Z` 是僵尸（要处理父进程）
3. **信号：先 TERM 后 KILL**；9/19 不可捕获；HUP 常表示重载
4. **前后台**：`&` 后台、`$!` 取 PID、`jobs`/`fg`/`bg` 切换、`wait $!`/`wait %1` 等待、Ctrl+Z 挂起
5. **登出后继续跑**：`nohup cmd > log 2>&1 &`（临时）→ 正经服务用 systemd
6. **nice 越小越优先**（-20~19）；普通用户只能调低优先级；提高优先级要 `sudo nice -n -5 cmd`
7. **占端口/文件**：`ss -ltnp` 看监听、`ss -tnp` 看已建立、`lsof -i :端口`、`lsof | grep deleted`
8. `/proc/<pid>/` 是排查利器：`cmdline`/`cwd`/`fd`/`environ`
9. **孤儿 vs 僵尸**：孤儿换爹无害、僵尸要父进程 `wait`；守护进程化 = fork + setsid + 重定向（现在交给 systemd）
10. **调度三件**：nice 管优先级、ionice 管 IO、chrt 管实时类（通常要 root / `CAP_SYS_NICE`）
11. **超时兜底**：`timeout 30s cmd`；强制结束用 `timeout -s KILL 10s cmd`
