# 软件包与构建环境

apt 装包、源码编译、多版本切换，以及部署最容易踩的"找不到动态库"。

## 1. apt / dpkg

```bash
sudo apt update                 # 更新软件源索引（装东西前先做）
sudo apt upgrade                # 升级已安装的包
sudo apt install nginx          # 安装
sudo apt remove nginx           # 卸载（保留配置）
sudo apt purge nginx            # 卸载 + 删配置
sudo apt autoremove             # 清理不再需要的依赖

apt search nginx                # 搜索
apt show nginx                  # 看包信息（版本/依赖/大小）
apt list --installed            # 已装的包
apt list --upgradable           # 可升级的包
```

脚本/CI 里更常用 `apt-get`：它的输出和参数更稳定；`apt` 主要面向交互。

**dpkg（底层工具，管本地包）**：

```bash
dpkg -l | grep nginx            # 已装包列表
dpkg -L nginx                   # 这个包装了哪些文件到哪
dpkg -S /usr/sbin/nginx         # 这个文件属于哪个包（反向查询）
                                # 注意：/bin 是 /usr/bin 的软链接，查的时候要用真实路径
sudo dpkg -i pkg.deb            # 装本地 deb（缺依赖时用下面这条修）
sudo apt --fix-broken install   # 修依赖
```

**版本、锁定与包内容**：

```bash
apt-cache policy nginx          # 候选版本、已装版本、源优先级
apt-cache depends nginx         # 依赖谁
apt-cache rdepends libfoo       # 谁依赖它
sudo apt-mark hold nginx        # 锁定版本，不让 upgrade 动它
apt-mark showhold               # 看当前锁定的包
sudo apt-mark unhold nginx      # 解除
dpkg -s nginx                   # 包状态/版本/依赖
dpkg -c pkg.deb                 # 看 deb 里有哪些文件
sudo dpkg --audit               # 检查半安装/损坏的包
apt-get source nginx            # 下源码（源里要启用 deb-src）
sudo apt install apt-file && sudo apt-file update
apt-file search libfoo.so       # 哪个包提供这个文件
```

**常见报错**：

| 报错 | 原因 / 处理 |
|------|------------|
| `Could not get lock /var/lib/dpkg/lock` | 另一个 apt/dpkg 在跑：先 `ps` / `lsof` 找进程并等它；不要直接删锁。确认没有进程后 `sudo dpkg --configure -a`，锁文件残留再处理 |
| `Unmet dependencies` | `sudo apt --fix-broken install` |
| `NO_PUBKEY` / GPG error | 按源文档装 keyring；当前做法是 `gpg --dearmor` 到 `/usr/share/keyrings/`，源里写 `signed-by=...`；`apt-key` 已废弃 |
| `404` | 源地址过期（发行版升级后常见）→ 改 `/etc/apt/sources.list.d/` |

### 软件源与镜像

```bash
ls /etc/apt/sources.list.d/     # Ubuntu 24.04 用 .sources 格式（deb822）
cat /etc/apt/sources.list.d/ubuntu.sources
```

换成国内镜像（清华/中科大）后 `sudo apt update` 会快很多。**PPA**：`sudo add-apt-repository ppa:xxx/yyy`（第三方源，装完同样要 update）。

## 2. 源码编译安装

```bash
sudo apt install build-essential cmake ninja-build   # 编译工具链

# 经典三步
./configure --prefix=/usr/local        # 检查环境 + 生成 Makefile
make -j$(nproc)                        # 编译（并行）
sudo make install                      # 装到 prefix 下（bin/lib/include）

# 卸载？Makefile 有 uninstall 才行；否则只能手动删 prefix 里的文件
```

**要点**：

- `--prefix=/usr/local` 是默认习惯（不动系统包）；想隔离就 `--prefix=/opt/xxx` 或 `$HOME/.local`
- 装到 `/usr/local` 后命令能否直接跑，取决于 PATH 顺序（`/usr/local/bin` 通常在前）
- 现在更推荐用项目的构建系统（CMake/Meson）而不是裸 configure；构建方法看项目 README
- 编译加速：`ccache`（缓存编译结果）、`-j$(nproc)`

## 3. 多版本共存与切换

```bash
# gcc/g++/clang/python 的版本切换：update-alternatives
sudo update-alternatives --install /usr/bin/gcc gcc /usr/bin/gcc-13 100
sudo update-alternatives --install /usr/bin/gcc gcc /usr/bin/gcc-14 50
sudo update-alternatives --config gcc        # 交互选择（优先级高的默认）
update-alternatives --display gcc            # 看当前链接与候选
```

**手动方式**：把想要的版本目录放进 `PATH` 前面（`~/.local/bin`、`/usr/local/bin` 通常已优先于 `/usr/bin`）。Python 用 venv/conda（见 Python 章），别动系统 Python。

## 4. 动态库加载路径

**编译期 vs 运行期**：`LIBRARY_PATH` 给链接器找 `-lfoo`；`LD_LIBRARY_PATH` 给动态加载器在运行时找 `.so`，两者不是一回事。

**程序启动时怎么找 `.so`**：先看 ELF 里的 `RPATH/RUNPATH`，再看 `LD_LIBRARY_PATH`、`/etc/ld.so.cache`（由 `ldconfig` 生成）、`/lib`、`/usr/lib`。

```bash
ldd ./server                          # 看依赖哪些 .so（有 not found 就是问题）
ldd ./server | grep "not found"
ldconfig -p | grep libfoo             # 查系统库缓存里有没有
echo $LD_LIBRARY_PATH                 # 临时路径（会话级）
readelf -d ./server | grep -i path    # 看 ELF 里的 RPATH/RUNPATH
```

**三种解法**：

| 方式 | 怎么做 | 特点 |
|------|--------|------|
| `LD_LIBRARY_PATH` | `export LD_LIBRARY_PATH=/opt/foo/lib:$LD_LIBRARY_PATH` | 临时/启动脚本里用；**会被继承、优先级高，别滥用** |
| 系统配置（推荐） | 写 `/etc/ld.so.conf.d/foo.conf`（内容是库目录）→ `sudo ldconfig` | 全局永久；`ldconfig -p` 能查到 |
| 编译期 rpath | 链接时加 `-Wl,-rpath,'$ORIGIN/lib'` | 程序自带查找路径，适合打包分发（`$ORIGIN` = 可执行文件所在目录） |

**排查套路**：

```bash
ldd ./server | grep "not found"       # 1. 谁缺了
find / -name 'libfoo.so*' 2>/dev/null # 2. 它在哪
export LD_LIBRARY_PATH=/path/to/lib   # 3. 临时验证
sudo ldconfig                         # 4. 配好后刷新缓存
LD_DEBUG=libs ./server 2>&1 | head    # 5. 还不行：打开加载日志看它搜了哪些目录
```

## 5. 常用开发环境安装

```bash
# C++ 工具链
sudo apt install build-essential gdb cmake ninja-build ccache clang clangd clang-format clang-tidy
# 性能/调试
sudo apt install linux-tools-common linux-tools-$(uname -r) sysstat strace ltrace valgrind
# 常用小工具
sudo apt install tree ripgrep fd-find jq htop tmux ncdu
```

（装不上 `linux-tools-*` 时 perf 可能受限；perf 的用法见[系统观测与调优](12-系统观测与调优.md)。Ubuntu 的 `fd-find` 包命令名是 `fdfind`，需要的话自己建个 `fd` 别名。）

## 6. 内核模块（了解）

```bash
lsmod                      # 已加载的模块（kvm、nvidia、overlay、nf_conntrack…）
modinfo nvidia             # 模块信息：路径、参数、依赖
sudo modprobe overlay      # 加载模块（-r 卸载）
# 开机自动加载：写 /etc/modules-load.d/xxx.conf（一行一个模块名）
dmesg | grep -i module     # 加载失败时看内核日志
```

驱动类问题（显卡、文件系统、虚拟化）第一步先确认"模块加载了没"。

## 7. 要点回顾

1. **apt 管一切**：`update` 更新索引 → `install`；`dpkg -S/-L` 做反向查询（这个文件属于哪个包 / 这个包装了什么）；`apt-mark hold` 锁版本，`apt-cache policy` 看候选版本；依赖用 `apt-cache depends/rdepends`，坏包用 `dpkg --audit`
2. **源/镜像**配好再装，`404`/GPG 错误基本都是源的问题；GPG 用 `signed-by` keyring，`apt-key` 已废弃
3. **源码编译三步**：`configure --prefix` → `make -j` → `make install`；卸载麻烦，优先用包管理或项目自带构建
4. **多版本**：`update-alternatives` 管理 gcc/clang 等；Python 用 venv
5. **动态库找不到**：`ldd` 定位 → `LD_LIBRARY_PATH` 临时验证 → `/etc/ld.so.conf.d/` + `ldconfig` 永久 → 打包分发用 `-Wl,-rpath,'$ORIGIN/lib'`；编译期找库用 `LIBRARY_PATH`，不是 `LD_LIBRARY_PATH`
6. **`LD_DEBUG=libs`** 是排查加载路径的杀手锏
7. **内核模块**：`lsmod` 看已加载、`modprobe` 装/卸、`dmesg` 看报错
