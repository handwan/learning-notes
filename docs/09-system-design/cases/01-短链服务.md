# 短链服务

把前面的方法落到一个具体系统：短链服务。

目标不是“设计一个像大厂”的系统，而是展示：

```text
需求 → 约束 → 容量 → API → 数据 → 缓存 → 安全 → 失败 → SLO → 演进
```

所有数字都是示例假设，不是实际业务数据。

## 1. 需求

### 功能

- 创建短链：长 URL → 短码
- 访问短码：302 跳转到原 URL
- 支持自定义别名（可选）
- 支持过期时间
- 创建者查看点击统计
- 管理员封禁滥用链接

### 非功能

| 维度 | 目标 |
|---|---|
| 读延迟 | 跳转 p95 < 50ms |
| 写延迟 | 创建 p95 < 200ms |
| 可用性 | 99.9% |
| 一致性 | 创建后立即可跳转；统计可最终一致 |
| 规模 | 100 万新链/天，5000 万跳转/天 |
| 保留 | 5 年 |
| 安全 | 防开放重定向、滥用、越权 |
| 成本 | 小团队可维护 |

### 非目标

- 第一版不做多地域
- 不做自定义域名
- 不做复杂分析后台
- 不承诺 99.99%
- 不支持超过 2048 字符的 URL

## 2. 容量

沿用[需求、约束与容量估算](../fundamentals/02-需求与容量估算.md)的假设：

| 指标 | 结果 |
|---|---:|
| 峰值总 QPS | 1770.8 |
| 原始存储 | 509.9 GiB |
| 3 副本 + 索引 | 2.24 TiB |
| 缓存 | 2.79 GiB |
| 回源读 | 173.6 QPS |
| 峰值带宽 | 1.81 MB/s |
| 并发（50ms） | 88.5 |
| 应用节点 | 1（N+1=2） |

结论：

- 读多写少，缓存/读副本有价值
- 容量不是瓶颈，复杂度和安全更关键
- 第一版不需要分片

容量计算器不是压测；上线前要按真实 URL 长度/跳转比例压测。

## 3. 总体结构

第一版：

```text
Client
  → 入口/LB
  → API（创建/查询/统计）
  → Resolver（短码跳转）
  → PostgreSQL
  → Redis（缓存）
  → Queue → Stats Worker → 统计存储
```

形态：

- 模块化单体
- 一个部署单元
- 模块：links、resolver、stats、admin
- 队列只用于点击事件/统计，不阻塞跳转

为什么不直接微服务：

- 团队小
- 领域还在变
- 创建/跳转需要简单事务
- 统计可以异步，不需要拆服务

参考[架构风格](../architecture/01-架构风格.md)和[边界与依赖](../architecture/02-边界与依赖.md)。

## 4. API

### 创建

```http
POST /v1/links
Authorization: Bearer ...
Idempotency-Key: ...
Content-Type: application/json

{"url":"https://example.com/a","expires_at":"2027-01-01T00:00:00Z"}
```

成功：

```json
{
  "id": "lnk_123",
  "short_code": "aB3xK9q",
  "short_url": "https://s.example/aB3xK9q",
  "expires_at": "2027-01-01T00:00:00Z"
}
```

错误：

- `invalid_url`
- `alias_taken`
- `blocked_url`
- `rate_limited`
- `unauthorized`

### 跳转

```http
GET /{short_code}
```

- 302 到原 URL
- 404/410：不存在/过期
- 429：限流
- 503：暂时不可用

### 统计

```http
GET /v1/links/{id}/stats?from=...&to=...
```

按租户/链接授权；统计可最终一致。

API 细节参考[API 与契约](../architecture/03-API与契约.md)。

## 5. 数据模型

```text
links(
  id,
  tenant_id,
  short_code,
  url,
  created_by,
  created_at,
  expires_at,
  status,
  unique(short_code),
  index(tenant_id, created_at),
  index(status, expires_at)
)

clicks(
  id,
  tenant_id,
  link_id,
  clicked_at,
  ip_hash,
  user_agent,
  referer
)
```

设计：

- `short_code` 全局唯一；租户隔离靠 `tenant_id` 查询/授权
- 过期用 `expires_at`，不要只靠定时删除
- 状态：active/blocked/expired
- 点击事件追加写，不进主库热路径
- 统计用聚合表/分析存储

参考[数据建模与存储选型](../data/01-数据建模与存储选型.md)。

## 6. 短码生成

- Base62（a-z A-Z 0-9）
- 7 位约 3.5 万亿组合
- 随机生成 + 唯一索引
- 冲突时重试几次
- 自定义别名要校验保留字/敏感词
- 不要用可预测自增 ID 直接当短码

冲突处理：

```text
generate → insert unique → conflict → retry
```

短码空间足够时，冲突很少；但不能假设永不冲突。

## 7. 读路径

```text
GET /{code}
  → 本地缓存
  → Redis
  → DB
  → 302
```

缓存策略：

- cache-aside
- 热链缓存
- 空值缓存防穿透
- TTL + 主动失效
- 热点 key 本地缓存/副本

跳转用 302：

- 301 会被浏览器长期缓存，统计/封禁/过期难生效
- 302/307 更适合需要控制跳转的场景
- 如果确定永久且不统计，再考虑 301

缓存一致性参考[缓存](../scalability/02-缓存.md)和[缓存一致性](../data/03-缓存一致性.md)。

## 8. 写路径

```text
POST /v1/links
  → 认证/限流
  → 校验 URL
  → 生成短码
  → insert links
  → 失效缓存（如果有）
  → 返回
```

要点：

- 幂等键防重复创建
- URL 规范化（scheme/host/path）
- 唯一索引兜底
- 创建成功后立即可读；缓存可以懒加载
- 统计事件异步，不阻塞创建

## 9. 点击统计

跳转路径不能同步写统计库：

```text
302 → 发点击事件 → 队列 → stats worker → 聚合/分析库
```

允许：

- 统计延迟
- 少量丢失（按业务）
- 重复（用事件 ID 去重）

不允许：

- 统计拖慢跳转
- 统计失败导致跳转失败
- 统计写入打爆主库

## 10. 安全

短链是开放重定向/滥用的高发场景：

- 只允许 `http/https`
- 拒绝 `javascript:`、`data:`、`file:`
- 解析 URL，禁止私网/环回/链路本地/metadata 地址（如果服务会抓取/预览）
- 恶意软件/钓鱼检测（外部服务或名单）
- 租户/用户配额、限流
- 管理员封禁/举报
- 统计/管理接口做资源级授权
- 不信任客户端 tenant
- 日志脱敏

开放重定向不是“只是跳转”：它可被用于钓鱼/绕过信任。

参考[安全与多租户](../architecture/04-安全与多租户.md)。

## 11. 失败模式

| 失败 | 行为 |
|---|---|
| 缓存挂 | 回源 DB；限流/降级 |
| DB 挂 | 缓存命中仍可跳转；miss 返回 503 |
| 短码冲突 | 重试生成 |
| 热 key | 本地缓存/副本/拆分 |
| 统计队列积压 | 跳转不受影响；统计延迟 |
| 统计丢失 | 可接受则告警；不可接受则补偿 |
| 过期/封禁 | 404/410/403，按策略 |
| 恶意 URL | 阻断/封禁/告警 |
| 创建重复 | 幂等键去重 |

不要为了统计/分析牺牲跳转可用性。

## 12. SLO

- 跳转可用性 99.9%
- 跳转 p95 < 50ms
- 创建 p95 < 200ms
- 5xx < 0.1%
- 缓存命中率/回源 QPS
- 统计延迟 < 5min

错误预算、告警、runbook 参考[可观测性与 SLO](../operations/01-可观测性与SLO.md)。

## 13. 演进

第一版：

- 模块化单体
- PostgreSQL + Redis
- 统计异步

按需演进：

1. 读多 → 读副本/本地缓存
2. 热 key → 本地缓存/分片/专用池
3. 写多/存储大 → 按 short_code/tenant 分片
4. 多地域 → 区域化部署/数据复制
5. 统计大 → 独立分析存储

不要第一版就分片/多活；按[演进与技术债](../architecture/05-演进与技术债.md)的触发条件做。

## 14. ADR

### ADR-1：模块化单体

```text
Context：小团队、读多写少、领域还在变
Decision：模块化单体，一个部署单元
Consequences：部署简单、事务简单；扩展需后续拆分
Alternatives：微服务，独立发布但复杂度高
Revisit：团队/发布/故障隔离成为瓶颈
```

### ADR-2：302 跳转

```text
Context：需要统计、封禁、过期控制
Decision：默认 302
Consequences：浏览器不长期缓存，服务端可控
Alternatives：301 永久缓存，省流量但难撤销
Revisit：确定永久且不需要统计
```

### ADR-3：统计异步

```text
Context：跳转是核心路径，统计可延迟
Decision：点击事件入队列，异步聚合
Consequences：统计最终一致；队列需监控
Alternatives：同步写统计，延迟/故障耦合
Revisit：统计需要强实时
```

## 15. 检查清单

- 需求/非目标写了吗？
- 容量假设和峰值对吗？
- API 契约/错误/幂等清楚吗？
- 短码唯一性/冲突处理？
- 读路径缓存/回源/热点？
- 写路径事务/幂等？
- 统计是否异步？
- 开放重定向/SSRF/滥用防了吗？
- 失败时跳转/创建/统计分别怎样？
- SLO/告警/runbook？
- 演进触发条件？

## 16. 要点回顾

1. 短链是读多写少系统，缓存/读副本优先
2. 第一版模块化单体足够，不要先拆微服务
3. 短码全局唯一，随机+唯一索引+冲突重试
4. 302 便于统计/封禁/过期控制
5. 统计异步，不能拖慢跳转
6. 开放重定向/SSRF/滥用是核心安全风险
7. 缓存挂/DB 挂/热点要有降级路径
8. SLO 按跳转/创建/统计分别定
9. 分片/多地域按触发条件演进
10. 设计文档要写 ADR：选择、代价、替代、重审条件
