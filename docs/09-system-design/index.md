# 系统设计

系统设计不是堆中间件，也不是画一堆方框。它要回答：在给定约束下，怎么划边界、选方案、承担代价，并让系统能演进。

## 范围

系统设计和架构经常混用。这里不把两者当互斥概念：架构是系统设计的一部分，关注模块边界、依赖和数据所有权；系统设计还要覆盖容量、存储、一致性、故障、成本和演进。

后面统一用“系统设计”指端到端设计，不把架构单独拆出去。

## 边界

| 属于这里 | 不属于这里 |
|---|---|
| 需求分析、容量估算、边界、依赖 | 某门语言的语法/类库 |
| 架构风格、分布式基础、扩展性/可用性 | 具体框架 API |
| 数据与存储选择、缓存一致性 | 网络协议细节（见计算机基础） |
| 案例、ADR、技术债 | 中间件安装/参数大全（见工具章） |

底层机制见[计算机基础](../02-computer-basics/index.md)；部署与成本见运维章；具体工具见[工具](../05-tools/index.md)。

## 怎么读

1. 先看[系统设计方法](fundamentals/01-系统设计方法.md)和容量估算，建立“问题 → 约束 → 方案”的顺序。
2. 再看架构风格、分布式基础，知道有哪些选项和代价。
3. 按需补缓存、队列、限流、存储等组件。
4. 上线前补可观测性、发布回滚和容灾。
5. 最后用案例把选择串起来，再用 ADR 记录决策。

不先背“微服务、CAP、Redis、Kafka”，先学会判断：当前约束下，什么该用，什么不该用。
