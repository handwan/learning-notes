# 故障、超时与恢复

分布式系统里，失败是常态：

- 网络会慢、会断
- 下游会超时、会返回 5xx
- 队列会积压
- 节点会重启
- 重试会放大流量

故障处理不是“加个 try/catch”，而是设计：

```text
超时 → 重试/不重试 → 幂等 → 熔断/隔离 → 降级 → 恢复/补偿
```

## 1. 先区分失败类型

| 类型 | 例子 | 处理 |
|---|---|---|
| 瞬时故障 | 网络抖动、短暂 503 | 有界重试 + backoff |
| 持久故障 | 依赖宕机、配置错误 | 熔断/降级/告警 |
| 客户端错误 | 400/401/403/404 | 不重试，修正请求 |
| 限流 | 429 | 按 Retry-After 退避 |
| 部分失败 | 多步写一半成功 | 补偿/对账/回滚 |
| 超时 | 不知道成功没成功 | 幂等 + 查询/对账 |
| 数据错误 | 脏数据/坏消息 | 隔离、死信、修复 |

“失败”不是一种东西，不能统一重试。

## 2. 超时

超时要分层：

- 连接超时
- 读/写超时
- 整个请求的 deadline
- 队列等待超时
- 重试后的总预算

原则：

- deadline 从入口传到下游
- 下游超时不能大于上游剩余预算
- 超时要取消/释放资源
- 不要把超时设得极短，制造假失败
- 也不要不设超时，拖死连接池

超时后要问：

```text
请求到底成功了吗？
重试会不会重复写？
能不能查询状态/对账？
```

## 3. 重试

只对**瞬时、幂等**的失败重试：

- 连接失败/超时
- 429
- 502/503/504
- 明确的 retryable 错误

不要重试：

- 400/401/403/404
- 参数/校验错误
- 业务拒绝
- 非幂等写（除非有幂等键）

重试策略：

- 指数退避 + jitter
- 最大次数/最大时间
- 重试预算
- 只重试失败的那一步
- 记录重试原因/次数

## 4. 重试放大

失败率上升时，重试会放大负载：

```text
base 100 QPS，最多 3 次重试
failure 10% → 111 QPS
failure 30% → 142 QPS
failure 50% → 188 QPS
failure 80% → 295 QPS
```

下游已经过载时，无限重试会把小故障变成雪崩。

??? note "代码：retry amplification"
    ```python
    def expected_attempts(base_qps, failure_rate, max_retries):
        total = 0.0
        remaining = float(base_qps)
        for _ in range(max_retries + 1):
            total += remaining
            remaining *= failure_rate
        return total


    def with_retry_budget(base_qps, failure_rate, max_retries, budget_ratio):
        raw = expected_attempts(base_qps, failure_rate, max_retries)
        extra = raw - base_qps
        return base_qps + min(extra, base_qps * budget_ratio)


    if __name__ == "__main__":
        base = 100.0
        max_retries = 3
        budget = 0.10
        print(f"base_qps={base:.0f} max_retries={max_retries} retry_budget={budget:.0%}")
        print("failure  attempts  amplification  with_budget")
        for failure in [0.10, 0.30, 0.50, 0.80]:
            attempts = expected_attempts(base, failure, max_retries)
            capped = with_retry_budget(base, failure, max_retries, budget)
            print(f"{failure:6.0%}  {attempts:8.1f}  {attempts / base:12.2f}x  {capped:10.1f}")
    ```

输出：

```text
base_qps=100 max_retries=3 retry_budget=10%
failure  attempts  amplification  with_budget
   10%     111.1          1.11x       110.0
   30%     141.7          1.42x       110.0
   50%     187.5          1.88x       110.0
   80%     295.2          2.95x       110.0
```

读法：

- 失败率越高，重试放大越明显
- retry budget 把额外尝试封顶，但被封住的请求会失败
- 预算不是“消除故障”，是用可控失败换系统稳定
- 真实系统还要看重试并发、队列、超时和下游容量

## 5. 幂等

写操作重试的前提是幂等：

- 幂等键
- 去重表
- 唯一约束
- 状态机（已支付不能重复支付）
- 版本号/条件更新

超时后不要假设失败；可能已经成功。正确做法：

- 用幂等键重试
- 查询状态
- 对账
- 补偿/回滚

## 6. 熔断

熔断器状态：

```text
closed → 正常放行
open → 直接失败/降级
half-open → 少量试探，成功则恢复
```

按依赖/租户/接口配置，不要全局一个开关。

熔断不是“放弃”，是：

- 快速失败，释放资源
- 防止级联故障
- 给下游恢复时间
- 触发降级/告警

## 7. 隔离和背压

- 线程池/连接池按依赖隔离
- 队列有界，满了拒绝/降级
- 租户配额/舱壁
- 限流/负载丢弃
- 慢消费者 backpressure
- 不要让一个依赖拖垮所有请求

队列不是无限缓冲；积压会把延迟和内存一起拖爆。

## 8. 降级

降级要提前设计：

- 返回缓存/旧数据
- 只读模式
- 部分结果
- 关闭非关键功能
- 转人工/异步
- 明确告诉用户“现在不完整”

降级不是静默返回错数据。要区分：

- 可接受的旧读
- 不可接受的业务错误
- 需要人工/补偿的部分失败

## 9. 恢复

故障后：

- 重启/重连/重建连接池
- 重放队列/死信
- 对账/补偿
- 清理幂等键/临时状态
- 回滚配置/版本
- 复盘：触发条件、检测、影响、改进

恢复步骤要可执行、可验证，不是“再试一次”。

## 10. 观测

至少看：

- 错误率/超时率/重试率
- p95/p99 延迟
- 熔断状态
- 队列长度/积压/死信
- 连接池/线程池
- 下游依赖健康
- 每租户/每依赖分片

trace 要能串起：

```text
request → retry → downstream → timeout/error
```

没有 request_id/trace，跨服务故障很难定位。

## 11. 检查清单

- 失败类型分了吗？
- deadline 是否从入口传下去？
- 哪些错误可重试？
- 写操作幂等吗？
- 重试有 backoff/jitter/上限吗？
- 有 retry budget 吗？
- 熔断/隔离/背压有吗？
- 降级行为定义了吗？
- 恢复/对账/补偿能执行吗？
- 错误/重试/队列有观测吗？

## 12. 常见坑

1. **所有错误都重试**
   参数/权限错误重试没有意义。

2. **无限重试**
   下游过载时放大成雪崩。

3. **没有 jitter**
   大量客户端同时重试，形成尖峰。

4. **重试非幂等写**
   重复下单/扣款。

5. **超时后假设失败**
   请求可能已成功。

6. **熔断器全局一个**
   一个小依赖拖垮全部。

7. **队列无界**
   积压吃内存，延迟失控。

8. **降级返回错数据**
   旧读可以，错误事实不可以。

9. **没有对账/补偿**
   部分失败永远修不回来。

10. **只看平均延迟**
   超时/重试都在尾部。

## 13. 要点回顾

1. 先分失败类型，再决定重试/熔断/降级
2. deadline 要端到端传递，超时要释放资源
3. 只重试瞬时、幂等错误；backoff + jitter + 上限
4. 重试会放大负载，retry budget 用可控失败换稳定
5. 写重试必须幂等；超时不等于失败
6. 熔断/隔离/背压防级联故障
7. 降级要明确可接受的行为，不静默返回错数据
8. 恢复要对账/补偿/重放，不是简单再试
9. 观测错误、重试、熔断、队列和 trace
