# 特征工程与预处理

模型不是只由算法决定。同样的数据，特征怎么进来，往往比换一个模型影响更大。

这篇讲表格数据最常见的一层：

- 先切分，再预处理，避免泄漏
- 缺失值、类别特征、数值缩放
- 特征选择、交互特征
- 用 Pipeline 把预处理和模型绑在一起

示例用 pandas + scikit-learn。如果环境里没有：

```bash
pip install pandas scikit-learn
```

## 1. 先切分，再预处理

最重要的规则：**所有从数据里学到的统计量，只能在训练集上 fit**。

包括：

- 均值、方差、中位数
- 缺失值填充值
- 类别词表、目标编码的均值
- 特征选择的评分

验证集和测试集只能 `transform`，不能参与 `fit`。否则评估会虚高。

先造一份带缺失值的表格数据：

??? note "代码：数据生成"
    ```python
    import numpy as np
    import pandas as pd

    rng = np.random.default_rng(0)
    n = 400

    age = rng.integers(18, 65, n).astype(float)
    income = rng.lognormal(10, 0.5, n)
    city = rng.choice(["A", "B", "C"], n)
    plan = rng.choice(["basic", "pro"], n)

    logit = (
        -0.04 * (age - 40)
        + 0.8 * (plan == "pro")
        - 0.5 * (city == "C")
        + rng.normal(0, 0.5, n)
    )
    churn = (logit > 0).astype(int)

    df = pd.DataFrame({
        "age": age,
        "income": income,
        "city": city,
        "plan": plan,
        "churn": churn,
    })

    df.loc[rng.choice(n, 40, replace=False), "age"] = np.nan
    df.loc[rng.choice(n, 30, replace=False), "city"] = np.nan

    print("shape", df.shape)
    print(df[["age", "city"]].isna().mean().round(3))
    ```

输出：

```text
shape (400, 5)
age     0.100
city    0.075
dtype: float64
```

先用数值特征跑一个最小 Pipeline：

??? note "代码：数值基线"
    ```python
    from sklearn.model_selection import train_test_split
    from sklearn.pipeline import Pipeline
    from sklearn.impute import SimpleImputer
    from sklearn.preprocessing import StandardScaler
    from sklearn.linear_model import LogisticRegression

    X = df[["age", "income"]]
    y = df["churn"]

    Xtr, Xte, ytr, yte = train_test_split(
        X, y, test_size=0.25, stratify=y, random_state=0
    )

    pipe = Pipeline([
        ("imputer", SimpleImputer(strategy="median")),
        ("scaler", StandardScaler()),
        ("clf", LogisticRegression(max_iter=1000)),
    ])
    pipe.fit(Xtr, ytr)
    print("test acc", round(pipe.score(Xte, yte), 3))
    ```

输出：

```text
test acc 0.67
```

`pipe.fit(Xtr, ytr)` 只在训练集上学中位数和均值/方差；`score` 对测试集只做 `transform`。如果先对全量 `X` 做 `fillna` 或 `StandardScaler`，测试集信息就进训练了。

## 2. 缺失值

先问三个问题：

1. 缺失比例多少？
2. 缺失是不是有信息？（比如“没填收入”本身可能和流失相关）
3. 缺失机制是什么？完全随机、和特征相关、还是和标签相关？

常见处理：

| 方法 | 适合 | 注意 |
|---|---|---|
| 删除行/列 | 缺失很少，或列几乎全空 | 可能丢样本/丢信息 |
| 均值/中位数 | 数值特征，快速基线 | 会缩小方差，扭曲分布 |
| 众数 | 类别特征 | 类别不平衡时可能全填多数类 |
| 常数 | “缺失”本身有意义 | 常配合缺失指示变量 |
| KNN / 迭代填充 | 特征相关性强 | 更贵，必须在训练集上 fit |
| 树模型原生缺失 | XGBoost/LightGBM 等 | 不是所有实现都支持 |

数值中位数填充：

??? note "代码：缺失值"
    ```python
    from sklearn.impute import SimpleImputer

    imp = SimpleImputer(strategy="median")
    Xtr_age = imp.fit_transform(Xtr[["age"]])
    Xte_age = imp.transform(Xte[["age"]])

    print("median", imp.statistics_)
    print("remaining", int(np.isnan(Xte_age).sum()))
    ```

输出：

```text
median [42.]
remaining 0
```

如果缺失本身有信息，加上指示变量：

```python
imp = SimpleImputer(strategy="median", add_indicator=True)
```

类别特征常用 `strategy="most_frequent"` 或 `strategy="constant", fill_value="missing"`。不要把“缺失”直接当成一个普通类别，除非你确认它在业务上有意义。

## 3. 类别特征

类别特征不能直接当连续数喂给线性模型。常见编码：

| 方法 | 适合 | 风险 |
|---|---|---|
| One-hot | 低基数、无序类别 | 高基数会维度爆炸 |
| Ordinal | 有序类别（低/中/高） | 无序类别会引入假顺序 |
| Target / mean encoding | 高基数 | 泄漏标签，必须 out-of-fold |
| Hashing | 超高基数、流式数据 | 不可逆，可能碰撞 |
| 频率编码 | 高基数 | 只保留频次信息 |

One-hot：

??? note "代码：One-hot"
    ```python
    from sklearn.preprocessing import OneHotEncoder

    cat = pd.DataFrame({
        "city": ["A", "B", "A", "C", "B"],
        "plan": ["basic", "pro", "pro", "basic", "basic"],
    })

    enc = OneHotEncoder(handle_unknown="ignore", sparse_output=False)
    Z = enc.fit_transform(cat)

    print("shape", Z.shape)
    print(list(enc.get_feature_names_out()))
    ```

输出：

```text
shape (5, 5)
['city_A', 'city_B', 'city_C', 'plan_basic', 'plan_pro']
```

不同 scikit-learn 版本的列名格式可能略有差异，形状和编码含义不变。

`handle_unknown="ignore"` 很重要：线上出现训练集没见过的类别时，不会直接报错，而是编码成全 0。

高基数类别（用户 ID、商品 ID、地区）不要 one-hot。target encoding 的简化版：

??? note "代码：Target encoding"
    ```python
    train = pd.DataFrame({
        "city": ["A", "A", "B", "B", "C", "C"],
        "y": [1, 0, 1, 1, 0, 0],
    })
    valid = pd.DataFrame({"city": ["A", "B", "D"]})

    def target_encode(train, valid, col, target, smoothing=2):
        stats = train.groupby(col)[target].agg(["mean", "count"])
        prior = train[target].mean()
        enc = (
            stats["mean"] * stats["count"] + prior * smoothing
        ) / (stats["count"] + smoothing)
        return train[col].map(enc).fillna(prior), valid[col].map(enc).fillna(prior)

    tr_enc, va_enc = target_encode(train, valid, "city", "y")
    print("train", tr_enc.round(3).tolist())
    print("valid", va_enc.round(3).tolist())
    ```

输出：

```text
train [0.5, 0.5, 0.75, 0.75, 0.25, 0.25]
valid [0.5, 0.75, 0.5]
```

这里用训练集统计量，验证集只做映射；没见过的 `D` 回退到先验均值。真实数据上还要做 out-of-fold：每一折用其他折的标签算编码，避免当前折标签泄漏进特征。

## 4. 数值特征

数值特征常见问题：尺度差太大、长尾、异常值。

| 缩放 | 公式 | 适合 |
|---|---|---|
| StandardScaler | `(x-μ)/σ` | 线性模型、神经网络、PCA |
| MinMaxScaler | `(x-min)/(max-min)` | 需要固定区间，如图像 |
| RobustScaler | `(x-median)/IQR` | 异常值多 |
| 不缩放 | 原值 | 树模型、GBDT |

??? note "代码：数值特征"
    ```python
    from sklearn.preprocessing import StandardScaler, MinMaxScaler, RobustScaler

    x = df["income"].to_numpy().reshape(-1, 1)

    for name, scaler in [
        ("standard", StandardScaler()),
        ("minmax", MinMaxScaler()),
        ("robust", RobustScaler()),
    ]:
        z = scaler.fit_transform(x)
        print(name, round(float(z.min()), 2), round(float(z.max()), 2),
              round(float(z.mean()), 2), round(float(z.std()), 2))
    ```

输出：

```text
standard -1.63 5.89 -0.0 1.0
minmax 0.0 1.0 0.22 0.13
robust -1.16 5.27 0.23 0.86
```

长尾分布（收入、点击量、停留时长）可以先做 `log1p`：

```python
df["income_log"] = np.log1p(df["income"])
```

树模型不需要缩放，但长尾和异常值仍可能影响分裂；可以先看分布，不要盲目套 `StandardScaler`。

## 5. 特征选择

特征太多会带来过拟合、训练慢、解释困难。三类方法：

| 类型 | 例子 | 特点 |
|---|---|---|
| Filter | 方差、相关系数、互信息 | 快，但不看模型 |
| Wrapper | RFE、前向/后向选择 | 更贴近模型，计算贵 |
| Embedded | L1、树重要性 | 训练时顺便选择 |

特征选择必须放进交叉验证：

- 错误：先在全量数据上选 20 个特征，再 CV
- 正确：每一折内部重新选特征

否则验证折的标签已经参与特征选择，CV 会虚高。第 3 篇的泄漏实验就是这个问题。

一个把选择器放进 Pipeline 的写法：

??? note "代码：特征选择"
    ```python
    from sklearn.feature_selection import SelectKBest, f_classif

    # 片段：Pipeline / SimpleImputer / StandardScaler / LogisticRegression 已定义
    sel = Pipeline([
        ("imputer", SimpleImputer(strategy="median")),
        ("scaler", StandardScaler()),
        ("select", SelectKBest(f_classif, k=1)),
        ("clf", LogisticRegression(max_iter=1000)),
    ])
    ```

`SelectKBest` 在 `fit` 时只看训练折，`transform` 时应用到验证折。

## 6. 交互与领域特征

模型不会自动知道“单价 = 总价 / 数量”“小时是循环的”。这些特征要人来造：

- 比值/差值：客单价、停留时长、转化率
- 聚合：用户历史均值、最近 7 天计数
- 时间：小时、星期、是否节假日
- 周期：`sin(2πh/24)`、`cos(2πh/24)`
- 文本：长度、词数、TF-IDF
- 交互：`PolynomialFeatures`、两两乘积

多项式交互容易爆炸：

```python
from sklearn.preprocessing import PolynomialFeatures

poly = PolynomialFeatures(degree=2, include_bias=False)
Z = poly.fit_transform(Xtr[["age", "income"]].fillna(Xtr[["age", "income"]].median()))
print("shape", Z.shape)
```

输出：

```text
shape (300, 5)
```

两个特征、二次交互只有 5 列；十个特征就会到 65 列。先想业务含义，再决定要不要加。

## 7. 完整 Pipeline

把数值和类别一起处理：

??? note "代码：完整 Pipeline"
    ```python
    from sklearn.compose import ColumnTransformer
    from sklearn.pipeline import Pipeline
    from sklearn.impute import SimpleImputer
    from sklearn.preprocessing import OneHotEncoder, StandardScaler
    from sklearn.linear_model import LogisticRegression
    from sklearn.model_selection import train_test_split, cross_val_score

    X = df[["age", "income", "city", "plan"]]
    y = df["churn"]
    Xtr, Xte, ytr, yte = train_test_split(
        X, y, test_size=0.25, stratify=y, random_state=0
    )

    num_cols = ["age", "income"]
    cat_cols = ["city", "plan"]

    num_pipe = Pipeline([
        ("imputer", SimpleImputer(strategy="median")),
        ("scaler", StandardScaler()),
    ])
    cat_pipe = Pipeline([
        ("imputer", SimpleImputer(strategy="most_frequent")),
        ("onehot", OneHotEncoder(handle_unknown="ignore")),
    ])

    pre = ColumnTransformer([
        ("num", num_pipe, num_cols),
        ("cat", cat_pipe, cat_cols),
    ])

    model = Pipeline([
        ("pre", pre),
        ("clf", LogisticRegression(max_iter=1000)),
    ])

    cv = cross_val_score(model, Xtr, ytr, cv=5)
    model.fit(Xtr, ytr)

    print("cv", round(float(cv.mean()), 3), "std", round(float(cv.std()), 3))
    print("test", round(float(model.score(Xte, yte)), 3))
    print("features", len(model.named_steps["pre"].get_feature_names_out()))
    ```

输出：

```text
cv 0.78 std 0.029
test 0.85
features 7
```

`ColumnTransformer` 让数值列走“中位数 + 标准化”，类别列走“众数 + one-hot”；`Pipeline` 保证交叉验证时每一折都重新 fit 预处理器。

训练完把整个 Pipeline 存下来，而不是只存分类器：

```python
import joblib

joblib.dump(model, "feature_pipeline.joblib")
loaded = joblib.load("feature_pipeline.joblib")
print("reload", round(float(loaded.score(Xte, yte)), 3))
```

输出：

```text
reload 0.85
```

推理时直接 `loaded.predict(raw_df)`，预处理会自动跟着走，不会出现训练和线上两套逻辑。

## 8. 常见坑

1. **先预处理再切分**
   均值、方差、缺失值填充值、编码词表都会泄漏测试集信息。

2. **Target encoding 不用 out-of-fold**
   当前折的标签进入特征，CV 会虚高。

3. **One-hot 高基数**
   用户 ID、商品 ID 动辄几万类，one-hot 直接维度爆炸；用 target/hashing/embedding。

4. **无序类别用 Ordinal**
   把“红/绿/蓝”编码成 0/1/2，模型会误以为有大小关系。

5. **对树模型强行标准化**
   不是错，但通常没必要；树只看分裂点，不看尺度。

6. **缺失值全填 0**
   0 可能是一个合法值；填 0 会把“缺失”和真实 0 混在一起。

7. **训练/推理预处理不一致**
   训练用 Pipeline，线上手写 `fillna`/`scale`，分布很容易偏。

8. **特征选择放在 CV 外**
   先用全量标签选特征，再 CV，是最常见的泄漏之一。

9. **把 ID 当特征**
   除非 ID 本身有业务含义；否则模型会记住 ID，而不是学规律。

10. **交互特征加太猛**
    两两交互、三阶多项式会让特征数爆炸，小数据上更容易过拟合。

11. **不看分布漂移**
    训练时收入均值 2 万，线上变成 5 万；预处理器和模型都可能失效。

12. **只保存模型，不保存预处理器**
    只存 `model.pkl` 不存 scaler/encoder，推理时输入对不上。

## 9. 检查清单

1. 先切分了吗？测试集有没有参与任何 `fit`？
2. 缺失值比例和缺失机制看清了吗？
3. 类别编码和基数匹配吗？线上新类别怎么办？
4. 数值特征需要缩放吗？长尾/异常值处理了吗？
5. 特征选择在 CV 内部吗？
6. 交互特征有业务含义吗？维度可控吗？
7. 预处理和模型是否在同一个 Pipeline 里？
8. 保存的是整个 Pipeline，而不只是分类器吗？

## 10. 要点回顾

1. **先切分，再预处理**；所有统计量只在训练集 `fit`
2. 缺失值：删除、均值/中位数/众数、模型填充；有信息时加缺失指示
3. 类别：低基数 one-hot，有序用 ordinal，高基数用 target/hashing，并防泄漏
4. 缩放：线性/神经网络/KNN/PCA 需要；树模型通常不需要
5. 特征选择：filter / wrapper / embedded，必须放进交叉验证
6. 交互和领域特征能提升表达，但维度会爆炸
7. 用 `Pipeline` + `ColumnTransformer` 绑定预处理和模型
8. 保存整个 Pipeline，保证训练和推理一致
