# 预训练目标

架构决定“模型长什么样”，预训练目标决定“模型从数据里学什么”。

LLM 主流用的是 **causal next-token prediction**：给定前 $t$ 个 token，预测第 $t+1$ 个。它不是唯一的目标；BERT 的 masked LM、T5 的 span corruption、ELECTRA 的替换检测，都是不同的预训练目标。

这篇讲：

- causal LM 和 masked LM 的数学形式
- encoder-only / decoder-only / encoder-decoder 和目标的关系
- 两种目标的训练信号、生成能力和适用场景
- 一个小语料实验：同一个模型，换目标，cloze 表现差多少
- 为什么现代 LLM 基本选 causal LM

## 1. Causal LM：预测下一个 token

给定序列 $x_1,\dots,x_T$，自回归分解：

$$
p(x)=\prod_{t=1}^{T}p(x_t\mid x_{<t})
$$

损失：

$$
L_{\mathrm{causal}}
=-\frac{1}{T}\sum_{t=1}^{T}\log p(x_t\mid x_{<t})
$$

特点：

- 每个目标都提供监督信号，训练信号密
- 必须用 causal mask，位置 $t$ 只能看它左边的 token，不能看自己和未来
- 训练时可以并行算整条序列的所有位置
- 推理时逐 token 生成，需要 KV cache
- 和生成任务天然对齐

GPT 系列、Llama、Qwen、DeepSeek 的基座模型都用这个目标。

## 2. Masked LM：完形填空

随机遮住一部分 token，让模型用左右上下文还原：

$$
L_{\mathrm{MLM}}
=-\frac{1}{|M|}\sum_{t\in M}\log p(x_t\mid x_{\setminus M})
$$

- $M$：被遮住的位置集合
- 只对被遮住的位置算 loss
- 没有 causal mask，左右都能看
- BERT 常用 15% 的 mask 比例
- BERT 的 80/10/10：80% 换成 `[MASK]`，10% 换随机 token，10% 保持不变

特点：

- 双向上下文，适合理解类任务
- 训练信号只来自被遮住的位置，密度低于 causal LM
- 不能直接做自回归生成
- 预训练有 `[MASK]`，下游任务没有，存在 pretrain-finetune 不一致

BERT、RoBERTa 属于这一类；ELECTRA 用替换检测，是相关但不同的目标。

## 3. Encoder-only、Decoder-only、Encoder-Decoder

| 结构 | 注意力 | 典型目标 | 适合 |
|---|---|---|---|
| Encoder-only | 双向 | masked LM | 分类、抽取、embedding |
| Decoder-only | causal | next-token | 生成、LLM |
| Encoder-Decoder | 编码器双向 + 解码器 causal | span corruption / seq2seq | 翻译、摘要、T5 |

### Encoder-only

BERT 是代表：

- 双向 self-attention
- 输出每个位置的表示
- 加一个 `[CLS]` 做分类
- 不能直接生成

### Decoder-only

GPT/LLM 是代表：

- causal self-attention
- 每个位置预测下一个 token
- 天然支持生成
- 训练目标、推理过程、产品形态一致

### Encoder-Decoder

T5/BART 是代表：

- encoder 看完整输入
- decoder 因果生成输出
- 中间有 cross-attention
- 适合输入输出结构不同的任务

## 4. 其他预训练目标

| 目标 | 做法 | 代表 |
|---|---|---|
| Span corruption | 遮住连续 span，decoder 还原 | T5 |
| Prefix LM | 前缀双向，后缀 causal | UniLM、部分对话模型 |
| Permutation LM | 按随机排列分解序列 | XLNet |
| Replaced token detection | 判断每个 token 是否被替换 | ELECTRA |
| Multi-token prediction | 一次预测未来多个 token | 部分新模型 |

这些目标各有取舍。对通用 LLM 来说，causal next-token 仍是主流，因为：

- 训练和生成一致
- 每个位置都有监督
- 实现简单，扩展性好
- 可以直接用 KV cache 做流式生成

## 5. 训练信号与成本

### Causal LM

- 序列长度 $T$，通常有 $T-1$ 个 next-token 目标；加 BOS 并预测首 token 时才是 $T$ 个
- 每个位置都算 loss
- 一次前向可以并行算所有位置
- 生成时必须逐 token

### Masked LM

- 序列长度 $T$，通常只 mask 15%
- 一次前向仍然要看整条序列
- 只有被 mask 的位置算 loss
- 不能直接生成；要做生成得另外加 decoder

所以不能只看“谁的 loss 更低”。MLM 的 loss 只对被 mask 的位置求平均（BERT 常用 15%，本文实验用 25% 放大信号），causal 对所有目标位置求平均，两个数不可直接比较。

## 6. 一个小实验：causal vs masked

为了控制变量，用同一个 Transformer 编码器：

- 4 个符号的 palindrome 语料，长度 8
- 例如 `a b c d d c b a`
- 前半段随机，后半段是前半段的镜像
- 同一个模型、同样参数量、同样训练步数
- 一个用 causal mask + next-token loss
- 一个用双向 mask + masked LM loss

评估“前半段 cloze”：

- causal 模型只能用左边前缀预测
- MLM 模型可以看右边镜像

??? note "代码：一个小实验：causal vs masked"
    ```python
    import torch
    import torch.nn as nn
    import torch.nn.functional as F

    torch.manual_seed(0)

    def make_palindromes(n, half=4, vocab=4):
        left = torch.randint(0, vocab, (n, half))
        return torch.cat([left, left.flip(1)], dim=1)

    train = make_palindromes(2000)
    val = make_palindromes(200)
    V = 4

    class TinyEncoder(nn.Module):
        def __init__(self, vocab, d=64, nhead=4, layers=2, max_len=8):
            super().__init__()
            self.tok = nn.Embedding(vocab + 1, d)
            self.pos = nn.Embedding(max_len, d)
            layer = nn.TransformerEncoderLayer(
                d_model=d, nhead=nhead, dim_feedforward=4 * d,
                dropout=0.0, activation="gelu",
                batch_first=True, norm_first=True,
            )
            self.enc = nn.TransformerEncoder(layer, layers, enable_nested_tensor=False)
            self.head = nn.Linear(d, vocab)

        def forward(self, x, causal=False):
            B, T = x.shape
            pos = torch.arange(T, device=x.device)
            h = self.tok(x) + self.pos(pos)[None]
            mask = None
            if causal:
                mask = torch.triu(torch.ones(T, T, dtype=torch.bool, device=x.device), diagonal=1)
            h = self.enc(h, mask=mask)
            return self.head(h)

    def train_causal(steps=400, bs=64, lr=1e-3):
        torch.manual_seed(0)
        model = TinyEncoder(V)
        opt = torch.optim.AdamW(model.parameters(), lr=lr)
        for _ in range(steps):
            idx = torch.randint(0, len(train), (bs,))
            x, y = train[idx, :-1], train[idx, 1:]
            loss = F.cross_entropy(model(x, causal=True).reshape(-1, V), y.reshape(-1))
            opt.zero_grad()
            loss.backward()
            opt.step()
        return model, loss.item()

    def train_mlm(steps=400, bs=64, lr=1e-3, mask_prob=0.25):
        torch.manual_seed(0)
        model = TinyEncoder(V)
        opt = torch.optim.AdamW(model.parameters(), lr=lr)
        for _ in range(steps):
            idx = torch.randint(0, len(train), (bs,))
            x = train[idx]
            mask = torch.rand(x.shape) < mask_prob
            inp = x.clone()
            inp[mask] = V
            loss = F.cross_entropy(model(inp)[mask], x[mask])
            opt.zero_grad()
            loss.backward()
            opt.step()
        return model, loss.item()

    def eval_next(model, data):
        with torch.no_grad():
            logits = model(data[:, :-1], causal=True)
        return (logits.argmax(-1) == data[:, 1:]).float().mean().item()

    def eval_causal_cloze(model, data, half=4):
        correct = total = 0
        for i in range(1, half):
            with torch.no_grad():
                pred = model(data[:, :i], causal=True)[:, -1, :].argmax(-1)
            correct += (pred == data[:, i]).sum().item()
            total += len(data)
        return correct / total

    def eval_mlm_cloze(model, data, half=4):
        correct = total = 0
        for i in range(1, half):
            inp = data.clone()
            inp[:, i] = V
            with torch.no_grad():
                pred = model(inp)[:, i, :].argmax(-1)
            correct += (pred == data[:, i]).sum().item()
            total += len(data)
        return correct / total

    causal, causal_loss = train_causal()
    mlm, mlm_loss = train_mlm()

    print("causal loss", round(causal_loss, 4),
          "next_acc", round(eval_next(causal, val), 3),
          "cloze_first_half", round(eval_causal_cloze(causal, val), 3))
    print("mlm loss", round(mlm_loss, 4),
          "cloze_first_half", round(eval_mlm_cloze(mlm, val), 3))
    ```

输出：

```text
causal loss 0.5979 next_acc 0.685 cloze_first_half 0.265
mlm loss 0.4523 cloze_first_half 1.0
```

读法：

- causal 的 next-token 准确率 `0.685`：后半段镜像能学会，前半段随机，拉低平均
- causal 的前半段 cloze `0.265`，接近 4 类随机猜的 `0.25`
- MLM 的前半段 cloze `1.0`：它能看到后半段镜像
- MLM 的 loss 更低，但只对 25% 的 mask 位置求平均；不要和 causal loss 直接比

这个实验故意把“未来信息”做成镜像，放大了双向上下文的优势。真实语言不是回文；MLM 在理解类任务上强，不代表它适合生成。

## 7. 怎么选

| 目标 | 适合 |
|---|---|
| Causal next-token | 通用 LLM、对话、代码生成、长文本生成 |
| Masked LM | 分类、抽取、embedding、NLU |
| Span corruption | 翻译、摘要、seq2seq |
| Replaced token detection | 想用更小算力做预训练 |
| Prefix LM | 输入理解 + 输出生成兼顾 |

现代 LLM 的主线：

- 基座预训练：causal next-token
- 对齐：SFT → 偏好优化
- 推理增强：长 CoT、RLVR、test-time compute

MLM 仍然重要，但更多出现在 encoder、embedding、检索和分类模型里。

## 8. 常见坑

1. **直接比较 MLM loss 和 causal loss**
   分母和位置不同：MLM 只算 mask 位置，causal 算所有位置。

2. **causal mask 漏了**
   模型能看到未来，loss 异常低，生成时又不工作。

3. **MLM mask 比例不当**
   太低信号少，太高上下文不足；15% 是 BERT 的经验值，不是定律。

4. **MLM 的 loss 分母算错**
   只对 mask 位置求平均，不要把所有位置都算进去。

5. **拿 MLM 模型直接生成**
   BERT 没有 causal decoder；它输出的是表示，不是下一个 token 的分布。

6. **`[MASK]` 出现在下游**
   预训练有 mask token，下游没有；微调时要保证输入格式一致。

7. **pad / ignore_index 没处理**
   变长序列的 padding 会拉低 loss 或引入错误梯度。

8. **perplexity 跨 tokenizer 比较**
   PPL 依赖 tokenizer；词表不同，PPL 不可直接比。

9. **以为 objective 能弥补数据问题**
   目标只决定怎么学；数据质量、去重、污染仍然决定上限。

10. **prefix LM 的 mask 写错**
    前缀双向、后缀 causal；两种 mask 拼错会泄漏或限制过头。

11. **multi-token prediction 的 loss 直接复用**
    多个预测头/多个位置的加权方式不同；不能直接套 next-token 的系数。

12. **只看预训练 loss，不看下游**
    loss 降不代表指令跟随、推理、代码能力同步提升；要跑目标任务。

## 9. 要点回顾

1. Causal LM 用自回归分解，每个位置都预测下一个 token
2. Masked LM 遮住部分 token，用左右上下文还原，只算 mask 位置
3. Encoder-only 适合理解，decoder-only 适合生成，encoder-decoder 适合 seq2seq
4. Causal 训练信号密、和生成一致；MLM 双向但信号稀疏
5. MLM 和 causal 的 loss 不可直接比较
6. 现代 LLM 基座基本用 causal next-token
7. 目标、结构、数据、对齐要一起看，不能只换 objective
