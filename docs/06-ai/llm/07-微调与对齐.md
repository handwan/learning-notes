# 微调与对齐

预训练得到的是 base model：它会续写，但不一定会按指令回答。

微调和对齐要解决的是：

- 怎么让模型听懂“任务/指令”
- 怎么让输出更符合人类偏好
- 怎么在有限显存下微调大模型

常见路线：

```text
预训练 → SFT → 偏好优化（RLHF / DPO / ORPO）→ 评测
```

这篇讲 SFT、RLHF、DPO、ORPO，以及 LoRA 这种参数高效微调方法，最后用一个小模型做 LoRA SFT 实验。

## 1. SFT

SFT（supervised fine-tuning）用“指令 + 回答”的配对数据继续训练：

```text
<user>
把这句话翻译成英文：你好
<assistant>
Hello
```

损失通常只算回答部分：

$$
L_{\mathrm{SFT}}
=-\sum_{t\in\text{response}}
\log p_\theta(y_t\mid x,y_{<t})
$$

为什么 mask 掉 prompt：

- prompt 是条件，不是要模型复述的内容
- 只在回答上算 loss，模型更关注“怎么答”
- 长 prompt + 短回答时，不 mask 会让 loss 被 prompt 主导

SFT 的要点：

- 数据格式要统一：system/user/assistant、分隔符、EOS
- 用 tokenizer 的 chat template，不要手拼
- 回答质量比数量重要；低质回答会教坏模型
- 多轮对话要保留角色和轮次
- 训练太久会过拟合固定模板，泛化变差

SFT 不是“教会模型知识”的主要阶段；知识主要来自预训练，SFT 更多是教格式、任务和风格。

## 2. RLHF

RLHF 通常分三步：

1. SFT：先让模型会按指令回答
2. 奖励模型：用人类偏好数据训练一个打分器
3. PPO：用奖励模型优化策略，同时加 KL 约束

目标可以写成：

$$
\max_\pi\;
\mathbb{E}_{x,y\sim\pi}\left[r(x,y)\right]
-\beta\,D_{\mathrm{KL}}\left(\pi(\cdot\mid x)\,\|\,\pi_{\mathrm{ref}}(\cdot\mid x)\right)
$$

- $r$：奖励模型分数
- $\pi_{\mathrm{ref}}$：SFT 模型，防止跑偏
- $\beta$：KL 强度

问题：

- 训练不稳定，超参多
- 奖励模型会被“刷分”（reward hacking）
- 需要在线采样，工程复杂
- 人类偏好有噪声、位置偏差、标注者偏差

RLHF 仍然有用，但它不是唯一方案。

## 3. DPO

DPO（Direct Preference Optimization）直接用偏好对训练，不需要显式奖励模型和 PPO。

数据是三元组：

```text
(x, y_w, y_l)
```

- $x$：prompt
- $y_w$：chosen，更好的回答
- $y_l$：rejected，更差的回答

损失：

$$
L_{\mathrm{DPO}}
=-\log\sigma\left(
\beta\log\frac{\pi_\theta(y_w\mid x)}{\pi_{\mathrm{ref}}(y_w\mid x)}
-\beta\log\frac{\pi_\theta(y_l\mid x)}{\pi_{\mathrm{ref}}(y_l\mid x)}
\right)
$$

直觉：

- 提高 chosen 相对 reference 的概率
- 降低 rejected 相对 reference 的概率
- $\beta$ 控制偏离 reference 的强度
- 不需要奖励模型，训练更像普通监督学习

优点：

- 离线、稳定、实现简单
- 不需要 PPO 的采样和值函数
- 训练成本低

局限：

- 依赖偏好数据质量
- 容易过拟合偏好对
- 仍需要 reference model（显存翻倍）
- 偏好数据覆盖不到的能力，DPO 也学不到

## 4. ORPO

ORPO（Odds Ratio Preference Optimization）把 SFT 和偏好优化合成一个阶段：

$$
L_{\mathrm{ORPO}}=L_{\mathrm{SFT}}+\lambda L_{\mathrm{OR}}
$$

- $L_{\mathrm{SFT}}$：正常的回答监督
- $L_{\mathrm{OR}}$：odds ratio 偏好项
- 不需要单独的 reference model
- 一个阶段同时学“怎么答”和“偏好哪个”

适合显存/流程受限、又想做偏好优化的场景。具体实现和权重要看论文/框架，不同实现的细节会有差异。

## 5. 其他路线

| 方法 | 特点 |
|---|---|
| KTO | 只用“好/坏”标签，不要求成对偏好 |
| IPO | 对 DPO 的偏好建模做正则 |
| SimPO | 用长度归一化的平均 log 概率，减少长度偏置 |
| RLVR | 用可验证奖励（数学答案、代码测试）做 RL |
| GRPO | 组内相对优势，常见于推理模型 |

推理模型（Reasoning）常用 RLVR（见[第 8 篇：推理模型](08-推理模型.md)）：

- 答案可验证：数学、代码、工具调用
- 用规则/测试给奖励，不依赖人类偏好模型
- 长 CoT、test-time compute 和 RLVR 结合

这条线属于[第 8 篇：推理模型](08-推理模型.md)，这里只做定位。

## 6. LoRA / PEFT

全量微调要更新所有参数，还要存梯度、优化器状态。LoRA 冻结原权重，只训练低秩增量：

$$
W'=W+\frac{\alpha}{r}BA
$$

- $W$：冻结的原始权重
- $A\in\mathbb{R}^{r\times d_{in}}$
- $B\in\mathbb{R}^{d_{out}\times r}$
- $r$：秩，通常 4–64
- $\alpha$：缩放，常取 $r$ 的 1–2 倍

可训练参数约：

$$
r(d_{in}+d_{out})
$$

每层相比原矩阵小很多。

实践：

- 常挂在 attention 的 q/k/v/o 和 FFN 上
- `B` 初始化为 0，`A` 随机小值；初始时增量为 0
- 推理时可以合并回 $W$，不增加延迟
- QLoRA：base 用 4-bit 量化，LoRA 仍训练
- LoRA 权重可以单独保存/加载，base 不变

LoRA 不是“免费全量微调”：秩太小、目标模块不对、数据太少，效果都会受限。

## 7. 数据与评测

### SFT 数据

- 指令/回答要成对，格式统一
- 回答质量 > 数量
- 去重、去污染、去低质
- 多轮对话保留角色和轮次
- 训练/验证按对话或用户分组，避免泄漏

### 偏好数据

- chosen/rejected 要针对同一个 prompt
- 标注者偏差、位置偏差要检查
- 安全偏好和有用偏好要分开
- 偏好对数量不需要像 SFT 那么多，但质量要求更高

### 评测

- 留出未见过的指令集
- 任务指标：准确率、通过率、格式合规
- LLM-as-judge 只能做辅助，要校准
- 人工抽检
- 安全/越狱单独评测
- 不要用训练 prompt 评估

## 8. 实验：LoRA SFT 一个小模型

任务：8 条固定的“指令 → 回答”：

```text
copy a   → a
copy cat → cat
upper a  → A
upper cat→ CAT
```

模型是 2 层 TinyLM，词表 14，序列长度 6。LoRA 挂在所有 Linear 上，rank=4，alpha=8。

??? note "代码：实验：LoRA SFT 一个小模型"
    ```python
    import math
    import torch
    import torch.nn as nn
    import torch.nn.functional as F

    torch.manual_seed(0)

    pairs = [
        ("copy a", "a"), ("copy b", "b"),
        ("copy cat", "cat"), ("copy dog", "dog"),
        ("upper a", "A"), ("upper b", "B"),
        ("upper cat", "CAT"), ("upper dog", "DOG"),
    ]

    vocab = ["<pad>", "<bos>", "<sep>", "<eos>",
             "copy", "upper", "a", "b", "cat", "dog",
             "A", "B", "CAT", "DOG"]
    stoi = {w: i for i, w in enumerate(vocab)}
    itos = {i: w for w, i in stoi.items()}
    V = len(vocab)

    def encode(instr, resp):
        return [stoi[t] for t in ["<bos>"] + instr.split() + ["<sep>"] + resp.split() + ["<eos>"]]

    data = torch.tensor([encode(i, r) for i, r in pairs])

    class Block(nn.Module):
        def __init__(self, d, heads, ff):
            super().__init__()
            self.heads = heads
            self.dh = d // heads
            self.ln1 = nn.LayerNorm(d)
            self.qkv = nn.Linear(d, 3 * d, bias=False)
            self.out = nn.Linear(d, d, bias=False)
            self.ln2 = nn.LayerNorm(d)
            self.ff1 = nn.Linear(d, ff)
            self.ff2 = nn.Linear(ff, d)

        def forward(self, x):
            B, T, C = x.shape
            q, k, v = self.qkv(self.ln1(x)).split(C, dim=2)
            q = q.view(B, T, self.heads, self.dh).transpose(1, 2)
            k = k.view(B, T, self.heads, self.dh).transpose(1, 2)
            v = v.view(B, T, self.heads, self.dh).transpose(1, 2)
            scores = q @ k.transpose(-2, -1) / math.sqrt(self.dh)
            mask = torch.triu(torch.ones(T, T, dtype=torch.bool, device=x.device), diagonal=1)
            attn = F.softmax(scores.masked_fill(mask, float("-inf")), dim=-1)
            y = (attn @ v).transpose(1, 2).contiguous().view(B, T, C)
            x = x + self.out(y)
            return x + self.ff2(F.gelu(self.ff1(self.ln2(x))))

    class TinyLM(nn.Module):
        def __init__(self, vocab, d=64, heads=4, layers=2, ff=128, max_len=8):
            super().__init__()
            self.tok = nn.Embedding(vocab, d)
            self.pos = nn.Embedding(max_len, d)
            self.blocks = nn.ModuleList([Block(d, heads, ff) for _ in range(layers)])
            self.lnf = nn.LayerNorm(d)
            self.head = nn.Linear(d, vocab)

        def forward(self, x):
            h = self.tok(x) + self.pos(torch.arange(x.size(1), device=x.device))[None]
            for block in self.blocks:
                h = block(h)
            return self.head(self.lnf(h))

    class LoRALinear(nn.Module):
        def __init__(self, base, r=4, alpha=8):
            super().__init__()
            self.base = base
            for p in base.parameters():
                p.requires_grad = False
            self.A = nn.Parameter(torch.randn(r, base.in_features) * 0.01)
            self.B = nn.Parameter(torch.zeros(base.out_features, r))
            self.scale = alpha / r

        def forward(self, x):
            return self.base(x) + (x @ self.A.T @ self.B.T) * self.scale

    def apply_lora(module, r=4, alpha=8):
        for name, child in list(module.named_children()):
            if isinstance(child, nn.Linear):
                setattr(module, name, LoRALinear(child, r, alpha))
            else:
                apply_lora(child, r, alpha)

    torch.manual_seed(0)
    model = TinyLM(V)
    base_params = sum(p.numel() for p in model.parameters())

    for p in model.parameters():
        p.requires_grad = False
    apply_lora(model, r=4, alpha=8)
    trainable = sum(p.numel() for p in model.parameters() if p.requires_grad)

    x = data[:, :-1]
    y = data[:, 1:]
    mask = torch.zeros_like(y, dtype=torch.bool)
    for i, row in enumerate(data):
        sep = (row == stoi["<sep>"]).nonzero().item()
        mask[i, sep:] = True

    opt = torch.optim.AdamW(
        [p for p in model.parameters() if p.requires_grad],
        lr=1e-2,
    )
    for _ in range(400):
        logits = model(x)
        loss = F.cross_entropy(logits[mask], y[mask])
        opt.zero_grad()
        loss.backward()
        opt.step()

    model.eval()

    def generate(model, prompt, max_new=4):
        ids = [stoi["<bos>"]] + [stoi[w] for w in prompt.split()] + [stoi["<sep>"]]
        prompt_len = len(ids)
        with torch.no_grad():
            for _ in range(max_new):
                logits = model(torch.tensor([ids[-8:]]))
                nxt = logits[0, -1].argmax().item()
                ids.append(nxt)
                if nxt == stoi["<eos>"]:
                    break
        return " ".join(
            itos[i] for i in ids[prompt_len:] if i != stoi["<eos>"]
        )

    lora_acc = sum(generate(model, i).strip() == r for i, r in pairs)

    torch.manual_seed(0)
    base_model = TinyLM(V)
    base_model.eval()
    base_acc = sum(generate(base_model, i).strip() == r for i, r in pairs)

    print("params", base_params, "trainable", trainable)
    print("loss", round(loss.item(), 4))
    print("lora acc", lora_acc, "/", len(pairs))
    print("base acc", base_acc, "/", len(pairs))
    ```

输出：

```text
params 68878 trainable 6456
loss 0.0001
lora acc 8 / 8
base acc 0 / 8
```

读法：

- base 是随机初始化，8 条全错
- LoRA 只训练 6456 / 68878 个参数，8 条全对
- 这叫“记住了 8 条样本”，不是泛化
- 真正评估要留出未见过的指令组合
- LoRA 的秩、目标模块、学习率都会影响效果

## 9. 怎么选

| 场景 | 路线 |
|---|---|
| 教格式/任务/风格 | SFT |
| 有高质量偏好对 | DPO / ORPO |
| 有可靠奖励模型和工程能力 | RLHF / PPO |
| 数学/代码有验证器 | RLVR / GRPO |
| 显存有限 | LoRA / QLoRA |
| 需要改知识/能力 | 全量微调或继续预训练，不是只靠 SFT |

实践顺序：

1. 先做 SFT，确认格式和任务能学会
2. 用留出集评估，不只看 loss
3. 有偏好数据再考虑 DPO/ORPO
4. 需要推理增强再考虑 RLVR
5. 显存不够先上 LoRA，不要一上来全量

## 10. 常见坑

1. **prompt 也算 loss**
   模型在学复述 prompt，而不是回答；要 mask。

2. **chat template 手拼**
   多一个/少一个角色标记，训练和推理格式不一致。

3. **SFT 数据质量差**
   错误回答、模板化回答会被学进去；质量 > 数量。

4. **训练太久**
   固定模板过拟合，开放指令泛化变差。

5. **LoRA 目标模块选错**
   只挂 head 或只挂 FFN，效果可能很差；常挂 q/k/v/o + FFN。

6. **LoRA rank 太小**
   容量不够；rank 不是越小越优雅。

7. **忘记合并/保存 LoRA**
   推理时 base + adapter 要一起加载；只存 adapter 不存 base 会错。

8. **DPO 的 reference model 不一致**
   reference 要和 SFT 起点一致；换 base 会改变偏好目标。

9. **β 乱设**
   β 太大贴近 reference，学不动；太小容易跑偏。

10. **偏好数据有位置偏差**
    chosen 总在前面/后面，模型会学位置而不是内容。

11. **reward hacking**
    奖励模型/验证器有漏洞，模型会钻空子；要红队和人工检查。

12. **用训练 prompt 评估**
    分数虚高；要留出未见过的指令和场景。

## 11. 要点回顾

1. SFT 用指令-回答对，通常只对 response 算 loss
2. RLHF = SFT + 奖励模型 + PPO + KL 约束
3. DPO 直接用偏好对，不需要奖励模型和 PPO，但需要 reference
4. ORPO 把 SFT 和偏好合成一个阶段，不需要 reference
5. LoRA 冻结 base，只训练低秩增量；QLoRA 再量化 base
6. SFT 数据重质量/格式，偏好数据重 pair 质量/偏差
7. 评估要留出指令集，不能只看 loss，也不能用训练 prompt
8. 先 SFT，再偏好优化；显存不够先 LoRA
