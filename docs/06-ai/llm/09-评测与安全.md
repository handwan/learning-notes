# LLM 评测与安全

评测不是“跑一个分数”，而是回答：

- 这个模型在什么任务上、什么条件下、比谁好？
- 分数有没有被污染、prompt、解码参数或 judge 偏置影响？
- 安全性有没有单独测？会不会为了安全变得过度拒答？

这篇讲 benchmark 设计、指标、污染、LLM-as-judge、安全红队，最后用一个可控实验演示“污染如何把分数抬高”。

## 1. 评什么

LLM 评测至少分几层：

| 层面 | 例子 |
|---|---|
| 知识 | MMLU、GPQA |
| 推理 | GSM8K、MATH、BBH |
| 代码 | HumanEval、MBPP、SWE-bench |
| 指令跟随 | IFEval、MT-Bench |
| 对话偏好 | Chatbot Arena、AlpacaEval |
| 长上下文 | RULER、LongBench |
| 工具/Agent | 工具调用、多步任务、环境交互 |
| 安全 | HarmBench、AdvBench、越狱/注入 |
| 效率 | token/s、延迟、显存、成本 |

一个总分不能代表所有能力。报告要按任务、难度、语言、场景拆开。

## 2. Benchmark 设计

好的 benchmark 要满足：

- **构念有效**：测的东西和名字一致
- **区分度**：不同模型能拉开差距
- **难度梯度**：不是全对/全错
- **可复现**：prompt、解码、评分固定
- **抗污染**：测试集不公开或动态更新
- **多语言/多场景**：不能只看英文
- **成本可控**：推理预算、人工评测预算

常见问题：

- benchmark 饱和：头部模型都 90%+，没有区分度
- benchmark 过拟合：模型/数据专门针对它优化
- prompt 敏感：换模板分数大幅波动
- 评分器偏差：精确匹配太严，judge 太松
- 测试集泄漏：题目进了训练集

## 3. 指标与统计

常见指标：

- 准确率 / exact match
- F1 / precision / recall
- pass@1 / pass@k
- win rate / Elo
- 人工评分 / LLM judge
- 校准 / Brier score
- 延迟 / token 成本

注意：

- 样本量小，置信区间很宽；100 题上的 1% 差异可能没有意义
- 报告均值的同时报告方差/置信区间
- 多 seed、多 prompt 模板，避免单次幸运
- pass@k 要写清 k、采样温度、是否去重
- 不同 tokenizer 的 loss/PPL 不可直接比
- 测试集不能反复调参；调过就不再干净

## 4. LLM-as-judge

用模型当评委，常见两种：

- **pointwise**：给单个回答打 1–5 分
- **pairwise**：给两个回答选更好的

常见偏置：

- **位置偏置**：总偏好第一个/最后一个
- **长度/风格偏置**：更长、更正式的回答得分高
- **自我偏好**：模型偏爱自己/同家族的输出
- **提示敏感**：rubric、顺序、措辞会改变分数
- **安全盲区**：judge 可能被越狱/诱导

降低偏置：

- 交换 A/B 位置，取平均
- 用 rubric + 参考答案
- 多 judge 投票/集成
- 和人工标注做一致性校验
- 报告 judge 与人的 agreement
- 不要用 judge 评自己训练过的数据

LLM-as-judge 适合大规模初筛，不适合替代全部人工评测，尤其是安全和高风险场景。

## 5. 数据污染

污染 = 测试题/答案以某种形式出现在训练数据里。

形式：

- 原题原文
- 改写、翻译、回译
- 同套题的相似题
- 答案/解析泄漏
- benchmark 的 few-shot 示例进入训练

检测：

- n-gram / 子串匹配
- embedding 相似度
- 训练数据时间切分
- 动态/私有 benchmark
- 人工抽查

去污染只能降低风险，不能证明“完全没见过”。报告时要写：

- 训练数据截止时间
- 用了哪些去污染方法
- benchmark 是否公开、是否动态
- 是否在测试集上调过参

## 6. 安全评测

安全不是单一指标，至少包括：

- 有害内容：暴力、违法、自伤、仇恨
- 越狱：角色扮演、编码、多轮诱导、many-shot
- prompt injection：直接注入、间接注入（网页/文档/工具返回）
- 数据外泄：系统提示、隐私、密钥、工具结果
- 工具滥用：越权调用、危险操作
- 过度拒答：正常请求被误拒
- 多语言安全：英文安全不代表中文安全

评测方法：

- 红队：人工 + 自动化生成攻击
- 安全 benchmark：HarmBench、AdvBench 等
- 人工审核：严重性、可操作性、上下文
- 防御测试：输入过滤、输出过滤、工具权限、沙箱
- 安全/utility 权衡：安全提升不能以全拒答为代价

不要用 system prompt 当唯一防御。真正的安全要分层：模型、过滤器、权限、工具沙箱、人工复核。

## 7. 评测 harness

一个可复现的评测要固定：

- 数据版本、split、去污染版本
- prompt 模板、system prompt
- 解码参数：temperature、top-p、max tokens
- few-shot 示例
- 评分脚本/版本
- 模型版本、tokenizer、量化
- seed、硬件、batch
- 成本/延迟

日志至少保存：

- 原始 prompt
- 原始输出
- 解析后的答案
- 分数和评分理由
- token 数、延迟、错误

否则出了问题无法复查。

## 8. 实验：clean vs contaminated

用两个可控 benchmark：

- `add`：两位数加法
- `parity`：12 位二进制串的奇偶校验

两个“模型”：

- `solver`：规则求解，真的会算
- `memorizer`：只背训练集，没见过就输出 `?`

测试集：

- clean：未参与训练的 100 题
- contaminated：训练集里的 100 题

??? note "代码：实验：clean vs contaminated"
    ```python
    import math
    import random

    def make_add(n, seed):
        rng = random.Random(seed)
        out = []
        seen = set()
        while len(out) < n:
            a, b = rng.randint(0, 99), rng.randint(0, 99)
            if (a, b) in seen:
                continue
            seen.add((a, b))
            out.append((f"{a}+{b}", str(a + b)))
        return out

    def make_parity(n, seed, length=12):
        rng = random.Random(seed)
        out = []
        seen = set()
        while len(out) < n:
            bits = tuple(rng.randint(0, 1) for _ in range(length))
            if bits in seen:
                continue
            seen.add(bits)
            out.append((" ".join(map(str, bits)), str(sum(bits) % 2)))
        return out

    def wilson(k, n, z=1.96):
        p = k / n
        den = 1 + z * z / n
        center = (p + z * z / (2 * n)) / den
        half = z * math.sqrt(p * (1 - p) / n + z * z / (4 * n * n)) / den
        return max(0.0, center - half), min(1.0, center + half)

    def evaluate(model, bench):
        correct = sum(model(q) == a for q, a in bench)
        lo, hi = wilson(correct, len(bench))
        return correct / len(bench), lo, hi

    class Solver:
        def __call__(self, q):
            if "+" in q:
                a, b = q.split("+")
                return str(int(a) + int(b))
            return str(sum(map(int, q.split())) % 2)

    class Memorizer:
        def __init__(self, train):
            self.table = dict(train)

        def __call__(self, q):
            return self.table.get(q, "?")

    add = make_add(600, 0)
    parity = make_parity(600, 1)

    for name, (train, test) in {
        "add": (add[:500], add[500:]),
        "parity": (parity[:500], parity[500:]),
    }.items():
        for model_name, model in [
            ("solver", Solver()),
            ("memorizer", Memorizer(train)),
        ]:
            clean, lo, hi = evaluate(model, test)
            contaminated, _, _ = evaluate(model, train[:100])
            print(
                f"{name:7s} {model_name:10s} "
                f"clean={clean:.3f} [{lo:.3f},{hi:.3f}] "
                f"contaminated={contaminated:.3f}"
            )
    ```

输出：

```text
add     solver     clean=1.000 [0.963,1.000] contaminated=1.000
add     memorizer  clean=0.000 [0.000,0.037] contaminated=1.000
parity  solver     clean=1.000 [0.963,1.000] contaminated=1.000
parity  memorizer  clean=0.000 [0.000,0.037] contaminated=1.000
```

读法：

- solver 真的会算，clean 和 contaminated 都 1.0
- memorizer 只背训练集：clean 只有 `0.000`
- 同一份“模型”，在 contaminated 测试集上都变成 1.0
- 如果只跑 contaminated benchmark，memorizer 看起来完美
- 差异不是模型变强，而是测试集泄漏

这个实验是评测 harness 的玩具演示，不是 LLM 分数。真实污染更隐蔽：改写、翻译、相似题、答案泄漏都可能。

## 9. 怎么报告

至少包含：

- 任务/benchmark 名称和版本
- clean/contaminated 检查
- 每类任务分数，不只是一个总分
- 置信区间/方差
- 解码参数、prompt 模板
- 成本、延迟、token 数
- 安全/过度拒答
- 失败案例抽样
- 和 baseline 的对比

避免：

- 只报最高分
- 只报一个 benchmark
- 用测试集调参
- 不写 judge 版本和 prompt
- 把 contaminated 分数当能力

## 10. 常见坑

1. **只跑一个 benchmark**
   不能代表知识、推理、代码、安全等全部能力。

2. **测试集污染**
   分数虚高；要做 n-gram/语义检查，最好用动态/私有集。

3. **用测试集调参**
   测试集被“训练”后不再干净。

4. **样本量太小**
   100 题上的小差异可能只是噪声；报告置信区间。

5. **prompt/解码不一致**
   不同模型用不同模板、temperature、max tokens，分数不可比。

6. **judge 偏置**
   位置、长度、风格、自我偏好；要交换顺序、多 judge、人工校验。

7. **pass@k 当 pass@1**
   多次采样分数不能代表单次部署。

8. **只看平均分**
   难例、长尾、多语言、安全类别可能很差。

9. **安全只测拒答率**
   全拒答看起来“安全”，但 utility 归零；要测过度拒答。

10. **只靠 system prompt 防注入**
    间接注入、工具返回、文档内容都可能绕过；要权限和沙箱。

11. **不保存原始输出**
    分数异常时无法复查；日志要存 prompt、输出、评分理由。

12. **benchmark 饱和后继续刷**
    头部模型都 90%+ 时，分数没有区分度；要换更难/动态集。

## 11. 要点回顾

1. 评测是多维的：知识、推理、代码、指令、长上下文、安全、效率
2. benchmark 要看构念、区分度、难度、污染和成本
3. 指标要带置信区间、样本量、prompt/解码配置
4. LLM-as-judge 有位置/长度/自我偏好，不能替代全部人工
5. 污染只能降低不能完全消除；clean/contaminated 要分开报告
6. 安全要测越狱、注入、外泄、工具滥用、过度拒答
7. 评测 harness 要固定数据、prompt、解码、评分和日志
8. 不要用测试集调参，不要把 contaminated 分数当能力
