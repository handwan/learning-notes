# 解码与采样

模型每一步输出的是词表上的 logits，不是最终文本。**解码策略**决定怎么把 logits 变成下一个 token。

同一个 prompt，换 greedy、temperature、top-k、top-p 或 beam，输出可能完全不同。这篇讲这些策略的取舍，并用一个小 n-gram 模型做同一 prompt 的对比。

## 1. 自回归解码

生成过程：

```text
prompt → 模型 → 最后一个位置的 logits
→ 选一个 token → 拼回输入
→ 重复，直到 EOS 或 max_new_tokens
```

模型给的是每个 token 的分数，解码器要回答：

- 选概率最高的？
- 按概率采样？
- 只在头部采样？
- 保留多条候选？

不同策略没有绝对优劣，取决于任务。

## 2. Greedy

每步选概率最高的 token：

$$
x_t=\arg\max_w p(w\mid x_{<t})
$$

特点：

- 通常确定，容易复现；概率并列时不同框架的 tie-break 可能不同
- 快，不需要维护多条候选
- 容易重复、循环、生成“安全但无聊”的文本
- 高概率不等于人类觉得好

适合：短答案、结构化输出、代码补全的确定性部分。

## 3. Temperature

温度缩放：

$$
p_i=\frac{\exp(z_i/T)}{\sum_j\exp(z_j/T)}
$$

- $T=1$：模型原始分布
- $T<1$：分布更尖，低概率 token 被压低
- $T>1$：分布更平，随机性更大
- $T\to0$：趋近 greedy；不要直接传 0，用 argmax

温度不是“质量旋钮”。调高温度会增加多样性，也会增加胡言乱语；调低会稳定，也会更重复。

## 4. Top-k

只保留概率最高的 $k$ 个 token，再归一化采样：

```text
排序 → 取前 k 个 → 重新归一化 → 采样
```

- $k$ 固定，不随分布形状变化
- 分布很尖时，top-k 仍保留固定 $k$ 个，尾部 token 可能几乎是噪声
- 分布很平时，top-k 会砍掉一部分合理长尾
- 常和 temperature 一起用

适合：想要固定候选数量、实现简单的场景。

## 5. Top-p / Nucleus

按概率从高到低累加，取最小的集合，使累计概率达到 $p$：

```text
排序 → 累加 → 达到 p 就停 → 重新归一化 → 采样
```

- $p=0.9$：保留“核”内的 token
- 分布尖时，候选少；分布平时，候选多
- 比 top-k 更自适应
- 常和 temperature、top-k 组合

注意顺序：一般先 temperature，再 top-k/top-p；不同框架的顺序可能不同，复现时要确认。

## 6. Beam Search

维护 $k$ 条候选序列，每步扩展，保留总分最高的 $k$ 条：

$$
\text{score}=\sum_t \log p(x_t\mid x_{<t})
$$

- 比 greedy 更可能找到高概率序列
- 朴素 beam 的计算/显存约是 greedy 的 $k$ 倍；共享前缀可以省一部分 KV cache
- 容易生成高概率但重复、保守的文本
- 通常加长度归一化，避免偏向短句

适合：翻译、摘要、结构化生成等“有相对明确正确答案”的任务。

不适合：开放对话、创意写作；这些任务更看重多样性，beam 往往显得呆板。

## 7. 重复控制

常见手段：

- **repetition penalty**：对已经出现过的 token 降低分数
- **frequency / presence penalty**：按出现次数/是否出现惩罚
- **no_repeat_ngram**：禁止重复 n-gram
- **top-k / top-p**：减少低概率 token 进入
- **stop strings / EOS**：及时停止

注意：

- 惩罚太强会破坏语法和必要重复（比如 `the`、括号、代码变量）
- 惩罚太弱会循环
- 不同框架的 penalty 实现不同，调参要看文档

## 8. KV cache 与解码

训练时整条序列并行；推理时逐 token：

- **prefill**：一次算完 prompt，建立 KV cache
- **decode**：每步只算新 token 的 Q/K/V，和历史 K/V 做 attention
- 没有 cache 就要每步重算整个前缀，长上下文非常慢

批量生成还要处理：

- 左侧 padding（生成任务常用）
- attention mask
- 不同序列在不同步结束
- `max_new_tokens` 和上下文长度的区别

## 9. 实验：同一 prompt，不同解码

用一个词级 trigram 模型，语料很小，只看解码策略，不看模型能力。

??? note "代码：实验：同一 prompt，不同解码"
    ```python
    import math
    import random
    from collections import Counter, defaultdict

    sentences = [
        "the cat sees the dog",
        "the dog sees the bird",
        "the cat likes the mat",
        "the dog likes the ball",
        "a cat sees a dog",
        "a dog sees a cat",
        "the cat follows the dog",
        "the dog follows the bird",
        "the cat finds the ball",
        "the dog finds the mat",
    ]

    trigram = defaultdict(Counter)
    bigram = defaultdict(Counter)
    unigram = Counter()

    for sent in sentences:
        toks = ["<s>", "<s>"] + sent.split()
        for w in toks[2:]:
            unigram[w] += 1
        for i in range(2, len(toks)):
            trigram[(toks[i - 2], toks[i - 1])][toks[i]] += 1
            bigram[(toks[i - 1],)][toks[i]] += 1

    def dist(context):
        if len(context) >= 2 and tuple(context[-2:]) in trigram:
            return trigram[tuple(context[-2:])]
        if len(context) >= 1 and tuple(context[-1:]) in bigram:
            return bigram[tuple(context[-1:])]
        return unigram

    def probs(context, temperature=1.0, top_k=None, top_p=None):
        c = dist(context)
        total = sum(c.values())
        items = sorted(
            [(w, n / total) for w, n in c.items()],
            key=lambda x: (-x[1], x[0]),
        )

        if temperature != 1.0:
            z = [(w, math.log(p) / temperature) for w, p in items]
            m = max(v for _, v in z)
            e = [(w, math.exp(v - m)) for w, v in z]
            s = sum(v for _, v in e)
            items = [(w, v / s) for w, v in e]

        if top_k is not None:
            items = items[:top_k]
            s = sum(p for _, p in items)
            items = [(w, p / s) for w, p in items]

        if top_p is not None:
            keep = []
            acc = 0.0
            for w, p in items:
                keep.append((w, p))
                acc += p
                if acc >= top_p:
                    break
            s = sum(p for _, p in keep)
            items = [(w, p / s) for w, p in keep]

        return items

    def sample(context, rng, **kwargs):
        items = probs(context, **kwargs)
        r = rng.random()
        acc = 0.0
        for w, p in items:
            acc += p
            if r <= acc:
                return w
        return items[-1][0]

    def generate(prompt, n=12, seed=0, **kwargs):
        rng = random.Random(seed)
        toks = ["<s>", "<s>"] + prompt.split()
        out = prompt.split()
        for _ in range(n):
            w = sample(toks, rng, **kwargs)
            toks.append(w)
            out.append(w)
        return " ".join(out)

    def greedy(prompt, n=12):
        toks = ["<s>", "<s>"] + prompt.split()
        out = prompt.split()
        for _ in range(n):
            w = probs(toks)[0][0]
            toks.append(w)
            out.append(w)
        return " ".join(out)

    def beam(prompt, n=12, width=3):
        beams = [(["<s>", "<s>"] + prompt.split(), prompt.split(), 0.0)]
        for _ in range(n):
            cand = []
            for toks, out, score in beams:
                for w, p in probs(toks):
                    cand.append((toks + [w], out + [w], score + math.log(p)))
            cand.sort(key=lambda x: x[2], reverse=True)
            beams = cand[:width]
        best = max(beams, key=lambda x: x[2])
        return " ".join(best[1])

    for name, fn in [
        ("greedy", lambda: greedy("the")),
        ("temp 0.5", lambda: generate("the", seed=1, temperature=0.5)),
        ("temp 1.5", lambda: generate("the", seed=1, temperature=1.5)),
        ("top_k 3", lambda: generate("the", seed=1, top_k=3)),
        ("top_p 0.9", lambda: generate("the", seed=1, top_p=0.9)),
        ("beam 3", lambda: beam("the")),
    ]:
        print(name, "|", fn())

    print("P(next|the)", [(w, round(p, 3)) for w, p in probs(["<s>", "the"])])
    print("P(next|the cat)", [(w, round(p, 3)) for w, p in probs(["<s>", "the", "cat"])])
    ```

输出：

```text
greedy | the cat finds the ball the dog finds the ball the dog finds
temp 0.5 | the cat sees the bird the dog likes the ball the ball the
temp 1.5 | the cat sees the bird a cat sees the bird the bird cat
top_k 3 | the cat likes the ball the dog follows the bird the ball the
top_p 0.9 | the cat sees the bird dog finds the mat the dog sees a
beam 3 | the cat finds the ball the dog finds the ball the dog finds
P(next|the) [('cat', 0.5), ('dog', 0.5)]
P(next|the cat) [('finds', 0.25), ('follows', 0.25), ('likes', 0.25), ('sees', 0.25)]
```

读法：

- greedy 和 beam 都偏重复、可预测
- temperature 0.5 更稳定，1.5 更发散
- top-k 固定保留 3 个；top-p 按累计概率自适应
- 采样结果依赖 seed；换 seed 会变
- 这是 trigram，不是 LLM；解码策略是模型无关的

## 10. 怎么选

| 场景 | 策略 |
|---|---|
| 短答案、结构化输出 | greedy / 低 temperature |
| 代码补全 | greedy 或低 temperature + 停止条件 |
| 翻译、摘要 | beam search（配合长度归一化） |
| 开放对话/创意写作 | temperature + top-p |
| 需要多样性 | 较高 temperature / top-p |
| 需要可复现 | 固定 seed + greedy，或固定采样 seed |

常用起点：

- 事实问答：`temperature=0.2–0.5`，`top_p=0.9`
- 开放写作：`temperature=0.8–1.2`，`top_p=0.9–0.95`
- 代码：`temperature=0–0.3`
- beam：宽度 3–5，配合长度惩罚

这些只是起点，不同模型/任务差别很大。

## 11. 常见坑

1. **temperature=0 直接传给 softmax**
   除零；要单独走 argmax/greedy。

2. **top-k 和 top-p 顺序混乱**
   不同框架顺序不同；复现时确认是 temperature → top-k → top-p 还是别的。

3. **top-p 之后不重新归一化**
   采样前要重新归一化，否则概率和不为 1。

4. **beam 不做长度归一化**
   容易偏向短句；长文本要加 length penalty。

5. **把高概率当高质量**
   beam/greedy 可能生成高概率但重复、空洞的文本。

6. **重复惩罚太强**
   破坏语法、代码变量、必要重复；要按任务调。

7. **采样不可复现**
   没固定 seed、GPU 非确定性、batch 内不同序列互相影响。

8. **padding side 错**
   生成通常左侧 padding；右侧 padding 会让模型把 pad 当上下文。

9. **忘记 EOS/stop**
   生成不停，浪费算力；也可能截断在句子中间。

10. **`max_tokens` 和上下文长度混了**
   一个是生成长度，一个是模型可接受的总长度。

11. **只看 PPL 评估生成**
   PPL 衡量似然，不衡量有用性、事实性、风格。

12. **batch 生成长度不一致**
    不同序列在不同步结束；要 mask 已结束的序列，避免继续算。

## 12. 要点回顾

1. 模型输出 logits，解码策略决定下一个 token
2. greedy 确定但容易重复；temperature 控制分布的尖锐程度
3. top-k 固定候选数；top-p 按累计概率自适应
4. beam 保留多条候选，适合有明确答案的任务，不适合开放创作
5. 重复惩罚、no-repeat n-gram、stop 条件要按任务调
6. 推理用 KV cache：prefill 一次，decode 逐步
7. 采样要固定 seed；batch 生成要处理 padding 和提前结束
8. 解码策略没有万能最优，要和任务、模型、评测一起选
