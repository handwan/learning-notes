# 预训练数据

模型架构决定上限，数据决定能不能接近上限。

同样的参数量、同样的训练步数，换一份语料，loss 和下游能力会差很多。预训练数据不是一个“下载完就喂”的步骤，而是一条完整管线：

```text
采集 → 抽取正文 → 语言识别 → 质量过滤 → 去重
→ PII/安全过滤 → 去污染 → 配比 → tokenize/pack
```

这篇讲这条管线里最影响结果的几件事：质量、去重、污染、配比、合成数据和 packing。

## 1. 数据管线

| 步骤 | 做什么 | 常见问题 |
|---|---|---|
| 采集 | 网页、书籍、代码、论文、对话 | 许可、版权、来源偏差 |
| 抽取正文 | HTML → 纯文本 | 导航栏、广告、模板残留 |
| 语言识别 | 判断语言/脚本 | 短文本、混语言误判 |
| 质量过滤 | 去掉低质/重复/乱码 | 过滤太狠丢多样性 |
| 去重 | 文档/段落/行/子串级去重 | 误删代码、法律等重复文本 |
| 安全过滤 | PII、毒性、隐私 | 误伤正常内容 |
| 去污染 | 去掉 benchmark 测试集 | 只能降低，不能完全保证 |
| 配比 | 各来源采样比例 | 比例靠拍脑袋 |
| tokenize/pack | 转 ID、拼接序列 | 文档边界、padding、mask |

每一步都会改变数据分布，不能只在最后看 loss。

## 2. 数据来源

| 来源 | 优点 | 风险 |
|---|---|---|
| 网页（Common Crawl 等） | 规模大、覆盖广 | 噪声、模板、垃圾、版权 |
| 书籍 | 长文本、连贯 | 版权、扫描错误 |
| 代码 | 结构、推理、工具使用 | 许可、测试泄漏、重复 |
| 论文/数学 | 推理、符号 | 格式复杂、公式抽取 |
| 对话/指令 | 对齐、任务格式 | 质量参差、隐私 |
| 合成数据 | 可控、可验证 | 模型偏差、自我循环、许可 |

网页是主粮，但网页的“平均质量”很低。质量过滤和去重往往比换模型更影响最终效果。

## 3. 质量过滤

常见启发式：

- 长度：太短、太长、行数异常
- 符号/数字比例：大量乱码、代码符号、重复标点
- 重复行/重复段落比例
- 停用词比例：自然语言通常有稳定停用词分布
- 语言识别置信度
- 模板/导航栏/广告关键词
- 成人、毒性、PII 分类器
- 困惑度/质量分类器：用一个小模型给文本打分

取舍：

- 过滤太松：垃圾、模板、重复内容进入训练
- 过滤太狠：低资源语言、口语、代码、长尾知识被删掉
- 质量分类器会继承训练数据的偏差；英文、正式文本更容易高分
- 阈值没有通用值，要在小规模验证集上看下游效果

一个实用原则：**先做便宜的规则过滤，再用模型打分；每一层都保留抽样人工检查。**

## 4. 去重

重复数据有三个代价：

- 模型更容易记住训练样本，隐私/版权风险更高
- 重复内容会放大某些领域，改变数据配比
- 浪费训练算力；重复 token 不会带来等比例的新信息

### 去重粒度

- **文档级**：整篇文档 hash / MinHash
- **段落级**：按段落 hash，保留不同文档里的相同段落一次
- **行级**：代码、日志、表格常用
- **子串级**：后缀数组、n-gram 重叠，能发现长重复片段

### 方法

| 方法 | 原理 | 特点 |
|---|---|---|
| 精确 hash | 规范化后算 SHA/xxHash | 快，只能抓完全重复 |
| MinHash | 用多个哈希估计 Jaccard | 适合大规模近似去重 |
| SimHash | 文档指纹的汉明距离 | 快，适合网页 |
| 后缀数组 | 找最长公共子串 | 精确，内存/实现更重 |
| n-gram 重叠 | 统计共享 shingle | 简单，阈值要调 |

去重不是越狠越好：代码、法律条款、许可证、API 文档天然有大量重复；全删可能损失重要模式。常见做法是分来源设阈值，并对代码/法律单独处理。

### 实验：exact + near duplicate

构造 1200 篇文档：

- 800 篇随机基准文档
- 200 篇完全重复
- 200 篇近似重复（改一个 token）

比较原始、精确去重、近似去重后的文档数和 token 数。

??? note "代码：实验：exact + near duplicate"
    ```python
    import hashlib
    import random

    rng = random.Random(0)
    vocab = [f"w{i}" for i in range(200)]

    base = [" ".join(rng.choice(vocab) for _ in range(24)) for _ in range(800)]
    exact = base[:200]

    near = []
    for doc in base[:200]:
        toks = doc.split()
        j = rng.randrange(len(toks))
        new = rng.choice(vocab)
        while new == toks[j]:
            new = rng.choice(vocab)
        toks[j] = new
        near.append(" ".join(toks))

    docs = base + exact + near
    rng.shuffle(docs)

    def norm(doc):
        return " ".join(doc.lower().split())

    def shingles(doc, k=5):
        toks = norm(doc).split()
        return {tuple(toks[i:i + k]) for i in range(len(toks) - k + 1)}

    exact_seen = set()
    exact_unique = []
    for doc in docs:
        h = hashlib.sha1(norm(doc).encode()).hexdigest()
        if h not in exact_seen:
            exact_seen.add(h)
            exact_unique.append(doc)

    near_kept = []
    near_sigs = []
    for doc in exact_unique:
        sig = shingles(doc)
        dup = False
        for other in near_sigs:
            inter = len(sig & other)
            union = len(sig | other)
            if union and inter / union >= 0.5:
                dup = True
                break
        if not dup:
            near_kept.append(doc)
            near_sigs.append(sig)

    def count_tokens(items):
        return sum(len(norm(doc).split()) for doc in items)

    print("raw", len(docs), count_tokens(docs))
    print("exact", len(exact_unique), count_tokens(exact_unique))
    print("near", len(near_kept), count_tokens(near_kept))
    print("removed", len(docs) - len(exact_unique), len(exact_unique) - len(near_kept))
    ```

输出：

```text
raw 1200 28800
exact 1000 24000
near 800 19200
removed 200 200
```

读法：

- 精确去重去掉 200 篇完全重复，token 从 28800 降到 24000
- 近似去重再去掉 200 篇，token 到 19200
- 最终保留 800 篇；如果继续训练，重复 token 不会带来等比例的新信息
- 真实语料不会这么规整；生产上用 MinHash/SimHash/后缀数组，阈值要在验证集上调

## 5. 数据污染

污染 = 训练集里出现 benchmark 的题目/答案。

后果：

- 分数虚高，不能反映真实能力
- 不同模型之间的 benchmark 不可比
- 越新的 benchmark 越容易被“背过”

处理：

- 用 n-gram / 子串匹配从训练集删掉测试题
- 对 benchmark 做时间切分：训练数据截止时间早于测试集发布时间
- 用动态/私有 benchmark
- 报告污染检查结果，不只报分数

去污染只能降低风险，不能证明“完全没看过”。模型可能见过改写、翻译、相似题。

## 6. 数据配比

预训练不是把所有数据混在一起等比例采样。常见做法：

- 网页、代码、数学、书籍、多语言分别设权重
- 高质量来源上采样，低质量来源下采样
- 代码/数学在后期阶段提高比例
- 用小规模 ablation 选配比，不要直接拿测试集调

temperature sampling：

$$
p_i'=\frac{p_i^\alpha}{\sum_j p_j^\alpha}
$$

- $\alpha=1$：按原始比例
- $\alpha<1$：更均匀，低比例领域被上采样
- $\alpha>1$：更集中在高比例领域

配比会改变模型的能力结构：代码比例高，代码能力更强，但自然语言/多语言可能退化。没有“万能配比”，只有和目标能力匹配的配比。

## 7. 合成数据

常见方式：

- Self-instruct：让模型生成指令/回答，再筛掉低质样本
- 蒸馏：用强模型生成训练数据
- Rejection sampling：生成多个候选，用规则/验证器/模型选最好的
- 可验证任务：代码跑测试、数学对答案、工具调用检查结果

风险：

- 模型把自己的偏差/错误放大
- 合成数据分布单一，长期只用合成数据会退化
- 许可和署名问题
- 验证器有漏洞时，模型会学会钻空子

合成数据适合补长尾、补格式、补推理链，不适合替代全部真实语料。常见做法是“真实数据为主，合成数据为辅，严格过滤”。

## 8. Tokenize 与 packing

数据管线最后一步：

- tokenize：文本 → token ID
- packing：把多条短文档拼成固定长度序列
- 文档之间加 EOS/BOS，避免模型把边界当成连续文本
- attention mask / loss mask 要区分 padding 和文档边界

packing 的取舍：

- 不 pack：短文档大量 padding，浪费算力
- pack：吞吐高，但文档边界处理不好会泄漏/混淆
- 变长序列要 mask padding； causal LM 还要保证不会跨文档注意

## 9. 常见坑

1. **只抓数据，不做质量过滤**
   网页平均质量很低；垃圾、模板、乱码会浪费算力。

2. **过滤太激进**
   低资源语言、口语、代码、长尾知识被删掉，模型变得单一。

3. **只做精确去重**
   改一个词、换模板、翻译都能绕过去；要配合 MinHash/SimHash/子串去重。

4. **去重误删代码/法律文本**
   这些领域天然重复；按来源设阈值，不要一刀切。

5. **训练集污染 benchmark**
   分数虚高；用 n-gram/子串匹配去污染，并报告检查结果。

6. **配比拍脑袋**
   不跑 ablation，直接按“网页越多越好”或“代码越多越好”调。

7. **合成数据不验证**
   模型错误被放大；要有规则、测试、验证器或人工抽检。

8. **packing 不处理文档边界**
   模型把上一篇的结尾和下一篇的开头连起来，学出错误模式。

9. **tokenize 后才去重**
   通常先在文本层去重；token 级去重适合特定场景，但 tokenize 后的哈希对格式变化更敏感。

10. **忽略许可/隐私**
    版权、PII、许可证、robots 规则都要在采集和过滤阶段处理。

11. **只看 token 数，不看有效 token**
    重复、模板、低质内容也是 token；数据预算要按有效信息算。

12. **用测试集调配比**
    测试集被“训练”后，最终评估不再干净。

## 10. 要点回顾

1. 预训练数据是一条管线：采集、抽取、语言识别、质量过滤、去重、安全、去污染、配比、packing
2. 质量过滤要先规则后模型，阈值用验证集调，别过滤太狠
3. 去重分文档/段落/行/子串；精确 hash + MinHash/SimHash/后缀数组
4. 去重降低记忆、污染和算力浪费，但代码/法律要特殊处理
5. 数据污染只能降低，不能完全消除；要报告检查结果
6. 配比决定能力结构；temperature sampling 和小规模 ablation 比拍脑袋可靠
7. 合成数据要验证、要和真实数据混合，不能自我循环
8. packing 提高吞吐，但必须处理文档边界和 mask
