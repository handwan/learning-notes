# 量化

量化不是“把权重存成 4-bit”这么简单。它同时影响：

- 显存/带宽
- 计算 kernel/吞吐
- 精度/长上下文/工具调用
- 引擎/硬件支持
- 校准数据和评测

这篇讲 weight-only / W8A8 / FP8 / INT4、GPTQ/AWQ/SmoothQuant、校准与评测，最后做一个小线性层的 weight-only 量化实验。训练侧的 FP8/QLoRA/NF4 见 [混合精度与显存](../training/06-混合精度与显存.md) 和 [微调](../training/02-微调.md)；这里讲推理。

## 1. 量化基础

仿射量化：

$$
q=\mathrm{clamp}\left(\mathrm{round}\left(\frac{x}{s}\right)+z,q_{\min},q_{\max}\right),
\quad
\hat{x}=(q-z)s
$$

- $s$：scale
- $z$：zero-point；对称量化常取 0
- $q_{\min}/q_{\max}$：INT8 是 -128..127，INT4 是 -8..7
- 反量化：$\hat{x}=(q-z)s$

粒度：

| 粒度 | 每个 scale 覆盖 | 精度 | 开销 |
|---|---|---|---|
| per-tensor | 整个张量 | 最低 | 最小 |
| per-channel | 每个输出通道 | 较好 | 小 |
| per-group | 每组 G 个权重 | 更好 | 随 G 增大而减小 |

weight-only vs W8A8：

- weight-only：只量化权重，激活还是 FP16/BF16；解码省带宽，但计算仍要反量化
- W8A8：权重和激活都 INT8；能用 INT8 tensor core，但激活 outlier 更难
- FP8：权重/激活 1 byte；需要硬件/框架支持
- KV cache 量化：单独量化 KV，长上下文省显存

PTQ vs QAT：

- PTQ：训练后量化，用校准数据估范围；GPTQ/AWQ/SmoothQuant 都是 PTQ
- QAT：训练时模拟量化；更准但更贵，LLM 少用

## 2. 常见方法

| 方法 | 量化对象 | 校准 | 特点 | 注意 |
|---|---|---|---|---|
| GPTQ | 权重 INT4/INT8 | 是 | 逐层重构/Hessian，group size | 校准数据/act order 影响精度 |
| AWQ | 权重 INT4 | 是 | 激活感知，保护 salient weights | 需要 kernel 支持 |
| SmoothQuant | W8A8 INT8 | 是 | 把激活 outlier 平滑到权重 | 校准/实现细节多 |
| FP8 | 权重/激活 | 视方案 | E4M3/E5M2、scaling | 硬件/框架支持 |
| INT8/INT4 weight-only | 权重 | 视方案 | 简单、省显存 | 反量化开销 |
| KV cache 量化 | KV | 视方案 | FP8/INT8 | 长上下文精度 |
| QLoRA/NF4 | 训练 | 是 | 4-bit base + LoRA | 训练用，不是推理 |

要点：

- GPTQ/AWQ 是 weight-only；SmoothQuant 是 W8A8
- GPTQ/AWQ/SmoothQuant 都需要校准数据；校准分布错了，精度会掉
- FP8 不是软件开关；要看 GPU/框架/kernel
- KV cache 量化是独立的一层；权重 4-bit 不代表 KV 也 4-bit

## 3. 精度与速度

显存/带宽：

- FP16/BF16：2 bytes/param
- INT8：1 byte/param；权重约为 FP16 的 1/2
- INT4：0.5 byte/param；权重约为 FP16 的 1/4
- 还要加 scale/zero-point/元数据；group 越小，开销越大

速度：

- Decode 通常 memory-bound；weight-only INT4 省带宽，可能明显提速
- Prefill 通常 compute-bound；weight-only 要反量化，可能不提速甚至变慢
- W8A8 能用 INT8 tensor core，但精度/outlier 更难
- FP8 需要硬件/内核；不是“1 byte = 4 倍加速”

精度：

- 小模型对量化更敏感
- 长上下文、工具调用、多语言、代码更容易掉
- outlier 通道/激活会放大误差；per-tensor 最容易被拖垮
- group size 越小通常越准，但 scale/管理开销越大
- KV cache 量化会影响长上下文；要单独测

## 4. 校准与评测

校准数据：

- 领域/语言/长度要接近线上
- 样本不用很多，但要覆盖 outlier/长尾
- 不要用评测集校准/调参；会泄漏
- 记录校准数据版本/模板

评测：

- 同一模型/版本/精度基线
- 同一 tokenizer/template/sampling
- PPL + 任务指标 + 长上下文 + 工具调用 + 安全
- 质量 vs 显存/吞吐/延迟一起看
- 小模型/边缘场景更要看任务指标

只看 PPL 不够：PPL 好看，工具调用/长上下文/拒答可能已经坏了。

## 5. 引擎支持

- vLLM：GPTQ/AWQ/FP8/INT4，具体看版本/kernel
- TensorRT-LLM：FP8/INT4/AWQ/GPTQ，编译型
- SGLang：GPTQ/AWQ/FP8，按版本
- TGI：bitsandbytes/GPTQ/AWQ/FP8，按版本
- 量化格式、group size、模型架构、CUDA/驱动都要匹配

选引擎前确认：

- 模型架构支持
- 量化方法/格式支持
- kernel 是否真的启用
- KV cache 量化支持
- 多卡/并行下是否支持

引擎选型见[推理引擎](02-推理引擎.md)。

## 6. 实验：weight-only 量化误差

一个小线性层：

- 权重 256×512，输入 batch=16
- 人为加少量 outlier 通道
- 对比 FP16 / INT8 / INT4
- 粒度：per-tensor / per-channel / group128 / group32
- 指标：输出相对误差、bytes/param

??? note "代码：weight-only 量化误差"
    ```python
    import torch

    torch.manual_seed(0)
    out_dim, in_dim, batch = 256, 512, 16
    W = torch.randn(out_dim, in_dim) * 0.02
    X = torch.randn(batch, in_dim)

    # 制造少量 outlier 通道，观察 per-tensor vs per-channel/group
    W[0] *= 10
    W[1, ::64] *= 5

    Y = X @ W.T

    def qmax(bits):
        return 2 ** (bits - 1) - 1

    def quant_tensor(w, bits):
        q = qmax(bits)
        scale = w.abs().max() / q
        return (torch.round(w / scale).clamp(-q - 1, q) * scale), scale

    def quant_channel(w, bits):
        q = qmax(bits)
        scale = w.abs().amax(dim=1, keepdim=True) / q
        return (torch.round(w / scale).clamp(-q - 1, q) * scale), scale

    def quant_group(w, bits, group):
        q = qmax(bits)
        out_dim, in_dim = w.shape
        assert in_dim % group == 0
        wg = w.view(out_dim, in_dim // group, group)
        scale = wg.abs().amax(dim=2, keepdim=True) / q
        wq = torch.round(wg / scale).clamp(-q - 1, q) * scale
        return wq.view(out_dim, in_dim), scale

    def report(name, w_hat, bits):
        y_hat = X @ w_hat.T
        rel = (Y - y_hat).norm() / Y.norm()
        print(f"{name:16s} rel_err={rel.item():.4f} bytes/param={bits/8:.2f}")

    report("FP16", W, 16)
    for bits in [8, 4]:
        for gran in ["tensor", "channel", "group128", "group32"]:
            if gran == "tensor":
                wh, _ = quant_tensor(W, bits)
            elif gran == "channel":
                wh, _ = quant_channel(W, bits)
            else:
                g = int(gran.replace("group", ""))
                wh, _ = quant_group(W, bits, g)
            report(f"INT{bits} {gran}", wh, bits)
    ```

输出：

```text
FP16             rel_err=0.0000 bytes/param=2.00
INT8 tensor      rel_err=0.0716 bytes/param=1.00
INT8 channel     rel_err=0.0079 bytes/param=1.00
INT8 group128    rel_err=0.0065 bytes/param=1.00
INT8 group32     rel_err=0.0048 bytes/param=1.00
INT4 tensor      rel_err=0.7647 bytes/param=0.50
INT4 channel     rel_err=0.1393 bytes/param=0.50
INT4 group128    rel_err=0.1089 bytes/param=0.50
INT4 group32     rel_err=0.0848 bytes/param=0.50
```

读法：

- FP16 误差 0，2 bytes/param
- INT8 per-tensor 误差 7.16%；per-channel 降到 0.79%；group32 0.48%
- INT4 per-tensor 误差 76.5%（outlier 拖垮）；per-channel 13.9%；group32 8.5%
- 粒度/group size 对精度影响很大；per-tensor 最容易受 outlier 影响
- bytes/param 不含 scale/zero-point 开销；group 越小，额外开销越大
- 这不是 GPTQ/AWQ 的实现；它们用校准/salient weights 进一步降误差
- 也没有测 kernel 速度；真实吞吐要看引擎/硬件/batch/seq

## 7. 常见坑

1. **只看 bits，不看 kernel**
   4-bit 存储不等于 4 倍加速；可能卡在反量化/带宽。

2. **拿不同模型/精度横比**
   不同模型/版本/量化方案的数字不可比。

3. **只看 PPL**
   长上下文、工具调用、多语言、安全可能已经掉了。

4. **校准数据不匹配**
   领域/长度偏了，activation range 估错，精度掉。

5. **per-tensor 硬扛 outlier**
   一个 outlier 通道就能拖垮整层；用 per-channel/group。

6. **group size 乱设**
   太小开销大，太大精度掉；按模型/任务扫。

7. **weight-only 和 W8A8 混淆**
   权重 4-bit 不代表激活也 4-bit；KV 也不一定量化。

8. **KV cache 没量化**
   长上下文时 KV 仍是大头；只省权重不够。

9. **引擎/kernel 不支持**
   格式能存，运行时没有对应 kernel，速度/精度都不对。

10. **小模型过度量化**
    容量小，4-bit 更容易掉；先测任务指标。

11. **忽略反量化开销**
    weight-only 在 prefill/compute-bound 场景可能不提速。

12. **量化后不重测安全**
    拒答/越狱/内容过滤可能变化；要红队/回归。

13. **校准/评测泄漏**
    用评测集校准或调参，数字虚高。

## 8. 要点回顾

1. 量化 = scale/zero-point + 低比特存储；粒度决定精度/开销
2. weight-only 省权重带宽；W8A8 用 INT8 tensor core；FP8 看硬件
3. GPTQ/AWQ 是 weight-only PTQ；SmoothQuant 是 W8A8；都需要校准
4. INT4 权重约为 FP16 的 1/4；但 kernel/反量化可能限制速度
5. per-tensor 最容易被 outlier 拖垮；per-channel/group 更稳
6. group size 越小通常越准，但 scale/管理开销越大
7. KV cache 量化是独立一层；长上下文要单独测
8. 评测看任务/长上下文/工具/安全，不只 PPL
9. 引擎/模型/kernel/版本要匹配；量化后必须重测
