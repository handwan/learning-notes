# 存储与数据

训练和推理不只吃 GPU，也吃存储：数据要读得进来，checkpoint 要写得出去，权重和缓存要放得下。

存储问题经常表现成“GPU 利用率上不去”：

- dataloader 等磁盘，GPU 空转
- checkpoint 写太久，训练停顿
- 小文件/元数据太多，并行文件系统扛不住
- 对象存储延迟高，随机读放大

这篇讲训练侧最常见的存储路径、对象存储和并行文件系统、checkpoint、数据集缓存，以及一个 checkpoint 写入实验。

## 1. 存储层级

从快到慢、从贵到便宜：

```text
寄存器 / shared memory
→ L1 / L2 / HBM
→ 本地 NVMe SSD
→ 并行文件系统 / NAS
→ 对象存储
→ 冷归档
```

训练数据通常在：

- 对象存储：原始语料、归档
- 并行文件系统：热数据、checkpoint
- 本地 NVMe：缓存、临时文件

推理权重可能在：

- 本地 NVMe
- 并行文件系统
- 对象存储（冷启动时拉取）

## 2. 文件、块、对象

| 类型 | 接口 | 适合 | 注意 |
|---|---|---|---|
| 块存储 | 块设备 | 数据库、VM | 需要文件系统 |
| 文件存储 | POSIX | 共享目录、checkpoint | 元数据/小文件瓶颈 |
| 对象存储 | HTTP/S3 API | 海量数据、归档 | 延迟高、非 POSIX |
| 并行文件系统 | POSIX + 条带 | HPC、训练热数据 | 部署/调优复杂 |

POSIX 语义很重要：

- `open/read/write/close`
- `rename` 原子性
- `append`、`mmap`
- 目录遍历、权限

对象存储通常没有真正的 rename/append，常用：

- 写临时对象，再更新 manifest
- multipart upload
- versioning
- 原子指针/数据库记录

## 3. 对象存储

常见：S3、OSS、GCS、MinIO。

优点：

- 容量几乎无限
- 按量付费
- 多副本/跨区
- 适合冷数据和归档

缺点：

- 首字节延迟高
- 小文件/大量 LIST 很贵
- 不是 POSIX
- 随机读性能差
- 请求费用/egress 费用

训练时常见模式：

- 原始数据放对象存储
- 预处理后写成大 shard
- 训练节点本地缓存热 shard
- checkpoint 写对象存储/并行 FS，保留本地副本

## 4. 并行文件系统

常见并行文件系统：Lustre、GPFS/Spectrum Scale、WekaFS。

关注：

- 聚合带宽（GB/s）
- 元数据 IOPS
- 条带（striping）
- 客户端并发
- RDMA/IB
- 容量和配额

Lustre/GPFS 适合大文件顺序读写和高聚合带宽；小文件、海量元数据操作容易成为瓶颈。

NFS 是共享/网络文件系统，不是并行文件系统（pNFS 才是并行扩展）；它简单，但高并发训练/checkpoint 不一定扛得住。

## 5. 数据加载路径

训练读取：

```text
对象存储 / 并行 FS
→ 本地 NVMe 缓存
→ DataLoader worker
→ CPU decode / tokenize / pack
→ GPU
```

常见瓶颈：

- 存储带宽不够
- 随机小读太多
- 元数据操作太多
- CPU 解码/分词慢
- worker 太少/太多
- batch 等待

优化：

- 预处理成大的 shard（如 1–4GB）
- 顺序读，少随机 seek
- 本地 NVMe 缓存
- 预取/后台下载
- 足够 worker，但不要打爆 CPU
- 固定 shard 顺序，shuffle 在 shard 内/全局做
- 监控 dataloader 等待时间

## 6. Checkpoint

训练 checkpoint 通常包含：

- 模型权重
- 优化器状态（Adam m/v）
- 学习率调度器
- 训练步数/epoch
- 数据顺序/RNG 状态
- 并行/分片元数据

粗略大小：

- 权重：2 bytes/参数（BF16）
- 优化器：Adam m/v 各 4 bytes，加 fp32 master 等
- 训练 checkpoint 常按 12–16 bytes/参数估

写 checkpoint 的问题：

- 同步写会停顿训练
- 大文件写带宽不够
- 多 rank 同时写造成拥塞
- 写到一半失败，checkpoint 损坏
- 保留太多旧 checkpoint，占满容量

实践：

- 分片 checkpoint（按 rank/张量）
- 先写临时目录，完成后原子切换
- 异步写，但要保证存储带宽有余量
- 保留最近 N 个 + 关键里程碑
- 定期做恢复演练
- 记录 checkpoint 与数据/代码版本

## 7. 实验：checkpoint 写入

按 16 bytes/参数粗算训练 checkpoint：

??? note "代码：实验：checkpoint 写入"
    ```python
    def checkpoint_gb(params_b, bytes_per_param=16):
        return params_b * bytes_per_param

    print("checkpoint size")
    for p in [7, 70]:
        print(p, "B", f"{checkpoint_gb(p):.0f} GB")

    print("\nwrite time (s) / overhead per hour (1h interval)")
    for p in [7, 70]:
        size = checkpoint_gb(p)
        for bw in [1, 5, 20]:
            t = size / bw
            print(f"params={p:3d}B bw={bw:2d}GB/s time={t:7.1f}s overhead={t/3600:.1%}")
    ```

输出：

```text
checkpoint size
7 B 112 GB
70 B 1120 GB

write time (s) / overhead per hour (1h interval)
params=  7B bw= 1GB/s time=  112.0s overhead=3.1%
params=  7B bw= 5GB/s time=   22.4s overhead=0.6%
params=  7B bw=20GB/s time=    5.6s overhead=0.2%
params= 70B bw= 1GB/s time= 1120.0s overhead=31.1%
params= 70B bw= 5GB/s time=  224.0s overhead=6.2%
params= 70B bw=20GB/s time=   56.0s overhead=1.6%
```

读法：

- 7B 训练 checkpoint 约 112GB；70B 约 1.1TB
- 1GB/s 下，70B 写一次要 18.7 分钟；每小时一次就是 31% 的训练时间
- 20GB/s 下仍需 56 秒；异步写可以重叠，但会占存储带宽
- checkpoint 太频繁，训练有效吞吐下降；太稀疏，故障丢进度
- 这里只算写入，恢复时间还要另算

## 8. 容量、带宽、成本

选存储要同时看：

- 容量
- 聚合带宽
- IOPS/元数据
- 延迟
- 持久性/副本
- 价格（容量、请求、egress）
- 地域/合规
- 运维复杂度

冷热分层：

- 热数据：本地 NVMe / 并行 FS
- 温数据：对象存储标准层
- 冷数据：归档层

不要把所有数据都放最热层，也不要让训练直接随机读冷归档。

## 9. 常见坑

1. **只算容量，不算带宽**
   容量够，带宽不够，GPU 还是等数据。

2. **小文件太多**
   元数据和小随机读会拖垮并行 FS/对象存储。

3. **对象存储当 POSIX 用**
   没有 rename/append，随机读写语义不同。

4. **dataloader 直接读对象存储**
   延迟高、请求多；先缓存/打包。

5. **checkpoint 同步写**
   训练停顿；要分片/异步/临时文件。

6. **checkpoint 覆盖唯一副本**
   写坏就丢；保留上一个可用版本。

7. **保留太多 checkpoint**
   容量被占满，元数据也变多；要有 retention。

8. **不演练恢复**
   能写不一定能读回；恢复时间要测。

9. **多 rank 同时写同一文件**
   拥塞/锁竞争；按 rank 分片。

10. **忽略 egress/请求费用**
    对象存储的读请求、跨区流量可能比容量贵。

11. **NFS 扛高并发 checkpoint**
   元数据和锁容易成为瓶颈；评估并行 FS。

12. **缓存没有淘汰策略**
    本地盘被旧 shard 占满；要 LRU/容量上限。

## 10. 要点回顾

1. 存储层级：HBM → 本地 NVMe → 并行 FS → 对象存储 → 归档
2. 文件/块/对象语义不同；对象存储不是 POSIX
3. 训练数据尽量大 shard、顺序读、本地缓存、预取
4. 并行 FS 看聚合带宽、元数据、条带和并发
5. checkpoint 含权重+优化器+训练状态，常按 12–16 bytes/参数估
6. checkpoint 要分片、异步、原子切换、保留版本、演练恢复
7. 7B/70B checkpoint 约 112GB/1.1TB；写入时间和训练停顿要算
8. 容量、带宽、IOPS、延迟、请求/egress 成本要一起看
