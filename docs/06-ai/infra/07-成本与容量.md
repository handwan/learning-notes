# 成本与容量

AI 系统的成本不是一个“GPU 单价”，而是：

```text
GPU/算力
+ 存储/网络
+ 机房/电力/散热
+ 运维/人力
+ 空闲/冗余
+ 失败重试/冷启动
```

容量规划也不是“买几张卡”，而是：在目标延迟/SLO 下，需要多少副本、多少 GPU、多少余量。

这篇讲每百万 token 成本、API vs 自托管、训练成本、容量规划和利用率，最后做一个成本/容量实验。

## 1. 成本组成

| 项目 | 计费方式 | 容易漏掉 |
|---|---|---|
| GPU | 按小时/按月/按卡 | 空闲、碎片、MIG |
| CPU/内存 | 节点资源 | dataloader、服务 |
| 存储 | GB/月、请求、egress | checkpoint、数据集、缓存 |
| 网络 | 带宽/流量 | 跨区、egress、NCCL |
| 电力/散热 | kWh、PUE | 高功耗卡、机房 |
| 运维 | 人力/工具 | 监控、升级、值班 |
| 失败/重试 | 隐性 | 抢占、OOM、冷启动 |

云上还要看：

- 按需 vs 预留 vs spot
- 跨区流量
- 对象存储请求费
- 负载均衡/NAT/日志费用

## 2. 每百万 token 成本

粗略公式：

$$
\text{cost/1M}
=
\frac{\text{GPU USD/h}}
{\text{tokens/s}\times3600\times\text{utilization}}
\times10^6
$$

- tokens/s：单 GPU 满载吞吐（压测峰值）；若用长期实测平均吞吐，则 utilization 取 1
- utilization：有效利用率（不是 nvidia-smi 的时间占比）
- GPU USD/h：按需/预留/摊销后的价格

例：GPU USD 2/h、2000 tokens/s、60% 利用率：

$$
\frac{2}{2000\times3600\times0.6}\times10^6
\approx \text{USD }0.463/1M
$$

注意：

- 输入/输出 token 成本不同
- prefill 和 decode 吞吐不同
- batch、序列长度、KV cache 都会改变 tokens/s
- 缓存命中会降低成本
- 量化/蒸馏/小模型会改变分母

## 3. API vs 自托管

API：

- 按 token 付费
- 无 GPU 运维
- 价格透明但可能限流/涨价
- 数据/合规/供应商锁定

自托管：

- GPU/机房/运维固定成本
- 利用率越高，单位成本越低
- 空闲时仍然烧钱
- 需要容量规划/故障处理

盈亏平衡吞吐：

$$
\text{tps}_{\text{break-even}}
=
\frac{\text{GPU USD/h}\times10^6}
{\text{API USD/1M}\times3600\times\text{utilization}}
$$

例：GPU USD 2/h、API USD 0.50/1M、60% 利用率：

$$
\frac{2\times10^6}{0.5\times3600\times0.6}
\approx1852\text{ tokens/s}
$$

低于这个吞吐，API 可能更便宜；高于它，自托管可能有优势（还要算运维/存储/网络）。

## 4. 容量规划

需求：

$$
\text{GPU 数}
=
\left\lceil
\frac{\text{日 token 需求}}
{\text{tokens/s}\times86400\times\text{utilization}}
\right\rceil
$$

例：300M tokens/day、2000 tokens/s、60% 利用率：

- 单 GPU 日吞吐约 103.7M tokens
- 需要 3 张 GPU
- 加 N+1 冗余是 4 张
- 4 张时利用率约 72.3%

容量规划还要看：

- 峰值/平均比
- 增长趋势
- SLO/延迟
- 故障域
- 冷启动/扩容时间
- 地域分布
- 预留/spot 比例

## 5. 训练成本

训练算力：

$$
C\approx6ND
$$

GPU 小时：

$$
\text{GPU-h}
=
\frac{C}{\text{effective TFLOPS}\times10^{12}\times3600}
$$

例：7B 参数、1T token、有效 400 TFLOPS、USD 3/GPU-h：

- $C=6\times7\times10^9\times10^{12}=4.2\times10^{22}$ FLOPs
- 约 29,167 GPU-h
- 约 USD 87,500
- 折合训练每百万 token 约 USD 0.0875

训练还有：

- 失败重跑
- checkpoint 存储
- 数据预处理
- 调参实验
- 人工/评估

所以“训练成本”通常要乘一个实验/失败系数。

## 6. 利用率与 TCO

TCO 不是只看 GPU 单价：

- 利用率低 → 单位成本高
- 过度冗余 → 利用率低
- 利用率太高 → 没余量，故障/突发扛不住
- 电力/散热/机房可能占很大比例
- 存储/网络/运维是隐性成本

常见目标：

- 训练：尽量高利用率，但留故障恢复
- 推理：目标利用率通常 50–70%，即留 30–50% headroom
- 多租户：用配额/抢占提高整体利用率

## 7. 实验：成本与容量

??? note "代码：实验：成本与容量"
    ```python
    import math

    def cost_per_m(gpu_hour, tps, util):
        return gpu_hour / (tps * 3600 * util) * 1e6

    for util in [0.3, 0.6, 0.9]:
        for tps in [500, 2000, 5000]:
            print(f"util={util:.1f} tps={tps:4d} cost=${cost_per_m(2, tps, util):.3f}/1M")

    print("break-even tps for api $0.50/1M")
    for util in [0.3, 0.6, 0.9]:
        tps = 2 * 1e6 / (0.5 * 3600 * util)
        print(f"util={util:.1f} tps={tps:.0f}")

    print("capacity 300M tokens/day")
    per_gpu = 2000 * 86400 * 0.6 / 1e6
    need = math.ceil(300 / per_gpu)
    print(f"per_gpu={per_gpu:.1f}M need={need} n+1={need + 1} util_at_n1={300 / ((need + 1) * per_gpu):.1%}")

    def train_cost(params_b, tokens_t, effective_tflops=400, price=3):
        flops = 6 * params_b * 1e9 * tokens_t * 1e12
        hours = flops / (effective_tflops * 1e12 * 3600)
        return hours, hours * price

    hours, cost = train_cost(7, 1)
    print(f"train 7B/1T: {hours:.0f} GPU-h ${cost:,.0f} per1M=${cost / 1e6:.4f}")
    ```

读法：

- 同样 USD 2/h，tokens/s 从 500 到 5000，单位成本差 10 倍
- 利用率从 0.3 到 0.9，单位成本差 3 倍
- API USD 0.50/1M 时，60% 利用率下需要约 1852 tokens/s 才打平
- 300M tokens/day 需要 3 张卡，加 N+1 是 4 张
- 训练 7B/1T 约 29k GPU-h、USD 87.5k（示例）

## 8. 常见坑

1. **只算 GPU 单价**
   存储、网络、电力、运维、空闲都要算。

2. **用峰值吞吐算成本**
   实际 tokens/s 受 batch/序列/KV cache 影响。

3. **把 nvidia-smi 利用率当有效利用率**
   时间占比不等于算力/带宽用满。

4. **忽略输入/输出 token 差异**
   prefill 和 decode 成本不同；输出通常更贵。

5. **API 和自托管直接比单价**
   自托管有固定成本/运维；API 有数据/限流/锁定。

6. **不留 N+1**
   一台故障就超 SLO；省下的钱不够赔。

7. **过度冗余**
   利用率太低，单位成本高；要按峰值/增长/SLO 规划。

8. **忽略冷启动**
   GPU 节点/模型加载要时间；扩容不是瞬时。

9. **spot 不留 checkpoint**
   抢占后重跑，成本可能更高。

10. **缓存/前缀缓存没算命中率**
    命中率高会显著降低成本；但要不影响正确性。

11. **只看训练成本**
    推理是长期成本；部署量越大，推理越关键。

12. **用单一/理想负载调容量**
    过拟合到某个负载，线上会翻车；要按真实流量、峰值和增长留余量。

## 9. 要点回顾

1. 成本 = GPU + 存储 + 网络 + 电力 + 运维 + 空闲/失败
2. cost/1M ≈ GPU USD/h ÷ (tokens/s × 3600 × utilization) × 1e6
3. API vs 自托管看盈亏平衡吞吐，不只看单价
4. 容量 = 日需求 ÷ 单卡日吞吐，再加 N+1/增长/峰值
5. 训练成本用 6ND、有效 TFLOPS、GPU 价格估算
6. 利用率低会放大单位成本；太高又没故障余量
7. 推理是长期成本，缓存/量化/批处理都能改变分母
8. 成本规划要和 SLO、容量、故障恢复一起做
