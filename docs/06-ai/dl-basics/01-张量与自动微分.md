# 张量与自动微分

神经网络拆到最底层，就两件事：

- 数据怎么存成**张量**，怎么变形、广播
- 梯度怎么**自动**算出来

这篇不训练模型，只把这两个地基跑通。

## 1. 张量是什么

张量是多维数组，但比 Python 的 `list` 多了向量化、广播、GPU 和自动求导。先看几个属性：

| 属性 | 含义 | 例子 |
|---|---|---|
| `shape` | 每个维度多长 | `(2, 3)` |
| `dtype` | 元素类型 | `torch.float32` |
| `device` | 存在 CPU 还是 GPU | `cpu` / `cuda:0` |
| `requires_grad` | 要不要记录梯度 | `True` / `False` |
| `stride` | 布局：每个维度走一步跨多少个元素 | `(3, 1)` |

维度直觉：

| 维度 | 形状 | 典型用途 |
|---|---|---|
| 0D | `()` | 一个标量，比如 loss |
| 1D | `(d,)` | 一个向量、一个样本 |
| 2D | `(n, d)` | 一批样本，或一张矩阵 |
| 3D | `(b, n, d)` | batch + 序列 + 特征 |

> `torch.tensor([1, 2])` 默认是 `int64`；`torch.tensor([1., 2.])` 才是 `float32`。训练前先确认 dtype。

### 形状、view、reshape

??? note "代码：形状、view、reshape"
    ```python
    import torch

    x = torch.arange(6, dtype=torch.float32).reshape(2, 3)
    print("x", x)
    print("shape", x.shape, "dtype", x.dtype, "device", x.device, "stride", x.stride())

    y = torch.tensor([10.0, 20.0, 30.0])
    print("broadcast", (x + y).shape)
    print(x + y)

    t = x.t()
    print("t", t.shape, t.stride(), t.is_contiguous())
    try:
        print(t.view(6))
    except RuntimeError:
        print("view error: non-contiguous tensor")
    print("reshape", t.reshape(6))
    print("contiguous view", t.contiguous().view(6))
    ```

输出：

```text
x tensor([[0., 1., 2.],
        [3., 4., 5.]])
shape torch.Size([2, 3]) dtype torch.float32 device cpu stride (3, 1)
broadcast torch.Size([2, 3])
tensor([[10., 21., 32.],
        [13., 24., 35.]])
t torch.Size([3, 2]) (1, 3) False
view error: non-contiguous tensor
reshape tensor([0., 3., 1., 4., 2., 5.])
contiguous view tensor([0., 3., 1., 4., 2., 5.])
```

几个点：

- `x.stride() == (3, 1)`：第 0 维走一步跨 3 个元素，第 1 维走一步跨 1 个
- `x.t()` 只改 stride，不复制数据，所以 `t` 不连续
- `view` 要求内存布局兼容，通常要求连续；`reshape` 不满足时会复制
- `contiguous()` 在不连续时复制成连续布局，之后才能 `view`；本来就连续则直接返回

> `stride` 的单位是**元素个数**，不是字节。

### 广播

广播规则：

1. 从最后一维开始对齐
2. 维度相等，或其中一个是 1，才能广播
3. 缺的维度当成 1

```text
x: (2, 3)
y:    (3,)
=> (2, 3)
```

`y` 被当成 `(1, 3)`，再沿第 0 维复制。广播本身不复制数据，但运算结果会分配新内存。

## 2. 自动微分

### 计算图

前向计算时，PyTorch 会为每个带梯度的运算记录一个节点：

```text
x → square → add → loss
```

需要梯度的结果会带一个 `grad_fn`，指向产生它的反向函数。叶子节点是没有 `grad_fn` 的张量，通常是用户直接创建的；只有 `requires_grad=True` 的叶子才会累积 `.grad`。中间结果是非叶子节点。

反向传播从标量 loss 开始，按链式法则往回乘：

$$
\frac{\partial L}{\partial x}
= \sum_i \frac{\partial L}{\partial y_i}
  \frac{\partial y_i}{\partial x}
$$

这就是**反向模式自动微分**。它一次 backward 就能算出所有参数的梯度，代价大约是前向的两倍，适合“参数多、输出少”的神经网络。

### 最小例子

??? note "代码：最小例子"
    ```python
    import torch

    a = torch.tensor(2.0, requires_grad=True)
    f = 3 * a**2 + 2 * a + 1
    f.backward()
    print("f", f.item(), "df/da", a.grad.item())

    u = torch.tensor(2.0, requires_grad=True)
    v = torch.tensor(3.0, requires_grad=True)
    z = (u * v + 1) ** 2
    z.backward()
    print("z", z.item(), "dz/du", u.grad.item(), "dz/dv", v.grad.item())

    w = torch.tensor(1.0, requires_grad=True)
    for i in range(3):
        loss = w**2
        loss.backward()
        print("acc", i, w.grad.item())

    p = torch.tensor([1.0, 2.0, 3.0], requires_grad=True)
    q = p**2
    try:
        q.backward()
    except RuntimeError:
        print("non-scalar: need sum() or gradient=")
    q.sum().backward()
    print("p.grad", p.grad)

    r = torch.tensor([1.0, 2.0], requires_grad=True)
    s = (r * 2).detach()
    with torch.no_grad():
        t = r * 3
    print("detach/no_grad", s.requires_grad, t.requires_grad)

    m = torch.tensor(2.0, requires_grad=True)
    n = m * 3
    n.retain_grad()
    o = n ** 2
    o.backward()
    print("m/n grad", m.grad.item(), n.grad.item())
    ```

输出：

```text
f 17.0 df/da 14.0
z 49.0 dz/du 42.0 dz/dv 28.0
acc 0 2.0
acc 1 4.0
acc 2 6.0
non-scalar: need sum() or gradient=
p.grad tensor([2., 4., 6.])
detach/no_grad False False
m/n grad 36.0 12.0
```

逐条看：

- $f(a)=3a^2+2a+1$，$f'(a)=6a+2$；$a=2$ 时手算是 14，autograd 也是 14
- $z=(uv+1)^2$；$\partial z/\partial u=2(uv+1)v=42$，$\partial z/\partial v=2(uv+1)u=28$
- 连续三次 `backward()` 没有清梯度，`w.grad` 从 2 累加到 4、6
- 非标量 `q` 不能直接 `backward()`；要么 `q.sum()`，要么传 `gradient`
- `detach()` 和 `torch.no_grad()` 都会切断梯度记录
- 非叶子节点默认不存 `.grad`；`retain_grad()` 后才有

### 常用 API

| API | 作用 |
|---|---|
| `requires_grad=True` | 让叶子节点记录梯度 |
| `backward()` | 从标量输出反向传播 |
| `.grad` | 叶子节点累积的梯度 |
| `zero_grad()` | 清空梯度，训练循环每步都要做 |
| `detach()` | 返回共享存储、不参与计算图的张量 |
| `torch.no_grad()` | 块内不记录梯度，推理/评估常用 |
| `retain_grad()` | 让非叶子节点也保存 `.grad` |

## 3. 放回训练循环

一个最小训练步骤就是把这几个动作排好：

??? note "代码：放回训练循环"
    ```python
    # 片段：model、loss_fn、optimizer 已定义
    pred = model(x)
    loss = loss_fn(pred, y)

    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
    ```

顺序：

1. 前向：建计算图，得到 `loss`
2. `zero_grad()`：清掉上一步累积的梯度
3. `backward()`：反向传播，把梯度写进参数的 `.grad`
4. `step()`：按梯度和优化器规则更新参数
5. 下一轮重新前向，建新的计算图

评估时用 `model.eval()` + `torch.no_grad()`，不建图，省显存也更快。

[下一篇](02-最小线性模型.md) 会用这套循环写一个最小线性模型。

## 4. 常见坑

1. **忘记 `zero_grad()`**
   PyTorch 的梯度是累加的，不清就会把上一步的梯度加进来。

2. **对非标量直接 `backward()`**
   会报 `grad can be implicitly created only for scalar outputs`。先 `sum()`/`mean()`，或传 `gradient=`。

3. **`view` 和 `reshape` 混用**
   `transpose` 后的张量不连续，`view` 会报错；用 `reshape` 或先 `contiguous()`。

4. **对叶子节点做 in-place**
   `x += 1` 会报 `a leaf Variable that requires grad is being used in an in-place operation`。要么在 `no_grad()` 里改，要么新建张量。

5. **`detach()` 和 `no_grad()` 分不清**
   `detach()` 返回一个共享存储但不带梯度的张量；`no_grad()` 是一个上下文，块内所有运算都不记录。

6. **以为中间节点也有 `.grad`**
   默认只有叶子节点保存；要看中间梯度，先 `retain_grad()`。

7. **重复 backward 没加 `retain_graph`**
   计算图默认在 backward 后释放，再 backward 会报 “Trying to backward through the graph a second time”。一般不需要保留；要保留就显式加。

8. **dtype / device 不一致**
   模型在 GPU、数据在 CPU，或者 `float64` 和 `float32` 混用，都会报错或变慢。统一用 `float32`，并在同一 device 上。

9. **把 loss 张量一直存着**
   日志用 `loss.item()`，不要把带计算图的 loss 累积到 list 里，否则内存/显存会涨。

## 5. 要点回顾

1. **张量 = 多维数组 + dtype + device + requires_grad + stride**
2. `view` 不复制，但要求布局兼容（通常要连续）；`reshape` 可能复制；`transpose` 只改 stride
3. 广播从最后一维对齐，维度相等或为 1 才能广播
4. autograd 前向建图，反向从标量 loss 开始，按链式法则算梯度
5. `.grad` 是**累加**的；训练循环每步先 `zero_grad()`
6. 非标量输出不能直接 `backward()`；`detach()` / `no_grad()` 可以切断梯度
7. 默认只有叶子节点保存 `.grad`；中间节点需要 `retain_grad()`
