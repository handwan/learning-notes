# 推理训练：RLVR 与长 CoT

推理训练不是“让模型多想”这么简单。要解决：

- 奖励从哪来（verifier）
- 哪些题值得采样（难度/覆盖）
- 长 CoT 变长后怎么防止废话/长度 hacking
- rollout、verifier、训练怎么衔接
- 怎么评测（pass@1/pass@k、token、延迟、污染）

这篇讲 RLVR 的训练工程：verifier、数据、GRPO/PPO、长 CoT 控制、rollout 与评测，最后做一个小模型 RLVR 实验。CoT/RLVR/test-time compute 的概念见 [LLM 第 8 篇](../llm/08-推理模型.md)；这里不重复。

## 1. RLVR 的闭环

```text
prompt
→ policy rollout（每题采样 G 个回答）
→ verifier 打分
→ group advantage
→ policy update
```

| 环节 | 关键问题 |
|---|---|
| prompt | 答案可验证吗？难度分布如何？ |
| rollout | 采样多少、温度多少、长度上限 |
| verifier | 判对判错是否可靠、是否能被绕过 |
| advantage | 组内相对优势，还是 critic/GAE |
| update | KL、clip、长度惩罚、学习率 |

RLVR 和 RLHF 最大的区别：奖励来自规则/测试/答案，不是人类偏好模型。好处是自动、便宜；风险是 verifier 漏洞会被模型放大。

## 2. Verifier 工程

Verifier 是 RLVR 的核心组件，不是附属脚本。

数学：

- 抽取最终答案（`\boxed{}`、最后一行、指定格式）
- 归一化：空格、大小写、分数/小数、单位、等价表达式
- 多解/区间/集合要按题意判
- 复杂表达式用 sympy，但要有超时和失败回退

代码：

- 单元测试 + 隐藏测试
- 沙箱、资源限制、超时、网络隔离
- 测试本身要防 flaky/顺序依赖
- 防硬编码/读测试/打印答案

工具/结构化：

- JSON Schema/参数校验
- 工具返回是否符合预期
- 多步任务的中间状态

奖励设计：

- 0/1 最干净，但稀疏
- partial credit/过程奖励更密，但更容易被刷
- format reward 只给格式，不要压过正确性
- 长度惩罚/预算要单独加，别把“短”当成“对”

Verifier 自己也要测试：

- 拿已知正确/错误答案跑一遍
- 构造 adversarial 输出，看能不能骗过
- 统计 false positive/false negative
- 保留 verifier 版本，训练/评测一致

Verifier 的漏洞就是 reward hacking 的入口。

## 3. 数据构造

RLVR 的数据不是“随便找题”，而是“可验证 + 有梯度”。

- 题目要有确定答案/测试
- 难度要覆盖：全对/全错都没有学习信号
- 答案格式统一，verifier 能稳定抽取
- 训练/评测去重，防污染
- 动态/私有题集，防背题

来源：

- 人类出题 + 标准答案
- 强模型生成题/解，verifier 过滤
- 拒绝采样：只保留答案正确的轨迹
- 合成变体：改数字、改约束、改测试
- 过程奖励/PRM：更贵，但能减少“错过程 + 对答案”

SFT 冷启动：

- 先用带 CoT 的数据做 SFT，教格式和基本步骤
- 再上 RLVR，别让模型从零学“怎么想”
- SFT 数据要 concise；太长会教出冗长风格

课程：

- 从易到难，或按 pass rate 分层
- 全 0/全 1 的组没有 advantage；要动态采样/换题
- 难题可以给更多 rollout，但要注意成本

## 4. GRPO / PPO 工程

GRPO 是 RLVR 常用算法：每题采样 G 个回答，用组内相对奖励做 advantage，不需要 critic。

简化损失：

$$
L_{\mathrm{GRPO}}
=-\frac{1}{G}\sum_{i=1}^{G}
\hat A_i \log\pi_\theta(y_i\mid x)
+\beta\,\mathrm{KL}\left(\pi_\theta\,\|\,\pi_{\mathrm{ref}}\right)
$$

- $\hat A_i=(r_i-\mathrm{mean}(r))/\mathrm{std}(r)$
- 组内全对/全错时 std=0，advantage=0，没有信号
- reference 冻结，KL 防止跑偏
- 可以加 PPO 式 clip、长度惩罚、entropy

这里写的是响应级最小演示；实际 GRPO 用 token-level log-prob + importance ratio/clip，不是每个 response 一个标量 log-prob。

RLHF 的 PPO 要 actor/critic/reward/reference 四类模型，见[对齐训练](03-对齐训练.md)；RLVR 用 verifier 代替 reward model，但 PPO 仍要 actor/critic/reference，依然更重。

工程参数：

| 参数 | 常见做法 |
|---|---|
| group size G | 4–16；越大 advantage 越稳，rollout 越贵 |
| batch | 按 prompt 数，不是按回答数 |
| 温度/top-p | 保证多样性；太低组内全一样 |
| 长度上限 | 防无限长；truncation 要标记 |
| KL β | 小一点让模型探索，太大退化成 SFT |
| 学习率 | 比 SFT 小；看 KL/entropy |
| clip | PPO 式更新时用；GRPO 简化版可不用 |

rollout 工程：

- vLLM/SGLang 生成，训练侧 FSDP/ZeRO
- 生成和训练的 tokenizer/template/version 必须一致
- old policy log-prob 要对齐；异步要注意 off-policy
- verifier 可能慢/超时；要并发、重试、隔离
- 生成失败/截断的样本要标记，不要当负样本

显存：

- GRPO：policy + reference，7B BF16 约 28GB 权重，另加激活/rollout
- PPO：RLHF 版再加 critic/reward；RLVR 版用 verifier 代替 reward model，但仍要 critic
- LoRA/QLoRA 能降，但 rollout 和 reference 仍要算

## 5. 长 CoT 控制

长 CoT 对难题有帮助，但不是越长越好。

奖励只给正确性时：

- 长 CoT 可能因为“多写几步碰对”被强化
- 模型会学会写废话、重复检查、堆 token
- 简单题也变长，延迟和成本上升

控制手段：

- 长度惩罚/预算：超过预算扣分或截断
- 长度分层：按题目难度给不同预算
- 格式奖励：最终答案必须可解析
- 截断标记：未完成/超时的 CoT 不给正奖励
- SFT 冷启动用简洁 CoT，别先教冗长
- 评测同时看 pass@1/pass@k、token、延迟

不要只看“更长 = 更聪明”。长 CoT 是工具，不是目标。

thinking/non-thinking 的路由、test-time compute 的预算分配见 [LLM 第 8 篇](../llm/08-推理模型.md)。

## 6. 评测与失败模式

指标：

- pass@1：一次回答的正确率
- pass@k：采样 k 次的覆盖率
- majority vote / best-of-N：推理时策略
- token/延迟：长 CoT 的成本
- 难度分层：简单/中等/难题分开看
- cost per correct answer：把 token/延迟折算后除以准确率

评测集：

- 动态/私有题，防背题
- 训练/评测去重，防污染
- verifier 和训练用同一版本
- 固定 seed/温度，报告方差

失败模式：

- verifier false positive/negative
- reward hacking：格式/测试/答案漏洞
- 长度 hacking：废话、重复、过度检查
- 全 0/全 1 组：没有学习信号
- rollout 和训练分布漂移
- CoT 不忠实；答案对但过程错
- 安全/越狱：长 CoT 暴露更多信息
- 只在简单题上提升，难题没变化

## 7. 实验：最小 GRPO/RLVR

用一个表格型 policy 演示 RLVR 闭环：

- 32 个 prompt，每个 4 个候选答案
- verifier：选对答案得 1，否则 0
- 每题采样 G=8 个回答
- group-relative advantage，KL 到初始 policy
- β=0.01，Adam 300 步

??? note "代码：最小 GRPO/RLVR"
    ```python
    import torch
    from torch.distributions import Categorical

    torch.manual_seed(0)
    P, A = 32, 4
    correct = torch.randint(0, A, (P,))
    logits = torch.zeros(P, A, requires_grad=True)
    ref_logits = logits.detach().clone()
    opt = torch.optim.Adam([logits], lr=0.1)
    G, B, beta = 8, 16, 0.01

    def accuracy():
        with torch.no_grad():
            return (logits.argmax(dim=1) == correct).float().mean().item()

    def entropy():
        with torch.no_grad():
            p = torch.softmax(logits, dim=1)
            return -(p * torch.log(p + 1e-9)).sum(dim=1).mean().item()

    print("prompts", P, "answers", A, "group", G, "beta", beta)
    print("initial acc", f"{accuracy():.2%}", "entropy", f"{entropy():.3f}")

    for step in range(1, 301):
        idx = torch.randint(0, P, (B,))
        dist = Categorical(logits=logits[idx])
        actions = dist.sample((G,))
        logp = dist.log_prob(actions)
        reward = (actions == correct[idx].unsqueeze(0)).float()

        mean = reward.mean(dim=0, keepdim=True)
        std = reward.std(dim=0, keepdim=True) + 1e-6
        adv = (reward - mean) / std

        ref_dist = Categorical(logits=ref_logits[idx])
        logp_ref = ref_dist.log_prob(actions)
        kl = (logp - logp_ref).mean()

        loss = -(adv.detach() * logp).mean() + beta * kl
        opt.zero_grad()
        loss.backward()
        opt.step()

        if step in [50, 100, 200, 300]:
            print(f"step {step:3d} loss {loss.item():.4f} reward {reward.mean().item():.3f} acc {accuracy():.2%} entropy {entropy():.3f}")
    ```

输出：

```text
prompts 32 answers 4 group 8 beta 0.01
initial acc 28.12% entropy 1.386
step  50 loss -0.3324 reward 0.961 acc 100.00% entropy 0.200
step 100 loss -0.0817 reward 0.992 acc 100.00% entropy 0.069
step 200 loss 0.0138 reward 1.000 acc 100.00% entropy 0.033
step 300 loss -0.1157 reward 0.992 acc 100.00% entropy 0.020
```

读法：

- 初始 policy 接近均匀，accuracy 28.12%、entropy 1.386
- step 50 已经到 100%，说明这个小任务很快被记住
- reward 从约 0.25 升到约 1.0，entropy 从 1.386 降到 0.020，策略变确定
- 这是表格型最小 GRPO，验证 verifier → group advantage → update 的闭环；不是 LLM，也没有长 CoT
- 组内全对/全错时 advantage=0；真实训练要靠难度分层/动态采样避免这种组

## 8. 怎么选

| 场景 | 路线 |
|---|---|
| 数学/代码有可靠 verifier | RLVR/GRPO |
| 没有 verifier，有偏好对 | DPO/ORPO（见[对齐训练](03-对齐训练.md)） |
| 只有正确轨迹，没有偏好 | 拒绝采样 + SFT（RFT） |
| 长 CoT/难推理 | SFT 冷启动 + RLVR + 长度控制 |
| 算力有限 | RFT/蒸馏优先，RLVR 小规模试 |
| 小模型 | 强模型蒸馏 + 易/中等题 RLVR |

RLVR 不是免费的：verifier、题目、rollout 都要成本。先用拒绝采样/SFT 验证数据和格式，再上在线 RL。

## 9. 常见坑

1. **Verifier 判错**
   false positive/negative 会把模型带偏；先测 verifier。

2. **只看最终答案**
   “错过程 + 对答案”会被强化；需要过程奖励/人工抽查。

3. **全 0/全 1 组**
   advantage 全是 0，没有学习信号；要难度分层/动态采样。

4. **长度 hacking**
   奖励长 CoT，模型会写废话；要长度惩罚/预算。

5. **截断/超时不算失败**
   未完成的 CoT 给了正奖励，模型学会拖长；要标记失败。

6. **format reward 过强**
   模型只学格式，不学推理；格式奖励要小于正确性。

7. **reference/KL 设置错**
   reference 没冻结/换了 checkpoint，KL 没意义。

8. **rollout 和训练引擎不一致**
   tokenizer/template/version 不同，old log-prob 对不上。

9. **采样温度太低**
   组内回答几乎一样，advantage 没方差；要保证多样性。

10. **训练/评测污染**
    评测题进了训练集；用动态/私有题集。

11. **只看 pass@1**
    忽略 token/延迟，长 CoT 可能“更准但更贵”。

12. **只在简单题上提升**
    难题没覆盖，或全错没信号；要做难度分层。

13. **安全/CoT 泄漏**
    长 CoT 暴露更多信息，也可能被诱导绕过安全策略。

## 10. 要点回顾

1. RLVR 闭环：prompt → rollout → verifier → group advantage → update
2. Verifier 是核心组件；要测 false positive/negative 和漏洞
3. 数据要可验证、难度分层、去重防污染；全 0/全 1 没信号
4. GRPO 用组内相对优势，不需要 critic；PPO 更重
5. 7B GRPO 的 policy + reference 约 28GB 权重，另加激活/rollout
6. 长 CoT 要有长度惩罚/预算/截断标记，防长度 hacking
7. 评测看 pass@1/pass@k、token、延迟、难度分层、安全
8. 数据质量/verifier 质量 > 算法；RLVR 不会修复坏奖励
9. 算力有限先 RFT/拒绝采样 + SFT，再小规模 RLVR
