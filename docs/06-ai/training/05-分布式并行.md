# 分布式并行

单卡放不下、或者单卡训得太慢时，分布式不是“多买几张卡”这么简单。先决定切什么：

- 数据（DP）
- 层内（TP）
- 层间（PP）
- 模型状态（ZeRO/FSDP）
- 专家（EP，MoE）

每切一刀都有通信、显存和实现复杂度。这篇讲 DP/TP/PP/ZeRO 的显存账、通信量、拓扑映射和单卡模拟实验。NVLink/IB/RDMA/all-reduce 的基础见 [Infra 第 4 篇](../infra/04-网络与互联.md)；这里讲训练并行。

## 1. 五种切法

| 方法 | 切什么 | 每卡模型状态 | 主要通信 | 适合 |
|---|---|---|---|---|
| DP | batch | 完整模型 | 梯度 all-reduce | 模型放得下，吞吐不够 |
| TP | 层宽/头 | 约 1/TP | 每层 all-reduce/all-gather | 单卡放不下，NVLink 域内 |
| PP | 层 | 约 1/PP | stage 间 P2P | 深模型/多机，能忍 bubble |
| ZeRO/FSDP | 优化器/梯度/参数 | 16/N–16 bytes/param | all-gather/reduce-scatter | 模型状态太大 |
| EP | 专家 | 约 1/EP | all-to-all | MoE |

并行不是互斥的。生产常见 3D 并行：TP 放机内 NVLink，PP/DP 跨机。

## 2. DP：数据并行

做法：

- 每张卡一份完整模型
- 全局 batch 切给各卡
- 反向后对梯度做 all-reduce（通常取平均）
- 每张卡用相同梯度更新，模型保持一致

全局 batch：

$$
\text{global batch}
=
\text{local batch}\times\text{DP}\times\text{grad accum}
$$

显存：

- DP **不降低模型状态**；每卡仍是完整权重+梯度+优化器
- 7.2B 混合精度 AdamW 约 16 bytes/param ≈ 115GB；DP 不会把它变成 1/N
- DP 降的是每卡 batch/激活，不是模型状态

通信：

- ring all-reduce 约 2S/step，S 是梯度大小
- 7.2B BF16 梯度约 14.4GB；2S ≈ 28.8GB/step
- 可以和 backward 重叠、bucket、减少小消息
- 跨机看 IB/RoCE 带宽和拓扑，见 [Infra 第 4 篇](../infra/04-网络与互联.md)

梯度累积：

- 用多个 micro-batch 累积梯度，再 step
- 等大小 micro-batch 时，`loss/accum` 的平均等于大 batch 的平均
- 省激活，不省模型状态；不是多卡的替代品
- 全局 batch 变了，学习率/warmup 要一起调

常见问题：

- 各卡 batch 不均/最后一批不满；`drop_last` 或调整
- 慢卡拖住 all-reduce（straggler）
- 只在 rank 0 记录日志/评测，其他 rank 空转
- 以为 DP 能解决 OOM

## 3. TP：张量并行

把一层内的矩阵切给多张卡：

- **Column parallel**：按输出维切权重，各卡算一部分输出
- **Row parallel**：按输入维切权重，各卡算部分和，再 all-reduce 求和
- Attention 按 head 切；MLP 按 intermediate 维切

显存：

- 权重约 1/TP
- 激活也会下降，但不是所有 buffer 都按 TP 切
- 每层都要通信，TP 越大通信越频繁

通信：

- 每层 all-reduce/all-gather，消息小、次数多
- 对延迟敏感；尽量放同机 NVLink 域
- TP 跨机会被网络延迟吃掉，通常不划算

约束：

- attention heads / hidden / FFN 要能被 TP 整除
- GQA/MQA 的 KV heads 可能限制 TP 大小
- vocab/embedding 切分要单独处理

常见组合：TP 机内 + DP 跨机；大模型再叠 PP。

## 4. PP：流水并行

按层切成 stage：

```text
GPU0: layer 0-7
GPU1: layer 8-15
GPU2: layer 16-23
GPU3: layer 24-31
```

一个 batch 再切成多个 micro-batch，stage 之间传激活：

- 前向：stage0 → stage1 → ...
- 反向：... → stage1 → stage0
- 通信是点对点，量约等于激活大小

Bubble：

$$
\text{bubble}
\approx
\frac{P-1}{M+P-1}
$$

- P：stage 数
- M：micro-batch 数
- M 越大 bubble 越小，但在途激活越多
- 1F1B 主要降在途激活；interleaved schedule 进一步降 bubble；实现更复杂

显存：

- 权重约 1/PP
- 激活取决于在途 micro-batch 数；1F1B 比 naive 更省
- activation checkpointing 可以再降

难点：

- stage 计算量要均衡；否则最慢 stage 拖住整条流水线
- micro-batch 太小，kernel 效率低；太大，bubble/显存上升
- PP 跨机要传激活，带宽/延迟要算
- 全局 batch 仍由 `micro_batch × grad_accum × DP` 决定

## 5. ZeRO / FSDP：切模型状态

DP 每卡都存完整模型状态。ZeRO 把它切开：

| 阶段 | 切什么 | 每卡模型状态（bytes/param） |
|---|---|---|
| DP | 不切 | 16 |
| ZeRO-1 | 优化器状态 | 2 + 2 + 12/N |
| ZeRO-2 | + 梯度 | 2 + (2+12)/N |
| ZeRO-3 | + 参数 | 16/N |

7.2B、8 卡、混合精度 AdamW（模型状态，不含激活）：

| 方法 | 每卡 |
|---|---|
| DP | 115.2GB |
| ZeRO-1 | 39.6GB |
| ZeRO-2 | 27.0GB |
| ZeRO-3 | 14.4GB |

注意：

- 这是理想模型状态；真实还有激活、临时 buffer、碎片
- ZeRO-3 前向/反向要 all-gather 参数，反向还要 reduce-scatter 梯度
- 通信比 DP 多；省显存不是免费的
- FSDP 类似 ZeRO-3，支持 hybrid sharding/分片组
- CPU/NVMe offload 能再省，但速度慢
- activation checkpointing、mixed precision 和 ZeRO 要一起算

## 6. 3D 并行与拓扑

常见映射：

- TP：机内 NVLink 域
- PP：跨机，stage 间 P2P
- DP：跨机，梯度 all-reduce
- EP：all-to-all，对拓扑/负载均衡敏感

通信量级：

| 并行 | 通信 | 特点 |
|---|---|---|
| DP | 梯度 all-reduce，约 2S | 大消息、带宽 |
| TP | 每层 all-reduce/all-gather | 小消息、延迟 |
| PP | stage 间激活 P2P | 与 micro-batch 相关 |
| ZeRO-3 | 参数 all-gather + 梯度 reduce-scatter | 通信更多 |
| EP | all-to-all | 路由不均/拥塞 |

工程：

- rank 映射要匹配 NVLink/IB rail/NUMA
- NCCL 算法/通道数要调；看 `NCCL_DEBUG=INFO`
- 计算/通信重叠（bucket、async）
- straggler 会放大所有并行
- checkpoint 要分片/重分片；别让 rank0 写全量

## 7. 实验：单卡模拟 DP/TP/PP 与显存账

单卡做六件事：

- 梯度累积 vs 全 batch 梯度
- DP 本地梯度平均 vs 全 batch 梯度
- TP column/row parallel 的输出等价
- PP 顺序切层的输出等价
- 7.2B 在 8 卡下的模型状态显存
- PP bubble

??? note "代码：单卡模拟并行与显存账"
    ```python
    import torch
    import torch.nn.functional as F

    torch.manual_seed(0)
    X = torch.randn(32, 16)
    y = torch.randn(32, 1)
    W = torch.randn(1, 16)

    def grad_on(X, y, W):
        W = W.clone().requires_grad_(True)
        loss = F.mse_loss(X @ W.T, y)
        loss.backward()
        return W.grad

    full = grad_on(X, y, W)

    W_acc = W.clone().requires_grad_(True)
    for i in range(4):
        xb = X[i*8:(i+1)*8]
        yb = y[i*8:(i+1)*8]
        loss = F.mse_loss(xb @ W_acc.T, yb) / 4
        loss.backward()
    acc = W_acc.grad

    local = [grad_on(X[i*8:(i+1)*8], y[i*8:(i+1)*8], W) for i in range(4)]
    dp = torch.stack(local).mean(0)

    print("accum max diff", (full - acc).abs().max().item())
    print("dp max diff", (full - dp).abs().max().item())

    X2 = torch.randn(4, 16)
    W2 = torch.randn(8, 16)
    full2 = X2 @ W2.T
    col = torch.cat([X2 @ W2[:4].T, X2 @ W2[4:].T], dim=1)
    row = X2[:, :8] @ W2[:, :8].T + X2[:, 8:] @ W2[:, 8:].T
    print("tp col max diff", (full2 - col).abs().max().item())
    print("tp row max diff", (full2 - row).abs().max().item())

    W1 = torch.randn(32, 16)
    W3 = torch.randn(8, 32)
    full3 = torch.relu(X2 @ W1.T) @ W3.T
    pp = torch.relu(X2 @ W1.T) @ W3.T
    print("pp max diff", (full3 - pp).abs().max().item())

    params_b = 7.2
    print("memory per GPU (7.2B, 8 ranks, model state only)")
    for name, bpp in [("DP", 16), ("ZeRO-1", 2 + 2 + 12/8), ("ZeRO-2", 2 + (2 + 12)/8), ("ZeRO-3", 16/8)]:
        print(f"{name:7s} {params_b*bpp:6.1f} GB")

    S = params_b * 2
    print("DP all-reduce", f"{2*S:.1f} GB/step")

    print("PP bubble")
    for P in [2, 4, 8]:
        for M in [8, 16, 32]:
            print(f"P={P} M={M:2d} bubble={(P-1)/(M+P-1):6.1%}")
    ```

输出：

```text

dp max diff 9.5367431640625e-07
tp col max diff 0.0
tp row max diff 9.5367431640625e-07
pp max diff 0.0
memory per GPU (7.2B, 8 ranks, model state only)
DP       115.2 GB
ZeRO-1    39.6 GB
ZeRO-2    27.0 GB
ZeRO-3    14.4 GB
DP all-reduce 28.8 GB/step
PP bubble
P=2 M= 8 bubble= 11.1%
P=2 M=16 bubble=  5.9%
P=2 M=32 bubble=  3.0%
P=4 M= 8 bubble= 27.3%
P=4 M=16 bubble= 15.8%
P=4 M=32 bubble=  8.6%
P=8 M= 8 bubble= 46.7%
P=8 M=16 bubble= 30.4%
P=8 M=32 bubble= 17.9%
```

读法：

- 梯度累积/DP 平均和全 batch 梯度只差浮点误差（约 1e-6）
- TP column/row parallel 和完整线性层等价；PP 顺序切层也等价
- 7.2B 模型状态：DP 115.2GB；ZeRO-1 39.6GB；ZeRO-2 27.0GB；ZeRO-3 14.4GB
- 这些都不含激活；真实显存会更高
- 7.2B BF16 梯度 14.4GB；DP all-reduce 约 28.8GB/step
- PP bubble：P=4、M=8 时 27.3%；M=32 降到 8.6%；P=8、M=8 是 46.7%

这是单卡数学模拟，不是实际 NCCL 多卡；真实性能要看拓扑、重叠、kernel 和通信库。

## 8. 怎么选

| 场景 | 选择 |
|---|---|
| 模型放得下，吞吐不够 | DP + 梯度累积 |
| 单卡放不下，层内宽 | TP，放 NVLink 域 |
| 层数多/多机 | PP，控制 bubble |
| 模型状态太大 | ZeRO/FSDP |
| MoE | EP |
| 多机 | TP 机内，DP/PP 跨机 |

顺序：

1. 先算模型状态和激活，确认单卡/单机能不能放下
2. 放不下再选 TP/PP/ZeRO；不要一上来 3D
3. 算通信量和拓扑；TP 不跨机
4. 调 global batch/学习率/warmup
5. 压测吞吐、显存、NCCL、straggler
6. 做 checkpoint 分片/恢复演练

## 9. 常见坑

1. **以为 DP 能降显存**
   每卡仍是完整模型状态；DP 只降 batch/激活。

2. **TP 跨机**
   每层小消息多，跨机延迟会把收益吃掉。

3. **TP 维度不整除**
   heads/hidden/FFN 不匹配，直接报错或切不干净。

4. **PP stage 不均衡**
   最慢 stage 拖住整条流水线；要按计算量/显存分。

5. **PP bubble 太大**
   micro-batch 太少；加 M 或换 1F1B/interleaved。

6. **global batch/学习率不匹配**
   加卡/加累积后 global batch 变了；学习率/warmup 要一起调。

7. **ZeRO-3 通信没重叠**
   参数 all-gather/梯度 reduce-scatter 很多；要 bucket/overlap。

8. **activation checkpointing + use_cache**
   训练时关 cache；否则冲突/浪费。

9. **checkpoint 不分片**
   rank0 写全量，慢且容易 OOM；用分片/分布式 checkpoint。

10. **straggler**
    慢卡/慢节点拖住所有 rank；监控每卡 step time。

11. **NCCL/拓扑没配好**
    rank 映射、rail、NUMA、MTU 都会影响；用 `NCCL_DEBUG=INFO`。

12. **只在 rank0 评测/记录**
    其他 rank 空转；要同步或只在 rank0 做。

13. **OOM 只怪模型状态**
    激活、临时 buffer、碎片、KV cache 都可能；分开算。

## 10. 要点回顾

1. DP 切 batch，每卡完整模型；不降模型状态
2. TP 切层宽/头，权重约 1/TP；每层通信，放 NVLink 域
3. PP 切层，权重约 1/PP；bubble ≈ (P-1)/(M+P-1)
4. ZeRO-1/2/3 依次切优化器/梯度/参数；ZeRO-3 通信更多
5. 7.2B 模型状态：DP 115GB；ZeRO-1 39.6；ZeRO-2 27.0；ZeRO-3 14.4
6. 7.2B BF16 梯度约 14.4GB；DP all-reduce（2S）约 28.8GB/step
7. 3D 并行：TP 机内，PP/DP 跨机；EP 看 all-to-all
8. 先算显存，再算通信，再选拓扑；不要一上来 3D
9. checkpoint 要分片/恢复演练；straggler 会放大所有并行
