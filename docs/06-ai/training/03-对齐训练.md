# 对齐训练

SFT 让模型会“答”，对齐让它“按偏好答”。对齐不是只有 PPO：

```text
SFT → RM → PPO
SFT → DPO
SFT → ORPO
```

每条路线的数据和资源不同：

- SFT：只要 prompt-response
- RM/PPO：要偏好对，还要奖励模型和在线 rollout
- DPO：只要偏好对，不需要显式奖励模型
- ORPO：把 SFT 和偏好优化合成一个阶段

这篇讲训练工程：SFT 数据/损失、RM、PPO 的四模型、DPO 的 loss/β/reference、显存与失败模式，最后做一个小数据 DPO 实验。SFT/RLHF/DPO/ORPO 的概念见 [LLM 第 7 篇](../llm/07-微调与对齐.md)；这里不重复。

## 1. 路线与资源

| 路线 | 数据 | 模型 | 7B 权重量级 | 适合 |
|---|---|---|---|---|
| SFT | prompt-response | 1 | 约 14GB | 格式/任务/风格 |
| RM | 偏好对 | 1 + scalar head | 约 14GB | 需要奖励信号 |
| DPO | 偏好对 | policy + reference | 约 28GB | 显存有限、稳定 |
| PPO | 偏好对 → RM | actor + critic + reward + reference | 约 56GB+ | 有工程能力、大规模 |
| ORPO | 偏好对 | 1 | 约 14GB | 单阶段、无 reference |
| RLVR | 可验证奖励 | policy (+ reference) | 14–28GB | 数学/代码/工具 |

上表只是 7B BF16 权重，不含优化器、激活和 rollout；PPO 实际会高很多。

路线不是越复杂越好。数据质量决定上限，PPO 不会把噪声偏好变成好模型。

## 2. SFT 工程

SFT 是对齐的起点，也是 DPO/PPO 的 reference。

数据：

- prompt + response，统一 chat template
- 只在 response 上算 loss，mask 掉 prompt
- 多轮对话保留角色和轮次
- EOS/分隔符和推理时一致

工程：

- 用 tokenizer 的 chat template，不要手拼
- packing 时按样本隔离，别让后一条样本看到前一条
- 长度分布、截断策略、padding side 要固定
- 数据质量 > 数量；低质回答会教坏模型
- 训练 1–3 epoch，别把固定模板训到过拟合

SFT 的 loss、数据和 packing 细节见 [LLM 第 7 篇](../llm/07-微调与对齐.md) 和 [数据管道](01-数据管道.md)。

SFT checkpoint 要冻结一份作为 reference；后面换 base/tokenizer，DPO 的目标就变了。

## 3. 奖励模型（RM）

RM 把“哪个回答更好”学成一个分数。常见 Bradley-Terry：

$$
P(y_w\succ y_l\mid x)=\sigma\left(r_\theta(x,y_w)-r_\theta(x,y_l)\right)
$$

损失：

$$
L_{\mathrm{RM}}
=-\log\sigma\left(r_\theta(x,y_w)-r_\theta(x,y_l)\right)
$$

工程：

- 从 SFT 模型初始化，换一个 scalar head
- 同一个 prompt 的 chosen/rejected 成对训练
- 留出集看 pairwise accuracy，不只看 loss
- 分数是相对的，不是绝对质量；校准要看分布
- RM 推理在 PPO 里是额外成本，批处理和长度要算

数据问题：

- 标注噪声、位置偏差、长度偏差
- chosen 总是更长/更短，模型会学长度
- 同一 prompt 的偏好对要一起去 train/eval，避免泄漏
- tie/难例要单独处理

RM 是 proxy，不是真值。PPO 会放大它的漏洞，见 reward hacking。

## 4. PPO

RLHF 的经典路线：SFT → RM → PPO。

目标：

$$
\max_\pi\;
\mathbb{E}_{x,y\sim\pi}\left[r(x,y)\right]
-\beta\,D_{\mathrm{KL}}\left(\pi(\cdot\mid x)\,\|\,\pi_{\mathrm{ref}}(\cdot\mid x)\right)
$$

四类模型：

- **actor**：当前策略，要训练
- **critic**：value function，估计 advantage
- **reward**：冻结的 RM，给 rollout 打分
- **reference**：冻结的 SFT，算 KL

一次更新大致是：

1. actor 采样 response
2. RM 打分，reference 算 log-prob
3. critic/GAE 算 advantage
4. clipped surrogate + value loss + entropy
5. KL 约束，更新 actor/critic

工程难点：

- 四个模型 + rollout + 激活，7B 很容易上多卡
- rollout 引擎和训练引擎要衔接（vLLM/FSDP/ZeRO）
- reward scale、KL 系数、clip fraction、长度都要监控
- 在线采样和训练分布会漂移；old policy log-prob 要对齐
- 异步/offload 能省显存，但增加复杂度和延迟

常见不稳定：

- reward hacking：RM 被刷分
- KL 太小：策略跑偏；KL 太大：学不动
- 长度 gaming：模型学会更长/更短
- critic 跟不上 actor，advantage 噪声大
- rollout 和训练引擎的 tokenizer/template 不一致
- seed 方差大，一次实验说明不了问题

PPO 不是不能做，是成本高。没有多卡和工程能力，先用 DPO。

## 5. DPO

DPO 直接用偏好对，不需要显式 RM 和 PPO。

数据：

```text
(x, y_w, y_l)
```

损失：

$$
L_{\mathrm{DPO}}
=-\log\sigma\left(
\beta\left[
\log\frac{\pi_\theta(y_w\mid x)}{\pi_{\mathrm{ref}}(y_w\mid x)}
-\log\frac{\pi_\theta(y_l\mid x)}{\pi_{\mathrm{ref}}(y_l\mid x)}
\right]
\right)
$$

直觉：

- 提高 chosen 相对 reference 的概率
- 降低 rejected 相对 reference 的概率
- β 控制偏离 reference 的强度

工程细节：

- prompt/chosen/rejected 用同一套 chat template
- 只在 response 上算 log-prob，mask 掉 prompt
- chosen/rejected 分别 tokenize，padding side 一致
- 原始 DPO 用 sum log-prob；用 mean 要做长度归一化，训练/评测保持一致
- reference 必须冻结，且和 SFT 起点一致
- β 常用 0.1–0.5；太大贴近 reference，太小容易跑偏
- 学习率通常比 SFT 小；1–3 epoch，别过拟合偏好对

DPO vs PPO：

| 维度 | DPO | PPO |
|---|---|---|
| 模型 | policy + reference | actor + critic + reward + reference |
| 数据 | 离线偏好对 | 在线 rollout + RM |
| 显存 | 较低 | 很高 |
| 稳定性 | 较高 | 较低 |
| 奖励 | 隐式 | 显式 RM |
| 适合 | 有限 GPU、快速迭代 | 大规模、有工程能力 |

7B 全参数 DPO 的 policy + reference 两份权重约 28GB，还没算优化器和激活；8–24GB 要用小模型/LoRA/QLoRA。

DPO 的局限：

- 偏好数据覆盖不到的能力，DPO 也学不到
- 容易学长度的捷径；要控制长度/做长度归一化
- 偏好噪声会被直接学进去
- reference 不一致会改变优化目标

ORPO 把 SFT 和偏好项合成一个阶段，不需要 reference；适合单阶段/显存受限。细节见 [LLM 第 7 篇](../llm/07-微调与对齐.md)。

## 6. 实验：最小 DPO

把每个 response 压成一个特征向量，policy 是线性打分；这是 DPO 的最小形式，用来隔离 loss、reference 和 β。

- 512 个偏好对，特征维度 8
- 隐藏偏好方向 `r_true`
- reference 与 `r_true` 正交，初始 pairwise accuracy 约 50%
- β=0.5，Adam 200 步

??? note "代码：最小 DPO"
    ```python
    import torch
    import torch.nn.functional as F

    torch.manual_seed(0)
    dim, n = 8, 512
    r_true = torch.randn(dim)
    r_true = r_true / r_true.norm()

    base = torch.randn(n, dim) * 0.5
    noise = torch.randn(n, dim) * 0.5
    signal = torch.randn(n, 1).abs() * 1.5
    h_w = base + noise + signal * r_true
    h_l = base - noise - signal * r_true

    # 保证 chosen 在隐藏偏好下确实更好
    sw = (h_w @ r_true) < (h_l @ r_true)
    h_w[sw], h_l[sw] = h_l[sw].clone(), h_w[sw].clone()

    w_ref = torch.randn(dim)
    w_ref = w_ref - (w_ref @ r_true) * r_true
    w_ref = w_ref / w_ref.norm() * 0.5
    w = w_ref.clone().requires_grad_(True)
    beta = 0.5
    opt = torch.optim.Adam([w], lr=0.05)

    def acc(w):
        return ((h_w @ w) > (h_l @ w)).float().mean().item()

    def score_margin(w):
        return ((h_w @ w) - (h_l @ w)).mean().item()

    print("pairs", n, "dim", dim, "beta", beta)
    print("initial acc", f"{acc(w_ref):.2%}", "score_margin", f"{score_margin(w_ref):.3f}")

    for step in range(201):
        logp_w = h_w @ w
        logp_l = h_l @ w
        ref_w = (h_w @ w_ref).detach()
        ref_l = (h_l @ w_ref).detach()
        m = (logp_w - ref_w) - (logp_l - ref_l)
        loss = -F.logsigmoid(beta * m).mean()
        opt.zero_grad()
        loss.backward()
        opt.step()
        if step in [0, 50, 100, 200]:
            print(f"step {step:3d} loss {loss.item():.4f} acc {acc(w):.2%} score_margin {score_margin(w):.3f}")
    ```

输出：

```text
pairs 512 dim 8 beta 0.5
initial acc 49.80% score_margin 0.006
step   0 loss 0.6931 acc 73.05% score_margin 0.327
step  50 loss 0.1386 acc 96.09% score_margin 8.197
step 100 loss 0.1061 acc 96.88% score_margin 10.784
step 200 loss 0.0782 acc 98.05% score_margin 14.749
```

读法：

- 初始 policy=reference，pairwise accuracy 约 50%
- DPO loss 从 0.693 降到 0.078，score margin 从 0.006 涨到 14.749
- 这里打印的是 policy 的原始分数差（score margin），不是 DPO 的隐式 reward margin
- 最后 pairwise accuracy 98.05%，说明 chosen 的分数稳定高于 rejected
- β 控制偏离 reference 的力度；实验只跑了 β=0.5，β 的具体影响要另做扫参
- 这是特征级最小 DPO，不是 LLM；真实训练要用 token log-prob、mask 和更长序列

## 7. 怎么选

| 场景 | 路线 |
|---|---|
| 只有 prompt-response | SFT |
| 有偏好对、8–24GB（小模型/QLoRA） | DPO/ORPO |
| 有可靠 RM + 多卡 + 工程 | PPO |
| 数学/代码有验证器 | RLVR/GRPO（见 LLM 第 8 篇） |
| 需要 reward model 做排序 | RM |
| 单阶段、无 reference | ORPO |

实践顺序：

1. 先 SFT，确认格式/任务能学会
2. 用留出集评估，不只看 loss
3. 有偏好数据再上 DPO；PPO 是更重的选项
4. 需要推理增强再考虑 RLVR
5. 数据质量 > 算法；偏好噪声会直接进模型

## 8. 常见坑

1. **SFT 的 chat template 不一致**
   训练/推理多一个角色标记，DPO/PPO 的 reference 也会错。

2. **prompt 也算进 DPO loss**
   模型在学复述 prompt；只算 response token。

3. **chosen/rejected 的 tokenization 不一致**
   模板、EOS、padding side 不同，log-prob 不可比。

4. **sum vs mean log-prob 混用**
   训练用 sum、评测用 mean，pairwise accuracy 会漂。

5. **reference 没冻结/换了 checkpoint**
   DPO 的目标变了，效果不可复现。

6. **β 或学习率乱设**
   β 太大贴近 reference，学不动；太小容易跑偏。

7. **偏好数据有位置/长度偏差**
   chosen 总在固定位置或总是更长，模型学的是偏差。

8. **RM 过拟合/未校准**
   PPO 会放大 RM 的漏洞，出现 reward hacking。

9. **PPO 四模型 OOM**
   actor/critic/reward/reference + rollout；先算显存再上。

10. **PPO 的 KL/reward scale 失控**
    看 KL、response length、clip fraction、entropy，不只看 reward。

11. **rollout 和训练引擎不一致**
    tokenizer/template/version 不同，old log-prob 对不上。

12. **在训练偏好对上评测**
    pairwise accuracy 虚高；要留出 prompt/分布。

13. **只看 win rate，不看安全和回归**
    对齐可能带来拒答/能力回退；要任务评测 + 红队。

## 9. 要点回顾

1. 对齐路线：SFT → RM → PPO，或 SFT → DPO/ORPO
2. SFT 是起点和 reference；template/mask/packing 要和推理一致
3. RM 用 Bradley-Terry 学相对偏好；留出集看 pairwise accuracy
4. PPO 要 actor/critic/reward/reference 四模型，显存和工程成本最高
5. DPO 只要 policy + reference，离线、稳定、适合有限 GPU
6. DPO 的 β 控制偏离 reference；reference 必须冻结且与 SFT 一致
7. DPO 的 tokenization、sum/mean log-prob、padding 要一致
8. 偏好数据的位置/长度偏差和噪声会直接进模型
9. 评测看留出集 pairwise accuracy/win rate、长度、安全，不只看 loss
10. 数据质量 > 算法；PPO 不会修复坏偏好
