# 混合精度与显存

混合精度不是“把 dtype 改成 BF16”这么简单。它同时影响：

- 显存：权重、梯度、激活、优化器状态
- 速度：带宽、tensor core、kernel
- 数值：范围、精度、loss scaling
- 硬件/框架：BF16/FP8 支持不一样

这篇讲 FP32/BF16/FP16/FP8、loss scaling、master weights、activation checkpointing 和显存账，最后在同一模型上换精度量显存。量化/推理精度见 Inference；LoRA/QLoRA 的显存见[微调](02-微调.md)；GPU 显存/OOM 的基础见 [Infra 第 1 篇](../infra/01-GPU与加速器.md)。

## 1. 精度格式

| 格式 | 存储 | 指数/尾数 | 特点 | 常见用途 |
|---|---|---|---|---|
| FP32 | 4B | 8/23 | 范围大、精度高 | master weights、优化器、敏感算子 |
| BF16 | 2B | 8/7 | 范围接近 FP32，精度较低 | LLM 训练/推理 |
| FP16 | 2B | 5/10 | 精度较高，范围窄 | 混合精度 + loss scaling |
| FP8 E4M3 | 1B | 4/3 | 范围窄，精度低 | FP8 训练/推理（需 scaling） |
| FP8 E5M2 | 1B | 5/2 | 范围更大，精度更低 | 梯度/FP8 训练 |
| INT8 | 1B | 整数 | 需要 scale/zero-point | 推理量化 |

注意：

- “存储字节”不等于“计算格式”：TF32 是 tensor core 的计算格式，存储仍是 FP32
- FP8 不是“把模型存成 1 byte 就能直接训”；要 scaling、kernel、框架支持
- BF16/FP16 都是 2 bytes，但数值行为不同

## 2. 混合精度训练

常见做法：

- 前向/反向用 BF16 或 FP16
- 权重、优化器状态保留 FP32 master
- 敏感算子（softmax、layernorm、loss）用 FP32
- 用 autocast 控制算子精度

FP16：

- 范围窄（最大约 65504），梯度容易 underflow/overflow
- 需要 GradScaler：放大 loss，反向后再 unscale
- 出现 inf/nan 时跳过这一步
- unscale 后再做 gradient clipping

BF16：

- 指数位和 FP32 一样，范围大，通常不需要 loss scaling
- 尾数少，精度低；对 LLM 通常够用
- Ampere 及以后支持较好；老卡可能不支持/模拟很慢

PyTorch 大致是：

```python
import torch

use_fp16 = True
model = torch.nn.Linear(8, 1).cuda()
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3)
x = torch.randn(4, 8, device="cuda")

scaler = torch.amp.GradScaler("cuda", enabled=use_fp16)
with torch.autocast("cuda", dtype=torch.float16):
    loss = model(x).float().pow(2).mean()
scaler.scale(loss).backward()
scaler.unscale_(optimizer)
torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
scaler.step(optimizer)
scaler.update()
```

BF16 一般不用 scaler；FP16 用。不要把 GradScaler 和 BF16 硬绑在一起。

## 3. 显存账

训练显存大致是：

```text
权重
+ 梯度
+ 优化器状态（Adam m/v、master）
+ 激活
+ 临时 buffer / workspace
+ CUDA context / 碎片
```

### 权重

- FP32：4 bytes/param
- BF16/FP16：2 bytes/param
- FP8：1 byte/param

7.2B 参数：

| 精度 | 权重 |
|---|---|
| FP32 | 28.8GB |
| BF16/FP16 | 14.4GB |
| FP8 | 7.2GB |

### 全量训练状态

混合精度 AdamW 常见：

- 权重 BF16：2
- 梯度 BF16：2
- FP32 master：4
- Adam m/v：8

合计约 **16 bytes/param**。

纯 FP32 Adam 也是 4+4+8 = 16 bytes/param。**所以混合精度不会把全量训练显存减半**；它主要省激活、带宽和算力，优化器状态仍然是大头。

FP8 训练如果 master/Adam 还是 FP32，约 1+2+4+8 = 15 bytes/param，省得也有限；具体看 grad/master 精度。

### 激活

粗略：

$$
\text{activation}\approx B\times S\times H\times L\times \text{bytes}
$$

- B：batch
- S：序列长度
- H：hidden
- L：层数
- attention 的 score/中间量另算
- 临时 buffer/workspace 另算

所以：

- batch/seq 是线性放大器
- 精度从 FP32 到 BF16/FP16 激活减半
- activation checkpointing 用时间换显存

## 4. Activation checkpointing

做法：

- 前向不保存所有层激活，只保存每段的输入
- 反向需要时重新算前向
- 常见按层/按段 checkpoint，不是所有 tensor 都存

收益：

- 激活从 `B×S×H×L` 降到约 `B×S×H`，理论上省约 `1/L`
- 代价是额外前向计算，常见 step time +20–30%

注意：

- `torch.utils.checkpoint` 有 reentrant/non-reentrant 两种；新代码常用 `use_reentrant=False`
- checkpoint 段太大，省得少；段太小，重算开销大
- 和 `use_cache=True` 一起用可能冲突；训练时关 cache
- dropout/RNG 状态要一致；否则重算结果对不上
- 不是所有模型/算子都支持；先小规模验证

## 5. FP8

FP8 有两个常见格式：

- E4M3：尾数多，范围窄，常用于前向/权重
- E5M2：范围大，精度低，常用于梯度

工程要点：

- 需要 scaling：per-tensor/per-block、delayed scaling、amax history
- 不是所有算子都支持；不支持的回退到 BF16/FP16
- 需要硬件/框架：Hopper/Ada/Blackwell + Transformer Engine/torchao 等
- 训练和推理的 FP8 不是一回事；推理 FP8 还要看 kernel/量化校准
- 不要假设“1 byte = 4 倍加速”；瓶颈可能在内存、kernel、通信

## 6. 实验：同一模型换精度量显存

在一个小 MLP 上测：

- FP32/BF16/FP16 的峰值显存
- 理论激活显存，以及 checkpointing 的节省
- 7.2B 权重在不同精度下的字节数

??? note "代码：混合精度显存"
    ```python
    import gc
    import torch
    import torch.nn as nn

    def run(dtype, H=1024, L=16, B=16, S=512):
        gc.collect()
        torch.cuda.empty_cache()
        torch.cuda.reset_peak_memory_stats()
        torch.manual_seed(0)
        layers = nn.ModuleList([nn.Linear(H, H) for _ in range(L)]).cuda().to(dtype)
        x = torch.randn(B, S, H, device="cuda", dtype=dtype)
        for layer in layers:
            x = torch.relu(layer(x))
        loss = (x.float() ** 2).mean()
        loss.backward()
        torch.cuda.synchronize()
        peak = torch.cuda.max_memory_allocated() / 1024**3
        del layers, x, loss
        return peak

    print("dtype bytes")
    for name, dtype in [("FP32", torch.float32), ("BF16", torch.bfloat16), ("FP16", torch.float16), ("FP8", torch.float8_e4m3fn)]:
        print(name, torch.empty(1, dtype=dtype).element_size())

    print("peak GiB (RTX 4060 8GB, H=1024 L=16 B=16 S=512)")
    for name, dtype in [("FP32", torch.float32), ("BF16", torch.bfloat16), ("FP16", torch.float16)]:
        print(name, f"{run(dtype):.2f}")

    H, L, B, S = 1024, 16, 16, 512
    print("activation estimate (GiB)")
    for name, b in [("FP32", 4), ("BF16", 2), ("FP16", 2)]:
        no = B * S * H * L * b / 1024**3
        ck = B * S * H * b / 1024**3
        print(f"{name} no_ckpt={no:.2f} ckpt={ck:.2f} saving={1 - ck / no:.1%}")

    print("7.2B weights (GB)")
    for name, b in [("FP32", 4), ("BF16", 2), ("FP16", 2), ("FP8", 1)]:
        print(name, f"{7.2 * b:.1f}")
    ```

输出：

```text
dtype bytes
FP32 4
BF16 2
FP16 2
FP8 1
peak GiB (RTX 4060 8GB, H=1024 L=16 B=16 S=512)
FP32 0.73
BF16 0.47
FP16 0.47
activation estimate (GiB)
FP32 no_ckpt=0.50 ckpt=0.03 saving=93.8%
BF16 no_ckpt=0.25 ckpt=0.02 saving=93.8%
FP16 no_ckpt=0.25 ckpt=0.02 saving=93.8%
7.2B weights (GB)
FP32 28.8
BF16 14.4
FP16 14.4
FP8 7.2
```

读法：

- FP32 峰值 0.73 GiB；BF16/FP16 0.47 GiB，约低 36%
- 理论激活：FP32 0.50 GiB；checkpointing 后 0.03 GiB，省 93.8%
- BF16 激活 0.25 GiB；checkpointing 后 0.02 GiB
- 7.2B 权重：FP32 28.8GB；BF16/FP16 14.4GB；FP8 7.2GB
- 实际峰值还包含权重、梯度、输入/临时 buffer，不只是激活
- 这是 RTX 4060 Laptop 8GB 的实测；不同驱动/框架会有差异
- FP8 这里只验证了 1 byte/元素，没有做 FP8 训练；支持取决于硬件和框架

## 7. 7B 在 8GB 上怎么放

7.2B 权重：

- FP32：28.8GB
- BF16/FP16：14.4GB
- FP8：7.2GB

所以：

- 8GB 放不下 7.2B 的 FP32/BF16/FP16 权重，更不用说全量训练状态
- FP8 权重 7.2GB 名义上能放进 8GB，但 FP8 全量训练状态仍约 15 bytes/param ≈ 108GB；8GB 只能做推理/量化或 QLoRA，不是 FP8 全量训练
- 7.2B 全量 BF16 训练状态约 115GB；8GB 不可能（不 offload）
- BF16 LoRA 约 15GB；8GB 也不够
- 4-bit QLoRA 约 4.5GB；8GB 可以尝试，但要小 seq/batch + checkpointing

具体配方见[微调](02-微调.md)；显存构成见 [Infra 第 1 篇](../infra/01-GPU与加速器.md)。

## 8. 怎么选

| 场景 | 选择 |
|---|---|
| 训练，Ampere+ | BF16 + FP32 master |
| 训练，老卡/不支持 BF16 | FP16 + GradScaler |
| 训练，FP8 支持 | FP8 + scaling/框架，先小规模验证 |
| 显存不够 | activation checkpointing、减小 seq/batch、ZeRO/QLoRA |
| 推理 | FP16/BF16、FP8、INT8、4-bit；按质量和 kernel 选 |
| 只省权重 | 量化；不要指望混合精度省优化器状态 |

原则：

- 先保证数值稳定，再谈速度
- 混合精度主要省带宽/激活/算力，不一定省全量训练显存
- 任何精度/checkpointing 改动都要重测 loss、任务指标、峰值显存

## 9. 常见坑

1. **老卡上硬上 BF16**
   不支持时会模拟/很慢；先确认硬件和框架。

2. **FP16 不用 loss scaling**
   梯度 underflow/overflow，loss 变 NaN。

3. **BF16 也加 GradScaler**
   通常没必要；反而增加复杂度。

4. **autocast 范围写错**
   该 FP32 的 softmax/layernorm/loss 被降精度，数值不稳。

5. **没有 FP32 master**
   优化器更新精度不够，训练容易漂。

6. **以为混合精度能减半全量训练显存**
   Adam master/m/v 仍是大头；16 bytes/param 没变。

7. **FP8 当 plug-and-play**
   没有 scaling/kernel/框架支持，结果不可用。

8. **checkpointing + use_cache**
   训练时开 cache 会冲突/浪费；关掉。

9. **checkpoint 粒度太细/太粗**
   太细重算多，太粗省得少；按段调。

10. **`empty_cache()` 当 OOM 解药**
    只释放缓存块，不释放活 tensor；要减真实占用。

11. **只看权重，不看激活**
    长 seq/大 batch 时激活可能超过权重。

12. **量化后不重测**
    FP8/INT8/4-bit 可能掉长上下文、工具调用、多语言。

13. **dtype 不匹配**
    输入/权重/输出 dtype 不一致，报错或隐式转换变慢。

## 10. 要点回顾

1. FP32 4B、BF16/FP16 2B、FP8 1B；存储字节不等于计算格式
2. FP16 范围窄，需要 GradScaler；BF16 范围大，通常不用
3. 混合精度要保留 FP32 master；敏感算子用 FP32
4. 全量训练状态约 16 bytes/param；混合精度不会减半
5. 7.2B 权重：FP32 28.8GB、BF16/FP16 14.4GB、FP8 7.2GB
6. 激活随 B×S×H×L 增长；checkpointing 可省约 1/L，但更慢
7. 8GB 放不下 7.2B BF16 全量/LoRA；QLoRA 4-bit 才可以尝试
8. FP8 需要 scaling/硬件/框架；不要假设 4 倍加速
9. 任何精度改动都要重测数值、任务指标和峰值显存
