# 误差与精度损失

浮点运算会"丢精度"，几种典型场景和避免方法。实际偶尔会用到。

## 1. 舍入误差（基础）

**来源**：每个浮点运算的结果都要"舍入"到 52 位尾数（double），一次次运算误差会**累积**。

```cpp
double x = 0.1;          // 存进去就已经舍入了
// 大量运算后误差累积，结果和"数学上正确"的值有偏差
```

## 2. 大数吃小数（精度损失的经典场景）

**场景**：一个大数和一个小数相加，小数的低位被"吞掉"：

```cpp
float x = 1e8f;
float y = x + 1.0f;
y == x;                  // → true！那个 1 被"吃"了
```

**原因**：float 只有约 7 位有效数字。`1e8 + 1` 需要 9 位（100000001），尾数存不下，最低的 "1" 被舍入丢掉。

```cpp
// double 好一些（约 15 位），但一样有这个问题：
double x = 1e16;
double y = x + 1.0;
y == x;                  // → true（1e16 + 1 需要 17 位，double 也存不下）
```

**避免**：避免数量级悬殊的数直接相加；需要时用 `long double` 或换算法（如 Kahan 求和）。

## 3. 相减抵消（Catastrophic Cancellation）

**场景**：两个**非常接近的数相减**，有效数字互相抵消，只剩误差：

```cpp
double a = 1.0000000001;
double b = 1.0000000000;
double c = a - b;        // 数学上 = 1e-10
// 但 double 只有 15 位精度，a、b 本身就有舍入误差
// 相减后，误差在结果里占比巨大 → 结果极不准确
```

**为什么危险**：相减"消掉"了大部分有效数字，剩下的几乎全是误差。

**经典案例**：解二次方程 `x = (-b ± √(b²-4ac)) / 2a`，当 `b² ≈ 4ac` 时，分子相减产生灾难性抵消 → 结果错误。

**避免**：变换公式（如共轭有理化）、用稳定的算法。

## 4. 求和顺序影响结果

浮点加法**不满足结合律**：

```cpp
// 两种顺序，结果可能不同！
double s1 = (1e16 + 1.0) + 1.0;   // 大数先加，两个 1 都被吃
double s2 = 1e16 + (1.0 + 1.0);   // 小数先加，1+1=2，可能保留

// 求和优化：
// ❌ 从大到小依次加（大数吃小数，小值全被吞）
// ✅ 按绝对值从小到大加 / Kahan 补偿求和 / 用 double 替代 float
```

## 5. numpy 验证

```python
import numpy as np

# 大数吃小数
x = np.float32(1e8)
y = x + np.float32(1.0)
print(x == y)          # True！1 被吃了

# 相减抵消
a = 1.0000000001
b = 1.0000000000
print((a - b) - 1e-10)   # 不为 0（误差很大）

# 求和顺序
vals = np.array([1e16, 1.0, 1.0])
print(vals.sum())              # numpy 的 sum 可能和朴素顺序不同
```

## 6. 小结

1. **舍入误差**：每次运算都舍入，误差累积
2. **大数吃小数**：数量级悬殊相加，小的被吞（float 7 位、double 15 位有效数字）
3. **相减抵消**：接近的数相减，有效数字全消掉只剩误差（最危险）
4. **求和顺序**：浮点不满足结合律，顺序影响结果
