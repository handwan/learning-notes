# 排序与选择

排序不是“把数组排好”这么简单。先问五件事：

- `n` 多大？
- 元素能比较，还是整数/范围有限？
- 需要稳定吗？
- 内存够不够？
- 数据是随机、基本有序，还是流式到达？

选择问题（第 k 小、Top-K）往往**不需要全排序**，这是另一条线。

> 八种排序的手写实现、复杂度/稳定性总表见 [查找与排序](../../02-computer-basics/data-structure/09-查找与排序.md)；比较排序下界见 [算法分析](01-算法分析.md)。

## 1. 比较排序的下界与可达上界

比较排序只通过“比较两个元素”获得信息。`n` 个不同元素有 `n!` 种排列，决策树至少 `n!` 个叶子，因此：

```text
最坏情况 Ω(n log n)
```

归并排序、堆排序达到这个下界；快排平均达到，最坏会退化。

**计数/基数/桶排序能突破它**，因为它们不靠比较，而是利用 key 的整数结构或分布。代价是额外假设和空间。

## 2. 稳定性、原地、适应性

| 性质 | 含义 | 典型 |
|---|---|---|
| **稳定** | 相等元素的相对顺序不变 | 归并、插入；计数/基数需实现正确 |
| **不稳定** | 相等元素可能换位 | 快排、堆排、选择 |
| **原地** | 额外空间 `O(1)`（递归栈另算） | 快排、堆排、插入 |
| **非原地** | 需要 `O(n)` 或更多辅助空间 | 归并、计数、基数 |
| **自适应** | 输入越接近有序，越快 | 插入、Timsort |

稳定性的用处：按多个 key 排序。

```text
先按次要 key 排，再按主要 key 稳定排
→ 主要 key 相同的记录，保持次要 key 的顺序
```

如果不稳定，第二次排序会打乱第一次的结果，只能改用复合比较器。

## 3. 快速排序

思路：选 pivot，分区，使左边 ≤ pivot、右边 ≥ pivot，再递归两边。

```text
quick_sort(a, lo, hi):
    if lo >= hi: return
    p = partition(a, lo, hi)
    quick_sort(a, lo, p-1)
    quick_sort(a, p+1, hi)
```

### 分区

Lomuto 分区（简单，适合教学）：

```text
pivot = a[hi]
i = lo
for j = lo .. hi-1:
    if a[j] <= pivot:
        swap(a[i], a[j]); i++
swap(a[i], a[hi])
return i
```

Hoare 分区交换次数更少，但边界更容易写错。

### 最坏情况

- 已排序 + 取首/尾元素当 pivot → 每次分割 0 和 n-1 → `O(n²)`
- 全部相同 → 普通分区也可能退化

处理：

- **随机 pivot**
- **三数取中**（首、中、尾的中位数）
- **三路分区**：`< pivot`、`= pivot`、`> pivot`，重复元素多时接近线性

快速排序：

| 指标 | 结果 |
|---|---|
| 平均 | `O(n log n)` |
| 最坏 | `O(n²)` |
| 空间 | 期望 `O(log n)` 栈，最坏 `O(n)` |
| 稳定 | 否 |
| 自适应 | 否 |

## 4. 归并排序

思路：分成两半，分别排序，再合并。

```text
merge_sort(a, lo, hi):
    if lo >= hi: return
    mid = (lo + hi) / 2
    merge_sort(a, lo, mid)
    merge_sort(a, mid+1, hi)
    merge(a, lo, mid, hi)
```

合并时，相等元素**优先取左边**，才能保持稳定。

| 指标 | 结果 |
|---|---|
| 时间 | `O(n log n)`（最好/平均/最坏） |
| 空间 | `O(n)` |
| 稳定 | 是 |
| 自适应 | 普通实现否 |

归并的强项是稳定和最坏保证；弱点是额外数组和内存拷贝。

### 外部排序

数据放不进内存：

1. 分段读入，段内排序，写回临时文件
2. 多路归并这些有序段

瓶颈是磁盘 IO，不是比较。优化方向是减少读写趟数、增大归并路数。

## 5. 堆排序

思路：建大顶堆，反复把堆顶换到末尾，再下沉。

```text
build_heap(a)                 // O(n)
for end = n-1 down to 1:
    swap(a[0], a[end])
    sift_down(a, 0, end)      // O(log n)
```

| 指标 | 结果 |
|---|---|
| 时间 | `O(n log n)` |
| 空间 | `O(1)` |
| 稳定 | 否 |
| 自适应 | 否 |

建堆是 `O(n)`，不是 `O(n log n)`；每次删除堆顶才是 `O(log n)`。

堆排序适合“要最坏 `O(n log n)` + 原地”的场景；实际常数通常比快排大，缓存也不友好。

## 6. 插入、希尔、冒泡、选择

这四种更多是教学和特定场景：

- **插入排序**：小数组、基本有序时很快；最好 `O(n)`，最坏 `O(n²)`，稳定
- **希尔排序**：分组插入，增量递减；复杂度依赖增量序列，不稳定
- **冒泡排序**：加“无交换即停”后，已排序数组接近 `O(n)`；实践中通常被插入替代
- **选择排序**：每趟选最小放到前面；`O(n²)`，不稳定，交换次数最多 `O(n)`；多数场景被堆排/快排替代

工程里的混合排序常在小段切回插入排序，因为常数小、对短数组友好。

## 7. 线性排序

### 计数排序

前提：key 是范围不大的整数。

```text
统计每个值出现次数
前缀和 → 每个值的结束位置
从后往前放回，保证稳定
```

- 时间 `O(n + r)`，`r` 是值域
- 空间 `O(n + r)`
- 稳定（从后往前放）

`r` 远大于 `n` 时，不如比较排序。

### 基数排序

按位从低到高（LSD），每一位用稳定计数排序：

```text
for each digit from least significant to most:
    stable counting sort by digit
```

- 时间 `O(d(n + r))`
- 空间 `O(n + r)`
- 稳定
- 32 位整数可以按 8 位一组，做 4 趟

负数要额外处理：整体加偏移，或先按符号分开。

### 桶排序

把值域分成桶，桶内再排序。

- 均匀分布：平均 `O(n)`
- 分布极不均匀：可能退化为 `O(n²)`
- 稳定性取决于桶内排序

## 8. 选择与 Top-K

只找第 k 小/第 k 大，不需要全排序。

### 快速选择

用快排的分区。这里的 `k` 是原数组的 0-based 下标，不是当前子数组内的名次。

```text
quick_select(a, lo, hi, k):
    p = partition(a, lo, hi)
    if p == k: return a[p]
    if k < p: return quick_select(a, lo, p-1, k)
    else:     return quick_select(a, p+1, hi, k)
```

- 平均 `O(n)`
- 最坏 `O(n²)`
- 随机 pivot 可让最坏情况概率极低
- 不稳定

### 中位数的中位数

把元素每 5 个一组：

1. 每组用插入排序找中位数（组大小固定，常数代价）
2. 递归找这些中位数的中位数 `p`，作为 pivot
3. 按 `p` 分区，得到 `p` 的排名
4. 只递归包含目标排名的那一侧

复杂度：

```text
T(n) ≤ T(n/5) + T(7n/10) + O(n)
```

至少 `3n/10` 个元素 ≤ `p`，至少 `3n/10` 个元素 ≥ `p`，所以分区后最大一侧不超过 `7n/10`。递归树每层规模按 `9n/10` 缩小，总和为 `O(n)`。

- 最坏 `O(n)`
- 常数很大，实践中通常不如随机快速选择
- 价值在于“最坏线性”的理论保证

### 堆方法

维护大小为 `k` 的堆：

- 找前 k 大：小顶堆
- 找前 k 小：大顶堆
- 时间 `O(n log k)`
- 空间 `O(k)`
- 适合**流式数据**，不能回头扫

### 怎么选

| 场景 | 方法 |
|---|---|
| 一次性、内存够、只要第 k 个 | 快速选择 / `nth_element` |
| 流式、`k` 很小 | 大小为 k 的堆 |
| 要前 k 个有序 | 堆 + 最后排序，或全排序 |
| 要最坏线性 | 中位数的中位数（理论） |
| 数据量巨大 | 外部选择/分块 |

## 9. 工程实践

### C++ 标准库

- `std::sort`：常见实现是内省排序（快排 + 堆排 + 插入），不稳定，平均 `O(n log n)`、最坏 `O(n log n)`
- `std::stable_sort`：归并类，稳定；有足够额外内存时 `O(n log n)`，否则最坏 `O(n log² n)`
- `std::nth_element`：快速选择，平均 `O(n)`
- `std::partial_sort`：维护前 k 个，`O(n log k)`

### 常见优化

- 小数组切插入排序
- 三数取中/随机 pivot
- 三路分区处理重复值
- 快排递归深度过大时切堆排（内省排序）
- 基本有序用插入/Timsort
- 多 key 排序用稳定排序或复合比较器

### 比较器要严格弱序

```cpp
// 错：相等时返回 true，违反严格弱序
sort(a.begin(), a.end(), [](int x, int y) { return x <= y; });

// 对：
sort(a.begin(), a.end(), [](int x, int y) { return x < y; });
```

比较器写成 `<=`、用 `a - b` 判断大小（可能溢出），都可能让 `std::sort` 行为未定义。

## 10. 常见坑

- 快排对已排序数组取首元素当 pivot → `O(n²)`
- 以为 `std::sort` 稳定 → 需要稳定用 `stable_sort`
- 以为堆排序自适应 → 基本有序也还是 `O(n log n)`
- 计数排序值域过大 → 空间爆炸
- 基数排序每趟不稳定 → 最终结果错
- 选择问题先全排序 → 多做 `O(n log n)` 的工作
- 流式数据用快速选择 → 数据不能回头扫，应该用堆
- 比较器不满足严格弱序 → 未定义行为

## 11. 要点回顾

1. **比较排序下界**：`Ω(n log n)`；计数/基数/桶排序靠非比较突破
2. **快排**：平均 `O(n log n)`、最坏 `O(n²)`；随机 pivot/三路分区缓解
3. **归并**：稳定、最坏 `O(n log n)`、`O(n)` 空间；适合外部排序
4. **堆排**：最坏 `O(n log n)`、`O(1)` 空间、不稳定；建堆 `O(n)`
5. **稳定性**：多 key 排序和保持记录顺序时需要
6. **选择**：快速选择平均 `O(n)`；流式 Top-K 用大小 `k` 的堆
7. **工程**：`std::sort` 不稳定，`stable_sort` 稳定，`nth_element` 做选择
8. **比较器**：必须严格弱序，不要写 `<=` 或 `a-b`
