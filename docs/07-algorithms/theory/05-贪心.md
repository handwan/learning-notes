# 贪心

贪心（greedy）是：**每一步都做一个当前看起来最好的选择，而且不回头。**

它快、代码短，但最容易“感觉对、其实是错的”。判断贪心能不能用，不能靠样例，要靠证明或反例。

## 1. 适用条件

一个贪心策略要正确，通常需要：

1. **贪心选择性质**：存在一个最优解，包含当前贪心选择
2. **最优子结构**：做出贪心选择后，剩下的子问题仍是最优子问题

只看“局部最优”不够；局部最优堆起来不一定是全局最优。

## 2. 证明工具箱

### 交换论证

最常用：

1. 假设有一个最优解 `O`
2. 找到 `O` 中第一个和贪心选择 `g` 不同的地方
3. 把 `O` 里的选择换成 `g`
4. 证明替换后仍然可行、且不劣于 `O`
5. 反复替换，得到一个包含贪心选择的最优解

### 贪心领先

把贪心的前缀和任意其他可行解的前缀比较，证明贪心始终“不落后”。适合跳跃游戏、覆盖问题。

### 结构性质

例如 Huffman 的交换论证、MST 的 cut property、拟阵（matroid）上的贪心。拟阵是理论工具，初学不必展开。

### 先找反例

证不出来时，先构造小反例：

- 两个选择互相影响
- 当前最优导致后面无法选择
- 权重/容量/区间有特殊组合

一个反例就能否定策略。

## 3. 区间调度

问题：给若干区间 `[start, end]`，选最多不重叠的区间。

> 以下默认半开区间 `[start, end)`，`end == start` 可复用；按闭区间理解时需要相应调整。

### 策略

```text
按 end 升序排序
last_end = -∞
count = 0
for (s, e) in intervals:
    if s >= last_end:
        count++
        last_end = e
```

### 反例

按开始最早会错：

```text
[0, 10], [1, 2], [3, 4]
```

选 `[0,10]` 只能选 1 个；选 `[1,2]`、`[3,4]` 能选 2 个。

按最短优先也会错：

```text
[0, 3], [2, 4], [3, 6]
```

最短的 `[2,4]` 同时挡住左右两个；最优是 `[0,3]` + `[3,6]`，能选 2 个。

回到第一个例子：按结束最早会选 `[1,2]`、`[3,4]`，能选 2 个。

### 区间调度的交换论证

设贪心第一次选 `g`（结束最早），最优解第一次选 `o`。

- `g.end <= o.end`
- 把 `o` 换成 `g`，不会和后面的区间冲突（因为 `g` 结束更早）
- 所以存在一个包含 `g` 的最优解
- 对剩余区间归纳

### 变体

| 问题 | 策略 |
|---|---|
| 最多不重叠区间 | 按结束时间升序 |
| 最少会议室 | 按开始时间排序 + 小顶堆维护结束时间 |
| 最少区间覆盖目标 | 按起点排序，每次选能覆盖当前点的最远终点 |
| 合并区间 | 按起点排序，维护当前区间终点 |
| 带权区间调度 | 不是贪心；排序后做 DP |

- 会议室数量等于**最大重叠数**；按半开区间理解，`end == start` 可以复用同一间。
- 只求“最多数量”时，结束时间相同可以任选；要求特定方案/字典序时才需要 tie-break。
- 带权区间要按结束时间排序后 DP：选/不选当前区间 + 前驱。

## 4. Huffman

问题：给字符频率，构造前缀码，使总编码长度最短。

策略：**每次合并频率最小的两个节点**。

```text
把所有频率放进小顶堆
while 堆大小 > 1:
    a = pop_min()
    b = pop_min()
    ans += a + b
    push(a + b)
```

- 时间 `O(n log n)`
- 每次合并产生一个父节点
- `ans` 就是加权路径长度
- 频率低的字符离根更远，编码更长

正确性用交换论证：

1. 设 `a`、`b` 是频率最小的两个字符
2. 取一棵最优树，找最深层的一对兄弟叶子 `x`、`y`
3. 把 `a` 与 `x`、`b` 与 `y` 交换。因为 `a`、`b` 频率不高于 `x`、`y`，交换后总代价不增，所以仍是最优树
4. 此时 `a`、`b` 是最深层的兄弟；把它们合并成频率 `a+b` 的新字符，原问题与缩小后的问题一一对应
5. 对缩小后的问题归纳

所以“每次合并最小频率”不会错过最优解。

## 5. 分数背包

物品可以切开时，按**单位重量价值**从高到低拿：

```text
sort by value/weight descending
take as much as possible
```

这是贪心正确的经典例子：如果最优解没有先拿最高密度物品，可以用它替换一部分更低密度的物品，价值不会下降。

比较 `value/weight` 时，浮点可能不够精确；可用交叉相乘：

```text
a.value * b.weight > b.value * a.weight
```

注意乘法溢出，必要时用 `long long`/`__int128`。

## 6. 贪心失效

### 0/1 背包

物品不能切开，按单位价值贪心会错：

```text
容量 50
(weight, value):
(10, 60)   密度 6
(20, 100)  密度 5
(30, 120)  密度 4
```

贪心先拿 10+20，价值 160，剩余 20 放不下 30；最优是 20+30，价值 220。

0/1 背包要用 DP。

### 硬币找零

贪心：每次拿面值最大的硬币。

- 对某些硬币系统（如 1、5、10、25）正确
- 对任意面值不一定正确

反例：面值 `[1, 3, 4]`，目标 6。

```text
贪心：4 + 1 + 1 = 3 枚
最优：3 + 3     = 2 枚
```

所以“硬币找零贪心”只在**特定面值系统**成立；通用解法是 DP。

### 共同点

这两个反例都不是“代码写错”，而是**贪心选择性质不成立**：

- 0/1 背包：拿了高密度物品，占用了后面更优组合需要的容量
- 硬币：拿了最大面值，导致剩余金额无法用更少硬币凑出

## 7. 维护边界

### 跳跃游戏

问题：每个位置 `nums[i]` 表示最远能跳多远，问能否到终点。

策略：维护当前能到达的最远位置。

```cpp
bool canJump(const vector<int>& nums) {
    int reach = 0;
    for (int i = 0; i < (int)nums.size(); ++i) {
        if (i > reach) return false;
        reach = max(reach, i + nums[i]);
    }
    return true;
}
```

正确性用“贪心领先”：处理到 `i` 时，贪心的 `reach` 不小于任何可行走法能到达的最远位置。

### 加油站

问题：环形路线，`gas[i]` 是油量，`cost[i]` 是到下一站的消耗，找能跑完的起点。

```text
total = 0   // 总油量 - 总消耗
tank = 0    // 当前起点出发的剩余油
start = 0

for i:
    diff = gas[i] - cost[i]
    total += diff
    tank += diff
    if tank < 0:
        start = i + 1
        tank = 0

return total >= 0 ? start : -1
```

为什么可以跳过一整段？如果从 `start` 到 `i` 油量变负，那么 `start..i` 中任何位置出发都撑不到 `i+1`；所以起点至少是 `i+1`。

总油量小于总消耗时无解。

## 8. 实现载体

| 载体 | 典型 |
|---|---|
| **排序 + 扫描** | 区间调度、分数背包、Kruskal |
| **堆** | Huffman、Dijkstra、会议室、Top-K |
| **维护边界** | 跳跃游戏、加油站 |
| **双指针** | 有序数组、滑动窗口 |
| **贪心 + 二分** | 二分答案，`check` 里用贪心判断可行性 |

“区间覆盖”主要靠排序 + 扫描/维护最远终点，不要硬归到双指针。

## 9. 图上的贪心

- **最小生成树**：Kruskal 按边权排序 + 并查集；Prim 每次选连接已选集合的最小边
- **Dijkstra**：每次取出当前距离最小的未确定点，松弛邻居；要求边权非负
- **拓扑排序**：每次取入度为 0 的点；不是“最优”，但是合法顺序

实现见[数据结构 · 图算法](../../02-computer-basics/data-structure/07-图算法.md)，证明见[图算法](08-图算法.md)。这里只记一点：**Dijkstra 不能处理负权边**，因为“当前最小”可能被后面的负边推翻。

## 10. 贪心 vs DP

| | 贪心 | DP |
|---|---|---|
| 选择 | 每步做一个，不回头 | 枚举所有选择 |
| 子问题 | 通常只有一个 | 可能多个/重叠 |
| 证明 | 交换论证/领先 | 最优子结构 + 转移 |
| 风险 | 局部最优不是全局 | 状态/转移写错 |

判断：

- 能不能证明“当前选择一定属于某个最优解”？
- 做了这个选择后，剩下的问题是否还是同类最优子问题？
- 如果答案依赖前面的多个选择，通常不是贪心。

## 11. 常见坑

- 只看了样例就下结论，没有证明/反例
- 排序键选错：区间调度按开始而不是结束
- 把“平局需要特殊处理”泛化：只求数量/总值时通常不需要；要求特定方案/字典序才需要 tie-break
- 忽略区间端点约定：`end == start` 能不能复用，会影响会议室/覆盖计数
- 0/1 背包按单位价值贪心
- 任意面值硬币按最大面值贪心
- 负权图用 Dijkstra
- 贪心选择后子问题不再是同类问题
- 浮点比较价值密度，精度不够
- 比较器不满足严格弱序，排序结果未定义
- 把“区间覆盖”写成双指针，实际需要按起点排序并维护最远终点

## 12. 要点回顾

1. **贪心 = 局部选择 + 不回头**；正确性要靠证明或反例
2. **两个条件**：贪心选择性质、最优子结构
3. **交换论证**：把最优解替换成含贪心选择的解，证明不劣
4. **区间调度**：按结束时间最早；按开始最早会错
5. **Huffman**：每次合并最小频率；正确性靠交换论证
6. **分数背包**贪心对，**0/1 背包**贪心错
7. **硬币找零**只对特定面值系统；通用用 DP
8. **Dijkstra** 要求非负边权；负权会破坏贪心
