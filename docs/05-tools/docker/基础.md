# Docker 基础

## 1. 为什么用

| 痛点 | Docker 的解法 |
|------|--------------|
| "在我机器上是好的" | 镜像里打包**完整环境**（系统+依赖+代码） |
| 项目间依赖冲突 | 每个项目一个**容器**，互相隔离 |
| 交付/部署麻烦 | 一条 `docker run`，哪台机器都一样 |
| CI 环境不一致 | 用同一个镜像构建 |

## 2. 核心概念

```
Dockerfile ──build──→ 镜像（Image）──run──→ 容器（Container）
                         │
                         └──push/pull──→ 仓库（Registry，如 Docker Hub）
```

| 概念 | 含义 | 类比 |
|------|------|------|
| **镜像** | 只读模板（系统+依赖+代码） | 类 / 安装盘 |
| **容器** | 镜像的运行实例（可读可写） | 对象 / 运行中的程序 |
| **仓库** | 存放镜像的地方 | GitHub（存代码） |
| **Dockerfile** | 构建镜像的"配方" | 源码 |

### 分层与写时复制

- 镜像由**一层层**叠加而成：`RUN`/`COPY`/`ADD` 生成文件系统层；`ENV`/`CMD` 等只改配置（`docker history` 里显示 0B）
- 层**只读共享**：多个镜像用同一个基础层，不重复存
- 容器启动时，在镜像上**加一个可写层**（写时复制）——改文件才拷贝，不改就共享

**两个推论**：

1. 为什么快：启动不用拷贝整个系统，只是加一层
2. 为什么镜像会胖：**每个文件系统层都保留**，删文件只是标记（下一层看不到，但空间还在）

### 架构

```
docker CLI ──→ dockerd（守护进程）──→ 容器运行时（runc）
                    │
                    └──→ Registry（拉/推镜像）
```

### 隔离靠什么

| 机制 | 管什么 | 对应 Docker |
|------|--------|-------------|
| **namespaces** | 看不见：PID、网络、挂载、主机名、IPC、用户 | `--pid`、`--network`、`-v`（挂载） |
| **cgroups** | 用多少：CPU、内存、IO、进程数 | `--cpus`、`--memory`、`--pids-limit` |
| **unionfs / overlayfs** | 文件系统分层：镜像只读层 + 容器可写层 | 镜像分层、写时复制 |

**一句话**：namespaces 负责“隔离”，cgroups 负责“限额”，unionfs 负责“分层”。容器本质是宿主机上的进程（通常一个主进程），共享宿主内核，不是轻量 VM。

## 3. 常用命令

```bash
# ---- 镜像 ----
docker pull ubuntu:22.04        # 下载镜像
docker images                   # 列出本地镜像
docker rmi <image>              # 删镜像

# ---- 容器 ----
docker run -it --rm ubuntu bash        # -it 交互式  --rm 退出即删
docker run -d -p 8080:80 nginx         # -d 后台  -p 宿主端口:容器端口
docker run -d -v "$(pwd)/data:/data" myapp   # -v 挂载目录
docker run -d -e TZ=Asia/Shanghai myapp    # -e 环境变量
docker run --name app1 myapp               # --name 起名字

docker ps                       # 运行中的容器
docker ps -a                    # 所有（含已停）
docker stop <c>                 # 停止
docker start <c>                # 启动
docker rm <c>                   # 删除（-f 强制删运行中的）

# ---- 排查 ----
docker exec -it <c> bash        # 进"运行中"的容器（没有 bash 就用 sh）
docker logs -f <c>              # 看日志（-f 跟踪）
docker inspect <c>              # 看详细信息（IP、挂载、配置）
docker cp file <c>:/path        # 宿主 → 容器
docker cp <c>:/path file        # 容器 → 宿主
```

**参数速查**：

| 参数 | 含义 |
|------|------|
| `-d` | 后台运行（detached） |
| `-it` | 交互式 + 终端（要进 shell 就加） |
| `--rm` | 退出后自动删容器（临时用） |
| `-p 8080:80` | 端口映射：宿主 8080 → 容器 80 |
| `-v 宿主:容器` | 挂载目录/卷 |
| `-e KEY=VAL` | 环境变量 |
| `--name` | 容器名 |

### 清理与磁盘

Docker 吃满磁盘是**最常见的实际故障**——先看，再删：

```bash
docker system df              # 看占用（镜像/容器/卷/缓存各多少）
docker system df -v           # 详细到每个对象

docker system prune           # 清：已停容器 + 悬空镜像 + 无用网络
docker builder prune          # 清构建缓存（通常占最大）
docker image prune            # 清悬空镜像（<none>）
docker image prune -a         # 清所有没被容器使用的镜像（狠）

docker system prune -a --volumes   # ⚠️ 连数据卷一起清（数据会没！）
```

**经验**：`docker builder prune` 通常能释放最多（构建缓存堆积）。

## 4. Dockerfile

```dockerfile
# 基础镜像（第一条指令；ARG 可写在它前面）
FROM ubuntu:22.04

# 工作目录（后续命令在这跑）
WORKDIR /app

# 构建时执行；curl 供 HEALTHCHECK 用
RUN apt-get update \
    && apt-get install -y python3 python3-pip curl \
    && rm -rf /var/lib/apt/lists/*

# 先拷依赖清单，装完再拷源码（利用层缓存）
COPY requirements.txt .
RUN pip3 install --no-cache-dir -r requirements.txt

COPY . .

# 环境变量（运行时也在）
ENV APP_PORT=8080

# 构建参数（只构建时用）
ARG VERSION=1.0

# 声明端口（仅文档：真正暴露端口靠 -p）
EXPOSE 8080

# 先创建用户，再切换（基础镜像里默认没有 appuser）
RUN useradd -m appuser && chown -R appuser:appuser /app
USER appuser

# 容器启动命令
CMD ["python3", "app.py"]
```

### CMD vs ENTRYPOINT

| | CMD | ENTRYPOINT |
|--|-----|-----------|
| 作用 | **默认**命令/参数 | **固定**入口命令 |
| `docker run` 带参数时 | **被覆盖** | 不被覆盖，参数追加在后面 |
| 典型用法 | 提供默认参数 | 定义"这个镜像就是干这个的" |

`docker run --entrypoint` 可临时覆盖 ENTRYPOINT；镜像名后的参数替换 CMD（设了 ENTRYPOINT 时，这些参数追加给它）。

```dockerfile
ENTRYPOINT ["python3", "app.py"]
# 默认参数；run 时传参可覆盖
CMD ["--port", "8080"]
# docker run myapp --port 9000 → python3 app.py --port 9000
```

### HEALTHCHECK（健康检查）

让 Docker 定期检测"容器里的服务**是否真的可用**"：

```dockerfile
HEALTHCHECK --interval=30s --timeout=3s --start-period=5s --retries=3 \
    CMD curl -f http://localhost:8080/health || exit 1
```

> 镜像里必须有 `curl`（上面示例已装）；用 slim/alpine 时先确认，否则健康检查永远失败。

- `--interval` 检查间隔 / `--timeout` 单次超时 / `--retries` 连续失败几次算 unhealthy
- `--start-period` **启动宽限期**（这期间失败不计，给服务初始化时间）
- 状态看 `docker ps` 的 `STATUS` 列（`healthy` / `unhealthy`）

**为什么需要**：**进程活着 ≠ 服务可用**（数据库进程起了，但还在初始化）。

**配合 Compose 实现"等就绪再启动"**：

```yaml
services:
  app:
    depends_on:
      db:
        condition: service_healthy   # 等 db 健康了才启动 app
  db:
    image: postgres:16
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      retries: 5
```

## 5. 层缓存

**规则**：`RUN`/`COPY`/`ADD` 各生成一个文件层；**某一层变了，它之后的所有层都要重建**。`ENV`/`CMD` 等只改配置，不占文件层。

```dockerfile
# ❌ 改一行代码 → 重装所有依赖
COPY . .
RUN pip3 install -r requirements.txt

# 依赖清单没变 → 复用缓存
COPY requirements.txt .
RUN pip3 install -r requirements.txt
# 源码放最后
COPY . .
```

**配套：`.dockerignore`**（别把 `.git`、`build/`、`node_modules` 塞进构建上下文）

```
.git
build/
.venv/
*.o
```

## 6. 数据持久化

**容器的可写层，删容器就没了**——数据要放出来：

| 方式 | 写法 | 特点 |
|------|------|------|
| **volume**（卷） | `-v mydata:/data` | Docker 管理，跨容器共享，**生产用** |
| **bind mount**（绑定挂载） | `-v /host/path:/data` | 直接挂宿主目录，**开发调试用** |

```bash
docker volume ls                 # 列出卷
docker volume create mydata      # 创建卷
docker volume rm mydata          # 删除卷
```

## 7. 网络

| 模式 | 说明 |
|------|------|
| `bridge`（默认） | 容器有独立 IP，端口要 `-p` 映射出来 |
| `host` | 直接用宿主机网络（无隔离） |
| `none` | 无网络 |

**容器互访**：**默认 bridge 不支持容器名解析**——只有**自己创建的网络**里，才能用容器名当主机名：

```bash
docker network create mynet
docker run -d --network mynet --name db postgres
docker run -d --network mynet myapp     # 代码里连 `db:5432` 即可
```

## 8. Docker Compose

用一个 YAML 定义**多个容器**，一条命令起整套：

```yaml
# compose.yaml
services:
  app:
    build: .
    ports: ["8080:8080"]
    depends_on: [db]
    environment:
      - DB_HOST=db
  db:
    image: postgres:16
    volumes: [pgdata:/var/lib/postgresql/data]

volumes:
  pgdata:
```

```bash
docker compose up -d        # 起整套（-d 后台）
docker compose logs -f      # 看日志
docker compose down         # 停 + 删（-v 连卷删）
docker compose ps
```

> 注意：现在命令是 **`docker compose`**（子命令）；老的 `docker-compose`（带横线）已废弃。

> **`depends_on` 的坑**：它只保证**启动顺序**，**不保证服务就绪**（数据库进程起来了，但还在初始化）。解法：给依赖加 **HEALTHCHECK** + `condition: service_healthy`（见 §4）。

### 常用补充

```yaml
services:
  app:
    build: .
    env_file: .env
  debug:
    image: busybox
    command: ["tail", "-f", "/dev/null"]
    profiles: ["debug"]
```

```bash
docker compose up -d --build            # 改代码后重建镜像
docker compose exec app bash            # 进运行中的服务（没有 bash 用 sh）
docker compose run --rm app pytest      # 新容器里跑一次性命令
docker compose --profile debug up -d    # 额外启动 debug 服务
```

- `env_file` 把文件里的变量注入容器；`.env` 默认只是 Compose 自己的变量替换文件
- `environment` 里的同名变量会覆盖 `env_file`
- `profiles` 里的服务默认不启动，带 `--profile` 才起
- `exec` 进已有容器；`run` 新建容器（默认不映射端口）
- `compose.override.yaml` 会自动合并；多文件用 `-f base.yaml -f prod.yaml`

**用在哪**：本地开发环境（app + 数据库 + Redis）、CI 集成测试、小规模部署。单个服务用不上。

## 9. 镜像分发

```bash
# 打标签：registry/namespace/name:tag
docker tag myapp registry.example.com/team/myapp:1.2.3

docker login registry.example.com
docker push registry.example.com/team/myapp:1.2.3
docker pull registry.example.com/team/myapp:1.2.3
```

- `docker tag` 只是给同一个镜像起别名，不复制
- `push` 前必须带上 registry/namespace
- `latest` 只是普通标签，不保证最新；生产 pin 版本或 digest
- 按 digest 拉取：`docker pull image@sha256:...`
- 查 digest：`docker inspect --format '{{index .RepoDigests 0}}' image:tag`（推送/拉取过的镜像才有）

离线搬运：

```bash
docker save -o myapp.tar registry.example.com/team/myapp:1.2.3
docker load -i myapp.tar
```

> `save` 存的是镜像和标签；`export/import` 导的是容器文件系统，会丢镜像历史和元数据，别混用。

## 10. 常见坑与最佳实践

| 坑 | 对策 |
|----|------|
| 镜像巨大 | 用**多阶段构建**（见 [构建与调试](构建与调试.md)）、选 alpine/slim 基础镜像、`RUN` 里清理 apt 缓存 |
| 构建慢 | 写好层顺序（不变的在前）；配 `.dockerignore` |
| 数据丢了 | 该挂 volume 的挂上 |
| 权限问题 | 见 [运行与安全](运行与安全.md)；宿主目录 UID 对齐 |
| 密钥进镜像 | **别** `COPY` 密钥/`.env`；构建时用 BuildKit secret（见 [构建与调试](构建与调试.md) §3），运行时用挂载/secret 管理；`--env` 会进 `inspect`，不能当保密手段 |
| 时区不对 | `-e TZ=Asia/Shanghai` |
| 日志写容器内部文件 | **输出到 stdout/stderr**——`docker logs` 才看得到，且容器删了文件就没 |

**最佳实践一句话**：**一个容器一个主进程**（原则，不是硬限制）、镜像越小越好、版本要 pin、数据放外面、**日志走 stdout**。

## 11. 要点回顾

1. **分层 / 写时复制**：`RUN`/`COPY`/`ADD` 生成文件层；镜像层只读；容器加可写层（改文件才拷贝）；隔离靠 namespaces/cgroups/unionfs
2. **CMD vs ENTRYPOINT**：CMD 会被 `run` 参数覆盖；ENTRYPOINT 不被覆盖、参数追加；`--entrypoint` 可临时覆盖
3. **构建缓存**：变化少的指令在前，源码放最后；`.dockerignore` 缩小构建上下文
4. **数据持久化**：volume（生产）vs bind mount（开发）；容器可写层删容器就丢
5. **网络**：默认 bridge **不支持容器名 DNS**，自定义网络才支持
6. **Compose**：`depends_on` 只管启动顺序；`env_file`/`profiles`/`exec`/`run` 管环境和日常操作
7. **`EXPOSE`** 只是文档，暴露端口必须 `-p`
8. **分发**：`tag` + `push` 到 registry；离线用 `save`/`load`；生产 pin digest

> 运行时资源、重启、日志、停止和加固见 [运行与安全](运行与安全.md)。
