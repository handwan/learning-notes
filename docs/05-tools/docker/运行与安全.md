# 运行与安全

容器跑起来之后：限制资源、看日志、优雅停止、降低攻击面。

> 容器能跑不等于能管：资源要限、日志要轮转、停止要优雅、权限要收。

## 1. 资源限制

```bash
docker run -d \
    --memory=512m --memory-swap=512m \
    --cpus=1.5 \
    --pids-limit=256 \
    --restart=unless-stopped \
    myapp
```

| 参数 | 作用 | 注意 |
|------|------|------|
| `--memory` | 内存上限 | 超了会被 OOM kill（退出码 137） |
| `--memory-swap` | 内存 + swap 总量 | 和 `--memory` 相等 = 不用 swap |
| `--cpus` | CPU 配额（可小数） | 不是绑核；绑核用 `--cpuset-cpus=0,1` |
| `--pids-limit` | 进程/线程数上限 | 防 fork 炸弹 |
| `--restart` | 退出后的重启策略 | 见 §2 |

看运行时占用：

```bash
docker stats --no-stream
docker stats <c>          # 持续刷新
```

> OOM 后可以用 `docker inspect --format '{{.State.OOMKilled}}' <c>` 确认。

改运行中容器的限制：

```bash
docker update --memory 1g --cpus 2 <c>
```

> 能用 `docker update` 改的项以 `docker update --help` 为准；改不了的重建容器。

## 2. 重启策略

| 策略 | 行为 |
|------|------|
| `no` | 不重启（默认） |
| `on-failure[:N]` | 非 0 退出才重启，最多 N 次 |
| `always` | 总是重启（包括 dockerd 重启后） |
| `unless-stopped` | 总是重启，除非手动 `docker stop` |

> `--restart` 只处理容器退出，不判断服务是否可用；服务就绪用 HEALTHCHECK。

## 3. 日志与磁盘

```bash
docker logs --tail 100 --since 10m -f <c>
```

Docker 默认用 `json-file` 驱动，日志放在 `/var/lib/docker/containers/<id>/`；不轮转会一直长。

```bash
docker run -d \
    --log-opt max-size=10m --log-opt max-file=3 \
    myapp
```

全局配置在 `/etc/docker/daemon.json`：

```json
{
  "log-driver": "json-file",
  "log-opts": { "max-size": "10m", "max-file": "3" }
}
```

改完重启 dockerd；这些配置只对新建容器生效。生产也可以换 `journald`/`syslog`/`fluentd`，但换完后 `docker logs` 不一定还能看。

## 4. 停止与 PID 1

```bash
docker stop <c>            # SIGTERM，默认等 10s，再 SIGKILL
docker stop -t 30 <c>      # 等 30s
docker kill <c>            # 默认直接 SIGKILL
docker kill -s SIGINT <c>  # 发指定信号
```

- `STOPSIGNAL SIGTERM` 可以改镜像的停止信号
- `CMD ["app"]`（exec 形式）能让 app 直接收到信号；`CMD app` 会经过 `/bin/sh -c`，shell 可能不转发
- `--init` 用 tini 做 PID 1，负责转发信号和回收僵尸进程

> 容器里的 PID 1 默认不会自动收尸；应用自己不是 init 时，加 `--init`。

## 5. 运行时加固

| 做法 | 作用 |
|------|------|
| `--user <uid>:<gid>` / 镜像里 `USER` | 不用 root 跑 |
| `--cap-drop=ALL` + 按需 `--cap-add` | 去掉不需要的 root 能力 |
| `--security-opt no-new-privileges` | 禁止 setuid 等方式提权 |
| `--read-only` + `--tmpfs /tmp` | 根文件系统只读，临时写放 tmpfs |
| `--pids-limit`、`--memory` | 限制 fork 炸弹和内存 |
| rootless Docker | dockerd 本身以普通用户跑，降低 daemon 被攻破的后果 |

```bash
docker run --rm -it \
    --user 1000:1000 \
    --cap-drop=ALL \
    --security-opt no-new-privileges \
    --read-only --tmpfs /tmp \
    --pids-limit=128 --memory=256m \
    myapp
```

> `--privileged` 等于放开大部分隔离，不要拿来图省事；加固是分层的，能去掉的权限就去掉，不能去掉的再按需加回。

## 6. 要点回顾

1. **资源**：`--memory`/`--cpus`/`--pids-limit`；OOM 退出码 137；`docker stats` 看，`docker update` 改
2. **重启**：`no` / `on-failure` / `always` / `unless-stopped`；重启不等于健康
3. **日志**：默认 `json-file`；`max-size`/`max-file` 轮转；换驱动后 `docker logs` 不一定可用
4. **停止**：`docker stop` 先 SIGTERM，默认 10s 后 SIGKILL；PID 1 不收尸时用 `--init`
5. **加固**：非 root、`--cap-drop=ALL`、`no-new-privileges`、`--read-only`、rootless；`--privileged` 不要图省事
