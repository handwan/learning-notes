# 生成器表达式

## 1. 为什么需要

`CMakeLists.txt` 执行（configure）时，有些信息**还不知道**（构建配置、目标平台、语言）。生成器表达式 `$<...>` 在**生成阶段**才求值。

```cmake
target_compile_definitions(app PRIVATE
    $<$<CONFIG:Debug>:DEBUG_MODE>     # 仅 Debug 配置时定义 DEBUG_MODE
)
```

## 2. 语法

`$<表达式>`，可嵌套。

## 3. 常用表达式

### 构建 / 安装接口

```cmake
target_include_directories(mylib PUBLIC
    $<BUILD_INTERFACE:${CMAKE_CURRENT_SOURCE_DIR}/include>   # 编译自己时：源码路径
    $<INSTALL_INTERFACE:include>                             # 安装后别人用：安装前缀
)
```

**原因**：构建目录的绝对路径不能写进导出文件（别人机器上会失效），必须区分两种场景。

### 配置相关

```cmake
$<CONFIG:Debug>                    # Debug 时为真
$<$<CONFIG:Release>:NDEBUG>        # Release 时加 NDEBUG
$<IF:$<CONFIG:Debug>,d,optimized>  # 三目
```

### 目标相关

```cmake
$<TARGET_FILE:app>                 # target 产物的完整路径
$<TARGET_PROPERTY:...>             # 属性值
$<TARGET_OBJECTS:objlib>           # 对象库的对象文件
```

### 语言 / 编译器

```cmake
$<COMPILE_LANGUAGE:CXX>            # 只对 C++ 生效
$<CXX_COMPILER_ID:GNU>             # 编译器是 GCC
$<$<CXX_COMPILER_ID:MSVC>:/W4>     # MSVC 时加 /W4
```

## 4. 常见用途

```cmake
# 不同配置不同宏
target_compile_definitions(mylib PRIVATE
    $<$<CONFIG:Debug>:MYLIB_DEBUG>
)

# 不同编译器不同警告
target_compile_options(mylib PRIVATE
    $<$<CXX_COMPILER_ID:GNU,Clang>:-Wall>
    $<$<CXX_COMPILER_ID:MSVC>:/W4>
)

# 构建时 / 安装时不同的 include（导出库标配）
target_include_directories(mylib PUBLIC
    $<BUILD_INTERFACE:${CMAKE_CURRENT_SOURCE_DIR}/include>
    $<INSTALL_INTERFACE:${CMAKE_INSTALL_INCLUDEDIR}>   # 需先 include(GNUInstallDirs)
)
```

## 5. 一句话

> `$<...>` 在生成阶段求值，用来表达**配置 / 编译器 / 构建 vs 安装**相关的差异；`$<BUILD_INTERFACE>` / `$<INSTALL_INTERFACE>` 是导出库的标配。
