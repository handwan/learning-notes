# 工程实践

## 1. 多目录项目组织

标准结构：

```
project/
├── CMakeLists.txt          # 顶层
├── include/mylib/          # 公共头文件
├── src/
│   ├── CMakeLists.txt
│   └── ...
├── tests/
│   └── CMakeLists.txt
├── apps/
│   └── CMakeLists.txt
└── cmake/                  # config 模板等
```

`CMakeLists.txt`（顶层）：

```cmake
cmake_minimum_required(VERSION 3.16)
project(proj VERSION 1.0 LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_EXPORT_COMPILE_COMMANDS ON)

option(BUILD_TESTS "Build tests" ON)

add_subdirectory(src)
add_subdirectory(apps)
if(BUILD_TESTS)
    enable_testing()
    add_subdirectory(tests)
endif()
```

`src/CMakeLists.txt`：

```cmake
add_library(mylib src/a.cpp)
add_library(mylib::mylib ALIAS mylib)
target_include_directories(mylib PUBLIC
    $<BUILD_INTERFACE:${PROJECT_SOURCE_DIR}/include>
    $<INSTALL_INTERFACE:include>
)
```

**要点**：每个目录一个 `CMakeLists.txt`，**用 target 互相连接**（不用全局命令）。

**易混变量**：

| 变量 | 含义 |
|------|------|
| `CMAKE_SOURCE_DIR` | 最顶层源码目录 |
| `PROJECT_SOURCE_DIR` | 最近一次 `project()` 的目录 |
| `CMAKE_CURRENT_SOURCE_DIR` | 当前 `CMakeLists.txt` 所在目录 |

## 2. CMakePresets.json

把 configure/build 配置存成文件，团队共享，不用记一堆 `-D`（下面 schema `version: 3` 需 CMake 3.21+）：

```json
{
  "version": 3,
  "configurePresets": [
    {
      "name": "debug",
      "generator": "Ninja",
      "binaryDir": "${sourceDir}/build/debug",
      "cacheVariables": {
        "CMAKE_BUILD_TYPE": "Debug",
        "CMAKE_EXPORT_COMPILE_COMMANDS": "ON"
      }
    },
    {
      "name": "release",
      "generator": "Ninja",
      "binaryDir": "${sourceDir}/build/release",
      "cacheVariables": { "CMAKE_BUILD_TYPE": "Release" }
    }
  ],
  "buildPresets": [
    { "name": "debug", "configurePreset": "debug" }
  ]
}
```

用法：

```bash
cmake --preset debug              # 代替 cmake -S . -B ...
cmake --build --preset debug      # 代替 cmake --build ...
```

新人 `cmake --preset debug` 就能跑，配置进版本库。

## 3. 自定义构建步骤

### add_custom_command（生成文件）

```cmake
add_custom_command(
    OUTPUT ${CMAKE_CURRENT_BINARY_DIR}/generated.cpp
    COMMAND ${CMAKE_COMMAND} -E copy
            ${CMAKE_CURRENT_SOURCE_DIR}/template.cpp
            ${CMAKE_CURRENT_BINARY_DIR}/generated.cpp
    DEPENDS ${CMAKE_CURRENT_SOURCE_DIR}/template.cpp
    COMMENT "Generating generated.cpp"
)
add_executable(app main.cpp ${CMAKE_CURRENT_BINARY_DIR}/generated.cpp)
```

典型用途：**protobuf/flatbuffers 生成、代码生成器、资源嵌入**。

### add_custom_target（额外目标）

```cmake
add_custom_target(run
    COMMAND app
    DEPENDS app
    COMMENT "Running app"
)
add_custom_target(format
    COMMAND clang-format -i ${SRCS}     # SRCS = 前面 set 的源文件列表
)
```

- `add_custom_target` **不会自动构建**，要显式指定：`cmake --build build --target run`
- `add_custom_command(OUTPUT ...)` 由**依赖它**的 target 触发

## 4. CTest（测试）

顶层：

```cmake
enable_testing()          # 或 include(CTest)
add_subdirectory(tests)
```

`tests/CMakeLists.txt`：

```cmake
add_executable(test_add test_add.cpp)
target_link_libraries(test_add PRIVATE mylib::mylib)
add_test(NAME add_basic COMMAND test_add)
```

运行：

```bash
ctest --test-dir build --output-on-failure
```

配 GoogleTest：

```cmake
find_package(GTest REQUIRED)
target_link_libraries(test_add PRIVATE GTest::gtest_main)
include(GoogleTest)
gtest_discover_tests(test_add)     # 自动发现每个 TEST
```

## 5. 编译加速

### ccache（缓存编译结果）

```cmake
find_program(CCACHE ccache)
if(CCACHE)
    set(CMAKE_CXX_COMPILER_LAUNCHER ${CCACHE})
endif()
```

或命令行：`cmake -S . -B build -DCMAKE_CXX_COMPILER_LAUNCHER=ccache`。**切分支重编译快很多**。

### 预编译头（PCH）

```cmake
target_precompile_headers(mylib PRIVATE
    <vector>
    <string>
    <memory>
)
```

### 用 Ninja

```bash
cmake -S . -B build -G Ninja      # 比 Make 快
```

## 6. 小结

- **多目录**：每目录一个 `CMakeLists.txt`，用 target 连接
- **CMakePresets.json**：配置进文件、团队共享
- **自定义命令**：`add_custom_command`（生成文件）/ `add_custom_target`（额外目标）
- **测试**：`enable_testing()` + `add_test`（或 `gtest_discover_tests`）
- **加速**：ccache + PCH + Ninja
