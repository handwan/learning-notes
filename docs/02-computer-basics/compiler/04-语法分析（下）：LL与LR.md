# 语法分析（下）：LL 与 LR

自顶向下（LL）和自底向上（LR）两条路线——**LR 更强**（能处理的文法更多），yacc/bison 用的就是它的简化版 **LALR(1)**。

## 1. LL(1)：表驱动的自顶向下

**LL(1)** = 从左到右扫描、最左推导、向前看 1 个 token。

两个集合决定一切：

| 集合 | 含义 | 用途 |
|------|------|------|
| **FIRST(α)** | α 能开头的终结符集合 | 看"这个产生式能不能从当前 token 开始" |
| **FOLLOW(A)** | A 后面可能跟的终结符集合 | 处理 ε 产生式（什么时候可以"空"） |

**预测分析表构造**（手算模板，速查篇有）：
1. 求所有 FIRST/FOLLOW
2. 对每个产生式 `A → α`：把 α 的 FIRST 填进 `M[A, ·]`；若 α 能推出 ε，把 FOLLOW(A) 也填上
3. 一格里有两个产生式 = **冲突**（该文法不是 LL(1)）

## 2. LR：自底向上、移进-归约

```
词法流 → [ 栈：已分析的符号 ] + 移进下一个 token → 归约（用产生式合并）→ 直到归约到开始符号
```

**LR 家族演进**（也是工程演进史）：

| 版本 | 前瞻 | 能力 | 说明 |
|------|:---:|------|------|
| LR(0) | 无 | 最弱 | 归约不看输入 → 冲突多 |
| SLR(1) | 1 | 中 | 用 FOLLOW 集消解冲突 |
| LR(1) | 1 | 强 | 每项带"前瞻符"，状态爆炸 |
| **LALR(1)** | 1 | ≈LR(1) | **合并同心项**，状态数大减——**yacc/bison 的默认** |

**冲突的消解**（现实中最常见）：

- **移进-归约冲突**：经典来源是 `expr → expr '+' expr`（优先级）→ 声明 `%left '+' '-'` / `%left '*' '/'` 就能消解
- **归约-归约冲突**：两个产生式都能归约 → 一般说明文法设计有问题

## 3. 实测：用 bison 生成一个计算器

```
calc.y（文法 + 优先级）      calc.l（flex 词法）
        ↓ bison -d                  ↓ flex
   calc.tab.cpp/.hpp  +  calc.lex.cpp  →  g++  →  ./calc
```

**实测结果**：

| 指标 | 数值 |
|------|------|
| bison 生成的 LALR 状态数 | **19** |
| 冲突数 | **0**（优先级声明消解了移进-归约） |
| 解析输入 `1+2*3` / `(1+2)*3` / `10-4/2` / `2*3+4*5` | **7 / 9 / 8 / 26** |

**踩到的三个坑（都是经典）**：

1. **`yylval` 重复定义**：bison 的 `-d` 头文件已经声明了它，词法器里再写一遍定义 → 链接报 `multiple definition`
2. **`yywrap` 未定义**：flex 默认要它 → 加 `%option noyywrap`（或链接 `-lfl`）
3. **flex 的 `.` 不匹配换行**：`. { return yytext[0]; }` 漏掉 `\n` → 解析器永远等不到行尾 → `syntax error`（实测报错）→ 显式加 `\n { return '\n'; }`

**结论**：bison 这类工具把"文法 → 状态机"全自动化了；但**手写递归下降依然流行**（错误信息更好、调试更直观）——工具与手写各有战场。

## 4. 两条路线怎么选

| | 手写递归下降（LL） | bison/yacc（LALR） |
|--|------------------|-------------------|
| 写法 | 一个非终结符一个函数 | 写产生式 + 词法规则 |
| 错误信息 | **好**（能定制） | 一般 |
| 适合文法 | 大多数编程语言（消除左递归后） | 表达式密集/工业标准（SQL、PHP） |
| 调试 | 直接断点 | 看 `.output` 状态机 |
| 现实 | **C++/Go/Rust 等编译器主流** | 数据库/配置语言/语言前端常用 |

## 5. 要点回顾

1. **LL(1)**：FIRST/FOLLOW + 预测分析表；表里有冲突就不是 LL(1)
2. **LR 家族**：LR(0) → SLR(1) → LR(1) → **LALR(1)**（合并同心项，bison 默认）
3. **冲突消解**：优先级 + 结合性声明（`%left`/`%right`）解决移进-归约；归约-归约多为文法缺陷
4. **bison 实测**：19 状态、0 冲突、四个表达式全对；踩坑：`yylval`/`yywrap`/flex 的 `.` 不含换行
5. **手写递归下降 vs bison**：前者错误信息好、主流语言编译器用它；后者自动生成、适合表达式密集场景
