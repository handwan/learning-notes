# 代码优化

优化是"在不改变程序行为的前提下，让目标代码更快/更小"——**在 IR 上做等价变换**。这一篇讲清"优化器在干什么"，并且**看它真干了什么**。

## 1. 优化的三个层次

| 层次 | 范围 | 例子 |
|------|------|------|
| 局部 | 单个基本块内 | 常量折叠、代数化简 |
| 全局 | 整个函数（跨基本块） | 常量传播、循环优化、CSE |
| 过程间 | 跨函数 | **内联**、死函数删除、过程间常量传播（LTO） |

**基本块（Basic Block）**：一段"一进一出"的顺序代码；函数 = **流图**（基本块 + 跳转边）。
实测：`-O0` 的 `sum()` 分成多个基本块（每个 label 一块）。

## 2. 数据流分析：优化的"情报系统"

在流图上迭代求解"每个点上的事实"：

| 分析 | 问的问题 | 用途 |
|------|---------|------|
| **到达定值** | 某点可能来自哪些赋值？ | 常量传播、死代码删除 |
| **活跃变量** | 某点之后变量还会被用吗？ | 寄存器分配、死代码删除 |
| 可用表达式 | 某点哪些表达式已经算过？ | 公共子表达式消除 |

（方程模板见[速查篇](10-速查与手算模板.md)；工程上直接用 LLVM 的 AnalysisManager。）

## 3. 经典优化 + 实测证据

| 优化 | 干什么 | 实测（`-O0` → `-O2`） |
|------|-------|---------------------|
| **常量折叠/传播** | 编译期算掉常量表达式 | `const_fold(){ 2*3+4 }` → **`ret i32 10`**（-O0 要一步步真算） |
| **内联** | 把被调函数展开 | `add()` 的调用被内联消掉（函数定义仍保留——外部链接要留着） |
| **SSA 转换** | 变量单赋值 + φ | 程序里出现 `phi` 节点 |
| **自动向量化** | 一条指令算一批 | IR 里出现 `<4 x i32>` 向量类型；汇编里 `pxor/movdqu`（xmm） |
| 死代码删除 | 删掉没人用的计算 | -O0 的 `alloca/load/store` 在 -O2 全没了 |
| 循环优化 | 不变量外提、展开 | 循环体从"每轮一条"变成"批量 + 收尾" |

**结果**：同一份代码的汇编在 -O2 下明显变短（还多了向量指令）。

## 4. -O0 到 -O3 各做什么（工程指南）

| 级别 | 做什么 | 什么时候用 |
|------|--------|-----------|
| `-O0` | 几乎不优化（可调试性最好） | 日常开发/排错 |
| `-O1` | 基础优化（不激进） | 想快又想调 |
| `-O2` | **主流优化全开**（内联/向量化/循环优化） | **发布默认** |
| `-O3` | 更激进的向量化/展开（代码更大） | 计算密集 |
| `-Os` | 最小体积 | 嵌入式/镜像 |
| `-Ofast` | 连"不符合 IEEE 的浮点优化"也开 ⚠️ | 明确不需要精度的场景 |

## 5. 优化的边界：UB 与浮点

- **UB 是优化的"许可证"**：IR 里的 `add nsw`（有符号不溢出假设）、`inbounds` 等标记让编译器敢做更多事——UB 代码的行为因此"看起来随机"
- **浮点默认不重排**（保持 IEEE 语义）；`-ffast-math`/`-Ofast` 才允许重排/合并——**精度会变**
- **volatile / 原子 / 内存屏障**：优化器必须遵守（否则并发代码会被优化坏）

## 6. 要点回顾

1. **优化 = IR 上的等价变换**；层次：局部 → 全局 → 过程间（LTO）
2. **基本块/流图**是优化的工作单元；**数据流分析**（到达定值/活跃变量/可用表达式）提供"事实"
3. **优化证据**：常量折叠成 `ret i32 10`、调用被内联、出现 φ 与 `<4 x i32>` 向量类型、汇编明显变短
4. **-O0/O1/O2/O3/Os/Ofast** 各干什么；发布默认 `-O2`，`-Ofast` 牺牲浮点精度
5. **UB 是优化的许可证**：`nsw` 之类的假设让编译器更大胆——写 UB 就别抱怨"结果不对"
6. 优化不是"越多越好"：调试构建用 `-O0`，发布用 `-O2`（[三套 build](../computer-organization/05-CPU与流水线.md)）
