# AI 编译器与推理引擎

模型 = 一张**计算图**，推理引擎 = **图编译器 + 运行时**——传统编译器那套（IR、优化、代码生成、内存规划）在 AI 时代换了个名字继续用。

> 这篇讲机制；具体引擎（ONNX Runtime / TensorRT 等）的图优化日志属于推理工程，本章不展开。

## 1. 为什么 AI 需要"编译器"

| 问题 | 说明 |
|------|------|
| 算子太多 × 硬件太多 | 手写每个算子在每种芯片上的实现不现实 → **自动生成/自动调优** |
| 性能要求极端 | 推理要低延迟高吞吐 → 必须做图级优化（融合、量化） |
| 硬件碎片化 | CPU/GPU/NPU，NVIDIA/AMD/Apple/华为…… → 需要中间层（IR）解耦 |
| 部署形态多 | 服务端/边缘/手机 → 同一模型要适配多目标 |

**和传统编译器的对应**：模型（计算图）≈ 源程序；图优化 ≈ 编译优化；kernel 生成/调库 ≈ 目标代码生成。

## 2. 计算图 IR

```
输入张量 ──→ [算子1] ──→ [算子2] ──→ ... ──→ 输出张量
              Conv        BN            ReLU
```

| 层 | 代表 | 类比 |
|----|------|------|
| 交换格式 | **ONNX**（跨框架通用） | 源码 |
| 高层图 IR | TVM Relay、TensorRT Network、StableHLO | 高层 IR（语言语义） |
| 通用编译器框架 | **MLIR**（多种方言） | LLVM IR（多级 IR） |
| 低层/机器 | CUDA/PTX、LLVM IR、汇编 | 机器 IR |

## 3. 图优化（推理性能的大头）

| 优化 | 干什么 | 收益来源 |
|------|--------|---------|
| **算子融合** | Conv+BN+ReLU 合成一个 kernel | **省中间张量的读写**（带宽！ roofline 的"低算术强度算子"被合掉） |
| 常量折叠 | 权重里的常量运算提前算 | 省计算/省图节点 |
| 布局转换 | NCHW ↔ NHWC 等 | 匹配硬件偏好（cuDNN 喜欢 NHWC） |
| 死代码消除 | 推理时 dropout/训练专用算子删掉 | 省计算 |
| 公共子表达式 | 共享权重/共享中间结果 | 省显存/带宽 |
| **量化改写** | 插入 quant/dequant，FP32 → INT8 | 带宽/算力都减（[量化](../computer-organization/02-数据表示与运算.md)） |

**为什么融合最值钱**：逐个算子跑 = 每个中间结果都要"写显存 + 读显存"；融合后中间结果**留在片上（寄存器/shared memory）**——**访存少了，算术强度就上去了**（[roofline](../computer-organization/07-性能模型与roofline.md) 的斜线右移）。

## 4. 内核选择与代码生成

两条路：

| 路线 | 做法 | 例子 |
|------|------|------|
| **调库** | 调厂商高度优化的库 | cuDNN/cuBLAS/MKL/oneDNN |
| **生成代码** | 编译器生成 kernel（CUDA/LLVM/汇编） | TVM、XLA、TensorRT 的部分 kernel |

**自动调优（auto-tuning）**：同一个算子有多种实现/schedule（分块大小、向量化宽度、线程组织），**在目标硬件上实测挑最快**：

- TensorRT：每个算子尝试多个 tactic，选最快的
- TVM：AutoTVM/Ansor 搜索 schedule
- 代价：调优要时间（可离线做、缓存下来）

## 5. 内存规划（显存复用）

推理的显存常常是瓶颈（[总线/IO 篇](../computer-organization/08-总线、IO与外部设备.md)）：

- **张量生命周期分析** → 不复用的张量共享同一块显存（**arena/内存池**）
- **in-place 算子**（如 ReLU 原地写）省一份拷贝
- 权重常驻显存 + 输入/输出双缓冲（[PCIe 算账](../computer-organization/08-总线、IO与外部设备.md)）

**这和"运行时存储组织"是同一个问题**：谁在什么时候活着 → 谁可以复用谁的空间。

## 6. 执行层

| 方式 | 特点 |
|------|------|
| 逐算子执行（eager） | 灵活、易调试；启动开销大 |
| 图执行器 | 预规划内存/调度，启动开销小 |
| **CUDA Graph** | 把整张图录成一次提交，减少 kernel 启动开销（小 batch 高 QPS 场景很值） |

## 7. 传统编译器 vs AI 编译器（对照表）

| | 传统编译器 | AI 编译器 |
|--|-----------|----------|
| 源 | 程序（标量/控制流） | 计算图（张量/无控制流为主） |
| IR | 三地址码/SSA/LLVM IR | 计算图/MLIR 方言 |
| 优化重点 | 常量折叠/内联/循环/寄存器 | **融合/布局/量化/内存复用** |
| 目标 | CPU 指令 | CPU/GPU/NPU + 库调用 |
| "正确性" | 语义完全一致 | 允许数值近似（fast-math/低精度） |
| 调优 | 编译选项 | **autotuning（实测选最快 kernel）** |

## 8. 要点回顾

1. **推理引擎 = 图编译器 + 运行时**；模型 = 计算图，IR 照样是枢纽
2. **图 IR 层次**：ONNX（交换）→ Relay/StableHLO/MLIR（优化）→ CUDA/PTX/LLVM IR（生成）
3. **图优化大头是融合**：省中间张量的显存读写 = 提高算术强度（roofline 视角）
4. **内核两条路**：调库（cuDNN 等）vs 生成代码（TVM/XLA）；**autotuning 按硬件实测选最快**
5. **内存规划**（arena/in-place）是"运行时存储组织"的 AI 版；CUDA Graph 省启动开销
6. **和传统编译器的区别**：优化重点在张量图、允许数值近似、目标多样——但"IR + 优化 + 代码生成"的骨架没变
