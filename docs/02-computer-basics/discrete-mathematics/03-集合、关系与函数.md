# 集合、关系与函数

集合运算是数学的"语法"，关系是**数据库**和**图**的共同底层，函数是"映射"的抽象。

## 1. 集合与运算

**集合**：无序、不重复的元素汇集。`x ∈ A`（属于）、`x ∉ A`（不属于）；空集 ∅；子集 A ⊆ B。

| 运算 | 符号 | 定义 | 类比 |
|------|:---:|------|------|
| 并 | A ∪ B | 属于 A 或 B | 逻辑 ∨ |
| 交 | A ∩ B | 同时属于 | 逻辑 ∧ |
| 差 | A − B | 属于 A 不属于 B | |
| 补 | Ā（相对全集 U） | U − A | 逻辑 ¬ |
| 对称差 | A ⊕ B | 只属于其中一个 | 逻辑异或 |
| 幂集 | P(A) | A 的所有子集构成的集合 | `1 << n` 种子集 |

**⚠ 与逻辑的对应（德摩根在集合上的样子）**：

```
(A ∪ B)ᶜ = Aᶜ ∩ Bᶜ
(A ∩ B)ᶜ = Aᶜ ∪ Bᶜ
```

**要点**：**集合的运算和布尔代数一一对应**（∪=∨、∩=∧、ᶜ=¬、∅=F、U=T）——这就是"位图/位集合"能表示集合的原因：一个整数的一位表示"某元素在不在集合里"。

```cpp
// 位集合：用整数的位表示集合，运算就是位运算
uint32_t A = 0b1010;      // {1, 3}（第 1、3 位是 1）
uint32_t B = 0b0110;      // {1, 2}
A | B;                    // 并集 = 0b1110 = {1,2,3}
A & B;                    // 交集 = 0b0010 = {1}
A & ~B;                   // 差集 = 0b1000 = {3}
A ^ B;                    // 对称差 = 0b1100 = {2,3}
```

## 2. 关系

**二元关系 R ⊆ A × B**：一组有序对（a, b）的集合；`a R b` 表示 (a, b) ∈ R。

**A 到自身的关系统称"关系"，性质**：

| 性质 | 定义 | 例子 |
|------|------|------|
| 自反 | ∀a, a R a | ≤、=（相等）；父母的"同姓" |
| 反自反 | ∀a, ¬(a R a) | <、≠ |
| 对称 | a R b ⇒ b R a | =、"同年生" |
| 反对称 | a R b 且 b R a ⇒ a = b | ≤、⊆ |
| 传递 | a R b, b R c ⇒ a R c | ≤、<、=、"是祖先" |

**两个特别重要的关系**：

| 类型 | 条件 | 要点 |
|------|------|------|
| **等价关系** | 自反 + 对称 + 传递 | 把集合**划分**成若干等价类 |
| **偏序关系** | 自反 + 反对称 + 传递 | 可以排"序"（但并非任意两个都可比） |

**等价关系的用途（"分类"）**：

- 模运算：`a ≡ b (mod n)`（同余）是等价关系 → 把整数分成 n 个剩余类
- 并查集（Union-Find）：维护等价类（连通分量）——图的连通性、Kruskal 算法
- 对象去重/规范化：按某个键分组

**偏序的用途（"依赖/层次"）**：

- 集合的包含 ⊆、整除 |、任务依赖图（拓扑序）、类型/类继承
- 偏序可能**有不可比的元素**（如 {1,2} 与 {1,3} 互不包含）
- **全序（线序）**：偏序 + 任意两个可比（如实数 ≤）
- **拓扑排序**：把偏序"拉直"成全序（每个偏序都能扩展成全序）——构建系统、依赖解析、课程安排

## 3. 关系的运算与表示

**表示**：

- **集合**：{(1,2), (2,3), ...}
- **矩阵**：邻接矩阵（第 i 行 j 列为 1 表示 i R j）；关系运算 = 布尔矩阵运算（并=或、交=与、合成=布尔矩阵乘）
- **图**：有向图（关系就是"边集"）

**关系的合成**（R∘S）：先 R 再 S，`a (R∘S) c` 当且仅当 ∃b（a R b 且 b S c）。

| 语言 | 运算符 | 对应 |
|------|--------|------|
| 关系代数 | 选择 σ、投影 π、连接 ⋈、笛卡尔积 × | **SQL 的底层** |
| SQL | `WHERE`（σ）、`SELECT`（π）、`JOIN`（⋈） | 业务查询 |

**SQL 和关系代数的对应**（一张表）：

| SQL | 关系代数 |
|-----|---------|
| `SELECT a, b FROM t WHERE p` | π(a,b) (σ_p (t)) |
| `SELECT * FROM a, b` | a × b（笛卡尔积） |
| `a JOIN b ON a.k = b.k` | a ⋈_{a.k=b.k} b |
| `UNION` / `INTERSECT` / `EXCEPT` | ∪ / ∩ / − |

（数据库的"关系模型"这个名字就来自这里；写 SQL 时知道它对应哪种关系运算，就容易判断"能不能用索引"。）

## 4. 函数

**函数 f: A → B**：A 的**每个**元素恰好映射到 B 的一个元素（"一对一方向"的一种特殊关系）。

| 类型 | 条件 | 例子 |
|------|------|------|
| 单射（injective） | 不同输入 → 不同输出 | f(x) = 2x |
| 满射（surjective） | B 中每个元素都被映射到 | f: ℝ→ℝ, f(x)=x³ |
| 双射（bijective） | 单射 + 满射 | f(x) = x + 1（可逆） |

**要点**：

- **只有双射才有逆函数**（逆映射要求"每个输出唯一对应一个输入"）
- 哈希函数追求"近似单射"（不同 key 尽量不同桶）；哈希冲突就是"不满足单射"的例子
- 单射/满射在计数里有大用处（**鸽巢原理**：A 到 B 的单射要求 |A| ≤ |B|）

## 5. 基数（"集合多大"）

| 概念 | 说明 |
|------|------|
| 有限集 | 元素个数有限，|A| = n |
| 可数无限 | 能和自然数一一对应（双射）：ℕ、ℤ、ℚ、**所有程序** |
| 不可数 | 不能：ℝ、ℂ、**所有函数的集合** |
| 康托尔定理 | |P(A)| > |A|（幂集总比原集合"大"）— 用对角线法证明 |

**为什么值得知道**：

- 程序是"有限字符串"，所以**程序的总数是可数无限**，而实数不可数——这说明"大部分实数无法被任何程序精确表示"（计算/表示能力的天花板，对接可计算性篇）
- 停机问题的证明就用对角线法（"判定器" 自己喂自己）

## 6. 要点回顾

1. **集合运算 = 布尔代数**（∪=∨、∩=∧、ᶜ=¬）→ 位图表示集合、位运算就是集合运算
2. **关系是 (a,b) 有序对的集合**；图 = 关系的可视化，数据库表 = 关系
3. **等价关系（自反对称传递）划分等价类**：同余类、并查集、连通分量
4. **偏序 = 依赖/层次**（⊆、整除、任务图）；拓扑排序把偏序拉直成全序
5. **关系合成 = SQL 的 JOIN**；选择/投影 = WHERE/SELECT——关系代数就是 SQL 的底层
6. **函数三态**：单射/满射/双射；只有双射可逆；鸽巢原理来自单射的计数约束
7. **可数 vs 不可数**：程序可数、实数不可数——这是"计算有边界"的第一层直觉
