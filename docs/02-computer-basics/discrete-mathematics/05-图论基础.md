# 图论基础

图 = 顶点 + 边。依赖关系、网络、状态机、社交关系都能建模成图——它是"关系"最直观的形式。

## 1. 图的基本概念

| 概念 | 说明 |
|------|------|
| 顶点（vertex） | 对象；n = \|V\| |
| 边（edge） | 对象间的联系；m = \|E\| |
| 无向图 / 有向图 | 边有没有方向（`(u,v)` 还是 `u→v`） |
| 带权图 | 边上带数值（距离/代价） |
| 简单图 | 无自环、无重边（默认讨论的都是简单图） |
| 度 deg(v) | 与该顶点相连的边数；有向图分**入度/出度** |
| 邻接 | 两个顶点间有边 |
| 子图 / 导出子图 | 顶点子集 + 边子集 |

**握手定理**：Σ deg(v) = 2m（每条边贡献 2 个度）。

**推论**：**奇度顶点的个数必为偶数**（对"证明某个图不存在"很有用）。

## 2. 图的表示

| 表示 | 空间 | 查边 | 遍历邻居 | 适用 |
|------|:---:|:---:|:---:|------|
| **邻接矩阵** | O(n²) | O(1) | O(n) | 稠密图、要频繁查两点是否相邻 |
| **邻接表** | O(n+m) | O(deg) | O(deg) | **稀疏图（绝大多数情况）** |
| 边列表 | O(m) | — | — | Kruskal、简并处理 |

```cpp
// 邻接表（最常用）
std::vector<std::vector<int>> adj(n);
adj[u].push_back(v);   // 无向图两边都加
adj[v].push_back(u);

// 带权：每个邻居存 (v, w)
std::vector<std::vector<std::pair<int,int>>> wadj(n);
wadj[u].emplace_back(v, w);
```

## 3. 路径、回路与连通性

| 概念 | 说明 |
|------|------|
| 路径（path） | 顶点不重复的走法 |
| 回路（cycle） | 起点 = 终点的路径（长度 ≥ 3，简单图） |
| 连通 | 任意两点间有路径；否则分成**连通分量** |
| 割点 / 桥 | 删掉它（们）会让连通分量变多 |

**连通性怎么求**：BFS/DFS 遍历（次数 = 连通分量个数）或**并查集**（边逐个 union，最后数集合数）。有向图分**强连通**（互相可达）与**弱连通**（忽略方向后连通）。

## 4. 特殊图

| 图 | 定义 | 用途 |
|----|------|------|
| 完全图 Kₙ | 任意两点都有边 | 最坏情况上界；n(n−1)/2 条边 |
| **树** | 连通、无环 | 层次结构（文件系统、DOM、决策树） |
| **二分图** | 顶点分两组，边只跨组 | 匹配/分配问题、二着色 |
| **DAG** | 有向无环图 | 依赖关系、任务调度、拓扑排序 |
| 平面图 | 可画成边不交叉 | 地图着色（欧拉公式 n−m+f=2） |

## 5. 树（最常用的特殊图）

**树的等价定义**（n 个顶点的图，以下任意一条成立即为树）：

1. 连通且无环
2. 连通且有 n−1 条边
3. 无环且有 n−1 条边
4. 任意两点间**恰好一条**路径

| 概念 | 说明 |
|------|------|
| 森林 | 无环图（每棵连通分量为树）；n − m = 连通分量数 |
| 生成树 | 连通图的子图：覆盖所有顶点、是一棵树 |
| 有根树 | 指定根；术语：父/子/叶/深度/高度 |
| 二叉树 | 每个节点 ≤ 2 个子节点 |

**要点**：

- 树是"最少边的连通图"（n−1 条）；加一条边必产生环，删一条边必不连通
- **生成树**：MST 是"边权和最小的生成树"（见下篇）
- 树没有环 → 遍历时不需要 visited 之外的去重（父节点判断即可）

## 6. 二分图

**定义**：顶点能分成 X、Y 两组，所有边都在 X 与 Y 之间。

**判定（充要条件）**：**不含奇环**（长度是奇数的回路）——用**二着色**（BFS/DFS 给相邻点染不同色）验证：

```text
从任意点染红 → 邻居染蓝 → 邻居的邻居染红 ...
如果遇到"相邻同色" → 有奇环 → 不是二分图
```

**为什么有用**：

- **匹配问题**（相亲/任务分配/选课）：X 和 Y 之间的"配对"
- 二分图的许多问题多项式可解（匹配、最小顶点覆盖），而一般图上是 NP-hard——**"二分"是一个重要的结构条件**

## 7. 图 × 编程

| 场景 | 图的建模 |
|------|---------|
| 依赖关系 | 有向图；**拓扑排序**（编译顺序、包管理、任务调度）；有环 = 循环依赖 |
| 构建系统（make/CMake） | DAG + 拓扑序（文件是顶点、依赖是边） |
| 状态机 | 有向图（状态 = 顶点、转移 = 边） |
| 社交/推荐 | 无向图/带权图（好友关系、二部图"用户-物品"） |
| 网络/路由 | 带权图（最短路 = 路由） |
| 连通性 | 并查集 / BFS（"是否互相可达"） |
| 排课/装箱 | 二分图匹配（老师和课、任务和机器） |

**工程提示**：

- 顶点规模 n ≤ 几百：邻接矩阵随便用；n 大且稀疏：**邻接表 + 1-index 编码**（把字符串 id 映射成 0..n−1 的整数，哈希表或排序 + 二分）
- 递归 DFS 深度可能爆栈（n 大时）→ 用显式栈或 BFS
- 图算法都要防**重边/自环**（输入清洗）

## 8. 要点回顾

1. **握手定理**：Σdeg = 2m → 奇度顶点个数为偶数
2. **表示**：稀疏用**邻接表**（O(n+m)），稠密/常查边用邻接矩阵（O(n²)）
3. **连通性**：BFS/DFS 数分量，或**并查集** union
4. **树**：连通无环 ⇔ 连通 n−1 边 ⇔ 无环 n−1 边 ⇔ 两点间恰好一条路径
5. **二分图**：能二着色 ⇔ **不含奇环**；匹配问题的天然结构
6. **DAG**：依赖/调度的建模；拓扑排序把依赖"排成一条线"
7. 工程上把**字符串 id 映射成整数**，注意稀疏性、递归深度、重边
