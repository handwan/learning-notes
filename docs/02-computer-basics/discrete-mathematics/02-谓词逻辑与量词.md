# 谓词逻辑与量词

命题逻辑只能说"真/假"，说不出"所有""存在"。加上**谓词**和**量词**之后，才能表达数学定理、SQL 查询、程序契约。

## 1. 谓词与量词

**谓词**：带参数的"命题模板"，如 `P(x)` = "x > 3"、`is_even(n)`、`parent(a, b)`。代入具体的 x 才变成命题。

| 量词 | 符号 | 读法 |
|------|:---:|------|
| 全称量词 | ∀x P(x) | 对所有 x，P(x) 成立 |
| 存在量词 | ∃x P(x) | 存在（至少一个）x 使 P(x) 成立 |
| 唯一性量词 | ∃!x P(x) | 恰好存在一个 x |

**论域（domain）必须明确**：

- ∀x∈ℤ, x² ≥ 0 为真；∀x∈ℝ 也对；但 "∀x, x² ≥ 0" 如果论域是复数就不成立
- **空论域**：∀x P(x) 为**真**（"空集里所有元素都满足"不违反任何例子），∃x P(x) 为**假**——编程里对应 `all([]) == True`、`any([]) == False`

**为什么需要它**：命题逻辑表达不了三段论

> 所有人都会死；苏格拉底是人；⇒ 苏格拉底会死
> 用谓词逻辑：∀x (人(x) → 死(x))，人(苏格拉底) ⊢ 死(苏格拉底)

## 2. 量词的否定

**规则：否定往里推、量词翻转、谓词取反**。

| 原式 | 否定 |
|------|------|
| ¬∀x P(x) | **∃x ¬P(x)** |
| ¬∃x P(x) | **∀x ¬P(x)** |
| ¬∀x∃y P(x,y) | ∃x∀y ¬P(x,y) |
| ¬∃x∀y P(x,y) | ∀x∃y ¬P(x,y) |

**自然语言的坑**（同一个意思，说法差很多）：

| 形式 | 等价说法 |
|------|---------|
| ∀x ¬P(x)（所有人都不） | "没人 P" |
| ¬∀x P(x)（并非所有人都 P） | "有人不 P"——**不等于**"所有人都不 P" |
| ∃x ¬P(x)（存在人不 P） | 同上 |
| ¬∃x P(x)（不存在 P 的人） | "所有人都不 P" |

> 例："没有人喜欢被批评" 是 ∀x ¬喜欢(x)，不是 ¬∀x 喜欢(x)（后者只表示"有人不喜欢"）。

## 3. 嵌套量词（顺序有语义）

- 同种量词可以交换：∀x∀y ≡ ∀y∀x；∃x∃y ≡ ∃y∃x
- **不同种量词不能交换**：∀x∃y P(x,y) 与 ∃y∀x P(x,y) 不同，后者更强

```
∃y∀x P(x,y)  ⇒  ∀x∃y P(x,y)        （反方向不成立）
```

**例子**（论域是整数，P(x,y) = "x + y = 0"）：

| 公式 | 含义 | 真值 |
|------|------|:---:|
| ∀x∃y (x+y=0) | 每个数都有相反数（y 可以随 x 变） | **真**（y = -x） |
| ∃y∀x (x+y=0) | 存在一个"万能 y"让所有 x 都满足 | **假**（没有这样的 y） |

**微积分的经典对照**：极限定义 lim f(x) = L

```
∀ε>0, ∃δ>0, ∀x: |x-a|<δ → |f(x)-L|<ε
```

δ **可以依赖 ε**（先给 ε，再找 δ）。如果写成 ∃δ∀ε（同一个 δ 对所有 ε 都行）就强得多、含义完全变了。

## 4. 量词推理规则

| 规则 | 形式 | 用途 |
|------|------|------|
| 全称实例化 | ∀x P(x) ⊢ P(c) | 拿到具体对象 |
| 全称推广 | 对**任意** c 证明 P(c) ⊢ ∀x P(x) | 证明"对所有" |
| 存在实例化 | ∃x P(x) ⊢ P(c)（c 是**新**符号） | 取出那个存在的东西 |
| 存在推广 | P(c) ⊢ ∃x P(x) | 用一个例子证"存在" |

**证明套路**：

- 目标形如 **∀x P(x)**：取"任意但固定"的 x，证 P(x)（"任取 x..."）
- 目标形如 **∃x P(x)**：**构造**一个具体的 x 并验证（构造性证明），或反证（假设 ∀x¬P(x) 矛盾）

**注意**：存在实例化的 c 必须是全新的符号（不能和已有的重名）——否则会推出错误结论。

## 5. 前束范式：把量词提到最前

**定义**：所有量词都在公式最前面，后面是没有量词的"矩阵"。

**转换步骤**：

1. 消去 → 和 ↔（用 p→q ≡ ¬p∨q 等）
2. 否定内推（德摩根 + 量词否定律），直到 ¬ 只贴着谓词
3. 变量改名（不同量词用不同变量名，避免**变量捕获**）
4. 量词逐个外移到最前

**例子**：¬∃x (P(x) ∧ ∀y Q(y)) 的前束范式

```
¬∃x (P(x) ∧ ∀y Q(y))
≡ ∀x ¬(P(x) ∧ ∀y Q(y))          （¬∃ → ∀¬）
≡ ∀x (¬P(x) ∨ ¬∀y Q(y))         （德摩根）
≡ ∀x (¬P(x) ∨ ∃y ¬Q(y))         （¬∀ → ∃¬）
≡ ∀x∃y (¬P(x) ∨ ¬Q(y))          （量词外移）
```

**有什么用**：前束范式再配合 **Skolem 化**（把 ∃ 换成新函数符号）就得到 SAT/SMT 求解器、Prolog、自动定理证明的输入形式。

## 6. 逻辑 × 编程

**① SQL 就是谓词逻辑**（关系数据库 = 谓词逻辑的实现）：

```sql
-- ∃：选了课 101 的学生
SELECT * FROM students s
WHERE EXISTS (SELECT 1 FROM enroll e WHERE e.sid = s.id AND e.cid = 101);

-- ¬∃：一门课都没选的学生（= ∀ 没选）
SELECT * FROM students s
WHERE NOT EXISTS (SELECT 1 FROM enroll e WHERE e.sid = s.id);

-- 经典的"没有哪门课是所有学生都选了"：
-- ¬∃c ∀s 选了(s, c)  ≡  ∀c ∃s ¬选了(s, c)
SELECT * FROM courses c
WHERE EXISTS (SELECT 1 FROM students s
              WHERE NOT EXISTS (SELECT 1 FROM enroll e
                                WHERE e.sid = s.id AND e.cid = c.id));
```

（"双重 NOT EXISTS"就是 ∀ 的实现——SQL 里没有 FORALL。）

**② 契约与断言**：函数的前置/后置条件本质是量词命题

```cpp
// 前置：∀ 合法的输入 —— "任何 n >= 0"
// 后置：∀ 返回值满足的关系 —— "结果 r 满足 r*r <= n < (r+1)*(r+1)"
int isqrt(int n);   // 注释里的"对所有"就是 ∀
```

- 断言 `assert` 就是"运行期检查一个谓词"
- 类型系统 ≈ 一种可判定的逻辑：泛型是 ∀ 类型、`trait object`/存在类型是 ∃ 类型

**③ 自动化推理**：

| 工具 | 处理 | 例子 |
|------|------|------|
| **SAT** | 命题逻辑（布尔可满足性） | CNF 输入；硬件验证、规划 |
| **SMT** | 谓词逻辑 + 算术/数组/字符串等理论 | **Z3**、CVC5；符号执行、程序验证 |
| 交互式证明 | 人给证明，机器检查 | Coq、Lean |

实用场景：用 Z3 检查"分支覆盖有没有漏"、约束求解（调度/配置）、静态分析器内部也在用（对接编译原理）。

**④ 与测试的关系**：测试是"采样验证"（∃ 一组输入通过了），形式化验证是"∀ 证明"——工程上按风险取舍（核心算法形式化、业务代码靠测试）。

## 7. 要点回顾

1. **谓词 + 量词**才够表达数学/查询/契约；论域必须明确
2. **空论域**：∀ 为真、∃ 为假（`all([]) == True`、`any([]) == False`）
3. **量词否定**：否定内推、量词翻转（¬∀ → ∃¬、¬∃ → ∀¬）；"并非所有人都" ≠ "所有人都不"
4. **嵌套顺序有语义**：∀∃ 弱、∃∀ 强（∀ε∃δ vs ∃δ∀ε）；∃ 的实例化要用新符号
5. **前束范式**：消蕴含 → 否定内推 → 改名 → 量词外移；再 Skolem 化就是求解器输入
6. **SQL = 谓词逻辑**：`EXISTS` 是 ∃、双重 `NOT EXISTS` 是 ∀
7. **验证的谱系**：测试（采样）< SMT 求解（有界/理论受限）< 交互式证明（∀，但要人写证明）
