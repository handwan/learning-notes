# 图论定理与算法

遍历、拓扑排序、最短路、最小生成树、欧拉/哈密顿、匹配与网络流——图上的"工具箱"，以及哪些问题根本解不动。

## 1. 遍历：BFS 与 DFS

| | BFS（队列） | DFS（栈/递归） |
|--|------------|---------------|
| 顺序 | 层层扩散 | 一条路走到黑再回退 |
| 最短路 | **无权图的最短路**（按边数） | 不保证 |
| 用途 | 连通分量、层次、二分图判定、无权最短路 | 连通性、找环、拓扑排序、割点/桥、回溯 |
| 复杂度 | O(n + m) | O(n + m) |

**BFS 求无权最短路**：从源点开始层层扩展，第一次到达某点的层数就是最短边数。

**DFS 的性质**（有向图）：

- 边的分类：树边（走过去）、**回边**（指向祖先 → **有环**）、前向边/横向边
- **有向图有环 ⇔ DFS 出现回边**（判环）
- 无向图 DFS 遇到"已访问且不是父节点"的边 → 有环

## 2. 拓扑排序（DAG 上的线性化）

**目标**：把有向无环图排成一条线，使每条边 u→v 中 u 都在 v 前面。

**Kahn 算法（入度法）**：

```text
1. 统计所有点的入度
2. 入度为 0 的点入队
3. 出队一个点 u，输出；把 u 的所有邻居入度 -1
4. 邻居入度变 0 → 入队
5. 重复到队空；若输出点数 < n → 有环（不是 DAG）
```

**DFS 法**：DFS 后序的**逆序**就是拓扑序（有回边则说明有环）。

**应用**：构建顺序（make/CMake 依赖图）、包管理（npm/apt 依赖）、任务调度、课程安排、循环依赖检测。**一个 DAG 可能有多个合法拓扑序**。

## 3. 最短路

| 算法 | 适用 | 复杂度 | 要点 |
|------|------|:---:|------|
| **BFS** | 无权图 | O(n+m) | 按层数 |
| **Dijkstra** | **非负权**（单源） | O((n+m) log n) | 贪心：每次选"当前最近"的点确定下来 |
| **Bellman-Ford** | 可有负权（单源） | O(n·m) | 松弛 n−1 轮；**第 n 轮还能松弛 = 有负环** |
| **Floyd-Warshall** | 全源，可有负权 | O(n³) | DP：允许经过前 k 个点时的最短路 |

**Dijkstra 的贪心为什么对**：边权非负时，"当前距离最小的未确定点"的距离不可能再被别的路径改小（换条路只会更长）——所以可以定死。**有负权边时这个前提崩掉**，必须用 Bellman-Ford。

**Floyd 的 DP 直觉**：

```
dp[i][j] = 从 i 到 j 的最短路
初始：直连边的权（无边 = ∞，自己 = 0）
依次"允许经过点 k"来更新：dp[i][j] = min(dp[i][j], dp[i][k] + dp[k][j])
```

**传递闭包（可达性）**：把 Floyd 的运算从"min / +"换成"或 / 与"（布尔矩阵运算），得到的就是"任意两点是否可达"——这就是关系的**传递闭包**（Warshall 算法）。可用于：依赖关系的传递闭包、图的可达性判定、编译里的调用图分析。

**伪代码（Dijkstra，优先队列）**：

```cpp
dist[s] = 0;  pq.push({0, s});
while (!pq.empty()) {
    auto [d, u] = pq.top(); pq.pop();
    if (d > dist[u]) continue;              // 过期条目，跳过
    for (auto [v, w] : adj[u])              // 松弛
        if (dist[u] + w < dist[v]) { dist[v] = dist[u] + w; pq.push({dist[v], v}); }
}
```

## 4. 最小生成树（MST）

**定义**：连通带权图的生成树中，边权和最小的那棵。

| 算法 | 思路 | 复杂度 | 适合 |
|------|------|:---:|------|
| **Kruskal** | 边按权排序，逐条加（**不成环就加**），用并查集判环 | O(m log m) | 稀疏图 |
| **Prim** | 从一个点开始，每次加"连接已选集合与外界的最小边" | O((n+m) log n) | 稠密图 |

**为什么贪心是对的（切割性质）**：把顶点分成任意两部分，**跨切的最轻边一定属于某棵 MST**——Kruskal/Prim 每一步都在选"当前安全边"。

**注意**：MST 是"连通所有点的最省方案"，和"两点间最短路"是**不同的问题**（最短路径树 ≠ 最小生成树）。

**应用**：网络布线、道路修建、聚类（切掉 MST 中最长的边 → 连通分量就是簇）。

## 5. 欧拉与哈密顿

**欧拉路径/回路**：走遍**每条边恰好一次**。

| 条件 | 结论 |
|------|------|
| 连通 + 所有顶点度数为**偶** | **欧拉回路**存在（回到起点） |
| 连通 + 恰好 **2 个奇度**顶点 | **欧拉路径**存在（从奇度点出发、另一个奇度点结束） |
| 否则 | 不存在 |

（"连通"指忽略孤立点后；有向图的度条件改成"入度 = 出度"或"起点出度比入度大 1、终点反之"。）

**Hierholzer 算法**：DFS 走到底、走不动就回溯，把边倒序收集即可得到欧拉路径——复杂度 O(m)。

**哈密顿路径/回路**：走遍**每个顶点**恰好一次——**这是个 NP 完全问题**（判存在都难），欧拉问题的"兄弟"却有多项式算法。这个对比很典型：**问题描述改一个字，难度可能天差地别**。

## 6. 匹配与网络流

**匹配**：一组**不相邻**的边（点不重复配对）。**最大匹配**：边数最多的匹配。**完美匹配**：所有点都被匹配。

| 图 | 最大匹配 |
|----|---------|
| 二分图 | **匈牙利算法**（找增广路）：O(n·m) |
| 一般图 | 带花树算法（复杂）；很多场景归约成网络流 |

**匈牙利算法的直觉**：不断找"增广路"——一条从一个未匹配点出发、交替经过非匹配边/匹配边、到达另一个未匹配点的路径；找到就**翻转匹配状态**（匹配数 +1）。找不到增广路 ⇒ 已是最大匹配（Berge 定理）。

**Hall 定理（婚配定理）**：二分图（左 X、右 Y）存在**覆盖 X 全部点**的匹配 ⇔ 对 X 的**任意**子集 S，都有 `|N(S)| ≥ |S|`（N(S) 是 S 的邻居集合）。

直观：**任意 k 个左点至少要能碰到 k 个不同的右点**，否则必然有人配不上。它给出"完美匹配存在"的判定条件，也是匹配类算法正确性的理论基础（判定本身只需检查所有子集——子集很多，实践上直接用算法求）。

**网络流**：每条边有容量，从源点 s 到汇点 t 的最大流量。

- **Ford-Fulkerson**：每次找一条"还能推流"的路径（**残量网络**）推流，直到没有增广路
- **Edmonds-Karp**：FF 的 BFS 版，O(n·m²)
- **最大流最小割定理**：**最大流 = 最小割**（割 = 把 s 和 t 分开的边集，容量和的最小值）——同一个数的两种看法

**应用**：

- 匹配问题 → 建网络流模型（源 → 左点 → 右点 → 汇）
- **最小割**：图像分割、最小代价"切断联系"、任务分配
- 项目选择（最大权闭合子图）等组合优化

## 7. 哪些图问题解不动

| 问题 | 难度 |
|------|:---:|
| 最短路、MST、拓扑排序、欧拉路径、二分图匹配、最大流 | **P（多项式可解）** |
| 哈密顿回路、TSP（旅行商）、最大团、图着色（k≥3）、一般图最大独立集 | **NP-hard** |

**工程上遇到 NP-hard 怎么办**：

- **小规模**：暴力/回溯 + 剪枝（n ≤ 20 用状压 DP）
- **规模大**：**近似算法**（**度量 TSP** 有 2-近似（走 MST 双遍）；一般 TSP 没有常数因子近似）、启发式（爬山/模拟退火）、整数规划求解器（Gurobi/OR-Tools）、SMT
- **结构特化**：如果图是二分/平面/树，很多难题变简单——**先看结构再选算法**

## 8. 要点回顾

1. **BFS**：无权最短路、层次；**DFS**：判环（有向图的回边）、拓扑排序、割点
2. **拓扑排序**：Kahn（入度归零入队）；输出数 < n ⇒ 有环
3. **最短路**：Dijkstra（非负、贪心+堆）；Bellman-Ford（负权、判负环）；Floyd（全源 O(n³)）
4. **MST**：Kruskal（排序+并查集）／Prim（堆）；依据是**切割性质**；和"最短路"是两回事
5. **欧拉**有多项式算法（度数条件），**哈密顿**是 NP 完全——差一个词，难度差一个量级
6. **匹配**：二分图用增广路（匈牙利）；**最大流 = 最小割**，能建模分配/切割类问题
7. **NP-hard 的应对**：小规模搜索、近似/启发式、求解器，或利用图的结构特化
