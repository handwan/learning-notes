# 线性结构

数组、链表、栈、队列、双端队列、环形缓冲——**"线性"是数据排成一条线**；选型的关键是**内存布局**（实测能差几倍到几百倍）。

> 所有实现都是**手写的**（无标准库容器）。

## 1. 数组与动态数组

**数组**：一块**连续**内存，下标访问 O(1)、遍历对缓存友好；缺点是**大小固定**、中间插入/删除 O(n)。

**动态数组**要解决"自动扩容"：

```
关键字段：data 指针 + size（用了多少）+ capacity（能装多少）
插入时 size == capacity → 扩容：申请 2 倍新块 → 拷贝旧元素 → 释放旧块
删除不缩容（缩容会导致"反复扩缩"抖动）
```

**完整实现**：

```cpp
struct SeqList {
    int* data;              // 数据区
    int size, cap;          // 当前长度、容量
    explicit SeqList(int cap_ = 8) : data(new int[cap_]), size(0), cap(cap_) {}
    ~SeqList() { delete[] data; }

    void reserve(int need) {                 // 扩容（翻倍）
        if (need <= cap) return;
        int nc = cap * 2; while (nc < need) nc *= 2;
        int* nd = new int[nc];
        for (int i = 0; i < size; ++i) nd[i] = data[i];
        delete[] data; data = nd; cap = nc;
    }
    void push(int v) { reserve(size + 1); data[size++] = v; }        // 尾插：均摊 O(1)
    bool insert(int pos, int v) {                                    // 位置插入：O(n)
        if (pos < 0 || pos > size) return false;
        reserve(size + 1);
        for (int i = size; i > pos; --i) data[i] = data[i - 1];
        data[pos] = v; ++size; return true;
    }
    bool erase(int pos) {                                            // 位置删除：O(n)
        if (pos < 0 || pos >= size) return false;
        for (int i = pos; i < size - 1; ++i) data[i] = data[i + 1];
        --size; return true;
    }
};
// 实测：SeqList L(2) 尾插 0..4（容量 2→8）+ 位置插入/删除均正确
```

**头插是数组的死穴**（每次要搬全部元素）：

```
在 100 万元素的数组上做 1 万次头插：每次 memmove 约 100 万个 int
同样 30 万次头插，单链表只是接两个指针（下一节的实现）
```

要头部 O(1) 就得换结构：**链表**（指针接上就行）或**环形缓冲/双端队列**（预留两头空间）。

## 2. 实测：连续的威力（缓存局部性）

遍历 200 万个 int（求和）：

| 结构 | 耗时 |
|------|:---:|
| 手写动态数组（连续） | 基准 |
| 手写单链表（节点分散） | **慢 7 倍** |

为什么：CPU 拿内存是**按 cache line（64 字节）**拿的——数组一次搬 16 个 int，链表每跳一个节点都可能**换 cache line + 随机访存**，预取器也帮不上忙。

**结论**：理论复杂度一样（都是 O(n)），实际差几倍——这就是"数组几乎总是优于链表"的原因。

## 3. 链表

| 形态 | 特点 |
|------|------|
| 单链表 | 每节点一个 next 指针 |
| 双链表 | 前后都能走；每节点两个指针 |
| 循环链表 | 尾接回头（环形调度、轮询） |

**链表的真正优势**：**已有节点指针时**插入/删除 O(1)（不用搬别人）；但代价是：

- 每元素多 8~16 字节指针
- 遍历慢（上面实测 7 倍）
- 每个节点一次分配（分配器开销 + 碎片）
- 只能顺序访问，不支持下标的 O(1)

**手写实现**（单链表头插 + 删除）：

```cpp
struct LNode {
    int val;
    LNode* next;
    LNode(int v, LNode* n = nullptr) : val(v), next(n) {}   // 构造即初始化
};
void list_push_front(LNode*& head, int v) { head = new LNode(v, head); }   // 头插 O(1)
bool list_delete(LNode*& head, int v) {                     // 删"第一个值为 v"的节点
    LNode** cur = &head;                                    // 指向指针的指针：省前驱特判
    while (*cur && (*cur)->val != v) cur = &(*cur)->next;
    if (!*cur) return false;                                // 没找到
    LNode* dead = *cur;
    *cur = dead->next;                                      // 上一个节点的 next 直接跨过去
    delete dead;
    return true;
}
```

**"指向指针的指针"技巧**：删除头节点和其他节点是同一套代码（不用特判 `if (head->v == v)`）。

### 哑结点（dummy）：另一种"省头部特判"

一个**不存数据的假头节点**，让"结果链的头会变"的操作不用写 if（力扣链表题的通用套路）：

```cpp
LNode dummy(0);
LNode* tail = &dummy;      // dummy 本身不进入结果链
// …在 tail 后面接节点…
return dummy.next;         // dummy 是栈对象：函数返回自动销毁，结果链不受影响
```

**别用 `new` 建 dummy**（常见手滑）：dummy 只在本函数内用，栈对象完全够——栈版本**别 `return &dummy`**（返回即悬垂）；`new` 出来没人 `delete` 就是泄漏（ASan 实测 16 字节）。

```cpp
LNode* dummy = new LNode(0, head);   // 堆上：谁 new 谁 delete，忘了就泄漏
```

真需要 dummy 活过函数（罕见），用 `unique_ptr` 托管，自动 delete：

```cpp
auto dummy = std::make_unique<LNode>(0, head);
LNode* prev = dummy.get();           // 拿裸指针用
```

最常用的两个场景：

```cpp
// ① 合并两条有序链：不用判断"结果链的第一个节点是谁"
LNode* merge_sorted(LNode* a, LNode* b) {
    LNode dummy(0);
    LNode* tail = &dummy;
    while (a && b) {
        if (a->val <= b->val) { tail->next = a; a = a->next; }
        else                  { tail->next = b; b = b->next; }
        tail = tail->next;
    }
    tail->next = a ? a : b;          // 剩下那一段整段接上
    return dummy.next;
}

// ② 删除（头节点可能被删）：不用把 head 单独特判
bool list_delete_dummy(LNode*& head, int v) {
    LNode dummy(0); dummy.next = head;
    LNode* prev = &dummy;
    while (prev->next && prev->next->val != v) prev = prev->next;
    if (!prev->next) return false;   // 没找到
    LNode* dead = prev->next;
    prev->next = dead->next;
    delete dead;
    head = dummy.next;               // 头可能变了 → 回写
    return true;
}
```

（实测：合并 `{1,2,4}+{1,3,4}` → `1 1 2 3 4 4`；删除头/中间/不存在的返回值 → 1 1 0）

**和上面"指向指针的指针"技巧的分工**：两者都解决"头要变"——`LNode**` 不用额外节点（更省）；dummy 更好读，在链表算法（合并、分组反转）里更通用。

**常见误区**："链表插入删除快，所以能替代数组"——**找位置本身就要 O(n)**（遍历过去），只有"手里已有指针"（如 LRU、侵入式链表、算法内部）才体现优势。

## 4. 栈与队列

**栈（LIFO）/队列（FIFO）** 是"受限的线性结构"——限制反而让实现简单、语义清晰：

| 用途 | 结构 |
|------|------|
| 函数调用栈、DFS、撤销、括号匹配 | 栈（动态数组，尾巴进出） |
| BFS、任务调度、消息缓冲 | 队列（环形缓冲，头出尾进） |
| 滑动窗口、单调队列（见工程结构篇） | 双端队列 |

**为什么栈用数组**：栈只在**一端**进出 → 连续的尾插尾删最赚（均摊 O(1)，还吃缓存）。

**为什么队列别用数组**：出队在头部 → 数组要整体前移（O(n)）——所以队列用**环形缓冲**（下一节六）。

### 应用：表达式求值（中缀 → 后缀 → 求值）

**栈的经典应用**：计算机不算"1+2*3"这种中缀式，而是两步走——

```
① 中缀 → 后缀（逆波兰式）：数字直接输出；运算符与栈顶比优先级，低/等就弹出再入栈；括号特殊处理
   1+2*3      → 1 2 3 * +
   (1+2)*3    → 1 2 + 3 *
② 后缀求值：遇到数字入栈；遇到运算符弹出两个算完再入栈，最后栈里就是结果
```

```cpp
static int prec(char op) { return (op == '+' || op == '-') ? 1 : (op == '*' || op == '/') ? 2 : 0; }

void infix_to_postfix(const char* s, char* out) {      // 中缀 → 后缀（多位数 + 括号）
    char ops[128]; int sp = 0, on = 0;
    for (int i = 0; s[i]; ) {
        char c = s[i];
        if (c >= '0' && c <= '9') {                    // 数字（可能多位）直接输出
            while (s[i] >= '0' && s[i] <= '9') out[on++] = s[i++];
            out[on++] = ' '; continue;
        }
        if (c == '(') ops[sp++] = c;
        else if (c == ')') { while (sp && ops[sp - 1] != '(') { out[on++] = ops[--sp]; out[on++] = ' '; } --sp; }
        else {                                          // 运算符：把优先级 >= 自己的先弹出
            while (sp && prec(ops[sp - 1]) >= prec(c)) { out[on++] = ops[--sp]; out[on++] = ' '; }
            ops[sp++] = c;
        }
        ++i;
    }
    while (sp) { out[on++] = ops[--sp]; out[on++] = ' '; }
    out[on] = 0;
}
long long eval_postfix(const char* s) {                 // 后缀求值（栈）
    long long st[128]; int sp = 0;
    for (int i = 0; s[i]; ) {
        if (s[i] == ' ') { ++i; continue; }
        if (s[i] >= '0' && s[i] <= '9') {
            long long v = 0; while (s[i] >= '0' && s[i] <= '9') v = v * 10 + (s[i++] - '0');
            st[sp++] = v; continue;
        }
        long long b = st[--sp], a = st[--sp];
        switch (s[i++]) { case '+': st[sp++] = a + b; break; case '-': st[sp++] = a - b; break;
                          case '*': st[sp++] = a * b; break; case '/': st[sp++] = a / b; break; }
    }
    return st[0];
}
// 实测：1+2*3=7、(1+2)*3=9、10+20*30=610、100/5-3*4=8、2*(3+4*(5-1))=38、8/2/2=2（6 个全对）
```

**两个栈**也可以一遍扫描直接求值（数字栈 + 运算符栈交替处理），但"先转后缀再求值"更清晰、也是编译器的标准做法（后缀式 = 表达式的"后序遍历"）。

## 5. 双端队列：分段连续

要"头尾都 O(1) + 还能随机访问"，纯连续数组做不到 → **分段连续**：

```
map（中控数组）：[块0][块1][块2]...
                 ↓
        块：| 元素 | 元素 | ... | （固定大小，例如 512 字节）
```

- 头尾插入 O(1)（在两端块里放；块用完就加一块）
- 随机访问 O(1)（先算出第几块、再算块内偏移）
- 中间插入 O(n)（要搬元素）
- 代价：内存不如连续数组紧凑；它的"迭代器"要跨块寻址，比纯指针重

**选型**：默认用动态数组；头尾都要频繁操作才用分段双端队列。

## 6. 环形缓冲（Ring Buffer）

**固定容量、覆盖最旧数据、零分配**——流式场景的标配（日志、音视频帧、串口、KV cache 淘汰）：

```
             head(读)
               ↓
        ┌───┬───┬───┬───┬───┐
        │ 7 │   │   │ 4 │ 5 │     tail(写) → 下一个写这里
        └───┴───┴───┴───┴───┘
        容量固定；写满后继续写 → 覆盖最旧
```

要点：

- `head/tail` 用"自增 + 取模"（容量取 2 的幂时 `& (cap-1)` 更快）
- 满/空判断：留一格不用，或**额外计数**（下面的实现用计数，容量精确）
- 无锁版：单生产者单消费者只需原子 head/tail（并发篇有讲）

**手写实现**（额外计数版）：

```cpp
struct Ring {
    int* buf; int cap, head, count;
    explicit Ring(int cap_) : buf(new int[cap_]), cap(cap_), head(0), count(0) {}
    ~Ring() { delete[] buf; }

    void push(int v) {                       // 满了覆盖最旧
        if (count == cap) { buf[head] = v; head = (head + 1) % cap; }
        else { buf[(head + count) % cap] = v; ++count; }
    }
    bool pop(int& out) {                     // 空返回 false
        if (!count) return false;
        out = buf[head]; head = (head + 1) % cap; --count;
        return true;
    }
};
// 实测：Ring r(5)，写 1..7 → 1、2 被覆盖，依次读出 3 4 5
```

## 7. 结构选型

| 需求 | 用 | 备注 |
|------|-----|------|
| 随机访问、遍历、尾部增删 | 动态数组 | 默认首选 |
| 头尾都要 O(1) | 分段双端队列 | 中间插入仍是 O(n) |
| 频繁在"已知位置"增删 | 双链表 | 遍历慢 7 倍，慎用 |
| 受限的 LIFO | 栈（动态数组） | 尾插尾删最快 |
| 受限的 FIFO / 流式缓冲 | 环形缓冲 | 固定容量、零分配 |
| 需要"两头都能进出"的窗口 | 双端队列 / 环形双端 | 滑动窗口、单调队列 |

## 8. 要点回顾

1. **连续内存是最大的性能武器**：手写数组遍历比手写链表快 **7 倍**（cache line + 预取器）
2. **动态数组**：size/capacity 分离、扩容翻倍（均摊 O(1)）、缩容不自动做
3. **链表的优势只有一个**：**已有位置指针时**的 O(1) 增删；"找位置"仍是 O(n)，还搭上指针空间和缓存不友好
4. **头插是数组的死穴**：每次都要搬整个数组；链表头插只是接指针——量级差距
5. **栈用数组**（单端进出）、**队列/流式缓冲用环形缓冲**（固定容量、覆盖最旧、零分配）
6. **双端队列 = 分段连续**：头尾 O(1) + 随机访问 O(1)，代价是内存和"迭代器"更复杂
7. **默认选择**：动态数组 → 环形缓冲（FIFO）→ 链表（很少）
