# 工程常用结构

课堂外、但工程里天天用的五个结构：**并查集、布隆过滤器、LRU、跳表、单调栈/队列**。

> 耗时只给量级与比率（精确值机器相关）。

## 1. 并查集（Union-Find / DSU）

**问题**：一堆元素不断"合并成组"，随时问"这两个是不是同一组？"

- 典型场景：**连通性判断**、Kruskal 最小生成树、社交圈子、图片连通区域
- 结构：每个元素存一个 `parent` 指针，根代表组；`find` 找根、`union` 把两个根连起来

**两个优化**（缺一不可）：

| 优化 | 做法 | 效果 |
|------|------|------|
| 路径压缩 | find 时把路径上的点直接接到根 | 树变矮 |
| 按秩/按大小合并 | 小树的根接到大树上 | 树不涨高 |

**实测**：最坏链式结构（20 万结点）下，两个优化一起用比"朴素随便接"**快约 500 倍**。

理论：两个优化一起用，均摊复杂度 O(α(n))（反阿克曼函数，实际 ≤ 4）——**近似 O(1)**。

```cpp
struct DSU {
    int *p, *rank, n;
    explicit DSU(int n_) : p(new int[n_]), rank(new int[n_]()), n(n_) {
        for (int i = 0; i < n; ++i) p[i] = i;
    }
    ~DSU() { delete[] p; delete[] rank; }
    int find(int x) { while (p[x] != x) { p[x] = p[p[x]]; x = p[x]; } return x; }  // 路径减半
    void unite(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return;
        if (rank[a] < rank[b]) { int t = a; a = b; b = t; }     // 按秩合并
        p[b] = a; if (rank[a] == rank[b]) ++rank[a];
    }
};
```


## 2. 布隆过滤器（Bloom Filter）

**问题**：判断"这个 key 在不在集合里"，但**允许极小的误判**（说"在"可能错，说"不在"一定对）。

**原理**：一个位数组 + k 个哈希函数——插入把 k 个位置 1，查询看 k 位**是否全 1**：

```
插入 "cat"：h1,h2,h3 → 置位 3 个
查询 "dog"：只要有一位是 0 → 100% 不在
            全 1 → "可能存在"（可能是别人的位凑出来的）
```

**手写实现**（`uint64_t` 位数组 + 双重哈希造 k 个位置）：

```cpp
struct Bloom {
    static constexpr int M = 1 << 20;      // 1048576 位 = 128 KB
    static constexpr int K = 7;
    uint64_t bits[M / 64] = {};

    static uint32_t h1(uint32_t x) { x *= 2654435761u; return x ^ (x >> 16); }
    static uint32_t h2(uint32_t x) { x *= 0x85ebca6bu; return x ^ (x >> 13); }

    void add(uint32_t x) {
        uint32_t a = h1(x), b = h2(x) | 1;          // 步长取奇数
        for (int i = 0; i < K; ++i) {
            uint32_t h = (a + i * b) % M;           // 双重哈希造 k 个位置
            bits[h >> 6] |= 1ull << (h & 63);
        }
    }
    bool maybe(uint32_t x) const {
        uint32_t a = h1(x), b = h2(x) | 1;
        for (int i = 0; i < K; ++i) {
            uint32_t h = (a + i * b) % M;
            if (!(bits[h >> 6] >> (h & 63) & 1)) return false;   // 一位是 0 → 一定不在
        }
        return true;                                 // 全 1 → 可能存在
    }
};
```

**实测（n = 10 万，m = 1048576 bit，k = 7）**：

| 指标 | 数值 |
|------|------|
| 占用 | **128 KB**（10 万条） |
| 实测误判率 | **0.64%**（理论 ~0.8%） |
| 假阴性 | **0**（已插入的 10 万 key 复查全过） |

**工程用法**（典型是"挡在数据库前面"）：

```
查缓存 → 布隆说"不在" → 直接返回（挡掉穿透请求，不用查库）
                  → 说"可能在" → 老老实实查库
```

**注意**：标准布隆**不支持删除**（删了会影响别人）——要删除用计数布隆或布谷鸟过滤器。

## 3. LRU 缓存（哈希 + 双向链表）

**问题**：容量有限，淘汰"最久未使用"的。

**组合结构**：**哈希表**（key → 节点指针）+ **双向链表**（头部最新、尾部最旧）：

| 操作 | 做法 | 复杂度 |
|------|------|:---:|
| get | 查哈希 → 把节点摘链再头插 | O(1) |
| put | 已有则更新并移头；没有则插入头部；超容量淘汰尾部 | O(1) |

**为什么是双向链表**：删除/移动任意节点要拿它的**前驱**——单链表只有 next，做不到 O(1)

**手写实现**（链式哈希索引 + 双向链表）：

```cpp
/* 双向链表（头最新、尾最旧）+ 链式哈希索引（key → 节点指针） */
struct LRUNode {
    int key, val; LRUNode *prev, *next;
    LRUNode(int k, int v) : key(k), val(v), prev(nullptr), next(nullptr) {}
};
struct LRU {
    LRUNode *head = nullptr, *tail = nullptr;
    struct Entry {
        int key; LRUNode* node; Entry* next;
        Entry(int k, LRUNode* n, Entry* nx) : key(k), node(n), next(nx) {}
    };
    static constexpr int NB = 256;
    Entry** buckets; int cap, n = 0;
    explicit LRU(int c) : buckets(new Entry*[NB]()), cap(c) {}
    ~LRU() {
        for (int i = 0; i < NB; ++i) { Entry* e = buckets[i];
            while (e) { Entry* nx = e->next; delete e; e = nx; } }
        delete[] buckets;
    }
    static unsigned hash(int k) { return (unsigned)k * 2654435761u; }

    LRUNode* idx_get(int k) { for (Entry* e = buckets[hash(k) % NB]; e; e = e->next) if (e->key == k) return e->node; return nullptr; }
    void idx_put(int k, LRUNode* x) { buckets[hash(k) % NB] = new Entry(k, x, buckets[hash(k) % NB]); }
    void idx_del(int k) {
        Entry** c = &buckets[hash(k) % NB];
        while (*c && (*c)->key != k) c = &(*c)->next;
        if (*c) { Entry* d = *c; *c = d->next; delete d; }
    }
    void unlink(LRUNode* x) {
        if (x->prev) x->prev->next = x->next; else head = x->next;
        if (x->next) x->next->prev = x->prev; else tail = x->prev;
    }
    void push_front(LRUNode* x) {
        x->prev = nullptr; x->next = head;
        if (head) head->prev = x; head = x;
        if (!tail) tail = x;
    }
    int get(int k) {                                  // 命中：摘链再头插
        LRUNode* x = idx_get(k); if (!x) return -1;
        unlink(x); push_front(x); return x->val;
    }
    void put(int k, int v) {
        if (LRUNode* x = idx_get(k)) { x->val = v; unlink(x); push_front(x); return; }
        if (n == cap) { idx_del(tail->key); LRUNode* old = tail; unlink(old); delete old; --n; }  // 淘汰最旧
        LRUNode* x = new LRUNode(k, v); push_front(x); idx_put(k, x); ++n;
    }
};
```


## 4. 跳表（Skip List）

**问题**：想要平衡树的 O(log n)，但不想写旋转——**用多层链表随机化**：

```
level 3: 1 ──────────────→ 9
level 2: 1 ──────→ 5 ────→ 9
level 1: 1 → 3 → 5 → 7 → 9     ← 底层是全量有序链表
```

- 每个节点随机决定"盖几层"（p = 0.5 掷硬币）→ **期望** O(log n)
- 查找：从最高层一路"向右走不动就下潜"
- 范围查询：底层链表顺序扫（比平衡树友好）

**手写实现**（固定最大层数 + 随机层数 + 逐层右移）：

```cpp
struct SkipList {
    static constexpr int MAXL = 18;                 // 2^18 > 20 万
    struct Node {
        int val;
        Node* next[MAXL];
        explicit Node(int v) : val(v) {
            for (int i = 0; i < MAXL; ++i) next[i] = nullptr;
        }
    };
    Node* head = new Node(-1);
    uint32_t seed = 12345;

    int level() {                                   // p = 0.5 掷硬币
        int l = 1;
        while (l < MAXL && ((seed = seed * 48271u % 2147483647u) & 1u)) ++l;
        return l;
    }
    void insert(int v) {
        Node* prev[MAXL];
        Node* cur = head;
        for (int l = MAXL - 1; l >= 0; --l) {       // 先找每层的前驱
            while (cur->next[l] && cur->next[l]->val < v) cur = cur->next[l];
            prev[l] = cur;
        }
        int lv = level();
        Node* n = new Node(v);
        for (int l = 0; l < lv; ++l) {              // 在 lv 层内接上
            n->next[l] = prev[l]->next[l];
            prev[l]->next[l] = n;
        }
    }
    bool find(int v) const {
        const Node* cur = head;
        for (int l = MAXL - 1; l >= 0; --l)
            while (cur->next[l] && cur->next[l]->val < v) cur = cur->next[l];
        cur = cur->next[0];
        return cur && cur->val == v;
    }
    ~SkipList() {
        for (Node* p = head; p;) {
            Node* next = p->next[0];
            delete p;
            p = next;
        }
    }
};
```

**实测结论**：**插入与 AVL 同量级，查找慢约一个数量级**（跳表每层都要追指针）——它的价值不在原始速度，而在**实现简单、范围查询自然、并发友好**：

- 代码比红黑树**简单得多**（没有旋转/颜色）
- **范围查询/区间扫描**自然（底层链表）
- **并发友好**：加锁只需局部（Redis 的 zset 就是跳表）

## 5. 单调栈 / 单调队列

**单调栈**：栈里保持单调，新元素来了把"破坏单调"的弹掉——**每个元素只进栈出栈一次 → O(n)**。

**经典题：下一个更大元素**：

```cpp
std::vector<int> nextGreater(const std::vector<int>& a) {
    std::vector<int> res(a.size(), -1);
    std::vector<int> st;                        // 存下标，栈内对应值单调递减
    for (int i = 0; i < static_cast<int>(a.size()); ++i) {
        while (!st.empty() && a[st.back()] < a[i]) {
            res[st.back()] = a[i];              // 右边第一个更大者找到了
            st.pop_back();
        }
        st.push_back(i);
    }
    return res;
}
// [2,1,5,3,4] → [5,5,-1,4,-1]
```

**实测（最坏场景：递减数组）**：朴素 O(n²) 与单调栈**差约 1000 倍**——"每个元素只进栈出栈一次"的直接体现。

**单调队列**：滑动窗口最大值的 O(n) 解法（窗口里保持递减，队头就是最大值）——常用于"定长窗口统计"：

```cpp
std::vector<int> maxInWindows(const std::vector<int>& a, int k) {
    std::vector<int> res;
    std::deque<int> q;                          // 存下标，队内对应值单调递减
    for (int i = 0; i < static_cast<int>(a.size()); ++i) {
        while (!q.empty() && a[q.back()] <= a[i]) q.pop_back();
        q.push_back(i);
        if (q.front() <= i - k) q.pop_front();  // 窗口左边界滑出去了
        if (i >= k - 1) res.push_back(a[q.front()]);
    }
    return res;
}
// [1,3,-1,-3,5,3,6,7], k=3 → [3,3,5,5,6,7]
```

**本质**：把"每个元素要和前后比较"的场景，从 O(n²) 优化到 O(n)（每个元素只被处理常数次）。

## 6. 要点回顾

1. **并查集**：连通性问题专用；**路径压缩 + 按秩合并缺一不可**（两个优化一起约快 500 倍，均摊 O(α(n))）
2. **布隆过滤器**：用 128 KB 换 10 万条的"存在性判断"（实测误判 0.64%、零假阴性）；**说"不在"一定对**，用来挡数据库穿透；**不能删**
3. **LRU = 哈希 + 双向链表**，get/put 都是 O(1)；单链表做不到（要前驱）
4. **跳表**：随机多层链表，期望 O(log n)；插入与 AVL 同量级、查找常数更大，但实现简单、范围查询/并发友好（Redis zset 的选择）
5. **单调栈/队列**：利用"每个元素只处理一次"把窗口/前后比较类问题降到 O(n)
6. 这些结构都需要自己实现（或用现成库）——遇到场景要能**想到它们**（连通性、去重前置、缓存、有序范围、窗口统计）
