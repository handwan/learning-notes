# 复杂度与均摊分析

复杂度是"选结构"的语言：先会估，再看常数——**同是 O(n)，实测能差 7 倍**（见下一篇的缓存实测）。

> 本篇所有实现都是**手写**的。

## 1. 为什么先讲复杂度

数据量小时，什么结构都"能跑"；数据量一大，选错结构就是灾难：

| 操作次数 | 每次都"只做一点点"的代价 |
|---------|------------------------|
| 1 千 | 无所谓 |
| 100 万 | 毫秒级（均摊操作撑得住） |
| 10 亿 | 秒级起步——O(n²) 就彻底没救 |

## 2. 三个记号

| 记号 | 含义 | 一句话 |
|------|------|--------|
| O(f(n)) | **上界**：增长不快于 f | 最常用，表示"最坏/保证" |
| Ω(f(n)) | 下界：不快于 f 的下限 | 少用 |
| Θ(f(n)) | 紧确界：上下一夹就是 f | 想说"就是 f"时用 |

两个常见误区：

- **O 是上界不是精确值**：`O(n)` 的算法可能实际跑得比另一个 `O(n)` 快 7 倍（常数与局部性，见下篇实测）
- **O 忽略了常数和低阶**：小数据量下 `O(n²)` 的插入排序可能比 `O(n log n)` 的快（常数小）——工程上"小数组用插入排序"是常规优化

## 3. 常见增长量级

| 复杂度 | n=1e6 时的感觉 | 典型结构/操作 |
|--------|--------------|--------------|
| O(1) | 立刻 | 数组下标、哈希查找（均摊） |
| O(log n) | ~20 步 | 平衡树、二分的查找路径 |
| O(n) | 线性扫一遍（实测毫秒级） | 数组/链表遍历 |
| O(n log n) | 排序的主战场（比 O(n²) 快得多） | 快排/归并/堆排 |
| O(n²) | 1e12 步——跑不完 | 双重循环、朴素字符串匹配 |
| O(2ⁿ) | 只敢 n ≤ 30 | 子集枚举 |

**对数从哪来**：每次把问题**砍一半**（二分、平衡树）或**翻倍**（倍增、扩容），层数就是 log n。

## 4. 均摊分析：为什么 `push_back` 是 O(1)

单次 `push_back` 可能很贵（扩容 + 搬全部元素），但**不是每次都贵**：

```
动态数组扩容序列（实测 capacity）：1 → 2 → 4 → 8 → 16 → ...（翻倍）
第 k 次扩容搬 k/2 个元素；把"总搬运量"摊到每次插入：
1 + 2 + 4 + ... + n/2 = n - 1  →  均摊 O(1) 每次
```

实测：1000 万次 `push` 几乎线性（约 24 次扩容也不拖后腿）——这就是“均摊”的样子。

**均摊 vs 平均**：

| | 含义 | 例子 |
|--|------|------|
| 均摊（amortized） | **最坏情况下的序列保证**：任何 n 次操作总代价 ≤ c·n | 动态数组 push |
| 平均（average） | 假设输入分布下的期望 | 哈希表查找（对随机输入） |

均摊是"数学保证"，平均是"概率期望"——说"哈希查找 O(1)"严格说是**平均** O(1)。

## 5. 常数与空间：别忘了这两项

- **常数因子**：同 O(n) 的遍历，手写数组比手写链表实测快 **7 倍**（缓存局部性，下一篇细讲）
- **空间**：
  - 数组：只有元素本身（紧凑）
  - 链表：每元素多 1~2 个指针（8~16 字节/元素）+ 分配器头部
  - 哈希表：桶数组要留空位（负载因子 0.5~0.75 → 额外 30%~100%）
  - 跳表：平均每元素 ~2 个指针

**结论**：先按复杂度筛选（数量级），再用实测挑同量级里更快的（常数/局部性）。

## 6. 怎么估一段代码

1. 数**循环层数**：一层 O(n)、两层 O(n²)（除非内层有边界递减——那是 O(n²/2) 仍然是 O(n²)）
2. 看**每次砍多少**：砍一半 → log n（二分、平衡树、堆）
3. 递归：写**递归式**或画递归树；`T(n) = 2T(n/2) + O(n)` → O(n log n)（归并）
4. 注意**隐藏的循环**：字符串拼接（每次复制 O(n)）、**数组头插**（每次搬全部——100 万元素上做 1 万次，就要搬 1 万遍整个数组）

## 7. 要点回顾

1. **O 是筛选器**：先排除掉数量级不对的（O(n²) 在大 n 下没救），再比常数
2. **三个记号**：O 上界（最常用）、Ω 下界、Θ 紧确界；O 不代表"精确等于"
3. **对数**来自"砍半/翻倍"；排序的 n log n 就是"log n 层 × 每层 n"
4. **均摊 O(1)**：动态数组扩容翻倍 → 总搬运量 O(n)；均摊是**保证**，平均是**期望**
5. **常数不是小事**：同 O(n) 数组遍历比链表快 7 倍（局部性）；数组头插则被链表头插碾压（量级差距）
6. **空间也算账**：链表指针、哈希空桶、跳表索引——按"每元素开销"记账
7. **估算四步**：数循环 → 看砍半 → 写递归式 → 找隐藏循环
