# 选型手册

前面六篇的收束：**按需求查表 → 看复杂度 → 看内存/局部性 → 实测确认**。

## 1. 按需求选（第一直觉）

| 需求 | 首选 | 次选/备注 |
|------|------|----------|
| 随机访问、遍历、尾部增删 | 动态数组 | 默认就是它 |
| 头尾都要 O(1) | 分段双端队列 | 中间插入仍 O(n) |
| 已知位置的频繁增删 | 双向链表 / 侵入式链表 | 遍历慢 7 倍，慎用 |
| 纯查找（无需顺序） | 哈希表 | 平均 O(1)，要防哈希 DoS |
| 有序遍历、范围、前驱后继 | 平衡树（AVL/红黑树） | O(log n) |
| 每次只要最值 | 堆 | Top-K 用小顶堆 |
| 前缀/自动补全/tokenizer | Trie / Radix Tree | 纯查词不如哈希 |
| 连通性合并查询 | 并查集 | 压缩 + 按秩 |
| "可能存在"过滤 | 布隆过滤器 | 挡缓存穿透，不可删 |
| 缓存淘汰 | LRU（哈希 + 双向链表） | O(1) get/put |
| 有序 + 范围 + 并发 | 跳表 | Redis zset 的选择 |
| 定长窗口最值/统计 | 单调队列 | O(n) |
| 静态大图 / 稀疏矩阵 | CSR | 构建 7.6 倍快、BFS 1.8 倍（实测） |
| 固定容量流式缓冲 | 环形缓冲 | 零分配、覆盖最旧 |

> **本篇管"选哪个结构"**：需求 → 决策表 → 对应篇的复杂度与实测数据。

## 2. 操作复杂度总表

| 结构 | 访问 | 查找 | 插入 | 删除 | 有序 |
|------|:---:|:---:|:---:|:---:|:---:|
| 动态数组 | **O(1)** | O(n) | 尾均摊 O(1) / 中间 O(n) | 同插入 | ❌ |
| 单/双向链表 | O(n) | O(n) | **O(1)**（有位置） | **O(1)**（双向给节点） | ❌ |
| 分段双端队列 | O(1) | O(n) | 头尾 O(1) / 中间 O(n) | 同插入 | ❌ |
| 哈希表 | — | 平均 **O(1)** | 平均 O(1) | 平均 O(1) | ❌ |
| 平衡树 | — | O(log n) | O(log n) | O(log n) | ✅ |
| 堆 | 堆顶 O(1) | O(n) | O(log n) | 堆顶 O(log n) | 偏序 |
| Trie | — | O(词长) | O(词长) | ⚠️ 复杂 | ✅ 前缀 |
| 跳表 | — | 期望 O(log n) | 期望 O(log n) | 期望 O(log n) | ✅ |
| 并查集 | — | O(α(n)) | O(α(n)) 合并 | ❌ | ❌ |
| 布隆过滤器 | — | O(k) | O(k) | ❌ | ❌ |

## 3. 内存与局部性总表

| 结构 | 每元素额外开销 | 缓存友好度 |
|------|--------------|:---:|
| 数组/动态数组 | 0（还有扩容余量） | 极好 |
| 分段双端队列 | 块指针（摊薄很小） | 好 |
| 链表 | 1~2 指针（8~16 B）+ 分配头 | 差（实测遍历慢 7 倍） |
| 哈希表 | 空桶（负载因子 ~0.75 → +33%） | 较好 |
| 平衡树 | 3 指针 + 颜色（~24 B） | 一般 |
| Trie | 每节点 26 指针（稀疏时极浪费） | 一般 |
| CSR | 偏移数组 (n+1)×4B | 极好 |

**记法**：指针越多、分配次数越多、越"跳"的结构 → 缓存越差、常数越大。

## 4. 常见误区

| 误区 | 实际 |
|------|------|
| "链表插入删除 O(1)，比数组快" | **先要 O(n) 找位置**；遍历还慢 7 倍（实测） |
| "哈希表 O(1)，所以永远最快" | 平均才有保证；范围/有序做不了；哈希差会退化 |
| "堆能查任意元素" | 堆只保证**堆顶**是最值，查别的要 O(n)（要删任意元素得配哈希索引） |
| "动态数组扩容很贵不能用" | 翻倍扩容下**均摊 O(1)**（1000 万次 push 也几乎线性） |
| "Trie 查找比哈希快" | 实测慢几十倍；它的价值是前缀操作 |
| "同复杂度就一样快" | 差在常数与局部性（同 O(n) 差 7 倍） |
| "平衡树一定比哈希慢" | 查找慢，但**有序**；小数据量常数差异不明显 |

## 6. 选择流程（四步）

1. **列操作**：主要做哪些操作（查找/插入/有序/最值/前缀…）
2. **查表**：按需求锁定候选（§1）
3. **比代价**：复杂度（§2）→ 内存/局部性（§3）→ 排除误区（§4）
4. **实测**：真数据 + `-O2`，量 100 万次级别的耗时——数字会告诉你选对了没有

## 7. 要点回顾

1. **默认选动态数组**；要头尾 O(1) 用分段双端队列；链表只在"已知位置频繁增删"时用
2. **有序需求 = 平衡树/跳表；纯查找 = 哈希；前缀 = Trie；最值 = 堆**
3. **内存局部性是一等公民**：连续 > 跳指针（7 倍差距），CSR 是极致形态
4. **特殊需求记结构名**：连通性→并查集、存在性→布隆、缓存→LRU、窗口→单调队列
5. **别背结论，走四步**：列操作 → 查表 → 比代价 → 实测
