# 串与模式匹配

串（字符串）是"数据元素为字符"的线性表——重点是**子串定位**（模式匹配）：在文本 `s` 里找模式 `p` 第一次出现的位置。

> 实现都是手写。

## 1. 串的存储结构

| 方式 | 结构 | 特点 |
|------|------|------|
| 顺序存储（定长） | `char ch[MAXLEN]; int len;` | 简单，长度受限 |
| 堆分配存储 | `char* ch; int len;`（malloc 分配） | 长度灵活，工程用这种 |
| 块链存储 | 每节点存若干字符 + next | 理论上讲；实践不用（缓存差） |

```cpp
/* 堆分配存储：长度 + 动态数组，构造时分配、析构时释放 */
struct HString {
    char* ch; int len;
    explicit HString(const char* p) : ch(new char[strlen(p) + 1]), len((int)strlen(p)) {
        memcpy(ch, p, len + 1);          // +1 带上 '\0'，便于 printf
    }
    ~HString() { delete[] ch; }
};
```

**朴素匹配的起点**：`s[i..i+m-1]` 和 `p[0..m-1]` 逐字符比。

## 2. 朴素（BF）算法

```cpp
int naive_match(const char* s, const char* p, long long* cnt) {
    int n = strlen(s), m = strlen(p);
    for (int i = 0; i + m <= n; ++i) {          /* 枚举起点 */
        int j = 0;
        while (j < m) { ++*cnt; if (s[i + j] != p[j]) break; ++j; }
        if (j == m) return i;                   /* 全比完 → 匹配 */
    }
    return -1;
}
```

**复杂度**：最好 O(n+m)，**最坏 O(n×m)**（每次快匹配完才失败，指针回退重新比）。

**最坏实测**：文本 = 20 万个 `a`，模式 = 999 个 `a` + `b`：

```
朴素：约 2 亿次比较（几乎 n×m 次）
```

## 3. KMP：让模式指针不回退

**核心思想**：当 `s[i] != p[j]` 时，`s[i]` 之前的 `j` 个字符已经匹配过了——**利用这个信息，把模式右滑到"最长相等前后缀"的位置继续比，文本指针 `i` 永不回退**。

**next 数组**（前缀函数）：`next[j]` = `p[0..j]` 的**最长相等前后缀**长度。

```
p = a b a b a c a
next = 0 0 1 2 3 0 1     （实测与手算一致）

含义：p[0..j] 的前缀 = 后缀的最长长度。
例：p[0..4]="ababa"，前后缀最长相等是 "aba"（长 3）→ next[4]=3
```

**递推求法**（O(m)）：

```cpp
void kmp_next(const char* p, int* next) {
    int m = strlen(p);
    next[0] = 0;
    for (int i = 1, k = 0; i < m; ++i) {
        while (k > 0 && p[i] != p[k]) k = next[k - 1];   /* 失配就跳回上一个后缀 */
        if (p[i] == p[k]) ++k;                           /* 匹配上，前后缀加长 */
        next[i] = k;
    }
}
int kmp_match(const char* s, const char* p, const int* next, long long* cnt) {
    int n = strlen(s), m = strlen(p);
    for (int i = 0, k = 0; i < n; ++i) {
        while (k > 0 && s[i] != p[k]) { ++*cnt; k = next[k - 1]; }   /* 模式回退（用 next） */
        ++*cnt;
        if (s[i] == p[k]) ++k;                                       /* 文本不回退，i 一直加 */
        if (k == m) return i - m + 1;
    }
    return -1;
}
```

**复杂度**：求 next O(m) + 匹配 O(n) → **O(n+m)**。

**实测（同一最坏数据）**：

| 算法 | 比较次数 |
|------|:---:|
| 朴素 BF | 约 2 亿次（n×m） |
| KMP | 约 40 万次（n+m 量级） |

（随机数据上两者结果一致——2000 组对拍验证；随机数据下朴素通常也很快，"最坏"才是 KMP 的战场。）

### nextval：KMP 的改进

**问题**：失配后跳到的位置，如果**字符和刚失败的那个一样**，必然再次失配——白比一次。

```
例子：模式 aaaab，文本里出现 "aaaax"
在 p[3]（'a'）处失配 → 朴素 KMP 跳到 next[2] = 2，p[2] 还是 'a' → 又失败 → 再跳……
改进：直接跳到"最后一个不同的字符"后面
```

**跳转表的改进**（0-based，`next[]` 是前面的前缀函数）：

```cpp
// jump[k]：已匹配 k 个字符、当前失配时应跳到的位置
// 朴素：jump[k] = next[k-1]；改进：若 p[k] == p[jump[k]]（跳过去还是同字符）→ 继续往前跳
void kmp_nextval(const char* p, int* next, int* jump) {
    int m = strlen(p);
    kmp_next(p, next);
    jump[0] = 0;
    for (int k = 1; k < m; ++k) {
        int j = next[k - 1];
        jump[k] = (p[k] == p[j]) ? jump[j] : j;      // 相同字符 → 一步跳到底
    }
    jump[m] = next[m - 1];                            // 完整匹配后的状态
}
```

**实测（20 万文本）**：

| 场景 | 朴素 KMP | KMP + nextval |
|------|:---:|:---:|
| 最坏数据（全 `a` + 尾部 `b`） | 399001 次比较 | 399001 次（**没差别**——失配字符和跳转目标不同） |
| 重复模式（`aaaab` 在 `(abaa)^N` 里） | 350001 次比较 | **250002 次（省 29%）** |

**结论**：nextval 不是无条件更快——**只有"模式里存在相等字符、失配后跳转目标字符相同"时才省**；两个版本结果完全一致（1000 组随机对拍）。

## 4. 其他模式匹配算法（了解）

| 算法 | 思路 | 特点 |
|------|------|------|
| **Rabin-Karp** | 滚动哈希：把子串哈希成数，O(1) 滑动更新 | 平均 O(n+m)；需处理哈希冲突；适合多模式/二维 |
| **BM（Boyer-Moore）** | **从右往左**比，坏字符/好后缀规则大跳 | 实践最快（文本搜索工具常用） |
| **AC 自动机** | Trie + KMP 的失配指针 | **多模式**匹配（敏感词过滤） |
| 后缀数组/后缀自动机 | 预处理文本本身 | 反复查询/最长重复子串等 |

## 5. 实战建议

- **优先用成熟实现**：工程里字符串查找直接用库（性能已很好），别手写 KMP 去跑生产
- 但**要知道**：`find` 类接口不是魔法——最坏情况各家实现不同（有的就是朴素）
- **多模式**（一堆关键词同时匹配）用 AC 自动机/库，而不是跑 N 次单模式
- **数据规模大 + 模式短**时，KMP/BM 这类 O(n+m) 算法才有意义；小数据随便写

## 6. 要点回顾

1. **串的存储**：堆分配（`char* + len`）是工程标准；定长的只适合教学
2. **朴素匹配 O(nm) 的根源**：失配后**文本指针回退**重比（实测最坏约 2 亿次比较）
3. **KMP 的关键**：`next` 数组 = 最长相等前后缀 → 失配时**模式滑到正确位置、文本不回退**（O(n+m)）
4. `next` 手推：`ababaca` → `0 0 1 2 3 0 1`（实测一致）
5. 同一最坏数据：朴素约 2 亿次比较 vs KMP 约 40 万次（**约 500 倍**）
6. 还有 BM（实践最快）、Rabin-Karp（滚动哈希）、AC 自动机（多模式）
7. **实战用库**；知道原理是为了"遇到性能问题知道往哪想"
