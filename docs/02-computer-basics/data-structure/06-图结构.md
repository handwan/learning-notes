# 图结构

图 = 点 + 边。**结构选择决定性能**：邻接矩阵、邻接表、CSR——同一个 BFS 实测能差近一倍，构建能差 7.6 倍。

> 全部手写实现：100 万点、200 万条边。

## 1. 三种表示

**邻接矩阵**：`n × n` 的 0/1 矩阵。

- 判边 O(1)、实现最简单
- 空间 O(n²)：100 万点 → 10¹² 位，**放不下**
- 适合**稠密图**（边数接近 n²）或 n 很小

**邻接表**：每个点存一个"邻居列表"（每点一个动态数组，或链表）。

- 空间 O(n + m)（m = 边数）
- 判边 O(度数)、遍历邻居方便
- 缺点：**每个点一个动态数组**——100 万点就是 100 万次分配（还要留扩容余量）

**CSR（压缩稀疏行）**：把邻接表压成**两个大数组**：

```
offsets: [0, 3, 5, 9, ...]          ← 点 i 的邻居在 targets[offsets[i]..offsets[i+1])
targets: [2, 5, 7 | 1, 5 | 0, 3, 4, 6 | ...]
          └─ 点0的邻居 ─┘└点1的邻居┘
```

- 空间 = `(n+1) × 4B` + `2m × 4B`（**无指针、无每节点分配**）
- 遍历邻居 = 连续内存扫一段 → **cache 友好**
- 判边要扫（或用额外哈希/二分）
- **不能动态增删边**——适合**静态图**（构建一次、查很多次）

## 2. 实测：邻接表 vs CSR

| 操作 | 邻接表（每点一个动态数组） | CSR |
|------|:---:|:---:|
| 构建（100 万点 200 万边） | 百万次分配/扩容 | **快 7.6 倍**（两次线性扫描） |
| BFS 全图 | 指针跳着走 | **快 1.8 倍**（连续内存） |
| 内存 | 每点一个动态数组的头部 + 扩容余量 | 偏移 4 MB + 目标 16 MB，一次分配 |

**为什么差这么多**：邻接表每个点都要 malloc/扩容（100 万次分配），遍历时跳来跳去；CSR 是**两次线性扫描**（数度数 → 前缀和 → 填数组），内存连续、无分配。

**CSR 构建就三步**：

```cpp
struct Graph {
    int *off, *tgt, n;                       // CSR：偏移数组 + 邻居数组
    Graph(int n_, int m, const int* eu, const int* ev)
        : off(new int[n_ + 1]()), tgt(new int[2 * m]), n(n_) {
        for (int i = 0; i < m; ++i) { ++off[eu[i] + 1]; ++off[ev[i] + 1]; }   // ① 数度数
        for (int i = 0; i < n; ++i) off[i + 1] += off[i];                     // ② 前缀和
        int* pos = new int[n];
        for (int i = 0; i < n; ++i) pos[i] = off[i];                          // ③ 按游标填
        for (int i = 0; i < m; ++i) { tgt[pos[eu[i]]++] = ev[i]; tgt[pos[ev[i]]++] = eu[i]; }
        delete[] pos;
    }
    ~Graph() { delete[] off; delete[] tgt; }
    // 点 u 的邻居 = tgt[off[u] .. off[u+1])
};
// 实测：100 万点 200 万边，构建比手写邻接表快 7.6 倍
```

三步都是 O(n + m) 且是**顺序访问**——这就是它构建快（实测 7.6 倍）的原因；代价是建好后不能动态增删边。

## 3. 稀疏矩阵：CSR 的主场

图就是稀疏矩阵（邻接矩阵的稀疏版），所以 **CSR/CSC 也是稀疏矩阵的标准格式**：

| 格式 | 存什么 | 适合 |
|------|-------|------|
| COO（坐标） | `(row, col, val)` 三元组 | 构建期（好写） |
| **CSR**（按行） | offsets + 列号 + 值 | **按行扫**（SpMV: y = A·x） |
| CSC（按列） | 同上按列 | 按列操作 |

AI 里的出现位置：

- **GNN/GCN**：图的邻接矩阵就是 CSR（`torch_geometric` 的 `edge_index` 本质是 COO）
- **稀疏 attention / 稀疏权重**：SpMV、SpMM 的输入格式
- **倒排索引**：term → posting list = CSR 的变体（文档 ID 的偏移数组）

## 4. 遍历：结构视角

**BFS（队列）**：一层层扩散——无权图最短路、社交几度关系。

**DFS（栈/递归）**：一条路走到黑——连通分量、环检测、拓扑排序。

从**结构**角度要记的两点：

1. **遍历性能取决于内存布局**：CSR 的邻居是连续段，BFS/DFS 都吃缓存红利（实测 1.8 倍）
2. **标记数组（visited）也是热点**：位压缩省内存，但每位都要读改写（并发不安全）；性能敏感用**字节数组**

（具体的 BFS/DFS/最短路/最小生成树算法见[图算法](07-图算法.md)，这里只讲"结构怎么存、怎么访"。）

**在 CSR 上写遍历**（`neighbors(u)` 就是 `tgt[off[u]..off[u+1])`）：

```cpp
void bfs(const Graph& g, int s) {                 // 队列：一层层扩散（无权最短路）
    int* q = new int[g.n]; char* vis = new char[g.n]();
    int qh = 0, qt = 0; q[qt++] = s; vis[s] = 1;
    while (qh < qt) { int u = q[qh++];
        for (int i = g.off[u]; i < g.off[u + 1]; ++i)              // 连续内存扫邻居
            if (!vis[g.tgt[i]]) { vis[g.tgt[i]] = 1; q[qt++] = g.tgt[i]; } }
    delete[] q; delete[] vis;
}
void dfs(const Graph& g, int s) {                 // 栈：一条路走到黑（连通性、环检测）
    int* st = new int[g.n]; int sp = 0; char* vis = new char[g.n]();
    st[sp++] = s;
    while (sp) { int u = st[--sp];
        if (vis[u]) continue; vis[u] = 1;
        for (int i = g.off[u + 1] - 1; i >= g.off[u]; --i)         // 逆序压栈，出栈顺序才自然
            if (!vis[g.tgt[i]]) st[sp++] = g.tgt[i]; }
    delete[] st; delete[] vis;
}
```

**连通分量**：对所有点跑一遍"没访问过就 BFS/DFS 一次并计数"——实测 6 个点 4 条边 = 3 个分量

**拓扑排序（DAG）**：在 CSR 上算入度（扫一遍 `tgt`）→ 入度 0 入队 → 出队时把邻居入度减 1，减到 0 再入队——实测产出的顺序满足所有边的方向（有环则有节点永远不入队，顺便能检测环）。

## 5. 选择表

| 场景 | 选择 | 理由 |
|------|------|------|
| n 小 / 稠密 / 频繁判边 | 邻接矩阵 | O(1) 判边，n² 能接受 |
| 动态增删边 / 通用建模 | 邻接表 | 灵活、好写 |
| 大规模静态图 / 稀疏矩阵 | **CSR** | 内存省、遍历快（构建 8 倍、BFS 1.6 倍实测） |
| 需要判边又要动态 | 邻接表 + 哈希集合补判边 | 折中 |

## 6. 要点回顾

1. **边数决定表示**：稀疏（m ≪ n²）用邻接表/CSR，稠密才用矩阵（n² 空间放不下大图）
2. **CSR = offsets + targets 两个数组**：无指针、无分配、邻居连续——静态图/稀疏矩阵首选
3. **CSR 的代价**：不能动态增删边、判边要扫 → 构建一次查多次的场景
4. **AI 里到处是 CSR**：GNN 的邻接、稀疏 attention 的 SpMM、倒排索引的 posting list
5. **遍历要顺着内存走**：同样 BFS，CSR 比手写邻接表快 **1.8 倍**（实测）
6. 遍历与最短路算法见[图算法](07-图算法.md)；这里的关键是"**结构选对了，算法才发挥得出来**"
