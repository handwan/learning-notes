# IO 系统

## 1. 五种 IO 模型

以"读 socket 数据"为例：

| 模型               | 过程                              | 问题               |
|--------------------|-----------------------------------|--------------------|
| **阻塞 IO**        | 一直等到有数据                    | 一个连接占一个线程 |
| **非阻塞 IO**      | 没数据立刻返回，靠**轮询**        | 轮询费 CPU         |
| **IO 多路复用**    | `select/poll/epoll` 同时等一堆 fd | **高并发主力**     |
| **信号驱动 IO**    | 数据到了发信号通知                | 少用               |
| **异步 IO（AIO）** | 内核全干完，再通知你              | 最理想，实现复杂   |

**关键区分**：前四种都是**同步 IO**（最后"读"还得自己调，会阻塞）；只有 **AIO** 是真异步。

## 2. select / poll / epoll

|           | select               | poll   | **epoll**                |
|-----------|----------------------|--------|--------------------------|
| fd 上限   | 1024                 | 无上限 | 无上限                   |
| 每次调用  | **全量拷贝 fd 集合** | 同左   | **内核维护，不重复拷贝** |
| 找就绪 fd | O(n) 遍历            | O(n)   | **回调 → 就绪链表 O(1)** |
| 触发      | LT                   | LT     | **LT + ET**              |

### epoll 三个系统调用

```cpp
int epfd = epoll_create1(0);               // 建实例（红黑树 + 就绪链表）
epoll_ctl(epfd, EPOLL_CTL_ADD, fd, &ev);   // 注册 fd（O(log n)）
epoll_wait(epfd, events, maxevents, -1);   // 只返回就绪的 fd
```

### epoll 为什么快（三条）

1.  **不用每次传整个 fd 集合**——内核里存着
2.  **事件驱动**：fd 就绪时由**回调**放进"就绪链表"
3.  `epoll_wait` **只返回就绪的**，O(1) 拿，不用遍历全部

### LT vs ET

|      | 水平触发 LT（默认）  | 边缘触发 ET                |
|------|----------------------|----------------------------|
| 通知 | 有数据就**一直通知** | **只在状态变化时通知一次** |
| 编程 | 简单，可以慢慢读     | **必须循环读到 EAGAIN**    |
| 风险 | 效率略低             | 没读完 → 数据"卡住"        |

## 3. 同步/异步 vs 阻塞/非阻塞

这是**两个不同维度**，别混：

|          | 阻塞              | 非阻塞                                           |
|----------|-------------------|--------------------------------------------------|
| **同步** | 一直等（阻塞 IO） | 返回"还没好"，自己再来问（非阻塞 IO / 多路复用） |
| **异步** | —                 | 内核干完**主动通知**（AIO）                      |

**经典误解**：epoll 叫"非阻塞多路复用"，但**读写本身还是同步的**——你仍然要自己 `read`。

## 4. DMA（直接内存访问）

**为什么 IO 不占 CPU**：数据搬运交给 **DMA 控制器**，CPU 只负责"发起"和"收尾"。

```cpp
无 DMA（PIO）：CPU 一个字节一个字节搬 → 全程占着
有 DMA：CPU 告诉 DMA"从设备搬到内存" → DMA 干活 → 搬完发中断通知 CPU
```

- 磁盘、网卡等**外设都靠 DMA**
- 它也是零拷贝能成立的基础

## 5. 零拷贝

**普通读文件 + 写 socket**：4 次拷贝 + 4 次上下文切换

```cpp
磁盘 → 内核缓冲区 → 用户缓冲区 → socket 缓冲区 → 网卡
```

**零拷贝**（`sendfile` / `splice`）——数据**不经过用户态**：

```cpp
磁盘 → 内核缓冲区 → 网卡        （少 2 次拷贝）
```

用在：静态文件服务、Kafka 这类高吞吐场景。

## 6. Reactor / Proactor

IO 多路复用（epoll）之上，**程序结构**怎么组织：

| 模型         | 谁读数据                                    | 对应                         |
|--------------|---------------------------------------------|------------------------------|
| **Reactor**  | **应用自己读**（通知你"可读了"，你去 read） | epoll + 同步 IO              |
| **Proactor** | **内核帮你读完**，通知你"数据在这"          | 真异步 IO（io_uring / IOCP） |

**Reactor 的常见变体**：

| 变体              | 结构                                   | 例子              |
|-------------------|----------------------------------------|-------------------|
| 单 Reactor 单线程 | 简单，但吃不满多核                     | Redis             |
| 单 Reactor 多线程 | 事件线程 + 业务线程池                  | —                 |
| **主从 Reactor**  | 主 Reactor 只接连接，从 Reactor 管读写 | **Netty / muduo** |
