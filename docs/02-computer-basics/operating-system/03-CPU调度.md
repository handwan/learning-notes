# CPU 调度

同一时刻 CPU 数量有限，却可能有几百个可运行任务：谁先上、跑多久、下一个是谁？

这就是调度。它没有“绝对最优”，只有在某个目标下的取舍。

## 1. 调度要优化什么

| 指标 | 定义 | 谁更在意 |
|------|------|---------|
| CPU 利用率 | CPU 忙碌的比例 | 批处理、服务器 |
| 吞吐量 | 单位时间完成的任务数 | 批处理 |
| 周转时间 | 提交 → 完成 | 批处理 |
| 等待时间 | 在就绪队列里等的时间 | 通用 |
| 响应时间 | 提交 → 第一次运行 | 交互 |
| 公平 / 可预测 | 不饿死；实时任务不超时 | 分时 / 实时 |

几个关系：

- `周转 = 完成 − 提交`，`等待 = 周转 − 运行`
- `响应 = 第一次运行 − 提交`
- 吞吐和响应常冲突：批处理喜欢一次跑久点，交互喜欢快点切
- 公平和优先级常冲突：严格优先级会饿死低优先级

> 所以“哪个算法好”要先问：优化什么、能接受什么代价。

## 2. 抢占 vs 非抢占

| | 非抢占 | 抢占 |
|--|-------|------|
| 规则 | 任务不让出就一直跑 | 时间片到 / 高优先级来 → **踢下来** |
| 优点 | 简单、切换少 | 响应好、公平 |
| 缺点 | **一个长任务不让出，卡住所有人** | 切换有开销 |
| 例子 | 早期批处理 | 现代通用 OS |

还有一个中间态：**协作式**——任务主动 `yield` 才切换，协程和用户级线程常用。

抢占需要**调度点**：时钟中断、系统调用返回、唤醒更高优先级任务等。用户态任务在指令边界就能被抢占；内核态能不能被抢占，取决于内核配置（Linux 有 `CONFIG_PREEMPT_*` 几档）。

## 3. 经典算法

### FCFS（先来先服务）

- 非抢占，按到达顺序跑
- 问题：**护航效应**——一个长任务把后面全堵住，平均等待时间可能很差

### SJF / SRTF（短作业优先）

- SJF 非抢占；SRTF（最短剩余时间优先）是它的抢占版，新任务剩余时间更短时抢占
- 在“所有任务同时到达、运行时间已知、非抢占”的前提下，SJF 的**平均等待时间最小**
- 问题：
  - 事先**不知道要跑多久**（实际用历史 CPU burst 做指数平均预测，估计错会退化）
  - 长作业可能**饿死**（总有短作业插队）

### 时间片轮转（RR）

每个任务跑一个**时间片**，轮着来。

| 时间片 | 后果 |
|--------|------|
| 太小 | 切换开销占比高，吞吐下降 |
| 太大 | 退化成 FCFS，响应变差 |

传统 RR 的时间片常在 **10–100 ms** 量级；具体系统会按负载调。同优先级下 RR 不会饿死，但平均周转不一定好。

### 优先级调度

- 高优先级先跑；分静态优先级和动态优先级
- 问题：低优先级**饿死** → 解法：**老化（aging）**（等越久优先级越高）

### 多级反馈队列（MLFQ）

多个队列，优先级不同、时间片不同：

```text
新任务 → 最高优先级队列（时间片小）
用完整个时间片还没跑完 → 降到下一级（时间片变大）
时间片没用完就主动让出 → 留在原级
```

**效果**：

- **短任务/交互任务**很快跑完 → 一直高优先级，**响应快**
- **CPU 密集长任务** → 自动降级，**不挡别人**
- 定期把所有任务提升回最高优先级队列，防止长任务饿死

> MLFQ 是一类设计思想，不是某个具体 OS 的实现；很多通用 OS 的多级队列都受它影响。Linux 的 CFS/EEVDF 不是 MLFQ，但同样要处理“交互 vs 批处理”的冲突。

## 4. Linux：CFS 与 EEVDF

**CFS（完全公平调度）**：

- 每个任务维护**虚拟运行时间** `vruntime`，跑得越久越大
- 总选 `vruntime` 最小的任务（红黑树最左节点）
- `nice` 值（-20 ~ 19）映射成权重：nice 越低，权重越高，分到的 CPU 越多
- 每个 CPU 一个运行队列，靠负载均衡在核间搬任务

**EEVDF**（Earliest Eligible Virtual Deadline First）：Linux 6.6 起默认，取代 CFS。

- 在“公平份额”之外加入**虚拟截止时间**：先选“有资格且截止最近”的任务
- 改善短任务/交互任务的延迟，同时保留按权重分配
- `nice` 的语义不变

**调度类**（优先级从高到低）：

| 类 | 用途 |
|----|------|
| stop | 内核内部停机/迁移 |
| deadline（`SCHED_DEADLINE`） | EDF 风格的截止时间调度 |
| RT（`SCHED_FIFO` / `SCHED_RR`） | 固定优先级实时任务 |
| fair（CFS/EEVDF） | 普通任务 |
| idle | 没事可做时才跑 |

> 调度单位是 **task（线程）**，不是进程——和上一篇的 Linux 实现对应。

## 5. 多核调度

单核只需“选下一个任务”；多核还要决定“**在哪个 CPU 上跑**”。

- 每个 CPU 有独立运行队列，内核做**负载均衡**
- **亲和性**（affinity）把任务绑在某些核上，减少迁移
- 迁移有成本：cache/TLB 变冷，NUMA 上还会跨节点访问内存
- 异构核（big.LITTLE）还要考虑任务适合大核还是小核

`taskset` / `numactl` 就是把这层策略暴露给用户。

## 6. 优先级反转

场景：三个优先级 L < M < H。

```text
1. L 拿了锁
2. H 来了，要同一把锁 → 阻塞等待
3. M 就绪，抢占 L（L 优先级低）
4. L 跑不了 → 锁不释放 → H 一直等，被 M 间接卡住
```

**结果**：优先级最高的 H 反而最后完成。这种等待没有上界，叫**无界优先级反转**。

**解法**：

| 方案 | 做法 |
|------|------|
| **优先级继承** | L 持锁期间临时继承 H 的优先级，不被 M 抢占；释放后恢复 |
| **优先级天花板** | 拿锁时把优先级提到**该锁的天花板**（可能使用这把锁的任务里的最高优先级） |

优先级继承是“按需提升”，天花板是“预先提升”；后者更保守，但需要预先知道每把锁的天花板。

> 现实案例：火星探路者号（Pathfinder）因优先级反转反复重启，最终启用优先级继承。

POSIX 线程里可用 `PTHREAD_PRIO_INHERIT` 打开继承。

## 7. 实时调度

**实时任务的关键不是“快”，而是“不能晚”**——必须在**截止时间**前完成。

| 类型 | 含义 | 例子 |
|------|------|------|
| **硬实时** | 错过截止 = 事故 | 刹车控制、飞控 |
| **软实时** | 错过 = 体验差 | 音视频播放 |

两种经典算法：

| 算法 | 优先级 | 思路 |
|------|--------|------|
| **RMS**（速率单调） | **静态** | 周期越短 → 优先级越高 |
| **EDF**（最早截止优先） | **动态** | 截止越近 → 优先级越高 |

**可调度性**（假设：独立周期任务、截止 = 周期、可抢占、单核、忽略开销）：

- RMS：利用率 `U = Σ(Ci/Ti) ≤ n(2^(1/n) − 1)` 时一定可调度；n 很大时约 **69.3%**。超过这个界不一定不可调度，只是不能保证
- EDF：`U ≤ 1` 时可调度，是单核可抢占下的**最优**算法；但过载时可能连锁错过（多米诺效应）

**和普通调度的区别**：普通调度追求公平/吞吐；实时调度追求**可预测性**——能分析最坏情况。

Linux 里对应 `SCHED_FIFO` / `SCHED_RR`（固定优先级）和 `SCHED_DEADLINE`（EDF + CBS）。

## 8. 演进与边界

**演进**：

- 批处理 → FCFS，吞吐优先，响应很差
- 分时 → RR，保证交互响应
- MLFQ → 按行为动态调优先级，兼顾短任务和长任务
- CFS → 按权重公平分配，适合通用服务器
- EEVDF → 在公平之上补延迟，照顾短任务/交互

**边界**：

- 调度器只能在**可运行**任务之间选；任务都在等 IO，调谁都一样
- 时间片不是越小越好；切换开销会吃掉收益
- `nice` 是权重提示，不是硬优先级；硬实时要用 RT 类
- 实时任务需要**准入控制**；无限制地加任务，EDF 也会崩
- 容器里还有一层：cgroup v2 的 `cpu.weight`（按权重分）和 `cpu.max`（限额）

## 9. 要点回顾

1. **指标与冲突**：吞吐 vs 响应、公平 vs 优先级；周转/等待/响应的定义
2. **抢占 vs 非抢占**：响应与切换开销的取舍；协作式是中间态
3. **经典算法**：FCFS 护航、SJF 最优但有前提且会饿死、RR 时间片权衡、优先级 + 老化
4. **MLFQ**：新任务高优先级、用完降级、定期提升；不是 Linux 的具体实现
5. **Linux**：CFS 的 `vruntime`/红黑树/权重；EEVDF 从 6.6 起默认；`nice` 和调度类
6. **多核**：每核运行队列、负载均衡、亲和性、迁移/NUMA 成本
7. **优先级反转**：无界反转、优先级继承、优先级天花板；Pathfinder
8. **实时**：RMS 静态 + 利用率界、EDF 动态且最优；假设和过载边界
