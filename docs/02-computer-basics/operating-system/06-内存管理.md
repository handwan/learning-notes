# 内存管理

## 1. 从物理内存到虚拟内存

**如果程序直接用物理地址**，会有三个问题：

- 进程之间**不隔离**（能改别人的内存）
- 程序要自己管"我的代码放在哪块物理内存"
- 内存不够时不好处理

**虚拟内存**：每个进程看到一个**独立的、连续的**地址空间，由 OS/MMU 映射到物理内存。

**三大好处**：

| 好处 | 说明 |
|------|------|
| **隔离** | 进程只能访问自己的地址空间 |
| **简化编程** | 不用关心物理布局，链接器按固定地址来 |
| **超售** | 地址空间可以**大于**物理内存（不常用的换到磁盘） |

## 2. 分页

把虚拟地址空间和物理内存都切成固定大小的**页**（通常 4KB），按页映射。

```
虚拟地址 = 虚拟页号 + 页内偏移
             ↓ 查页表
物理地址 = 物理页号 + 页内偏移
```

**页表**：记录"虚拟页 → 物理页"的映射，**每个进程一张**。

**问题**：页表本身太大（32 位下 4MB/进程；64 位更夸张）
**解法**：**多级页表** + **TLB**

### 多级页表

页表再分页——**没用到的二级页表不分配**，省空间。

代价：地址转换要**多次访存**（64 位常见 4 级）。

### TLB（页表缓存）

- CPU 里的"页表高速缓存"（几十~几百项）
- 命中 → 直接拿到物理页号（快）
- 未命中 → 查页表（慢），然后填入 TLB
- **进程切换要"换" TLB**（现代 CPU 用 ASID/PCID 打标记，避免整表刷掉）← 上下文切换贵的原因之一

## 3. 分段与段页式

**分页是"物理视角"（切固定块），分段是"逻辑视角"（按程序结构切）。**

| | 分页 | 分段 |
|--|------|------|
| 切分依据 | **固定大小**（如 4KB） | **逻辑单位**（代码段/数据段/栈） |
| 大小 | 固定 | 可变 |
| 对用户 | **不可见**（透明） | **可见**（编译器按段组织） |
| 地址 | 一维（线性地址） | **二维**（段号 + 段内偏移） |
| 碎片 | **内部碎片**（最后一页填不满） | **外部碎片**（段间空隙） |
| 主要目的 | 内存利用率 + 虚拟内存 | 共享 / 保护 / 动态增长 |

**段页式**：先按逻辑**分段**，每段内部再**分页**——"逻辑上分段，物理上分页"。
（现代 x86-64 里"段"基本退化，主要靠分页。）

## 4. 缺页中断（Page Fault）

访问的页**不在物理内存**时触发：

```
1. CPU 访问虚拟地址 → 查页表：标志位显示"不在内存"
2. 触发缺页异常 → 陷入内核
3. 内核：找空闲物理页（没有就置换一页出去）
4. 从磁盘把需要的页读进来
5. 更新页表
6. 返回用户态，【重新执行】那条指令（这次命中）
```

**关键**：是"重新执行"不是"继续"——所以对程序**完全透明**。

## 5. 页面置换算法

内存满了，得选一页换出去。选谁？

| 算法 | 思路 | 问题 |
|------|------|------|
| **FIFO** | 先进先出 | 可能换掉常用页；**Belady 异常**（页框变多，缺页反而变多） |
| **LRU** | 换出**最久没用过**的 | 符合局部性，但**精确实现贵** |
| **Clock（近似 LRU）** | 环形队列 + 访问位，转一圈找访问位 0 的 | **实际常用** |
| LFU | 换出使用次数最少的 | 老热门页赖着不走 |

**LRU 为什么理论好**：依据**局部性原理**——最近用过的，大概率马上还用。

**为什么不精确实现 LRU**：每次访问都要更新链表/时间戳，硬件开销大 → 用 **Clock** 近似。

## 6. 其他要点

### 局部性原理

| 类型 | 含义 |
|------|------|
| 时间局部性 | 刚访问的，马上还会访问 |
| 空间局部性 | 访问了 A，附近的 B 很快也会被访问 |

这是**缓存、预取、LRU 都有效**的根本原因。

### 用户态内存分配

- `malloc` 小块 → 从**堆**要（`brk`）；大块 → 直接 `mmap`
- 释放**不一定还给 OS**（缓存起来复用，所以 RSS 不降）

### swap（交换区）

物理内存不够时，把不常用的页写到磁盘。

> ⚠️ 频繁 swap = **性能灾难**（磁盘比内存慢几个数量级）

### 写时复制（COW）

- `fork()` 后，父子进程**共享**同一份物理页（只读）
- 谁**写**，才拷贝一份出去
- 好处：fork 快、省内存（exec 前就写的情况很少）

### NUMA 与 CPU 亲和

多路服务器里，CPU 访问"**自己插槽**"的内存快，访问别的插槽慢（NUMA 架构）。

| 手段 | 作用 |
|------|------|
| **NUMA 亲和** | 让线程优先用**本地内存**，避免跨节点访问 |
| **CPU 亲和** | 把线程绑到固定核（`taskset` / `sched_setaffinity`），减少迁移、提升缓存命中 |

> 对 AI 推理：多路机器上要注意"内存和 GPU/CPU 的本地性"。

### 大页（Huge Pages）

普通页 4KB；大页是 **2MB / 1GB**。

好处：**页表项大幅减少** → TLB 命中率高、缺页少 → 大内存应用（数据库、AI）性能提升。

### 内核内存分配（伙伴系统 / slab）

| 机制 | 解决什么 |
|------|---------|
| **伙伴系统** | 按 2 的幂管理**页框**，相邻空闲块可合并 → 缓解**外部碎片** |
| **slab** | 给频繁分配的小对象（inode、task_struct）建**缓存池**，避免反复构造/析构 |

### OOM（内存耗尽）

物理内存 + swap 都满了 → 内核的 **OOM Killer** 按评分挑一个进程杀掉。
