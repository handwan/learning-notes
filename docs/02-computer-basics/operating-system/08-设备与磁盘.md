# 设备与磁盘

顺序读能到 GB/s，随机 4KB 却只有几十~一百多 IOPS——差在哪？SSD 上为什么“电梯算法”没意义？

答案在**存储介质**：HDD 有机械寻道，SSD 没有。

## 1. IO 栈：从 read 到设备

```text
用户层          read() / write()
  ↓
文件系统/VFS    文件 → 块，页缓存
  ↓
块层            合并、排序、IO 调度
  ↓
设备驱动        操作控制器、寄存器
  ↓
中断 / DMA      完成通知、数据搬运
  ↓
硬件（控制器 + 设备）
```

**设计要点**：**上层统一、下层各异**——换硬件只换驱动，上层 API 不变。

| 设备类型 | 例子 | 特点 |
|---------|------|------|
| **块设备** | `/dev/sda`、NVMe | 可随机访问、按块读写、走页缓存 |
| **字符设备** | `/dev/tty`、`/dev/random` | 字节流、不一定可 seek |
| 网络设备 | `eth0` | 特殊，走 socket 接口 |

- 设备文件用 **major/minor** 号找驱动；`udev` 负责在 `/dev` 下建节点，`sysfs` 暴露设备树
- **PIO**：CPU 用 `in/out` 一条条搬数据，慢
- **MMIO**：设备寄存器映射到内存地址，像访问内存一样访问
- **DMA**：设备直接把数据搬进/搬出内存，CPU 只负责设置描述符和收中断；**IOMMU** 负责地址翻译/隔离
- 中断处理分**上半部/下半部**：紧急的在中断上下文做，耗时的推后（softirq/工作队列）

## 2. 缓冲与 SPOOLing

**为什么需要缓冲**：

1. 速度不匹配（CPU 快、磁盘慢）
2. 粒度不匹配（进程按字节写，磁盘按块读写）
3. 减少系统调用/设备操作次数（攒一批再发）

| 类型 | 说明 |
|------|------|
| **单缓冲** | 一块缓冲，读写交替（不能同时） |
| **双缓冲** | 两块，一块读一块写（流水线，重叠） |
| **缓冲池** | 多个缓冲块统一管理（现代 OS 的做法） |

> 缓冲（buffer）是“临时存放”，缓存（cache）是“存一份复用”；页缓存既是缓存，也承担写回缓冲。

**SPOOLing（假脱机）**：经典例子是打印机。

```text
多个进程都要打印 → 先写进磁盘上的“输出井”（排队）
                → 后台进程按顺序真正打印
```

效果：把**独占设备**虚拟成**共享设备**——进程写完就返回，不用排队等打印机。

## 3. HDD：机械结构的代价

```text
盘片 → 磁道 → 扇区（512B / 4KB）
多个盘片同一磁道 → 柱面
```

- **LBA**：把盘面/磁道/扇区抽象成线性块号；文件系统只认 LBA
- **512e / 4Kn**：盘内部 4KB 扇区，对外模拟 512B（512e）或直接 4K（4Kn）；分区没对齐会影响性能
- **NCQ**：盘自己可以重排请求，减少寻道

**访问时间 = 寻道 + 旋转延迟 + 传输**：

| 部分 | 说明 | 量级 |
|------|------|------|
| **寻道** | 磁头移到目标磁道 | 几 ms，最慢 |
| 旋转延迟 | 等扇区转到磁头下 | 7200 RPM 平均约 4.17 ms |
| 传输 | 读写数据 | 取决于密度/接口 |

**所以 HDD 上顺序和随机差很多**：顺序读不用反复寻道，随机读每次都要等机械动作。

## 4. 磁盘调度

目标：**减少寻道**，别让磁头来回跳。

| 算法 | 做法 | 问题 |
|------|------|------|
| **FCFS** | 按请求顺序 | 简单；磁头来回跳，慢 |
| **SSTF** | 先处理**离当前最近**的 | 平均寻道短；远的请求可能**饿死** |
| **SCAN**（电梯） | 单向扫到底，再折返 | 公平；中间磁道被扫两次，占便宜 |
| **C-SCAN** | 只单向扫，回来时不服务 | 更公平；回程浪费 |
| **LOOK / C-LOOK** | 到最后一个请求就折返，不扫到底 | 比 SCAN/C-SCAN 少走路 |

**SCAN 为什么叫电梯**：像电梯一路向上、到顶再向下。

**现代系统**：

- Linux 块层有 `mq-deadline`、`kyber`、`bfq`、`none` 等调度器
- SATA/SAS 盘常用 `mq-deadline`；桌面交互可用 `bfq`
- NVMe 随机访问没有寻道，常用 `none`（不再排序）或轻量调度

> 调度只能减少寻道，不能改变介质物理；SSD 上“电梯算法”基本没意义。

## 5. SSD：没有机械部件，但有 FTL

SSD 的随机读 latency 在几十~几百微秒，比 HDD 的毫秒级好两个数量级；但它有自己的问题。

- **FTL（Flash Translation Layer）**：把 LBA 映射到物理页（PBA）
- **写前擦除**：闪存按页写、按块擦；改一页要先搬有效页、擦整块
- **磨损均衡**：把写分散到全盘，避免某些块先坏
- **GC**：回收无效页，搬有效页 → **写放大**
- **TRIM/discard**：告诉盘“这些块不用了”，减少 GC 搬无效数据
- **over-provisioning**：预留空间，给 GC 和坏块替换
- **NVMe**：走 PCIe，队列深度大，延迟低；SATA SSD 受 AHCI 限制

> SSD 的“顺序 vs 随机”差距比 HDD 小得多，但随机写仍可能触发 GC，尾延迟会抖。

## 6. RAID

RAID = 用多盘换**带宽/容量/可靠性**，但不是备份。

| 级别 | 做法 | 容量 | 容错 | 性能特点 |
|------|------|------|------|---------|
| **RAID 0** | 条带化 | 100% | ❌ 坏一块全完 | 读写带宽高 |
| **RAID 1** | 镜像 | 50% | ✅ 坏一块（每组） | 读快、写两份 |
| **RAID 5** | 条带 + 分布式校验 | (n-1)/n | ✅ 容错 1 块 | 读快；写有校验惩罚 |
| **RAID 6** | 双校验 | (n-2)/n | ✅ 容错 2 块 | 写惩罚更大；大容量阵列更稳 |
| **RAID 10** | 先镜像再条带 | 50% | ✅ 每镜像组 1 块 | 读写好、重建快 |

**RAID 5 的代价**：

- 小写要 **read-modify-write**：读旧数据/旧校验，算新校验，再写——写 IOPS 明显下降
- **写洞（write hole）**：掉电时数据和校验可能不一致；靠 BBU/日志/COW 缓解
- **重建慢**：大容量 HDD 重建要几小时到几天，期间再坏一块就完；还有 URE 风险

所以“RAID 5 最常用”要看场景：盘数少、容量优先时常见；大容量 HDD 阵列更倾向 **RAID 6 或 RAID 10**。

- **硬件 RAID**：RAID 卡带缓存/BBU，OS 看到一块逻辑盘；配置在卡里
- **软件 RAID**：`mdadm`、ZFS/Btrfs 的 RAID；灵活，吃 CPU/内存
- **热备盘**：坏盘后自动顶上重建
- **scrub**：定期校验/修复，别等重建时才发现另一块也坏了

> RAID 主要解决“盘坏”，不解决误删、勒索、机房火灾——**备份是另一回事**。

## 7. 要点回顾

1. **IO 栈**：用户 → 文件系统/VFS → 块层 → 驱动 → 中断/DMA → 硬件；上层统一、下层各异
2. **设备类型**：块设备可随机访问、字符设备是字节流；major/minor + `udev`/`sysfs`
3. **DMA/MMIO/中断**：DMA 让设备直接搬内存；中断分上半部/下半部
4. **缓冲**：解决速度/粒度不匹配；单缓冲 → 双缓冲 → 缓冲池；SPOOLing 把独占设备虚拟成共享
5. **HDD**：寻道 + 旋转 + 传输；顺序远快于随机；NCQ 可重排
6. **调度**：FCFS、SSTF（饿死）、SCAN/C-SCAN、LOOK/C-LOOK；SSD 上调度意义有限
7. **SSD**：FTL、磨损均衡、GC、写放大、TRIM、over-provisioning、NVMe
8. **RAID**：0 性能、1 镜像、5 单校验、6 双校验、10 镜像+条带；RAID 5 有写惩罚/写洞/重建风险
9. **RAID 不是备份**：热备、scrub、BBU 都只是降低故障概率，不替代备份
