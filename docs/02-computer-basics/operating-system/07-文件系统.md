# 文件系统

`rm` 掉一个正在写日志的文件，`df` 还是满的，`du` 又找不到——空间去哪了？

因为 `rm` 只是删掉了**目录项**；只要还有进程开着这个文件，inode 和数据块就不会释放。

## 1. 文件系统做什么

把磁盘“一堆块”的硬件，抽象成**目录树 + 文件**。

| 职责 | 说明 |
|------|------|
| **组织** | 数据块怎么分配、回收 |
| **命名** | 路径 → 文件 |
| **元数据** | 权限、大小、时间、属主、链接数 |
| **可靠性** | 崩溃后还能不能把结构修回来 |
| **共享/隔离** | 多进程打开同一文件、挂载命名空间 |

一句话：**文件 = 名字 + inode + 数据块**；目录的本质是“**名字 → inode 号**”的表。

## 2. inode 与目录项

**inode = 文件的“身份证”**：存**元数据 + 数据块位置**。

| 存什么 | 不存什么 |
|--------|---------|
| 类型、权限、属主 | **文件名**（在目录项里） |
| 大小、时间戳、链接数 | |
| 数据块指针 / extent 树 | |

- **目录项（dentry）**：目录里的一行，记录“文件名 → inode 号”
- **inode 号**：文件系统内唯一；`ls -i` 可以看
- **链接数**：有多少个目录项指向这个 inode；删到 0 且没有打开 fd，才释放数据
- **inode 也会用完**：`df -i` 看 inode 使用率；inode 耗尽时，磁盘还有空间也建不了新文件

**数据块指针**：

- 经典实现：直接块 → 一级间接 → 二级间接 → 三级间接（文件越大，用越高层）
- ext4 默认用 **extent（区段）树**：一个 extent 描述一段连续的块，比“每块一个指针”省得多；旧的间接块仍兼容

## 3. 硬链接 vs 软链接

```bash
ln a.txt b.txt        # 硬链接
ln -s a.txt c.txt     # 软链接（符号链接）
```

| | 硬链接 | 软链接 |
|--|-------|-------|
| 本质 | **指向同一个 inode** | 新文件，**内容是目标路径** |
| inode | 相同 | 不同 |
| 跨分区 | ❌ 不行 | ✅ 可以 |
| 指向目录 | ❌ 不允许 | ✅ 允许 |
| 目标删除后 | 只要还有其他硬链接，数据还在（链接计数减 1） | **悬空**（指向不存在的路径） |
| `ls -l` | 第二列链接数 +1 | 显示 `c.txt -> a.txt` |

**`unlink` 的语义**：删掉一个目录项，inode 链接数减 1；只有当链接数为 0 **且没有进程打开它**时，数据块才释放。硬链接只是多了一个名字，不是复制。

## 4. 文件描述符（fd）

fd 是一个小整数（0=stdin、1=stdout、2=stderr 默认占用）。

**打开文件的三张表**：

```text
fd（进程私有）──→ 打开文件表项（系统共享：偏移量、状态标志）──→ inode（文件系统：元数据 + 数据块位置）
```

| 表 | 作用域 | 内容 |
|----|--------|------|
| 进程 fd 表 | 每进程私有 | fd → 表项指针 |
| 系统打开文件表 | **系统共享** | 读写偏移、打开模式、引用计数 |
| inode 表 | 每个文件系统 | 文件元数据 |

**由此推出的行为**：

- `fork()` 后父子**共享文件偏移**（指向同一表项）
- `dup()` / `dup2()` 复制的 fd 也共享偏移
- 想独立偏移 → 重新 `open()`
- `O_APPEND` 让每次写都原子地追加到末尾
- `FD_CLOEXEC` 让 fd 在 `exec` 时自动关闭，避免泄漏

**回到开头的现象**：`rm` 后文件仍被打开 → 链接数 0，但打开文件表项还在 → 数据块不释放；`df` 仍算占用，`du` 走目录树看不到。`lsof +L1` 可以找出来。

## 5. 磁盘布局与块分配

**简化布局**：

```text
引导块 | 超级块 | inode 表 | 数据区
```

真实文件系统（ext4）会分**块组**，每组有自己的位图、inode 表和数据区；超级块有备份。

**块分配方式**：

| 方式 | 说明 | 问题 |
|------|------|------|
| 连续分配 | 文件占连续块 | **外部碎片**，扩展难 |
| 链式分配 | 每块存下一块指针 | 随机访问慢（要顺着链走） |
| **索引分配** | inode 存块指针 / extent | 元数据开销 |

- **extent**：用“起始块 + 长度”描述一段连续空间，减少指针数量
- **空闲空间**：用位图或 extent 树管理；分配时尽量连续，减少碎片
- **稀疏文件**：逻辑上有空洞，实际不占块；`ls -l` 看 apparent size，`du` 看实际占用

## 6. 一致性：日志、COW、fsck

断电/崩溃时，最怕“元数据改了一半”。

### 日志（Journaling）

**先把这次事务写进日志并提交，再回写实际位置**；崩溃后重放日志，保证要么全做、要么全不做。

- ext4 默认 `data=ordered`：数据先于元数据提交，避免元数据指向未写入的数据
- 其他模式：`data=journal`（数据和元数据都进日志，最慢最稳）、`data=writeback`（只保证元数据）
- `fsync` 负责把文件数据和必要元数据刷到持久存储

### 写时复制（COW）

**不覆盖旧块**：改数据时写新块，再原子地切换指针。

- 代表：Btrfs、ZFS
- 好处：**快照**天然便宜、校验和、崩溃一致性更好
- 代价：碎片、垃圾回收（GC）、写放大；随机写多时可能不如 ext4/XFS

### 日志结构（Log-structured）

**所有写都追加**，后台 GC 回收无效段。

- 代表：F2FS（面向 flash）
- 好处：顺序写、适合 SSD、减少随机写
- 代价：GC 开销、写放大、空间回收复杂

### fsck

离线一致性检查：扫描 inode/目录/位图，修复不一致。日志文件系统通常先重放日志，再做 fsck；COW 文件系统一般不需要传统 fsck。

| 方案 | 一致性手段 | 典型 |
|------|-----------|------|
| 日志 | 预写日志 + 重放 | ext4、XFS |
| COW | 写新块 + 原子指针切换 | Btrfs、ZFS |
| 日志结构 | 追加 + GC | F2FS |

## 7. 页缓存与写回

**读文件不是每次都读磁盘**——内核把读过的页缓存在内存里：

```text
读文件 → 先查页缓存
  · 命中 → 直接返回（不碰磁盘）
  · 未命中 → 从磁盘读进缓存 → 返回
```

- `write` 默认是**写缓存**（write-back）：先改页缓存，标记 dirty，攒够/到期再刷盘
- `fsync` 刷文件数据和元数据；`fdatasync` 只保证数据；`O_SYNC` 每次写都同步
- `rename` 在同一文件系统内是原子的；要保证掉电后仍然生效，文件和目录都要 `fsync`
- `mmap` 文件把页缓存直接映射进地址空间，省一次拷贝；`MAP_PRIVATE` 是 COW（写不影响文件），`MAP_SHARED` 的修改对其他映射可见并最终写回文件
- 顺序读会触发 **readahead**，提前把后面的页读进来

> 所以“写完就断电”可能丢数据；要持久化，必须 `fsync`（必要时连目录也 fsync）。

## 8. VFS 与挂载

**VFS（虚拟文件系统）**：一层抽象，让 `open/read/write` 对**所有文件系统**（ext4/XFS/NFS/proc…）用同一套接口。

| VFS 对象 | 代表什么 | 作用 |
|----------|---------|------|
| **superblock** | 一个挂载的文件系统 | 块大小、根 inode、操作表 |
| **inode** | 一个文件 | 元数据、数据块位置 |
| **dentry** | 一个目录项 | 名字 → inode，带 dcache |
| **file** | 一次打开 | 偏移、标志、引用 |

- 向上：给应用统一 API；向下：各文件系统实现具体操作
- **dcache / icache / page cache** 分别缓存目录项、inode、文件页
- `/proc`、`/sys` 是虚拟文件系统，读写直接落到内核对象

**挂载（mount）**：把一个文件系统接到目录树的某个点。

```bash
mount /dev/sdb1 /mnt/data      # 把 sdb1 挂到 /mnt/data
umount /mnt/data
```

- **mount namespace** 让不同进程看到不同的挂载树——容器的基础之一
- **bind mount** 把已有目录再挂到别处，不复制数据
- **overlayfs** 把只读镜像层和可写层叠成一个目录，是容器镜像/根文件系统的基础
- NFS 等网络文件系统也通过 VFS 接入，所以 `cp`/`open` 用法不变

> “一切皆文件”是接口风格，不是字面意义：socket、pipe、设备都提供文件式接口，但语义各自不同。

## 9. 要点回顾

1. **文件系统职责**：组织、命名、元数据、可靠性；文件 = 名字 + inode + 数据块
2. **inode**：存元数据和块位置，**不存文件名**；目录项负责名字 → inode 号
3. **链接**：硬链接同 inode、不能跨分区；软链接是新文件、可悬空
4. **fd 三张表**：进程 fd 表 → 系统打开文件表 → inode；`fork`/`dup` 共享偏移
5. **`unlink` 语义**：链接数 0 且无打开 fd 才释放；`rm` 后空间没回来先查 `lsof +L1`
6. **块分配**：连续/链式/索引；ext4 用 extent；注意外部碎片和 inode 耗尽
7. **一致性**：日志（预写+重放）、COW（新块+快照）、日志结构（追加+GC）、fsck
8. **页缓存**：读缓存、write-back、`fsync` 才持久；`buff/cache` 可回收
9. **VFS**：superblock / inode / dentry / file 四个对象；mount namespace 是容器基础
