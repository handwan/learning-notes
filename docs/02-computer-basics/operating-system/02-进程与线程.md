# 进程与线程

一个浏览器标签页崩了，其他标签页为什么还在？一个线程崩了，为什么整个进程跟着挂？

答案在两种抽象的分工：**进程管隔离，线程管并发**。

## 1. 进程：隔离的执行实例

**进程 = 程序的一次执行**（地址空间 + 执行上下文 + 资源）。

- 程序是静态文件；进程是运行中的实例，同一个程序可以跑出多个进程
- 地址空间：代码段、数据段、堆、栈
- 执行上下文：寄存器、PC、栈指针
- 资源：fd、信号处理、权限、页表

内核用 **PCB**（Linux 是 `task_struct`）记录这些信息：PID、状态、寄存器、页表指针、打开的文件…

**为什么需要进程**：隔离。一个进程崩了、越界了，不该拖垮别人；资源也能按进程记账和限额。

## 2. 状态机：三种基本状态

| 转换 | 触发 |
|------|------|
| 创建 → 就绪 | 进程创建完成 |
| 就绪 → 运行 | 被调度器选中 |
| 运行 → 就绪 | **时间片用完** / 被更高优先级抢占 |
| 运行 → 阻塞 | 等 IO / 等事件 |
| 阻塞 → 就绪 | IO 完成 / 事件到达 |
| 运行 → 终止 | 退出 |

| 状态 | 含义 |
|------|------|
| **就绪** | 万事俱备，等 CPU |
| **运行** | 正占着 CPU |
| **阻塞** | 等 IO/事件——**给 CPU 也没用** |

**注意**：阻塞 ≠ 就绪。阻塞的进程即使有 CPU 也跑不了（数据没到）。

## 3. 线程：共享地址空间的执行流

线程是进程内的一条执行流：有自己的寄存器、栈、PC，但和同进程的其他线程共享地址空间和大部分资源。

| | 进程 | 线程 |
|--|------|------|
| 定义 | **资源分配/隔离**的单位 | **CPU 调度**的单位（经典模型） |
| 地址空间 | 各自独立 | **共享**同一进程的 |
| 切换开销 | 大（换页表，TLB/缓存影响大） | 小（同地址空间，主要换寄存器/栈） |
| 通信 | IPC（管道/共享内存/消息队列） | 直接读写共享变量（**要同步**） |
| 崩溃影响 | 只自己挂 | **整个进程挂** |
| 创建开销 | 大 | 小 |

| 线程共享 | 线程私有 |
|---|---|
| 地址空间、fd 表、cwd、信号处理函数、资源限制 | 寄存器/栈/PC、TLS、信号屏蔽字、`errno` |

> **一句话**：进程是“隔离的容器”，线程是“容器里干活的工人”。

> Linux 里调度单位都是 task；`tgid` 相同的 task 组成线程组，`getpid()` 返回 tgid——所以“内核完全不区分进程/线程”只是简化说法。

## 4. 上下文切换：到底切了什么

先分清两个概念：

| | 模式切换 | 上下文切换 |
|--|---------|-----------|
| 是什么 | 用户态 ↔ 内核态 | 从一个任务换到另一个任务 |
| 触发 | 系统调用、中断、异常 | 调度器选中另一个 task |
| 代价 | 保存/恢复少量寄存器、换栈 | 再加完整上下文；进程切换还要页表/TLB、缓存 |

**保存/恢复**：寄存器、PC、SP、FPU/SIMD 状态；进程切换还要换页表。

**开销来源**：

1. 保存/恢复寄存器（快）
2. 切换页表 → TLB 失效（PCID/ASID 可减少刷新）
3. **缓存变冷**（新任务的数据不在 cache 里）

| 切换 | 量级 |
|------|------|
| 模式切换 | ~0.1–1 µs |
| 线程切换 | ~1–5 µs |
| 进程切换 | 通常更贵，随工作集变化 |
| 协程切换 | ~几十–几百 ns |

> 数量级随硬件、内核、负载变化，用来建立尺度感，不要当 benchmark。

**触发时机**：

- 时间片用完（时钟中断）
- 进程阻塞（等 IO）
- 有更高优先级进程就绪
- 主动让出（`sched_yield`）

> **结论**：不是免费的操作——**线程不是越多越好**（切换本身也吃 CPU，还会挤占 cache）。

## 5. 线程模型与 Linux 实现

| 模型 | 说明 | 缺点 |
|------|------|------|
| 用户级线程 | 内核看不见，切换快 | 一个线程调阻塞系统调用，**全体阻塞** |
| 内核级线程 | 内核管理，能真并行 | 切换要进内核 |
| 混合模型 | 多对多映射 | 复杂 |

**Linux 的实现**：

- 调度单位是 **task**（`task_struct`），内核线程没有用户地址空间
- `clone()` 的标志决定共享什么：`CLONE_VM` 地址空间、`CLONE_FILES` fd 表、`CLONE_FS` cwd/root、`CLONE_SIGHAND` 信号处理、`CLONE_THREAD` 同线程组
- `tgid` 相同 = 同进程；`getpid()` 返回 tgid，`gettid()` 返回 task id

## 6. 协程：用户态调度

**用户态的轻量执行流**——切换不进内核，由程序/运行时自己调度。

| | 线程 | 协程 |
|--|------|------|
| 调度 | 内核**抢占式** | 用户态**协作式**（运行时也可能抢占，如 goroutine） |
| 切换开销 | 微秒级 | **纳秒级** |
| 数量级 | 几千 ~ 几万 | **几十万**（看栈大小） |
| 适合 | CPU 并行；阻塞 IO 可用线程池 | **高并发 IO**（配合非阻塞/异步） |

**为什么快**：不陷入内核、不切页表、栈小（KB 级）。

**边界**：

- 协程里直接调阻塞系统调用会卡住当前运行时线程；多数 runtime 用线程池兜底
- CPU 密集任务协程没有优势（单线程内不提供并行）
- Go 的 `goroutine` 有栈、可抢占，是 runtime 调度的绿色线程，不只是协程

推理服务的并发常用 Python `asyncio`、C++20 协程——它们解决的是“等 IO 时别占线程”。

## 7. 僵尸进程与孤儿进程

| | 定义 | 处理 |
|--|------|------|
| **僵尸**（Zombie） | 子进程已退出，但父进程**没 wait**（task_struct 残留） | 父进程 `wait()`；否则占 PID |
| **孤儿**（Orphan） | 父进程先退出 | 被 **init（PID 1）或最近的 subreaper** 收养 |

- 父进程可以处理 `SIGCHLD`，或循环 `waitpid(-1, ..., WNOHANG)` 回收
- 僵尸**杀不掉**（已经死了）——只能让父进程回收，或杀父进程让 init/subreaper 接手
- 容器里 PID 1 要负责回收，否则僵尸会堆积

## 8. 进程的创建与回收（fork / exec / wait）

### fork：复制当前进程

```c
pid_t pid = fork();
if (pid == 0) {
    /* 子进程 */
} else if (pid > 0) {
    /* 父进程，pid 是子进程的 PID */
} else {
    /* 出错 */
}
```

**为什么“调用一次、返回两次”**：fork 之后，父子进程都从 fork 处继续往下执行——靠返回值区分“我到底是谁”。

**fork 干了什么**：

- 复制父进程的 PCB 和页表，页表项指向同一物理页（**写时复制**，写时才真拷）
- 子进程有**新的 PID**，继承父进程的 fd、环境变量、信号处理等

**多线程程序 fork 的坑**：子进程里只有调用 fork 的那个线程；其他线程持有的锁可能永远不释放。通常 fork 后尽快 `exec`，或用 `posix_spawn`。

### exec：替换成另一个程序

`exec` 系列**不创建新进程**——它把当前进程的**地址空间整个换成新程序**（代码/数据/栈全换），**PID 不变**。

- fd 默认保留（除非设了 `FD_CLOEXEC`）
- 捕获的信号处理重置为默认

### 为什么 fork 和 exec 要分开

`fork` 之后、`exec` 之前，子进程可以**先改环境**：

- 用 `dup2` 重定向 stdin/stdout
- 改工作目录、设置信号处理、调整资源限制

> 这就是 shell 实现**管道和重定向**的方式（`ls | grep` 就是在中间改 fd）。

`posix_spawn` 把 fork+exec 打包，避免复制大地址空间（内部可能用 `vfork`/`clone`）。

### wait：回收子进程

- 父进程调 `wait()` / `waitpid()` **回收**子进程的退出状态
- **不回收 → 子进程变僵尸**（task_struct 残留）
- `waitpid` 可指定 PID、可用 `WNOHANG` 非阻塞
- 退出状态用 `WIFEXITED` / `WEXITSTATUS` 解析

### 守护进程（daemon）

**脱离终端、后台长驻**的进程。经典做法：

```text
fork() → 父进程退出（子进程被 init 收养）
       → setsid() 开新会话、脱离控制终端
       → 再 fork()（可选，确保不是会话首进程）
       → chdir("/") + 重定向 stdin/stdout/stderr 到 /dev/null
```

现代 systemd 服务通常不用自己 daemonize，`Type=simple` 托管即可。

### 一句话

> **fork 复制、exec 替换、wait 回收**。

## 9. 演进：为什么会有线程和协程

- **进程**：隔离和资源记账，但创建、切换、通信都重
- **线程**：共享地址空间，切换和通信便宜，能利用多核；代价是一个线程崩了整个进程挂
- **用户级线程**：把切换搬到用户态，快；但阻塞系统调用会卡住整个进程（除非配合非阻塞 IO）
- **内核级/混合**：内核看得见，能真并行；切换要进内核
- **协程/goroutine**：用户态调度 + 小栈，适合高并发 IO；CPU 密集和阻塞调用仍是边界

一条线：**隔离越强，切换和通信越贵；并发越高，越倾向于用户态调度。**

## 10. 要点回顾

1. **进程 vs 线程**：隔离/共享、切换、通信、崩溃影响
2. **上下文切换**：模式切换 ≠ 任务切换；页表/TLB、cache；线程不是越多越好
3. **线程模型**：用户级/内核级/混合；Linux 的 task、`tgid`、`clone` 标志
4. **协程**：用户态协作、纳秒级、适合高并发 IO；阻塞调用和 CPU 密集是边界
5. **僵尸/孤儿**：`wait` 回收；`SIGCHLD`；init/subreaper；容器 PID 1 要回收
6. **fork/exec/wait**：返回两次、COW、PID 不变、fd/`CLOEXEC`、`WNOHANG`
7. **守护进程**：fork + setsid + 重定向；现代用 systemd 托管
8. **演进主线**：隔离强度和切换/通信开销之间的取舍
