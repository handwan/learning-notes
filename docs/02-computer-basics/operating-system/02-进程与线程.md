# 进程与线程

## 1. 进程是什么

**进程 = 运行中的程序**（代码 + 数据 + 资源）。

组成：

- **地址空间**：代码段、数据段、堆、栈
- **PCB（进程控制块）**：PID、状态、寄存器、页表指针、打开的文件…
- 其他资源：文件描述符、信号处理、权限

## 2. 进程状态机

**状态转换**：

| 转换 | 触发 |
|------|------|
| 创建 → 就绪 | 进程创建完成 |
| 就绪 → 运行 | 被调度器选中 |
| 运行 → 就绪 | **时间片用完** / 被更高优先级抢占 |
| 运行 → 阻塞 | 等 IO / 等事件 |
| 阻塞 → 就绪 | IO 完成 / 事件到达 |
| 运行 → 终止 | 退出 |

**三种基本状态**：

| 状态 | 含义 |
|------|------|
| **就绪** | 万事俱备，等 CPU |
| **运行** | 正占着 CPU |
| **阻塞** | 等 IO/事件——**给 CPU 也没用** |

**注意**：阻塞 ≠ 就绪。阻塞的进程即使有 CPU 也跑不了（数据没到）。

## 3. 进程 vs 线程

| | 进程 | 线程 |
|--|------|------|
| 定义 | **资源分配**的单位 | **CPU 调度**的单位 |
| 地址空间 | 各自独立 | **共享**同一进程的 |
| 切换开销 | 大（换页表 + 刷 TLB） | 小（同地址空间） |
| 通信 | IPC（管道/共享内存/消息队列） | 直接读写共享变量（**要同步**） |
| 崩溃影响 | 只自己挂 | **整个进程挂** |
| 创建开销 | 大 | 小 |

> **一句话**：进程是"隔离的容器"，线程是"容器里干活的工人"。

## 4. 上下文切换

**要保存/恢复什么**：寄存器、PC、栈指针、（进程切换时）页表。

**开销来源**：

1. 保存/恢复寄存器（快）
2. **切换页表 + 刷 TLB**（进程切换最贵）
3. **缓存变冷**（新任务的数据不在 cache 里）

**触发时机**：

- 时间片用完（时钟中断）
- 进程阻塞（等 IO）
- 有更高优先级进程就绪
- 主动让出（`sched_yield`）

> **结论**：不是免费的操作——**线程不是越多越好**（切换本身也吃 CPU）。

## 5. 线程模型

| 模型 | 说明 | 缺点 |
|------|------|------|
| 用户级线程 | 内核看不见，切换快 | **一个阻塞，全体阻塞** |
| 内核级线程 | 内核管理，能真并行 | 切换要进内核 |
| 混合模型 | 多对多映射 | 复杂 |

**Linux 的实现**：

- 用 `task_struct` 描述"调度单位"，**内核不区分进程/线程**
- 都是 task，**共享程度不同**（`clone()` 传不同标志）
- 共享地址空间/文件表 = "线程"；不共享 = "进程"

## 6. 协程

**用户态的轻量级"线程"**——切换不进内核，由程序自己调度。

| | 线程 | 协程 |
|--|------|------|
| 调度 | 内核**抢占式** | 用户态**协作式**（主动让出） |
| 切换开销 | 微秒级 | **纳秒级** |
| 数量级 | 几千 ~ 几万 | **几十万** |
| 适合 | CPU 密集 + 阻塞 IO | **高并发 IO** |

**为什么快**：不陷入内核、不切页表、栈小（KB 级）。

**对 AI 方向**：推理服务的并发（Python `asyncio`、C++20 协程）都用它。

> 注：Go 的 `goroutine` 常和协程一起讨论，但严格说是 **runtime 调度的绿色线程**（有栈、可抢占），不只是协程。

## 7. 僵尸进程与孤儿进程

| | 定义 | 处理 |
|--|------|------|
| **僵尸**（Zombie） | 子进程已退出，但父进程**没 wait**（PCB 残留） | 父进程 `wait()`；否则占 PID |
| **孤儿**（Orphan） | 父进程先退出 | 被 **init（PID 1）收养** |

> 僵尸进程**杀不掉**（已经死了）——只能让父进程回收，或杀父进程。

## 8. 进程的创建与回收（fork / exec / wait）

### fork：复制当前进程

```c
pid_t pid = fork();
// 父进程：pid > 0（返回子进程的 PID）
// 子进程：pid == 0
// 出错：  pid < 0
```

**为什么"调用一次、返回两次"**：fork 之后，**父子进程都从 fork 处继续往下执行**——靠返回值区分"我到底是谁"。

**fork 干了什么**：

- 复制父进程的 PCB、地址空间（**靠写时复制，不真拷内存**）
- 子进程有**新的 PID**，但继承父进程的 fd、环境变量等

### exec：替换成另一个程序

`exec` 系列**不创建新进程**——它把当前进程的**地址空间整个换成新程序**（代码/数据/栈全换），**PID 不变**。

### 为什么 fork 和 exec 要分开

`fork` 之后、`exec` 之前，子进程可以**先改环境**：

- 用 `dup2` 重定向 stdin/stdout
- 改工作目录、设置信号处理、调整资源限制

> 这就是 shell 实现**管道和重定向**的方式（`ls | grep` 就是在中间改 fd）。

### wait：回收子进程

- 父进程调 `wait()` / `waitpid()` **回收**子进程的退出状态
- **不回收 → 子进程变僵尸**（PCB 残留）
- `waitpid` 可指定 PID、可用 `WNOHANG` 非阻塞

### 守护进程（daemon）

**脱离终端、后台长驻**的进程。经典做法：

```
fork() → 父进程退出（子进程被 init 收养）
       → setsid() 开新会话、脱离控制终端
       → chdir("/") + 重定向 stdin/stdout/stderr 到 /dev/null
```

### 一句话

> **fork 复制、exec 替换、wait 回收**。
