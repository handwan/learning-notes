# 进程间通信

`ps aux | grep nginx` 为什么能把两个程序的输出接起来？两个进程的地址空间互相隔离，数据到底怎么过去？

IPC 有两条路：**内核中转**（拷贝）和**共享区域**（映射）。

## 1. 两类 IPC

| 方式 | 数据路径 | 代价 | 例子 |
|------|---------|------|------|
| **消息传递** | 用户 → 内核 → 用户 | **2 次拷贝** | 管道、消息队列、socket |
| **共享内存** | 映射后直接读写 | **0 次数据拷贝** | `shm`、`mmap` |

- 消息传递由内核中转：隔离好、能做权限和阻塞，但每次都要拷；是否有消息边界取决于机制（管道没有，消息队列/数据报有）
- 共享内存把同一批物理页映射进两个地址空间：数据不拷，但**同步要自己做**

还有一类不算“传数据”的机制：**信号**、信号量、eventfd——它们只做通知/同步。

## 2. 管道与 FIFO

| | 匿名管道（pipe） | 命名管道（FIFO） |
|--|-----------------|-----------------|
| 创建 | `pipe()` | `mkfifo()` |
| 名字 | 无 | 文件系统路径 |
| 使用关系 | 通常靠 `fork` 继承 fd | 任意有权限的进程 |
| 生命周期 | 所有 fd 关闭后消失 | 节点保留到 `unlink` |

- 本质：**内核里的一块缓冲区**，两端各一个 fd
- **单向**：要双向就开两根；`socketpair` 才是一对双向 fd
- **字节流，无消息边界**：读到的可能是半条消息，要自己 framing
- 匿名管道通常只能给有亲缘关系的进程；但 fd 可以通过 Unix socket 传给无关进程

**几个容易踩的边界**：

- 管道容量有限（Linux 默认 64KB，可调）；写满后 `write` 阻塞，`O_NONBLOCK` 下返回 `EAGAIN`
- 单次 `write` 不超过 `PIPE_BUF`（Linux 4KB）才保证原子；更大的写可能和别的写交错
- 所有写端关闭后，读端 `read` 返回 0（EOF）；所以**没用的端要尽早 close**
- 读端全关了还写，会收到 `SIGPIPE`（默认终止进程），或返回 `EPIPE`
- `pipe2(O_CLOEXEC | O_NONBLOCK)` 可以一次设好标志，避免 fd 泄漏到 `exec`

典型用法：shell 的 `ls | grep`、父子进程传数据。

## 3. 消息队列

- 内核维护的**队列**，按“消息”为单位读写
- **有边界**：一次读一条；消息太大要分批或调大限制
- **可分类/带优先级**：System V 按类型取，POSIX 按优先级
- 数据同样要 **2 次拷贝**（用户 → 内核 → 用户）
- 内核对象有生命周期：POSIX 到 `mq_unlink`，System V 到 `msgctl(IPC_RMID)`；进程退出消息还在

POSIX 接口是 `mq_open` / `mq_send` / `mq_receive`；System V 是 `msgget` / `msgsnd` / `msgrcv`。

适合“消息有结构、要分类、要跨进程解耦”的场景；不适合大块数据。

## 4. 共享内存

思路：内核管理一组共享页，两个进程都把它映射进自己的地址空间。

```text
shm_open → ftruncate → mmap(MAP_SHARED)     # POSIX
shmget → shmat                              # System V
mmap(MAP_SHARED | MAP_ANONYMOUS)            # 匿名，fork 后父子共享
```

- **数据读写不经过系统调用、不做内核拷贝**——这是“最快”的来源
- 但**页错误、页表/TLB 维护、同步**仍可能进内核；第一次访问会缺页
- **必须自己同步**：信号量、进程共享 mutex、文件锁；否则就是数据竞争
- 信号量只做同步：POSIX 命名信号量 `sem_open` 可跨进程；匿名 `sem_init(pshared=1)` 要放在共享内存里
- 进程共享 mutex 要设 `PTHREAD_PROCESS_SHARED`；持有者崩溃时可用 robust mutex
- 名字用 `shm_unlink` 删除后，已建立的映射仍然有效，直到 `munmap`

> “共享内存最快”有前提：**数据量大、竞争低**。小消息加两次拷贝可能比“映射 + 加锁 + 唤醒”更便宜。

## 5. 信号

- 只是**通知**（“有事发生”），不是数据通道
- **标准信号不排队**：同一信号连续来可能丢；实时信号（`SIGRTMIN` 起）会排队
- `sigqueue` 可以带一个 `sigval`（整数/指针），但只有配实时信号才保证排队；别指望用它传大块数据
- 处理函数是异步的，只能调用 **async-signal-safe** 函数；共享标志用 `volatile sig_atomic_t`
- 多线程里更推荐 `sigwait` / `signalfd`，把信号变成同步读取，避免处理函数里踩坑

典型用法：`SIGCHLD` 通知子进程退出、`SIGTERM` 请求退出、`SIGUSR1` 触发重载。

## 6. socket

| | AF_UNIX | AF_INET / AF_INET6 |
|--|---------|-------------------|
| 范围 | 本机 | 跨主机 |
| 地址 | 文件路径 / 抽象命名空间 | IP + 端口 |
| 性能 | 通常比 TCP loopback 快（少走 TCP/IP 栈） | 受协议栈和网络影响 |
| 用途 | 本机 RPC、fd 传递 | 网络服务 |

- 支持 `SOCK_STREAM`（字节流）、`SOCK_DGRAM`（数据报）、`SOCK_SEQPACKET`（有边界）
- `socketpair()` 一次拿到一对**双向** fd，父子进程常用
- **`SCM_RIGHTS` 可以传 fd**：接收方拿到一个新 fd，指向同一个打开文件描述；这是“主进程收连接、worker 处理”的经典手法
- Linux 的**抽象命名空间**（地址以 `\0` 开头）不落文件系统，没有路径权限，靠网络命名空间隔离

socket 的数据同样要经过内核缓冲区，通常是 **2 次拷贝**；跨主机时还要加上协议栈和网络延迟。

## 7. 对比与选型

| 机制 | 方向 | 边界 | 数据拷贝 | 跨主机 | 生命周期 | 阻塞/同步 |
|------|------|------|---------|--------|---------|------|
| 管道 / FIFO | 单向 | 字节流 | 2 | 否 | 随 fd / 文件节点 | 阻塞、EOF |
| 消息队列 | 多对多 | 消息 | 2 | 否 | 内核对象 | 阻塞；按优先级/类型取 |
| 共享内存 | 双向 | 原始字节 | **0** | 否 | 对象/映射 | **自己做** |
| 信号 | 通知 | 无/极少 | — | 否 | 事件 | 异步 |
| AF_UNIX socket | 双向 | 字节流/消息 | 2 | 否 | 套接字 | 可选 |
| TCP / UDP | 双向 | 字节流/消息 | 2 | **是** | 套接字 | 可选 |

选型可以按这几个问题走：

- 父子进程、简单数据 → 管道
- 消息有结构、要分类 → 消息队列
- 大块数据、高吞吐 → 共享内存 + 信号量/进程共享锁
- 只通知事件 → 信号、eventfd
- 本机通用、要传 fd → AF_UNIX socket
- 跨机器 → TCP / UDP

## 8. 常见坑

- **管道**：忘了 close 不用的端 → 读端等不到 EOF；写超过 `PIPE_BUF` → 交错；不处理 `SIGPIPE` → 进程被杀
- **消息队列**：消息大小/队列长度有上限；消息会一直留在内核，直到删除
- **共享内存**：不同步 → 数据竞争；忘记 `shm_unlink` → 残留对象；权限没设好 → 别的用户能读写
- **socket**：字节流没有边界 → 要自己 framing；`read`/`write` 可能只处理一部分 → 循环；传 fd 忘关 → 泄漏
- **信号**：标准信号会丢；处理函数里调用非 async-signal-safe 函数 → 未定义行为；多线程里信号投递给哪个线程不确定
- **fd 泄漏**：`fork`/`exec` 前没设 `CLOEXEC`，子进程会继承一堆没用的 fd

## 9. 现代 Linux 的补充

这些机制把“事件/内存”统一成 fd，方便塞进 `epoll`：

| 机制 | 用途 |
|------|------|
| `eventfd` | 64 位计数器，读写/poll，做事件通知 |
| `signalfd` | 把信号变成可读 fd |
| `timerfd` | 定时器到期变成可读 fd |
| `memfd_create` | 匿名内存文件，可配合 `SCM_RIGHTS` 传 fd |
| `SCM_RIGHTS` | Unix socket 传文件描述符 |
| `pipe2` | 创建管道时直接带 `O_CLOEXEC`/`O_NONBLOCK` |

## 10. 要点回顾

1. **两类 IPC**：消息传递（2 次拷贝）vs 共享内存（0 次数据拷贝，但要同步）
2. **管道/FIFO**：单向字节流；`PIPE_BUF` 原子写、EOF、`SIGPIPE`、close 不用的端
3. **消息队列**：有边界、可分类/优先级、内核持久、2 次拷贝
4. **共享内存**：映射后直接读写；信号量/进程共享 mutex 同步；注意生命周期和权限
5. **信号**：通知而非数据；标准信号会丢、实时信号排队；`sigqueue` 只能带很小的值
6. **socket**：AF_UNIX 本机、AF_INET 跨主机；`socketpair` 双向；`SCM_RIGHTS` 传 fd
7. **选型**：看数据量、边界、方向、跨主机、同步需求；“最快”要结合竞争和消息大小
8. **常见坑**：EOF/SIGPIPE、framing、部分读写、fd 泄漏、共享内存不同步
