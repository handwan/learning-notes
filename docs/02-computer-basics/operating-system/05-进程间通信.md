# 进程间通信

## 1. 为什么需要 IPC

进程之间**地址空间互相隔离**——这是好事（安全），也是麻烦（不能直接读写对方内存）。

要协作，就得靠**内核中转**或**共享区域**。

## 2. 五种主要方式

| 方式 | 方向 | 特点 |
|------|------|------|
| **管道** | **单向** | 简单；父子进程最常用 |
| **消息队列** | 双向 | 有消息边界；内核维护 |
| **共享内存** | 双向 | **最快**（不经过内核拷贝） |
| **信号** | 单向通知 | 只"通知"，不带数据 |
| **socket** | 双向 | **唯一能跨主机** |

### 管道（Pipe）

- **匿名管道**：`pipe()` 创建，只能**有亲缘关系**的进程用（父子/兄弟）
- **命名管道（FIFO）**：`mkfifo`，无亲缘也能用
- 本质：**内核里的一块缓冲区**，两端各一个 fd
- 局限：**只能单向传**（双向要两根；教材常写"半双工"）、**无消息边界**（是字节流）

### 消息队列

- 内核维护的**链表**，按"消息"为单位读写
- **有边界**（一次读一条），可以按类型取
- 缺点：数据要**两次拷贝**（用户 → 内核 → 用户）

### 共享内存（最快）

```
内核分配一块物理内存 → 两个进程都把它映射进自己的地址空间
```

- 读写**完全不经过内核**（直接内存访问）→ **最快**
- **代价**：必须**自己同步**（配信号量/互斥锁），否则数据竞争

### 信号（Signal）

- 只是**通知**（"有事发生"），**不能带数据**
- 异步、可能丢失（不可靠）

### socket

- **唯一能跨主机**的方式
- 本机进程间也能用（`AF_UNIX`），比走 TCP 环路快

## 3. 怎么选

| 需求 | 选 |
|------|----|
| 父子进程传数据 | 管道 |
| **高吞吐、大数据** | **共享内存**（自己加锁） |
| 消息有结构/要分类 | 消息队列 |
| 只通知事件 | 信号 |
| 跨机器 / 通用 | socket |

**为什么共享内存最快**：数据**不经过内核拷贝**（管道/消息队列都要 2 次拷贝：用户→内核→用户）。

## 4. 和"线程通信"对比

| | 线程 | 进程 |
|--|------|------|
| 地址空间 | **共享** | 隔离 |
| 通信 | 直接读写变量 | 必须 IPC |
| 代价 | 要**同步**（防竞争） | 要**拷贝/映射** |

3. **匿名管道 vs 命名管道**、为什么是单向
4. **进程通信 vs 线程通信**的本质区别
