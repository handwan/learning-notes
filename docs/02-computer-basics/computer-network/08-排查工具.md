# 排查工具

网络出问题时，用这几个工具按"**从下往上**"排查。

## 1. ping：通不通

```bash
ping example.com            # 对方是否可达 + 延迟
ping -c 4 example.com       # 只发 4 个包（不然一直发）
```

**看什么**：有没有回复（通不通）、延迟多少、丢包率。

## 2. traceroute：路径

```bash
traceroute example.com      # 经过哪些路由器（逐跳）
```

**看什么**：在哪一跳开始不通/变慢（定位是本地网络、运营商还是对方的问题）。

## 3. ss / netstat：连接和端口

```bash
ss -tlnp                    # 看本机监听（Listening）的 TCP 端口
ss -tnp                     # 看已建立的 TCP 连接
ss -s                       # 连接统计（各种状态计数）
```

```text
-t TCP   -u UDP   -l 只监听   -n 不解析域名   -p 显示进程
```

**看什么**：

- 服务有没有起来（`-l` 有没有那个端口）
- 连接多不多、**CLOSE_WAIT / TIME_WAIT 数量**（见 [TCP](04-TCP.md)）

## 4. tcpdump：抓包

```bash
sudo tcpdump -i eth0 port 80            # 抓 eth0 上 80 端口的包
sudo tcpdump -i any host 1.2.3.4        # 抓和某个 IP 的往来
sudo tcpdump -i any port 8080 -w a.pcap # 存文件（用 Wireshark 看）
```

**看什么**：握手是否成功、有没有重传（`retransmission`）、RST（被拒绝）。

## 5. curl / telnet：测服务

```bash
curl -v http://example.com       # 看完整请求/响应（含状态码、头）
curl -v https://example.com      # 顺便能看 TLS 握手过程
telnet example.com 80            # 测端口通不通（能不能建立连接）
```

**看什么**：HTTP 状态码、响应头、证书信息；`telnet` 通了说明 TCP 层没问题。

## 6. 分层排查思路

**从下往上**（哪层坏了修哪层）：

```text
① 网卡通不通？      → ping 网关 / ping 8.8.8.8
② DNS 通不通？      → ping 域名 / nslookup 域名
③ 端口通不通？      → telnet host port / nc -vz host port
④ 服务正常吗？      → curl -v http://host:port
⑤ 数据对不对？      → tcpdump 抓包看
```

| 现象 | 可能原因 |
|------|---------|
| ping 网关不通 | 本机网络/网卡问题 |
| ping IP 通、域名不通 | **DNS 问题** |
| 端口不通 | 服务没起 / 防火墙 / 安全组 |
| 连上了但请求超时 | 服务处理慢 / 后端卡住 |
| 大量 CLOSE_WAIT | **代码漏 close**（见 TCP 篇） |
| 大量 TIME_WAIT | 短连接太多 / 本端频繁主动关 |

## 7. 要点回顾

1. **ping**（通不通）、**traceroute**（哪一跳）
2. **ss -tlnp** 看监听、**ss -s** 看状态计数（CLOSE_WAIT/TIME_WAIT）
3. **tcpdump** 抓包：看握手、重传、RST
4. **curl -v / telnet** 测应用服务
5. **排查顺序**：网卡 → DNS → 端口 → 服务 → 数据（从下往上）
