# 网络安全

## 1. 加密基础

### 对称加密 vs 非对称加密

| | 对称加密 | 非对称加密 |
|--|---------|-----------|
| 密钥 | **同一把**（双方共享） | **公钥 + 私钥** |
| 速度 | **快** | 慢（慢几个数量级） |
| 例子 | AES、ChaCha20 | RSA、ECC |
| 用途 | **传数据** | **交换密钥**、签名 |

### 数字签名

- **私钥签名、公钥验证** → 证明"是谁发的 + 内容没被改"
- 和加密**方向相反**：加密是"公钥加密、私钥解密"

```text
加密：公钥加密 → 只有私钥能解（保密）
签名：私钥签名 → 只有公钥能验（认证）
```

### 证书与 CA

**证书 = 公钥 + 身份信息 + CA 的签名**

- CA（证书颁发机构）用自己的私钥给"你的公钥 + 域名"签名
- 浏览器内置 CA 公钥 → 能验证证书真伪 → **防冒充**

## 2. HTTPS 的加密链条（回顾）

```text
非对称加密（交换会话密钥）
   → 对称加密（传数据）
   → 证书 + CA（防中间人冒充）
```

详见 [HTTP 与 HTTPS](06-HTTP与HTTPS.md)。

## 3. 常见攻击

| 攻击 | 原理 | 防御 |
|------|------|------|
| **DDoS** | 海量流量/请求打垮服务 | 流量清洗、CDN、限流 |
| **SYN Flood** | 发大量 SYN 不完成握手 → **占满半连接队列** | **SYN Cookie**、缩短超时 |
| **XSS**（跨站脚本） | 往页面注入 JS → 偷 Cookie | 输出转义、CSP |
| **CSRF**（跨站请求伪造） | 借用用户的 Cookie 发请求 | CSRF Token、SameSite Cookie |
| **SQL 注入** | 拼接 SQL → 偷/改数据 | **参数化查询**（预编译） |
| **中间人**（MITM） | 劫持通信、冒充双方 | **HTTPS + 证书校验** |

### SYN Flood 细节（和 TCP 握手相关）

```text
正常：客户端 SYN → 服务端分配资源、回 SYN+ACK → 客户端 ACK（完成）
攻击：攻击者发海量 SYN，但**不回最后的 ACK**
      → 服务端半连接队列被占满 → 正常用户连不上
```

**SYN Cookie**：服务端**先不分配资源**，把状态编码进 SYN+ACK 的序号里；收到 ACK 再验证并分配 → 抗 SYN Flood。

## 4. 防火墙

| 类型 | 干什么 |
|------|--------|
| **包过滤** | 按 IP / 端口 / 协议放行或拒绝 |
| **状态检测** | 记住连接状态（只放行"回包"） |
| **WAF**（应用层） | 防 XSS / SQL 注入等应用层攻击 |

## 5. 要点回顾

1. **对称加密快（传数据）、非对称慢（换密钥/签名）**
2. **数字签名**：私钥签、公钥验；**证书**：CA 背书防冒充
3. **常见攻击**：DDoS、SYN Flood、XSS、CSRF、SQL 注入、MITM
4. **SYN Flood 防御**：**SYN Cookie**（不提前分配资源）
5. **防火墙**：包过滤 / 状态检测 / WAF
