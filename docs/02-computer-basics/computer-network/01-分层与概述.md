# 分层与概述

## 1. 为什么要分层

网络通信很复杂（网线、IP、TCP、HTTP……），分成几层，**每层只管一件事**：

- 解耦：改一层不影响别的层
- 各司其职：物理层管信号，传输层管可靠，应用层管业务

**类比**：寄快递——你只管填地址（应用层），快递公司负责运输（网络层），公路铁路是基础设施（物理层）。

## 2. OSI 七层 vs TCP/IP 四层

| OSI 七层 | TCP/IP 四层 | 干什么 | 例子 |
|----------|------------|--------|------|
| 应用层 | **应用层** | 业务协议 | HTTP、DNS、SMTP |
| 表示层 | （并入应用层） | 编码/加密/压缩 | — |
| 会话层 | （并入应用层） | 会话管理 | — |
| 传输层 | **传输层** | 端到端（进程到进程） | **TCP、UDP** |
| 网络层 | **网络层** | 主机到主机（寻址+路由） | **IP**、ICMP |
| 数据链路层 | **网络接口层** | 相邻设备之间 | 以太网、MAC |
| 物理层 | （同上） | 电信号/光信号 | 网线、网卡 |

**实际用的**：TCP/IP 四层（OSI 七层是教学模型）。

## 3. 每一层在干什么（用"发一个 HTTP 请求"串一遍）

```text
你输入网址 → HTTP 生成请求（应用层）
→ TCP 加上序号、端口（传输层）
→ IP 加上源/目的 IP（网络层）
→ 以太网加上 MAC 地址（链路层）
→ 网卡发出去（物理层）
```

## 4. 封装与解封装

**发送方**：每下一层，加一个"头"（头里是该层需要的信息）：

```text
[HTTP 请求]
[TCP头][HTTP 请求]                    ← 加 TCP 头（端口、序号）
[IP头][TCP头][HTTP 请求]              ← 加 IP 头（源/目的 IP）
[以太网头][IP头][TCP头][HTTP]...[校验] ← 加帧头（MAC）
```

**接收方**：反过来，一层层剥头 → **解封装**。

**各层数据单位**：

| 层 | 单位 | 记法 |
|----|------|------|
| 应用层 | 报文（message） | — |
| 传输层 | **段**（segment，TCP）/ 数据报（UDP） | — |
| 网络层 | **包**（packet） | — |
| 链路层 | **帧**（frame） | — |

## 5. 要点回顾

1. **分层 = 每层只管一件事**（解耦、各司其职）
2. **OSI 七层 vs TCP/IP 四层**，实际用四层
3. **封装**：发送时逐层加头；接收时逐层剥头
4. 各层数据单位：段（TCP）/ 包（IP）/ 帧（链路）
