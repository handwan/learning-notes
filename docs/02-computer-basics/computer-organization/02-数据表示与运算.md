# 数据表示与运算

整数补码、浮点 IEEE 754、量化、字节序——**写 C++/做 AI 部署时真正会咬人的那些表示问题**。

## 1. 整数：补码与溢出

**补码**（现代计算机统一用它）：正数原样，负数 = "取反加一"；好处是**加减法统一**、只有一个 0。

```c
printf("%d\n", INT_MIN);              // -2147483648
printf("位模式: 0x%08x\n", (unsigned)INT32_MIN);   // 0x80000000（最高位是符号位）
printf("-1 按无符号解释: %u\n", (unsigned)-1);      // 4294967295
```

**溢出**：

- **无符号**：定义行为（模 2³² 回绕）——实测 `4294967295 + 1 == 0`
- **有符号**：**未定义行为（UB）**——编译器可以假设"不会溢出"来优化

```c
// 溢出判断（做加法后判断符号是否翻转 —— 教材要背、代码里用内置检测）
if (__builtin_add_overflow(a, b, &c)) { /* 溢出 */ }
```

**移位**：`<<` 左移等于乘 2 的幂（对无符号安全）；有符号左移溢出同样是 UB；`>>` 对负数"实现定义"（常见算术右移）。

## 2. IEEE 754 浮点：结构

```
double（64 位）：| 1 符号 | 11 阶码（偏移 1023） | 52 尾数（隐含 1.xxx） |
float （32 位）：| 1 符号 |  8 阶码（偏移 127）  | 23 尾数              |
```

**能表示什么、精度多少**：

| 事实 | 实测 |
|------|------|
| float 约 7 位十进制有效数字、double 约 16 位 | `1.0f + 1e-8f == 1.0f`（吃掉）；`1.0 + 1e-16` 仍是 1.0 |
| float 从 2²⁴ 起整数不再连续 | `16777216.0f + 1.0f == 16777216.0f` |
| 0.1 不是精确值 | `0.1 + 0.2 = 0.30000000000000004441`（位模式 `0x3fd3333333333334`，0.3 是 `…333`） |

**特殊值**（实测）：

| 表达式 | 结果 |
|--------|------|
| `1.0/0.0` | `inf` |
| `-1.0/0.0` | `-inf` |
| `0.0/0.0` | `NaN` |
| `NaN == NaN` | **false**（判断要用 `isnan()`） |

**denormal（非规格化数）**：阶码全 0 时尾数不再隐含 1，用来表示更小的数，但**精度骤降**：

```
FLT_MIN       = 1.175e-38（规格化最小）
FLT_TRUE_MIN  = 1.401e-45（denormal 最小）
→ 从 1.18e-38 到 1.4e-45 之间是 denormal 区，精度越来越差（有些硬件上还会变慢）
```

**工程注意**：`float` 比较用容差（`fabs(a-b) < eps`）；别用 `==` 直接比浮点；金额用整数/`numeric`（数据库篇也讲过）。

## 3. 量化：AI 部署的"数据表示"实战

推理时把 FP32 权重压成更低位宽，换**显存/带宽/算力**——先理解三种格式的**结构差异**：

| 格式 | 位宽 | 结构 | 特点 |
|------|:---:|------|------|
| FP32 | 32 | 1+8+23 | 训练基准 |
| **FP16** | 16 | 1+5+10 | 尾数多、范围小（**上限 65504**） |
| **BF16** | 16 | 1+8+7 | **范围同 FP32**、尾数少（精度差） |
| **INT8** | 8 | 定点整数 + 缩放系数 | 最省、需要校准（scale/zero-point） |

**实测对比**：

| 原值 | FP16（硬件转换） | BF16（截断） | INT8（对称量化，scale=1000.5/127） |
|------|:---:|:---:|:---:|
| 0.123457 | 0.123474（误差 0.0000） | 0.123047（0.0004） | 0（0.1235） |
| -3.14159 | -3.14062（0.0010） | -3.14062（0.0010） | 0（3.1416） |
| 1000.5 | 1000.5（0.0000） | 1000（0.5000） | 127 → 1000.5（0.0000） |
| 100000 | **inf（溢出）** | 100000 | — |

**读表**：

- **FP16 更准**（尾数 10 位 vs BF16 的 7 位），但**范围小**——大数值直接溢出成 inf（实测 100000 → inf）
- **BF16 范围大**（阶码和 FP32 一样），适合"数值动态范围大"的训练场景
- **INT8 的坑**：用全张量最大值当 scale 时，**小数值全被压成 0**（上面 0.123 → 0）→ 实践中用 per-channel/per-group 量化、或先做离群值裁剪

## 4. 字节序

**实测**：`0x01020304` 在内存里是 `04 03 02 01` → **小端（little endian）**（x86/ARM 默认小端）。

**什么时候要注意**：

- **网络协议/文件格式**：用大端（网络字节序）→ `htonl/ntohl` 转换
- **跨语言/FFI**：Python `struct`、C++ 读写二进制要声明字节序
- **看内存调试**：`gdb`/`hexdump` 里数值是反的，别慌

```c
uint32_t h = htonl(0x01020304);      // 主机序 → 网络序（大端）
union { uint32_t u; uint8_t b[4]; } x = { 0x01020304 };   // 探测本机字节序
```

## 5. 运算器

- **ALU**：加减与或非、移位、比较；加法器从"串行进位"到"先行进位（CLA）"的优化思路 = 用更多硬件换更短延迟
- **定点乘除法**：教材讲移位-相加、Booth 编码、阵列乘法器——核心是"乘法 = 多次移位相加"，现代 CPU 用专门单元做
- 这部分**工程上不会手写**（编译器/CPU 已封装），细节见[组成原理速查](09-组成原理速查.md)

## 6. 深入实测：误差累积与量化策略

### 浮点误差会累积（不是"多算几位就好"）

**实测：1000 万个"0.1"求和**（真值 1000000）：

| 写法 | 结果 | 误差 |
|------|------|:---:|
| 朴素 float 累加 | 1087937 | **87937**（8.8%！） |
| double 累加 | 1000000 | 0.0149 |
| **Kahan 补偿求和（float）** | 1000000 | **0.0000** |

**读法**：float 的和大到 100 万后，再加 0.1 会被"吃掉"（有效位用尽）——误差随规模**线性累积**。Kahan 用"补偿项"把丢失的低位捞回来（代价：每步多几次运算）。**结论**：累加大量浮点用 double，或用分块/补偿算法；AI 里的"累加用 FP32"也是同一个道理。

### 量化策略：per-tensor vs per-channel

**实测**（16 个通道，其中一个通道有离群值 100）：

| 策略 | 平均绝对误差 |
|------|:---:|
| per-tensor（全张量一个 scale） | 0.083 |
| **per-channel（每通道一个 scale）** | **0.001**（83 倍好） |

**原因**：per-tensor 的 scale 被离群值（100）撑大，**正常数值全被压到很小的量化级**；per-channel 让离群值只影响自己那一路。这就是主流量化方案都用 **per-channel/per-group** 的原因。

### INT8 乘加链路（AI 推理的定点路径）

```
量化: q = round(x / scale)          → INT8
计算: acc = Σ(qx × qy)              → INT32 累加（防溢出）
还原: y = acc × (sx × sy)           → 浮点
```

**实测**：`1.7 × -0.9` → 量化 `(127 × -127 = -16129)` → 还原 `-1.5300`（误差 0.0000）——**整数运算单元没有浮点误差**，误差只来自量化本身。

### 特殊值与转换（边界行为）

| 表达式 | 结果 |
|--------|------|
| `inf - inf` | **NaN**（不是 0！） |
| `inf * 0` | **NaN** |
| `nan + 1` | NaN（污染传播） |
| `(int)3.99f` | 3（**截断**） |
| `lroundf(3.5f)` | 4（就近） |
| int 最大值转 float | 会舍入成 2³¹（**超出 int 范围**）→ 转回来是 UB |

**工程注意**：`inf - inf = NaN` 会让"检测异常值"的代码失效（NaN 参与比较永远 false）→ 用 `isnan/isinf` 显式检查。

## 7. 校验码（数据在传输/存储里的"防错"）

| 方式 | 能力 | 开销 | 用途 |
|------|------|:---:|------|
| 奇偶校验 | 检出奇数个位错误 | 1 位 | 简单场景（串口） |
| **海明码** | 检出并**纠正 1 位** | log₂n 位 | 内存 ECC |
| **CRC** | 强检错（不纠错） | 8~32 位 | 网络/磁盘/压缩包 |

**海明码实测**（7,4 码）：数据 `1011` → 编码 `1010101`（校验位放在 1/2/4 位置）；依次翻转全部 7 个位置，校验子 `(s4s2s1)` **每次都能精确指出错误位**（1~7 全部定位正确）——"纠错"就是"定位 + 取反"。

**CRC 实测**（CRC-8，多项式 0x07）：16 种单比特错误 **16/16 检出**；120 种双比特错误 **120/120 检出**。标准 CRC-32 还能检出所有 ≤32 位突发错误——以太网、zip、磁盘都用它。

**工程印记**：内存 ECC（海明码）、网络包/文件校验（CRC）、下载文件的 sha256（密码学哈希，检错+防篡改）。

## 8. 舍入模式与扩展（类型转换的位级行为）

**IEEE 754 四种舍入**：

| 模式 | 规则 | 实测/例子 |
|------|------|----------|
| **就近偶数（默认）** | .5 往偶数靠 | `2.5→2`、`3.5→4`（printf/nearbyint 实测） |
| 向零（截断） | 直接砍 | `(int)2.9 = 2` |
| 向 +∞ / 向 −∞ | 往上/往下取 | 区间算术用 |

**符号扩展 vs 零扩展**（实测）：

| 转换 | 位行为 | 例子 |
|------|--------|------|
| 有符号 → 更宽有符号 | **符号扩展**（高位补符号位） | `int8(-1)` → `0xffffffff` |
| 无符号 → 更宽（或无符号） | **零扩展**（高位补 0） | `uint8(255)` → `0x000000ff` |
| 宽 → 窄 | 截断（丢高位） | `int → int8` |
| 有符号/无符号互转 | 位不变、解释变 | `-1 → 4294967295` |

**工程坑**：`int` 和 `unsigned` 混用比较会自动转无符号（负数变成巨大正数 → 循环写错）；`-1` 当 `size_t` 传给 `substr/memcpy` 直接灾难——所以编译开 `-Wsign-compare`。

## 9. 字符编码（扩展到"数据表示"）

| 编码 | 规则 | 特点 |
|------|------|------|
| **ASCII** | 7 位，128 个字符 | 英文够用；扩展 ASCII 用满 8 位 |
| **GBK** | 双字节，兼容 ASCII | 中文 2 字节；和 Unicode 不兼容 |
| **UTF-8** | **变长**：1~4 字节（ASCII 1 字节、中文 3 字节、emoji 4 字节） | 兼容 ASCII、Web 标准、**自同步**（首字节前缀表明长度） |
| **UTF-16/32** | 定长/变长（代理对） | 内存里定长好处理；Windows/Java 内部用 |

**工程坑**：

- **乱码 = 解码用的编码和编码时不一致**
- **"字符串长度"要看按什么算**：`strlen`（字节）≠ 字符数（中文 3 字节/字）；emoji 可能 4 字节
- **UTF-8 自同步的好处**：从字节流中间开始也能找到字符边界（网络协议/流式处理喜欢它）
- C++ 里 `std::string` 是字节串（不管编码）；处理 Unicode 要用专门库（Python 的 `str` 是码点串，这也解释了跨语言文本处理为什么容易出错）

## 10. 要点回顾

1. **补码**：负数取反加一；有符号溢出是 **UB**、无符号是"模回绕"（实测 `4294967295+1=0`）
2. **IEEE 754**：符号+阶码+尾数；float ~7 位有效数字、2²⁴ 后整数不连续（实测）
3. **特殊值**：inf/-inf/NaN，`NaN != NaN`；denormal 区精度骤降
4. **量化**：FP16 准但范围小（65504 上限，实测溢出）、BF16 范围大精度低、INT8 最省但要防"小值归零"（per-channel 量化）
5. **字节序**：x86/ARM 小端；网络/文件大端；跨语言数据交换必须声明
6. **运算器**（ALU/乘法器/Booth）属于理解范畴，工程细节由编译器/硬件封装
