# 概述与性能指标

计算机怎么组成、怎么衡量快慢——**后面所有"为什么慢"的问题，最终都落到这几个指标上**。

## 1. 冯·诺依曼结构与五大部件

```
        ┌──────────────┐
        │   控制器      │←──── 指令流 ────┐
        └──────┬───────┘                 │
               │ 控制信号                 │
        ┌──────▼───────┐   ┌──────────┐  │
        │   运算器 ALU  │←→│  存储器   │──┘
        └──────┬───────┘   └──────────┘
               │                ↑↓
        ┌──────▼───────┐   ┌──────────┐
        │  输入设备     │   │ 输出设备  │
        └──────────────┘   └──────────┘
```

**核心思想（存储程序）**：指令和数据都以二进制存在同一存储器里，CPU 按顺序取指、执行。

| 部件 | 职责 | 现代形态 |
|------|------|---------|
| 运算器 | 算术/逻辑运算 | ALU + 浮点单元 + SIMD 单元 |
| 控制器 | 取指、译码、发控制信号 | 乱序执行核心（见流水线篇） |
| 存储器 | 存指令和数据 | 寄存器/L1-L3/DRAM/SSD 的层次（见存储篇） |
| 输入/输出 | 与外界交换 | PCIe 设备、网卡、GPU |

**层次结构**：硬件 → 操作系统 → 应用。越往上越好写、越抽象；越往下越接近物理限制（性能问题常常要"下钻"）。

## 2. 性能指标：先分清"延迟"和"吞吐"

| 指标 | 含义 | 例子 |
|------|------|------|
| **延迟（latency）** | 一次操作要多久 | 内存访问 ~100 ns、SSD 随机读 ~几十 µs |
| **吞吐（throughput）** | 单位时间能做多少 | 内存带宽 GB/s、GPU TFLOPS |
| 主频 | 时钟周期频率（GHz） | 提高主频不必然提速（见 CPI） |
| **CPI / IPC** | 每条指令平均周期数 / 每周期指令数 | IPC = 1/CPI；现代 CPU IPC 可 >1（超标量） |
| MIPS | 每秒百万条指令 | 只对同架构比较有意义 |
| **FLOPS** | 每秒浮点运算次数 | 算力指标；实测：单核矩阵乘 32.7 GFLOP/s（-O3；-O2 版 24.6，见 roofline 篇） |

**关键认知**：

- **延迟和吞吐是两回事**：内存带宽 6 GB/s（吞吐）不代表一次随机访问快（延迟 ~100 ns）；优化前先分清在解决哪个
- **主频不等于性能**：同样 3 GHz，IPC 差一倍性能就差一倍；而 IPC 受流水线、缓存、分支预测影响（后面的篇全在讲这个）
- **实测优先**：微基准（microbenchmark）容易被编译器优化掉或测偏——本笔记所有结论都配真跑数据

## 3. Amdahl 定律：并行优化的天花板

```
加速比 = 1 / ((1-p) + p/s)      p = 可并行比例，s = 并行部分加速倍数
```

**实测数值**：

| 可并行比例 p | 4 线程 | 16 线程 | 1024 线程 | 理论上限（s=∞） |
|:---:|:---:|:---:|:---:|:---:|
| 0.50 | 1.6× | 1.9× | 2.0× | **2×** |
| 0.90 | 3.1× | 6.4× | 9.9× | **10×** |
| 0.95 | 3.5× | 9.1× | 19.6× | **20×** |
| 0.99 | 3.9× | 13.9× | 91.2× | **100×** |

**结论**：**不可并行的那 5% 决定了你的天花板**（p=0.95 时，给你 1024 核也快不过 20 倍）——优化先找串行瓶颈，别急着加核。

**实测对照（多线程求和/访问）**：1/2/4/8 线程加速比 1.00/1.81/2.66/2.17 倍（走内存的负载，带宽和调度限制了扩展性）。

## 5. 实测：性能指标的"手感"

**CPU 时间三要素**：`CPU 时间 = 指令数 × CPI × 时钟周期`——三者任何一个改善都能提速，而它们由不同层面决定：

| 要素 | 谁决定 | 例子（本篇后续实测） |
|------|--------|------|
| 指令数 | 算法/编译器优化 | 循环展开、内联、消除冗余计算 |
| CPI | 微架构/负载特征 | 分支预测失败（10.9 倍差距）、依赖链（1.6 倍） |
| 时钟周期 | 硬件/频率 | 超频、能效核 vs 性能核 |

**几个"手感数字"**（后面各篇细讲）：

| 操作 | 实测 |
|------|------|
| 普通自增（单线程，寄存器/缓存内） | 基准（亚纳秒级） |
| 原子自增（无竞争） | **约 20 倍于普通自增** |
| 原子自增（两线程争抢） | **约 40 倍于普通自增**（缓存行来回搬） |
| 一次内存随机访问 | ~100 ns（存储篇） |
| 一次 memcpy 的字节成本 | 亚纳秒/字节级（GB/s 带宽） |
| 单核矩阵乘 | 几十 GFLOP/s 档（roofline 篇，-O3） |

（原子/自增来自并行篇实测；内存/磁盘/GPU 见对应篇）

**用这组数字做"费米估算"**：比如"1 亿次原子自增要多久？"→ 单次纳秒量级 → 零点几秒（量级对得上）。

## 6. 字长：三个"字长"别混

| 术语 | 含义 | 影响 |
|------|------|------|
| **机器字长** | ALU/通用寄存器宽度（如 64 位） | 一次能处理的整数宽度；决定"64 位程序" |
| **指令字长** | 一条指令的位数 | x86 变长（1~15 字节）、RISC 定长（4 字节） |
| **存储字长** | 一次访存能读写的位数（MDR 宽度） | 通常 = 机器字长 |

**工程关联**：

- **64 位不只是"数字更大"**：指针 8 字节 → 同样是数据结构的内存占用和带宽更大（AI 推理里指针密集的结构要留意）
- **32 位 vs 64 位的部署坑**：库/驱动的架构必须匹配（`uname -m`）；32 位进程地址空间 <4GB
- **字长和寻址范围**：地址位数决定能寻址多大内存（x86-64 虚拟地址有效 48 位 ≈ 256TB）

## 7. 基准测试方法论（踩过的坑）

本笔记所有数字都真跑，但**微基准处处是坑**（我们实测中就遇到多次）：

| 坑 | 表现 | 解法 |
|----|------|------|
| 死代码消除 | 循环被优化掉（白测） | 把结果打印/累加进 sink（`volatile`/`asm`） |
| 条件传送/向量化改写语义 | 分支预测测不出差距（0.9 倍） | `-fno-if-conversion -fno-tree-vectorize` 或看汇编 |
| 参数被优化 | 带宽算出 65 万 GB/s | 检查计算式的类型（int 溢出） |
| 测量工具不可用 | WSL 里 `perf`/`rdtsc` 不可用 | 用墙钟 + 对照实验；裸机上再用 `perf stat` |
| 缓存/分支热身 | 首次测量偏慢 | 多轮取最优/中位 |

**原则**：**对照实验 > 绝对数字**（同样的代码改一个变量，看差异）；**怀疑任何"太漂亮"的结果**。

**标准基准套件**（避免"只信自家 microbenchmark"）：

- **CPU**：SPEC CPU 系列（整数/浮点综合）、CoreMark
- **AI**：**MLPerf**（训练/推理分榜；比较时注意"同硬件、同模型、同精度"才可比）
- **存储**：fio（IOPS/带宽/延迟）
- 用法：标准套件做**横向对比**，自家 microbenchmark 做**定位瓶颈**



## 8. 要点回顾

1. **冯·诺依曼五部件**：运算器/控制器/存储器/输入/输出；存储程序思想
2. **延迟 vs 吞吐**：先分清优化目标；内存带宽大 ≠ 随机访问快
3. **IPC/CPI/FLOPS**：IPC > 1 靠超标量；FLOPS 是算力指标（实测单核矩阵乘 32.7 GFLOP/s）
4. **Amdahl**：串行部分定天花板（p=0.95 → 最多 20 倍）——先打串行瓶颈
5. **层次结构**：硬件→OS→应用；性能问题要能下钻
6. **一切结论以实测为准**：微基准有坑（被优化掉/测偏/工具不可用），用**对照实验**验证
7. **手感数字**：普通自增（亚纳秒）→ 原子无竞争约 20 倍 → 争抢约 40 倍；内存随机 ~100 ns——用来做费米估算
