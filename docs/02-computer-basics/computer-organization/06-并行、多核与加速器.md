# 并行、多核与加速器

单核频率涨不动之后，性能靠**并行**：指令级（ILP）→ 数据级（DLP/SIMD）→ 线程级（TLP/多核）→ 设备级（GPU/NPU）。

## 1. 四个并行层次

| 层次 | 含义 | 手段 | 谁负责 |
|------|------|------|--------|
| **ILP** 指令级 | 同一线程内多条指令并行 | 超标量、乱序、流水线 | 硬件+编译器 |
| **DLP** 数据级 | 一条指令处理一批数据 | SIMD（SSE/AVX/NEON） | 编译器/手写 intrinsics |
| **TLP** 线程级 | 多线程/多核并行 | 线程、进程、多核 | 程序员 |
| **设备级** | 多设备/多卡 | GPU、多卡、集群 | 系统/框架 |

**Amdahl 提醒**：加核/换卡之前先看串行部分（[概述篇](01-概述与性能指标.md)）。**扩展性 != 线性**：

**实测（同一内存访问型负载，1/2/4/8 线程）**：

| 线程数 | 加速比 |
|:---:|:---:|
| 1 | 1.00× |
| 2 | 1.81× |
| 4 | 2.66× |
| 8 | 2.17× |

**读法**：不是线性（4 线程只 2.66 倍、8 线程反而降）——原因：**共享内存带宽饱和** + 线程调度开销 + WSL 虚拟化。**内存密集型负载加核收益有限；计算密集型才容易线性扩展**。

## 2. 多核的代价：缓存一致性

多个核各有自己的缓存 → 同一份数据复制多份 → 需要**缓存一致性协议**（MESI：Modified/Exclusive/Shared/Invalid）：

- 一核改数据 → 其他核的副本失效（Invalidate）
- **代价**：失效的缓存行要重新取（延迟 ~100 ns 级）
- **伪共享**是它的极端情况（两个核抢同一条 cache line，见[存储篇](03-存储系统与Cache.md)）
- **内存序**：一致性协议只管缓存，不管"指令重排可见性"——那是内存模型（语言语义层）的事

**NUMA（非统一内存访问）**：多路服务器上，访问"本地内存"快、访问别的 CPU 挂的内存慢（本机单节点，无法实测）。工程影响：`numactl --localalloc`、绑核绑内存。

## 3. 加速器：为什么 GPU 成了 AI 的标配

**CPU vs GPU 的设计哲学**：

| | CPU | GPU |
|--|-----|-----|
| 核心 | 少而强（几十个，乱序、大缓存） | 多而简单（几千个，顺序执行） |
| 适合 | 分支复杂、延迟敏感 | **数据并行、算力密集** |
| 存储 | 大缓存、延迟优先 | 高带宽显存（HBM/GDDR）、带宽优先 |
| 模型 | MIMD | **SIMT**（单指令多线程：一个 warp 32 线程同指令、不同数据） |

**实用习惯**：拿 `nvidia-smi` 对照自己的卡——型号、显存总量与占用、功耗上限、驱动 / CUDA 版本。

**为什么 AI 用 GPU**（用 roofline 的话说，见[性能模型篇](07-性能模型与roofline.md)）：

- 矩阵乘**算术强度高**（算得比搬得多）→ 吃算力 → GPU 的算力密度高一个量级
- 显存带宽（~几百 GB/s）远高于 DDR → 喂得起大矩阵
- SIMT 天然匹配"同样的运算刷几百万个元素"

**软件栈**：CUDA（NVIDIA）/ ROCm（AMD）/ Metal（Apple）；推理侧的 TensorRT、ONNX Runtime 等。

## 4. 多卡与设备互联

- **PCIe**：GPU 与 CPU/内存之间的通道（带宽有限 → "数据搬运"常是瓶颈）
- **NVLink**：GPU 之间的高速互联（多卡训练/推理）
- **拓扑**：单机多卡 / 多机（RDMA 网络）——部署时的"通信开销"来源

**工程直觉**：**别让数据搬来搬去**（CPU↔GPU、卡↔卡）——搬运的带宽/延迟往往比计算贵。

## 5. 深入实测：同步的代价、负载类型、GPU 细节

### 同步操作的真实代价（1 亿次）

| 操作 | 每次耗时 | 相对成本 |
|------|:---:|:---:|
| 普通自增（寄存器/缓存内） | 基准 | 1× |
| **原子自增（`fetch_add` relaxed，无竞争）** | 明显更贵 | ~20× |
| **原子自增（两线程争抢同一变量）** | 最贵 | ~40× |

**读法**：

- **原子操作本身有成本**（锁总线/缓存行独占 ~20 倍）——不是"无锁就免费"
- **争抢再翻倍**：缓存行在两个核之间来回搬（和伪共享同源）
- 工程结论：**减少共享写**（线程本地累加、分片计数、最后合并）比"换个锁"有效得多

### 扩展性取决于负载类型

| 负载类型 | 扩展性 | 原因 |
|---------|-------|------|
| 纯计算（寄存器/SIMD 内） | 接近线性（不超过核数） | 执行单元独立 |
| 内存带宽型（本节求和/遍历） | 差（实测 4 线程 2.66×） | 带宽是共享资源 |
| 锁/原子密集 | 可能**负扩展** | 争抢加剧 |
| IO 型 | 看设备队列 | DMA/中断/驱动 |

**判据**：先看**算术强度**（roofline 篇）——强度低的多线程收益有限，应该先做数据布局/分块/量化。

### GPU 细节与查询命令

| 项目 | 怎么看 |
|------|--------|
| 显存 | `nvidia-smi` 看总量与当前占用（决定能装多大模型 / 多大 batch） |
| 功率 | `nvidia-smi -q -d POWER` 看功耗上限与实时功耗 |
| 驱动 / CUDA | `nvidia-smi` 顶部两行：驱动版本、驱动支持的最高 CUDA 版本 |
| 链路 | `nvidia-smi -q` 查 `GPU Link Info` 段（PCIe 代宽/宽度） |
| 拓扑 | `nvidia-smi topo -m`（多卡时看 NVLink/PCIe 连接） |

**SIMT 执行模型**（和 CPU 的对照）：

```
CPU: 少数强核，每核乱序执行、大缓存，靠 ILP+分支预测
GPU: 数千简单核，以 warp（32 线程）为单位同指令执行：
     · 一个 warp 里分支不同 → "分支发散"，两条路都走（浪费一半）
     · 靠海量线程掩盖访存延迟（而不是靠缓存/乱序）
     · 显存带宽高但延迟不低 → "提高占用率（occupancy）"掩盖
```

**给部署的直觉**：GPU 适合"**数据并行 + 分支规整 + 算术强度高**"的算子（矩阵乘/卷积/attention）；分支复杂的逻辑放 CPU 更划算（这也是推理引擎"哪些算子放哪"的决策依据）。

## 6. 两个多核细节：MESI 与超线程

### MESI 状态与转换

| 状态 | 含义 | 谁的副本有效 |
|------|------|------------|
| **M** odified | 本核独占、已修改（脏，和内存不一致） | 只有本核 |
| **E** xclusive | 本核独占、和内存一致 | 只有本核 |
| **S** hared | 多核共享、干净 | 多核 |
| **I** nvalid | 失效 | 无 |

```
读未命中 → 从内存/其他核取，进 E 或 S
写命中 S/E → 要升到 M：**通知其他核把副本置 I**（失效广播）
写 M 的行被别核读 → 写回内存/直接转发，双方变 S
```

**这解释了实测的代价**：原子争抢（比无竞争再翻倍）就是"同一行在核间来回搬家"；**伪共享**同理（见[存储篇](03-存储系统与Cache.md)）。

（工业界还有 **MOESI** 变体——多一个 O（Owned）状态：脏数据可共享、不必立刻写回；AMD 用它。知道名字即可。）

### 超线程（SMT）：逻辑核 ≠ 物理核

**实测**（`lscpu`）：**12 个物理核 × 2 线程 = 24 个逻辑核**（Core(s) per socket 12，Thread(s) per core 2）。

- 两个逻辑核共享执行单元/缓存 → **单核性能不翻倍**（通常 +20~30%）
- 收益来自"填执行槽"：一个线程访存/分支停顿时空出的发射槽，被同核的另一个线程用上
- **别开满 24 线程**：计算密集负载上 12 线程常常更好（共享资源争抢）

## 7. 要点回顾

1. **四个并行层次**：ILP（硬件）→ DLP（SIMD）→ TLP（多核）→ 设备级（GPU/多卡）
2. **扩展性不是线性的**：实测 1/2/4/8 线程 = 1.00/1.81/2.66/2.17×（内存带宽 + 调度限制）
3. **多核的代价是缓存一致性**（MESI）：失效重取 ~100 ns；**伪共享**是极端情况
4. **NUMA**：本地/远程内存访问速度不同（本机单节点）；`numactl`/绑核绑内存
5. **GPU 的设计哲学**：多而简单的核 + 高带宽显存 + SIMT → 匹配"数据并行、算术强度高"的负载
6. **本机 GPU**：RTX 4060 8GB（实测）；CUDA 生态
7. **数据搬运往往比计算贵**：PCIe/NVLink 带宽是系统设计的硬约束
8. **同步有价**：原子无竞争约 20× 普通自增、争抢再翻倍——**减少共享写**比换锁有效
9. **扩展性看负载**：计算型接近线性、带宽型差、锁密集可能负扩展
10. **SIMT 的脾气**：分支发散、靠线程掩盖延迟——分支规整的高强度算子才适合 GPU
