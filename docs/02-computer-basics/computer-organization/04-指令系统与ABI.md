# 指令系统与 ABI

指令是 CPU 的"语言"（ISA），而**调用约定（ABI）**决定了函数怎么传参、库怎么互操作——写 C++、调库、跨语言 FFI 都绕不开。

## 1. 指令格式与寻址方式

**指令 = 操作码 + 地址码**：

```
| 操作码(opcode) | 地址码1 | 地址码2 | ... |     ← 变长（x86）或定长（RISC）
```

**常见寻址方式**（考研要背，工程里看反汇编时能认出来即可）：

| 方式 | 含义 | 汇编样子 |
|------|------|---------|
| 立即寻址 | 操作数是常数 | `mov $5, %eax` |
| 寄存器寻址 | 操作数在寄存器 | `mov %ebx, %eax` |
| 直接寻址 | 地址是常数 | `mov 0x1000, %eax` |
| 寄存器间接 | 地址在寄存器 | `mov (%rax), %ebx` |
| 变址/基址+偏移 | 地址 = 基址 + 索引×比例 + 偏移 | `mov (%rax,%rcx,4), %ebx` ← 数组下标 |
| 相对寻址 | 地址 = PC + 偏移 | 跳转指令用 |

**看反汇编的意义**：确认"编译器到底生成了什么"——比如数组访问变成 `(%rax,%rcx,4)`、循环有没有被向量化。

## 2. CISC vs RISC

| | CISC（x86） | RISC（ARM/RISC-V） |
|--|------------|-------------------|
| 指令 | 变长、复杂、一条顶多条 | 定长、简单、少而规整 |
| 寻址 | 方式多 | 方式少（load/store 架构） |
| 实现 | 前端解码成微操作（内部其实 RISC 化） | 原生简单 |
| 生态 | 服务器/桌面（向后兼容强） | 手机/嵌入式/Apple Silicon/服务器（能效好） |
| 部署时 | 选对**架构的包**（x86_64 vs aarch64） | 交叉编译/镜像多架构（manifest） |

**工程影响**：**跨平台部署第一件事就是确认目标架构**（`uname -m`：x86_64/aarch64）；Docker 镜像/conda 包/wheel 都分架构；x86 的 SIMD 指令集（SSE/AVX）与 ARM 的 NEON/SVE 需要各自编译（`-march=native` 不可跨平台）。

## 3. 调用约定（实测反汇编）

**System V AMD64 ABI（Linux/macOS 默认）**：前 6 个整型/指针参数依次放 **rdi、rsi、rdx、rcx、r8、r9**；浮点参数放 **xmm0-xmm7**；更多参数走栈。

```c
long add6(long a, long b, long c, long d, long e, long f) { return a+b+c+d+e+f; }
double mix(int a, double x) { return a * x + 1.0; }
```

```
反汇编 add6（实测）：
    add  %rsi,%rdi      ← b 加进 a（rdi=参数1、rsi=参数2）
    add  %rdx,%rdi      ← c
    add  %rcx,%rdi      ← d
    add  %r8,%rdi       ← e
    lea  (%rdi,%r9,1),%rax   ← f（r9），结果放 rax 返回

反汇编 mix（实测）：
    movapd %xmm0,%xmm1
    cvtsi2sd %edi,%xmm0      ← int 参数走 edi，double 参数走 xmm0
```

**读出来的信息**：

- 参数**不是都走栈**（前 6 个寄存器、浮点走 xmm）→ 所以"函数调用慢"不绝对
- 返回值放 **rax**（整数）/**xmm0**（浮点）
- 超过 6 个参数才用栈（CPU 篇的"寄存器压力"就是这事）

## 4. ABI 与互操作

**ABI = 调用约定 + 寄存器使用 + 数据布局 + 符号命名**。为什么重要：

- **C 的 ABI 稳定** → 各种语言的互操作都开 C 口子：`extern "C"`、Python ctypes、FFI
- **C++ ABI 不稳**（名字修饰、STL 布局随编译器/版本变）→ 跨编译器的 C++ 库容易出问题；所以导出库都用 C 接口
- **结构体布局也是 ABI**：对齐/padding 的具体布局不一致 → 跨语言传结构体要小心

**常用工具**：

```bash
objdump -d a.o          # 反汇编看指令
nm a.o                  # 看符号（C 的 add6；C++ 的是 _Z4add6llllll）
readelf -h a.out        # 看 ELF 头/架构
uname -m                # 看本机架构（x86_64）
```

## 5. 深入实测：栈帧、结构体传参、栈保护

**更多 ABI 实测**（objdump）：

```c
long add7(long a,...,long g);      // 第 7 个参数 → 走栈
struct Big { long a,b,c; };        // 24 字节 > 16 → 走栈（隐式指针）
struct Small { long a; };          // 8 字节 → 走寄存器
```

```
add7:    ... lea (%rdi,%r9,1),%rax     ← 前 6 个在寄存器
              add 0x8(%rsp),%rax       ← 第 7 个参数在栈上（%rsp+8）
sum_big: mov 0x10(%rsp),%rax           ← 24 字节结构体：在调用者的栈上（隐式指针）
sum_small: mov %rdi,%rax               ← 8 字节结构体：寄存器直接传
```

**结论**：

- **寄存器传参有上限**：整数/指针 6 个、浮点 8 个；**第 7 个开始走栈**（访存 → 更慢）
- **结构体按大小决定**：≤16 字节走寄存器对，>16 字节在栈上拷贝（所以"传大结构体用 const&"是有依据的）
- **返值**：整数在 `rax`、浮点在 `xmm0`；大结构体返值也会用"调用者提供的空间"

### 栈帧与安全（顺带看编译器做了什么）

```
caller 的反汇编（实测）：
  sub $0x218,%rsp                      ← 开栈帧（64 个 long = 512B + 对齐/保护）
  mov %fs:0x28,%rax
  mov %rax,0x208(%rsp)                 ← 栈保护"金丝雀"：函数返回前比对
  ...
  loop: add %rax,%rdx
        mov %rdx,(%rcx,%rax,8)         ← 数组访问 = 变址寻址
        ... jne loop
  ret 前：sub %fs:0x28,%rdx / jne 失败 → call __stack_chk_fail
```

**读出来的东西**：

- **局部数组在栈上**（`(%rcx,%rax,8)` 就是 `loc[i]` 的变址寻址）
- **栈保护（stack protector）**：`%fs:0x28` 取哨兵值放栈尾，返回前校验 → 栈溢出会 `__stack_chk_fail`（`-fstack-protector` 默认开启）
- **函数调用有成本**：`call/ret` + 栈帧调整 + 保护值校验（这也解释了内联的收益）

### 变长编码：x86 的"密度"与"对齐"

```
同一组参数，不同寻址方式的指令长度不同（1~15 字节变长）；
常量可用 lea 一条搞定（add 0x8(%rsp),%rax 是 5 字节）
```

RISC 定长（4 字节）译码简单；x86 变长省空间但译码复杂——这是现代 x86 在内部把指令**译成微操作（RISC 化）**的原因。

## 6. 要点回顾

1. **指令 = 操作码 + 地址码**；寻址方式里的"变址"就是数组下标（`(base,index,scale)` 实测可见）
2. **CISC/RISC**：x86 变长复杂、ARM 定长规整；**部署先确认架构**，SIMD 指令集各平台不同
3. **调用约定**（实测）：前 6 个整型参数走 **rdi/rsi/rdx/rcx/r8/r9**，浮点走 **xmm0-7**，返回在 rax/xmm0
4. **寄存器传参**意味着"函数调用"本身不慢；参数多到溢出到栈才要留意
5. **ABI 决定互操作**：C ABI 稳定（`extern "C"`/FFI 都靠它）、C++ ABI 不稳（所以导出 C 接口）
6. **工具**：`objdump -d` 看指令、`nm` 看符号、`uname -m` 看架构——性能排查和部署对齐都用得上
7. **传参规则**（实测）：6 个整型寄存器 + 8 个浮点寄存器；**第 7 个整型参数走栈**；>16 字节结构体在栈上拷贝
8. **栈帧里有安全机制**：栈保护金丝雀（`%fs:0x28`）、返回前校验——栈溢出会被抓
